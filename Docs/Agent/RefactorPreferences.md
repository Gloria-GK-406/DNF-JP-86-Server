## 2. 动机

- 让错误编译不过或启动不了，而不是靠审查发现（`86ba115e`、`7031862d`、`cb59bb1b`）。
- 一种事实只有一个归属（`43b3f9d8`、`7478e2eb`、`8abf77eb`）。
- 按概念切，不按协议段或表切。合表判据："同一个键、同一个生命周期、同一个写入用例"三条同时成立（`9c535a97`）。
- 用户原话："先把形状弄对，然后再说细节。不急暂时的正确性。"（引于 `02f9410f`）
- 用户原话："一次性全迁移吧，没必要留一半。"（`a0e916c0`）

## 3. 手法

1. **先设计、裁定，再动代码**：有来源的结论与待定项分开写（`f894034e`），逐列裁定后再拆表（`9c535a97`）。
   较大的重构先与用户谈方向，取得用户原话授权再开始。
2. **纯搬迁与语义改动分开提交**：搬内容（`3c828217`，方法体逐字节不变）→ 收切片（`3edc5f5d`）
   → 拆项目（`b4d86949`）→ 拆表（`9f7fec82`）→ 改 schema（`1a77ef8a`）。
3. **"行为不变"要有能失败的证据**：金样本、字节基线（`9f7fec82`、`43b3f9d8`）；改名归一化后测试零 diff（`2f56754d`）；
   先红后绿或变异演示（`86ba115e`）；测试数增减写出加法（`70a3e54e`）。
4. **风险大的先钉行为**：表征测试 → 结构 → 合并 → 行为修正（`Document/MarriageAggregateDesign-20261017.md`）。
5. **一次到位，删净，不留兼容层**：`[Obsolete]` 为零；"不是搬走，是删掉"（`d387bcb4`）；
   按概念搜而不是按标识符搜（`d94b4fd6`）。
6. **暂时空的调用点用名字说明**：`0d8e960e` 的 `Unaccounted…FatigueDomainService` 先占位，`bd029df3` 再接真实记账。
7. **规则用机器判据守**，并配反例用例证明判据会拒绝（`70a3e54e`）。
8. **范围外的问题只记录、不顺手改**（`2f56754d`、`3edc5f5d`）。
9. **证据被推翻就改记录**，说明之前为什么错（`075ac5fd`、`3575330c`）。
10. **受阻就封存、精确回滚，不硬做**（`052754b5`）。

## 5. 看代码时的七问

1. 这个事实别处还有一份吗？→ 删副本，留一个真源。
2. 这个判定别处还有另一种算法吗？→ 收进一个领域服务或规则。
3. 这条约束靠人记、靠名单吗？→ 换成类型、编译期或启动期检查。
4. 下一个功能会落在这里、而这里形状不对吗？→ 先重构再做功能。
5. 领域代码碰了连接、Session、协议字段吗？→ 移到边缘。
6. 名字看得出它属于哪一类吗？→ 看不出就改名。
7. 有没有用技巧（延迟解析、平行集合、补丁同步）掩盖结构问题？→ 拆结构。

命中时：在当前任务范围内就按第 3 节手法做；超出范围就记录下来交给用户决定，不顺手改。
