关联跟踪：[#212 A21 无客户端 E2E 全测试集](https://github.com/Gloria-GK-406/DNF-JP-86-Server/issues/212)；状态：范围已登记，待排期。

日期：2026-10-27（Asia/Shanghai）。服务端基准：`c076e80ebc460053af16e3a445da65b079ba4061`，`main`。用途：先按当前功能逐项进行真实客户端人工验收和双向采集，再据此实现可复用的无客户端完整集成回归。

**本目录包含 50 个功能域、348 个编号场景；全部新 E2E 基线均为“待采集”，没有执行结果。** [协议与源码覆盖对照](E2E-协议覆盖对照-20261027.md)将当前 180 个 Game 入站注册键、4 个 Channel 请求入口及 115 个 Game 切片目录映射到本目录。映射只是防漏清单，不等于自动测试或客户端行为已经通过。

## 1. 已确定的验收合同

- 固定完整 PVF 作为测试素材；开测前一次性准备包含所有相关账号、角色、资产、任务、关系、活动和配额的 SQLite 基线库。
- 每轮从基线复制运行库。一个连续流程内复用同一账号/角色和数据库，按明确步骤执行；不在每一步之间清库，不在被测步骤中补写状态。
- 真实 A21 客户端连接**我们当前服务端**执行同样流程。人工确认正确后，才把该次客户端双向报文及数据结果固化为正式回归基线。
- 自动阶段只模拟客户端，通过真实 HTTP、Channel/Game 网络运行正式 Host；不替换注册、仓储、规则、事件、时钟、随机源、房间布局或其它生产组件。
- 使用正式频道脚本与正常服务开关；端口、监听地址和数据库/PVF路径允许做隔离部署配置，必须记录。不能为了动态端口悄悄跳过生产脚本解析。
- 多人场景使用多个模拟连接；涉及真实跨日、在线时长或随机命中的场景按实际条件运行，不能靠测试替身制造通过。
- 这是一份当前实现范围的**功能与流程全量目录**，不是所有地图×职业×模板×随机结果的穷举声明。参数展开表和精确报文模板尚待固定素材与逐项采集后建立。
- 不在本任务中改代码、部署素材、创建测试账号或写测试程序；当前运行的玩家测试服务保持原状。

## 3. 记录规则及通过标准

每个场景按下述状态逐级登记，禁止跳级：

| 阶段 | 初始状态 | 升级所需证据 |
|---|---|---|
| 前置数据 | 待准备 | fixture版本、账号/角色映射、必要道具/任务/额度及前置校验 |
| 人工流程 | 未执行 | 实际客户端操作、时间、观察及明确人工结论 |
| 原始采集 | 待采集 | 完整C2S/S2C、步骤标记、客户端/补丁/PVF/Host身份 |
| 基线 | 未固化 | 已确认正确的样本、动态字段规则、数据断言及批准记录 |
| 自动回放 | 未实现 | 模拟客户端按网络执行，逐项断言和独立失败报告 |
| 本轮结果 | 未执行 | 通过/失败/阻塞/未覆盖/不适用，加证据路径 |

每行最后的“☐ 待采集”只表示新基线任务状态。人工已验、已抓包、已固化、自动通过须分别记，不能勾一次代表四件事。另建每轮结果记录时保留以下字段，勿回写覆盖原始基线：

`caseId / runId / fixtureVersion / hostCommit / pvfSha256 / clientExeSha256 / clientHackBuild / accountRole / startedAt / rawCapture / normalizedExpected / stateBeforeAfter / manualVerdict / replayVerdict / issue`

共同判据：

1. **包**：endpoint、方向、CMD/NOTI族、type、长度、固定字段、必要顺序、接收对象及数量符合已批准客户端样本。没有响应的入口也要明确记录无响应契约，不能等不存在的ACK。
2. **数据**：金币/三币/材料/物品/任务/配额/关系的净变化与操作一致；目标实例UID及未修改属性保持；失败不出现部分扣除或部分奖励。
3. **后续行为**：下一步通过正常网络能够使用刚产生的结果；重要资产和进度用正常退出重登复核。标明重启的场景另用同一run.db重启正式Host。
4. **动态值**：票据、线上号、序号、怪物/掉落ID和时间从本轮合法响应绑定并验证关系；不能照抄旧录制值，不能大段mask。每项动态规则必须有字段依据。
5. **随机/时间**：不替换随机源和时钟。随机结果检查合法分支及资产变化，未自然命中的分支为“未覆盖”；跨日/等待场景未到时间为“阻塞”，不能自动绿。
6. **拒绝来源**：若原生客户端在本地拦截且根本不发包，记“客户端本地观察项，不适用服务器E2E”；不能编造C2S当成客户端样本。协议变异/坏包测试可另建补充集，不混入本基线。
7. **失败处理**：停止受影响的依赖链，保存首差异、原始包、日志及一致数据库快照；不循环重试成绿，不自动用实际输出刷新预期。

## 4. 素材、预设库与账号编排

候选素材是当前使用的 `E:/Project/DNF/DNFClient-A21-protocol/Script.pvf`，73,069,947字节，SHA-256 `3822A9ED183CD17F74DFEE9C11B8F2E84AF596B23972A737846022148FB05C6B`。这里只记录候选快照，尚未复制或纳入Git，正式素材仍应在采集前确认并锁定。

准备阶段使用正式Host建表/迁移，随后通过可复现准备脚本一次性填充所有场景。账号密码是专用测试凭据，运行期票据每次真实登录获取；不从玩家库复制凭据。baseline需要可再生的源声明、完整性/外键和业务前置校验，不能只留无来源二进制。

以下各组的 A_* / B_* / C_* 是**逻辑角色别名**，不是已经创建的真实账号；名称、accountId、characterId、槽位、模板ID、数量、任务ID、配额周期和关系ID在后续fixture清单绑定，不能用本表描述直接声称预设库已准备。多个别名可以在无状态冲突时对应同一账号；互斥前置（例如未婚与已婚、零次与满次、满包与空包）须用不同预置角色，全部在开测前准备。

| 数据集合 | 一次性预置内容 |
|---|---|
| 账号与角色 | 正常/空账号、多角色、当前支持职业与觉醒组合；各等级/经验边界、当前城镇与设置 |
| 物品与钱包 | 普通/绑定/限时/锁定独立装备、堆叠物、各级容器容量、金币与三币；每件装备保留完整实例值 |
| 任务与副本 | 可接/已接/达标任务、难度与地图权限、疲劳/票据/各系统次数，循环/镜像有效配对 |
| 关系与专用进度 | 组队以真实网络建立；预设未婚/订婚/已婚角色、婚房/胶囊、各塔下一层及SAO共享季 |
| 活动与时间 | 各活动期次、正式可配置日程/启停、领取状态、临近到期资产；真实时钟边界独立排程 |
| 邮件与管理 | 在线/离线收件、过期/已领邮件、无角色账号、管理员及只读权限；GM数据与客户端采集分开 |

生成完成后用SQLite backup API或干净停服后的完整一致快照形成baseline；不可忽略活跃WAL。每轮复制成独立运行库，baseline只读。固定日期、获得后N天、每日删除三种期限不能统一改成永久；必要相对日期由准备阶段生成并写入本轮manifest。

## 5. 执行顺序与依赖

本目录表格顺序是建议的场景编排顺序，不依赖xUnit发现顺序。场景内部按“准备/操作”从左到右执行。运行器应把整个连续链作为一项明确流程驱动，不能把有依赖的每步散成无序独立Fact。

- 主线链：ENV → AUTH → ROLE/SET/TOWN → INV/CARGO/SHOP/MAIL/USE/BOX → EQUIP/DISJOINT/CRAFT/PET/SKILL → QUEST/DGN/DROP/CLEAR/LIFE → 再次挑战 → 重登与重启。
- 多人链：AUTH → 两至三个账号正常入城 → PARTY → 普通/剧情/循环共享场景 → 单人退出/断线与对方观察。
- 特殊内容链：先通过基础DGN/DROP/CLEAR，再按各自预设账号运行循环、镜像、异界、塔、祭坛、大会及特殊活动图；不强迫同一角色先从1级刷到所有资格。
- 婚姻链：ENGAGE → WEDDING → HOUSE → CAPSULE；部分恢复边界使用预先准备的订婚/已婚专用关系，不能在中途直接改数据库跳阶段。
- 活动链：有效期和日程条件已满足 → 查询/参与 → 正常结算 → 邮件领取 → 重登；跨日/自然时长场景另排等待批次。
- GM为HTTP扩展集：管理员调用正式接口 → 玩家客户端接收/领取/消费 → 读收据与重登；不要求把HTTP请求冒称为DNF原生游戏包。
- RECOVER在相关资产链通过后执行；REPORT随真实入场/使用/退出自然覆盖。数据修改可能影响其他场景时，使用预先分配的独立角色，而非运行中重置库。
- 单独重跑中段场景时，从baseline恢复并网络执行其前缀，或使用事先批准的版本化检查点；禁止把失败后的数据库直接当新基线。
