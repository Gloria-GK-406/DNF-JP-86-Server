# 掉落抽取倍率

修改地面掉落抽取或调用倍率设置前阅读。对应 #277。

## 语义

原本抽 K 次，倍率 N 下抽 K×N 次；每轮独立重抽，单次概率、稀有度和物品权重不变。N 是 1～100 的整数，默认 1。

这是本服策略，不是原版算法：70 的全局爆率（`CDataManager::SetItemDropRate`，70Reference）缩放的是物品生成权重，上游没有全局乘区。

## 范围

只覆盖掉在地上需要拾取的产出。翻牌、塔和祭坛结算、开罐礼包抽奖、任务掉落（直发背包）、巨龙耗时奖励、教学奖励不在范围内，规则另行设计。

| 入口键 | 重复单元（1 轮） |
|---|---|
| `monster.gold` / `monster.stackable`（槽 1、3）/ `monster.equipment` | 普通阶段 K 次中的对应槽 |
| `monster.extra` | Extra 阶段 K 次 |
| `monster.declared` | 一次权重表抽取 |
| `independent.monster` / `independent.apc` | 全部行一遍 |
| `world` | 一次世界表抽取 |
| `object.random.gold` / `object.random.item` / `object.specific` | 物件的原 attempts |
| `hell.equipment` / `hell.epic_piece` | 深渊组奖励的原 attempts |
| `dimension.equipment` / `dimension.material` | 次元个人掉落一次；碎片是固定产出，单独入口 |
| `lostland.regular` / `lostland.boss` | 遗忘之地一次产出的对应部分 |

一次抽取只属于一个入口。祭坛、塔和深渊里的怪物掉落走同一生成入口，归上表对应项，不会再乘一次。

## 设置

`SetAsync` 设置一个入口，`CurrentAsync` 读快照。给什么设什么，每个入口只存一个值，存于 `drop_draw_multiplier`。

读取经 `IDropDrawMultiplierDomainService`，写入经 `IDropDrawMultiplierControlDomainService`，后者唯一的生产消费方是爆率活动。

不建模来源：每个入口只有一个值。爆率活动每次对账把 17 个入口都写成目标值，结束后写回 1，所以库里手工设置的倍率会被覆盖，首次启动也会全部写回 1。

## 爆率活动（#231）

GM 在活动管理页配置有效期和各入口倍率（存于该活动的 `event_configuration`），编号 7，显示在客户端活动页，倍率大于 1 时，玩家看到的标题和短名由倍率生成（“N倍爆率活动”，入口倍率不同时为“最高N倍爆率活动”），说明开头也写上倍率；GM 配置的标题和短名只在全部为 1 倍时显示，GM 列表仍显示配置值。到点开始或结束最多晚约 1 分钟，失败整体回滚并由下次对账重试。

证据：70 的 `CItemDropRatioEvent` 占槽位 7，开始时设倍率，结束时写回 1.0（`08533340`，70Reference）；算法不同，见上文“语义”。编号 7 在 A21 上除活动页列表外的含义未取证。

## 接入约束

- **规则不读状态**：领域服务读快照后传入。怪物掉落由 `MonsterDropDomainService` 读取；物件、遗忘之地和深渊组奖励由 `DungeonCellFactory` 读取，经上下文的 `DrawMultipliers` 传入。
- **随机流**：`DropRandom.ForRound` 在第 0 轮返回原种子，所以 1 倍结果不变；后续轮次按入口加盐，改一个入口不影响其他入口。
- **Extra 互斥**：Extra 命中只压制同一轮的普通道具，不影响金币和其他轮。
- **独立表**：单轮成功上限保留，总量不裁回单轮上限。
- **新增抽取入口**：先确定入口归属和重复单元，再按上述方式接入。

## 生效时机

沿用各入口的冻结边界。普通副本在建房时读取并冻结，所以副本进行中改倍率只影响之后新建的房间；塔的击杀掉落在击杀时读取。已生成的掉落不追溯。

## 容量

产出超限时**丢弃并记告警日志**，不合并、不分帧、不直发：

| 上限 | 原因 | 超出时 |
|---|---|---|
| 单次击杀 255 条落地物 | `0x0026` 条数为 u8（ClientStatic：`00D54DF3` 循环无其他上限） | 冻结时告警，死亡落地时截断 |
| 单房 255 条物件掉落 | 协议页记录 `0x001D` 条数为 u8 | 建房时截断并告警 |
| 塔击杀单次 255 条独立掉落 | 同一上限，作为塔帧的保守限制 | 生成时截断并告警 |
| 整局约 65535 个地面编号 | 线上编号为 u16 | 不再落地，无单独日志 |

截断的是靠后的轮次，1 倍路径不受影响。

## 验证边界

自动化覆盖 1 倍不变、K×N、入口隔离、Extra 互斥、深渊轮次、取值范围和存储。实机只按 20 倍验证掉落有明显变化；2026-11-02 用户在单图确认爆率明显提升，其余入口及 Boss、物件和退出重登未单独确认。100 倍和接近 255 条的客户端显示与拾取未经实机验证。
