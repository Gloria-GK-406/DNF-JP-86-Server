# 马战活动设置（2026-10-06）

用户授权：完成一版活动设置重构，不部署。基线 `8c9d28e4`，分支 `task/warehouse-storage`。以下为 CurrentImplementation / ServerPolicy，未新增客户端协议或补丁，不代表官方算法。

## 弹窗

| 页签 | 内容 | 生效范围 |
|---|---|---|
| 玩法参数 | 强势/常态/弱势战斗力倍率、攻击克制倍率、历史战绩先验场数、本期预测修正权重、投注衰减基数；PVF 骑士和奖励只读 | 保存后新生成场次，已有场次不变 |
| 每日赛程 | 每天七场，10:00 起，每隔 120 分钟一场；90 分钟投注、10 分钟封盘、三轮各 200 秒；列出各场开始/封盘/开战时间 | 固定只读，与客户端素材一致 |
| 当前场次 | 本场八名骑士的名称/ID、状态倍率、攻击类型、预测夺冠率、赔率、全体玩家投注量、真实累计胜败和胜率 | 每 5 秒只读刷新；单选后明确提交，不自动写入 |

活动的总有效期与启停继续在通用配置管理。旧库中的每日赛程自定义值不再用于未来场次；已有场次保存的时间快照保留，避免改变已接受投注的比赛。

参数范围：`0.1 ≤ 弱势 ≤ 常态 ≤ 强势 ≤ 3`；克制倍率 1..3（反向倒数）；历史先验整数 1..1000；预测权重 0..1；投注基数整数 1..1,000,000。默认分别为 `1.15 / 1 / 0.85 / 1.25 / 10 / 0.4 / 1000`。赔率曲线基准 1.1..16 与中性 2.0 不变。

## 本场冠军操作

仅当前活动生效、场次未结算且处于 `Locked` 时允许指定或取消。即封盘时刻（含）至首轮战斗开始（不含）；例如 10:00 场为 11:30 ≤ 操作时间 < 11:40。服务器取得事务写锁后重新取时，并在保存前再检查时间；浏览器仍显示可操作时也不能越过服务端边界。

只允许本场八位参赛者。指定后，冠军所在的三条晋级路径全部胜出；不相关分支沿用原抽签结果。第一次操作保存原始七场赛果；切换冠军总是从原结果构建，取消恢复原结果。封盘赔率及概率快照保持不变，结果产生后仍由原生命周期统一更新统计、记录赛果和调用邮件服务派奖；冠军计三胜。管理接口不派奖、不广播公告。

操作和管理员审计在同一事务提交。请求包含本场 `roundId` 和独立 `revision`，场次或管理员版本变化返回 409；阶段或骑士无效返回 400。保存结果未确认或版本冲突时，UI 锁住写入并要求明确重新读取核对；自动轮询不能自行解锁。下一场重新抽签，无内定冠军；本场操作随 JSON 保存，重启保留。

## 接口与边界

既有 GM 全权限身份；写入需 JSON、CSRF；未知字段与缺少必填字段拒绝。HTTP → GM 领域服务 → 马战领域服务 → 规则服务 → PVF 源；UI 不访问 PVF。

```text
GET  /api/gm/v1/events/joust/settings
POST /api/gm/v1/events/joust/settings
     {expectedRevision, parameters: {strongMultiplier,normalMultiplier,weakMultiplier,
       counterMultiplier,historyPrior,forecastWeight,bettingScale}}

GET  /api/gm/v1/events/joust/current-round
POST /api/gm/v1/events/joust/current-round/champion
     {roundId, expectedRevision, knightIndex}   // null 取消；字段不能省略
```

查询只读，不生成场次，不补结算，不冻结赔率，不发邮件或公告，也不暴露后台预抽签的冠军/完整赛果。返回显式指定的冠军供管理界面核对。

沿用 `event_joust_schedule` 的 JSON 配置表，新增 Parameters；场次 JSON 增加 AdminRevision/NaturalWinners/ForcedChampionIndex/ChampionUpdatedAt/ChampionUpdatedBy，无 SQL 表迁移。旧场次缺少参数时使用旧默认参数；既有赔率、赛果和时间快照不重算。
