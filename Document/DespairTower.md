日期：2026-10-11；实现基准：b2c3134e856183cf000a1b3ef6dd769472a11f30。

2026-10-20 当前实现：楼层按 1→100→1 循环。角色记录为最近已通关层数（兼容字段名 `highest_cleared_floor`），不是历史最高层；通关100层后保留100，下一目标映射到1，下一次通关第1层才把记录更新为1。旧版本100层后停止接受挑战的行为已修正；兑换尚未实现。客户端提交塔内任何楼层 ID 都映射到服务端下一层，不能跳层。只支持70级以上单人普通模式，不扣疲劳。用户于2026-10-20确认实机通关100层后循环到1层正常，按此范围记为ClientVerified并关闭[#174](https://github.com/Gloria-GK-406/DNF-JP-86-Server/issues/174)；奖励去重、回滚等边界仍以自动回归为证，不扩大实机验收范围。对应实现提交为`fb88c1696557c6a38bb74502dd6f0375bfac7b74`。

每日采用现有游戏日（UTC+8 06:00）重置：第一次入场免费；同日再次入场（含失败重试、通关后挑战下一层）扣除 PVF 声明的邀请函 4473 × 1；每日最多通关三层。邀请函必须携带，不使用共享材料。首入资格在成功入场时消费，失败或放弃不推进楼层。这是当前服务器结合 70Reference 首入/重试与 A21 PVF 三层/邀请函说明采用的规则，尚不是全部原生异常路径的 ClientVerified 结论。

资格、门票消费复用 [入场凭证流程](DungeonAdmission.md)。布局或房间创建失败会回滚门票、每日记录与暂存的运行态。每日计数由 UsageQuotaDomainService 通过 EventService.DirectAsync 更新；长期楼层存在 character_despair_tower。跨越每日重置的战斗归入其入场时的游戏日。

战斗使用普通地下城 Cell/APC 机制；部分楼层没有标记 BOSS 的单个 APC，需要清空敌对目标。服务器确认通关后，在一次结算事务中发奖、推进一层、增加每日通关计数并支付现有地下城结算经验。长期楼层和 run ID 条件更新阻止重复奖励。背包满的奖励转入系统邮件，奖励和推进一起提交。

2026-10-13 场景楼层牌修复（ClientStatic / CurrentImplementation，待部署实机验收）：墙上的数字来自地图中的被动物件 10386，客户端读取 NOTI001C 在小地图组之后的第一个 u16（无图标组时 offset 12）选择数字动画。旧构包误将 `01 00` 当成固定标记与保留字节，导致进入第 7 层仍显示 1；现在发送已冻结入场 plan 的实际层数，通关后留在场景也不会误显示下一层。普通地下城报文保持原字节，无需修改 PVF 或客户端。资源、客户端读取与绘制链路见[楼层牌取证](outputs/despair-floor-sign-20261013/evidence.md)。
