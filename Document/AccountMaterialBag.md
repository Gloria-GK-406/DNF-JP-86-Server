# 账号共享材料容器

2026-10-03 更新。原 `AccountMaterialBag` 余额模型已由普通物品容器替代；保留文件名供历史链接使用。当前代码与自动验证为 `CurrentImplementation`，本次尚未部署。集中实机步骤见 [共享材料验收](SharedMaterialHumanTest-20261003.md)。

## 模型与边界

六种晶体与五种品级灵魂以 `items + item_slots` 保存，复用 `IBusinessItemContainer`、`IItemDomainStore` 和现有领域事务。`ContainerOwner` 表达角色/账号所有权；账号金库和共享材料均是账号拥有的容器，种类与槽空间独立。账号共享是本服策略，不声称是 A21 官服数据库结构。

共享材料内部种类为 `SharedMaterial=240`，局部槽 `0..10`；240 不发送给客户端。A21 显示仍投影为 Main/354..364。每槽只能放指定材料，数量上限 `int.MaxValue`；普通目的容器仍使用自身容量、物品准入和 PVF 堆叠上限。

## 读写与事务

默认发放根据 placement 选择账号共享容器；明确移动到个人/账号金库仍是同一套普通容器移动。`IItemGrantDomainService` 和整笔 `AddAsync` 返回既有物品落点结果，不再分别结算余额与实体。共享槽容量不足时整笔拒绝，不向快捷栏溢出。

技能、强化等消费通过真实 `BusinessSlot` 扣除，沿用统一消费 effect 与回执。来源仍限各玩法已有的携带物/共享材料范围，不自动从个人或账号金库扣材料。分解、任务、教程、拾取、翻牌、购买、开包以及邮件领取等已有入口使用统一物品状态。配方原本不支持的共享材料产物、邮件显式来源资格等限制不因归一化扩大。

事务内同时暂存材料、普通物品、费用和玩法状态，成功提交后才发应答。错误槽、跨账号、超量或后续数据库失败不得留下部分写入。装备等实例移动继续保留 UID 与附加属性；材料堆叠按数量守恒。邮件附件整体托管结构未在本次容器化。

入场和 replay 只从共享容器读取材料事实，再投影到线级 `AccountVirtualResources`；它是协议形状，不是第二份存储。Main 普通 Items 不重复携带这些共享记录。非零增量校正来自事务后真实槽值；耗尽且 ACK 已扣除的材料不发送正 itemId/count=0 的获得通知；无此 ACK 的清除沿用空槽通知。

## 旧库迁移

启动初始化在自身 SQLite 事务内执行 `account-shared-material-v1`：逐账号读取旧 11 列，非零数量导入固定槽，零数量不创建物品；同事务写入 `schema_migrations` 标记。合法高数量不按普通 PVF 上限截断。负数、非整数、越界数量或非法账号拒绝迁移；插入故障回滚物品、槽及标记。

首次迁移若已有任何 SharedMaterial 槽，或其他 item_slots 中已有这 11 种材料，会报告实际位置并拒绝，不猜测合并。需根据来源处理历史数据后再迁移，不能简单删除冲突行。邮件附件历史托管不在该冲突扫描范围。

迁移完成后，`RetiredColumnMigration` 确认标记存在再删除旧 `cube_* / soul_*` 列；新建库从一开始就没有这些列，迁移在列不存在时只写标记。旧列删除后不能直接回退旧版本，需要回滚时恢复部署前完整备份与匹配程序。部署前应停服备份完整数据库并先检查冲突。

账号槽唯一键包含 owner scope、owner id、list type、slot；旧的只按账号与槽号去重的索引已移除。账号金库读取限定 list type 12，不会吸入共享材料 240。

实现锚点：`SharedMaterialMigration`、`CharacterBusinessInventoryDomainService`、`ItemPlacementRuleService`、`CargoTransferDomainService`、`InventoryEntryAssembly`。自动证据与交付状态见 [任务结果](tasks/unify-item-containers/spec-result.md)。
