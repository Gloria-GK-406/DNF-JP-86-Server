# 账号材料袋模型

## 目标

六种晶体与五种品级灵魂统一归入账号级 `AccountMaterialBag`。角色不再以普通 `item_slots`
持有这些材料；同一账号的任意角色通过账号 id 获得同一个领域实例与同一份持久化状态。

宇宙灵魂（itemId `3257..3260`）明确不进入本模型，仍是角色材料栏中的普通堆叠物。

采用的明确策略，不宣称是 A21 官服数据库结构的取证结论。

## 领域与事务

`AccountMaterialBagDomainService.Get(AccountId)` 是唯一入口。服务在单进程内按账号缓存实例，
因此同一账号的两个角色得到同一实例；跨进程契约仍以账号 id 和数据库记录为准，不依赖引用相等。

所有“新物品到达角色”的生产路径统一通过 `IItemGrantDomainService` 分类。地面拾取、翻牌、任务
接受/完成、怪物任务直发和教程奖励命中上述十一种 itemId 时都会进入账号材料袋；普通物品才继续
进入角色容器。角色容器的最终写入边界还会拒绝这十一种 itemId，防止新调用方绕过分类后重新
制造角色材料真源。购买/开盒等尚未接入账号材料发放语义的路径如果意外产出它们，会整体拒绝并
回滚，而不是静默写入角色槽；后续为这些玩法接入账号材料时仍复用同一个 Grant 服务。

SQLite 存储作为现有 `SqliteDatabaseParticipant` 的一个 facet 加入领域事务。分解时按以下顺序
暂存变更，并由同一次事务统一提交：

1. 删除被分解装备；
2. 若使用便携分解机，扣除一台；
3. 普通产物进入角色背包；
4. 晶体与品级灵魂增加到账号材料袋；
5. 提交成功后才生成应答与通知。

任一步失败都会回滚装备、便携工具、角色材料和账号材料，不允许出现多个真实源。

## 协议投影

登录全量快照通过 `NOTI 0x000D` 投影账号材料的非零绝对值。分解成功后，`CMD 0x001A`
应答中的材料列表表达本次产量，随后用 `NOTI 0x000E` 将受影响虚拟槽写成事务后的绝对总量。

旧版错误写入角色材料栏的晶体与品级灵魂不自动迁移，也不自动删除；本次开发由用户手工清理，
避免服务器在缺少归属证据时猜测旧数据应转入哪个账号余额。
