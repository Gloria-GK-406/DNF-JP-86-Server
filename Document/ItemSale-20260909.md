# NPC 出售物品（2026-09-09）

`CMD 0x0016` 沿既有 `Command → 领域服务 → Event` 路径实现。
协议层只解码、校验字段和、提交命令及编码结果；规则服务读取 PVF 售价定义；
领域服务在同一事务中增加携带金币、扣减或清除物品。事务提交后 Event 发送单次成功应答。

成功应答由客户端同时更新金币和扣除物品，不追加重复扣物通知。
投递失败不重试这种扣减应答；重登按持久化状态恢复。

## 当前规则（2026-10-11）

出售资格和计价独立：强化、封印、增幅、锻造、随机词条、禁止赠送/交易/分解等均不表示禁止 NPC 出售。
仍校验会话、物品存在、数量、装备锁、过期状态及携带金币上限；显式禁售字段才影响出售许可。
按用户决定，出售不校验 NPC ID、商店定义、城镇位置或地下城通关状态；任意 NPC ID 均允许进入出售流程，ID 只保留在请求和成交／拒绝日志中。不影响 NPC 购买的商店、位置和商品资格校验。
本次验证：Release 解决方案构建 0 警告、0 错误；Application 3642 项、Protocol 1445 项通过，共 5087 项通过，无失败或跳过。覆盖空商店表、任意 NPC ID、未清场与已通关场景，以及既有装备锁、金币上限、重复出售和事务失败回滚。实际客户端验收待用户测试。
装备读取根作用域的 `[value]`、`[durability]` 和售价表，按既有基础价公式计算，不读取附加效果块的同名字段。
不额外推测强化等状态的客户端特殊售价加成，其价格一致性仍需实机验证。

缺失、重复、格式错误的计价数据及不支持的价格定义返回零价；领域服务记录 ERROR，包含角色、物品 ID/UID、槽位、数量、完整实例状态及失败原因。
合法的显式零价不报 ERROR。零价成交同样消耗物品，返回一次正常成功 ACK；数据库/事务失败继续抛出并回滚，金币空间不足继续拒绝整笔出售。

真实 PVF 中 101040127 的根 value=104960、耐久上限=48，106020145 的根 value=91840、耐久上限=34。
满耐久基础价分别为 18892、16531；仅为 CurrentImplementation/ContentStatic，未据此扩大 ClientVerified。

## 2026-09-09 支持范围

- 城镇中的已选角色，主背包 3..353 槽的普通装备和有明确 PVF 顶层 value 的堆叠物品。
- 普通装备按客户端的耐久、售价表、float32 截断及 90% 折算计算。
  锋利的印度古剑 value=12960、耐久 45/45，单件所得 2332，与客户端确认框相符。
- 堆叠物品逐件取整后乘数量；允许零价。缺失或不可信价格定义拒绝，不回退到购买价。
- 数量越界、过期物品、锁定物品、无商店 NPC、错误会话拒绝；携带金币空间不足整笔回滚。
- 穿戴栏、时装、宠物、特殊装备价格分支及任务收集进度联动尚未覆盖。
  特殊装备标记（强化/封印/增幅/随机属性/升级等）存在时保留物品并拒绝出售。
