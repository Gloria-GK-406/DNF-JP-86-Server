# 掉落内部切分与证据清单

日期：2026-09-23；改造基线：`0e8646f7`。授权范围：明确来源迁移重构，未知来源用空壳函数占位；不改变对外 Ground/Personal 接口。证据盘点和原始资料见[掉落来源实施方案](掉落来源实施方案.md)。

## 当前结构

- `MonsterDropDomainService.GenerateGroundAsync` 顺序组合普通、extra、怪物声明、独立、世界、特殊模式入口。普通与世界来源运行，其余入口明确禁用、返回空集合，不访问档案、不消耗随机数。
- 普通来源集中在 `MonsterDropDomainService.Sources.cs` 的 `GenerateOrdinary`，保留掉率调整接缝和缺等级表警告。`DropRuleService` 将金币金额 `DrawGold` 与物品 `DrawItem` 分开；触发门、随机调用顺序、品质和候选池算法保持原状。金币不是额外再抽一次的来源。
- `GeneratePersonalAsync` 仍校验目标参与者，调用任务领域服务。领域服务只查询该角色的任务与库存；`QuestMonsterDropRuleService` 读取任务静态定义并组合来源；`QuestMonsterDropRules.DrawMonsterRewards` 是纯计算，不读角色状态。内部传事实不改变外部只传身份的约定。
- 任务的 `DrawEnemyRewards` 是独立空壳，不把未知标签混入已工作的 monster reward 算法。
- 每怪一次地面生成、每人一次个人生成，合并到原有 PendingLoot。归属、投递方式、死亡发放上限、整图编号和协议保持既有流程。

这是具名函数与规则层切分，没有引入通用来源插件框架。顺序只表达本服编排位置，不证明所有来源在原版同时叠加；启用占位前还必须裁决替换/追加关系。

## 已完成与未闭合项

“迁移完成”表示保留本服既有规则并通过回归，**不表示已经证明原版算法**。

| 来源 | 当前实现状态 | 仍需证据或算法 |
|---|---|---|
| 普通装备、材料/消耗品 | 已迁移；类别触发→品质→品级候选池抽取完整保留 | 类别槽语义、品质阶梯索引轴、基础率分母与稀有度边界仍需原版消费证据 |
| 普通金币 | 已独立计算函数；保留基数、浮动、怪物等级/类型倍率 | control 表的条件轴、单位和应用时机未实现；不能把概率倍率同时当金额倍率 |
| 任务 monster reward | 已拆事实查询、静态规则读取、纯抽样；匹配怪物/地下城/难度、角色归属、库存及授予上限保留 | 同目标多任务目前沿用任务顺序和同物品 planned 数量保护，是否符合原版选择/合并语义仍待证实 |
| 普通 extra | `GenerateExtra` 空壳 | 替换普通、追加抽取还是特定场景选择，尚未定案 |
| 怪物脚本 [item] | 已接入启动全量缓存、每怪一次抽取 | 本服采用 max(10000, 总权重) 分母，超万必掉一件；不按人数重复，不采用上游10%外层门。见[怪物声明掉落规则](怪物声明掉落规则.md)，尚未实机验收 |
| 指定怪物独立掉落 | `GenerateIndependent` 空壳 | 五数量字段的轴、末尾筛选字段、内嵌 list 的相对权重/固定分母语义 |
| 世界掉落 | 已接入启动缓存与累计区间抽取，见[世界掉落规则](世界掉落规则.md) | 当前采用每怪一次、基数100000的本服政策；原版分母与次数仍待证 |
| 任务 enemy reward | `DrawEnemyRewards` 空壳 | 标签格式、触发对象及与 monster reward 的组合关系；当前 QuestDefinition 尚未承载该声明 |
| 深渊/特殊模式 | `GenerateSpecialMode` 空壳 | 事件结算时机、轮数、难度轴、与普通掉落替换关系；不能逐怪重复发完整事件奖励 |
| 异界外部池 | 独立来源的未启用能力 | 当前 A21 对应索引/表为空，需要匹配版本的有效数据及职业/难度映射 |
| 场景物件 | 保留原入口，未接到怪物生成 | 奖励组完整权重、触发时机、物件声明与 object 表去重关系需独立处理 |
| 通关翻牌 | 保留已验收的结算入口 | 不接到逐怪生成；本次未变更算法 |
| 活动/任务助手掉落加成 | 保留既有调整接缝，不新增倍率 | 加成适用来源与次数/概率/数量口径；禁止对所有来源统一乘倍率 |

未知来源的空返回是用户授权的禁用占位，不是对异常的吞没。正式启用时，必需引用缺失、格式错误、未知模式须显式报错；正常未命中才返回空集合。

## 后续优先取证

1. 独立掉落：先裁决五数量列和 list 抽样语义，决定正式生成算法；原服差分方法见来源实施方案第 4 节。
2. 普通掉落：复核类别/阶梯/分母与金币 control，当前代码不能作为原版算法的自证。
3. 世界、怪物声明：确认外层触发与空结果，再实现生成，避免大幅增加产出。
4. 任务 enemy reward：先读真实声明与消费链，再接规则模型。多任务同物品规则另行核对。
5. 特殊模式和物件按各自生命周期处理；异界先补数据。

世界来源已具备启动全量索引；其他来源的全量索引、来源级 SourceKind/RuleKey 诊断和独立模拟统计工具仍是未完成能力；本次只固化来源函数与任务计算边界，未宣称它们已交付。后续新增来源需要独立随机流，不能消耗普通/任务的既有随机序列。

## 验证

掉落、房间、死亡、副本运行和命令架构相关测试 122 项通过；全解决方案构建零警告、零错误。覆盖原有掉落行为、双人归属隔离、动态查询、64 个种子的普通来源组合一致性、多任务同物品数量保护，以及任务 0/100 概率边界和重放。未部署，未新增实机或原版概率验证结论。
