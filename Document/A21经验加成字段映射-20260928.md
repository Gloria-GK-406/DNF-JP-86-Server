# A21 经验加成字段映射

调查日期：2026-09-28。范围是即时经验 `NOTI 0x0025` 与通关结算 `NOTI 0x0023` 的客户端消费、既有实机证据及当前服务端投影。未修改经验算法、角色数据或运行中的服务端。

## 证据与口径

- **ClientVerified（既有）**：2026-08-28 两轮即时经验槽位探针；本日用户确认领主分类显示 `+362`。本轮没有新增非零加成实机实验。
- **ClientStatic**：客户端读取、存储、求和及 UI 文案引用；详见两份报告中的镜像哈希、地址口径和汇编。
- **CurrentImplementation**：本仓入账与消息投影；不用于证明官方规则。
- **UpstreamImplementation**：参照服参数与算法，仅用于提供候选。

`ExperienceBreakdown` 表达一次实际获得的奖励；UI 槽表达客户端如何显示该奖励。两者不能直接视作同一套枚举。通关结算还包含此前已发出的击杀摘要，这部分不得再次加进通关 `Total`。

客户端由累计经验差算本次增量，再扣部分明细得到基础值；不是将这些明细再次加到人物经验。当前角色成长封顶而奖励不截断的服务端规则，仍可能造成满级时弹字差值与实际奖励概念不一致；本轮未改变该通知策略。

`Channel → 赛丽亚的祝福` 是当前服务端的选择，实机只证明显示名，不能据此宣称官方业务同义。`0x4B` 已证是“赛丽亚的欢迎”，不能按上游旧名称写频道奖励。

`0x2F` 显示“Buff奖励”却不参与基础减法；`0x33` 参与减法却不显示。当前普通投影继续将它们保留为零，不用单槽承载新增来源。`0x22/0x37/0x47` 不出现在这条弹字中，不代表它们在客户端所有功能里无用。

新增显示合计从 `base-party`（差为负则回退base）起算，加 `S[1..19]` 和三个特殊字段 `+0x708/+0x634/+0x638`。i16/i18不进入这条求和，可承载此前已付的击杀加成摘要；本仓需从击杀入账回执累计真值。**K整体并非纯击杀**，因为K[5]已经混合i8与i15；J也重复接收通关加成。

## 下一步实现边界

主要经验来源的协议位置已足以进入成长契约、经验药、燃烧疲劳的实现设计，尚不是全部功能实机验收。

1. **成长契约**：击杀即时通知写 `0025 +0x1E`；通关新增奖励写 `0023 i9`；已发击杀契约加成累计写 `i18`。后两项不能再次相加入账。既有PVF调查记录type84及`[bonus exp] 20`，读取/过期判断与倍率应用仍须在业务规则中明确。
2. **经验药**：通关明细有已证实的“远古精灵的秘药”槽 `i1`。即时经验通知没有已证实专用药名，不能照抄上游把它借填“疲劳值Buff”。可先在即时通知中让它留在基础增量内，通关面板单列真实药效金额。药效是否仅通关、乘算基数和同类覆盖策略是业务规则，需要结合具体PVF物品确认，UI标签不能证明倍率。
3. **燃烧疲劳**：击杀即时写 `0025 +0x26`，通关新增写 `0023 i10`，已付击杀加成累计写 `i16`。只有奖励事实变化才更新累计，不能由结算面板再次发同一笔奖励。
4. **领域模型**：继续让计算服务返回每次奖励record；给副本参与者摘要补充已发击杀加成的来源分解；协议层分别投影即时、新增通关和历史摘要。黑钻、装扮、宠物、冒险团等来源将来接入时再扩充固定业务字段，勿把所有UI索引泄漏到领域。

明确保留的缺口：i4/i6/i11/i22业务名、`+0x65C`最终呈现、即时通知变量列表键空间、Buff两槽联填的实机效果、满级累计封顶的弹字策略。它们不阻塞上述主要来源的保守接入。

最小后续实机方案：保持基础/评分可识别，给通关秘药/成长/燃烧和已付击杀成长/燃烧五项各一个不同小值，检查两类明细及新增合计。示例：base1000、rank100、新增药11/成长13/燃烧17，则新增总额应1141；历史击杀成长19/燃烧23只供摘要，不能再加42。所有值应来自隔离测试的真实入账或明确的一次展示探针，不能把伪造通知当作奖励实现验收。本轮未执行该实验。
