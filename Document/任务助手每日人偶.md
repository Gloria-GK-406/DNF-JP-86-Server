# 任务助手每日人偶

日期：2026-09-25。实现起点：main `42d36794`。规则来源为本轮用户裁定；不声明还原 70 或 A21 官方发放算法。

## 登录补齐

选角清理过期物品后、读取登录邮件列表前执行独立 `EnsureDailyContractPuppetsCommand`。
没有定时全服扫描，没有新增客户端请求或协议字段。

1. 校验角色归属及账号任务助手订阅（582 / slot2）当前有效。
2. 按 `Game:DailyResetTime` 与 UTC+8 业务时区检查角色的本周期处理记录。
3. 汇总背包（包含快捷栏）、角色个人仓库和未过期邮件中的未领取附件。
4. 将缺少的每种人偶各补 1 个，合并为一封系统邮件；发件角色 ID 为 0，名称为空。
5. 无论需要发信与否，都写入本次完整 UTC 时间戳。无订阅不写记录，当天购买后重登仍可检查。

角色之间独立计算，不统计其他角色和账号共享仓库。已读但未领取的附件仍然计入；已领取、过期或删除的邮件不再阻止补齐。
当天消费人偶后重登不再补发；下一业务日登录才重新检查。离线多天只检查当前周期，不累积补发。

## 原子性与库存边界

发信与检查记录在一个命令事务提交，先取得数据库写入锁再读状态。发信或记录失败均回滚，可重新登录重试。
记录复用 `character_daily_counters`，key=`quest_helper_puppets_checked`，value=1，`last_consumed_at` 在此键下表示最后检查时间；period 保持 NULL，每个角色只有一条覆盖更新的记录。

个人仓库已有 `item_slots` 的角色归属与 `PersonalCargo` 容器读路径，本次实际统计它，并未假定仓库为空。
以后仓库存储变化只需调整补发领域服务内部的库存查询；登录 CMD、邮件和每日规则不用变化。

登录顺序测试固定新增 CMD 在过期清理之后、邮件快照之前。真实 PVF 测试验证四个 ID 和可持有的单件堆叠定义。

建议实机：有效订阅角色重登收一封四附件邮件；再重登不新增；领取部分后重登不新增；跨业务日仍持有或未领取的不补，只补缺少种类。人偶召唤另行验证。
