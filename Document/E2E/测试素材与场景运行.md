## 一个场景、一个服务端、多个账号

1. 验证素材 SHA-256 和部署频道脚本身份。
2. 从同一个 baseline.db 复制本场景私有 run.db，启动一个完整生产 Host。
3. 场景内可使用不同账号/连接并行执行 case；各 case 内的业务顺序与状态连续保留。
4. 整个场景完成后保存报文、快照与人工结论，退出全部客户端并停止本场景 Host。
5. 下一场景从 baseline.db 重新复制到新的运行目录，再启动 Host。旧运行目录保留为证据，不在服务运行期间覆盖数据库。

例如首次训练、完成/退出、第二次进入属于同一连续 case，三步之间不重置。
并行 case 按连接/角色验证必要顺序和交互关系，不将跨连接线程交错强行固定为一条总顺序。

```powershell
python Tool/E2E/scene.py --verify-only
python Tool/E2E/scene.py --scene login-create-town
```

启动器读取当前本机 `http://127.0.0.1:18080/`；Channel 为7001，普通 Game 频道由生产脚本推导。
工具会检测端口可绑定、复制数据库、启动独立 Host，并核对 HTTP 和 Game 就绪；端口冲突直接拒绝，不停止其他进程。
首批关闭 PVP 频道（本机10060不可绑定），保留完整生产脚本和普通频道；本轮不覆盖 PVP。
Linux runner 保留供以后无客户端回归，当前实机采集不需要 SSH 隧道或把游戏服务迁到 Linux。

工具打印本场景 PID、run.db、frames.jsonl、HTTP地址和数据身份，保存于 `artifacts/e2e-collections/<场景编号>/collection.json`。
就绪探测只产生一个未认证 Game 连接，元数据明确标注为控制流量；正式业务采集从用户真实登录开始，不能把该探测算入 case。

## 全帧记录

仅在采集 Host 设置 `Networking:FrameCapturePath=<全新文件路径>`，平常不配置即关闭。
传输层在解包后、业务解码前记录所有已成帧 C2S，包括未注册入口；S2C 在唯一发送点记录实际编码字节。

- 一帧一行 JSON，含全局观察序号、UTC、连接ID、端点、方向、selector、CMD/NOTI、opcode、入站seq、头长及完整hex。
- Game C2S头14B、S2C头15B，Channel头11B；没有4096字节截断。
- S2C先记 send-attempt，随后以相同sendId记录是否已flush；失败或没有确认的发送不能当作成功交付。
- Channel保留实际加密/压缩的完整线上帧；其解码资料仍属于协议知识库。HTTP有独立Host访问日志，不混作Game协议帧。
- 不覆盖旧记录；写盘失败会使采集操作显式失败。原始帧含临时票据，保留在本地私有采集目录，不提交Git或上传公共报告。

该记录器只保存流量，不批准预期、不生成业务 case。正式 E2E 仍须根据真实客户端操作和人工确认的流程编写。
