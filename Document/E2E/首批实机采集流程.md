# 本机首批实机采集：登录、建角、入城、训练

此流程使用本机新启动的隔离服务和现有 DNFClient-A21-protocol。Linux runner 留给以后的无客户端 CI。本轮正式样本尚未采集签收，正式通过数为0。

## 固定起点

[素材与场景说明](测试素材与场景运行.md)给出仓库内的 PVF、构建好的专用数据库及账号角色映射。每个场景从 baseline.db 复制一个 run.db，场景中可用多账号并行做 case；全部 case 收尾后停止本场景 Host，再从固定起点开启下一场景。不是每个 case 或每个操作都重置。

```powershell
python Tool/E2E/scene.py --verify-only
python Tool/E2E/scene.py --scene login-create-town
```

工具打印本场景 PID、运行库与帧记录绝对路径，保存在 collection.json；不得把仓库 baseline.db 直接作为 Host 写入库。当前使用普通频道，PVP不属于本批。

## 人工操作顺序

1. 用 e2elogin 登录，选择普通频道，停在选人界面，确认空角色列表；正常退出客户端。该账号用于登录与下线采集。
2. 用 e2ecreate 登录，在真实建角界面选择职业、输入新名并创建角色；停在角色列表，记录实际名称、职业和画面。
3. 选择刚创建角色，记录实际进入训练/城镇的表现与完整入场消息。不要在流程中重置数据库。
4. 用 e2etutorial 的1级 E2ETutorial 收集首次训练流程，正常完成或走客户端真实支持的完成/跳过路径。记录实际退出行为；不能把仅进入当作完成。
5. 同一个角色退回选人再进入，并正常退出重登复核是否再次进入训练。前后是同一个连续case，中间不重置。
6. e2eroster 的两个1级角色保留给独立账号并行/角色切换的收集；多人同步需要实际多连接，不能从单连接推断通过。

这些是待采集步骤，不是已经确认的响应预期。失败时停在首差异并保存现场，不能继续重试到绿后覆盖失败。

## 证据和标记

Tool/E2E/collect.py 仅记录身份、人工标记和SQLite一致快照，不创建业务数据、不发业务请求、不批准预期。场景目录已经含collection.json，可直接打标与取快照：

```powershell
python Tool/E2E/collect.py mark --out <本场景目录> --step LOGIN --phase before
# 在真实客户端进行这一步
python Tool/E2E/collect.py mark --out <本场景目录> --step LOGIN --phase after --observation '<实际观察>'
python Tool/E2E/collect.py snapshot --out <本场景目录> --database <本场景目录>/run.db --name 01-after-login
```

每一步保存前后快照、人工观察和截图，关联本场景 frames.jsonl/host.log。SQLite backup API包含已提交WAL数据，不能只复制活跃主文件。服务器就绪探测连接已在collection.json标为控制流量，不计入业务case。

Game/Channel完整帧记录由服务端完成，字段和发送确认规则见素材运行说明。HTTP启动器访问另见Host日志，不混作Game协议帧。原始帧包含临时票据，保持私有；不覆盖旧文件，不提交运行库和原始认证流量。

## 转成自动化case

先人工确认实际流程与业务结果，再按连接重组操作和必要响应顺序，对照数据库净变化；明确动态票据、ID、时戳和seq的绑定关系。场景库作为固定测试材料入仓，报文预期必须依据真实采集审核后固化。收到ACK或当前服务器没有异常都不足以签收。

采集签收后才编写无客户端case和更新台账对应阶段。现有6个合成冒烟仍独立保留，不计正式覆盖。
