## 2. 推荐拓扑和前置准备

Windows 真实 Launcher/A21 → SSH 隧道认证 → Linux 隔离 Host；Channel/Game 由客户端直接连 Linux。
Linux tcpdump 同时记录回环 HTTP 和 LAN Channel/Game，数据库每个阶段通过 SQLite backup API 取一致快照。

1. 在 Linux 独立采集源码目录从选定 main 提交构建正式 Host，记录该提交、是否有脏改动、实际 DLL/PVF 哈希。
   不沿用旧冒烟产物和合成数据库。当前 PVF 与客户端为同一 SHA-256：
   `01f1be685d46647961df65207a36304777db20ef5a3d03c68efaa92f8b0c5189`，本轮启动前重新核对。
2. 为本轮新建私有采集目录。Host 正常启动生成当前结构空库；随后由操作者在真实 Launcher 注册专用测试账号。
   空库仅是准备起点，真正的场景前置来自实际操作后保存的快照，不用 SQL 造角色/物品，不复制玩家库或旧 smoke baseline。
3. 确认无人占用 18080、7001 和频道脚本的 Game 端口；有冲突即停止准备，不结束已有进程。
   采集期间不手动运行独立冒烟 CI。使用完整生产频道脚本，不替换时钟、随机或业务组件。
4. 保存客户端原始配置和插件清单；不改既有客户端 DLL/EXE。记录实际运行进程路径和 ClientHack 本轮启动日志。
5. 原始 pcap 会包含专用账号凭据和临时票据，保持私有，不进 Git/Actions artifact；另制脱敏分析副本。

Linux 首次准备采集专用源码目录（仅目录不存在时执行；不会改已有玩家服务）：

```bash
gh repo clone Gloria-GK-406/DNF-JP-86-Server "$HOME/dnf-e2e/collection-src" -- --depth 1 --branch main

export HOST_DLL="$HOME/dnf-e2e/collection-src/Server/src/Dfo.Server.Host/bin/Release/net10.0/Dfo.Server.Host.dll"
export PVF_ARCHIVE_PATH="$HOME/dnf-e2e/assets/Script.pvf"
```

第 3 节初始化本轮目录后，将以下命令用于采集 Host 终端，另开终端抓包和打标记；
保留本轮的源码提交、构建输出和启动配置。`collect.py` 尚在本任务分支，须先放到采集工具目录或通过绝对路径调用，
不能假设 main 已包含它。也不因此把采集 Host 换成旧 E2E 分支的服务端产物。

```bash
dotnet "$HOST_DLL" \
  --Database:Path="$RUN/run.db" \
  --LauncherAuth:Enabled=true --LauncherAuth:ListenUrl=http://127.0.0.1:18080 \
  --LauncherAuth:PublicChannel:Host=192.168.8.210 --LauncherAuth:PublicChannel:Port=7001 \
  --Networking:Enabled=true --Networking:ChannelPort=7001 --Networking:UdpDiscoveryEnabled=false \
  --Channel:UseScriptCatalog=true --Channel:IncludePvpChannels=true \
  --Channel:PublicServerIp=192.168.8.210 --Game:EndpointHost=192.168.8.210 --GmWeb:Enabled=false \
  2>&1 | tee "$RUN/host.log"
```

Linux 抓包应在打开 Launcher **之前**开始，另一个终端保持前台运行：

```bash
sudo tcpdump -i any -s 0 -U -w "$RUN/native.pcap" \
  'tcp and (port 18080 or port 7001 or portrange 10001-10255)'
```

`RUN` 必须指向本轮私有采集目录；结束时 Ctrl+C，保留 tcpdump 收包/丢包统计。先确认该目录未混入其他服务流量。
`-s 0` 保存完整包；后续须按 TCP sequence 重组，不能把一次 recv 或一个 TCP segment 当成完整游戏帧。
第一批不涉及战斗/P2P，UDP 证据不在本轮范围。

## 3. 记录工具（不代替实际操作）

`Tool/E2E/collect.py` 只记录文件身份、人工标记和真实 SQLite 快照，不发业务请求，不制造预期，不批准基线。

Windows 创建当前客户端清单（输出文件必须尚不存在；传输至 Linux 本轮目录归档）：

```powershell
New-Item -ItemType Directory -Force artifacts | Out-Null
python Tool/E2E/collect.py client-manifest --client-root E:/Project/DNF/DNFClient-A21-protocol --out artifacts/client-manifest-<本轮唯一编号>.json
```

Linux 在本轮目录不存在时初始化元数据，再用该目录启动采集 Host：

```bash
export RUN="$HOME/dnf-e2e/collections/<本轮唯一编号>"
python3 Tool/E2E/collect.py init --out "$RUN" --host "$HOST_DLL" --pvf "$PVF_ARCHIVE_PATH"
```

每个动作前后由操作者明确打标记；观察文字如实填写，不预先写“通过”：

```bash
python3 Tool/E2E/collect.py mark --out "$RUN" --step LOGIN --phase before
# 此时在 Windows 真实 Launcher 执行该动作
python3 Tool/E2E/collect.py mark --out "$RUN" --step LOGIN --phase after --observation '<实际观察或失败现象>'
python3 Tool/E2E/collect.py snapshot --out "$RUN" --database "$RUN/run.db" --name 01-after-login
```

快照工具只读打开源库，经 backup API 包含已提交 WAL 数据；不靠复制活跃 `.db` 文件，不改源库。
源码提交、端口配置、截图文件、pcap 统计由操作者一并写入本轮记录；元数据生成不代表样本签收。

## 4. 第一轮实际操作顺序

| 步骤 | 人工操作与停点 | 应保存的实证 | 对应目录项 |
|---|---|---|---|
| PREP | 正常 Host 建空库；真实 Launcher 注册专用账号，暂不点登录 | 原始注册流量、无角色账号实际状态、00-before-login.db | 准备阶段，不算正式通过 |
| LOGIN | 打标→真实账号登录→按实际 UI 选择频道→停在选人界面 | Launcher/Channel/Game 原始流量、空角色列表截图、01-after-login.db | AUTH-001、AUTH-003、AUTH-004 |
| CREATE | 打标→在真实建角界面选职业、填写合法新名→确认→停在角色列表 | 记录实际职业/名称；查名/建角/名单刷新原始流量、列表截图、02-after-create.db | ROLE-001 |
| ENTER | 打标→选择刚创建角色→等实际进入城镇并可操作 | 全部入场通知/请求及真实先后、人物/背包画面、03-after-enter.db | ROLE-004 |
| RELOGIN | 游戏内正常退出，完整保留 flush；重新 Launcher 登录，再选原角色入城 | 退出和重登流量；身份/起始资产/位置实际观察、04-after-relogin.db | 上述项的持久化复核，不新增“已通过”项 |

每步失败就停止受影响链，记录失败停点、窗口表现和现有证据，不继续点到成功后覆盖首次失败。
先使用一个实际选择的职业做单一路径，职业矩阵后续单列；不从“一项成功”推断所有职业或全量入场正确。

## 5. 采集质量与签收门槛

首次联通预检先查：双向 TCP 是否齐全、请求头实测为 A21 14B、响应头 15B、CMD/NOTI 从真实头部区分、
完整 body 无 4096B 截断、客户端没有报错/卡住。比对 Host 日志仅用于查缺，不能补造客户端没发出的请求。
若抓包丢包、端口漏抓、连接目标错误或客户端中途崩溃，本轮不得固化。

人工逐步确认 UI 与业务结果后，再审核 pcap、步骤边界和数据库净变化。保留原始证据的哈希和采集身份，
标出动态票据/ID/时戳/seq 的绑定关系；不能整包屏蔽差异。当前只准备流程，没有填入任何精确回包预期。

经签收的初始场景快照与步骤预期才可成为正式 baseline；自动化运行复制它，不能使用旧 smoke 生成的库。
之后逐项编写 case，并用相同采集版本检验，再更新台账的相应阶段。没有签收时正式通过数仍为 0。
