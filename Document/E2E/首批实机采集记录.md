## 本次实际报文观察

本次真实业务连接为 `Channel:02-00-00-00` 与 `Game:12-00-00-00`（10010）。到选人界面退出共记录 46 个业务帧，帧长度检查通过，全部业务 S2C 都有成功 flush 确认；早先探测连接的发送失败不属于此次业务流。

- Channel 请求为 `0B → 09 → 11`，对应响应为 `0C → 0A → 12`。本次未观察到独立 `05` 请求，不按旧工具的预设序列补造。
- Game 登录请求为 `CMD 0001`，总长88B，入站 seq 从0开始；随后收到成功响应与实际登录通知批次。
- 客户端还实际发送 `00AB / 01DD / 04F1 / 04D7 / 0008 / 0286 / 00C5 / 02A8 / 01BA / 0002` 等请求。完整顺序以原始流量为准，定时 `04DD` 不固定成跨连接或跨采集的唯一总顺序。
- 正常退出观察到 `00C2(376B) → 00FA(70B) → 0117(26B) → 0003(15B)`，`CMD 0003` 响应16B，随后还有 `02B3(15B)`。长度均包含帧头；不能省略尾帧后称为完整抓包。

这些是本机本版本实际观察，不升级为官方原服协议结论，也不自动批准字节级预期。HTTP 启动器仅有 Host 访问日志，未宣称已保存完整 HTTP 请求/响应原始体。
