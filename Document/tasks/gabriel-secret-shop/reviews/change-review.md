# 加百利秘密商店独立结果审查

审查范围为任务契约第 1 版、规格、实现方案、交付文档和功能分支实际增量。按 `reviewing-work` 的代码与交付物标准检查，结合仓库架构规则核对职责、权威状态和交易边界。代码目标为 `5a9143e1c88502f42929a80fe22dcec7d58e3fa0`。随后核对目标 `94757a1e1e4846a323184799a5aa13f707956c87`，增量只有实机说明的两行修订。

| 条件 | 审查结果 |
|---|---|
| SC-1 / SC-2 | 普通地下城在既有清场状态打开时抽选一次。规则优先取副本专表，再用基础等级和入场人数取常规表。副本聚合持有共用 NPC，各角色的不可变商品行分别保存在所属进度。清场投影仍经过既有精确会话和 run ID 过滤，发包顺序为 `0x001F → 0x0117 → 0x0118`。德利拉及特定副本原有分支保留。真实 PVF 的有效候选物品在设备或消耗道具清单均有对应定义，实际代币均为材料 600。 |
| SC-3 | `0x0128` 使用效果型请求工作单元，购买复用现有支付、容量和物品授予能力。扣库存与资产登记在同一个领域事务。准备阶段核对当前副本、成员和库存快照，可失败的持久化提交成功之后再应用内存库存。相同效果请求经现有重放路径读取当前状态，无再次扣费、发货或扣库存。复核 b1 的客户端成功 ACK 在 `0x011096D2–0x01109738` 读取资产字段，`0x01109A14` 读取结果库存并在 `0x01109BAF` 更新相应货单行。 |
| SC-4 | 购买和库存事务均按当前角色及 run 归属查找，释放的成员进度无法提供货单。关窗是独立遥测上报。普通商店延用原购买计划、独立协议和通知顺序。 |
| SC-5 | 三图测试覆盖三个 NPC、两种计价、售罄与重开、回城重登和双人库存。原说明只要求 400 金币，买齐龙人之塔商品和石巨人塔设计图共需 600。修订后前置条件为 600，双人步骤每方另备 300 并使用不同账号，便于区分账号共享材料。已核实测试 PVF 的 SHA-256、Host 产物存在且其程序集版本为 `0.3.5+5a9143e1c88502f42929a80fe22dcec7d58e3fa0`。 |
