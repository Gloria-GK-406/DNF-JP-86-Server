# Specification：任务与被动解锁各自拥有进度

## Why and Outcome

4303为grade=achievement、NPC2受理、击杀30只普通怪物的真实任务；6501为grade=title、clear quest4303的称号簿条件。6531为grade=title、level up70的被动条件。不能把4303的自动成就计数0当成任务完成。

## Scope

服务器双路线；客户端0200与当前TBM1协议保持。旧任务型成就行保留但不作为当前规则/完成事实，已解锁称号和物品不撤回。未知多条件不自动补全。

## Requirements

| ID | Requirement |
|---|---|
| RQ-001 | 原生grade=achievement属于任务日志；grade=title属于被动称号解锁规则。定义文件存在不等于需受理，不用条件类型或NPC是否存在猜分类。 |
| RQ-002 | 001F受理achievement任务；只有carried进度推进；放弃停止推进；达到0只表示ready，正式完成写cleared并发布QuestCompleted。title解锁定义不能伪装普通受理任务。 |
| RQ-003 | 被动领域只初始化/推进/投影title规则，clearquest从真实已完成任务或已完成被动依赖判断。旧4303等任务型自动行即使p1=0也不得满足6501或前置限制。 |
| RQ-004 | 任务正式完成事件驱动对应title成就，再由AchievementCompleted驱动称号簿。reward type=title不经普通背包重复发放；规则确认其奖励被称号簿映射承接，非称号奖励照常。不能吞掉无法映射的奖励。 |
| RQ-005 | 登录可补认已完成的任务和等级/职业等被动条件，跳过已激活；查询只读。重复事实/完成投递/重登不重复发称号。 |
| RQ-006 | 保留旧任务型计数原始行、任务记录/解锁/物品。登录和投影忽略非当前被动规则计数；未解锁的错误依赖完成计数在显式准备时恢复为待完成，已激活和合法title进度不重置；旧排队完成事件也必须核验真实任务完成依据。 |
| RQ-007 | 不侵入业务的称号条件判断。复用任务权威事实推进，不扩大本次为整个任务系统EventBus迁移；称号解锁仍仅订阅事件。 |
| RQ-008 | 构建/回归/独立审查后发布独立运行目录，备份SQLite和配置；验证实际PID/路径/监听/HTTP/hash。无客户端/PVF修改。 |

## Acceptance Criteria

| ID | Covers | Criterion |
|---|---|---|
| AC-001 | RQ-001/002 | 未接4303击杀不创建/推进该任务；接受起始30，击杀推进，仅普通怪计数；放弃再击杀无变化；重接受初始30。 |
| AC-002 | RQ-002/003/004 | 击杀达30但未正式完成时6501未完成且无奖励；完成写cleared，事件解锁一次26596；回滚没有完成/奖励，重复事件/重启不重发。 |
| AC-003 | RQ-003/006 | 旧4303自动行30或0不被Get投影或依赖判定采信，6501仍未解锁；旧行和已解锁/真实物品字节保留。 |
| AC-004 | RQ-004 | title奖励不会出现在任务背包发放计划；有明确承接规则才允许完成；普通物品任务仍按原逻辑发放。 |
| AC-005 | RQ-005/007 | 6531在70级登录完成一次；真实cleared4303登录补认6501；未接任务不补认，查询反复执行没有写入。 |
| AC-006 | RQ-008 | 新身份、健康及监听可复核；旧runtime与DB一致备份保留；客户端DLLhash保持当前025BF6FE…；称号簿现场验收不冒充自动证明。 |

## Success Evidence

真实PVF/SQLite领域与事件测试、任务CMD/codec回归，Application/Protocol/Infrastructure相关检查；独立审查增量和旧基线，部署记录及人工流程。现有技术债D-001..D-004与本次无直接依赖，未扩展实施范围。
