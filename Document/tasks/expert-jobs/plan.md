# 四副职业实施计划

四职业共用的状态、内容和任务入口应先闭合。双人摊位需在已有事务能力验证后接到分解与附魔，分别形成可检查的实现单元。

| 工作 | 交付 | 依赖 | 规范要求 |
| --- | --- | --- | --- |
| T-001 | 角色级状态、任务授予与放弃、通用入口、登录及在线刷新。复用两张 SQLite 表。实现职业资格和规则内容的基本接口 | 当前主线 | RQ-001 至 RQ-003 |
| T-002 | 专家商店运行态、精确会话和访客绑定，双人结算接入 | 已有 IExpertStoreDomainService、工作单元及 T-001 | RQ-003、RQ-007 |
| T-003 | 玩家分解机规则、修理/升级和分解摊位协议 | T-001、T-002 | RQ-004、RQ-007 |
| T-004 | 配方学习、制作和提取的共享逻辑，接通炼金术师和控偶师。支持所需的经验与自动学习 | T-001 | RQ-005 |
| T-005 | 附魔师资格、卡片转宝珠、摊位附魔及设备修理 | T-001、T-002、T-004 | RQ-006、RQ-007 |
| T-006 | 整体回归、协议知识库、用户实机操作顺序 | T-001 至 T-005 | RQ-008 |

## 共用接入边界

副职业服务在 Application 对表和规则建模，库存、任务、技能和金币调用已有 owner，SQLite 参与者沿用连接串身份。任务授职加入任务完成事务，配方学习加入堆叠物品使用事务。Protocol 保留封包与收件人选择。摊位资产事务使用普通命令的显式双方写入范围，在写入处复核精确会话及摊位实例。

## 验证

各单元期间用编译和静态检查验证接入。四职业实现完成后集中运行自动测试和必要的集成验证。测试覆盖副职业写入、资格不符、原子资产操作、过期会话及既有分解和宝珠入口。A21 客户端验收在四职业全部实现后进行。

## 第一实施单元

先确定角色副职业状态读写、基础规则与服务契约。根据任务奖励结算与技能的实际接入点细化就职、放弃、查询和投影；后续摊位与配方单元消费同一套角色状态及更新入口。
