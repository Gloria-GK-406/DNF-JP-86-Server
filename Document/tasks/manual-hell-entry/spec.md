# Specification: 主动深渊入场

## Why and Outcome
明确模式1的主动深渊能力，以领域服务判定类型和准备规则，复用已有共享入场事务；网络层仅提交命令和投影结果。

## Scope
完成主动准入、成本、冻结规则和投影。随机判定为普通的桩；柱战斗、深渊掉落不在此Spec。

## Requirements
| ID | Requirement |
|---|---|
| RQ-001 | 业务上下文含地下城、难度、模式、练习标志、队伍和任务事实；返回Normal/ManualHell/RandomHell，CMD switch分流；非1不触发主动深渊 |
| RQ-002 | 深渊规则只经规则服务读取PVF；不支持、前置任务不满足、票不足、配置无有效房间/演员组应拒绝 |
| RQ-003 | 服务端按手动难度权重一次选出难度、房间、演员组；全队成本先校验，公共事务内扣票和疲劳并准备一个共享run |
| RQ-004 | run保存类型和深渊方案；切房/重访复用方案；001C/001D及所需深渊信息消费该结果，无随机重抽 |
| RQ-005 | 普通请求保持既有行为；失败不扣资源；入场不伪装成已完成柱战斗/奖励 |

## Acceptance Criteria
| ID | Covers | Criterion |
|---|---|---|
| AC-001 | RQ-001 | 普通上下文返回Normal，模式1返回ManualHell；其他模式与练习开关不被误判为主动；CMD与消息边界审查通过 |
| AC-002 | RQ-002,RQ-003 | 支持的内容有准确任务/门票/房间/组规则；任意成员缺票或前置任务失败时无资源变更与run发布 |
| AC-003 | RQ-003,RQ-004 | 成功进入全队共享同一run、相同冻结方案，扣应付成本一次；准备失败/事务异常不留下部分扣除 |
| AC-004 | RQ-004 | 深渊入场和切房编码向量按静态消费映射；普通编码保持原向量；重访方案不变 |
| AC-005 | RQ-005 | 构建、普通副本和相关组队/事务回归通过；交付说明列明尚未部署和实机未验证 |

## Success Evidence
以真实领域/库存/事务结果为测试oracle，避免只断言调用了哪个服务。PVF与协议来源记录在实现说明；相关测试、独立审查和最终检查保存在本任务目录。
