# TaskContract: 主动深渊入场

## Context
### Source Request
用户：可以，就按这个流程写功能吧。
用户已确认：CMD handler 根据完整业务入场上下文，经领域判定返回普通、主动深渊、随机深渊类型后 switch 分流。当前仅模式字节 1 的主动深渊；随机深渊判定留桩。
### Current Situation
A21 CMD0010 正文偏移5为模式，1为主动深渊；偏移6为练习开关，不能当深渊难度。现有实现读取后忽略；普通入场共享队伍run与事务。

## Goal
让合法主动深渊请求按资格、门票、深渊规则进入具有冻结深渊配置的共享地下城，拒绝请求不扣资源，普通入场保持原行为。

## Scope
### In
- 完整业务上下文、类型判定和 CMD 分流；随机入口桩。
- PVF 深渊区域、任务、通行证、难度权重、房间与演员组的规则读取。
- 主动准入、全队成本、公共入场复用、run冻结结果与入场/切房协议投影。
- 自动化验证、协议证据说明与真实客户端待验收边界。
### Out
- 随机出现算法、柱交互与波次战斗、深渊奖励掉落与结算。
- 客户端/PVF修改、部署、PR和合并。

## Constraints
- 保持 Package Handler -> CMD -> Domain -> Rule 分层，领域层不引用网络包/连接。
- 只以模式==1发起主动深渊；练习字节不指定深渊难度。
- 深渊资格失败不得降级普通入场；公共入场资源与run创建保持统一提交。

## Success Conditions
| ID | Observable condition | Required evidence |
|---|---|---|
| SC-1 | 模式1走主动深渊，普通与随机桩有明确类型；业务上下文不依赖网络 | 路由行为验证与独立审查 |
| SC-2 | 不支持、任务不足、任一成员门票不足时拒绝且资源/run不变 | 单人/组队准入与失败测试 |
| SC-3 | 有效请求每位成员扣应付门票和首房疲劳，创建一个冻结深渊配置的共享run | 实际领域入场和事务测试 |
| SC-4 | 深渊布局/首房/切房投影消费冻结结果，普通场景回归通过 | codec与入场/切房测试；明确ClientStatic与待实机边界 |
| SC-5 | 构建及相关测试通过，实现与证据可交接 | 新鲜检查和完整结果审查 |

## Assumptions
- 门票规则和深渊难度采用本任务研究的70/上游/PVF来源，并明确来源；不宣称已实机验证。
- 深渊入场不等于已实现柱触发、波次和奖励闭环。
