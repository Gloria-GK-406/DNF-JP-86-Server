# 统一奖励交付规格

历史规格（38ede835）：后续用户明确要求主动开启满包拒绝；与下文“礼包/罐子预检查允许邮寄”冲突的部分，以 [交付模式](delivery-policy.md) 为准。统一发放入口要求仍然有效。

RQ-001 / AC-001：新增 IItemDeliveryDomainService，批量接受模板奖励或已生成实例及来源，返回入库数量、变化及邮件回执。逐物品满足 requested = inventory + mailed；满包不构成失败，其他错误不吞掉。

RQ-002 / AC-002：先兼容堆叠再用空槽，容量不足只邮件剩余。已生成装备的 UID、完整快照以及堆叠物的绑定、期限等状态在去向变化后保持不变。往返测试证明数量和属性。

RQ-003 / AC-003：归属当前用例事务，不另开独立提交。邮件失败、背包失败均使全部发奖和来源状态回滚；成功事件提交后才可通知。来源继续负责唯一领取、开奖与支付，服务不承载抽奖规则。

RQ-004 / AC-004：系统奖励制造者全部切换，包括免费/收费/黑钻翻牌、死亡/迷妄/绝望塔结算、教程、任务完成及任务授予物、礼包/装扮包/魔盒和直接奖励 Effect。以全仓制造者与底层写入双向扫描矩阵验收。

RQ-005 / AC-005：奖励容量预检查允许邮件去向；制作、购买、地面拾取、邮件领取、初始资产、临时塔物品和普通移动按原约定分类。共享 Effect 按用例区分，不改变制作的入库保证；邮件满包领取保留原附件，不寄第二封。

RQ-006 / AC-006：邮件支持奖励涉及的装备、堆叠、装扮和宠物实例；系统邮件不受玩家转让限制，保存完整实例、可正常领取。特殊虚拟资产继续原领域；不能把史诗碎片、权益奖励当普通堆叠邮寄。

RQ-007 / AC-007：正常与满包结果仍可构建正确客户端背包、奖励展示和新邮件通知。协议类型留 Protocol；统一服务只交回领域结果。每次交付剩余附件集中发送，按现有协议支持限制拆批。

RQ-008 / AC-008：验收清单必须说明每个低层生产授予和实例创建调用为何已迁移或为何不属奖励；独立审查从制造者和写入方反向检查。自动化测试与实机验收分开报告；本任务不部署。

范围澄清：成就解锁称号确实制造实例，但指定目的地是称号簿而非背包，其目录解锁、专属槽及镜像规则由称号簿负责；不改为背包优先。GM指定正文/附件的显式管理邮件保留原邮件路径，避免改变管理员明确选择的交付方式。两者必须在迁移矩阵中按真实制造者记录。
