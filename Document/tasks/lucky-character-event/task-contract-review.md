# 幸运角色活动任务契约审阅

## 权威来源

- 用户明确授权「好，你写任务契约后完成这个功能」。紧邻方案界定了默认关闭、GM 排期和职业范围、进图确定本局资格、名单和结算同步，以及首版福利固定并与 A21 提示对齐。
- 用户随后明确「队伍共享掉落一起提高，任何队友都可拾取加成产生的装备」，以此作为 JP86 的神器归属规则。
- [现有设计稿](E:/Project/DNF/Document/幸运角色-服务端设计.md)载有个人和组队经验条件，以及普通副本和任务的首版范围。[取证输入](evidence.md)记录 A21 文案、PVF 参数和第三方服实现各自支持的结论。
- 用户给出的工作区规范要求区分客户端静态、抓包与实机。 [仓库 AGENTS](../../../AGENTS.md) 和 [新功能开发流程](../../FeatureDevelopment.md) 规定独立工作区、自动验证、用户测试及 PR 的先后顺序。

## 意图覆盖

| 契约项 | 复核结果 |
| --- | --- |
| RI-1 | 用户的同一授权覆盖成文、实现和验证。 |
| RI-2 | SC-1 承接指定职业、全职业、默认关闭、GM 排期和启停。 |
| RI-3 | SC-2 和 SC-3 承接个人和组队经验、入场资格、退队、重连与按期切换。 |
| RI-4 | SC-4 和 SC-5 承接 A21 明细、实际入账、疲劳燃烧、神器与技能增益。神器 `+150%` 以已同意的界面口径为本服数值。 |
| RI-5 | 本期建角限制、固定自动轮换、独立玩法和自定义福利倍率属于此前讨论的可选范围。用户确认的 GM 时间、职业与固定福利方案支持把它们留在首版范围外。决斗场技能收益、版本号和发布产物受玩法适用范围及仓库发布规则约束。 |
| RI-6 | 契约明确隔离工作区、自动验证、真实客户端验收、真实玩家库操作及 PR 的边界。 |
| RI-7 | SC-5 明确普通副本有一名及以上幸运参与者时提高共享神器收益，额外神器进入队伍拾取路径，各队友有拾取资格。契约按队伍一次应用加成。 |

SC-5 的混合队伍结果可用实际掉落和普通成员的拾取验证，既有拾取合法性继续由副本结算和地面拾取路径判断。A21 文案与第三方服参考用于解释增益数值及取证边界，JP86 新增装备的归属由用户当前选择确定。PVF 的 `unique drop ratio = 50` 及原版服务器行为均按取证输入保留证据边界。具体抽取算法由后续设计确定。
