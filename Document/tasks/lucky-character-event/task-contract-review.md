# 幸运角色活动任务契约审阅

## 权威来源

- 用户明确授权「好，你写任务契约后完成这个功能」。紧邻方案界定了默认关闭、GM 排期和职业范围、进图确定本局资格、名单和结算同步，以及首版福利固定并与 A21 提示对齐。
- [现有设计稿](E:/Project/DNF/Document/幸运角色-服务端设计.md)载有个人和组队经验条件，以及普通副本和任务的首版范围。 [取证输入](evidence.md)补齐了第三方服对每位幸运参与者独立授予额外神器掉落的做法。
- 用户给出的工作区规范要求区分客户端静态、抓包与实机。 [仓库 AGENTS](../../../AGENTS.md) 和 [新功能开发流程](../../FeatureDevelopment.md) 规定独立工作区、自动验证、用户测试及 PR 的先后顺序。

## 意图覆盖

| 契约项 | 复核结果 |
| --- | --- |
| RI-1 | 用户的同一授权覆盖成文、实现和验证。 |
| RI-2 | SC-1 承接指定职业、全职业、默认关闭、GM 排期和启停。 |
| RI-3 | SC-2 和 SC-3 承接个人和组队经验、入场资格、退队、重连与按期切换。 |
| RI-4 | SC-4 和 SC-5 承接 A21 明细、实际入账、疲劳燃烧、神器与技能增益。混合队伍验收明确规定额外神器只归相应幸运角色，既有共享与普通队友收益规则继续适用。 |
| RI-5 | 本期建角限制、固定自动轮换、独立玩法和自定义福利倍率属于此前讨论的可选范围。用户确认的 GM 时间、职业与固定福利方案支持把它们留在首版范围外。决斗场技能收益、版本号和发布产物受玩法适用范围及仓库发布规则约束。 |
| RI-6 | 契约明确隔离工作区、自动验证、真实客户端验收、真实玩家库操作及 PR 的边界。 |

核查了 A21 字符串资源 `73061` 和第三方服的 `DungeonKillApplicationService.ApplyParticipantRewardAsync` 与 `LuckyCharacterDropBonus.Append`。文案显示 `+150%`，第三方服以参与角色自身资格传入 `150`，并将额外抽取结果限于神器等级装备。此证据支持契约所选的 JP86 本服个人收益与固定增益。PVF 的 `unique drop ratio = 50` 已在取证输入中记录为原版行为待证。具体抽取算法留给实现，SC-5 的混合队伍结果可以直接验收。
