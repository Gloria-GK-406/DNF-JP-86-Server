# 幸运角色活动实施计划

## Planning Choice

活动配置、运行身份及奖励都使用同一资格。以一份详细计划推进，避免分段时引入多个独立事实源。

## Approach and Shared Decisions

现有活动配置 JSON 保存职业条件，GM 沿用鉴权、审计与配置修订。读取时固定服务端时刻，生命周期负责客户端推送。副本保留入场解析后的角色权益，清算继续使用现有成员和清算入口。活动名单标记与经验面板由 Protocol 切片编码。新增领域与既有注册按仓库分层约束接线。

## Work and Dependencies

| ID | 工作 | 检查 |
| --- | --- | --- |
| T-001 | 复用 `IManagedEventDomainService`、`IEventPersistence` 和现有 GM 活动表单。加入职业选择、全职业、默认关闭及参数校验。内部使用独立活动身份，原生日历条目需有 A21 接受依据。 | 活动配置往返和排期边界，旧 JSON 可读。 |
| T-002 | 切片实现 `NOTI 0x0406`，编码 PVF 对应的职业阶段集合。通过现有选角链、返回选角和活动变更通知安排同一当前名单。全量通知刷新从现有事件投影接入，处理活动资格消失的空名单。 | 比对 0、1、多项结构，验证入城、变更、结束与重连帧，记录 A21 热刷新不确定性。 |
| T-003 | 普通副本入场产出按角色的权益状态，随共享副本运行保存，成员移动和槽位调整保持同一成员身份。击杀与通关计算按该状态；交任务从当前期计算。扩展 `ExperienceBreakdown`，将清算金额写入 `0x0023` 两个已证槽，并保留 `0x0025` 同一奖项的累计投影。 | 混合队伍、多个幸运、跨期、退出、重连、重复清算和新旧编码兼容。 |
| T-004 | `CMD 0x0233` 校验现有会话和城镇，回应并更新 `0x01EB`。持有的选择与当期资格关联。进图及首次走房使用同一入场冻结的决策，逐人扣疲劳。PVF 声明禁止燃烧的图继续遵循禁止规则。 | 成功／失败收包，普通/双倍成本以及额外经验一致。 |
| T-005 | 普通怪物共享装备抽取保留基线，对有幸运参与者的队伍增加只保留神器装备的独立掷样，额外装备使用既有共享路径。技能先复核 A21 原生名单触发的 PVF 增益链，服务端仅补确需的有效级投影，避免重复加级。 | 可控 RNG、普通队友可拾取、多个幸运不叠加、默认关闭、技能与决斗实际回退。 |
| T-006 | 更新协议人工区、catalog 和验收步骤。构建并运行受影响项目，准备可查证的客户端情景，实测前核对测试授权。 | 契约 SC-1 至 SC-6 逐项记录证据。 |

## Verification

使用独立数据库和测试工程验证业务与收发。现有活动、普通组队通关、不消耗疲劳与非幸运掉落路径作为回归对照。不会用玩家库执行自动化。授权后按新功能流程准备玩家库测试并等待用户实际验收。
