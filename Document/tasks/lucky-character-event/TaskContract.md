# TaskContract · JP86 幸运角色活动

## Context

### Source Request

> 好，你写任务契约后完成这个功能

用户确认了前一轮方案：将幸运角色加入现有 GM 活动管理，支持排期、职业范围、启用和停用，业务按时间切换，按进图时刻保留本局资格，客户端同步名单和两笔通关加成，首版福利固定并与 A21 提示对齐。

神器归属补充：「队伍共享掉落一起提高，任何队友都可拾取加成产生的装备」。

### Current Situation

远端 `main` 基线 `818cbeed7391a9fb6079270a06766fecac2a5ff6`。现有受管活动支持配置、排期、启停和通知，普通副本已有进图、成员、疲劳和奖励结算边界。A21 静态证据闭合了名单与通关金额字段，原生选角热刷新和具体燃烧状态仍待运行验证。可比国服资料用于了解玩法，JP86 福利规则以确认的设计为准。

## Goal

交付一项可由 GM 定期开关的幸运角色活动。玩家能看到有效资格，符合条件时获得显示的成长福利，普通队友能根据队伍条件获得通关加成。A21 实机验证、服务端自动验证和生产部署各自有明确状态。

## Scope

### In

- GM 配置开始、结束时间和基础职业名单，支持全职业。适用于符合职业的现有和新建角色，转职与觉醒继承。默认关闭，支持手动开关和到期切换。
- 普通地下城的幸运击杀、本人通关和组队通关经验，以及交任务时的幸运任务经验。兑现启用时 A21 原生提示所列的免费疲劳燃烧、神器装备概率增益和 PvE 技能等级增益。
- A21 原生幸运名单、角色状态、燃烧开关与经验面板同步，覆盖选角、进城、换角色、重连、换期和关闭。以原生读取能力为准验证推送时机。
- 在隔离工作区交付实现、协议记录、可复现的自动验证和按顺序的 A21 用户测试资料。

### Out

- 限本期建角、固定日历自动轮换及 GM 自定义福利倍率。
- 扩展独立玩法、决斗场技能收益、版本号及发布产物。

## Constraints

- 新功能从最新主干的独立工作区交付，验证使用独立的产物、数据库及监听。协议区分 `ClientStatic`、`WireCaptured` 和 `ClientVerified`。
- 按入图时的资格兑现已开副本的福利。同一次奖励通过现有事务语义入账，结算重试与重连保持正确。
- 走实机测试前核实实际主干数据库与备份边界。请用户完成实机验收，验收通过后才进入 PR 流程。
