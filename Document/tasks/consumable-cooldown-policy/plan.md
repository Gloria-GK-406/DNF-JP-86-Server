# 实施计划

1. Infrastructure 解析三位维护和最后一个冷却时长。Application 从现有规则选择无服务端计时、持久化或专用会话。将选择贯通使用预检、Effect 和修理直接事务。疲劳药继续用既有账本。
2. Persistence 引入 v49 的角色绝对截止表，写入在既有结算事务内，并用条件更新保护活跃的共享键。隔离库验证 v48 升级保留原数据，并验证回滚、重建服务和精确到期。
3. Protocol 维持登录空包基线及 0x00AE 顺序。恢复从当前状态集中投影 0x00AC，保留瞬移即时回包。使用 A21 可转换的秒数上限。
4. 对照契约执行服务端自动及真实 dev PVF 测试，核对使用、支持的专用动作、失败和重放。按仓库流程准备后续 A21 手工验证，再依据实测决定接入和交付。

验证入口为 `dotnet test Server/86JP.Server.slnx`。真实模板检查使用工作区 dev PVF。测试库由夹具创建。测试及迁移验证与运行中的服务和玩家库隔离。
