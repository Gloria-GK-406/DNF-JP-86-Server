# Quest 领域查询与完成计划归拢

## Context

### Source Request

2026-10-11 用户：“可以，按你的想法归拢quest的处理。你先派子代理完成任务范围的确定，然后写任务契约后实现，部署。”

用户确认：按任务查询未接／已接／完成；已接任务状态列表；列举可接任务。任务系统只读检查外部资产，返回交付需求、奖励及任务自身变化，由统一编排一次性结算。

### Current Situation

基线424da804。登录、持有变化、提交及任务材料掉落分别计算材料条件，已导致共享晶块判定不一致。普通完成和镜像完成直接执行外部资产变更，完成券在Inventory内生成任务变化。现有Effect预演、事务及提交后协议同步可复用。

## Goal

任务领域统一对外查询和条件计算；普通／镜像完成返回只读计划，由结算编排执行原有领域变动，任何失败保持整次结算原子性。部署供实机验收。

## Scope

### In

- 三个只读查询入口，明确可提交与已完成；统一登录、运行时、完成复核、任务材料需求计算。
- 可接条件由Quest负责，现有World、循环任务、协议调用迁移到同一规则。
- 普通／镜像完成计划与外部执行分离；完成券的任务状态计划归入Quest。
- 审计接取／放弃入口，消除协议层任务类型／条件编排的重复职责；外部物品授予仍由结算编排执行。
- 保留协议、原子事务、事件、真实库存更新、失败重放、重复提交与特殊任务行为；补测试、独立审查、备份部署。

### Out

- 新任务玩法、客户端/PVF修改、全量Quest事件化、数据库重置、发布版本／PR／清理分支。

## Constraints

- 查询和完成计划生成不得改变物品／金币／任务完成记录；任务进度刷新允许维护任务自己的记录。
- 检查、计划和应用处于同一事务及既有角色执行边界；协议仍在提交后发送。
- 普通任务、循环接取资格、镜像RunId临时任务、任务完成券免条件且不发普通奖励的语义保持。
- 共享材料仅以账号容器为准；缺条目为0，旧背包副本不能计数。
- 使用当前task/despair-tower工作区；保留既有未跟踪Document/outputs/tournament-scheduling-20261011资料。无权恢复或清空玩家数据库。
