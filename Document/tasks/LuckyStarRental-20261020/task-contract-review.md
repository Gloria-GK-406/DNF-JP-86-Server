# 幸运星与装备租赁任务契约审查

审查绑定上述精确路径的 revision 1，不构成协议、Spec、实现或实机验收结论。

## 权威来源

- 本会话用户要求了解幸运星功能如何由领域服务承载、依赖哪些服务及如何协调。
- 本会话用户接受的设计初稿：账号幸运星与角色装备租赁两个领域服务；各自经规则服务读取 PVF；租赁单向调用幸运星服务；金币、星币、真实装备 UID、租赁关系在同一事务内结算；复用物品投递、容器与生命周期；覆盖购星、道具兑换、适正通关、租赁与到期；复用完整 NOTI 03C1 当前状态投影。
- 初稿明确待核定：400/999 上限兼容、重复租赁及同时持有规则、在线到期回收时机、A21 请求字段与响应。用户随后明确授权：“可以，按你的想法实现吧。实现后部署，我看看效果”。因此可在继续核实后合理决定规则，但不得声称未知规则已经得到客户端验证。
- 工作区 AGENTS.md 与仓库 `E:/Project/DNF/DNF-JP-86-Server/AGENTS.md`：中文及文档位置、领域/规则/命令/协议边界、领域事务和物品生命周期、协议证据记录与实机结论边界。

## 意图及范围核查

| 契约覆盖 | 对照材料意图 | 结论 |
|---|---|---|
| RI-1；Scope In 1–4；SC-1–4 | 账号与角色职责、规则来源、业务闭环、真实 UID 与期限、事务一致性、登录及变化后的完整同步 | in_scope；合并归在同一产品闭环，未重复归属或漏掉当前任务应交付的结果。 |
| RI-2；Scope In 5；SC-5 | 实现后部署供用户实测，保留玩家数据和可回退输入 | in_scope；部署结果有运行身份、健康、监听及备份证据要求。 |
| RI-3；Scope Out 3；SC-6 | 用户保留实机验收权 | in_scope；排除的是用自动验证冒充实机通过，未排除功能实现或部署。 |
| RI-4；Constraints；SC-4/6 | 仓库架构及协议证据纪律 | in_scope；不将旧上游 opcode、历史实现或静态推导视为当前客户端已验证事实。 |

Scope Out 的其他活动图、商城及赛丽亚魔盒幸运值与本次授权闭环无交叉。聚合分支合并、远端推送、PR、发布版本和其他任务资料清理没有获得本轮明确授权，排除合理；本地任务提交及测试服务端部署仍保留在 Scope In 与 Authorization。

余额上限选择 400 且保留既有超额余额，符合初稿的 PVF 优先及不截断资产约束。24 小时期限与初稿一致。尚待核定的并存、续租、折扣及在线回收时机是可在 Spec 阶段通过取证和用户授予的合理裁量具体化的规则细节，未被悄然排除。后续 Spec 必须明确这些选择的证据和可观测行为；该裁量不允许凭空断言 A21 协议或虚构 ClientVerified。
