# Specification: 同一难度贯穿角色权限与地下城实例

## Why and Outcome

用户选择的普通/冒险必须成为本局实际难度。角色每图最高可选难度通过独立领域服务持久化，未记录时为 Normal。

## Scope

覆盖契约 SC-1 至 SC-6。通关自动升级、组队权限新政策、疲劳和地图开放重做均不在本轮范围。

## Requirements

| ID | Requirement |
|---|---|
| RQ-001 | DungeonDifficulty 为 byte 枚举，Normal=0、Adventure=1；2..4保留中性 Tier2/Tier3/Tier4 名称，避免把未验证UI名称写成事实。Pack读取u32编号、offset4难度，未知值拒绝；尾部未确定字段不得赋予新业务含义。 |
| RQ-002 | 角色难度服务按角色和地图读取最高值，缺省Normal；提供记录列表供权限投影。记录持久化，解锁为最大值操作，重复和较低请求不降级。 |
| RQ-003 | 复用现有 character_dungeon_permissions，0..4按客户端普通状态比较的静态证据解释为上限。非法值明确报错，不静默改写；同地图重复旧行取最高并保持所有旧行，写入统一最高值。 |
| RQ-004 | 单人入场在创建布局/房间/Run前校验最高难度；超限返回领域拒绝原因。组队现有路径保留，不为本轮推断全员或队长策略。 |
| RQ-005 | 入场只采用一个难度来源，实例创建后固定；布局筛选、房间创建、任务/奖励规则和通知均使用该枚举值，静态PVF数值索引仅在内容适配边界转换。 |
| RQ-006 | 权限通知每条为u32地图编号和u8状态；读取由角色难度领域服务统一提供，不受旧登录快照失效影响。 |

## Acceptance Criteria

| ID | Covers | Criterion |
|---|---|---|
| AC-001 | RQ-001 | #101普通/冒险15字节样本解包正确；高位地图编号不被截断；非法难度和截断请求不能进入业务。 |
| AC-002 | RQ-002,RQ-003 | 缺省、已有、角色/地图隔离、重复/较低解锁、重载、事务回滚与非法旧数据行为可观测。 |
| AC-003 | RQ-004,RQ-005 | 单人冒险权限不足无Run；已开放时布局与首房及换房均为冒险；旧房重访不改变难度；组队既有回归保持。 |
| AC-004 | RQ-006 | 已有记录投影为5字节条目；领域更新后新投影/重登读取最新记录。 |
| AC-005 | RQ-001,RQ-005,RQ-006 | 用户操作蜘蛛洞穴普通/冒险，助手核对0010、001C与服务端实例证据。该人工项须实际完成才可声称整体验收完成。 |
