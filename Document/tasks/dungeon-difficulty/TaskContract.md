# TaskContract: 地下城难度类型与角色最高可选难度

## Context

### Source Request

用户要求：“改成enum，然后按Normal=0这样的方式完成pack内的值到enum的强转可行性。到业务领域就只有DungeonDifficuty.Normal这样的值了。”

用户要求新的领域服务记录和获取角色可选难度：“默认情况没有记录就返回Normal，有记录就返回记录结果。这里直接返回的是可选的最高难度就行了。”

用户接受协议边界校验、实例固定难度、角色进度独立持久化和只升不降的解锁操作；随后指示：“ok，可以。现在可以启动任务契约了吗？”

### Current Situation

- #101 已归档[取证报告](../../普通地下城准入规则取证-101.md)。0010 地图编号是 u32，难度在 offset4；0005 条目是 u32 地图编号加 u8 状态，现有生产 codec 存在错位/宽度问题。
- DungeonRunAggregate 和 DungeonRunState 已有 byte Difficulty，不需要再增加另一份难度字段。入场参数与布局 facts 中的难度可能形成重复来源。
- 普通0、冒险1已有限定实机证据；其他难度命名、权限 wire 状态完整映射不能冒称已实测。
- GitHub #102 还包括地图开放、完整通关解锁和组队差异规则。本契约只承接本轮明确商定的难度基础能力，不代表完成整个 #102。

## Goal

业务领域使用强类型地下城难度；角色最高可选难度有统一的持久化领域能力；选择投影、入场判断与本局实际难度保持一致。

## Scope

### In

- 定义 DungeonDifficulty 枚举，显式数值对应 Pack 值，Normal=0；Pack 边界校验并转换，业务接口与实例使用枚举。
- 修正本范围内0010难度解析及0005权限条目编码。
- 新增按角色和地下城记录、获取最高可选难度的领域服务，缺省返回 Normal，有记录返回已记录结果。
- 提供持久化的“解锁至某难度”操作，只提升、不降级、重复执行幂等。
- 入场领域服务通过统一难度规则判断请求是否超过角色上限，通过后固定实例难度；房间创建、相关规则和客户端投影使用本局同一难度。
- 自动验证上述行为，并准备用户辅助的普通/冒险实机验证步骤。

### Out

- 决定或实现通关自动提升权限的触发规则；本次仅提供解锁能力。
- 重做剧情任务、地图可见性和地图开放规则；默认 Normal 不授予地图访问权。
- 裁定组队权限差异采用队长、全员或其他政策，以及补全所有准入拒绝码和双端提示。
- 疲劳账本、房间扣点、燃烧疲劳、零疲劳拒绝及重登城镇旅店修复。
- 深渊等特殊模式专属难度或次数；全量难度平衡调整。

## Constraints

- 用户已确认：领域层仅使用 DungeonDifficulty；协议原始数值转换及未定义值拦截在 Pack 边界完成。
- 用户已确认：角色最高可选难度与实例本局难度分别管理；实例创建后本局难度不变。
- 遵守仓库分层：Handler 驱动 CMD；CMD 调用领域服务；领域服务调用规则服务和领域实例。不得在 Handler 内直接操作 SQLite。
- 现有数据必须有明确兼容解释，不能未经验证把 clearState 原始值直接当作领域枚举或覆盖已有进度。
- 未确定的原版规则不得通过命名或默认值悄然补造；不将单人实测结论推广为全部地图或组队规则。

## Success Conditions

| ID | Observable condition | Required evidence |
|---|---|---|
| SC-1 | Pack 的合法值转成枚举，未定义值不进入业务；业务难度不再以裸 byte 传递 | 解包边界用例及相关业务调用链检查 |
| SC-2 | 不同角色、不同地下城的记录相互独立；缺项返回 Normal，有项返回记录最高难度 | 缺省、有记录及隔离用例 |
| SC-3 | 解锁只升不降且幂等；重登及服务重启后结果保持 | 重复/降级请求及持久化重载验证 |
| SC-4 | 单人请求超过上限时不创建实例；通过后布局、实例、首房、换房及投影使用同一难度 | 入场失败无实例与普通/冒险成功路径验证 |
| SC-5 | 权限投影符合0005条目布局，0010按正确位置读取难度 | #101样本回归；用户辅助观察普通/冒险并核对服务端实际实例难度 |
| SC-6 | 默认 Normal 不绕过地图或剧情限制；本次没有猜测自动通关解锁及组队新政策 | 相关边界回归和改动检查 |

## Assumptions

- “最高可选难度”表示该普通难度序列连续开放；特殊模式不复用该假设。
- 其他枚举成员名称及已有权限记录的转换需在规格阶段依据客户端/PVF和当前存储核对。若证据与最高难度模型冲突，先修订边界，不自行改变已接受语义。
- 用户辅助完成实际客户端验证；自动测试不能代替 ClientVerified 结论。
