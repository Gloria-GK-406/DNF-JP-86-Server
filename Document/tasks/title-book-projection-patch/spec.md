# Spec：称号簿原件、佩戴镜像与界面绑定

## 结果与职责

服务端持有书原件及唯一佩戴实例。客户端称号簿显示原件，装备位13显示佩戴镜像，两者不是物理交换关系。ClientHack 仅协调该界面原生请求/回包和本地显示，不决定所有权、资格或成就解锁。

成就规则、属性称号与外观称号保留现有服务端权威；不修改上游服务及数据。协议扩展明确标作本项目兼容约定，不伪称原生字段。

## 要求与验收

| 要求 | 结果 | 验收 |
|---|---|---|
| RQ-001 | 所有书类别使用相同镜像语义 | AC-001：装备任一有资格的书行，原件位置/实例不变，装备位出现镜像；取消仅删除镜像；替换没有背包中转 |
| RQ-002 | UI 按明确来源显示装备中 | AC-002：相同ID两个槽仅实际来源勾选；服务器物品ID与来源不匹配时不误勾选；登录恢复与开关窗口一致 |
| RQ-003 | 请求与确认不再搬动物理书实体 | AC-003：书佩戴/取消不触发旧称号自动019C/0013前置操作，不消费其他请求的等待项；拒绝解除本请求等待、保持原状态 |
| RQ-004 | 各类真实移动仍有明确边界 | AC-004：佩戴书原件不能拖至背包/交换；取消后普通自由称号可取出；成就原件仍不可取出；真实背包称号装卸与被书称号替换保留普通生命周期 |
| RQ-005 | 获取和成就提示只用于真实事件 | AC-005：佩戴/取消/替换不发送0168或全量000E书回填；书实体变更采用静默列表，同一称号不反复显示获得 |
| RQ-006 | 外观独立于属性与来源 | AC-006：Shift外观不移动原件或更改属性称号来源；取消清空佩戴实例；重登录保留佩戴实例外观 |
| RQ-007 | 身份校验、配置与回退可验证 | AC-007：目标字节全部匹配后安装；独立插件可禁用；发布文件哈希、服务端身份/就绪及原配置备份可查 |

## 状态不变量

- `book[category,index]` 为持久原件；`worn[13]` 为真实装备或有 `MirrorSourceUid` 的镜像。
- 绑定必须从当前镜像的 UID 关联到仍存在的书原件，而非只比较物品ID。
- 通常无佩戴书来源时，书中有实体为可佩戴；有准确绑定时只有该行显示佩戴并可取消。
- 失败不改变实体、绑定或外观；数据库事务及 EventService 保持职责分离。
- 快速重复佩戴同一原件应幂等，不生成多个镜像或丢失外观。
