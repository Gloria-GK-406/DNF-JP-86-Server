# 称号簿动画丢失与悬浮提示崩溃修订

## 问题与证据

用户反馈切换称号后游戏崩溃，同页其他称号展示消失；补充确认是切换称号簿时整页动画变空。本次保留故障进程 PID53340 的日志和原插件，位于主仓 `artifacts/title-book-mirror-patch-20261008/render-recovery-20261009/`。

- Runtime：2026-10-09 08:48:37 最后一轮019D确认及0002、五类0166投影，服务端无对应异常。客户端08:48:40记录空地址执行异常；前四条保护环境探测异常不作根因。
- ClientStatic：fault recorder 对镜像内地址输出RVA；崩溃栈RVA0217AB08为VA0257AB08，紧接调用VA02579230，属于称号簿鼠标悬浮提示更新。该函数在VA025793A9..025793BF先解引用UI+2B8的旧物品，再比较物品ID。
- ClientStatic：UI+2B8是提示缓存；+2BC=0借用实体、=1临时预览副本。0166原生handler在VA0118203E比较并清除指向旧书物品的提示，然后清空/重建实体；state3的提示在VA02579441读取装备位13，旧佩戴镜像可先被0002替换，原生书实体清理不涵盖该指针。空地址执行与该失效引用路径一致；没有完整崩溃内存，不能声称已精确证实当次指针的释放对象。
- CurrentImplementation / ClientStatic：旧补丁每份0166重建五类，五份共25次；随后对所有行重复setter并清cache+8。原生VA02576560初始化cache+8为称号自己的ANI，cache+18为静态帧；state1解锁动画使用+10。清+8误删了称号展示动画，用户确认的整页动画丢失与该行为一致。

## 修订边界

1. 删除同步时无条件清cache+8操作。保留真正state1解锁效果；有原件且可用/装备中的行缺帧或展示ID改变时，通过原生资源函数补齐。独立审查发现同一自由槽交换成另一种称号时，新物品无ANI会使原生资源函数提前返回、旧ANI残留；仅前后展示ID均有效且确实改变时，按原生smart引用清旧ANI后重建。同ID佩戴同步不清ANI，setter未成功写入预期state/ID也不碰资源。
2. 删除rebuild后第二次逐行归一化。原生rebuild中的setter调用已进入来源策略；每份列表只刷新对应分类，绑定变化时额外刷新旧/新来源分类。五份绑定相同的列表各刷新一次。
3. 在原生悬浮提示入口前比较缓存借用指针与当前选中行的权威对象，比较过程不解引用旧指针。若不一致只清缓存，不删除实体；临时预览副本由原生销毁。插件未启用或非自身视图完全委托原生。
4. 不更改服务端、019C/019D字段、书原件所有权、其他插件、EXE、PVF。
