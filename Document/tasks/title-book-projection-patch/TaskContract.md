# TaskContract：称号簿佩戴镜像与客户端一致性

## Context

### Source Request

2026-10-08 用户：『ok，可以，我们试试。起一个任务契约，先详细研究一下具体写patch和服务端逻辑的方案。然后再实现后部署到client。』

### Current Situation

原生 A21 的成就候选称号与自由存入称号使用不同的行状态判定，019C/019D 含物理交换及先行操作。当前服务端永久原件/佩戴镜像与其不一致：自由称号消失、无法再次佩戴、背包闪现及获取提示重复。上游比较不能满足本任务的永久镜像语义。

## Goal

称号簿中的原生成就称号与手动存入称号均可保留原件、佩戴镜像、显示装备中、取消与替换；客户端和服务端状态一致，操作不制造背包中转或获取提示。

## Scope

### In

- 详细研究客户端构包、等待队列、回包、书行状态、拖动、外观及服务端投影的联动方案。
- ClientHack 独立兼容插件与对应服务端领域、协议投影改动。
- 佩戴、取消、替换、重复相同物品ID、重登录恢复、失败恢复与称号外观的边界。
- 部署到本地 JP86 测试服务端及用户实际 protocol2 客户端，保存可回滚的原配置/插件与运行身份。

### Out

- 改动上游源代码或其测试数据；改动成就达成条件及其他装备规则。
- PR、合并、远端推送、版本发布及工作区清理。

## Constraints

- 不手工修改 EXE/DLL；补丁通过 ClientHack 构建，按已识别镜像校验目标字节，失败不得写入不匹配地址。
- 称号簿原件不因佩戴镜像而丢失；真实背包称号保留普通装备生命周期。
- 佩戴中书称号不能拖出至背包；取消佩戴后可以正常取出。普通装备物理移动与书镜像操作分开。
- 外观与属性称号独立；当前佩戴来源不能仅凭物品ID判断，避免相同ID的两个书槽同时显示佩戴。
- 服务端遵守现有领域/规则/协议/事件分层；查询无写入。

## Success Conditions

| ID | Observable condition | Required evidence |
|---|---|---|
| SC-1 | 具体方案覆盖客户端与服务端职责、等待队列、投影顺序、外观及登录恢复 | Spec/Plan 与目标函数、地址、来源分类 |
| SC-2 | 原件永久保留，镜像佩戴/取消/替换不进入背包，重复ID按实际来源区分 | 服务端回归测试与客户端目标路径审查 |
| SC-3 | 书行显示装备中，可再次佩戴；只更新佩戴状态，不重复获得提示 | 补丁构建、逻辑测试及部署后的用户实机验收清单；实机待测必须明确 |
| SC-4 | 拖出佩戴书称号被阻止；普通真实称号卸下及 Shift 外观逻辑保持正确 | 回归测试、客户端路径审查及实机清单 |
| SC-5 | 失败、快速切换及重登录可恢复，无永久请求锁 | 协议/领域/补丁验证及已知未验证边界 |
| SC-6 | 本地测试服务与实际客户端收到同一兼容方案，可关闭补丁回退 | 部署身份、文件哈希、配置备份、监听/就绪证据 |
