# Plan：称号簿佩戴兼容补丁

## Planning Choice

一个计划统一拥有双仓接口与顺序，具体地址校验结果追加研究文档，不另建重复Task清单。已定位原生旧称号自动路由、ACK物理交换、书行状态与静默列表入口，按本计划完成最小可测试联动后检查全部边界。

## Approach and Shared Decisions

服务端恢复完整原件投影：当前镜像的MirrorSourceUid在书原件中查出category/index/itemId，作为可空佩戴来源。没有镜像或来源不存在返回无绑定。查询只读。取消镜像必须匹配原件来源，佩戴原件禁止取出/交换；同源重复佩戴幂等。

扩展使用0166的整个原生列表之后追加显式兼容尾部，不改变每项26B结构或冒认未知4B字段。格式定为magic=`0x314D4254`（TBM1）、version=1、sourceCategory、sourceIndex、sourceItemId、trailerLength=24，各i32，共24B；无绑定为-1/-1/0。只在本项目当前自身列表InfoType0发送，查看其他人InfoType1保持原格式。扩展有别于原生协议，禁用插件不是完成用户目标的替代实现。

所有称号状态变化先完成CMD ACK，再经已有EventService投影装备位0002及静默0166书列表。佩戴/取消不再用000E制造物品获取；0168只留真实解锁。镜像删除事件在专用书操作里已有TitleStored/TitleWithdrawn投影，不重复刷新。

客户端新增独立0200_TitleBookMirror插件：仅对识别镜像与字节校验通过的入口操作。收到自身0166先验证末尾扩展，原生列表处理完成后更新绑定与UI。上游没有扩展时插件不启用镜像语义，不破坏比较环境。

016FA5F0仅书表op0/2、wornSlot13、兼容已激活时改走原生writer直接序列化019D/019C的五个i32。研究确认bypass=1仍受前置特殊容器拒绝，故不使用它。直接构包避开旧称号自动0013/019C路由及先行物品交换，保留原生flush→push pending7顺序。0111CE13/0111D172的局部helper调用改为有条件consume，只处理本插件发出的书佩戴/取消，其余委托原函数。书实体不从GET ACK搬走，装备实例由服务器投影创建。原生等待项不是插件可全局清空的状态。

UI setter025767F0按准确来源和当前自身簿覆写state，cache/图片/引用仍调用原setter；rebuild02578240之后归一化，避免物理空槽及相同ID造成错误勾选。book拖动及普通worn镜像→背包入口各加准确来源guard/路由，真实装备不拦截。0239外观保留独立路径。

交界修订：Main op6且实际worn匹配服务器镜像来源时转换为019C取消，无论目标背包槽是否占用都不交换镜像。Main真实称号op0替换镜像使用显式兼容019D，Space=TBM1 magic，Slot=Main原生game slot，ItemId=新真实称号，Category/Index=旧镜像书来源。服务端专用领域方法先验证来源UID、槽、物品、锁和资格，再同事务删除镜像并佩戴真实物品；失败保持旧状态。ACK统一为space3/slot13/旧category/index，准确消费book pending7，装备与Main刷新后书绑定none。两阶段取消再佩戴会破坏失败不变，已经撤回；不扩展未审查的0013原生ACK补丁。成功ACK执行完即释放本插件请求，不将busy永久绑定到下一份0166。

## Work and Dependencies

1. **T-001（RQ-001/002/004）**：服务端测试新增完整原件、重复ID来源、佩戴中取出/交换拒绝、同源重复佩戴UID稳定。依赖持久化UID，不新增数据库迁移。初次RED运行因沙箱构建进程挂起未获得结果；记录为实现后回归，不能宣称已观察RED。
2. **T-002（RQ-003/005/006）**：更新0166编码、title事件投影与错误码；装备投影先于书刷新；登录使用同一只读绑定。改协议测试验证兼容尾部和禁止000E/0168。检查真实背包称号替换、外观及通用镜像删除仍更新。
3. **T-003（RQ-002/003/004/007）**：根据三份client研究记录具体签名、预期字节、正常委托与等待项责任；实现0200插件、CMake目标和纯逻辑测试。全部目标预验后安装，不能盲写或改EXE。
4. **T-004（全RQ）**：双仓完整改动独立审查，修正后跑Application/Protocol相关回归及ClientHack构建/测试。文档标出ClientStatic与待实机验证。
5. **T-005（RQ-007）**：确认客户端退出；备份配置/插件与SQLite；发布独立服务runtime，停止经路径确认的上游测试服务，切回JP86；只复制0200新DLL到protocol2/plugins，不覆盖其他已部署插件或PVF。验证Hash、进程、监听、HTTPready及DLL加载身份。启动测试客户端仅用其原有启动方式，不动上游数据。

## Verification

启动恢复：Flush旧dump与实启保护阶段不同，按独立只读live-sites.json更正单处精确16B并新增init诊断。重新构建、签名与C策略验证；实际protocol2无登录启动确认全部插件初始化、线程放行，保留失败与修订工件。未改服务端，不重复无关完整测试；游戏内验收仍保留。

SQLite与真实PVF测试观察所有权、镜像数量、具体来源及重启恢复，协议测试观察消息族/字段与顺序；C测试覆盖无扩展/坏扩展、绑定错ID/重复槽、自身/他人视图、范围及行为选择。目标签名以权威dump和实际内存字节各自验证。实机清单：固定与自由称号轮换、取消再佩戴、重复ID单勾选、普通真实称号卸下、佩戴中拖出拒绝、Shift外观、重登录及是否无背包闪现/获得提示。
