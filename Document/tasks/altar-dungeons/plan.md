# 无尽与极限祭坛实施计划

## Planning Choice

同一联合交付，完整细节由此计划维护，不创建Task Unit。研究可以只读并行，写代码的工作顺序执行，.NET构建/测试串行。

## Approach and Shared Decisions

两个独立Altar领域服务，共享纯波次计划、通用动态Actor登记/机制清房门控与截止时间唤醒。Protocol负责请求/通知及命令调度，领域只处理状态和结果。使用当前工作分支，不新增工作区。实时投影在命令提交之后；可靠任务/成就事实入队。

## Work and Dependencies

| Work | Detail | Covers |
|---|---|---|
| T-001 | 只读核对每日时间/次数/费用、A21开场和死亡/难度/结算协议；记录来源、差异与采用策略 | RQ-002,RQ-007 |
| T-002 | Abstractions提供祭坛定义、阶段、波次、运行快照与两个领域接口；Infrastructure内容源读取当前PVF；Application规则准备计划 | RQ-001,RQ-003 |
| T-003 | 共享Run增加精确版本动态Actor登记与机制清房阻塞；死亡事务和地图清图事实同时遵循门控，保持普通图默认行为 | RQ-003,RQ-004 |
| T-004 | 两个领域服务处理入场、加载、波次、难度/超时、失败、结算与离场；扩展已有配额/时间检查而不散落新计数 | RQ-001,RQ-002,RQ-005,RQ-006 |
| T-005 | 新Altar协议切片、模块注册、即时投影与等待截止时间调度器；接现有入场/加载/移动/死亡/回城接缝 | RQ-005,RQ-007 |
| T-006 | 添加内容/规则/清房/重复请求/超时/拒绝/奖励与协议向量回归，串行构建；独立审查整体验收覆盖并修复阻断项 | RQ-001—RQ-007 |
| T-007 | 更新协议和实现文档，提交一个接受结果；核实当前服务身份并备份库/配置，发布独立运行包，停止旧实例启动新实例，记录健康/监听和测试清单 | RQ-008 |

T-001在具体门禁和codec落地前完成；T-002→T-003→T-004→T-005。T-006通过后才能部署。时间限制查证若有参考值未闭合，明确来源与策略，不能伪称原生已证实。不得为方便实机测试永久绕过门禁。

## Verification

分层内容与规则测试覆盖真实两个DGN所有关联MAP，状态转换测试覆盖最后活怪/待刷波次/选择超时/旧房间/重复结算；集成构造器判据与已有普通副本测试回归。部署前SQLite备份和完整性检查，部署后HTTP ready、监听所有者与产物身份；实机清单覆盖两祭坛正常/失败/退出及每日时间和次数拒绝。
