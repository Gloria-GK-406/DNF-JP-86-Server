# TaskContract：镜像阿拉德入场与当局任务

## Context

### Source Request

用户确认先迁移镜像任务生命周期到 EventBus，镜像功能验收后再讨论全部 Quest 迁移；执行授权：“ok，写一个任务契约后实现把”。

### Current Situation

基线 b9717c65；当前客户端点击镜像入口发送 CMD 02B6（实际地下城32、任务14299），服务端未处理。8000 是无实际地图的包装入口。客户端接收 NOTI 0278 后自动发送 001F 接受本局任务。普通任务日志会永久记录完成，不能直接用于重复的镜像任务。

## Goal

补齐镜像阿拉德的合法入场、本局任务接取/推进/结算/退出/再次入场循环，复用既有地下城能力；通过事件让任务系统自行处理生命周期，保持普通任务行为。

## Scope

### In

- 镜像专用入场协议、PVF 配对及入场规则、共用地下城加载。
- 绑定场次的镜像任务与必要的任务协议处理、奖励结算。
- 地下城离场事实、任务订阅清理、任务变化通知；重复与延迟事件隔离。
- 协议记录、自动化回归与实机待验收清单。

### Out

- 全部 Quest 系统的事件化迁移、随机深渊、客户端补丁。
- 部署、修改运行数据库、PR/合并及工作区清理。

## Constraints

- 保持 Handler → CMD → Domain Service → Rule Service 的职责边界；地下城不决定任务清理规则。
- 本局任务不能成为永久已完成任务；离开后不能继续推进或领奖。
- 旧场次或重复事件不能影响新场次任务；通关与离场分开。
- ClientStatic、上游参考、当前实现与实机验收证据分别标注。

## Success Conditions

| ID | Observable condition | Required evidence |
|---|---|---|
| SC-1 | 合法 02B6 进入实际地图，非法请求有明确拒绝，加载含本局任务且不触发重复入场 | 协议向量与入场流程回归 |
| SC-2 | 仅当前有效镜像场次可接取、推进和结算本局任务，重复请求不重复发奖 | 任务生命周期回归 |
| SC-3 | 离场事实由任务订阅者消费，清理只影响对应角色/场次；再次入场可重接相同任务 | 事件延迟、重复和跨场次回归 |
| SC-4 | 普通任务与普通/循环地下城行为保持 | 相关现有测试通过 |
| SC-5 | 未宣称实机已通过，交付明确待测流程 | 结果记录与协议证据边界 |
