# 任务契约：A21 账号荣誉品级

## 背景

用户询问「看看荣誉品级系统是怎么回事，我需要在服务端实现这个功能」，随后同意按调查结论写任务契约并实现。

JP86 的荣誉是账号共享成长。当前服务端会将角色封顶后的溢出经验计入账号荣誉，但荣誉通知仍填初始值，角色资料也缺少真实荣誉投影。开发、A21 参照客户端及参照服的荣誉 PVF 一致，可用来换算荣誉 Lv.1–59 和 6 个品级。

## 目标

同账号角色在 A21 上看到由持久荣誉经验算出的同一等级、品级和本级进度。满级角色获得经验后，客户端应收到结算后的进度，按原有资源显示跨品级提示和城镇特效。

## 范围

### 包含

- 使用匹配 A21 的 `etc/honorlevel.etc` 换算荣誉等级、品级和本级经验，兼容已有账号累计值。
- 接入登录、选角和退回选角的荣誉同步，接入有 A21 荣誉字段的角色资料以及现有经验通知路径。角色资料的荣誉应取被描述角色所属账号。
- 继续按现有角色经验与成长胶囊规则完成结算，复用既有奖励事务及防重复边界。
- 写入 A21 协议证据及验收步骤，完成隔离环境自动验证，分别记录 A21 实机观察和仍待用户验证的项目。

### 排除

- 新玩法奖励、荣誉经验倍率调整、客户端代码及资源修改。
- 线上部署、发版、远端分支或 PR 操作。涉及实际玩家服务切换的操作按仓库流程单独协调。

## 约束

- 保留现有玩家累计荣誉经验以及角色经验和成长胶囊的既有结算语义。荣誉显示投影不得使单次奖励重复记账。
- A21 协议字段宽度和已确认的现有包布局兼容。对存在歧义的字段保留证据边界。
- 功能工作区隔离于现有工作，自动验证使用隔离数据库和端口。

## 成功条件

| 编号 | 可观察结果 | 验证依据 |
|---|---|---|
| SC-1 | 新账号显示荣誉 Lv.1、本级经验 0。已有累计经验随 PVF 逐级换算，在门槛处升级并从本级经验 0 起算，达到荣誉上限后保持封顶。累计值超过 32 位仍可正确换算。 | 以开发 PVF、参照算法和边界用例核对，覆盖累计 `450,000,001` 对应 Lv.10、品级 2、本级经验 1。 |
| SC-2 | 普通角色经验奖励不跨 Lv.86 时，账号荣誉不增长。跨 Lv.86 时只有溢出计入，已满级时按现行规则累计，成长胶囊沿用既有规则。失败或重复的同一奖励不会重复记账。 | 数据库隔离用例核对角色经验、账号荣誉和胶囊的事务结果及已有结算回归。 |
| SC-3 | 登录、选角、退回选角、同账号换角色及已确认含荣誉字段的 A21 角色资料，同步所属账号当前持久值的换算结果。另一账号的角色在含荣誉字段的资料中使用自己的进度。 | 对非零账号数据检查出站帧，覆盖至少两个账号和同账号不同角色；已有协议兼容用例覆盖帧结构。 |
| SC-4 | 荣誉发生变化的经验通知携带同次结算后的等级和本级经验。后续无荣誉变化的经验通知保持已有进度，重登能取得持久结果。 | 从实际服务端奖励入口检查出站帧与累计值。A21 实机复核 Lv.9 到 Lv.10 的进度与品级提示、同账号换角色和城镇特效。 |
| SC-5 | 交付包含可构建的功能分支、证据与有前置条件和预期结果的 A21 验收步骤。 | 保存相关构建与测试结果；实际观察单独记录，无法运行的实机步骤标为待验。 |
