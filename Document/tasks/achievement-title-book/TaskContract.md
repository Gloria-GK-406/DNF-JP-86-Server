# TaskContract: 成就与独立称号簿闭环

## Context

### Source Request

“ok，这就没问题了。直接写任务契约实现吧，部署后我再测试”

已接受的信息流：业务事件 → EventBus → 成就系统 → 持久化 → AchievementCompleted → EventBus → 称号簿 → 持久化解锁/奖励 → TitleUnlocked → EventBus 通知订阅者 → 客户端 NOTI。称号存入和取出同样发布变化事件。

### Current Situation

现有服务有统一的事务事件投递能力、登录成就/称号簿投影及实际物品容器，缺少独立成就推进、完成和称号解锁/存取业务。开发沿用 task/abyss-research，基准 774f7b3581be1eeb1689b9220f4bf8ca31852caf。已有三份协议/深渊资料不属于本次改动，保持原样。

## Goal

实现可供 A21 客户端测试的成就推进、完成、称号解锁、称号簿存入/取出和重登恢复闭环，并部署新的服务端供用户验收。

## Scope

### In

- PVF 成就和称号簿规则读取、领域服务及持久化。
- 通用业务事实驱动成就，不让业务组件知道成就 ID 或称号规则。
- 成就完成事件可靠投递到独立称号簿；解锁及存取变化经 EventBus 通知投影。
- 接入成就与称号簿相关客户端协议；登录同步投影和他人查看查询保持只读；登录显式准备允许初始化/兼容数据。
- 兼容现有成就/称号物品数据，验证重复投递、事务回滚、重登和存取一致性。
- 更新协议证据和人工验收说明；保留运行数据并部署供用户测试。

### Out

- GM 成就编辑 UI、自定义成就内容、修改客户端/PVF资源。
- 本次未实现的其他游戏业务能力；不伪造未知成就条件完成。
- 推送、PR、主干合并、版本提升及工作区清理。

## Constraints

- 成就和称号簿分别拥有进度/完成事实及称号资格/实物管理，不相互直接调用；事件为协作入口，持久化为事实依据。
- 业务领域不得直接调用 INotiBus；通知投影消费 EventBus 变化。
- 查询不得完成成就、发奖励或产生其他写入。客户端上报不能无校验授予成就或物品。
- 遵守领域服务 → 规则服务 → PVF 分层；物品存取保留实例属性且不重复奖励。
- 保留现有用户数据和无关改动；自动验证不等同于 A21 实机验收。

## Success Conditions

| ID | Observable condition | Required evidence |
|---|---|---|
| SC-1 | PVF 定义决定成就条件及称号分类/槽位/奖励，支持与未支持条件明确 | 当前 PVF 解析验证和条件覆盖表 |
| SC-2 | 至少一个真实可操作流程推进并完成成就，事件驱动独立称号簿持久解锁 | 真实规则的领域/事件集成验证；人工测试步骤 |
| SC-3 | 成就完成和称号奖励在回滚/重复投递/离线或重启后保持一致且不重复发放 | 事务和恢复测试 |
| SC-4 | 称号簿存入和取出保留物品属性、验证槽位和容量、失败不丢失物品 | 存取持久化及协议测试 |
| SC-5 | 登录同步投影、列表、他人查看只读取已准备的持久化；提示及刷新经过统一事件投影 | 查询无写入验证、接线/架构检查 |
| SC-6 | 服务构建/相关回归通过，协议资料区分参照/静态/当前实现/实机证据 | 验证记录、协议更新 |
| SC-7 | 新服务端部署就绪且保留可恢复旧运行输入，用户可实机测试 | 运行路径、构建身份、监听与健康证据、人工验收清单 |

## Assumptions

- 现有 PVF 与 A21 客户端保持不变；协议布局以静态和参照证据实现，最终界面行为由用户部署后测试。
- 无法由现有服务器事实验证的客户端条件保留为未支持，不以客户端任意增量替代权威事实。
