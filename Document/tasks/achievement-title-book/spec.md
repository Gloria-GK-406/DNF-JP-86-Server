# 成就推进与独立称号簿

## Why and Outcome

玩家完成真实游戏条件后可看到成就进度和称号解锁；称号实物可以在称号簿与随身装备栏间存取，重登后仍正确。数据库不主动通知；通过现有可靠 EventBus 驱动成就完成到称号授予。

## Requirements

| ID | Requirement |
|---|---|
| RQ-001 | 成就规则来自 PVF，含条件类型、目标、计数、等级及关联；称号分类/槽位/允许物品来自 titlebook.etc。未知类型明确为未支持，不自动完成。 |
| RQ-002 | 原业务只发布通用成功事实；成就订阅者自行匹配条件，饱和累计/减少剩余量，仅首次完成发布 AchievementCompleted。 |
| RQ-003 | 成就系统不管理称号；称号簿可靠消费完成事件，读取持久化验证条件，首次授予持久化资格和真实物品并发布 TitleUnlocked。物品移出不撤销资格或再发奖励。 |
| RQ-004 | 事实与变化事件同事务；重复事件、失败重试及离线处理不丢进度、不重复奖励。客户端增量仅是提示，权威事实决定推进。 |
| RQ-005 | 019C/019D 存取验证位置、PVF允许物品、锁定、时效和容量；成功移动同一物品实例，失败不修改。事件通知与 CMD ACK 职责分离。 |
| RQ-006 | 登录、成就列表、称号簿及他人查看均只读。显式登录准备可兼容旧数据和初始化进度；GET 不作初始化。 |
| RQ-007 | 成就/称号变化只经 EventBus 通知订阅者转换为客户端帧；维持已有装备栏更新规则。 |
| RQ-008 | 新部署保留旧 runtime、配置、PVF和一致数据备份，确认新进程/监听/HTTP就绪及构建身份。 |

## Acceptance Criteria

| ID | Covers | Criterion |
|---|---|---|
| AC-001 | RQ-001 | 真实PVF可解析五分类，列明支持/未支持条件；无硬编码成就或称号ID决定奖励。 |
| AC-002 | RQ-002,RQ-003 | 真规则代表流程从业务事实推进到成就持久化、完成事件、称号实物和通知；相同事件不重复处理。 |
| AC-003 | RQ-004 | 回滚无事实/奖励，重启可靠待处理事件可完成，客户端任意delta不能得到奖励。 |
| AC-004 | RQ-005 | 加强/附魔等完整属性和物品身份往返不变，错位置、容量不足、已占槽或无资格失败时两端不变。 |
| AC-005 | RQ-006 | 读取多次表内容不变，重登恢复已持久化进度/称号；兼容旧表与现有物品容器。 |
| AC-006 | RQ-007 | 通知路径没有业务直接 INotiBus 调用；协议 body/ACK 根据参照及可用客户端静态证据测试并注明实机未验收。 |
| AC-007 | RQ-008 | 部署目录与身份可复现，备份可定位，新服务监听/健康成立，提供用户实机步骤。 |

## Evidence boundary

UpstreamReference、ClientStatic、CurrentImplementation 与 ClientVerified 分开。既有登录codec若与客户端reader不符必须在本次闭环中修正，不借用测试通过声明客户端已验证。客户端独有、当前服务无法验证的战斗评分等条件作为覆盖缺口记录，不按任意上报完成。
