# Implementation plan

一个详细计划统一维护规则、事件和物品交易的接缝；当前接口可以先行确定，不需要单独Task文件。

- T-001 / RQ-001,006：读取titlebook五分类及相关qst，建立成就和称号独立规则契约；保留原始条件并列出覆盖。核对A21 0167/0166/0168/019C/019D/01A1/01A8读取布局。
- T-002 / RQ-002,004：建立事务成就存储、首次完成记录、通用业务事件。先验证饱和进度/重复事件/事务回滚；再接入已成功的物品使用/材料消耗、任务完成、怪物击杀/地下城通关及角色等级事实。规则仅消费已实现能力，不在业务中匹配成就。
- T-003 / RQ-003,005：称号规则决定slot资格；可靠订阅完成事件，资格+真实item+TitleUnlocked同事务。使用现有IItemDomainStore移动完整实例，在写前完成存取验证；不重发已领取资格。
- T-004 / RQ-006,007：登录准备初始化/兼容数据；只读领域接口支撑entry和他人查看。协议CMD只驱动领域操作并ACK，LiveOnly通知订阅者转换成就列表、解锁和称号/背包刷新；无ICommandBus递归。
- T-005 / RQ-004,005,007：真实SQLite+真实PVF集成验证事件链、重试/离线/重登和存取；更新协议证据和用户步骤。独立结果审查，修复后重新验证。
- T-006 / RQ-008：确认实际旧运行进程/配置/数据库；Release发布到新目录；SQLite一致备份、迁移副本启动检查；停止已确认旧runtime并启动新runtime，验证监听、health和构建hash。保留旧服务目录且不改客户端。

## Protection and checks

- 保存三份已有资料SHA256并不纳入本次提交；构建/测试串行避免bin竞争。
- 自动测试保护持久化进度、奖励唯一性与物品往返结果；原有测试并未覆盖这些写入行为，因此新增集成测试有实质保护价值，不检查协作者调用次数。
- 标准完成审查由独立代理进行。完整构建及领域/协议/持久化/Host相关回归通过后接受一个本地结果提交；部署证据属于此次交付。
- 发布使用新目录，原数据库一致备份保留。若启动失败，先核对实际状态，再在用户已授权部署边界内恢复旧运行输入；不猜测进程身份或覆盖数据库。
