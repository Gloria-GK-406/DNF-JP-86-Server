# 普通决斗场擂台赛

## 范围与验收

在 `feature/pvp-duel-phase1` 上续做 CH60 普通匹配。用户要求沿用 1vs1 的流程完成擂台赛。六名玩家从大厅报名，组成两队。配对、确认、加载、连通、开战、轮换、整场结算和回大厅均可端到端验证。既有 1vs1 定级和自由房擂台战分别做回归。

先以六名独立会话验证原生匹配路径。选模式界面的 `max user=3` 提示可能支持预组队，预组队提交方式和队伍生命周期需要 A21 样本。用户确认擂台赛计入现有 20 场定级和 RP。

## 证据与实现

- **PVF / WireCaptured。** 当前 `etc/matchingmode.etc` 的 `integrated/relay` 配置左右各三席、最多六人，模式选择提示为 3 对 3、双方各一人出战。CH60 实际申请是 [CMD 0x0209 样本 2](../../../protocol/game/client-to-server/samples/0x0209-20261125-2.hex)，类别 `1`。
- **ClientStatic / High。** `0x01F9` 对阵名单按人数读取每条常规队员记录，组号 `1` 走普通决斗格式。`0x01FE` 按项目下标分发人数，因此分别投影 1vs1 和擂台排队人数。`0x012B` 在同一报文中列出各座位连通状态。
- **70Reference / Upstream / ClientVerified。** 70 的 `CRelayBattleMgr` 和 ServerS4A21 的擂台出战通知提供轮换参照。现有房间擂台规则已在 CH50 实测 KO、到点、补位、结算和回房。CH60 额外需要匹配入场协议，复用房间的模式 3 战斗和整场结果。
- **状态与事务。** `PvpRoomDomainService` 按频道监听和模式管理排队，配队、入座及离城在现有房间事务提交。每局冻结六个座位。全员确认后预加载，每名玩家加载并报告全部其他座位已连接后才开战。入场超时或离场取消临时房。开战后沿用擂台战候场、离场、判胜及每局幂等结算。
- **定级与 RP。** 两队用各自三名角色的赛前平均 RP 算预期得分。角色以自己的赛前 RP 与当前 K 值更新，正常成员沿用队伍胜负或整场平局，逃离者个人判负。整场计入一次，局内轮换不计数。共用现有赛季和原子写入流水，数据库仍为 v17。

## 验证顺序

1. 检查 1vs1 与擂台各自排队和取消。六个测试角色选擂台赛，先用五人确认继续候场，第六人加入后核对三对三名单。
2. 核对六端加载、连通和首轮出战。让一队第一、第二名队员依次 KO，先观察补位，最后一名 KO 后核对胜负和结果。
3. 确认六人正常回大厅并可以再排，核对整场只生成一条对局和六条角色结果。另测预加载离场不会留下结果或占座。

## 当前验证

416 项相关自动化通过。真实 TCP 覆盖 1vs1 与擂台分别计数、五人等待、六人配队、缺一条连通报告时仍等待、两次换人及末位 KO 后整局结算。预加载中断沿用普通匹配共用取消路径，自动化覆盖了该路径的 1vs1 超时。

2026-11-25 A21 六端实测通过普通擂台赛主流程。CH60 测试库记录了一场模式 3 擂台赛、六条个人结算和六条定级或 RP 结果。回大厅后进入练习决斗时发现客户端崩溃，见 [练习决斗设计](练习决斗设计.md#普通擂台赛后进入练习)。

实机角色对应 Client-08 至 Client-13，依次选择 PvPCapture、aaa、RelayMate22、RelayMate23、RelayMate24、RelayMate25。单人各自进 CH60 选择擂台赛。前两名角色在测试副本中均为 5/20，其余四名角色的定级从 0/20 开始，打完第一局应分别显示 6/20 和 1/20。

六个账号的测试角色已穿戴武器、称号、五件防具和三件首饰。测试副本中的 60 个实例逐一检查了 PVF 最低穿戴等级，武器与防具耐久均非零。辅助装备与魔法石槽均未开启。客户端擂台报名拦截是否完全通过待六端复测。

2026-11-25 03:02–03:03 CST，RelayMate24 和 RelayMate25 的 A21 选角因临时建档缺少 `character_expert_job` 被拒，表现为「网络连接中断」。按正常建角规则给两个测试角色补上零值副职业记录。修复后两账号均已通过 CH60 真实 TCP 登录、选角和全量背包下发，定级仍为 0/20。测试角色准备需同时核对副职业、角色状态、面板、设置与决斗战绩记录。

后续实机仍在加载页停住。服务端选角日志显示，每日补给叠加物品时遇到了共享同一物品记录的背包位置。按用户要求，以测试库中由「1123」改名的 PvPCapture 为模板重建 RelayMate24 和 RelayMate25 的角色档案、技能和物品，保留原账号、名字和独立定级。每个复制的物品位置都有独立记录。两个账号均通过 CH11 和 CH60 的 TCP 登录、选角和背包下发，CH60 仍显示 0/20，A21 实机复测待用户操作。
