# Specification：业务store与容器局部索引

## Why and Outcome

发放和移动以业务容器为对象，不再让客户端一个Equipment列表混合普通装备、装扮和宠物的结构控制领域归属。统一物品入口能把相同模板送到相同分区。

## Scope

物品/装扮/宠物store、容器索引及接入路径。勋章只留边界。仓库新行为、宠物成长、技能快捷键、部署不在本轮。

## Requirements

| ID | Requirement |
|---|---|
| RQ-001 | 角色取得业务store，再按内部容器类型取得container；普通物品、装扮、宠物具有独立归属，内部索引从各自空间起点开始。 |
| RQ-002 | 业务物品操作不得通过GameSlot转换后再用协议绝对索引读写；入站解码、事件发送/通知投影、旧存储兼容处负责坐标转换。 |
| RQ-003 | 模板分类和目标准入统一，普通发放、邮件、掉落、商城/奖励不得各自重建宠物/装扮分区规则。 |
| RQ-004 | 移动与穿脱双向校验容器、类型、容量和穿戴条件；失败事务不产生部分移动，保留实例附加信息。 |
| RQ-005 | 未知或冲突A21槽位须有证据裁决；不能把70/upstream或当前实现冒充客户端验证。 |
| RQ-006 | 已有登录、物品操作、奖励和发送结构保持兼容；可保留共享底层store和旧库物理坐标的适配，不直接修改运行数据。 |

## Acceptance Criteria

| ID | Covers | Criterion |
|---|---|---|
| AC-001 | RQ-001,RQ-002 | 三个store可取得归属正确的局部容器；跨分区同为索引0不会互相覆盖；业务调用无魔法偏移。 |
| AC-002 | RQ-002,RQ-005 | 已核定槽位的入站/出站/存储往返一致；冲突证据与未决项独立记录，未知地址拒绝而非别名映射。 |
| AC-003 | RQ-003 | 宠物装备、宠物消耗品、装扮及普通装备经过统一分类，在对应容器第一可用格落位；相同模板不同来源一致。 |
| AC-004 | RQ-004 | 空位移动、堆叠拆合、跨容器交换、穿脱交换成功；非法目标和回置失败保持两端原样，UID/附加属性不丢。 |
| AC-005 | RQ-006 | 相关自动测试及编译通过，数据库兼容由隔离测试证明；实机步骤明确但未经部署不标ClientVerified。 |

## Success Evidence

证据表记录来源、版本及可信等级；测试覆盖局部容器、分类及编码；完整审查检查迁移遗漏。实际客户端验收由用户操作，留待部署授权后执行，不把代码交付等同实机通过。
