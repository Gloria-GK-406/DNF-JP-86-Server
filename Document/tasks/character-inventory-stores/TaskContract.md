# TaskContract：角色物品领域分组与内部槽位

## Context

### Source Request

“对，在领域区域内只用内部索引，然后在传递给client时候做协议转换等行为。大概在event发送那里做。然后大部分的信息从client，上游和70服务端获取。走任务契约来按顺序完成重构。”

### Current Situation

当前容器按 Main/Equipment/Avatar/Pet 等线级列表组织；业务槽位绑定又转换回 GameSlot。普通物品放置把所有范围解释成 Main，商城单独处理宠物分区。穿戴表存在宠物与其他装备共用24的冲突，移动/准入规则没有完整覆盖宠物。上一轮已接受按物品、装扮、宠物分别归属store，勋章预留第四组、底层事务和物品实例继续共享的方向。

## Goal

角色物品操作通过按业务归属划分的store获取container；领域只使用内部槽位索引，协议坐标在入站和出站适配处理。已实现的物品流转保持一致性，并修正这次边界迁移覆盖的分区与交换缺陷。

## Scope

### In

- 物品、装扮、宠物三个store及内部容器；勋章归属预留，不新增勋章玩法。
- 依据A21客户端、上游、70参考核定物品分类和槽位映射，区分证据强度。
- 迁移相关物品发放、移动、交换、穿脱及通知投影入口；内部索引与持久化/协议坐标隔离。
- 保留统一按物品ID和数量发放入口；共享事务，保存已有物品身份和附加属性。
- 回归测试、协议/设计文档、实机验收步骤。

### Out

- 仓库新玩法、宠物喂养成长技能、完整勋章系统、技能快捷键重构。
- 部署、修改运行库、修改客户端、推送、合并与发布。

## Constraints

- 用户要求：领域只用内部索引；按页签对应的业务归属隔离，而非复制线级列表。
- 用户接受：共用持久化和事务；不因store拆分引入独立提交导致半次转移。
- 兼容：不能通过丢弃旧数据或把不明字段猜成已验证值完成迁移。
- 资料不一致时，70及上游仅作参考；保留A21差异与未决证据边界。
- 文档放Document；保留现有已接受的规划提交与其他工作。

## Success Conditions

| ID | Observable condition | Required evidence |
|---|---|---|
| SC-1 | 三个store按业务归属获取容器，领域不使用线级槽位偏移进行操作 | 接口、调用链和边界检查 |
| SC-2 | 入站/出站和存储适配保留正确坐标，未知映射不静默猜测 | 证据表、坐标往返与编码测试 |
| SC-3 | 发放来源共用归属规则，宠物装备/装扮不会错误落入普通装备分区 | 掉落/奖励/邮件/商城相关回归 |
| SC-4 | 移动、双向交换和穿脱都检查目标准入，失败不丢失或复制物品 | 成功/拒绝/回滚测试及实例属性保持 |
| SC-5 | 现有普通装备和装扮行为不回退，勋章与技能快捷键不越界扩展 | 相关测试、待实机验收清单，明确实机未执行项 |

## Authorization

| Capability | Evidence | Authorized scope |
|---|---|---|
| task | “走任务契约来按顺序完成重构。” | 本契约范围内的调查、实现、测试、文档及本地结果提交 |

## Requires Confirmation

- 运行库变更、客户端补丁或部署；远端推送、PR与合并。

## Assumptions

- “快捷栏”指物品快捷栏，技能按键继续属于技能配置。
- 独立store是业务分组；现有共享物品实例/事务存储可以复用。持久化旧坐标通过适配保留，不要求此轮改库结构。
