# TaskContract: 物品使用与奖励效果统一结算

## Context

### Source Request

“ok，写一个任务契约开始实现重构吧。这个范围会比较大，所以执行完一部分重构后要多多检查。主要是怕还有没进入到effect体系的情况。就交给你了”

此前已确认：物品状态可继续使用record；规则服务构建多个effect，自身消耗也必须显式表达。instance保留基础加减／设置行为，不能承载喂食或强化等完整业务规则。宠物Feed移入使用效果，保留Add饥饿等基础方法。强化成功／失败、保护、销毁返材料，以及任务奖励和经验结算均采用同一效果执行体系。

### Current Situation

基线b5506390，task/solo-play-roadmap工作区。普通使用已有小型效果列表；开包与制作已有库存批量结算；装备改造、任务奖励及专用道具仍有分散写入。部分隐含自耗、冷却和奖励状态变化不在计划中。此前用户已验收NPC强化／增幅等行为，本次须保留既有业务语义。

## Goal

相关业务由规则构建完整效果计划，通过统一领域执行服务整批结算；所有消费、奖励和关联状态变化均可从计划中观察，且不存在旧路径绕过体系造成重复、遗漏或部分成功。

## Scope

### In

- 共享效果record、规则计划、领域执行／分发、执行结果和现有通知投影适配。
- 普通物品使用、自耗／不自耗、冷却、精灵秘药；宠物饲料使用生成效果，pet只保留基础状态变化。
- 强化／增幅、保护券、失败惩罚及返材料、宝珠附魔、异次元操作、魔法封印、锻造；便携分解及其共用结算。
- 设计图、礼包、时装包、魔盒、袖珍罐、疲劳药、任务券；关联材料、金币、权益、幸运值、配额和状态变化。
- 任务完成交付／奖励、经验奖励与成长结算；共用经验发放的怪物／通关入口适配，保留各自规则和通知。
- 逐部分回归、独立审查和写入路径覆盖检查，最终自动验证及人工验收清单。

### Out

- 开发尚未实现的固定等级券、升级宝珠、魔法封印卷轴或所有PVF物品效果。
- 重写商城、交易、拍卖、地下城战斗、整个任务条件系统、宠物孵化／成长／专用背包。
- 改变现有概率、费用、奖励、等级上限或冷却持久化语义。
- 线上数据库修改、服务切换、客户端／PVF替换、push／PR／merge和工作区清理。

## Constraints

- 规则只接收领域收集的事实，遵守现有分层；不能自己查世界状态，执行器不重新判断业务成功／失败。
- 一个操作的业务状态变化必须完整包含于效果计划；正常业务概率失败也须生成完整计划，前置拒绝不留下修改。
- 整批结算、存储失败回滚；内存状态与数据库提交边界一致；重复请求不重复抽签、扣费或发奖。
- 保留装备身份、所有权、字段隔离与销毁不可复活保护；不能用陈旧完整快照覆盖新状态。
- 通知基于提交结果投影，保留协议顺序和零晶体过滤；发送通知不是业务effect。
- 获得经验与能否升级保持独立，保留不可变奖励明细和现有上限语义。

## Success Conditions

| ID | Observable condition | Required evidence |
|---|---|---|
| SC-1 | 共享效果体系支持多目标／多类型，未知效果明确拒绝，合法不自耗得到正确结果 | 真实执行器回归、类型注册检查 |
| SC-2 | 普通使用及宠物饲料通过计划表达消费／状态变化，无业务Feed旁路 | 源码路径检查、消费与宠物结果／回滚验证 |
| SC-3 | 装备改造的费用、成功失败、保护、损毁及返材料均进入计划 | 各入口覆盖表、既有语义回归、字段与身份保护测试 |
| SC-4 | 制作／开包／专用道具的所有关联变化进入计划，保留容量和期限限制 | 多堆材料／满包／腾槽／权益配额／疲劳任务券回归及写入审查 |
| SC-5 | 任务奖励和共用经验发放进入体系，保留任务及经验成长语义 | 任务、经验、跨级／满级、重复发奖与存储失败测试 |
| SC-6 | 整批失败不留下资产或内存状态变化，通知只反映提交结果 | 多effect失败／回滚／重放／通知顺序回归 |
| SC-7 | 纳入范围的旧写入入口均已迁移或有明确底层执行／范围外说明 | 分阶段写入覆盖记录、独立完整结果审查与遗漏检查 |
| SC-8 | 可交付重构代码、更新文档及可按顺序执行的人工验收列表 | 新鲜构建和相关测试记录、文档、实机状态明确保持未验收 |
