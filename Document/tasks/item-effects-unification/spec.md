# Specification: 完整效果计划与统一原子结算

## Why and Outcome

每一次使用、改造或奖励操作都能从不可变效果计划看出全部业务状态影响；执行结果与持久化一致，未知效果、前置拒绝和执行异常不会留下部分改变。业务规则决定计划，实例／存储提供基础操作，协议只投影结果。

## Scope

遵循TaskContract。覆盖普通使用、宠物饲料、装备五类改造及共用分解、设计图／开包／专用道具、任务奖励和共用经验发放。保留宠物内部、容器分栏、各入口协议与已实现规则。未实现物品效果不新增。

## Requirements

| ID | Requirement |
|---|---|
| RQ-001 | 规则生成包含全部目标和变化的不可变effect列表；自耗为显式效果，合法空计划与内容缺失拒绝分开 |
| RQ-002 | 执行器明确分发所有类型，目标匹配所有者／空间／预期物品或装备身份；同目标连续变化不会丢失，未知类型立即拒绝 |
| RQ-003 | 全部效果属于同一操作事务；容量、费用和目标前置检查整体成立，失败不保留数据库或冷却／秘药／宠物运行态变化 |
| RQ-004 | 普通使用和饲料通过计划表达；删除宠物Feed业务方法，保留基础加减行为 |
| RQ-005 | 装备成功失败、保护、损毁、返材料、附魔、气息、封印、锻造、分解全部进入效果计划，保留身份与字段隔离 |
| RQ-006 | 制作／礼包／魔盒／袖珍罐／疲劳药／任务券的源自耗、费用、奖励、权益、幸运、额度和进度变化显式规划 |
| RQ-007 | 任务交付和奖励、经验及关联成长采用共享效果执行，保留获得经验与成长上限的独立语义；共享经验入口不得绕回旧写入 |
| RQ-008 | 抽签每计划一次，重放只复用提交结果；通知与重试不重新执行业务效果，ACK／绝对NOTI顺序及零晶体过滤不变 |
| RQ-009 | 各迁移阶段和最终结果有写入覆盖检查，所有范围内旁路迁移或说明为执行器底层实现；保留范围外系统明确边界 |

## Acceptance Criteria

| ID | Covers | Criterion |
|---|---|---|
| AC-001 | RQ-001,RQ-002 | 不自耗道具数量不变；跨栏同索引正确；同槽累计扣除正确；未知类型或换物拒绝无修改 |
| AC-002 | RQ-003 | 多effect第二步及存储提交故障均整批回滚；扣除腾槽及竞争最后槽位正确；内存状态只在提交后生效 |
| AC-003 | RQ-004 | 普通药剂、共享冷却、秘药、饲料增量与最后一件清槽符合既有行为；保留宠物时钟／待发经验同步且回滚不丢奖励，没有可调用的Feed业务入口 |
| AC-004 | RQ-005 | 原装备相关回归通过；失败／保护／返材料计划可检查；UID和无关属性不变，销毁旧目标不可复活 |
| AC-005 | RQ-006 | 原制作／开包／疲劳／任务券回归通过，满包与拒绝无扣费，权益／幸运／配额均从effects落地 |
| AC-006 | RQ-007 | 任务交付、物品金币、经验及已有转职／技能重置奖励一致提交；跨级／满级符合既有语义，经验来源明细保留 |
| AC-007 | RQ-008 | 按各入口请求／业务事件的现有生命周期，同一次已提交操作重试不再次扣除／抽签／发奖，合法下一次相同参数操作正常执行；不能仅凭参数或计划内容判定重放。提交失败无成功缓存或通知；通知顺序和零晶体行为回归通过 |
| AC-008 | RQ-009 | 覆盖表逐条对应入口、规则构建、效果执行和底层写入；独立审查无未解释旁路，人工清单涵盖主要业务闭环 |

## Success Evidence

分阶段Task文件记录实际改动、局部检查和独立审查；覆盖表列出迁移与豁免；最终验证提供构建、相关自动回归、完整结果审查及人工验收清单。源码／自动测试只说明CurrentImplementation，不将本轮未执行的实机路径写成ClientVerified。
