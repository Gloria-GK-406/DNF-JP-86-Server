# Implementation Plan: 规则构建效果，统一领域结算

## Planning Choice

先建立共享契约并迁移一个可验证入口，再按现有领域迁移；后续详细适配依赖第一部分实际接口。Task Units拥有局部实施细节，本Plan保留整项覆盖与依赖。复用已有隔离工作区与接受基线，不创建中间提交。

## Approach and Shared Decisions

- 不可变效果record表达明确的业务变化；领域层汇集事实，规则服务构建列表，ApplyEffects领域服务解析／执行。不会使用闭包、任意委托或“运行整个旧业务”效果包装旁路。
- 共享执行上下文明确账户／角色／会话和时钟；物理效果带业务空间与预期物品，装备效果带身份。实例保留基础设置／加减和身份保护，完整业务只在规则计划中决定。
- 注册式分发器先确认完整数组的类型与目标；同一事务当前状态累计变化。现有库存容量模拟可作为底层批量执行能力，源消费、奖励、冷却、权益等仍为显式效果，不能从第一条消费猜规则或隐含追加影响。
- 执行失败必须异常退出或明确使事务回滚；不能部分执行后正常返回Failure而让UnitOfWork提交。数据库参与者、执行串行门和提交后内存参与者复用；effect内不派嵌套CommandBus。
- 执行结果汇集已应用变化和业务结果，转换为现有receipt以保留协议；通知不放进effect。随机结果在构建阶段一次确定，重放与合法下一次操作沿现有请求／业务事件生命周期区别。
- 专门保留获得经验与成长更新分开、宠物时钟与待发经验同步、任务转职／技能重置、保护券选择与失败返材料等已有复合语义。
- 每部分检查实际写入调用，将其归类为规则计划构建、effect执行底层、生命周期／范围外或尚未迁移；未迁移项必须进入后续单位，不以接口包装视为完成。

## Verification

- 普通使用基线与新增多effect同槽累计／跨栏／未知类型／回滚检查。
- 装备各入口既有真实PVF回归，UID／无关字段／保护／失败返材料；便携分解费用产物。
- 制作和开包的多堆材料、扣除腾槽、满包回滚、期限、权益／幸运／配额，疲劳药和任务券。
- 任务和共用经验的奖励／交付／成长、跨级满级、转职技能与合法重复操作；提交后通知投影和重放。
- 最终独立累积漂移、完整结果挑战／审查以及新鲜构建测试。保留基线失败的独立说明，不将未执行实机路径写成通过。
