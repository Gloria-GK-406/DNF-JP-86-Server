# Specification：活动管理与累计周签到

## Why and Outcome

一个注册的周签到实现同时提供 `IManagedEventDomainService` 和周签到玩法接口；活动管理服务汇总实例的领域信息，不另存一份可脱离实例的客户端日历定义。客户端从日历进入原生周签到窗口，推荐副本通关后看到进度，达标点击签到获取奖励。

## Scope

本阶段只实现 A21 2208 累计周签到。Web 新增活动管理入口，以已注册类型列出单一当前期次并配置展示信息与有效期、启停；不开放任意活动 ID、客户端资源地址或奖励原始字段输入。静态奖励及窗口绑定读取当前 PVF 对应脚本，禁止未知内容时退回硬编码奖励。

首例覆盖普通每周签到与累计奖励。PVF 的第二目标44及bonus字段已确认存在，但玩法/请求语义尚未闭合；上游也未实现该变体。首例不开放bonus按钮、不推定其为补签规则，状态字段保持未启用，并在使用说明中明确边界。

## Requirements

| ID | Requirement |
|---|---|
| RQ-001 | 管理服务列出注册活动并启动/关闭；两领域接口指向同一实现对象。管理列表包括未启用、未开始、已结束状态；客户端投影按共用有效性判断选择活动。 |
| RQ-002 | 周签到配置、启停与期次持久化。关闭再开启同一期不清空进度；明确的新期次与旧期次隔离。配置编辑不偷偷创建新期次或刷新已领取资格。 |
| RQ-003 | 日期和日/周分桶沿用 UTC+8，精确时间边界以当前时间与配置区间判断；每个账号在同一期每周最多签到一次。活动累计签到及对应阶段奖励沿用实际 PVF。 |
| RQ-004 | 活动进度只来自已成功完成的推荐地下城结算；纳入既有结算事务和去重边界，失败结算与重试不重复计数。关闭/未开始/过期不推进进度或允许领奖。 |
| RQ-005 | 达标签到将周奖励、适用累计奖励投递到当前角色邮箱，并保存本周领取状态；重复/并发签到不重复发奖，存储失败不产生部分状态。 |
| RQ-006 | 入场发送实际 `EVENT_INFO` 和个人周签到状态；有效通关/签到后刷新状态，启停/配置后具备在线状态刷新路径。未启用时仍发送客户端需要的清空/停用状态，不能保留旧活动可操作状态。 |
| RQ-007 | A21 042D 状态按客户端 450B 布局编码；0441 请求按已证14B读取，不凭未知字段授予进度；结果按客户端4B结果读取编码。所有业务判断基于服务端账号、当前角色及活动状态。 |
| RQ-008 | Web `/gm/events` 列出活动和期次状态，编辑与启动/关闭独立操作；使用现有 All 权限、CSRF、版本并发保护、原子审计和 NotiBar。保存冲突/结果未知后要求重新读取，避免重复写入。 |
| RQ-009 | 管理 UI 显示规则来源和奖励概要；配置合法性、实际 PVF 内容和物品有效性由服务端检查，错误不给虚构默认玩法。 |

## Acceptance Criteria

| ID | Covers | Criterion |
|---|---|---|
| AC-001 | RQ-001 | 同一注册实例通过两接口获取一致状态；管理列表始终可看，日历按生效及玩家上下文过滤。 |
| AC-002 | RQ-002,RQ-003 | 保存→重建服务→读取配置和账号周进度不丢失；启停保留领取标记；显式新期次不继承旧期次计数；起止与周界前后正确。 |
| AC-003 | RQ-004 | 成功推荐通关推进一次；非推荐、失败、结算重放不推进；已关闭和时间区间外不推进。 |
| AC-004 | RQ-005 | 未达标拒绝；达标领取对应 PVF 奖励；再次或并发请求最多产生一次奖励；故障回滚后仍可正常领取。 |
| AC-005 | RQ-006,RQ-007 | 请求解码、450B状态、4B结果及EVENT_INFO与原始客户端静态消费者相符；入场/通关/领奖/关闭有刷新，隔离协议路径证明业务结果。实际GUI测试列为独立人工验收。 |
| AC-006 | RQ-008,RQ-009 | HTTP覆盖权限、CSRF、严格输入、版本冲突、审计回滚；UI覆盖读取、编辑、启停、失败恢复，Chrome隔离环境确认列表和操作窗口。 |

## Success Evidence

静态核对绑定当前 A21 镜像/PVF身份；真实 SQLite 和现有结算路径自动验证业务与资产一致性；协议/HTTP/前端验证与相关回归、Release 构建；人工清单覆盖真实日历、窗口、通关、领奖、重登及关闭，不把待测项目称为已通过。
