# 祭坛死亡倒计时的触发与处理边界

当前A21静态接收链表明：通用复活币数字倒计时由NOTI0020死亡广播下游启动，
秒数由客户端本地计算。它不是CMD0028成功ACK或NOTI0360中携带的时长。
建议保留死亡状态同步及原生页面；没有足够依据为隐藏页面而修改协议字段。

## 触发链

| 环节 | 已核对行为 | A21 VA |
|---|---|---|
| 死亡广播 | 读取actorId、state、末字节；state=0进入死亡路径，1/2进入复活路径 | 0114F44E–0114F487、0114F6DD–0114F6ED |
| 死亡成员状态 | 将state==0写入角色死亡标志；随后统计未死亡成员 | 011500D0–011500E8、01150212–01150221 |
| 通用界面状态 | 普通路径未死亡人数为0且其余界面门通过，调用死亡UI setter(2) | 0115030B–01150416 |
| 计时器启动 | 死亡UI的+4C写入2，重置+30计时器 | 0138AE39–0138AE4E |
| 数字绘制 | 由9999减去本地已过毫秒，再除1000并钳到0；使用coin_countdown.img | 0138A36C–0138A39E |
| 回城关闭 | 帧回调检测城镇状态1后，调用同一setter(0) | 0138B39D–0138B3C1 |

普通死亡界面经getter02300BC0取得，挂在父UI的+8F54；
祭坛结束界面经02300CD0取得，挂在+8F8C。0360原因0/1走共同分支，
调用010C5860(10)更新自己的状态与计时；已核对的直接路径没有调用通用死亡UI的setter(0)。
因此不能把祭坛结束通知视为关闭通用倒计时的消息。

倒计时到期发送CMD002A还要求死亡UI的+54许可位非0；
普通setter尾部会清除此位。出现10秒数字本身不保证到期自动发回城请求。
它与祭坛在失败通知后等待50秒的服务端回城期限互不等价。

## 回包选择

- 0020的末字节在已核对handler后续未见被用作时长或隐藏开关，不赋予无证据语义。
- 不将state改成1/2隐藏页面：这会向客户端宣告复活。
- 不删除0020：它还同步角色死亡标志与存活人数；70祭坛死亡分发器也保留普通死亡广播。
- 0360目前已确认的字段是结束原因与是否还有挑战次数，没有通用死亡UI隐藏字段。
- 其他战争／突袭／复活通知也可能改写同一组件，但有各自状态副作用，不当作祭坛UI关闭消息。

若产品要求完全不显示该通用组件，应进一步在ClientHack研究祭坛场景下的UI兼容处理，
保留死亡同步与祭坛失败状态；这属于客户端显示适配，不能表述成已证明缺少某个服务端死亡字段。
