# TaskContract：固定成就条件的实时事件检查

## Context

### Source Request

用户认可业务只报告事实、成就订阅事件后按需检查、登录补检的方案，并授权：“ok，那你来弄个新的工作区，写任务契约和实施，部署。”

### Current Situation

主干 d0427ce3 的任务完成已发布 QuestCompleted；固定条件检查只在登录和升级运行。物品、装扮、宠物及穿戴变化没有统一成就事件入口，因此条件满足后可能必须重登才解锁。

## Goal

玩家完成转职/觉醒，或改变持有物品、装扮、宠物和穿戴状态后，已支持的固定条件自动检查并解锁；各业务保持独立，查询保持只读。

## Scope

### In

- 新工作区、任务契约、实现与独立结果审查。
- 复用任务完成事件，补充统一物品变化事实及成就订阅。
- 按变化范围检查未完成条件，账号共享材料覆盖所属角色。
- 保留任务型称号的受理/正式完成路线、永久解锁和登录兜底。
- 验证后部署服务端，保留原运行数据与回滚输入。

### Out

- 新增未支持的 PVF 条件、累计过程成就、称号簿奖励与客户端补丁。
- PR、主干合并、分支/工作区清理。

## Constraints

- 用户明确要求业务通过 EventBus 报告事实，由成就决定规则；不得直接调用成就或通知组件。
- 业务失败、事务回滚不得解锁；重复投递不得重复授予。
- 所有产品修改位于本工作区；不修改客户端 EXE、PVF、插件。

## Success Conditions

| ID | Observable condition | Required evidence |
|---|---|---|
| SC-1 | 任务完成后检查任务依赖和最终转职/觉醒状态；不绕过受理与正式完成 | 事件订阅回归与真实任务链测试 |
| SC-2 | 物品数量、装扮、宠物孵化及穿戴变化能在不重登时检查相关条件 | 统一持久化入口与可靠事件消费测试 |
| SC-3 | 已激活跳过，查询无写入，回滚不产生事件，重放不重复授予 | 自动化边界测试与独立审查 |
| SC-4 | 部署版本启动就绪且沿用现有玩家数据 | 旧进程/数据库确认、回滚快照及新运行身份和健康检查 |

## Authorization

| Capability | Evidence | Authorized scope |
|---|---|---|
| task | “ok，那你来弄个新的工作区，写任务契约和实施，部署。” | 本范围工作区、契约、实现、检查及服务端部署 |

## Assumptions

- 固定条件使用事件消费时的权威当前状态；短暂状态不补造历史，累计过程仍消费独立事实增量。
- 原客户端对新解锁的显示路径已验收；本次玩家交互仍由用户部署后测试。
