# TaskContract：地下城怪物声明统一解析

## Context

### Source Request

用户提出由子代理收集全部怪物声明结构，再统一生成解析器，并授权：「那你就写任务契约，直接跑吧。实现后部署一下」。

### Current Situation

追击歼灭战 MAP 22036 的 `[dummy]` 可选字段被固定十 token 解析误判为截断，切房请求抛出异常。根特防御战 MAP 21314 的特殊对象怪物模板未进入房间声明。现有输出只保留怪物 ID、等级、类别等少数字段，无法表示完整生成来源。

## Goal

盘点当前权威 PVF 的怪物声明形式，提供统一、保留语义的解析结果供房间规则与生成流程使用；有效变长记录不再导致断线，并部署供用户实机验证。

## Scope

### In

- 子代理调查当前 PVF、上游和 70 参考，明确结构覆盖及未知语义。
- MAP 普通怪物、APC、相关可选标记和特殊对象生成怪物声明的统一解析、模型与现有消费者接线。
- 条件生成声明的结构与条件信息保留；区分立即实体、占位和生成模板。
- 追击歼灭战有效记录、根特防御战对象模板及已有普通/深渊房间的回归保护。
- 文档、独立结果审查、验证与保留回滚产物的服务端部署。

### Out

- 客户端补丁、PVF 修改、全新条件脚本解释器或所有地下城机关行为重建。
- PR、主干合并、版本发布与其他工作区清理。

## Constraints

- 遵循内容源→规则服务→领域实例→协议投影的既有职责；资源解析不执行角色业务。
- 合法未知语义不能默认为普通敌人；损坏记录不能静默变为空房。
- 保留生成来源及原始顺序，防止生成模板错位、提前清房或错误奖励。
- 不改原工作区未提交文档和既有数据库数据。

## Success Conditions

| ID | Observable condition | Required evidence |
|---|---|---|
| SC-1 | 声明盘点覆盖当前 MAP 资源，说明结构、代表样本、参考边界 | 全量扫描统计及上游/70调查记录 |
| SC-2 | 当前合法声明可解析，变长记录不会破坏后续记录；原始语义与来源可取得 | 模式回归、实 PVF 22036/21314 与全量结构验证 |
| SC-3 | 房间消费者保留普通/APC/深渊既有行为，生成模板身份与清房/奖励语义一致 | 内容、领域及房间协议回归和独立审查 |
| SC-4 | 新服务运行于已验证构建，旧产物和数据保留 | 部署身份、监听、健康及启动检查；实机效果待用户验证 |

## Authorization

| Capability | Evidence | Authorized scope |
|---|---|---|
| task | 「那你就写任务契约，直接跑吧。实现后部署一下」 | 调查、统一解析重构、测试、文档、独立审查、本地结果提交与服务端部署 |

## Assumptions

- “完整”以当前实际 PVF 的结构覆盖为准；参考实现或自动化验证不等于 A21 实机验证。
