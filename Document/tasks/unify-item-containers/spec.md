# Specification：已有容器与共享材料归一化

## Why and Outcome

晶体存入金库应是物品在容器之间移动，账号共享只改变归属。对调用方，同一角色和账号的容器提供相同读写与结算语义，不再出现材料余额兑换实体的中间模型。

## Scope

以 TaskContract 的 In/Out 为准。现有金币钱包不改；邮件材料入口适配新模型，附件整体托管形态不在本次重构范围。

## Requirements

| ID | Requirement |
|---|---|
| RQ-001 | 容器身份包含可区分的所有权和容器种类；同账号不同容器同号槽不冲突，操作者不能越权访问 |
| RQ-002 | 11 种共享材料使用和其他物品一致的内容、发放/消耗/移动及事务机制；没有第二份可写余额 |
| RQ-003 | A21 已知材料槽解析到共享容器；合法金库移动、拆分、合并守恒；不合法请求按现有协议正常拒绝 |
| RQ-004 | 原账号材料迁移准确、可重复且失败原子；保留合法高数量，历史冲突不得猜测相加 |
| RQ-005 | 背包、装备、时装、宠物、金库及非本次材料的行为和身份保持；进出游戏读取当前容器事实 |
| RQ-006 | 受影响的材料发放、消耗、分解、丢弃、教程/任务/副本奖励、邮件、开盒/购买等现有入口均与统一模型一致，保留各玩法资格和材料来源限制 |
| RQ-007 | 说明新模型、证据边界和实机步骤；不把自动验证升级为 ClientVerified |

## Acceptance Criteria

| ID | Covers | Criterion |
|---|---|---|
| AC-001 | RQ-001 | 相同账号两个角色读取共享材料一致；不同账号及账号金库同索引独立；旧会话/越权请求不改状态 |
| AC-002 | RQ-002, RQ-006 | 材料生产、消耗和移位统一读写物品容器；生产代码没有仍可修改旧账号材料列的路径，所有数量投影来自容器 |
| AC-003 | RQ-003 | 11 种共享材料与支持该物品的个人/账号金库存取数量守恒；满仓、错误槽、超限拒绝不产生部分写入，已知材料槽不抛未映射异常导致断线 |
| AC-004 | RQ-004 | 旧数据库初始化迁移后每账号每材料总量等于迁移前；再次启动不增加数量；插入失败回滚；异常历史重复明确拒绝而不吞数 |
| AC-005 | RQ-005 | 相关现有回归通过；跨容器实例转移保持 UID、时装/宠物附加信息；重新加载仍保持物品与所有权 |
| AC-006 | RQ-002, RQ-006 | 至少覆盖发放/消费/分解/丢弃/邮件材料路径；失败事务中材料、其他物品、费用/领取状态一致回滚；通知不成功不重复结算 |
| AC-007 | RQ-007 | 旧材料袋设计说明注明已替代；协议实现记录及 human test list 包含存取、换角色、重登、数量刷新和拒绝场景 |
