# TaskContract：装备基本信息与强化增幅规则重构

## Context

### Source Request

用户：『这样取舍就好，直接开始重构任务吧。写个任务契约，主要是为了最后收尾时候做验收。这个改动还是要细致一点』。

已接受的设计：装备 record 只提供基础内容事实；是否可普通强化、增幅/赋予气息、锻造由统一的装备强化增幅规则服务查询；最大耐久为 `ushort?`，没有耐久机制为 `null`；非法内容显式抛异常，在运行时异常边界记录错误并失败当前操作，必需启动内容非法时启动失败。

### Current Situation

当前 `EquipmentReinforcementEquipmentDefinition` 混合基本信息、费用类型索引和普通强化资格。无 `[durability]` 的合法首饰使读取器返回并缓存 `null`，异次元规则复用该读取器后错误拒绝。解析失败未记录具体字段，业务层将其静默转成 UnsupportedContent。1123 的手镯 100310498 已真实复现；肩甲 100170123 已能赋予智力，普通升级入口尚未支持克伦特增幅等级提升。

## Goal

合法装备提供完整基本信息，规则按操作决定资格；合法无耐久首饰不因耐久缺失被拒绝；真实解析错误可定位且不会伪装成正常业务拒绝。保留已有装备实例、事务、协议和强化结果行为，交付可按顺序执行的最终验收清单。

## Scope

### In

- 通用装备基本信息契约及内容源，移除预计算普通强化资格和费用表索引；保留 PVF 原始禁止内容声明供规则解释。
- 最大耐久 `ushort?` 的缺失、零值、正常值和非法内容语义。
- 统一强化/增幅资格与异次元、锻造相关规则服务；迁移所有依赖旧装备基本信息读取器的生产调用方。
- 普通强化费用类型映射、满耐久判断、已有异次元字段与禁止内容限制的行为保持。
- 装备基础内容解析错误的字段级异常、异常日志和事务失败边界；合法不支持仍返回具体业务拒绝。
- 自动回归、真实 PVF 的首饰与武器/防具验证、最终人工验收清单和收尾证据。
- 准备保持现有服务功能的可部署产物；实际切换须在游戏正常退出、无业务请求时进行。

### Out

- 新增克伦特增幅等级提升、重新设计成功率或失败损毁奖励。这是后续功能，不将资格重构冒充增幅完整交付。
- 设计图金色晶体耗尽“获得 x0”的显示修复。
- 修改正式角色资产、数据库结构、客户端/PVF，远端 push、PR、merge、分支清理。
- 全仓 PVF 解析框架或其他无关内容源重构。

## Constraints

- 沿用实例负责状态操作、规则负责决策、领域服务负责检查结算的边界。
- 合法缺少耐久与真实非法字段必须区分，不用哨兵值，不以 Warn 日志后返回 null 继续掩盖解析错误。
- 不丢失 `[impossible contents]` 原始限制，不放行原本禁止操作的装备。
- 保持物品 UID、数量、金币、当前耐久、强化等级、异次元属性与其他字段的持久化/投影兼容；失败无成功回包或资产变化。
- 保留当前工作区所有既有改动，仅审查/提交明确属于本任务的差量；人工最后验收前不标功能完全验收。
