# Specification: 迷妄之塔挑战闭环

## Why and Outcome

角色使用当前 PVF 的迷妄之塔规则进入地下城 11001，连续挑战 15 层，按实际结果结算后返回。服务端独立持有塔状态，普通地下城继续保持原有行为；实际 A21 表现最终由集中实机验收确认。

## Scope

继承 TaskContract 的 In/Out。领域内使用 IllusionTowerDgn/TowerRoom，复用的是传统 dgn 的组织方式和已有基础资产能力，不共用普通 Cell/迷宫/Boss 通关流程，也不建立通用塔框架。

## Requirements

| ID | Requirement |
|---|---|
| RQ-001 | 迷妄之塔有独立领域服务、挑战实例和 TowerRoom；整局身份、成员和成绩由 dgn 唯一持有，房间事实由当前 TowerRoom 持有 |
| RQ-002 | 从当前 PVF 解析 15 层有序地图、演员和必要参数，固定/随机 APC 为敌对时参与清层；显式种子生成内容，缺少必要内容拒绝发布房间 |
| RQ-003 | 按角色资格、材料和运行归属进行入场；扣券和发布运行态一致，失败保留先前状态；一个角色只能在一种副本中 |
| RQ-004 | 房间依次装载、开始、完成；下一层由层序决定，必要客户端过渡信号不替代服务端完成检查；同一层只能推进一次 |
| RQ-005 | 开始、死亡、清层和装载上报必须属于有效成员和当前挑战/房间；重复和迟到消息不重复推进或奖励 |
| RQ-006 | 完成记录与奖励计层分离；末层成功、失败、退出和断线有明确结果，清理后可以重新进入且旧操作无效 |
| RQ-007 | 奖励由有依据的规则确定，资产与已结算事实一起提交；结果可重复投影但不能重复领取，通知失败不重新发奖 |
| RQ-008 | 协议 008E–0092、009F 及必要共享入口具备真实注册与领域接入；未知字段保留形状，不以无证据值驱动资产 |
| RQ-009 | 相关任务进度和返回/当前会话投影从已提交事实产生，不在编码器或handler中制造业务事实 |
| RQ-010 | 普通副本与通用能力回归通过，文档说明证据层次、未获实机验证处和集中验收路径 |

## Acceptance Criteria

| ID | Covers | Criterion |
|---|---|---|
| AC-001 | RQ-001 | 生产类型与调用路径不依赖普通 Cell/迷宫切换；领域代码不读具体网络消息、不绕过规则服务读内容 |
| AC-002 | RQ-002 | 真实 PVF 的 15 个 mapId 顺序正确；3/9 随机 APC 层、5/8 纯 APC 层和15混合层均有正确类型内容；同种子生成相同内容 |
| AC-003 | RQ-003 | 合格角色入场一次扣一张4183；不足材料/低等级/重复入场/准备失败不部分提交；普通副本与塔互斥 |
| AC-004 | RQ-004,RQ-005 | 未清场不能推进，重复开始/死亡/清层/过渡不跳层；新层重建装载状态，迟到旧层操作不影响新层 |
| AC-005 | RQ-006 | 第1层和中途失败、15层通关、退出、断线均有可断言的实际完成数/结果和清理效果；重新进入为新挑战 |
| AC-006 | RQ-007 | 奖励规则对成功/失败的输入确定；事务回滚后资产与运行态一致，重复提交和通知重发只保留一次入账 |
| AC-007 | RQ-008 | 字节向量确认008F演员14B、零塔掉落行路径及009F开始1B/清层17B；共享入场/装载/死亡/退出入口确实命中塔服务；协议注册检查通过 |
| AC-008 | RQ-009,RQ-010 | 已提交层/击杀事实触发适当任务处理且不重复；普通副本相关和解决方案验证通过，明确静态/自动化/待实机三种证据 |

## State and Evidence Boundary

挑战阶段至少区分进行中、结算中/已结算、结束；房间阶段区分装载、战斗、完成。具体类型和事务参与方式由实现选择。挑战结束原因与奖励是否已提交不混为同一布尔值。

本地源码/70参考仅证明各自实现。首层和跨层装载放行、排行和奖励UI的精确时序必须有当前客户端静态或实帧依据；无新实帧时保留待实机验收，不伪称原服等价。门票日补充不属于本次玩法政策。

## Success Evidence

内容/状态/事务行为测试、协议向量和handler/注册集成测试、相关与全量回归、最终独立评审；测试日志归到本任务验证目录或任务声明的本地artifact目录，human test list记录玩家可操作场景。
