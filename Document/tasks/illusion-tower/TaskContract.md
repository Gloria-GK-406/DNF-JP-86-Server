# TaskContract: 迷妄之塔独立领域实现

## Context

### Source Request

用户："可以，就按这个方案写任务契约实施吧"。

所批准方案：迷妄之塔独立领域服务维护本次挑战的 dgn 实例，内部战斗场景命名为 `TowerRoom`；参考普通地下城结构，按层序自动 NextLevel，塔业务代码独立；完成入场、战斗与层推进、结束/失败/退出/断线、结算和协议接入。先自动化验证，再提供集中实机验收入口。

### Current Situation

基线 `762d0cb4`。研究见 [IllusionTowerResearch-20261003.md](../../IllusionTowerResearch-20261003.md)。PVF 的地下城 11001 共 15 层，包含普通怪、固定和随机 APC。当前普通副本的 MazeCell/Boss 房/翻牌语义不适用；已有身份、事务、物品、经验、任务和通知能力可以调用。客户端静态证据与 70Reference、对照实现的差异必须保留，不能将它们标成实机已验证。

## Goal

在现有服务端上交付迷妄之塔从入场到逐层战斗、成功或失败结算并返回的可验证实现，使用独立领域模型，保持普通地下城行为与现有资产一致性。

## Scope

### In

- `IllusionTowerDomainService`、本次挑战实例 `IllusionTowerDgn`、当前战斗场景 `TowerRoom` 和所属规则/内容能力。
- 当前 PVF 15 层配置、入场材料、普通怪物及固定/随机 APC 内容；未知规则继续静态核查并标注依据。
- 当前挑战归属与通用消息的最小路由接入；首层与后续层装载、开始、死亡、清场、自动选择下一层。
- 区分实际当前层、已完成层与奖励计层；通关、战斗失败、主动退出、断线清理及重新进入。
- 奖励确定/提交/展示、经验与物品事务、重复请求防护、相关任务事实投影。
- 所需协议切片、编解码、注册、协议记录、自动化回归和集中 human test list。

### Out

- 死亡之塔、绝望之塔等其他塔的实现和公共塔框架。
- 普通副本难度扩展、觉醒等其他玩法；普通副本的大范围重构。
- 猜测或新增每日门票赠送政策、排行榜运营功能；缺少证据时保留明确边界。
- 修改在线服务、玩家数据库、客户端二进制；远端发布、PR/合并、分支清理。

## Constraints

- 用户已接受：一塔独立领域实现，参考结构而不共享塔业务流程；场景类型使用 TowerRoom，不能以现有 Cell 类型承载塔状态。
- dgn 是本次挑战的事实所有者；TowerRoom 管当前层战斗事实。遵循 Handler → CMD → Domain Service/Instance → Rule Service 与提交后通知架构。
- 角色不能同时属于普通副本和塔；重复或过期消息、定时操作不能重复推进、结算，或污染新房间/新挑战。
- 敌对 APC 参与完成条件，友方/非战斗对象不被误算；完整场景准备失败不能发布半成品房间。
- 资产提交与结算事实必须一致；发帧失败不重新发奖。普通地下城和既有资产行为保持兼容。
- 只在隔离测试中执行运行验证，保留当前游戏服务和用户数据；文档使用 Markdown 放在 Document，协议知识按仓库规范放 protocol。
