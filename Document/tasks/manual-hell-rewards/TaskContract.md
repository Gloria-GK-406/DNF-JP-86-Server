# TaskContract: 主动深渊冻结奖励与组结算

## Context

用户确认“可以，就那这个逻辑实现吧。然后部署，我再看看效果”。当前 Cell 工厂禁止深渊演员掉落，已验证真实 APC 死亡输入能进入现有死亡处理。缺票拒绝修复 9c6ff160 尚未部署。

## Goal

主动深渊在创建 Cell 时冻结自身和整组奖励，在对应死亡时释放，通过已有地面物品协议供客户端拾取，然后部署供用户验收。

## Scope

- 包含 PVF 奖励规则、深渊奖励领域服务、组身份、一次性结算、回归验证和部署。
- 不包含随机深渊、客户端补丁、GM 配置或声称还原未知官方爆率。

## Constraints

- 领域服务组合规则服务；规则服务读取 PVF。协议仅投影已经提交的结果。
- 组 ID 来自入场计划，重复 ID 合并。最后一个演员死亡才结算，空奖励和不合资格仍完成结算。
- 死亡和掉落在现有 Cell 聚合内原子提交，查询不抽奖、不发奖。

## Success Conditions

| ID | Observable condition | Required evidence |
|---|---|---|
| SC-1 | 冻结奖励仅在指定演员或组末死亡释放一次 | 自动回归，包括不同死亡顺序、重复死亡和空奖励 |
| SC-2 | 使用当前 PVF 的深渊难度、奖励次数、装备池和演员资格 | 内容解析和真实 PVF 检查；未知参数明确记录 |
| SC-3 | 普通掉落与拾取保持，缺票修复一并上线 | 相关回归、发布构建、运行身份与健康检查 |
