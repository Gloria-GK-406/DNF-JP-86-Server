# Spec：统一次数责任与DirectAsync

## Why and Outcome

成功入场或消费立即落下对应次数，失败不扣；界面在提交后显示真实次数，重登仍一致。业务负责声明发生了什么，不分别维护计数存储。

## Scope

消耗品、现有权益、镜像次数。保留已有规则与原始计数兼容；不扩展到无现成限制的地下城，不做客户端patch。

## 结构与职责变化

重构前：业务/Effect → 各自次数表；PublishAsync只能事务外；镜像计数缺少投影。
重构后：业务成功事实 → EventService.DirectAsync → 次数订阅者 → 统一配额领域服务 → 同一事务存储；提交完成 → EventService → 次数投影 → NotificationBus → 客户端。领域门面保留各自资格/规则，计数一致性由统一服务承担。EnqueueAsync继续负责可持久化异步消费，直接计数订阅不进入该队列。

## Requirements

| ID | Requirement |
|---|---|
| RQ-001 | DirectAsync 不入队/不自动开启事务；依序await订阅者、传播失败及取消；事务内继承当前事务，事务外可用于不要求事务的运行事件。移除IEventService.PublishAsync旧命名。 |
| RQ-002 | 统一配额服务提供只读状态和受事务保护的消费/更新。所有三类现有次数写入收口；额度、周期、冷却、预计旧值与溢出检查保留。业务通过直接事件更新次数。 |
| RQ-003 | 同次操作只扣一次；拒绝不扣；后续业务失败回滚次数；权益双倍罐的轮次/每日总量和续期不被清空绕过。 |
| RQ-004 | 原有数据可读取，不无故重置；每日周期沿用领域现有规则。查询按周期解释计数但不落库重置。 |
| RQ-005 | 同步通过EventService，提交前无网络输出；失败投影不能回滚已成功业务。登录/重新打开相关UI/必要重置时机可恢复权威快照，离线不阻塞。 |
| RQ-006 | 镜像0279第二u32为已入场数；成功加载CMD0025的客户端本地自增必须由后续权威快照校准。首字段含义不足时标明证据边界，不冒充完全确认。消耗品021E/权益036F保持原协议及饱和/拒绝策略，不截断。 |
| RQ-007 | 原配置和DB备份，部署保留回滚输入，核验新的运行身份和入口。 |

## Acceptance Criteria

| ID | Covers | Criterion |
|---|---|---|
| AC-001 | RQ-001 | 直接await顺序、事务内成功/异常回滚、事务外运行事件和取消均有测试；原持久化调度测试通过。 |
| AC-002 | RQ-002,RQ-003 | 三类次数来源全搜索无业务直接写表；成功消费一次/拒绝/异常/重复业务幂等、冷却/上限/溢出与总量续期有回归。 |
| AC-003 | RQ-004 | 原表值保持；周期内读回一致，跨周期读零且不写；不同领域周期不被静默改变。 |
| AC-004 | RQ-005,RQ-006 | 投影测试断言未提交/回滚无提示、提交后权威快照、离线与重登恢复、加载ACK后镜像数不重复；codec核验。客户端真实操作由用户另验。 |
| AC-005 | RQ-007 | 保留旧配置/运行路径/DB快照，新监听所属进程与artifact哈希匹配，health/bootstrap ready；提供实机清单。 |
