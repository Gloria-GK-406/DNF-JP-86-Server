# 实施结果

## Changed

不可变 Mail/Builder、装备/堆叠/金币附件及收发回执；邮箱服务包含发送、查询、已读、逐附件领取、删除。仓储复用旧三表增量迁移。装备转交保留原 items 行，账号材料按账号账本结算。登录经统一邮箱查询服务选择有效未删除邮件，避免角色服务的循环依赖。

## Why

原 Clear 会删除未在同批重新落位的装备，故增加窄的原实例转交能力。未领取附件以独立身份记录；取得 SQLite 写锁后读事实并条件更新。服务异常使当前事务回滚，避免上层捕获后提交部分资产。金币按全额成功判定，禁止静默截断。

物品身份架构判据原先假定所有形状都能表示堆叠，因此全部 Identity 必须nullable；本次用户明确要求纯装备引用，给 Equipment 和 EquipmentTransferItem 两个装备专属形状增加具名例外，普通库存/堆叠身份规则保留。
