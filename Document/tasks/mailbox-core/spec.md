# Specification: 邮箱核心服务

## Why and Outcome

调用方通过不可变 Mail 和邮箱服务完成离线投递与资产交付，装备原实例在寄出和领取间保持不变。服务结果供后续协议投影消费。

## Scope

以 TaskContract 的 In/Out 为边界。新增核心写路径并统一登录读路径；不部署、不改玩家数据，不新增邮件 wire 协议。

## Requirements

| ID | Requirement |
|---|---|
| RQ-001 | Builder 产生不可变内容；来源、收件人、文字、期限、装备引用、堆叠数量与金币明确；无效输入明确失败。 |
| RQ-002 | 发送验证权威事实，角色资产扣除和邮件落库同事务；系统投递不扣玩家资产。 |
| RQ-003 | 装备邮件保留既有实例与全部属性；不能同时存在于背包和未领附件。 |
| RQ-004 | 按独立附件身份领取，归属、期限、重复、容量和金币上限检查与入账原子结算。 |
| RQ-005 | 查询、已读、删除及到期规则统一；未领有效资产不能普通删除，已领正文保留。 |
| RQ-006 | 数据重载和登录投影一致，旧记录保留且不猜测重建已有装备。 |
| RQ-007 | 分层遵守 AGENTS；返回资产回执；文档准确标明服务完成与客户端未验收。 |

## Acceptance Criteria

| ID | Covers | Criterion |
|---|---|---|
| AC-001 | RQ-001 | SC-1 的结构和业务反例被拒绝；builder 后续变化不改变已建邮件。 |
| AC-002 | RQ-002,RQ-003 | SC-2/3：真实 SQLite 中装备、堆叠与金币发送成功；注入失败后全量不变；原 UID/属性往返且重复发送失败。 |
| AC-003 | RQ-002,RQ-006 | SC-4/8：离线系统投递后重建服务，查询及登录仍见同一内容和状态。 |
| AC-004 | RQ-004 | SC-5/6：逐附件、越权、重复/并发、容量不足、金币截断和故障回滚用例资产守恒。 |
| AC-005 | RQ-005,RQ-006 | SC-7/8：阅读/删除/期限边界重载后相同，登录不显示已领取附件。 |
| AC-006 | RQ-007 | SC-9/10：构建与相关回归通过，服务无网络发送，交付说明区分协议缺口。 |

## Success Evidence

隔离临时 SQLite 业务集成测试为资产真值判据；库存/入场回归与编译检查兼容性。独立结果审阅和 fresh verification 覆盖全部 SC。无实机证据不标 ClientVerified。
