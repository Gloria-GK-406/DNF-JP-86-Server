# 邮箱采样部署独立审查

审查目标：`feat/mailbox-core` 工作树在 2026-09-24 的未提交候选；范围仅为 **A21 收件、0144 查询、005F 领取、0086 已读/删除的采样部署安全**。依据 [TaskContract](../TaskContract.md)、[Spec](../spec.md)、[Plan](../plan.md)、当前生产 diff 与新增 `Game/Mailbox` 代码，按 `reviewing-work/references/code.md` 的完整代码审查标准判断。**本 verdict 只批准进入受控实机采样，不代表 A21 实机行为已通过，也不覆盖尚未注册的 `005E/013B` 玩家发信或整个 TaskContract。**

## 阻断修补与结论

先前 `0060` 严格空体 decoder 的断线风险已解除：`ProtocolModule.cs:120-122` 不注册打开请求 decoder/handler，只保留直接调用所需的 handler 实例和响应 encoder。现有网络层对未注册 wire key 记录完整 body 并丢弃，不进入严格 decoder；新增回归断言验证 `005E/0060/013B` 均不注册。本轮点击打开只用于采请求，不期待打开 ACK 或邮箱窗口刷新。

先前 `0061` 两组缺字节已在当前 writer 修正：第一组每条无条件写 `length=4 + u32(0)`、`length=8 + u64(0)`、块后 `u8`，尾部写 `u32/u32/u8`；第二组每条正文在 `u16 state` 后写 `u8`。本次逐字段复核了纯正文双记录测试：两组记录及最终帧尾消费完整，`CreatedAtUnixSeconds` 和 `RemainingSeconds` 均为 `int`，写入宽度是 4 字节；第二长度块的 `0L` 才按 8 字节写入。这消除了已知的纯正文错位风险，但金币、普通物品和时装需要后续实帧校准。旧报告 [receive-wire](../../../outputs/mail-protocol-integration/receive-wire.md) 中“只有时装才有双长度块”的说法应撤回。

基于当前源码、静态 A21 消费路径和定向测试结构，未发现阻止**空邮箱及纯正文收件/查询受控采样**的剩余代码问题。执行者报告 5 个真实 SQLite 集成测试和 6 个协议定向测试通过；本审查未并发运行测试，根任务仍在执行完整构建和更广测试。测试完成后，需核对结果无新增失败再部署采样候选。

## 已确认的安全边界

- `005F` 输入为精确 4 字节，线级附件 ID 经 `MailboxIds.DecodeAttachment` 转内部 ID；命令核对当前连接、所选角色和账号。`FindByAttachmentAsync(recipient,id)` 以收件角色筛选，随后同一写事务标记附件并入账；重复、过期、越权和入包/金币上限异常走回滚。`MailboxAssetDomainService` 在该事务内生成绝对资产投影，命令提交后才发布。未见客户端输入被直接当作资产值或发件人身份。
- `005F` 的 A21 成功 ACK 入口 `0x0111B340 → 0x01A4E860..0x01A4ECE8` 用回显 ID 查本地附件，计算的是提示文字的金额，刷新邮箱 UI，并可发下一次领取/状态请求；未见角色金币或背包加法。服务端目前先发送绝对背包/金币通知，再发送 ACK，不会由 ACK 把资产加两遍；该顺序还保证自动下一次领取前资产投影已到客户端。
- `0086` 只接收 0/2，0 经域服务删除时拒绝仍有效且未领资产；其他 action 安全拒绝。回复回显邮件 ID 与 action，客户端可按对象键处理。
- `0144` 查询使用长度前缀原始名字字节，库中按角色名字节精确查询。成功回包包含本版静态读取的额外字段，末字段已改为 0，避开 `0x01A3F4AE` 的特殊校验分支；错误 7/21 只在相应条件回送。名字运行时代码页仍待非 ASCII 实帧确认，采样中不能把 UTF-8 断言升级为 `ClientVerified`。
- 现有空邮箱仍编码为第一组计数 0、重置字节 0、两个 `u16` 0，共 6 字节；入场查询仍读取同三张邮箱表，空箱本身不会进入有缺口的记录循环。此为静态和本地编码结论，不替代 A21 实机验收。

## 采样部署前建议

本次采样保留 `0060` 为未注册帧，利用现有网络层日志得到完整 body；取到空体实帧后，当前严格 decoder 才有注册依据。若后续体非空，再按字段语义设计只读打开处理。未注册时用户点击邮箱不会得到打开 ACK，须在测试说明中明确：本轮可核对登录入场 `0061` 与 `0144` 收件人查询，打开动作只用来采请求，不期待邮箱 UI 刷新。

纯正文无物品/金币时，`0x01A4AC70` 在相关三个资产参数皆零时直接返回 false，第一组 seed 不创建本地附件对象；可仅编码第二组正文，减少不必要的第一组解析。若仍保留 seed，必须满足第一组完整字段长度；其尾 ID 为 0 还是正文 ID 的效果尚未实帧验证。

`005E/013B` 尚未注册是本轮定向采样边界，不应在交付说明中称玩家发信闭环已可用。部署需继续遵守计划中的在线会话退出、数据库保留和可回滚要求。A21 实机采样须重点记录 `0061` 空邮箱/纯正文入场表现、`0144` 非 ASCII 查询原始帧与 UI、`0060` 请求原始 body。若客户端断线或字段错位，应停止这轮验证并回滚候选。
