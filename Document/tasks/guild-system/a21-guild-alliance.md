# A21 公会联盟验收

日服 2016 年改版把结盟入口放在博肯的「查看同盟」。每个公会可以和一家公会结盟。[日服改版说明](https://arad.nexon.co.jp/campaign/2016april_guild.aspx)

## 实机操作

两套客户端由 ClientStore 的 `guild-alliance-lab` 通道生成，连接隔离验收服 `127.0.0.1:52480`。Client-36 对应 `1123`（公会「测试测试」），Client-37 对应 `GuildPilot`（公会「同盟验收乙」）。两名角色分别是各自公会的会长。可在 PowerShell 直接打开两套已登录的游戏客户端。

```powershell
python 'E:/Project/DNF/DNF-JP-86-Server/.worktrees/guild-system/Document/tasks/guild-system/.local-evidence/a21-guild-benefits/guild-alliance-acceptance.py' launch both
```

1. 两个角色分别到暗黑城，找头上标着「公会管理」的博肯。确认会长菜单同时出现「查看同盟」和「解散公会」。
2. 用 `1123` 打开「查看同盟」，确认推荐列表里没有自己所在的「测试测试」。搜索「同盟验收乙」并发出申请。用 `GuildPilot` 打开同盟申请列表，核对申请公会名和留言。
3. 用 `1123` 撤回，核对双方列表清空。再发一次，由 `GuildPilot` 拒绝，核对双方申请消失。
4. 第三次由 `GuildPilot` 同意。两边公会信息页的「同盟公会」应显示对方。任选一边重登，检查结盟还在。
5. 任选一边解除同盟。两边「同盟公会」栏都应清空。
6. 如要再测解散，重新结盟后用 `GuildPilot` 在博肯处解散「同盟验收乙」。该公会是独立验收库里的单人空仓公会。确认另一边的「同盟公会」栏同步清空。

## 协议与验证

| 动作 | A21 CMD | 当前实现 |
| --- | --- | --- |
| 申请 | [0x02F1](../../../protocol/game/client-to-server/0x02F1.md) | 公会 ID、名称和留言，双方资格按当前数据重验 |
| 发出和撤回 | [0x02F2](../../../protocol/game/client-to-server/0x02F2.md)、[0x02F3](../../../protocol/game/client-to-server/0x02F3.md) | 查询发出的申请，发起方会长可撤回 |
| 收到、同意和拒绝 | [0x02F4](../../../protocol/game/client-to-server/0x02F4.md)、[0x02F5](../../../protocol/game/client-to-server/0x02F5.md)、[0x02F6](../../../protocol/game/client-to-server/0x02F6.md) | 接收方会长审批，对方会长收到更新后的申请列表 |
| 解除 | [0x02F7](../../../protocol/game/client-to-server/0x02F7.md) | 一方会长解约，双方在线成员收到最新公会资料 |

A21 b1 `025A57AF` 在查看同盟权限有效时直接跳过解散分支。验收客户端的 0200 兼容补丁在添加「查看同盟」后继续执行原本的会长检查。只有原生的会长检查能添加「解散公会」。菜单效果待实机验收。

公会信息 `NOTI 0x0046` 的同盟记录由 b1 `01196390–0119645E` 读取，字段为对方公会 ID、名称 DSTR 和图标。成功结盟、解除和解散后从最新关系生成投影。

隔离线路 `1795775146293874500` 验证申请、双向重复防护、撤回、拒绝、同意、跨频道和普通成员刷新、单同盟上限、重登、解除、解散以及外键一致性。53 项迁移测试、51 项公会协议测试和两项客户端兼容测试通过。原生窗口、菜单以及申请时间显示待用户验收。

A21 实机中的「测试测试」和「同盟验收乙」已结盟。两边打开推荐列表时，这两家公会都应被排除。解除同盟后，对方应重新进入推荐。
