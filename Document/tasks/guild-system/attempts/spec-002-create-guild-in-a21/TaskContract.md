# 任务契约 · 在 A21 中创建公会

## 背景

用户选择「完整公会系统分期实现」。首期已交付持久化、原子创建和身份查询。A21 创建流程的验名、宣传、许可与最终提交有旧分支的静态证据及 ServerS4A21 的后续行为记录。JP86 还需要把这些请求与当前会话及持久化公会接起来。

## 目标与范围

通过本项目支持的 A21 原生入口完成单人建会。创建者能看到正确的余额与公会身份，角色重登之后可恢复身份，切到未入会角色时不会串会。覆盖会话取消、余额不足、重名和重复提交。协议材料补到归属页；申请、完整名册、主管理菜单和其他公会玩法继续由根任务负责。

## 约束

- 同一客户端标识的上游实机记录和静态读路径可以用于协议假设。A21 身份位置、字符编码、通知顺序和重登行为的 JP86 验收，用匹配项目组件及 PVF 组合的真实帧与界面观测建立。
- 不向玩家库写入测试。测试服务分配独立端口和 SQLite 库，客户端由 ClientStore 生成或登记。
