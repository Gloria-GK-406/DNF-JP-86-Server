# 创建与身份实施计划

同一个流程可以按客户端发送顺序落实，再通过相同隔离环境完整验收。

| 工作 | 内容和方法 | 对应需求 |
| --- | --- | --- |
| T-001 | 核对 A21 历史 evidence、当前协议页及上游同版本创建链。以此为 decoder 和回包候选，补实机确认编码与按钮、ACK 时序。建立仅使用新 SQLite 库和独立端口的 Host，ClientStore 使用 trace 配置、匹配 PVF，记录原始收发和组件版本 | RQ-001、RQ-004 |
| T-002 | 领域层增加当前选角会话的创建草稿。验名复用核心名称／成员规则，取消及失效由选角会话的生命周期清理。将名称、宣传、许可和最终提交接入 typed CMD。使用现有工作单元写公共公会关系；提交后按实证顺序登记金币、身份、创建和 ACK | RQ-001、RQ-002 |
| T-003 | 接入公开身份查询。沿选角和当前状态查询装配身份，在各 USERINFO 子型分别编码，复用现有外观刷新。以现有无会样本和有会实机对照相邻字段与清空路径 | RQ-003 |
| T-004 | 以真实客户端记录创建、余额不足或重名、换角、重登和他人查看。通过独立客户端或受控采集复验，形成针对性协议／事务回归并更新协议证据与目录 | RQ-001 至 RQ-004 |

隔离服务必须可确认绑定地址、数据库位置和 PVF，客户端动作、帧顺序和账目变化如实记录。代码与静态对照只能满足其覆盖部分，界面恢复以 A21 观测为准。
