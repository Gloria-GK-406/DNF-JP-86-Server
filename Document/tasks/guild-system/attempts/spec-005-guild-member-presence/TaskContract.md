# 任务契约 · 公会成员上下线通知

用户指定「把公会成员上下线通知接上吧，名单状态也一起实时更新。做好后开两个客户端，我来测试」。A21 静态已确认原生上下线通知能够更新已有成员项，并生成进入频道和退出游戏的提示。

沿用[已完成的成员名单](../spec-003-view-guild-roster/spec-result.md)的在线状态投影。本期对 SC-04 的贡献为同会成员频道状态提示。

| 意图 | 归属 | 结果 |
| --- | --- | --- |
| 公会成员上下线 | `in_scope` | 在线同公会成员看到角色进频道和离开游戏的原生提示，已打开的成员名单同步更新 |
| 完整会话入口 | `in_scope` | 登录进入游戏、正常回选或退出、断线和会话替换均遵循确切会话状态，避免身份串用和重复下线 |
| 用户验收 | `in_scope` | 独立服保留测试公会及成员，由两个 A21 客户端复测 |
| 其他社交功能 | `preserved_upstream` | 由[根契约](../../TaskContract.md)和[分期图](../../multi-spec-map.md)承接 |
| 发布和线上变更 | `not_applicable` | 本轮授权覆盖独立验收 |

## 成功条件

| ID | 可观察结果 | 验证 |
| --- | --- | --- |
| AC-1 | 同公会的在线成员看到进频道和退出提示，已打开成员名单中的角色状态原地变化，无需手动刷新或重开名单 | 线路核对登录、回选与断线通知，以用户双端确认上线、下线提示及名单变化作为 A21 实机验收 |
| AC-2 | 仅当前公会的其他在线成员接收状态。未进游戏的会话不触发，不让过期清理覆盖新的在线会话 | 受众隔离、重复清理和快速重登的自动化或线路证据 |
| AC-3 | 独立验收服使用上期测试公会和角色，打开两个已登录的 A21 客户端供用户操作 | 验收服运行和两端窗口确认 |

本轮用户明确授权本子任务实现、独立验收服和两个客户端启动。使用现有功能分支及根任务的本地检查点机制。
