# 任务契约 · 金币捐赠换公会 GM

用户在成员名单验收后指定下一功能为「金币捐赠换GM点」。A21 公会信息页已有金币捐赠入口。当前部署 PVF 的 `etc/(r)guild.etc` 声明每 1,000 金币兑换 1 点。

## 范围与根意图

| 意图 | 归属 | 结果 |
| --- | --- | --- |
| 公会成长中的金币捐赠 | `in_scope` | 当前公会成员按 PVF 兑换，扣随身金币，增加共享 GM 和捐赠者的累计贡献 |
| 持久化及同步界面 | `in_scope` | 扣款和积分同成同败。当前面板刷新，可在重登和重新打开后恢复 |
| 协议依据和隔离验收 | `in_scope` | 记录帧依据、旧库升级和 A21 验收结果 |
| GM 消费、排行榜、月度结算、运营规则与其他成长玩法 | `preserved_upstream` | 由[根任务](../../TaskContract.md)后续分期负责 |
| 正式环境切换、PR、发布 | `not_applicable` | 本任务使用根任务的本地实现与隔离验收授权 |

## 成功条件

| ID | 可观察结果 | 验证 |
| --- | --- | --- |
| AC-1 | 公会成员输入有效金币，金币减少所填数量，公会 GM 和捐赠者的累计贡献均按部署 PVF 比例增加，本次操作立即刷新面板的 GM。普通成员与会长均可捐赠，重登仍可读回 GM 和个人累计贡献 | 隔离线路、库账与 A21 面板对照，另一名成员的个人累计保持原值 |
| AC-2 | 无公会、金币不足、畸形金额、余额溢出或存储失败均不留下扣款和积分变化 | 拒绝线路、事务回归及失败注入 |
| AC-3 | 旧库升级保持已有公会、角色金币及关联，既有公会初始 GM 和捐赠贡献为 0 | 迁移与回归测试，隔离库与客户端步骤 |

## 授权

| 能力 | 用户原话 | 范围 |
| --- | --- | --- |
| task | 根任务「好，你来写一个任务契约然后实现它吧」「完整公会系统分期实现」，本轮「那没关系了，我们继续下一个功能。金币捐赠换GM点」 | 执行本期本地实现、可回退检查点和隔离验证 |
