# 公会管理代码审查

审查基线 `624bcd8b2`，目标为含 `0x02EC` 失败码修正的工作树。依据[子契约](../TaskContract.md)和[规格](../spec.md)，使用 `reviewing-work` 的 Code 和 Deliverable 准则。

- `0x0046` 保留原六项 `u32 + 24 字节` 顺序，公会配置、会长标志和个人贡献按当前成员视图组合。三项写入通过持久会长成员关系鉴权。变更和面板读取位于同一写工作单元，提交完成后才回执和发布。
- 持久化用例涵盖普通成员拒写、交叉公会隔离和两项职级字段互不覆盖。升级从 18 到 19，独立读取迁移线路库确认 `quick_check=ok`，两个角色的签到及原 50,000 金币捐赠仍在，包含预期的职级配置和宣传修改。
- 初审发现非法职级名称的 `0x6C` 会被 A21 的 `0x02EC` handler 忽略。修正版将其映射为该 handler 实际消费的 `0x24`，`0x02EB` 同样用 `0x24`，宣传 `0x02E3` 保留自己的 `0x6C`。复核依据为 A21 b1 的 `0111E292`、`0111E29B` 和 `0111CA3D` 分支及当前 `InvalidInputError` 实现。

加成购买与实际生效由父契约 SC-05 承接。原生界面是否按预期展示，以用户实机验收为准。
