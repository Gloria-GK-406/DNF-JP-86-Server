# 公会创建与成员关系基础

## 目标与范围

提供后续客户端切片可使用的核心公会身份、名单和事务动作。角色依据数据库中的有效成员关系显示公会身份。A21 自己和他人的界面、创建许可与社交通知在后续阶段接入。

| ID | 需求 |
| --- | --- |
| RQ-001 | 新库与主干的旧库都能持久化公会、成员、申请，既有账号、角色和资产保留 |
| RQ-002 | 合格角色创建一次，公会名唯一，初始只有一名会长。创建需从 PVF 获取价格，当前开发 PVF 价格为 300000。扣款、建立会与成员、清理待申请的结果一并提交 |
| RQ-003 | 无会角色可申请，首期一人只保有一条待申请。会长只批准指向本会的待申请，成员关系与申请消费一并写入。身份与成员查询可读取同一关系 |
| RQ-004 | 普通成员可退会，会长可移除本会普通成员和解散自身公会。当前成员受软删保护，非成员软删同时清理其申请 |

| ID | 覆盖 | 验收 |
| --- | --- | --- |
| AC-001 | RQ-001 | 新库和 v13 副本的公会状态初始为空，后者的账号、角色和金币数据保持原值。迁移步骤可离线执行 |
| AC-002 | RQ-002 | 真实 SQLite 中创建后才出现公会与会长，重复或重名不能重复扣费。余额不足、无创建费配置和插入中途异常不留下部分写入 |
| AC-003 | RQ-003 | 申请可按会与角色查回。错误审批人、错误目标和重复批准无法建立额外成员关系。正确批准后申请清除，按角色和公会查询得到一致结果 |
| AC-004 | RQ-004 | 普通成员能离会；越权移除失败；会长可移除其他成员。解散清理成员及待申请。成员删角被拒绝，可删除的申请者不会遗留待申请 |

证据来自本分支的 SQLite、应用工作单元、迁移与角色删除回归。数据库拒绝的事务路径以提交后的金币和关系状态为准。现有 A21 静态资料和参考实现只提供后续协议编排的定位。
