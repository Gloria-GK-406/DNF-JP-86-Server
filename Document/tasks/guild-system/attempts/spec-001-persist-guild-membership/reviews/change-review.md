# 公会基础实现审查

审查最终提交 `4988cb016f73318083bef2c963c9ba0b969f2967`，产品变更范围为 `6f1c94176..4988cb016`。依据同阶段任务契约第 2 版、实施规格、仓库架构与事务规则。范围包括公会领域、SQLite 持久化和迁移、角色软删及相关验证，A21 协议接线在后续阶段验收。

## 已关闭的阻断项

- 初始提交 `29069dcae` 缺少规格 AC-003 要求的公会维度申请查询。修复后的 `ReadApplicationsAsync` 在同一查询中从调用角色的会长关系确定公会，复用申请模型映射。回归断言覆盖会长获取本会完整申请、他会和普通会员查不到以及批准后原申请消失。实现者定向运行 `GuildDomainTests` 和 `SchemaOwnershipTests`，9 项通过。本轮复查了实际代码和测试断言。

## 已检查的边界

- 创会复用角色金币域与 SQLite 写事务，故障回滚测试覆盖扣款成功、插入会长失败的路径。角色唯一会员与公会单会长约束由 SQLite 索引承担。
- 移除成员验证会长和目标所属公会。角色软删在原命令工作单元内回滚现有会员的删除，并清理可删除角色的申请。
