# 任务契约 · JP86 完整公会系统

## 背景

用户先要求设计公会的领域服务和类，以及它们如何协作完成全部公会功能，随后要求「好，你来写一个任务契约然后实现它吧」。在范围选择中，用户明确选择「完整公会系统分期实现」。本契约覆盖完整结果，各阶段分别交付和验收。

2026-11-26 核对 GitHub `refs/heads/main` 为 `cada01a0ec33ad9e3ec34fcad1ce2ca475244fd4`。该基线已有选角、角色详情、聊天、物品移动和邮件，公会聊天人群仍为空，公会数据缺少核心成员关系。已有本地证据分支 `task/collect-guild-implementation-evidence@686dfab70`、ServerS4A21 源码与上游 A21 记录，以及开发 PVF `content:0.3.3-dev.1`。这些资料提供字段、规则与验收入口，来源和效力分别记录。

## 目标

把公会做成能在 JP86 项目 A21 客户端持续使用的系统。玩家能创建、加入、管理和退出公会，也能使用已明确属于本项目 A21 内容的公会社交、成长、设施、资产和战斗玩法。角色切换、重登、并发、重复提交以及跨周期后的客户端显示和持久状态保持一致。每期形成独立可验证的成果，并复用已交付的公会身份和权限能力。

## 范围

### 纳入

- 基础身份、创建、搜索、推荐、申请与审批、名册、角色详情、在线投影和换角／重登恢复。
- 职务管理、会长转让、权限、公告、宣传、个人备注、改名、会徽／旗帜、退会、踢人、解散及角色删除关联状态。
- 公会聊天、邀请、联盟、公告板、推荐频道与客户端已有的频道入口。
- 升级、捐献、贡献、里程、签到、商品、属性／经验／契约收益。配置与收益范围按对应 A21 证据和部署 PVF 核实。
- 公会据点、仓库与仓库历史、勋章与守护珠、公会礼物／红包、公会支援角色。
- 公会地下城、公会战，以及对应的入场、进度、结算、奖励和周期处理。
- 对以上功能进行 JP86 落地、数据兼容、自动化验证、A21 实机取证与验收准备。协议结论进入所属协议页和目录。已查明入口、失败分支和证据缺口可以单独记录，但缺口不能记为通过。

### 不纳入

- 其他版本、第三方专属菜单或补丁、仅名称相似的非公会玩法。
- 推送、创建 PR、合并、发布和线上变更，以及未协调的玩家库或运行服务切换。

## 约束

- 沿用 JP86 现有的玩法执行、事务、领域分层、会话、物品和通知边界。角色成员关系、在线会话和资产各使用自身权威状态。代码分期集成到独立功能工作区。
- 每个阶段分别标出上游参考、静态分析、真实收发帧和 JP86 实机行为。客户端线格式或玩法规则尚无法闭合时，明确记录所缺证据。只有实际证实当前支持配置无该玩法入口、或用户有明确裁决，才调整对应验收范围；更改同步到本契约。
- 自动验证使用隔离库和不冲突的端口，协议或正式 E2E 用例的参考行为、帧序与数据变化来自真实采集。涉及用户验收的真实数据库先核实路径、验证一致备份与迁移并协调单写入者。阶段实现与本地隔离验收可以持续推进。
