# A21 公会地下城

## 客户端验收

1. 用验收服的 `1123` 进入 CH10。角色从赛丽亚房间出发，经公会基地入口进入大厅。
2. 从大厅右侧进入「绝望冰崖」选图区域，选择「伤城」。当前 PVF 要求角色至少 50 级，使用指定难度 2，入场一次扣除 8 点疲劳。
3. 沿房间门清怪推进，击败领主并完成结算。伤城的净化率增加 50/10,000。2026-11-26 用户在 A21 界面确认从 0 升至 0.5%。
4. 回城打开邮箱。零进度开始的首场奖励为「公会贡献证书」3 张，公会可用 GM 增加 20。奖励邮件保留 30 天。分两次领取通关证书，核对背包里的证书合堆。

## 规则来源与实现

- 开发 PVF 的 `town/guildagit.twn` 将基地 Area 1 配置为地下城入口 37，`map/guildagit/guildagit_s.map` 定义大厅右侧的通路。`worldmap/guilddungeon.wdm` 定义选图区域。`etc/guild/guilddungeon/guilddungeonstyle.lst` 的样式 0 配置六张地下城，编号为 8500、8503、8504、8505、8507、8508。
- `GuildDungeonDomainService` 校验当前公会和大厅入口。组队参加者须属于同一个公会。最低等级、指定难度、疲劳、房间与领主使用地下城配置和既有规则。征服阈值和奖励档位由公会地下城 PVF 读取。
- 每个角色成功结算时，`SqliteGuildDungeonStore` 在同一事务写入一次通关、更新公会当期进度与 GM、发放奖励邮件。结算后推送公会成员共享进度。周期边界采用参照服规则，为北京时间每月 1 日 06:00。

## 净化率解锁

A21 伤城提示中的 50% 是本公会在伤城的净化率，用来开启后续地下城。伤城是起始地图，零进度即可进入。[日服官方更新公告](https://arad.nexon.co.jp/news/update_view.aspx?no=7191) 确认逐阶段开放和终点需要其他地图累积净化率。

| 要进的地图 | 当期前置地图 |
| --- | --- |
| 伤城（8500） | 无 |
| 呐喊之地（8504）、破灭峡谷（8507） | 伤城达到 50% |
| 失心迷宫（8505） | 呐喊之地达到 50% |
| 哀泣之穴（8503） | 破灭峡谷达到 50% |
| 永恒殿堂（8508） | 失心迷宫和哀泣之穴均达到 50% |

**ContentStatic**。上游 A21 PVF（SHA-256 `8FA275A3…`）的样式 0 声明上述五组 `[required dungeon conquest]`。开发和原验收 PVF（`A97132DD…`）缺失五组。移除上游这五组后，其余 210 个样式令牌完全一致。使用 `Tool/PvfGuildDungeonPrerequisitePatch` 从上游恢复这一个 PVF 条目，复用客户端和服务端现有的前置配置读取。修复版 SHA-256 为 `EAD42DBD4739111805903BD94573B50B2EE2262A094DC542EA6A593EFF70F4E4`。

服务端按 `[conquest gauge ratio]` 和上游校验使用达到门槛的判定，伤城 100 次（50.0%）满足配置。A21 界面将这个门槛描述为「超过50%」。同周期内，两个末端分支都达标自然要求其各自前置达标。

隔离服用旧 PVF 复现伤城净化率 0.5% 时可进入呐喊之地，再换修复 PVF，确认五张后续地图均返回 `0x13` 入场拒绝。伤城零进度可入，49.5% 拒绝呐喊之地，50.0% 开启呐喊之地和破灭峡谷。两条分支独立开启，末端仅一个达标时永恒殿堂仍拒绝，两个都达标时可入。证据日志为 `guild-conquest-smoke-1795703150706616600.stdout` 和 `guild-conquest-smoke-1795703159495488300.stdout`。

## 验证记录

隔离 SQLite 副本从 v24 升至 v25。使用开发 PVF 和已入会的 `1123` 完成了伤城的入口、选图、加载、房间通行、领主击杀与结果结算。两名同公会角色都收到进度从 0 变为 1 次的 [0x02E5](../../../protocol/game/server-to-client/NOTI-0x02E5.md)，重登恢复进度。数据库核对到一笔个人结算、一封含 3 张证书的奖励邮件及 20 GM，重发结算请求没有第二笔发放。

线路测试记录为 `guild-dungeon-smoke-1795702364214622300.stdout`。

2026-11-26，用户在 A21 验收服用 `1123` 确认低净化率时只能进伤城。将验收副本的伤城设为 49.5% 后，用户再通关一次并确认解锁符合预期。核对 `guild-conquest-user-20261126-222737.stdout` 和验收库，记录了这次伤城的结算，伤城次数为 100（50.0%），该次结算记入 20 GM 并生成含 3 张证书的邮件。用户验收覆盖伤城入场、通关、0.5% 增量和首层解锁。邮件附件领取、后续地图的完整实战、多人同步显示和周期切换留待正式部署后的反馈。

正式部署使用含已恢复前置规则的配对 PVF，数据库通过迁移工具升级到当前版本。

## 反复通关礼盒

进度按角色累计，跨公会地下城、重登和服务器重启保留。每名结算角色按通关时的副本人数获得进度，单人、双人、三人、四人分别加 5、10、15、20 个百分点。通关队员的最高和最低入场等级相差至少 10 级时翻倍。日服公告确认人数和等级差规则，具体倍率采用同期韩服玩家资料。A21 PVF 样式 0 定义 10 级阈值和礼盒 `10156320 ×1`。[日服公告](https://arad.nexon.co.jp/news/update_view.aspx?no=7398) · [同期韩服规则记录](https://tcatmon.com/wiki/%EA%B8%B8%EB%93%9C_%EB%8D%98%EC%A0%84)

达到或超过 100% 的这一次通关发一个礼盒到系统邮件，个人进度清零。清零、发盒和通关去重在同一事务。选图及结算后以个人 [0x02E6](../../../protocol/game/server-to-client/NOTI-0x02E6.md) 同步 HUD。旧数据库升级至 v35 后，既有净化、通关贡献和奖励记录保留，礼盒进度从零开始。

隔离服线路已复核伤城单人 0% → 5%，同级双人 0% → 10% 和 90% → 0%，以及两人相差 10 级时 0% → 20% 和 85% → 0%。达到门槛的角色收到恰好一个礼盒，重复上报不追加，重选角色后进度恢复。58 项迁移测试通过。

验收服 `52680` 预置 `1123` 为 0%、`GuildPilot` 为 90%。`GuildPilot` 调到 86 级以满足伤城入场并便于测试同级双人规则，两名测试角色的疲劳已恢复。先让 `1123` 单刷一次核对 5%，再同 `GuildPilot` 组队通关，核对 `1123` 到 15%、`GuildPilot` 清零且邮箱收到一个礼盒。

2026-11-27 用户确认 A21 礼盒链路符合预期。验收库记录 `1123` 进度 15%、`GuildPilot` 进度 0%，后者恰好收到并领取一件礼盒。客户端提交了开盒，服务端随后记录了开出的道具移入背包。

## 单刷回基地后组队邀请

**实机观察。** `1123` 单刷伤城返回公会区域后，22:18 两次邀请均通过服务端的同区域检查，均未到达接受请求。两人在银色村庄集合后成功组队，完成伤城并解散队伍后，22:24 在公会区域再次组队也成功。

**ClientStatic / WireTest。** A21 接受邀请前会检查本地保存的邀请者状态，检查失败会显示「对方不在城镇内」并提前返回。隔离双端复现中，`1123` 用 `0x0048 01 02` 结束伤城后，自己收到 `0x0003` 状态 0，同区等候的 `GuildPilot` 却收到 `0x0002` subtype 0 状态 1。让 `1123` 走回基地大厅再进选图区域，等候端收到状态 0。验证期间未组队。服务端日志为 `guild-return-peer-state-1795789841685531300.stdout`。[接受邀请预检](../../../protocol/game/client-to-server/0x000B.md)

**修复与验证。** `EplpOrdinaryAsync` 在结束副本之前读取角色当前视图，其中公开身份为状态 1。回城同步现在以已完成的城镇入场为准，为旁观者生成状态 0 的资料。89 项城镇、退图和组队相关测试通过。隔离线路 `guild-town-return-fix-smoke-1795790185616696500` 验证回城者和等候者都收到状态 0，等候者在原地收到邀请并成功接受。修正版部署在 `52680`，礼盒进度与既有记录保留。

**ClientVerified。** 2026-11-27 用户确认单刷回公会区域后原地组队符合预期。验收服日志记录 `1123` 单刷伤城、结算回城、发送邀请，随后 `GuildPilot` 接受成功。
