# 装备实例及规则边界规格
## Why and Outcome
装备提供实际状态操作，规则判断与资源结算清楚可读；以现有五项养成为兼容基线。
## Scope
遵循[TaskContract](TaskContract.md)范围；没有新增增幅玩法、没有新协议取证。
## Requirements
| ID | Requirement |
|---|---|
| RQ-001 | 装备实例按拥有者和物品身份定位最新装备，修改强化/附魔/锻造/异次元/封印/耐久及销毁，不能使用过期或外来身份 |
| RQ-002 | 实例仅执行基本状态转换及本地约束，不持有概率/费用/PVF；相关规则服务只接收facts，返回不可变决定 |
| RQ-003 | 全部在范围内养成、修理、耐久及分解适配实际实例写入，不留平行core写入路径 |
| RQ-004 | 保留原规则与拒绝语义，材料/金币/保护券/装备/产物共同提交或回滚，通知基于提交结果 |
| RQ-005 | 不改变wire布局与物品身份，登录/重登兼容，典型代码示例、部署和验收证据齐全 |
| RQ-006 | 最终由用户确认接口分工与重构版R-01强化、R-02重登。其他养成GUI留在原清单，不借结构回归标ClientVerified |
## Acceptance Criteria
| ID | Covers | Criterion |
|---|---|---|
| AC-001 | RQ-001 | 同事务两次改不同字段皆保留；换槽/同模板不同UID不误写；越权、销毁后及已提交/回滚实例拒绝；回滚原状态 |
| AC-002 | RQ-002 | 规则接收只读facts，能固定随机值验证结果且不读角色/库存；实例代码没有费用、概率、内容源 |
| AC-003 | RQ-003 | 当前调用链的状态修改统一实例，旧临时EquipmentInstance与其Repair公式已关闭或改归规则 |
| AC-004 | RQ-004 | 原养成/保护/破坏/材料/金币不足/回滚/重放/修理/耐久/分解行为测试通过；损坏=耐久变化，销毁=移除物品 |
| AC-005 | RQ-005 | Release构建、真实PVF和生产DI副本登录/库存编码通过；协议layout不变；备份后部署ready，给出当前样本和验收顺序 |
| AC-006 | RQ-006 | 用户明确认可实例及规则例子，R-01/R-02通过并由日志及只读数据核对。之前版本结果不冒充本轮 |
## Success Evidence
自动证据和结构复核证明AC-001至005；Human-Test-List及用户当前版本反馈证明AC-006。在最终用户反馈前状态为待验，不声明任务完成。
