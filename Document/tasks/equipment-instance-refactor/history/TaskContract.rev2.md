# TaskContract: 装备实例、养成规则与强化保护券

## Context
### Source Request
用户提出：规则服务尝试强化并返回结果；装备instance只负责加减/设置强化、增幅、异次元、魔法封印等状态，不承载强化和增幅规则。接受的方案为规则读取只读facts并返回决定，领域服务扣资源与应用决定，装备实例维护状态一致性。
授权原文：“可以，就按这个方案来完成吧。可能量比较大，走一个任务契约吧，需要明确做最后验收。”

后续授权：“给角色加强1000万金币和5万无色吧。以及增幅什么后续所需的材料。对了保护券也带一下，然后顺带着把保护券功能也做了吧。保护券功能走任务契约”。本revision将普通强化的普通/超级保护券闭环及验收补入当前未结束的装备任务；原结构与强化/重登最后门继续保留。
### Current Situation
基线6e60c4c6；已接受宠物普通范围和宠物实例重构。装备强化等五项实现尚待实机验收；当前EquipmentInstance仅为修理/耐久临时快照，还含修理价格计算。强化与附魔直接读取内容源并写回core，其他养成虽有规则服务但仍直接写回core。

## Goal
提供可理解、按装备身份操作的装备实例；养成规则判断与状态修改分别有唯一责任，使现有装备功能保持结算、持久化和协议行为，并提供可执行的最终验收。

角色取得请求的验收资金与后续养成材料；普通强化失败时适用保护券正确保住装备、按券规则调整等级，只有保护实际生效才消耗，客户端即时与重登状态一致。

## Scope
### In
- 装备实例基本状态操作：强化等级、增幅/异次元属性、附魔、魔法封印、锻造等级、耐久及销毁。
- 现有普通强化、附魔、异次元、魔法封印、锻造业务迁移；修理/耐久使用同一状态修改边界，既有分解调用适配。
- 强化/附魔/修理所需规则服务，复用并整理既有规则服务，使规则不查询或修改运行中的角色/装备。
- 保持装备身份、相关资产全有或全无、重登数据和现有请求/响应行为；测试、文档、独立结果复核、备份后部署和最后用户验收。
- 普通强化保护券及超级强化保护券的识别、资格、自动选券、结算、通知、重放及持久化闭环；不重复实现已有正确分支。
- 对角色2增加1000万金币、账号4增加5万无色，准备后续养成材料及保护券。发放与装备操作分开留证，保持原装备及其他资产。
### Out
- 新增尚未实现的增幅玩法、改变现有养成公式/概率/错误码或扩展未证协议。
- 增幅保护券预先发放，不用普通强化处理增幅券；增幅升级和增幅保护闭环继续后续增幅任务。
- 宠物特殊成长/技能；其他装备功能的新玩法；PR/推送/合并/分支删除。

## Constraints
- 用户已接受的分工：装备实例不承载养成概率、费用或处罚规则；规则服务接收只读facts并返回决定；领域服务负责资源与事务编排。
- 遵守Application引用方向、规则服务拥有静态规则输入、命令处理器只注入领域服务等仓库架构要求。
- 保留实际数据库及物品身份，不用造生产样本或修改资产掩盖回归；协议证据等级保持边界。
- 本revision明确授权的资金/材料发放以及此前已授权的UID689修复是有记录的资产操作；不能以此伪装新强化/保护验收成功。
- 常规功能自动验证不能替代用户最终实机验收，未验项须如实留存。
