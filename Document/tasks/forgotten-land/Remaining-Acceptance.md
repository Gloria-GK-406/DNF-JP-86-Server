# 遗忘之地剩余机制验收清单

已通过：入图与换房、热血总体表现、瞬移胶囊、变身药水、到期原生总结及回城，以及A组钥匙／银箱／跨房／重复领取检查／奖励重登保持（用户反馈“全部OK”）。当前每局20分钟；本服击杀产出专项已获用户“测试没问题，通过了”的总体反馈，已测主玩法通过，未覆盖项仍保留。
本清单按“先基础、再依赖机制、最后中断和次数”排列；已通过项仅在相关链路中顺带回看。

## 使用方法

- 每次只测一组。发现关键失败，反馈该编号后暂停依赖它的后续项；独立项可留到下一局。
- 每项记录“通过／异常／未遇到／前置不足”。未遇到对象、没拿到道具、等级或次数不足，不记为通过或确定故障。
- 使用有次数的25级以上单人角色。特殊领主建议用能正常击杀对应怪物的角色，避免把难度当成协议问题。
- 每局记角色、入图时间、初始次数，以及选定一两种掉落材料的入图前数量。反馈对象位置可用小地图格子、房间特点或区域名。
- 钥匙优先看专用界面计数，不预设它一定是背包物品。界面／动画正确后，还要结合服务端日志及重登后的资产核对。
- 时限为20分钟；不限次已关闭，当前按真实入场额度扣次，见[配置](AcceptanceOverrides.md)。F组保留实机验证边界。

## 顺序总览

| 顺序 | 建议安排 | 内容 | 进入下一组的条件 |
|---|---|---|---|
| A | 第1局 | 钥匙→银箱→拾取→跨房→完整20分钟结束→重登库存 | 基础开箱链正常 |
| B | 第2局 | 昼夜→追击者生成／遭遇／跨房，遇到相关道具再核对 | 已记录夜间与追击表现 |
| C | 后续各局，每局一个区域目标 | 人鱼／特殊门／区域领主／密室 | 前置与各区域分别走通 |
| D | 区域测试后 | 多区域解锁、最终区域及总结账目 | 同局解锁前置实际满足 |
| E | 最后，分局做 | 手动退出、死亡／复活、关闭客户端重登 | 每项有一次独立入场机会 |
| F | 正常游玩时顺带 | 100疲劳加次、次数持久化、游戏日刷新 | 具备自然观察条件 |

以下“预期”是核对目标；带“探查”的项仍缺专用服务端闭环证据，不能据PVF或画面先判完成。

## A：钥匙、银箱与持久奖励（用户已确认全部通过）

- [x] **A1 无钥匙开箱**：入图记录钥匙数，若为0，找到一个银质宝箱，按客户端正常开箱方式操作一次。预期提示需要钥匙，箱子不应成功出奖励。若入场已有钥匙，这项先记“前置不足”，不要刻意丢物品。
- [x] **A2 获得钥匙**：击杀稀有／精英怪或完成遇到的区域事件，观察钥匙掉落或计数变化。拾取一次，记录计数前后；目标是一次获取对应增加1。短时间没掉钥匙，记“未遇到”，不要因此判断掉落必坏。
- [x] **A3 跨房保留**：获得钥匙后先走到相邻房间再返回。预期钥匙计数保持，换房不重复增加或清零。
- [x] **A4 有钥匙开银箱**：操作一个未开启的银箱。记录开箱按键／攻击方式、钥匙前后数、箱子是否打开、地面掉落及提示。目标是成功开箱消耗1把钥匙，并且只产生一份奖励。
- [x] **A5 防止重复领取**：拾取一件箱子奖励，记名称和数量；再次操作已开启的箱子，再换房返回看一次。预期同一箱子不能再提供一份相同奖励，也不应重复扣钥匙。其他独立箱子不算重复。
- [x] **A6 完整10分钟与重登**：正常探索至倒计时结束，记录是否自动总结回城；回城核对所选材料“原数量＋实际拾取－实际消耗”。重新登录再看数量，预期与回城时一致。总结展示只是统计，不能再额外重复发一份。

**反馈 A**：入图时间／区域／开箱方式／钥匙0时表现／获取及跨房计数／开箱前后计数／奖励名称数量／重复操作结果／回城及重登库存。

A组不要求重复测试。用户总体反馈证明本轮客户端与库存行为通过，不扩展为构造伪造请求或所有箱型的安全验证。

## B：昼夜与追击者（用户已确认B1–B6总体正常）

- [x] **B1 昼夜切换**：在普通探索区域记录白天／夜晚界面。观察一次切换，记录大致倒计时和提示，不预设所有房间都会刷同一批怪。
- [x] **B2 生成与遭遇**：进入夜晚后，在已探索区域留意“追击猎手已出动”警告、小地图图标和实际怪物。夜间观察约1分钟仍未看到，记录区域、提示和图标即可；不要把整局都耗在原地等待。
- [x] **B3 跨房状态**：若遇到追击者，记录位置，走一个可通行房间再返回。检查操作和统计是否继续、是否出现明显复制或反复刷出。先记录其真实追踪范围，不要求它必须跟进任意房间。
- [x] **B4 伤害与击杀**：能安全正常交战时测试伤害、击杀和掉落，记录击杀前后统计、奖励。无法击杀则记难度／无敌等表现，不自动判为服务端故障。击杀后换房返回，核对同一个体不会再次提供同一份击杀奖励。
- [x] **B5 相关药剂**：监视者的威严（10093473）与免罪符（10093341）已获用户总体反馈“两者没问题”，日志及库存也确认各扣1。未单列的数值、晶石成本与冷却精确计量不扩大为通过；`[need material]`自身不证明每次使用都额外扣晶石。
- [x] **B6 修理券**：用户总体反馈“修理券测试没问题”，日志有两次成功操作。未单列的快捷栏、最后一张券及拒绝细项不扩大实机结论，见[修理券验收](RepairCoupon.md)。

B1–B4依据用户总体反馈“这部分也测试过了，功能正常”记为通过，未补造逐项打线或数值证据。B5、B6按随后实机总体反馈记为通过。[两局结果对账](ResultDiagnosis.md)确认结束列表包含未拾取掉落、已领取资产正常入库；保持现行行为继续C组，不扩大为最终领主或完整结算已验收。

**反馈 B**：昼夜／区域／警告和图标／是否实际出现／跨房变化／交战或击杀结果／相关药剂名称和效果。

## D：最终区域与完整账目（前置满足后再做，探查）

- [ ] **D1 解锁条件**：先记录最终入口锁定／解锁提示。只有本局已实际满足提示条件（例如各区域领主）才尝试最终入口，不把分多局击杀自动当作同局已满足。
- [x] **D2 最终战斗（用户总体反馈）**：已确认能进塔及交战；本服击杀产出专项获总体通过。未独立记录全部塔变体、随机装备出现或塔奖励精确数量，不补造逐项对账。
- [ ] **D3 账目核对**：比较入图前、最终战斗后、总结回城后和重登后的一两种代表性材料数量。区分已经拾取的材料、开箱所得和实际使用消耗；未识别的额外奖励先记名称来源，不猜固定收益。
- [ ] **D4 任务推进（已有任务时）**：记录相关任务在进图前后的进度。当前本服已采用20分钟，相关任务的真实推进与完成仍需单独核对，不以时限配置代替任务验收。

## E：中断与清理（分开入场，放到最后）

- [ ] **E1 手动返回**：在未到期时，拾取一件可记录物品，再手动返回城镇。核对退出完整、无遗忘之地放弃虚弱、拾取物品保留、没有重复扣入场次数；若仍有额度，选图应可正常再次操作。
- [ ] **E2 死亡／复活**：单独一局测试死亡界面、复活币前后数量、复活后是否可操作，以及倒计时是否继续而非重置。若不复活，记录退出方式与物品保留。当前没有宣称官方死亡是否额外扣时间，发现变化先记录。
- [ ] **E3 关闭客户端后重登**：单独一局在拾取物品后关闭客户端，再重新登录。记录回到城镇还是副本、次数和库存。硬性核对为角色不被卡住、已提交资产不丢失、不重复给奖／扣次；是否应续跑原局仍待定，先观察，不预设必须恢复。

## F：次数和其他时间机制（顺带验证）

- [ ] **F1 正常扣次与耗尽**：有额度时进入一次，结束后看剩余，再重登核对。无额度时应拒绝入场，且库存、疲劳和已有额度不发生额外消耗。
- [ ] **F2 每消耗100疲劳加次**：仅在正常刷图累计跨过100时，记录跨越前后的遗忘之地次数。不能只看剩余疲劳推断累计消耗；无需专为验收额外刷100疲劳。
- [ ] **F3 自然游戏日刷新**：下次正常登录时记录次数。本服实现按06:00游戏日计算；无需等待或熬夜跨点。用户反馈与服务端计数一起核对，不能仅凭旧1/1画面判周期正确。
- [ ] **F4 延时机制（条件项）**：目前没有确认具体延时道具名称／效果，也没有证明PVF第二参数1200就是可延长上限。若实际拿到会增加探索时间的物品／机关，先报告准确名称和说明，再安排使用；本轮不要求寻找一个尚未确认存在的道具。
