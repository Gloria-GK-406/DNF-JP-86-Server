# 实施记录

新增大会内容源、规则服务和 `ITournamentDungeonDomainService`。大会服务持有赛程、轮次、复活与领取状态，统一 DungeonRun 持有房间实体；入场沿用门禁和成本凭证。客户端一次收到四轮对阵，服务端只允许当前轮合法击杀，最后一轮才结算，避免普通通关流程提前触发。

0183/0184/0185 与 CMD01CA/01CB 分别处理抽签、地图、结果和选牌。材料奖励走统一被动派发，满包邮寄；金币及领取标记在同一事务内提交。首次有效选牌状态请求启动3秒自动补选，重复请求不延长时间或重复发奖。复用原有10秒复活窗口，超时按完成轮数淘汰结算，离开按run身份清理。

## 取舍

NPC胜负按PVF strength加权，均匀抽签；未复刻上游首轮优先最弱对手。疲劳每轮扣2，后续轮扣至0但不终止已入场比赛。运行态不跨服务重启恢复。未修改客户端或PVF。

## 验证边界

真实PVF内容、领域回滚、越轮/重复请求、满包邮件与协议固定字节已有自动化覆盖。原生客户端四轮动画、参赛者出现、失败界面和领奖回城仍需用户实机验收。
