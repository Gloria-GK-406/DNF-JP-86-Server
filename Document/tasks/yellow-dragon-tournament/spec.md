# 黄龙大会完整比赛循环

## Why and Outcome

玩家以资格材料进入黄龙大会，在同一个竞技场连续赢得四轮后领取大会专属奖励，并正常回城。服务端维护真实赛程与实体，客户端用原生大会协议展示。

## Scope

一期只开放黄龙大会 DGN120。青龙、黑龙和祭坛保留后续边界；公共抽签、协议模型可以复用，不代表其他大会已实现。

## Requirements

| ID | Requirement |
|---|---|
| RQ-001 | 从当前 PVF 读取黄龙定义、候选参赛者和奖励表；依据上游/客户端证据实现字段与时序，明确近似规则 |
| RQ-002 | 专门大会领域服务管理入场、冻结赛程和实体、轮次、终止结果、奖励领取；复用统一门禁成本与 DungeonRun，不复制一套普通入场 |
| RQ-003 | 单人、等级69及合法模式，资格4726×1扣一次；固定难度2；每开始一轮按PVF扣疲劳2，不叠加普通首房疲劳 |
| RQ-004 | 一次发送0183四轮对阵/对手、0184竞技场；加载完成后战斗；只接受当前轮合法且未死亡的actor；四轮完成才结算 |
| RQ-005 | 0185与01CA/01CB支持完成轮数经验、每行选一张奖励；重复/越轮/过早请求不能重复发奖，缺位置走被动奖励邮寄 |
| RQ-006 | 死亡允许原有10秒复活窗口，窗口结束后按已赢轮数失败结算；放弃与离开正常清理，重进生成新赛程 |
| RQ-007 | 保持普通地下城/深渊/塔原有路径；构建、回归和独立审查通过后保留数据库与旧包部署 |

## Acceptance Criteria

| ID | Covers | Criterion |
|---|---|---|
| AC-001 | RQ-001 | 真实PVF解析出15名候选、MAP17100、五档经验和六档卡片规则；协议测试闭合260字节0183、15字节最小0184及动态0185/ACK |
| AC-002 | RQ-002,RQ-003 | 合法入场提供一个已登记的大会DungeonRun及四个actor；缺票、多人、低等级、深渊/练习模式拒绝，失败不扣费；首轮只扣2疲劳 |
| AC-003 | RQ-004 | 未加载/越轮死亡被拒绝；顺序四次死亡分别推进1..4，重放不推进；前三轮没有普通通关或0185，第四轮才生成奖励 |
| AC-004 | RQ-005 | 冠军上下两行各两卡，每行最多领取一次；失败只上行；过早/非法/重复选牌无额外库存/金币/经验；背包满时奖励邮件可达 |
| AC-005 | RQ-006 | 复活窗口内可继续，过期失败进入大会奖励UI；结束后不能复活/再记杀；退出后无残留大会状态 |
| AC-006 | RQ-007 | 架构规则与相关地下城回归通过；新包源码/程序集/端口/HTTP就绪可验证，旧运行输入和数据库快照保留 |

## Evidence and Limits

静态布局：客户端0183 RVA D56690、0184 D5AB20、0185 D49030、01CA D04F70、01CB D04FB0。上游 `TournamentDungeonRuntime` / `TournamentPacketBuilder` 证明一次加载、当前轮门控和每行一次领取。均不是实机验收。

NPC胜负采用按PVF strength比例抽签，均匀洗牌，不继承上游首轮刻意最弱策略；这是本项目规则选择。疲劳每轮扣至0，后续轮不额外拒绝，避免已收费比赛半途终止；起始仍需有疲劳。奖励金币复用普通卡片基础金额乘PVF倍率。运行中的比赛与去重仅在本进程有效，重启不恢复未完成局。

用户部署后验收：四轮动画、对手出现、失败结算、领奖回城与真实物品结果；这些保留为 ClientVerified 待办，不用单元测试代替。
