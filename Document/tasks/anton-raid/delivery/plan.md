# 安图恩完整开发执行计划

以下动作共享一套运行态和最终客户端验收，按依赖顺序执行。使用现有唯一玩法执行器和正常协议分发，分段跑自动测试。

### T-001 实际编组与共同归属（RQ-001、RQ-003）

给 `PartyService` 增加有实例凭据的独占小队操作，继续通过同一 `FindByKey`、`KeyOf` 查询。维持空小队 key、机械成员唯一性、普通写入口拦截与普通目录过滤。协议投影使用 `PartyClientIdRegistry`。先验证同一角色只能属于一队、清空后 key 仍可再次使用、普通退出不能清除借出队伍。

### T-002 准备、门票、入口与进图（RQ-001、RQ-002）

扩展 `AntonRaidDomainService` 的单一团实例，冻结编组、会话、准备代次与时间。接 `0x029B`、门票状态 `0x0293`、`0x0253` 及普通组队准备分流。复用 `DungeonEntryMaterialsDomainService` 的全员材料计划，在同一写单元内扣票与发布阶段转换。复用 `DungeonDeadlineSource`。在 `0x000F` 选图前查验实际小队，可信进图身份随现有入口意图传至 `0x0010`，在路由最前接专属 mode 并守住普通副本回退。对失败、重复、超时、总人数和准备名单变化做回归。

### T-003 阶段内容、出战回报和回收（RQ-002、RQ-003）

由 PVF 内容源读取阶段、地图、符号、触发器和倒计时规则。以 `DungeonRunMode` 保存一次出战归属，用现有清场钩子和离场结果更新团实例。按实例／阶段／代次应用回报，维护图状态、同步机制及期限，按设计推进失败、重入和清理。验证多图出战、通关与复位、超时、断线重入。

### T-004 两阶段翻牌、任务与奖励（RQ-004）

在阶段成功边界冻结实际通关资格与翻牌状态，按 PVF 奖池抽取。接过场、选牌、自动翻牌、阶段任务和终结投影。逐人结算复用物品发放、邮件和已有存储事务，同一实例的领取重试与落账去重；失败的重试材料按设计投递。验证在线、离线和重复支付。

### T-005 隔离整体验证（RQ-005）

检查协议注册和证据文档。构建 Host，运行受影响项目的回归并记录基线差异。编写集中 A21 验收顺序，包含已延后的拒绝申请、第 7–10 队、进图、两阶段成功和失败、翻牌和重入。开发过程不切换现行服务或玩家库。
