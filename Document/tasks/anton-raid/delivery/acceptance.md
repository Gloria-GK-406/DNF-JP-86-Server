# A21 安图恩攻坚集中验收

本文件记录本轮实现合流后的验收顺序。实际结果在操作和取证后登记。

## 环境

- 使用本轮隔离服务端、独立角色数据库和由 ClientStore 生成的 A21 测试客户端。记录构建、PVF、频道号、角色和日志路径。
- 一阶段默认至少 10 人，门票为 10096296，每名未付过票的团员一张。小规模联调可使用与客户端一致的隔离测试 PVF，验收记录注明这项配置。
- 角色 12830 按两阶段分别观察进度。发奖前保留背包、金币和邮件状态，供同一角色前后核对。

## 顺序

| 步骤 | 操作与观察 |
| --- | --- |
| 1. 招募 | 两个会话进入 CH200。在海岚·克拉夫建团，经列表分别试一次申请拒绝、再次申请并同意。把成员放入第 6 组与已有证据对照，再依次验证第 7–10 组。记录组号和此时的实际小队状态。四人联调时逐一同意申请，每次都在已有团员和新团员窗口核对「入场材料」随新名单自动刷新。最后加入的持票角色也应立即显示「准备」。 |
| 2. 准备 | 在鹰眼杰克特处发起攻坚。先以缺票或不足人数观察拒绝，再让满足条件的团开启准备，观察倒计时、实际小队和队长。确认成功后逐角色核对门票，失败后核对原状态与门票。 |
| 3. 阻截 | 由队长进入地图选择，进 210 记录读图、清图和退图，核对全团战况。验证不能进入关闭的图，并观察黑雾与战况计时。继续达成 213 和 215 各两次通关。 |
| 4. 阶段一翻牌 | 记录结算过场，确认后选择卡位。用另一个角色等自动翻牌，核对牌位、背包、金币、邮件和任务。记录间歇倒计时及二阶段可开打条件。 |
| 5. 灭杀 | 开始第二阶段，核对已付成员的门票与间歇新增成员的扣票。观察 218、孵化场、屏障和 220，完成灭杀后核对第二次结算与退回城镇。 |
| 6. 重入与失败 | 在另一次攻坚中让普通成员或团长断线，在保留期内换会话重入并核对编组和战况。另跑超时失败，核对重试材料邮件、成员离场、小队释放和旧命令拒绝。 |

需要 A21 取证的具体帧序与字段见[修订设计](../design.md#82-a21-实机取证)。

## 2026-11-22 四人实机复测

- 队长离开两人小队后，剩余成员接任。原队长发出的普通组队请求到达留队者，但接受时服务端重新选回原队长，生成了试图清除留队者状态的入队通知。16:51:18 的 `GameResponsePeerCommand` 因此报错并断开答复会话。修复候选通过定向回归和隔离服四连接验证。原队长重新加入原队，留队者保持队长、队伍客户端 ID 未变，两条连接均保留。
- 在城镇右键留队角色时，客户端菜单显示「邀请入队」。日志确认实际发出 `0x000A` 子类型 0，申请加入和邀请入队使用相同的请求类型。菜单文案留待 A21 复测。
- 16:51:08，未编队团员打开黑雾之源后发出选图请求，服务端因无团本选图上下文拒绝。16:51:29，同一角色留在编号小队时以一人名单进入黑雾并完成读图。上游允许未编队成员各自形成独立的单人战况组，当前 JP86 仅允许编号小队入场。
- 韩服初版攻坚队公告明确允许一人一队。日服 2015 年首发公告描述了编号小队出战流程，未说明完全未编队的成员能否直接进图。日服 2018 年追加独立的单人攻坚模式。 [韩服初版攻坚队公告](https://df.nexon.com/pr/actupdate/MDAwNTk/?cat=4) · [日服首发公告](https://arad.nexon.co.jp/news/update_view.aspx?no=5909) · [日服单人攻坚公告](https://arad.nexon.co.jp/campaign/201802/season6_act1_3_1.aspx)

## 两份参照实现复核

以当前 JP86、ServerS4A21 `1870c85` 和第三方 v3.3 实现对照，采用 A21 实测、实际 PVF 和已裁定设计判断差异。

| 对照项 | 结论与依据 |
| --- | --- |
| 能量阻截战转入孵化中心 | JP86 替换出战时会清零已用和额外发放的复活币。第三方保留两项，ServerS4A21 走普通选图，缺少可类比的同局迁移。仅在局内转场时继承复活币使用量和额外额度。见[推进研究](../research/02-upstream-progression.md#6-对-jp86-设计的影响)。 |
| 掉线重入时的结算 | JP86 只冻结在线的结算通知对象，导致保留期内重入、没有奖励资格的团员能看过场却不能确认。两参照都允许当前团员确认过场，另行校验奖励资格。冻结阶段结束时仍有效的团员，保留严格的到期边界。 |
| 重入与战况查询 | JP86 补发了会触发旧动画的符号。四开 PVF 确认 `121–128` 是过场，第三方的重入快照排除这组符号，两个参照的普通查询也不重播过场。阶段启动和正常进度变化继续发送动画。见[重入设计](../design.md#74-上游帧序与-a21-取证参照)。 |
| 二阶段火山屏障 | 实际 PVF 中厄伽勒死亡销毁大型电池，电池动作发出符号 110 减 3,000。两参照和 JP86 都通过 `0x0297` 接收屏障变化。A21 实机检查上报时机和显示。 |
| 小队设置和单人进图 | 两参照使用固定设置块，其中的 `FF` 占位与 A21 原生组队样本不同。保留 JP86 设置。编号小队单人出战已有实机；完全未编队出战的日服原版规则仍待确认。见[组队样本](../../../../protocol/game/client-to-server/0x000C.md)。 |
| 选图拒绝和金币牌面 | 两参照在拒绝打开选图时发送 `0x000F` 错误回包和提示，目前缺少原生 A21 拒绝帧用于确认表现。金币牌面受 16 位字段限制，两参照用额外公告报实际金额，JP86 的实际发奖独立于牌面值。 |
| 其余重入协议差异 | `0x0255` 原始时长与剩余秒数，以及 `0x0249` 已通关小队的补发步骤仍待 A21 实机，不从两个参照的相同做法推定 A21 必须采用。 |

前三处均在修复前由定向用例复现，修复后使用四开 PVF 跑过 47 项应用、协议、持久化及内容定向测试。候选构建也在独立端口及复制的测试库上通过四连接入团、开团、退出小队、重新组队和前任队长回队。临时服务已停止，A21 原生的孵化转场、结算重入与动画表现待实机确认。

## 合并验收边界

本轮已实测 CH200、招募和编组、开团、黑雾首轮四次通关与一次复活。用户确认 PR 合并前暂停额外开团实测，待线上有人后继续验证完整攻坚。当前待验包括复活黑雾、二阶段孵化和火山屏障、重入后的客户端表现，以及两阶段翻牌。四人开团门槛来自隔离 PVF，开发通道 PVF 仍为十人。
