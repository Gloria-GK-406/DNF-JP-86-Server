# TaskContract — 安图恩攻坚完整链路

## Context

A21 招募实机已确认进 CH200、建团、申请、批准，以及两人编入第 6 队。招募的预定编组与实际出战小队是两个阶段。服务端工作保留在 `feature/anton-raid` 的隔离工作树。

用户确认「ok,那你就先全部完成后我们再开始测试流程」。以一次交付完成剩余开发，开发时做构建与自动验证，接通整条链路后集中做 A21 实机流程。

## Goal

基于修订设计，让 JP86 的团队安图恩从已有招募接到开团准备、实际小队、扣票、进图、阻截、灭杀、翻牌和收尾，并具备用隔离服务开展完整 A21 验收所需的可运行构建与步骤。

## Scope

- 准备期、冻住编组，建立并回收实际小队，入场资格、门票和出战生命周期。
- 两阶段地图、机制、计时、成功／失败与阶段间歇，团员断线及重入。
- 翻牌、奖励、阶段任务、异常退出和收尾。具体规则和留待实机裁定的字段沿用修订设计。
- 保留已验证的招募行为，把第 7–10 队与拒绝申请等剩余实机项并入集中验收。
- 通过构建、自动回归和必要的隔离服务验证；完成开发前无需用户参与实机。

范围外包括跨频道招募、普通或觉醒安图恩、设计明确排除的 PC 房专属奖励、上线、功能 PR 和写入现行玩家库。

## Success Conditions

| ID | 可观察结果 | 本轮所需证据 |
| --- | --- | --- |
| SC-1 | 可开团才进入准备，实际小队与冻结编组一致；门票不足或准备失败保持资产和名单一致，成功只扣一次 | 用例覆盖规模、资格、并发／重复、数据与小队结果；构建通过 |
| SC-2 | 可用小队进入允许的地图，地图开闭、计时与通关驱动两阶段推进；失败与出战退出正确收尾 | 自动回归覆盖两阶段关键路径、受限地图与失败／清理 |
| SC-3 | 有资格者在两阶段可翻牌或自动翻牌，奖励和任务进度能落地且重复请求不重复发放 | 隔离持久化与协议测试，验证授权范围、重复请求和离线发放 |
| SC-4 | 断线保留资格并可重入恢复攻坚视图，失效会话及超时不改变新实例；普通副本和组队保持正常 | 会话生命周期和普通玩法回归 |
| SC-5 | 以上接成一个可启动的开发构建，准备好完整 A21 用例和已有招募待补项 | 检查实际构建、相关自动测试和隔离环境；手动结果在集中联调时采集 |

## Constraints and Authorization

继续遵守唯一玩法执行器、实际小队与普通队伍共用查询、资产操作可重试一致等项目约束。以客户端证据和上游的实际材料驱动协议，保留未实机字段和流程差异。只操作任务工作树、任务分支和隔离服务。用户当前答复授权完成实现及开发验证，正式玩家库或对外集成需要另行授权。
