# TaskContract: 史诗碎片拾取与账号图鉴

## Context

### Source Request

“那么也就是拾取CMD里要做分流是吧。然后加一个史诗图鉴的领域服务。主要是记录史诗碎片数量，然后在查询时候返回。这里史诗碎片是有上限的，到达上限以后再拾取是不应该有变化的。”

执行授权：“OK,那就先按int.max做封顶。写个任务契约开始执行吧”。

### Current Situation

基线 a8a168df，现有 task/abyss-research 工作树。深渊已按 PVF 装备/碎片映射产出碎片，但拾取按普通背包物品处理；登录 EPIC_BOOK_INFO 仍为五个零字节。上游将碎片计数保存在账号，使用 0x0465 同步。现有 0x0465 记录只有空包证据，非空布局需要明确来源。

## Goal

碎片拾取进入账号图鉴而不进入材料背包；图鉴数量持久化、只读可查询，登录和拾取后同步实际数量，且封顶 int.MaxValue。

## Scope

### In

- 史诗图鉴领域服务、PVF 图鉴规则、账号计数持久化。
- 拾取 CMD 分流、成功拾取和图鉴通知、登录图鉴投影。
- 已误入背包的碎片转换为图鉴计数，保存数量并避免重复转换；本轮只修改迁移代码，不操作运行中的数据库。
- 协议证据边界更新和自动验证。

### Out

- 图鉴合成、随机深渊、新的掉落算法及客户端/PVF 补丁。
- 部署、操作线上数据库、推送、PR 与分支清理。

## Constraints

- 每种碎片按账号共享，最大数量为 2147483647；达到上限仍可成功拾取并移除地面掉落，数量不变。
- 查询不得写入；规则从 PVF 获取，不在协议层读取 PVF，不硬编码物品目录。
- 不破坏普通物品/金币拾取、背包容量判断及既有事务中的地面掉落提交语义。
- 保留已有 0x0010 协议及选图调查未提交改动。
