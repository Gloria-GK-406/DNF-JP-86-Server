# TaskContract: 服务概览与账号角色查询

## Context

### Source Request

用户授权独立后台典型GM功能，包括“查看角色列表，在线情况”，并要求按模块MultiSpec实施。根合同纳入全服账号/角色分页筛选、详情、频道/位置和服务概览。

### Current Situation

已接受基线416f26c9提供独立模块、管理员访问/QueryPlayers权限和中文界面。目前对应概览/账号角色页面尚是占位。数据库记录与当前运行态分属各自领域，必须明确来源。

## Goal

管理员能够查看本服务概况，按条件查询全服账号与角色、打开详情，并看到准确的当前在线、频道和位置资料。

## Scope

### In

- 受QueryPlayers权限保护的概览、账号/角色分页查询、详情和中文界面。
- 账号ID/登录名、角色ID/姓名/归属/职业/等级与三种点券余额等必要管理资料；仅查询，不修改。
- 当前登录账号（包括未选角）、已入场角色、实际频道和实时位置；离线角色的持久化位置明确标注为保存位置。
- 搜索/在线筛选、稳定分页、空结果/无效输入/不存在/失权反馈及刷新。
- 真实SQLite/运行态/HTTP验证与前端行为检查，为后续明确选择邮件及点券对象提供查询接缝。

### Out

- 玩家资产修改、邮件和点券发放、管理员管理、远端多服/监控平台、现行服务部署及真实玩家验收。

## Constraints

- 只读接口沿用统一管理员访问边界，不公开密码散列、会话秘密或不必要的个人/连接资料。
- 运行态与保存状态有明确来源；不能把静态频道CurrentUsers或选角entry快照当当前在线/位置事实。
- 保持现有分层和单一Host/DI，HTTP不直接查库；所有测试使用隔离库及模拟游戏会话，source checkout与现服不动。

## Success Conditions

| ID | Observable condition | Required evidence |
|---|---|---|
| SC-1 | 全服账号/角色分页搜索、关联详情与余额准确，中文及特殊字符搜索正常 | 隔离SQLite多对象分页/筛选/详情与不存在/边界场景 |
| SC-2 | 登录未选角、已入场、移动/切频道/退出后的状态反映运行事实，离线保存位置有清晰区分 | 当前会话及位置变化场景，非静态配置计数证明 |
| SC-3 | 概览与查询页面可使用，鉴权拒绝和输入错误明确，已有认证/审计及架构无回归 | HTTP权限/字段与UI检查、相关回归、独立审查及构建 |

## Authorization

| Capability | Evidence | Authorized scope |
|---|---|---|
| task | “可以，你来写任务契约实施吧。不过最好是multispec，按搭建项目到设计各个模块一步一步分spec完成。”（根合同原授权） | 当前只读查询模块规格、实现、隔离验证、独立审查与本地验收提交 |

## Assumptions

- 在线资料是当前进程某次采样的事实，页面可刷新，不承诺跨进程监控或所有采样字段的全局原子快照。
- 无法合法解码的历史角色姓名保留明确显示/诊断，不能误替成另一玩家或按替代字符寻址；实际操作对象以稳定账号/角色ID为准。
