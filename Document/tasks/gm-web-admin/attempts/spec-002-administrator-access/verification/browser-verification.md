# 管理员页面真实浏览器验证

日期：2026-10-02。使用 `cua_repl` 的 Codex In-app Browser，与主控启动的隔离 Debug Host；当前产品树与 implementation-report 所述实现一致，没有修改产品。

两个数据库仅位于任务工作区 `artifacts/gm-access-browser/empty.db` 和 `browser.db`。关闭游戏网络及登录器 API；未初始化实例使用 8584，已初始化实例使用 18081，Vite 使用 5175。测试身份来自 `GmTestHost.cs` 的纯测试值，未初始化真实数据库或管理员。

| 场景 | 实际观察 |
|---|---|
| 无 bootstrap | 显示“管理员尚未初始化”及部署配置提示，没有可用登录表单。 |
| 错误密码 | 提交后显示“账号或密码错误”，保持登录页。 |
| 成功登录 | 进入操作记录，显示管理员、菜单，以及本次成功和上次失败的真实 SQLite 审计记录。 |
| 开发代理 | 通过 5175 页面正常读取身份、退出回到登录页、重新登录；保留 Host 的代理未阻断 CSRF/Origin 校验。 |
| 真实分页 | 通过真实 HTTP 额外完成 22 次成功测试登录；总量 26，第一页 20 条，点击第二页后显示 6 条。独立 HTTP 查询 page=2/pageSize=20 也返回 total=26/items=6。 |
| 服务重启 | 重启同一隔离库并改变 bootstrap 密码和权限，原 Cookie 仍加载 operator 身份及原权限，可查看审计。 |
| 重启后退出 | 页面重新取得 CSRF 后退出成功，回到登录表单；没有依赖旧进程的 CSRF 密钥继续执行写入。 |
