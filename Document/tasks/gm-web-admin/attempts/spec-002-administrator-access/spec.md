# Specification: 独立管理员访问边界与操作审计

## Why and Outcome

管理员以独立身份进入中文 GM 后台，登录状态可跨请求保持，注销或过期后失效；权限不足、玩家身份、跨站请求不能访问管理能力。后台首次部署有明确的初始化入口，没有配置管理员时仍可启动，但私有管理接口保持封闭。本阶段交付后续查询、邮件和点券模块共同依赖的访问及审计边界，不开放玩家资料或资产写入。

## Scope

包括首次管理员初始化、安全凭据存储、登录/当前身份/注销、持久化可撤销会话、四类管理权限、跨站和传输保护、登录失败限制、审计领域与分页查询、中文登录及权限菜单。后台仍使用已接受的 React/TypeScript/Ant Design，保持既有 GM/登录器/游戏启动组合。

不包括多管理员管理 UI、修改管理员密码的运营界面、玩家查询、邮件与点券业务、SSO、部署当前运行服务或初始化真实数据库。

## Definitions and HTTP Contract

- 管理权限分别为 `QueryPlayers`、`SendMail`、`GrantCera`、`ViewAudit`。权限由服务器保存的管理员事实决定，不能接受客户端声明的角色或权限。
- 匿名访问仅限 GM 静态页面、无私有信息的健康/初始化状态及取得登录所需的跨站防护令牌。健康响应不能带管理员、会话或审计内容。初始化状态只说明是否已初始化和配置是否可用，不回显配置值。
- 登录提交正确凭据后建立独立 GM 会话；查询当前身份返回管理员显示信息、权限和会话到期时间，不返回密码散列、原始令牌或数据库记录。
- 私有接口匿名/过期/撤销/禁用身份返回 `401`；已认证但权限不足返回 `403`；请求格式无效返回 `400`；跨站防护或远程明文传输不合法返回 `403`；限流返回 `429`。登录失败采用相同通用提示，不泄露账号存在与否。错误响应和 UI 不显示堆栈及配置秘密。
- 会话最长存活 8 小时，不因查询自动无限续期。管理员禁用或权限改变后，下一次请求必须采用当前持久化事实，不继续相信旧 Cookie 中的权限。GM 凭据不能用于玩家登录，玩家票据不能用于 GM 登录或授权。
- 会话 Cookie 使用 `HttpOnly`、`SameSite=Strict`，路径覆盖 GM API 和页面；TLS 下必须为 `Secure`。明文 HTTP 仅允许直接来自回环地址的请求用于本地部署；不能用 `Forwarded`、`X-Forwarded-For` 或 `X-Forwarded-Proto` 自报来源/TLS。远程部署通过真实 HTTPS 访问；反向代理信任配置不在本阶段范围内。

## Requirements

| ID | Requirement |
|---|---|
| RQ-001 | 首次部署从外部配置初始化独立管理员，并持久化用户名、启用状态、权限和密码验证材料。全部未配置时 GM 正常启动、显示配置提示、私有接口封闭；缺项或无效初始化配置不能产生可登录的弱身份。已有管理员重启后不被 bootstrap 配置覆盖或重新授予权限。源码、配置样例及日志不含真实凭据。 |
| RQ-002 | 密码只保存带随机盐的成熟安全密码散列及其版本/参数，使用框架支持的密码验证机制，不自创加密/散列协议；原文不落库、不返回客户端、不进入审计。会话标识不可预测，持久化存储不得保存可直接重放的原始会话秘密。 |
| RQ-003 | 登录成功建立可跨请求与服务重启验证的持久化会话。查询当前身份反映当前权限；注销撤销该会话，捕获的旧 Cookie 此后不能访问。过期、禁用身份或无效 Cookie 不能进入私有接口。 |
| RQ-004 | 为四类权限提供一致的服务器端鉴权接缝。审计分页只允许 `ViewAudit`；未来 GM 私有能力默认拒绝匿名，必须显式指定权限。UI 根据当前权限显示菜单，直接调用接口仍独立鉴权。 |
| RQ-005 | 登录、注销及后续所有改变状态的 GM API 必须验证跨站防护，合法请求需要与当前浏览器上下文绑定的令牌；无令牌、错误令牌和伪造跨站请求被拒绝且不产生状态变化。不能仅靠 CORS、菜单或 SameSite 实现此承诺。 |
| RQ-006 | 远程明文请求不能提交登录凭据、取得或使用 GM 会话，也不能访问私有管理 API。来源和传输判断采用服务端连接事实。本机明文开发与 HTTPS 部署均有正确 Cookie 行为。 |
| RQ-007 | 错误登录有明确的限流行为并限制存储增长：同一来源与登录名组合在 15 分钟内失败 5 次后拒绝继续尝试；同一来源还有覆盖不断改变登录名的上限。被限制响应 `429`，窗口结束可恢复。有效会话查询不因他人登录失败被撤销。 |
| RQ-008 | 审计保存稳定操作标识、发生时间、操作类型、管理员身份（未知登录可为空）、对象/结果与安全的原因摘要。记录登录成功、登录失败、注销；审计查询分页稳定、边界有效，不暴露秘密。提供后续邮件/点券与审计共同提交/回滚的领域及存储接缝，审计写入不得自行绕过当前事务。 |
| RQ-009 | 中文页面实现未初始化提示、登录及失败反馈、加载当前身份、退出、按权限菜单与分页审计。会话失效后回到登录，权限不足明确提示；没有权限的页面不能通过直接 URL 显示私有数据。 |
| RQ-010 | 保持当前 Host 启动/监听边界与分层：GM HTTP 仅经命令或领域契约，Application 不引用 Persistence/Protocol，Persistence 类型 internal、Schema 统一建表，命令处理器仅注入允许的 DomainService/DomainStore。所有验证使用隔离数据库，不修改在线数据库、现行服务或主仓库。 |

## Acceptance Criteria

| ID | Covers | Criterion |
|---|---|---|
| AC-001 | RQ-001, RQ-010 | 分别启动无 bootstrap、完整 bootstrap、缺项 bootstrap 的隔离 Host：前者可访问公开健康/页面并提示配置，全部私有端点拒绝；完整配置首次建身份；缺项不能登录。首次成功后变更 bootstrap 密码/权限并重启，已存身份保持不变。继承的 GM/登录器开关矩阵仍通过。 |
| AC-002 | RQ-002 | 隔离数据库中不含测试明文密码及可直接重放的原始会话秘密；同密码的独立初始化散列不同，正确/错误验证明确区分。成功登录所必需且符合规定 Cookie 标志的 Set-Cookie 是传递会话凭据的受控例外；JSON 正文、错误内容、捕获日志和审计不得含测试密码、密码散列或会话秘密。 |
| AC-003 | RQ-003, RQ-004 | 真实 HTTP 登录后下一请求及重启后可查询身份；注销成功后重放旧 Cookie 返回 401。可控时间推进到到期后返回 401；禁用管理员后返回 401；撤回 ViewAudit 后相同旧 Cookie 访问审计返回 403。无权限身份、匿名及玩家票据分别验证，均无法读取审计。 |
| AC-004 | RQ-005 | 真实 HTTP 对登录/注销使用合法防护令牌成功；缺失、错配或另一浏览器令牌及跨站来源请求被拒绝。拒绝的登录不建立会话，拒绝的注销不撤销合法会话；后续模块可复用同一验证接缝。 |
| AC-005 | RQ-006 | 连接事实模拟和实际监听测试证明本机 HTTP、HTTPS 有可用的合法登录行为；远程 HTTP 的登录、身份/审计与注销拒绝。加入自报回环或 HTTPS 的转发头不改变拒绝；TLS Set-Cookie 包含 Secure，所有会话 Cookie 均包含 HttpOnly/SameSite=Strict。 |
| AC-006 | RQ-007 | 可控时钟与真实 HTTP 覆盖错误密码、未知账号、第 5 次失败后的拒绝、窗口到期恢复，以及不断变化用户名不能绕过同来源限制；限制状态占用有上限。错误提示保持通用，限流不影响其他合法已登录会话。 |
| AC-007 | RQ-008 | 登录成功/失败与注销均有审计，身份、时间、类型和结果正确。分页有有效页长、排序与总量，非法分页返回 400。隔离事务证明业务测试记录与审计一起提交，并在故意失败时一起回滚；此阶段不执行邮件或点券业务。 |
| AC-008 | RQ-009 | 前端类型检查/构建通过；页面交互测试或浏览器检查覆盖未初始化、错误密码、登录、权限菜单、审计分页、权限拒绝、退出及会话失效。界面不展示尚未实现的玩家/资产操作数据。 |
| AC-009 | RQ-010 | 分层/命令构造器断言通过；Persistence 新表由统一 Schema 初始化且类型不对外公开。相关服务端项目与启动回归通过，运行记录明确隔离数据库路径，未切换现行服务。 |

## Success Evidence

- EV-001：认证/权限/会话/CSRF/传输/限流的领域与真实 HTTP 集成结果，关联 AC-001 至 AC-006；不以仅 mock 端点返回值替代访问边界证据。
- EV-002：隔离 SQLite 初始化、重启、审计分页及共同事务提交/回滚结果，关联 AC-001、AC-002、AC-003、AC-007。
- EV-003：前端类型检查/构建和中文交互证据，关联 AC-008。
- EV-004：既有启动矩阵、分层与相关服务端回归、独立安全审查，关联 AC-001、AC-009，并审查秘密泄露与认证绕过路径。

此阶段完成声明为实现和自动验证完成；真实运行环境管理员初始化与最终人工使用验收由根合同后续阶段安排。
