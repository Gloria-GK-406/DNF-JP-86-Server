# Specification: 按实际账号发放三种点券

## Why and Outcome

管理员选择实际账号，核对币种、每账号增量和原因后发放点券。单个与明确批量选择均准确持久化，同账号只到账一次，离线及没有角色的账号可用。成功结果和个人记录保存真实前后余额，重复点击、并发、响应丢失或重启后的原请求重试不重复到账。

## Scope

包含中文点券页面、专用账号选择、编辑与预览、整批提交、持久防重收据、个人发放记录、审计、提交后当前钱包提醒及本模块使用说明。沿用已接受的管理员身份、GrantCera 权限、同源/防伪保护、独立监听和命令事务。

不包含扣减、任意设置余额、新币种、全服条件发放、定时任务、点券草稿/模板、整个角色 effect 重构或其它消费能力重构。最终 CI、完整发布集成和整体验收表由后续 Spec006 处理。本模块仅在任务工作区的隔离 SQLite、端口及本机 Chrome 验证；不操作现服、真实玩家数据库或客户端，PVF 仅按需只读。自动证据保持 CurrentImplementation，客户端到账展示留待用户验收。

| RQ-002 | 选择及提交目标是实际 accountId，支持无角色及离线账号；专用选择仅提供发放所需账号标识和三币余额。明确选择有界账号集合，按账号 ID 去重；角色数量、角色名或客户端声称的归属不决定发放次数或资产目标。 |
| RQ-003 | 一次请求只增加 Cera、TokenCera、HappyTokenCera 之一，使用统一规范化及数值规则。预览展示冻结的账号集合、币种、每账号增量、原因、每账号三币当前/预计余额和全批总增量；预览不写资产，也不保留余额。 |
| RQ-004 | 提交取得全体目标的有序独占账号租约后开启共同事务，在事务内读取并校验当前钱包，以现有三币 CAS 更新。只有指定币增加，其余三币及其它账号字段不变；任何目标、范围、竞争或存储失败令整批回滚，不能覆盖其它合法交易。 |

| RQ-008 | 中文页面具备账号定位/搜索/分页多选、三币编辑、预览确认、结果及个人记录查询。确认后冻结输入和 UUID；未知状态恢复、失权清除和乱序响应防护沿用邮件已接受行为。业务分层保持领域服务编排、规则服务接收 facts、命令 handler 仅调用 DomainService/DomainStore；账号发放不依赖角色 effect 上下文。 |

## 对外行为与输入边界

页面沿用 `/wallet`；点券路由前缀 `/api/gm/v1/cera`，JSON camelCase。权限、错误 JSON 的中文 message、no-store、仅 GM 独立端口、401/403、同源/防伪及服务器身份来源复用 [Spec002](../spec-002-administrator-access/spec.md) 和 [Spec004 的对外行为与边界](../spec-004-official-mail/spec.md)。个人收据跨管理员读取返回 404；全局操作记录仍由已有 ViewAudit 入口保护。

| 方法与后缀 | 输入和结果 |
|---|---|
| GET `/accounts` | page/pageSize，可选 accountId/q。page 默认 1、范围 1..1000000；pageSize 默认 20、范围 1..100；accountId 为正 int；q 去首尾空白后至多 128 UTF-16 单元，按登录名做字面包含搜索，不把 `%`/`_` 当通配。重复参数或非法值 400，按 accountId 升序。仅返回 accountId/loginName/balances 与分页信息，不返回密码、角色明细、连接地址或其它资产。无角色账号照常列出。 |
| POST `/preview` | `{accountIds,currency,amount,reason}`。成功返回规范化输入、实际账号标识、三币 before/预计 after、每账号增量及 long 全批总增量，不创建收据、审计成功事实或钱包写入。非法/不存在/钱包异常目标明确拒绝整个预览。 |
| POST `/grant` | `{requestId,accountIds,currency,amount,reason}`。成功返回 receipt/replayed/reminder；receipt 包含 requestId、管理员 ID/登录名、committedAt、规范化 input、各账号 ID/提交时登录名及三币 before/after。replayed 表示恢复原提交事实；reminder 仅说明服务器提醒尝试/未确认。 |
| GET `/operations`；GET `/operations/{requestId}` | 当前管理员的成功收据；分页范围同上，按提交时间降序及稳定编号次序。编号查不到 404，中文反馈不能据此推断先前请求已回滚；原编号重试仍是恢复入口。 |

accountIds 数组去重前须有 **1..100** 项，每项为 `1..int.MaxValue` 的整数；去重排序后的实际账号集合参与防重，顺序/重复不同不造成新发放。提交不能自动创建缺失账号。币种只接受准确的 `Cera`、`TokenCera`、`HappyTokenCera`，对应页面“点券”“代币点券”“欢乐代币点券”，不接受任意数值枚举或未知币种。amount 是每个不同账号得到的同一个正整数，范围 **1..2147483647**；不接受 0、负数、小数、数值字符串或越界数字。

当前及结果三币余额均须在 **0..2147483647**。计算使用可检测溢出的宽整数；指定币 `after = before + amount`，另两币保持不变；任一余额或增款结果越界拒绝全批，不钳制、不回绕、不把数据库 long 强制截成 int。数据库中负数、超过 int 的长整数或无法读取的钱包应明确反馈“账号钱包数据异常”，不绕过现有读取守卫。

reason 先将 CRLF/CR 归一 LF，再去首尾空白，长度须为 **1..256 UTF-16 单元**且含非空白内容；拒绝 NUL、无效代理和除 LF/tab 外控制字符。规范化 input 为有序去重 accountIds、准确 currency、amount、规范化 reason；预览时间、预览余额、登录名和通知结果不参与防重。请求体上限 32 KiB，所有必要字段必填，非法 JSON、未知字段、错误类型及超限请求不发放。非空 UUID 解析与大小写/格式归一沿用邮件操作编号规则；点券与邮件是独立操作域。

预览余额为当时观测，页面须说明“提交按当前余额结算，以发放结果为准”。确认冻结目标、币种、增量和原因；期间其它合法交易可以改变余额，提交使用事务内实际 before 再检查上限，不把预览旧余额写回。若已不能合法增加则整批拒绝/回滚，并提示重新核对。

## 原子结算、恢复与通知

持久防重键为点券操作域内 `(administratorId,requestId)`，有数据库唯一性保障；不能仅依赖按钮禁用或进程字典。新发放必须在服务器解析的完整账号范围内，通过 `IMultiAccountCommand` 的 Account Exclusive 租约与共同 Transactional 管线执行。事务内先占据适用的 SQLite 写边界、复核权限及防重事实，然后核对账号/当前钱包；每个 CAS 须影响恰好 1 行，否则整批失败。预检范围须与规范化目标相同，不能锁 A 写 B。

对已经成功的同 key/同 input，重新鉴权后优先返回原持久收据，即便该账号后来不可用或当前余额已变化，也不重新要求它满足新发放条件；同 key 改币种/增量/账号集合/原因返回 409。另一个管理员同 UUID 是独立请求，不能读取前者收据。仅成功操作永久绑定输入，明确失败后修改内容使用新的显式确认和编号。

拒绝/回滚/Unknown、独立失败审计事务、审计自身异常反馈、响应丢失后安全恢复以及“查无收据不能证明未提交”复用 [Spec004 的原子提交、重试与记录](../spec-004-official-mail/spec.md)，行动名改为 GrantCera。成功审计摘要记录编号、币种、每账号增量及账号数量，完整原因及前后余额由收据保存，不记录凭据。审计或收据写入失败不得留下增款；提交结局不明确时不能返回 rolledBack。

账号资产结算由 account-only 领域能力承载：可提供窄的账号钱包读取/发放接缝和不可变规则结果。规则服务仅依据传入的账号钱包 facts/输入产生决定，不自行查询账号状态；领域服务使用 `IAccountTable.FindWalletAsync/TrySetCeraBalancesAsync` 进行事务结算。不能虚构 characterId=0、挑一个代表角色计款，不能为本模块把整个 `EffectExecutionContext` 改成 nullable 角色。Application 不引用 Infrastructure/Persistence/Protocol/Networking，GM HTTP 不直接查库或引用协议；持久实现保持 internal，建表/调和只归属 Persistence/Schema。

提交返回后才能发布账号钱包变更的中立通知。通知及重试必须现查当前三币，经现有钱包 NOTI `0x0035` 投影；不得复用购买成功的历史钱包快照或 `AccountEntryAssembly` 的必须有角色读取路径。连接与当前选中角色解析留在投递/会话边界，不能由资产服务为通知查 socket；Protocol 通知 handler 仅注入领域服务，不直接注入 Table。无在线选中角色时自然无提醒；会话切换校验不得把旧会话状态送给其它账号。无需持久通知 outbox 或离线补提醒保证，重新登录仍读取持久钱包。

## 页面及模块交付

跨页选择保持明确 accountId，展示已选账号及可取消项，不提供“全服匹配发放”。预览逐账号展示三币前后余额，并显示“每账号增加”及“不同账号数量/总增量”；确认后不能改变本次冻结内容，提交结果显示实际余额和编号，提醒未确认仍显示到账成功。

刷新同浏览器页面可恢复当前管理员的待确认 UUID/冻结输入，但不自动发放；存储失败必须在发送前明确反馈，避免失去恢复标识。未知状态仅可查原结果或原内容安全重试，不自动创建新编号。加载、空结果、输入错误、401/403/409、500、超时均有中文反馈；失权立即清除可见点券资料、禁用操作，旧请求不得恢复旧管理员数据或覆盖新编辑。账号登录名和原因仅作文本渲染。普通未确认编辑不要求持久草稿。

本模块使用说明置 Document，包含权限、选择/预览/提交、批量上限、结果/通知含义和未知恢复；列出用户后续核对三币到账、在线展示和重新登录余额的验收项，不宣称 ClientVerified。

## 已核对的代码事实

基线 07e1f607 的 CurrentImplementation：`AccountCeraBalances` 使用三 int；`IAccountTable.FindWalletAsync` 返回 long 行值，SQLite 读取守卫拒绝非法范围，`TrySetCeraBalancesAsync` 同时比较三旧值且只更新三币列。`AccountExecutionBehavior` 已对 `IMultiAccountCommand` 去重排序并在事务前取得租约。邮件模块已有持久管理员范围收据、事务内鉴权及冻结 UUID 恢复模式。现有 `GameInstanceDelivery.Wallet` 编码 `u8=1 + Cera/TokenCera/HappyTokenCera 三个 int`，钱包 NOTI 为 `0x0035`；`AccountEntryAssembly.LoadAsync` 拒绝无角色账号，故不能作为本模块通用钱包读取能力。`ISelectedSessionDomainService.Find(AccountId)` 可取得当前选中会话；当前通知 audience 只有 TheseCharacters/TheseSessions/Scoped，并无现成 TheseAccounts。实施可选择最小中立投递接缝或必要的账号 audience 扩展，以账号所有权和精确会话核验满足上述通知行为，不要求采用某个尚不存在的 API。
