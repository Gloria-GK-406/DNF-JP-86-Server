# TaskContract: 按账号发放点券

## Context

### Source Request

根请求“发送点券等等”及已接受后台范围包括按账号与币种增加点券、批量去重、防重复提交、前后余额和记录；根授权按模块MultiSpec完成实现与验收。

### Current Situation

已接受07e1f607提供后台身份、GrantCera权限、审计、账号查询与可恢复邮件写操作。账号表持有三种币余额，交易使用账号执行租约和公共事务；点券页面仍为占位。账号可没有角色，不能用需要真实角色的通用effect上下文虚构发放目标。

## Goal

管理员能核对实际账号和币种后增加三种点券，单人及明确批量发放均准确持久化，可查看前后余额和操作记录；重试、并发和通知失败不会重复到账或丢失其它交易。

## Scope

### In

- GrantCera权限下的中文账号选择、币种/增量/原因编辑、预览核对、提交与个人记录。
- 三种现有点券按账号发放，同账号多角色不重复计次，离线及无角色账号可用。
- 余额范围、批量全部提交/回滚、持久防重、前后余额及审计；提交后在线钱包通知。
- 现有领域及账号事务边界接入，隔离SQLite/HTTP、并发/错误/重启与页面验证，使用说明及后续验收。

### Out

- 扣减/任意设置余额、新币种、自动化/全服发放；重构其它消耗品或整个角色effect系统；现服切换与真实玩家发放。

## Constraints

- 独立管理员与GrantCera权限，事务执行时有效鉴权；HTTP不直接查库、不引用Persistence/Protocol/Networking；符合现有模块分层和账号执行边界。
- 账号是资产目标，不以角色数计次、不造角色进入角色effect；余额变更与发放事实/成功审计同事务，错误不得形成部分到账或覆盖其它交易。
- 相同提交重试只能恢复原持久事实；通知失败不撤销/再发，重试投影读取当前余额，不发送旧历史收据余额。

## Success Conditions

| ID | Observable condition | Required evidence |
|---|---|---|
| SC-1 | 中文页面可选择实际账号、核对币种增量原因及单个/批量发放结果和记录；身份/输入/未知状态反馈明确 | 实际HTTP和页面行为、权限与范围验证 |
| SC-2 | 三种币准确持久化，无角色/离线账号和批量去重有效；失败整批回滚、并发不丢其它合法变更 | 真实SQLite/领域事务及竞争、溢出、重启验证 |
| SC-3 | 重复/并发/响应丢失/通知异常后不会重复到账，前后余额和审计可追溯，在线通知复用当前钱包投影 | 持久重试、错误/通知、架构和旧交易回归、独立审查 |
