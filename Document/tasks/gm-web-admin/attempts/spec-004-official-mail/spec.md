# Specification: 官方邮件编辑与发送

## Why and Outcome

管理员可以保存邮件草稿、复用内容模板、核对明确的收件角色和附件，再发送官方邮件。结果能按操作编号重新查询；一次批量发送只有全部提交或全部回滚，超时、重复点击和服务重启后的重试不重复发放。玩家仍从既有邮箱领取附件，后台不直接修改其背包。

## Scope

包含每管理员一份持久化草稿、个人内容模板、收件角色选择、内容及附件预览、单人/有界批量发送、个人发送记录和提交后邮箱提醒。沿用已接受的管理员登录、独立监听、权限、跨站保护和审计。支持永久普通装备、永久堆叠物和金币附件；不增加装备定制属性、时装、宠物、期限道具、服务权益、广播、定时发送或已发送邮件修改。

实现和验证仅在任务工作区及隔离测试库/端口进行，不切换现服，不向真实玩家发放，不修改客户端或 PVF。当前协议代码作为 CurrentImplementation 约束；自动测试和后台页面检查不构成 ClientVerified。

## Requirements

| ID | Requirement |
|---|---|
| RQ-001 | 全部邮件接口要求服务器确认有效管理员及 SendMail 权限；编辑、预览、保存、发送和重试的写请求继承同源/防伪保护。SendMail 与 QueryPlayers 独立，邮件专用收件人投影不泄露账号余额、密码、连接地址或秘密。 |
| RQ-002 | 草稿持久保存编辑内容和收件角色 ID；模板仅保存名称、正文及附件，不保存收件人。保存、加载、覆盖、删除是显式动作，版本冲突不得静默覆盖另一个页面的更改；刷新和重新登录后仍能恢复已保存内容。 |
| RQ-003 | 编辑、预览与最终提交使用同一文本及附件约束。预览展示归一后的实际文本、UTF-8 字节数、明确收件角色 ID/姓名诊断、每人附件及总发放数量。确认时发送预览的不可变快照，后续编辑不能偷偷改变已确认内容。 |
| RQ-004 | 收件角色必须实际存在且未删除；每批明确选择 1..100 个不同角色，不接受全服条件、名字替代 ID 或客户端声称的账号归属。服务器解析账号执行范围，提交事务中重新核验目标及归属。 |
| RQ-005 | 仅接受内容规则支持、现有邮箱可正确领取的永久普通装备/堆叠物和非负金币。新装备使用正常初始 core 与独立世界 UID，经系统邮箱保管；不能复用现有玩家 UID、伪造实例或绕过邮箱直接入背包。 |
| RQ-006 | 全批邮件、附件、新装备、成功操作收据及成功审计共用事务；任何目标、内容、ID 范围、创建或持久化失败都不产生部分邮件或孤立装备。拒绝、已确认回滚与提交状态未知必须区分，不能把未知写成已回滚。 |
| RQ-007 | 操作编号在管理员范围内持久防重；相同编号与相同归一输入返回原持久化收据，改变内容返回冲突。并发、进程重启及响应丢失后重试不再创建邮件/UID，也不再追加成功审计。 |
| RQ-008 | 只有提交成功后才尝试通知在线收件人；离线、断线或通知异常不撤销、不再次发放，也不描述为邮件发送失败。通知投影读取当前邮箱数量，重试不发送旧收据中的邮箱计数；结果不声称客户端已读或附件已领取。 |
| RQ-009 | 中文页面提供完整编辑、保存/加载、查找及选择收件人、预览确认、结果及历史查询；输入、加载、空结果、失权、会话过期、冲突、预期拒绝和未知结果均有明确反馈。旧请求不能恢复已失权资料或覆盖新编辑；未知结果保留编号与冻结输入供查询/安全重试，不自动新建编号重发。 |

## 对外行为与边界

邮件路由前缀 `/api/gm/v1/mail`，JSON camelCase。所有接口要求 SendMail，不以 ViewAudit/QueryPlayers 作为使用邮件功能的附加条件。管理页面普通操作记录继续要求 ViewAudit；邮件页面仅能查询当前管理员的稿件、模板与发送收据，另一管理员对象返回 404。操作者来自已认证服务器身份，不接受请求体指定管理员。写操作实际进入事务时再次确认会话有效、管理员启用及 SendMail，不能凭排队前旧权限发放。

| 路径与方法 | 输入和结果 |
|---|---|
| GET `/draft`；PUT `/draft` | 草稿包含 revision、title、body、recipientIds、items、gold。首次为空 revision=0；保存须 expectedRevision，成功 revision 加一。草稿允许空收件人/空正文等未完成状态，但结构和大小有界；尚不合法的发送内容在预览时明确拒绝。 |
| GET/POST `/templates`；PUT/DELETE `/templates/{id}` | 个人模板列表及显式新增、覆盖、删除。名称去首尾空白后 1..64 UTF-16 单元；最多 20 份，名称在同管理员内唯一，重复返回 409。更新/删除须 expectedRevision；保存内容满足文本/附件输入边界，可以不带收件人。加载模板保留当前收件人选择，加载草稿则恢复保存的收件人。 |
| GET `/recipients` | page/pageSize、可选 characterId/q。分页、范围、字面搜索及异常姓名诊断沿用 Spec003；仅返回有效角色的 characterId/name/nameDecodeStatus/nameBytesHex/level/job/growType，不返回登录名、账号资产或运行态。按 ID 升序；跨页选择保留明确 ID，取消选择可操作。 |
| POST `/preview` | 完整待发输入，不创建玩家资产或收据；成功返回归一快照、字节数、当前收件人最小身份及附件类别/初始状态/每人数量和全批汇总。非法内容返回 400 中文原因；不存在/已删除目标明确拒绝。 |
| POST `/send` | requestId 与完整待发快照。成功返回持久化收据及 replayed 标志。成功收据含 requestId、操作者、提交 UTC 时间、冻结输入、每位收件人 ID/提交时姓名诊断/生成 mailId、附件清单和新装备 UID。同 key 不同输入 409。 |
| GET `/operations`；GET `/operations/{requestId}` | 个人成功发送记录，分页默认 1/20，上限沿用 Spec003；按提交时间降序、稳定编号次序。编号查不到为 404，不能由此断言先前请求已经回滚；查询是已提交事实的恢复入口。 |

正整数 ID 为 1..int.MaxValue；requestId 为标准 UUID，归一大小写及格式，防重键为 `(administratorId, requestId)`。另一个管理员同 UUID 是独立操作，不能读取/重放前者收据。请求体最大 32 KiB，非法 JSON、缺少必要数组/字段、非整数、越界、未知附件类型或超过大小限制均不发放。未认证 401、缺权限/跨站拒绝 403；错误 JSON 使用中文 message，不暴露 SQL、堆栈、秘密。所有邮件响应 no-store，仅 GM 独立端口提供。

### 文本、附件和有效期

文本先把 CRLF/CR 归一为 LF；不裁剪有意义的首尾空白。拒绝 NUL、不成对 UTF-16 代理及除 LF/tab 外的控制字符。标题可为空、正文至少包含一个非空白字符；按当前客户端投影，标题为空或与正文相同则显示正文，否则显示 `title + LF + body`。严格 UTF-8 计算该显示内容，最多 **511 字节**，预览直接展示该字符串，服务端拒绝超限，不能依靠 codec 截断。草稿/模板保存的各文本至多 511 UTF-8 字节，可以组合超限但不能发送；保存和预览分别反馈其含义。

每位收件人金币 gold 为 0..int.MaxValue，0 不生成金币附件；items 为至多 10 个 `{itemId,count}` 行，同一模板不能重复输入。永久堆叠物 count 为 1..int.MaxValue，须匹配既有邮箱领取容器规则；永久普通装备数量为 1..10，每件展开成独立附件。展开后的物品附件总数最多 10，金币最多另加 1 行。因此既有 20 封邮箱页最多 220 个 GM 邮件摘要，仍能由 u8 摘要个数表示。

规则必须确认模板已知、placement/world class 合法、初始实例声明支持，且默认期限、绝对期限、权益类型均为零。拒绝宠物、宠物装备/消耗品、时装、复活币/虚拟资源、权益服务及其它无法按现有邮箱生命周期保真生成的物品。合法账号共享材料可通过既有堆叠物领取路径进入账号材料袋；未知/不支持内容不能退化成普通物品。

普通装备按内容规则建立初始品级/耐久/封装等状态，不接受客户端自定义强化、红字、附魔、UID 或 core。每次每人每件均有不同 UID；领取前无背包位置且被邮箱持有，领取时原 UID 进入已有装备转移领域。堆叠物记录 template/count；金币记录 amount。系统来源 sender=0、空发送者名。邮件统一在提交 UTC 时刻起 30 天过期，收据保存实际时间，重试不延长；不支持编辑过期时间。创建出的 mailId 及 attachmentId 必须仍在现有协议可表示范围内，否则本批回滚。

### 原子提交、重试与记录

归一输入含有序去重后的 recipientIds、归一 title/body、按输入顺序的 items 和 gold。100 人上限对提交的 ID 数组在去重前也成立；重复角色 ID 不重复发放，排序不改变防重语义；附件行顺序是内容的一部分。稿件/模板 ID、expectedRevision、预览时间不参与发放输入。快照不因模板之后修改而变化。

在 SQLite 事务及账号执行边界内获取防重事实、复核管理员与目标，再创建全批邮件、收据及一次 SendOfficialMail 成功审计；成功审计记录编号、对象数量及结果，不重复存正文，不记凭据。相同已提交请求先返回原收据，不要求此时目标仍存在/内容仍可新建；这不授权一次新的发送。数据库唯一约束提供持久防重，不能只靠进程字典或按钮 disabled。

已确认拒绝或已确认回滚的授权发送尝试，以独立审计事务记录 Rejected/RolledBack 原因；该记录不能冒充成功收据，审计异常明确反馈且不隐式重试发放。不要求为未通过身份/跨站保护、不可解析请求持久写业务审计。提交状态不确定时返回“结果暂未确认，请用原编号查询或重试”，记录 Unknown（记录成功才可声称已记录），不能返回“发送失败，未发送”。成功提交即使随后 HTTP 响应、通知或连接取消失败仍能用原编号恢复；没有成功收据的查询结果不能替代原编号重试来确定结局。仅成功请求永久绑定输入；明确失败后重新编辑发送应新建编号。

通知通过中立 Abstractions 契约接入 Protocol 邮箱投影，HTTP/Application 不引用协议类型。发送命令完成后才投递；通知 handler 只经邮箱领域查询当前数量，由既有精确在线接收者解析和发送链路决定目标。通知失败可以显示“已发送，在线提醒未送达/未确认”，不影响成功收据；无需实现持久通知 outbox 或保证离线补提醒，玩家后续打开邮箱/登录仍读取持久邮件。

## 页面行为

编辑区显示草稿保存状态，附件明确提示支持类别与每人数量。收件人允许 ID 定位、字面姓名搜索、分页多选，始终显示已选择 ID，包含异常姓名诊断。预览确认展示官方来源、30 天期限、每人及全批发放汇总，并说明“整批提交，附件由玩家在邮箱领取”。确认后锁定本次快照与 UUID；成功/明确拒绝后可退出确认修改，成功再次发送必须是新的显式确认。

网络超时/未知结果时保留冻结快照与 UUID，提供查结果及原请求重试；刷新同浏览器页面也可恢复待确认状态，但不得自动发放。客户端保存的状态是不可信输入，服务器仍完整鉴权/校验；切换管理员不可展示他人的草稿或待确认内容。失权清除可见邮件资料并禁用操作，401 进入登录；旧 poll/预览/保存/发送响应不能恢复旧权限或把另一位管理员的内容显示出来。正文、模板名、姓名只作为文本渲染。

## 已核对的代码事实

以下为基线 573be46b 的 CurrentImplementation，指导边界而非新的客户端规则证明：

- `MailboxDomainService.SendAsync/ClaimAsync` 支持系统来源、堆叠物/金币和 detached 普通装备，任何错误回滚当前 ambient transaction；批量不能 catch 后继续提交部分。
- `MailStackTransfers.ValidateAsync/GrantAsync` 使用 placement 与容器领域，账号共享材料进入既有账号袋；邮件堆叠附件只有模板/数量，不能携带期限等额外状态。
- `IWorldItemTable.InsertAsync` 分配 detached 世界实例 UID；`EquipmentTransferDomainService` 领取时把该实例移入正常容器。
- `IPackageOpeningRuleService.PrepareAsync` 及内容事实提供 supported、placement、初始耐久/封装与期限/权益诊断，可复用适用的规则准备；不能假造角色 0 进入需真实角色的 effect 上下文。
- `StateSynchronizationPayloadCodec.EncodeMailbox` 的实际展示合并 title/body、最大 512 的写函数超限取前 511 字节；summary 个数 u8、每页既有查询 20 封；`MailboxIds` 附件 ID 要求 `0 < id < 0x40000000`。
- 现有 `MailboxArrived` 是 Protocol 类型，GM 必须通过中立接缝接入；`AccountExecutionBehavior` 的账号租约在事务外按 ID 排序，命令返回时 `UnitOfWorkBehavior` 已完成提交。
