# TaskContract: 官方邮件编辑与发送

## Context

### Source Request

根授权包括“编辑发送官方邮件”，并接受按模块MultiSpec实施；根合同纳入文本草稿/模板/预览、合法金币物品附件、单人及明确选择的批量发送与记录。

### Current Situation

已接受573be46b提供独立后台、管理员SendMail权限/审计和玩家查询。系统邮箱领域可发送并保管附件，领取时入背包；后台邮件页面目前未实现，附件实例生命周期和提交后通知必须遵守原领域事实。

## Goal

管理员可以编辑、预览并给明确选择的角色发送官方邮件与合法附件，查看持久化发送结果；失败和重试不会造成误发、重复发放或半完成的不透明结果。

## Scope

### In

- 中文官方邮件编辑、文本草稿与模板、与客户端可表示文本一致的预览。
- 明确选择单人或多个角色、合法金币和物品附件，发送前核对收件人和内容。
- 受SendMail权限保护的发送、可追溯发送记录与结果；重试安全及明确失败反馈。
- 邮件及附件复用既有领域事务/生命周期，提交后接入在线通知。
- 隔离SQLite/HTTP、附件领取、批量和错误场景验证，页面验证与使用说明。

### Out

- 广播全服邮件、定时群发、修改已发送邮件、额外运营模块；现服部署及真实玩家发放。

## Constraints

- 复用管理员身份、写入跨请求保护和审计；HTTP不直接查库或引用Protocol/Networking/Persistence，遵守单一Host/DI及既有账号执行边界。
- 收件人必须是实际有效角色；附件按物品类型和生命周期生成，不得伪造或复用别人的实例、以发送代替背包直接写入。
- 发送结果反映持久化事实，重试不得重复发放；通知失败不得撤销或再发邮件。批量成功/失败边界明确且可追溯。
- 编辑结果及预览遵守当前客户端可表示文本/附件边界；不声称自动测试已证明真实客户端表现。

## Success Conditions

| ID | Observable condition | Required evidence |
|---|---|---|
| SC-1 | 草稿、模板、预览和单人/批量发送可操作，输入、失权与失败反馈清楚 | 中文页面行为与实际HTTP验证，文本及附件边界 |
| SC-2 | 合法邮件、金币/物品附件持久化并可领取；无效目标或附件不会形成部分误发 | 隔离真实SQLite发送/领取、批量及回滚场景 |
| SC-3 | 重复/并发/通知失败后重试不重复发送，记录及审计反映已提交事实 | 持久化重试与错误/通知场景、权限/架构回归、独立审查 |

## Authorization

| Capability | Evidence | Authorized scope |
|---|---|---|
| task | “可以，你来写任务契约实施吧。不过最好是multispec，按搭建项目到设计各个模块一步一步分spec完成。”（根合同原授权） | 当前官方邮件模块规格、实现、隔离验证、独立审查与本地验收提交 |

## Assumptions

- 附件支持的物品类别在规格与界面中明确说明；超出既有可正确生成/领取生命周期的类别清晰拒绝。
- 在线通知是提交后投影，不是客户端已读/已领取证明。
