# TaskContract: GM Web 管理后台

## Context

### Source Request

“分一个新的分支出来……独立的后台web模块……查看角色列表，在线情况，编辑发送官方邮件。发送点券等等。具体功能由你来设计和实现。”

用户接受独立模块、同进程 Host、React/TypeScript/Vite/Ant Design 的方案，并授权：“可以，你来写任务契约实施吧。不过最好是multispec，按搭建项目到设计各个模块一步一步分spec完成。”

### Current Situation

基线 5fbe2dad，版本 0.2.0。Host 共用 HttpApi、GameServer 与公共领域服务，HTTP 开关目前耦合 LauncherAuth。已有账号三种点券余额、系统邮件/附件、角色查询和选中会话快照；尚无 GM Web、管理员权限及通用发放入口。

## Goal

交付可随服务端启动和发布的中文 GM 后台，完成查询角色与在线状态、编辑发送官方邮件、按账号发放点券以及可追踪的操作结果，并提供最终验收清单。

## Scope

### In

- 独立 Web 前后端模块接入同一 Host；后台、登录器 API、游戏网络分别启用。
- React + TypeScript + Vite + Ant Design；统一中文管理界面与完整成功/失败反馈。
- 独立管理员认证和操作权限，管理员与玩家身份隔离。
- 全服账号/角色分页筛选、角色详情、在线及频道/位置查询、服务概览。
- 官方邮件文本草稿/模板/预览、合法物品与金币附件、单人及明确选择对象的批量发送与记录。
- 按账号与币种增加点券，批量去重、防重复提交、前后余额和记录。
- 查询和写入使用既有领域边界；写入事务、一致性、失败回滚、提交后在线通知。
- 自动验证、前端构建与随包发布、运行说明、实机验收清单。

### Out

- 全服广播、封号、修改角色职业/等级、任意 SQL、修改已发送邮件、自动化运营调度。
- 独立进程/RPC 部署、多服集群后台、另建玩家资产数据库。
- 当前运行游戏服务切换、真实玩家资产发放、推送、PR、合并、Release。

## Constraints

- 遵守仓库分层，GM HTTP 不直接引用 Persistence/Networking/Protocol；复用领域事务和适用的 effect 能力，不能旁路写在线玩家数据。
- 私有资料和写操作仅允许已认证且获授权的管理员；玩家登录票据不能取得管理权限。
- 发放结果反映持久化事实；重试不得重复到账，通知失败不得撤销或再次执行已经提交的发放。
- 官方邮件按客户端可表示的格式及物品生命周期生成；点券按账号发放，同账号多角色不重复计次。
- 一个隔离工作区，串行完成各个独立验收结果；已验收结果不可因下一阶段失败丢失。

## Success Conditions

| ID | Observable condition | Required evidence |
|---|---|---|
| SC-1 | 独立后台模块随 Host 启用和关闭，与登录器/游戏开关组合正确；前端随包可访问 | 真实 HTTP 启动矩阵与构建/发布检查 |
| SC-2 | 管理员登录、注销、权限及写入追踪有效，非管理员不能读写管理数据 | 认证/鉴权/跨请求保护与操作记录集成验证 |
| SC-3 | 页面能搜索全服角色/账号、看详情和真实在线角色、频道及位置 | 查询与实时会话场景验证、页面检查 |
| SC-4 | 官方邮件草稿到发送及附件领取使用已有领域，单人/批量结果可追溯且不会重复发送 | SQLite 邮件/附件与重复/错误场景、HTTP/UI 验证 |
| SC-5 | 指定账号三种点券可发放，余额准确持久化、批量去重、重复/并发安全、在线通知接入 | 账号账本/并发/回滚/HTTP 与通知测试 |
| SC-6 | 集成产品可构建发布，核心旧流程无回归，使用说明和逐项最终验收表完整 | 前后端检查、服务端回归、独立完整审查、验收文档 |

## Authorization

| Capability | Evidence | Authorized scope |
|---|---|---|
| task | “可以，你来写任务契约实施吧。不过最好是multispec，按搭建项目到设计各个模块一步一步分spec完成。” | 合同、隔离开发、分阶段设计/实施/验证/独立审查、验收结果的本地提交 |

## Requires Confirmation

- 如需切换当前正在运行的游戏服务或向真实玩家发放数据，单独获得操作授权。
- 推送、PR、合并与清理在用户要求分支收尾时执行。

## Assumptions

- 最终交付声明为实现及自动验证完成；真实客户端到账、邮件表现等由用户按清单验收，未验收项目不标记 ClientVerified。
- 默认管理员由部署配置首次初始化，凭据不写入代码或仓库；后续可独立扩展管理员管理。
