# Specification：魔法封印装备

## Outcome and Evidence Boundary

角色持有的魔法封印装备由服务端识别；解封与客户端支持的词条变更只在资格、费用和目标均有效时结算，得到可持久、可投影的随机属性。已知 A21 静态入口有 `0x0191`（四字节）与 `0x01B6`（五字节）；`0x0197`、`0x01C8` 属于待分辨的相邻入口，不能仅因名字相近就接到同一资产路径。无实帧的结论标 `ClientStatic` 或 `Hypothesis`，不标 `ClientVerified`。

## Requirements

| ID | Requirement |
|---|---|
| RQ-001 | 对照 70、上游、A21 静态/抓帧与真实 PVF，确认封印装备来源、解封资格、费用/材料及随机属性规则；裁定 `0x0191`、`0x01B6`、`0x0197`、`0x01C8` 与本功能的关系，并记录未知。 |
| RQ-002 | 服务端只对当前角色拥有的有效封印装备执行解封；已有解封状态、无权目标、错误槽位、缺费用或锁定/过期装备拒绝且资产不变。 |
| RQ-003 | 词条变更仅针对已解封且有效的条目，生成符合真实 PVF 规则的结果；装备 UID、强化/附魔/异次元等无关字段保持，金币/材料与装备变化原子提交。 |
| RQ-004 | A21 已判定可用的入口获得其能读取的响应或权威物品/金币刷新；提交失败不投递成功，重登展示与落库一致。 |
| RQ-005 | 人测清单提供固定样本、合法/拒绝/重登步骤及抓帧/日志定位，明确未实测与残余不确定性。 |

## Acceptance Criteria

| ID | Covers | Criterion |
|---|---|---|
| AC-001 | RQ-001 | 证据对照可追到具体 70/上游路径或地址、A21 构包/接收 RVA、PVF 路径/样本；每个候选入口标明实现、隔离或待证原因。 |
| AC-002 | RQ-002 | 给定有效样本可解封并持久读回；对错角色/槽位、锁定/过期、状态不符和资金不足的拒绝没有装备、金币或材料变化。 |
| AC-003 | RQ-003 | 给定固定随机输入，可重复得到规则内词条；替换指定位置且其余词条与装备无关属性/UID 不变，重复和 SQLite 提交失败不双扣或半提交。 |
| AC-004 | RQ-004 | 字节与 handler 测试覆盖已接入口的成功/拒绝投递及物品刷新；若客户端静态不支持独立 ACK，以证据说明并采用其可见的状态路径。 |
| AC-005 | RQ-005 | Human Test List 可供用户在 A21 上执行解封、词条变更、拒绝及重登，并分离自动测试与实机未验证结论。 |

## Success Evidence

- `Document/tasks/equipment-development/attempts/spec-003-magic-seal/` 的证据设计、验证和 Human Test List；`protocol/` 人工区记录候选入口证据等级。
- 真实 A21 PVF 内容测试、领域/SQLite 守恒与回滚测试、字节/handler 测试及完整变更审查。

## Stop Boundaries

若关键字段、费用或材料身份不能从 A21/PVF 安全确定，只交付已闭合子路径并把未闭合入口明确拒绝/隔离，不能用上游默认值暗扣资产。用户 GUI 与实帧验证留在集中验收阶段。
