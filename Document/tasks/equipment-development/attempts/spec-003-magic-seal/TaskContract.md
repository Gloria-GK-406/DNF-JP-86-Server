# TaskContract：魔法封印装备

## Context

### Source Request

用户授权在 `task/solo-play-roadmap` 分支逐项完成强化、附魔、魔法封印、异次元属性和锻造，每项依 70 服务端、上游、A21 客户端与 PVF 探查后设计实现；2026-09-30 要求快速开发、快速验证、提交后继续，并排除附魔师相关功能。本子项对应根任务 SC-3。

### Current Situation

接受基线 `8ab85ebd` 已有装备实例上的三个随机属性及变化状态持久化/投影，但魔法封印的生成、解封与词条处理业务尚未闭环。实例的 `SealFlag` 另有物品封装/交易用途，不能未经证据就当作魔法封印状态。`0x0191` 有 A21 四字节静态构包证据，第二字段的含义未证实；尚无实帧或 GUI 验收。

## Goal

让魔法封印装备在服务端可识别、可按 A21 支持的操作解封和处理词条，资产与装备属性原子持久，客户端在重登后能看到一致状态。

## Scope

### In

- 对照 70、上游、A21 静态/实帧与真实 PVF，确定封印装备的来源、解封及客户端支持的词条处理入口；标明未知。
- 实现可证实的装备目标、材料和费用校验、随机结果生成与状态转换，保持装备 UID 与无关属性，失败和重试不造成部分结算。
- 接入 A21 证据支持的协议结果与物品状态更新，提供自动测试和可供用户集中实机验收的 Human Test List。

### Out

- 异次元属性与锻造；附魔师相关功能 `0x025A`；未经证实的词条操作或资产扣除。
- 推送、合并、部署、用户数据库改写及未经执行的 `ClientVerified` 声明。

## Constraints

- 70 与上游是规则参考，A21 客户端和真实 PVF 决定线协议与内容边界；未知关键资产语义不得凭参照端猜测结算。
- 复用装备实例和现有事务边界，保护已接受的强化、宝珠附魔及宠物路径。

## Success Conditions

| ID | Observable condition | Required evidence |
|---|---|---|
| SC-1 | 封印装备来源、解封和 A21 支持的词条入口及材料/费用/结果语义可追溯，未知明确。 | 70/上游/A21/PVF 对照、方案与必要的 `protocol/` 记录。 |
| SC-2 | 合法操作形成持久状态转换；非法目标、材料不足、重复和提交失败不丢失、复制或部分改变资产。 | 真实 PVF 样本、确定性领域/SQLite 测试及重读结果。 |
| SC-3 | 客户端可用入口收到可解释结果与装备/材料状态，其他装备属性和 UID 不变。 | 字节/handler 测试及客户端静态或抓帧证据。 |
| SC-4 | 用户能按固定样本执行解封、词条处理与重登验收。 | Markdown Human Test List，标明未实测项和抓帧/日志定位。 |
