# 魔法封印装备 Human Test List

状态：**待用户 A21 GUI/实帧验收**。下表是执行清单，不是已经通过的客户端事实。只用隔离数据库、可丢弃角色与装备；操作前备份，不在珍贵装备上首测。

## 准备与定位

- 确认 Host 使用本分支构建；打开双向 `clienthack-frame-capture.log`，记下角色、装备 UID/物品 ID、背包槽、金币、时间和数据库备份。服务端可观察 `MAGIC_SEAL` 拒绝日志与 `0x000E` 背包刷新。
- 固定 PVF 样本：`equipment/character/swordman/weapon/katana/101010339.equ`（`[random option] 1`、等级 75、rarity 2），本服解析解封金币 1720、变更金币 3800。测试前确认角色实际能取得该装备并在主背包；若不可达，记录可达的 `[random option] 1` 装备 ID/PVF 路径及操作停点。
- 可选卷轴 `stackable/professional/common/alchemy_unlock1.stk`（ID `2600460`，脚本 Lv30 以下）只作静态证据样本。本轮尚未确认请求第二字段是卷轴槽，凡非 `0xFFFF` 均拒绝且不消费；即使找到低等级封印装备也不要期待本版卷轴功能可用。

## 操作与留证

| 检查 | 人类客户端动作 | 预期与证据 |
|---|---|---|
| 解封 | 在游戏魔法封印 UI 对空词条的 `101010339` 解封，不选卷轴 | 抓 C2S `0x0191` 的 4B 实帧、第二字段值；装备词条从空变为 PVF 候选，金币减少 1720；抓 S2C `0x000E` 与金币通知。若客户端发不同入口/长度，立即保留样本并停止该路径。 |
| 重复/拒绝 | 对同一件装备再次点解封，或锁定后操作 | 装备 UID/词条、金币不再变化；记录 UI 阻止还是服务端拒绝。`0x0191` 目前未发专用 ACK，需确认 UI 是否接受刷新。 |
| 词条变更 | 对已解封装备选择一个词条变更，不选择额外材料 | 抓 C2S `0x01B6` 5B 实帧与 S2C 同 type 结果，核对 index 和响应体；只选中词条变化，其余词条及强化/附魔不变，金币按该样本减少 3800。若 UI 要求材料或 ACK 解析失败，记录材料 ID/槽、提示与帧，不绕过验证直接扣资产。 |
| 无效词条/余额 | 选超出已有条目的位置（仅隔离回放可控时）或使金币不足后操作 | 不成功、不扣资产；记录实际错误码与提示。不可在正式角色注入非法包。 |
| 第二字段/卷轴门 | 观察 UI 选择/不选择卷轴时 `0x0191` 第二字段变化 | 非 `0xFFFF` 时本版安全拒绝、装备/卷轴/金币均不变；保留差分帧作为未来确认卷轴槽与等级限制的依据。 |
| 重登 | 游戏内正常退出再登录同一角色 | 词条、装备 UID、金币与最后一次成功提交一致；保留重登前后槽位/数据库快照。 |
| 相邻入口 | 观察 UI 是否另发 `0x0197` 或 `0x01C8` | 只记录动作与帧，不把这些入口误认为当前解封/变更成功；本服尚未接入。 |

## 自动与人工边界

自动测试已覆盖真实 PVF `101010339` 和卷轴 `2600460` 的只读解析、SQLite 装备/金币事务及失败回滚、同序列重放、请求字节与提交后投递；**本版不消费卷轴**。A21 响应 handler 静态检查支持 `0x01B6` 最小成功状态及单字节错误原因，但错误码显示与上述 GUI **尚未验证**；`0x0191` 的第二槽含义也仍待样本确认。出现差异时按抓包修订，不升级 `ClientVerified`。
