# TaskContract：装备锻造

## Context

### Source Request

用户授权在 `task/solo-play-roadmap` 分支按一个内聚功能一个 Spec 完成五项装备改造，要求参考 70、上游、A21 客户端和 PVF，探查、设计、实现、快速验证并逐项本地提交；附魔师路径排除。本子项只贡献根任务 SC-5。

### Current Situation

接受基线 `c15e6add` 已完成强化、宝珠附魔、魔法封印和异次元属性的自动交付。装备实例、金币/材料事务与客户端物品刷新可复用；锻造的 A21 入口、PVF 规则、独立装备字段和失败响应仍需核定。

## Goal

使角色拥有的合格装备能够经 A21 支持的锻造入口，按真实 PVF 的目标、材料与概率规则结算，保持它与普通强化独立，结果原子持久且对客户端可见。

## Scope

### In

- 核对 70、上游、A21 静态构包/接收和真实 PVF，分离参考事实、客户端静态与未闭合边界。
- 实现证据闭合的锻造路径：所有权、状态、槽位、材料、费用及上限校验；成功/失败、重试和持久化失败的资产一致性。
- 接入客户端可识别的请求/响应与权威装备、材料及金币刷新；补自动测试和集中实机 Human Test List。

### Out

- 附魔师、未证实的其它锻造入口、推送/合并/部署；未执行的 `ClientVerified` 声明。

## Constraints

- 锻造与普通强化字段、费用及准入不得混同。以 A21/PVF 为本服协议与内容边界；70/上游仅作参照。
- 不得猜测性扣除玩家资产；装备身份、消耗与结果必须同事务处理，失败、重放和提交失败不出现部分结算。

## Success Conditions

| ID | Observable condition | Required evidence |
|---|---|---|
| SC-1 | 锻造入口、装备状态、PVF 材料/金币/概率与响应字段可追溯，歧义单列。 | 70/上游/A21/PVF 对照及 `protocol/` 人工记录。 |
| SC-2 | 合格装备可锻造，成功/失败按规则改变结果并消耗资产；无权、错槽、材料不足及错误状态不改资产。 | 确定性领域/真实 PVF/事务回滚与重读测试。 |
| SC-3 | 客户端得到相符结果及权威装备、材料、金币状态；普通强化与锻造保持独立。 | 字节/handler/线级测试、相互独立的字段断言。 |
| SC-4 | 用户可按固定样本集中验证成功、失败、拒绝与重登。 | Markdown Human Test List，分清自动与未实机。 |

## Authorization

| Capability | Evidence | Authorized scope |
|---|---|---|
| task | 根契约记录五项逐项实现；用户补充“继续完成全部功能……快速开发，快速验证……提交后继续工作。这次不包括附魔师相关功能。” | 当前分支内锻造探查、设计、实现、验证和一项接受提交；不含外部发布。 |

## Assumptions

- 本轮自动交付与后续用户集中 A21 实机验收分开，不能由静态证据宣称 GUI 已验证。
