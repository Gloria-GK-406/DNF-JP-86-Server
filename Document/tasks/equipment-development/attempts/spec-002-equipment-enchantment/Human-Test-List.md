# 装备宝珠附魔 Human Test List

状态：**待用户 A21 GUI 验收**。下面是可重复步骤与观察点，不是已经通过的客户端事实。服务端静态/自动测试不能替代实机抓帧。

## 准备

- 确认运行的是此分支构建产物；用独立测试角色和可备份的数据库。不要对珍贵装备做首次试验。
- A21 PVF 样本：宝珠 `2600294`（`bead_Sieghart`，对应卡 `3600`）、可穿戴武器 `101010437`。先确认角色能够取得并装备两者；若实际上不可获得，记录可见的武器/宝珠 ID、脚本路径和操作停点，不要把脚本存在说成 UI 可达。
- 启用既有 `clienthack-frame-capture.log`（双向）和服务端 `ENCHANT_BY_BEAD` 日志，保留角色、装备/宝珠槽、时间、会话及数据库备份。`0x0110` 是 CMD；装备列表是 `3`，宝珠背包列表是 `0`。

## 操作与预期

| 检查 | 客户端动作 | 预期与留证 |
|---|---|---|
| 首次附魔 | 穿戴武器，背包放两颗相同宝珠；在游戏附魔界面使用一颗 | 抓 C2S `0x0110` 六字节候选与 S2C `0x0110`，附 `0x000E` 目标/宝珠槽更新；装备显示卡片属性，宝珠减一；服务端日志的卡 ID 是 `3600`。若客户端发的是另一入口，停止并记录帧。 |
| 覆盖 | 对同一武器再用一颗宝珠 | 原 UID 不变，卡 ID 保持/覆盖为 `3600`，宝珠再减一；原强化等级、异次元及封印字段不被重置。记录是否出现确认对话框及其帧。 |
| 不适用部位 | 将此宝珠施加于非武器部位（如 `[coat]`） | 拒绝或客户端阻止发送，宝珠与装备均不变；区分 UI 禁止与服务端错误 ACK。 |
| 锁定/不足 | 锁定装备或用尽宝珠后再操作 | 不出现成功 ACK，装备/库存资产不变；抓错误码及客户端提示。 |
| 宠物目标隔离 | 若 UI 允许对宠物目标使用同一宝珠，尝试一次 | `list=7` 不进入装备领域；当前版本应错误返回且不扣宝珠。记录宠物分支是否由另一功能处理，不能以装备 ACK 伪装成功。 |
| 重登 | 正常退出、重登选相同角色并查看装备 | 附魔卡 ID 与背包余量与成功 ACK 后一致，强化等级未受影响。 |
| 同序列重放 | 仅在隔离测试/回放工具可控时重送完全相同请求 | 缓存的近期重放不再扣珠，按当前两个槽状态重发刷新与 ACK；旧序列超过缓存窗口后拒绝。连接计数完整回绕后的合法新请求可前进。不要在生产角色上做报文注入。 |

## 判定边界

目前已通过真实 A21 PVF 解析、SQLite 原子结算及编解码/handler 自动测试；**没有** `0x0110` 实帧或 GUI 验收。错误 `0x11/0x13/0x17` 的本服映射有上游与客户端静态分支线索，具体提示和交互仍待验。A21 静态构包确认六个写入字节，但若实帧多于六字节，先保留抓包、修订协议证据和 decoder，不能伪称本版兼容。服务端在网络入口观察**所有** Game 帧的 16 位计数（含未注册 opcode）；长间隔不再按两个附魔请求之差判断。当前同序列重发只在 128 个入站帧内补投，超出会拒绝旧包；恰好完整回绕后字节完全相同的旧包与新操作在线缆上无法区分，属于仍需通过会话/入口约束防护的残余风险。若客户端帧计数并非连续递增，当前附魔会安全拒绝，须以真实抓包修订。附魔师摊位 `0x025A` 是另一入口，用户已明确排除本轮范围，不由本清单的宝珠成功代替。
