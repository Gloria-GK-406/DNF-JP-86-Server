# TaskContract：装备附魔

## Context

### Source Request

根任务授权在宠物所在分支逐项完成普通强化、附魔、魔法封印、异次元属性和锻造；每项依 70 服务端、上游、A21 客户端与 PVF 探查，设计后实现。本子项承担装备附魔，不把宠物附魔默认为同一资产流程。
2026-09-30 用户明确本轮不包括附魔师相关功能，并要求提交后继续。此处的装备附魔验收仅覆盖宝珠入口 `0x0110`；`0x025A` 摊位卡片附魔另行处理。

### Current Situation

已接受基线 `e1d4c216` 具备装备实例 `EnchantCardId`、容器、事务和库存投影。上游存在 `ENCHANT_BY_BEAD` `0x0110` 与宠物目标分支；A21 客户端对应请求/成功响应及真实 PVF 的目标/材料规则尚待本子项核对。普通强化结果已封存，不重开其 Spec。

## Goal

让 A21 客户端支持的装备附魔入口可以对角色拥有的合法装备结算指定附魔材料，保留装备实例身份，正确覆盖或拒绝既有附魔，在重登后保持结果，且给客户端可解释的响应和状态刷新。

## Scope

### In

- 对照 70 ELF、上游、A21 客户端静态/实帧及真实 PVF，确定装备附魔入口、材料（卡片/宝珠等实际支持类型）、目标部位、覆盖/失败及客户端投递语义；明确证据等级与未知。
- 实现由服务端权威校验目标、附魔源、角色归属和内容适配的装备属性更新与材料消耗；拒绝、提交失败与重试不得部分结算或复制，既有装备无关属性及 UID 保持。
- 接入证据支持的 A21 请求、响应和装备/材料刷新，针对宠物目标要么以现有宠物系统的独立流程接通并验证，要么显式隔离/拒绝，不能把宠物写进装备槽。
- 提供针对性自动测试、真实 PVF 样本和装备附魔 Human Test List，保留用户后续实机验收状态。

### Out

- 魔法封印随机词条、异次元增幅及锻造的规则；由根任务其他 SC 负责。
- 无直接客户端证据的附魔师摆摊/制作经济全链条，不因上游有实现而推定为本客户端必需入口。
- 用户明确排除的附魔师摊位卡片附魔 `0x025A` 及其摊主、配方和跨玩家结算。
- 推送、合并、部署、玩家数据库改写与未经执行的 `ClientVerified` 声明。

## Constraints

- 复用已接受装备实例与事务边界；70 与上游仅作参考，A21 客户端/PVF 决定线协议及内容事实。
- 保护宠物现有流程，记录当前真实 PVF 下两项 `CreatureGoesBackOnTests` 的既存失败，不把它们误认本子项回归或掩盖新回归。
- 对无法从 A21 证据安全裁定的覆盖、宠物目标或材料类型，先停在证据门，不执行猜测性的资产扣除。

## Success Conditions

| ID | Observable condition | Required evidence |
|---|---|---|
| SC-1 | 70/上游/A21/PVF 的附魔入口、请求/回包、材料与目标规则、覆盖语义可追溯，未知显式标出。 | 有证据等级和地址/路径的对照及设计文档，必要的 `protocol/` 记录。 |
| SC-2 | 装备附魔成功或拒绝时，装备原 UID 和无关属性、材料数量与角色资产保持原子一致，重登后可见。 | 确定性领域/SQLite 测试覆盖合法目标、错部位/非本角色、覆盖、材料不足、重复及提交失败。 |
| SC-3 | A21 可用入口得到客户端可解释的结果和物品状态；宠物目标不会错误走装备结算。 | 字节/handler 集成测试、客户端静态或抓帧证据、宠物路径隔离测试。 |
| SC-4 | 用户有固定样本可执行装备附魔及重登验收。 | Markdown Human Test List，记录准备、操作、预期、日志/抓帧定位和未实测项。 |

## Assumptions

- 先调查上游 `0x0110 ENCHANT_BY_BEAD` 是否为 A21 的实际装备附魔入口；若不是，以 A21 证据修正路径，不照搬上游命名。
- 用户实机验收在自动交付之后，验收前不得将静态解释升级为 `ClientVerified`。
