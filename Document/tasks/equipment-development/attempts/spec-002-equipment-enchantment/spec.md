# Specification：装备附魔

## Outcome and Evidence Boundary

玩家经 A21 实际装备附魔入口，把合法宝珠/附魔材料应用到自己拥有的装备，看到与服务端结算一致的结果；消耗与装备属性在重登后保持。宠物目标必须明确隔离或使用独立验证过的路径，不能因共享 `0x0110` 而复用装备写入。70 和上游只提供规则线索；`protocol/game/client-to-server/0x0110.md` 目前只有 A21 ClientStatic 请求字段下界，尚无实帧和可直接借用的成功响应事实。

## Requirements

| ID | Requirement |
|---|---|
| RQ-001 | 建立 70 ELF、上游、A21 客户端构包/接收及 A21 PVF 的对照，确定装备附魔材料/目标适配、列表类型、覆盖和失败条件；所有未闭合字段/语义标 Unknown。 |
| RQ-002 | 仅接受当前选中角色有权操作的可附魔装备、有效材料和允许部位；客户端槽位/模板/属性值不得代替服务端事实，宠物或非装备目标不能进入装备结算。 |
| RQ-003 | 成功附魔和覆盖依 A21 内容事实更新装备的实际附魔字段，保留原装备 UID 与其他实例属性；材料、金币（若有）和装备变更在一个事务中提交，拒绝、重试与提交失败不造成部分结算。 |
| RQ-004 | 已提交结果由 A21 客户端能读取的 ACK/必要物品刷新投递，错误不伪装成功；重登从持久化得到同一属性。 |
| RQ-005 | 提供可执行 Human Test List，涵盖合法附魔、覆盖/拒绝、宠物目标隔离和重登，记录抓帧与日志点，标明未实机确认。 |

## Acceptance Criteria

| ID | Covers | Criterion |
|---|---|---|
| AC-001 | RQ-001 | 对照可追到 70 符号/地址、上游路径、A21 客户端 RVA 和 PVF 条目；请求与响应的宽度/分支证据与业务语义分级，绝不把上游行为称为 ClientVerified。 |
| AC-002 | RQ-002 | 非本角色、错误列表/槽位、错模板、不可附魔部位、错误材料、被锁/不存在装备和宠物目标走明确拒绝或经独立验证的宠物路径，资产不变。 |
| AC-003 | RQ-003 | 给定真实 PVF 样本与确定输入，合法附魔和已附魔覆盖更新正确字段；数据库重读后 UID 及无关字段不变、消耗守恒；模拟提交失败和重复请求无半成品或双扣。 |
| AC-004 | RQ-004 | 字节级测试覆盖 A21 成功/错误回包及必要物品通知，提交后才发成功投影；重登后的装备属性等于 ACK 所示结算。 |
| AC-005 | RQ-005 | Human Test List 可按固定材料与装备完成附魔、覆盖/拒绝、宠物目标隔离、重登及日志/抓帧定位；未做的实机步骤保持待验收。 |

## Success Evidence

- `Document/tasks/equipment-development/attempts/spec-002-equipment-enchantment/` 的证据、设计、测试和 Human Test List；`protocol/` 记录只在人工区补证据。
- 真实 A21 PVF 解析测试、领域/SQLite 守恒与回滚测试、协议字节及 handler 投递测试。
- 完整变更独立审查和针对本合同的最终验证；既存宠物测试失败与本项新回归分开记录。

## Stop Boundaries

若 A21 不能证实影响资产或覆盖语义的关键条件，不得用 70/上游推断直接扣材料或改装备；先记录可复核的静态/实帧停点。`0x0110` 可能共用宠物目标，未验证前装备 handler 不得自行写宠物。用户 GUI 验收留在交付之后，不作为自动测试的假阳性。
