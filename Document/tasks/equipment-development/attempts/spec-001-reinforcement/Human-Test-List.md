# 普通强化 A21 人工验收清单（待用户执行）

本清单不是已完成验收记录。当前证据只有 ClientStatic、A21 PVF、70/上游对照和本服自动测试；强化 UI、真实 `0x0050` 帧、提示文案及公告均未标记 ClientVerified。建议用专门测试角色与可损失装备，先备份角色数据库，再按下列编号操作。不要用主力高强化装备做破坏/保护实验。

当前服务、现有装备和资产基线已整理到[2026-09-30验收准备](verification/acceptance-20260930.md)。先执行其中R-01、R-02，用户结果回填前保持待验。

## 准备

- 运行同 SHA-256 为 `F1FD58E6...D41` 的 A21 `Script.pvf` 对应服务端配置，记录服务端 commit、客户端版本、角色 ID 和测试时刻。若 `PVF_ARCHIVE_PATH` 与运行 Host 的内容源不同，先停止验收。
- 准备本角色一件可强化、满耐久、未封印、未锁定、无异次元/增幅属性的装备；记录物品模板 ID、背包绝对槽位、实例强化等级及其他随机属性。A21 PVF 的 `101010437` 可用作内容源解析样本（最低等级 3、最大耐久 45），但是否适合测试角色要由游戏内可见装备条件确认。
- 准备 `3037` 无色小晶块与足够金币。账号虚拟计数在主背包槽 358；若客户端实际传物理材料槽，也记录原槽位。保护分支另备游戏内有效的普通/超级保护券；PVF 可识别的脚本样例是 `7804` 和 `10007840`，它们带历史到期声明，不应只因脚本存在就认定当前角色可使用。
- 开启本次会话的 C2S/S2C 帧抓取和服务端结构化日志。检索 `UPGRADE_ITEM character=... seq=... slot=... old=... new=... outcome=...`，保存每项测试的请求/响应 hex、物品/金币前后值；不要把服务端自发消息当作真实客户端验收。

## 操作与预期

| ID | 操作 | 预期与检查点 |
|---|---|---|
| R-01 | 把同一件 +0 装备放在主背包装备槽，打开 NPC 普通强化 UI，执行一次。 | 客户端发 CMD `0x0050` mode `0`；服务端日志有一条提交记录；客户端显示 +1，材料按 PVF 行扣减、金币下降，其他实例属性不变。首行 PVF 失败阈值为 0，应可稳定命中成功。记录 ACK 与随后物品/金币通知的次序。 |
| R-02 | 正常退出并重登同一角色，重新查看 R-01 的装备、账户晶块与金币。 | +1 等级和资产余额与 R-01 提交后一致，无二次扣除；保存重登背包快照。 |
| R-03 | 用可损失的另一件装备到 +4，再尝试 +5；必要时重复正常请求以取得一次失败。 | PVF 第 5 行有失败阈值 `10000/100000`、处罚类型 2、降级值 1。实际失败时应显示与 ACK `resultCode=2` 一致的降级，且一次尝试只扣一次材料/金币。不要把单次随机结果当作概率证明。 |
| R-04 | 用可损失的 +11 装备和在游戏内有效的超级保护券尝试一次，且记录券槽。 | 失败时若服务端识别并选中保护券，装备不销毁、等级回到 +10，保护券减 1；成功时券不应减少。若 UI 不允许或客户端传入的可选槽与实现不符，保存实帧并停测，不要推断保护券已生效。 |
| R-05 | 仅用可损失的 +11 装备，在没有保护券的条件下尝试破坏分支；执行前确认背包可容纳分解产物。 | 如命中破坏，ACK `resultCode=3` 含 `rewardCount`，装备移除、按 PVF 产物入包、材料金币扣一次；背包不足则失败且全部资产不变。该场景风险最高，允许用户跳过并保留待验收状态。 |
| R-06 | 材料不足或金币不足时各尝试一次；另用锁定/损坏装备验证拒绝。 | 客户端收到二字节错误信封并给出提示；装备、材料、金币均不变。记录 reason、UI 文案与日志，不把静态 reason 候选解释成已验证文案。 |
| R-07 | 若抓包/代理允许，重复发送完全相同连接、相同序列的 `0x0050` 请求（只在测试环境）。 | 第二次不应再次扣资产；新序列的新请求仍能正常进行。序列回绕/断线重连的行为另记录，不用此项冒充完整抗重放证明。 |

## 发现差异时

记录测试 ID、角色与装备模板/实例、前后资产、原始帧、服务端日志和客户端可见变化。重点区分：`ClientStatic` 字段宽度错误、PVF/70/上游规则差异、通知顺序错误、UI 文案映射错误。若 ACK 与实际资产不一致，立即停测并保留数据库与日志，不继续对同一装备强化；先修服务器再复验。用户验收结果应写入新的记录，不能直接把本清单改成已通过。
