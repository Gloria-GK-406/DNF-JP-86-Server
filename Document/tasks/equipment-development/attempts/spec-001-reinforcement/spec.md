# Specification：装备普通强化

## Why and Outcome

玩家应能使用 A21 客户端的普通强化入口改造一件已有装备，看到与实际结算一致的成功或失败结果，并在重登后保持该结果。装备、金币、材料和保护道具由服务端裁决，不能因报文伪造、重复请求或保存失败出现部分结算。

## Scope and Evidence Boundary

本项覆盖普通强化及其适用的保护与惩罚分支。`0x0050` 若有增幅或高级强化模式，这些模式应准确识别并按未支持路径处理；增幅由根任务 SC-4 完成，`0x01B7` 锻造由 SC-5 完成。

当前可定位的证据：70 ELF 的 `Dispatcher_UpgradeItem::dispatch_sig` (`0x082006D0`) 与 `WongWork::CItemUpgrade` 校验、升级和惩罚方法；上游的 `ItemUpgradeRequest`、`InventoryItemUpgradeService` 与 ACK/通知构造器；A21 `protocol/game/client-to-server/0x0050.md` 的构包记录；A21 PVF `etc/upgrade.etc`。70 端反汇编和上游只作规则参考，A21 客户端和所用 PVF 才能约束本服线协议与内容规则。当前并无实机强化帧，因此本 Spec 不预设 `ClientVerified`。

## Requirements

| ID | Requirement |
|---|---|
| RQ-001 | 形成 70、上游、A21 客户端及 PVF 的可追溯对照，明确普通强化的请求、结果、准入、费用、成功率、惩罚与保护规则；将未闭合的推断标为未知。 |
| RQ-002 | 仅在真实选中角色拥有且位于允许位置的装备上接受普通强化；方法、目标模板/槽位、材料/保护道具、等级、锁定、耐久与足额金币均按已证实规则校验。客户端提供的名称、ID 与结果不得代替服务端事实。 |
| RQ-003 | 强化规则依 A21 PVF 及已确认的客户端语义计算费用、概率与结果；成功提升、失败保留/降级/破坏及保护作用按适用分支转换装备状态，不把增幅或锻造混入普通强化。 |
| RQ-004 | 一次请求的装备变更、金币/材料/道具消耗和可能的破坏产物形成原子结算；拒绝、重复请求或提交失败不造成部分写入、丢失或复制，并保留原装备实例身份及其无关属性。 |
| RQ-005 | 提交后向请求者发送 A21 客户端能够读取的结果和物品/金币状态更新；失败不发送虚假的成功投影，重登后的状态与提交结果一致。 |
| RQ-006 | 交付可直接执行的 Human Test List，注明准备样本、操作、预期、重登检查、日志定位与尚未实机确认的边界。 |

## Acceptance Criteria

| ID | Covers | Criterion |
|---|---|---|
| AC-001 | RQ-001 | 对照记录能从具体 70 符号/指令、上游位置、A21 客户端地址或协议记录及 PVF 路径复核；冲突与未知显式列出，没有把参考端输出称为客户端事实。 |
| AC-002 | RQ-002 | 给定非本角色物品、错模板/槽位、错误模式、错误或不足材料、锁定/损坏/不可强化装备、余额不足等请求，执行结果为拒绝，装备与资产保持原状。 |
| AC-003 | RQ-003 | 给定可控规则和随机输入，成功、普通失败、降级、破坏、保护生效等被证据支持的分支产生确定的目标状态与消耗；未支持模式不得获得普通强化结果。 |
| AC-004 | RQ-004 | 对已提交请求，数据库重读后装备身份和无关属性不变，金币/材料/道具与产物守恒；在模拟提交失败及重复提交时无半成品状态或重复奖励。 |
| AC-005 | RQ-005 | 请求的 A21 回包与必要状态更新可由客户端静态读取路径或实帧证据解释，编码测试覆盖成功及错误；登录重载得到同一强化状态。 |
| AC-006 | RQ-006 | Human Test List 能让用户以固定角色与装备完成至少成功、失败/保护、重登三个场景，并能按测试编号定位服务端日志和资产差异；未执行的实机测试标为待验收。 |

## Success Evidence

- EV-001（AC-001）：`Document/` 下的本项取证与设计记录，以及更新的 `protocol/` 记录；每一主张标明 70Reference、UpstreamReference、ClientStatic、WireCaptured、CurrentImplementation 或 Unknown。
- EV-002（AC-002—AC-005）：领域、协议、持久化与真实 PVF 的针对性测试及服务端构建结果；资产测试应检查提交前后而非只看返回码。
- EV-003（AC-006）：Markdown Human Test List 与可复用的样本/日志定位说明。用户之后的实机验收独立记录，不用自动测试替代。
