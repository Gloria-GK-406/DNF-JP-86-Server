# 选角每日副本信息

普通角色悬停提示查询实际进度，涵盖暗精灵遗迹、镜像阿拉德、绝望之塔和异界地下城。地狱模式不在本次实现范围。
协议布局、客户端显示条件、尾部字段与PVF边界唯一维护在 [02C1](../../../protocol/game/client-to-server/0x02C1.md)
和 [NOTI0002](../../../protocol/game/server-to-client/NOTI-0x0002.md#a21-roster-36字节尾部读序)。

## 实现边界

- 分支 `fix/roster-daily-info`，基于主干 `fe6c55321045f7099f14821759ac1ee625b8b43f`。
- CMD负责认证账号和列表索引校验、查询编排与回包；codec负责完整A21编码及普通绝望显示公式换算。
- 复用已有配额快照领域服务和暗精灵领域服务；不新增持久计数、不改变实际扣次和日切规则。
- 查询是只读路径，无选中角色亦可使用。索引按账号列表顺序解释，不把有空洞的槽位编号当列表位置。
- 本次不改PVF、客户端补丁、版本号或运行库；不启动／替换当前服务。

## 证据边界

- ClientStatic：A21响应与悬停绘制链闭合，详见协议页的镜像哈希、函数地址和配置路径。
- UpstreamReference：ServerS4A21仅登记CONTENTS_PLAY_INFO编号，未提供可复用的handler；角色尾部常量不能证明次数含义。
- 70Reference：本任务修复A21选角投影；沿用现有四个玩法的规则与存储，70版本不作为A21布局或显示规则依据。
- CurrentImplementation：完整响应及权威数据读取已接入；ClientVerified待用户测试。当前线上／运行服务不会因工作区编译而自动更新。

## 自动检查

- 包级回归：旧实现19字节在27字节断言上失败；修复后验证六整数顺序、非零索引、普通绝望机会／层数及拒绝信封。
- 真实SQLite与完整decoder→CMD→encoder流程：槽位有空洞、多角色差异、无已选角色、跨账号隔离、次数耗尽、跨日刷新、重复查询不扣次。
- 既有轻量协议流程覆盖无认证拒绝、发送和故障生命周期；架构注入检查通过。
- 构建及最终测试结果见交付说明；本文件不将自动测试升级为实机结论。

## 用户实机验收顺序（待执行）

1. 部署前确认当前实际服务、数据库和PVF，按工作区规范取得一致备份；协调切换时间后再启动候选服务。
2. 用有两个普通角色的现有账号进入选角，优先选择两名70级以上且副本进度不同的角色。依次悬停，确认次数随目标角色变化。
3. 普通角色应按等级显示暗精灵（40）、镜像（55）、绝望和异界（70）；异界另有职业排除。次数耗尽仍显示、变红。
4. 进入角色消耗一次副本机会，返回选角再次悬停；核对该玩法次数变化和另一角色保持原状态。暗精灵与镜像按入场、绝望按普通免费机会规则核对。
5. 检查绝望当前层数与实际可进入层一致；异界普通次数用尽后切换为额外次数提示。
6. 正常退出、重登后重查；有条件时跨每日重置边界验证恢复。未执行的玩法、跨日或额外票情形单独记录。
