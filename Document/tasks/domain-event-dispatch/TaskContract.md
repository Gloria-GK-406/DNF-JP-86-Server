# TaskContract：统一事件服务与通知职责迁移

## Context

### Source Request

“看起来ok了，起任务契约，实现全面重构。理论上重构后不再需要组件直接调用INotiBus。所有的职责由新的Event服务来承载。所以在重构结束后需要派遣子代理仔细检查是否有遗漏的地方。重点在写spec时候点明重构前后的结构性和职责变化。”

### Current Situation

已讨论并接受强类型 payload、统一信封、按类型订阅、提交后分发、持久化待处理记录与 Channel 唤醒；通知允许离线跳过，可靠订阅处理不能因离线遗漏。基线 ef00741dc3d4ee826c14b3d273042f38c3a1c31f 已移除旧的马战专用事件转发总线。现有业务、维护服务、HTTP 与协议处理器仍直接调用 INotificationBus；部分通知负载包含 CMD 回复、连接身份和严格顺序的协议投影，不能全部当作可重放业务事实。

## Goal

建立统一事件服务作为发布和订阅入口；业务事实提交后可恢复地分发给独立订阅者，通知只作为事件的一个消费者。移除生产业务组件直接依赖、调用 INotificationBus 的路径，同时保持既有协议回复、在线判断、精确会话校验、通知合并和马战公告语义。

## Scope

### In

- 事件契约、类型/订阅注册、持久化投递、后台异步消费与宿主生命周期。
- 邮件事实接入及现有全部 INotificationBus 发布点的分类迁移；即时协议投影保留等待完成的语义。
- 通知订阅适配与通知投递边界；重构前后结构/职责、迁移清单、自动验证和独立子代理检查。
- 验证不同 payload、多订阅者、重复处理、离线、回滚、重启恢复、失败隔离和停服行为。

### Out

- 称号/成就业务规则与客户端 UI 的完整实现；本轮提供可靠订阅能力及验证消费者。
- 修改客户端/PVF、协议线级格式、部署、操作运行数据库、版本发布、PR/合并、清理其它工作区。

## Constraints

- Application 不引用 Persistence、Infrastructure 或 Protocol；事件 payload 不持有连接、服务或可变聚合。
- 业务写入与对应可靠事件一致提交，回滚不可触发订阅；查询不可推进业务或发布新的业务事实。
- 通知投递仍是 best effort；不会重放过期公告或给新会话投递旧会话的回复。
- 保留原工作树 task/abyss-research 的未提交调查文档及 0x0010 协议改动。
