# TaskContract：骑士马战大竞猜

## Context

### Source Request

用户接受：活动起止日期放通用配置，每天开始时间、每天期数和每期时长放马战专属配置并持久化；PVF 提供骑士、下注材料和奖励内容。授权原文：「这是对的。写个任务契约开始这个功能构建吧。另一个agent修复了一个经验问题，所以代码和刚才会有一些差别。」重启后续令：「继续任务，刚才crash重启了」。

### Current Situation

工作区 `E:/Project/DNF/DNF-JP-86-Server/.worktrees/warehouse-storage`，分支 `task/warehouse-storage`，干净基线 `b4bf8d0d01113c39962c885b44002453dcb740c6` 已含经验/等级实例重构，必须保留。JP86 已有活动管理、周签到和通用物品目录；尚无 JOUST 实现。A21 PVF 有 `chn_joust.evt`、骑士马战 UI 和三种活动物品；协议入口已有静态定位，具体字段仍须闭合。ServerS4A21 的 Joust 是参考实现，不能当作目标客户端已验证行为。

## Goal

实现可配置赛程的骑士马战活动，交付注册、日历、原生竞猜查询/下注/赛果、持久化结算和 Web 专属配置闭环，可供用户真实客户端验收。

## Scope

### In

- 一个活动实例同时承载通用管理和马战玩法接口，复用现有活动列表与日历发布。
- 通用有效期/启停；马战专属的每日赛程编辑和 PVF 内容只读展示，刷新及重启不丢配置。
- 全服轮次、参赛名单、淘汰赛、个人投注、倍率、历史及奖励投递。
- 双币下注、等级与每轮限额、正确扣料与失败一致性；比赛和派奖在重启/重复处理时不重复执行。
- 原生 A21 JOUST 协议切片和进场/在线状态接线；静态及自动证据与实机验收分开。
- 相应领域、SQLite、协议、HTTP、前端验证和简明使用/人工验收说明。

### Out

- 修改 PVF、客户端二进制或客户端资源；其他活动、新窗口、任意脚本执行平台。
- 撤销下注、兑换商店、补做签到、真实战斗模拟或调整既有经验玩法。
- 自动部署正在运行的服务器、操作真实玩家数据、合并/推送/PR 或清理既有工作区。

## Constraints

- 保留新基线经验修复及其他既有功能；若基线继续变化，先核对变更归属，不能覆盖其他 agent 的工作。
- HTTP → 领域服务 → 规则服务 → PVF；UI 只呈现领域数据，通用管理不承载马战专属字段。
- PVF 来源的骑士、材料、奖励等内容先只读；每天赛程属于独立持久化设置，代码默认不能覆盖已保存设置。
- 修改配置不能追溯改变已下注轮次的规则或开奖权益；停用/到期不能丢弃已有投注的结算责任。
- 投注记录、扣料、奖励与结算状态保持失败一致性；不得因重启或同一请求/轮次重复处理而双扣/双发。
- 不将参考实现、静态字段、自动测试提升为 A21 实机证据；使用原生客户端验收单记录剩余边界。
- 本机浏览器验证使用 Chrome；生产写入按阶段串行，独立只读探索可并行。
