# Specification：骑士马战大竞猜

## Why and Outcome

GM 能设置活动期限和每日赛程；玩家在原生活动页查看参赛骑士、下注、观看赛果并收到参与和中奖奖励。重启和活动关闭不损害已有投注权益。

## Scope

遵循 TaskContract 的边界。本次开发可供部署和真实客户端验收，不操作现有运行目录或真实数据库。

## Requirements and Acceptance Criteria

| Requirement | Acceptance | Criterion |
|---|---|---|
| RQ-001 统一管理 | AC-001 / SC-1 | 马战管理和玩法由同一实例提供；启用且在有效期内才进入 EVENT_INFO；通用界面只配置通用信息。 |
| RQ-002 专属配置 | AC-002 / SC-2 | 专属弹窗保存每日开始时间、期数、间隔、下注/封盘/比赛阶段时长；重新加载及重启仍是已保存值；无效时间、跨午夜、阶段超出轮长被拒绝。骑士/币/奖励显示 PVF 名称和 ID，且只读。 |
| RQ-003 原子下注 | AC-003 / SC-3 | 每角色每轮最多 PVF 限额，满足最低等级；下注阶段可追加和分投，使用任一 PVF 材料，优先指定槽位。同一次稳定请求重复提交只扣一次。非下注期、非法骑士/材料、超额、余额不足均不扣料；持久化失败不留半笔交易。 |
| RQ-004 确定轮次 | AC-004 / SC-4 | 每日 UTC+8 绝对时间生成轮次，八骑士淘汰赛 8→4→2→1。结果落盘后永不重抽，跳时/重启补推进；既有轮次保存设置/内容快照，新设置仅作用于尚未生成的轮次。 |
| RQ-005 倍率和派奖 | AC-005 / SC-5 | 倍率为总池/该骑士投注数，取一位小数；无投注倍率 8.0。参与奖数量为个人总下注数，中奖币为向下取整(胜者投注数×最终倍率)。重复推进/重启不会重复邮件；停用/到期禁止新下注，但已生成有投注轮次仍结算。 |
| RQ-006 原生协议 | AC-006 / SC-6 | 原生查询、下注 ACK、历史查询、状态/投注/赛果通知布局有 A21 静态证据并经 codec/handler 测试；角色进入接线可用。未知语义明确记为未知，不借参考实现宣称 ClientVerified。 |
| RQ-007 回归交付 | AC-007 / SC-7 | 领域/SQLite/HTTP/协议/前端检查通过，现有签到、目录、初始化及基线经验功能不回归；独立审查无未处理阻断项，使用说明和实机验收清单齐备。 |

## Definitions and Policies

- 默认每天 10:00 开始，7 期，间隔 120 分钟；下注 90 分钟、封盘 10 分钟、3 个比赛阶段各 200 秒，剩余时间展示结果。此为服务器默认，可编辑，非 PVF 强制设定。
- 状态以保存的轮次时间为准，区间起点包含、终点不包含；所有 API 的时间均由服务器提供。
- 参赛名单选七位普通骑士与一位特殊骑士再随机排序；对局均等随机。PVF 攻击类型/战绩内容仅展示，不推断为胜率公式。
- 使用宽整数/decimal 计算奖池和倍率，显式限制协议可表示范围；不允许溢出截断导致扣错或发错。
- 老 PVF 的活动币/奖励包含 2016 年到期字段，活动专属授权需明确处理；其他物品原有时效检查保持有效。不能以修改 PVF 或全局忽略过期来解决。
- 同请求幂等键必须来自稳定的请求身份，不将内容相同的两笔正常追加投注错误合并。若原生请求无业务 ID，使用会话身份与帧序号，领域显式接收键。
