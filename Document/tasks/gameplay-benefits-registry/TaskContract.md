# 玩法权益归拢任务契约

## 背景

当前服务器分别在经验聚合、任务交付、全局掉落倍率和副本掉落中读取加成来源。强化已有独立的概率判定入口。用户确认将这些玩法接入中性的权益登记和查询组件。

## 目标

各玩法模块可以按来源、作用范围声明完整的权益状态。结算取得可归因的权益列表，由经验、掉落、强化各自决定计算方式。

## 范围

- 通用权益协议与组件支持发布、完整替换、明确无权益、有效时间、可选来源和有序快照。
- 归拢经验、装备与道具掉落、普通装备强化成功率三个结算领域内本次盘点发现的适用玩法加成。
- 保留幸运角色本人及队友经验口径、疲劳燃烧、队伍共享神器额外投掷和无个人归属的领取方式。保留既有经验展示、概率与结算行为。
- 支持有有效期的角色强化成功率权益。已存在且可确认规则的数据源一并接入。新增道具、活动数值和客户端协议由独立需求决定。
- 完成后复扫实际结算和来源，记录已迁移项、仍独立的基础规则和任何剩余绕行。

| ID | 来源与意图 | 状态 | 位置 | 理由 |
|---|---|---|---|---|
| RI-1 | 用户要求中性组件，来源、权益名、时效和替换声明，允许缺席 | in_scope | SC-1 | 同一组件可接收独立类型权益 |
| RI-2 | 用户要求经验结算消费所收集的权益 | in_scope | SC-2 | 经验入口使用同一权益来源 |
| RI-3 | 用户要求幸运角色神器掉落也可登记，队伍共享、任意队友可拾取 | in_scope | SC-3 | 保留现行额外投掷和归属 |
| RI-4 | 用户要求登记指定时间内的强化成功率加成 | in_scope | SC-4 | 强化入口实际消费时效权益 |
| RI-5 | 用户批准写契约、重构和结束后复扫 | in_scope | SC-5 | 交付可定位的入口与例外证据 |
| RI-6 | 本次为服务端归拢，既有 A21 口径和效果随重构保留 | in_scope | SC-2 至 SC-4 | 客户端补丁发布与部署不构成本次交付 |

## 约束

- 尊重服务端现有架构与状态所有权，保留已有生命周期和事务承诺。
- 以幸运角色功能分支当前实现作为行为兼容基线。共享神器已实现为额外期望 1.5 次投掷，基础掉落独立保留。
- 延用当前客户端协议。验证使用隔离的测试数据。

## 成功条件

| ID | 可观察结果 | 验证证据 |
|---|---|---|
| SC-1 | 经验、掉落、强化均可通过同一机制登记并查询。一次新声明替换对应来源与范围的整批权益，空声明清除旧权益，未登记来源可缺席，过期权益不参与结算 | 组件测试覆盖替换、缺失、空、时效、跨来源与稳定顺序，并确认业务类型各自由领域消费 |
| SC-2 | 经验结算按既有范围、计算顺序和取整使用所登记权益，任务、副本、适用的塔入口及恢复口径保留 | 主路径测试与基线对照，包含幸运本人、队友、任务、疲劳及现有经验来源 |
| SC-3 | 全局掉落倍率与幸运共享收益从权益读取。存在多个幸运队员时共享加成仍按队伍结算一次，额外装备符合既有品级、随机及拾取归属约定 | 掉落入口及随机确定性回归，覆盖额外掉落归属 |
| SC-4 | 有效角色权益改变普通强化的成功率，失效时恢复原概率。现有券、消耗、保护和失败路径继续成立 | 实际强化入口回归覆盖有效、过期以及券或独立规则 |
| SC-5 | 从来源到消费入口复扫并核对覆盖，任何未迁移的玩法加成都有具体定位和范围说明 | 交付复扫记录和验证结果 |
