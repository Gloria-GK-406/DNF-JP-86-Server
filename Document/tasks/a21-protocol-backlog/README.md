# A21 Game 协议分类与功能任务

分析以服务端主线 2d4d5b179c49f3de6204b537ddfd2dd709b94d10 和 A21 静态身份表为固定输入。调查期间的主线变更另行对账，当前对照到 91a5bbefb259881527fe2e319422fc0eeb5e9ad1。

每条身份由方向、CMD／NOTI 族和编号组成。初筛候选共 1,437 条，包括 C→S CMD 440、S→C CMD 413 和 S→C NOTI 584。分批表保留原始候选编号，使找到替代协议、发现已有注册和确认退役的条目也可回查。 [静态身份表](../../../protocol/patterns/data/protocol-identity.tsv) · [协议证据规范](../../../protocol/evidence.md)

## 主线对账修正

- 在原基线中，攻坚的 S→C CMD 0x0294、0x0295、0x029B 和 0x029D 都由 AntonRaidReply 构造和发出。旧动态映射表只列了同一编码器的其他三种编号。原基线的 413 个缺失响应候选因此至少应减这四条。 [编码器注册](../../../Server/src/Dfo.Server.Protocol/Game/AntonRaid/AntonRaidRegistration.cs#L43) · [攻坚请求应答](../../../Server/src/Dfo.Server.Protocol/Game/AntonRaid/AntonRaidCommand.cs#L129) · [过场与选牌](../../../Server/src/Dfo.Server.Protocol/Game/AntonRaid/AntonRaidRewardCommands.cs#L58)
- 91a5bbefb 新增三个协议身份，分别是幸运角色燃烧开关的请求和响应 CMD 0x0233，以及幸运职业名单 NOTI 0x0406。以同一机读口径对照该提交，新增这三条，没有移除。 [PR #401](https://github.com/Gloria-GK-406/DNF-JP-86-Server/pull/401)
- 源码登记说明服务端的收发入口。固定拒绝、部分子类型、空数据或复用其他通知的入口，按玩家流程阅读。多态帧的具体操作和玩法缺口见 [已接入口的覆盖边界](registered-variants.md)。

## 判读

| 台账结论 | 要求 |
|---|---|
| 待实现 | 有 A21 触发或消费证据，并核对了主线对应行为。功能边界按玩家操作组织，入口或错误分支待验时明确列出 |
| 已接部分 | 已有运行路径和一项尚无覆盖或尚未证实的独立操作 |
| 复用已覆盖 | 有其他现用协议或专用流程完成相应动作。已验证范围照原 evidence 保留 |
| 原基线已接／后续主线已接 | 查实初筛漏映射，或调查期间出现已合入的对应代码 |
| 已退役 | 有 A21 明确空入口、版本替换或现行功能入口撤回证据。空接收只裁定该接收方向 |
| 独立响应待核 | 同号请求已接，需要结合当前原生帧序判断此应答是否独立 |
| 随请求评估 | 该 CMD 应答随同号动作验证，缺少独立主动发送证据 |
| 活动或跨区候选 | 有相应资源、静态特征或参照实现，应先确认启用范围 |
| 运维或诊断 | 登录运维、遥测、安全或内部流程，按实际证据记录 |
| 待取证 | 触发、启用或替代路径的证据不足，每行记录下一次最小核验动作 |

ClientStatic 描述客户端静态构包和消费。WireCaptured 描述实际帧。ClientVerified 仅覆盖已观察的用户操作。CurrentImplementation 描述当前服务端。ServerS4A21 与旧 86JP 作为参照，引用中保留各自来源和版本。
