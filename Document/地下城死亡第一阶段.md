# 地下城死亡第一阶段

2026-09-20，范围：接通死亡上报与生死通知，等待 A21 实机确认。复活扣币、复活应答未知 flag、虚弱和服务器强制超时均不在本阶段。

## 已实现流程

1. CMD 0028 只接受 4/6 字节，保存未知 u16，不从载荷取角色身份。
2. 当前已选角色必须是本次副本入场登记的原会话，且已完成当前房间加载。
3. CMD 通过领域服务在共享副本实例记录死亡；旧 run/room、非成员、未加载和重复上报不产生新变更。
4. 向本人和当前仍在该副本的原会话队员发送 NOTI 0020：`actorId:u16, 0:u8, 0:u8`。不发送 CMD 0028 ACK。
5. 死亡集合随实例结束清理，新副本为空。死亡尚不作为所有其他业务的访问控制，本阶段不声称完整死亡/复活功能。

会话与副本投影锁顺序沿用入场路径。通知为已提交状态的投影；发送失败沿用既有连接错误处理，不将重复死亡当作重新启动 UI 的指令。

## 实机顺序

1. 更新服务端后重新登录，单人进入普通蜘蛛洞穴，死亡后先不操作，观察有无倒计时以及结束后的界面。日志核对 0028 被处理、0020 投递和是否随后出现 002A。
2. 下一轮死亡时按一次复活，记录 0029 请求及目标；本阶段尚无复活应答，不预期复活成功或扣币。
3. 单人结果确认后再测组队：一人死亡而另一人存活，然后全灭，分别记录界面和发包。不得以单人结果代替组队实测。
