# 地下城死亡第一阶段

2026-09-20，范围：接通死亡上报与生死通知，等待 A21 实机确认。复活扣币、复活应答未知 flag、虚弱和服务器强制超时均不在本阶段。

## 已实现流程

1. CMD 0028 只接受 4/6 字节，保存未知 u16，不从载荷取角色身份。
2. 当前已选角色必须是本次副本入场登记的原会话，且已完成当前房间加载。
3. CMD 通过领域服务在共享副本实例记录死亡；旧 run/room、非成员、未加载和重复上报不产生新变更。
4. 向本人和当前仍在该副本的原会话队员发送 NOTI 0020：`actorId:u16, 0:u8, 0:u8`。不发送 CMD 0028 ACK。
5. 死亡集合随实例结束清理，新副本为空。死亡尚不作为所有其他业务的访问控制，本阶段不声称完整死亡/复活功能。

会话与副本投影锁顺序沿用入场路径。通知为已提交状态的投影；发送失败沿用既有连接错误处理，不将重复死亡当作重新启动 UI 的指令。

## 实机顺序

1. 更新服务端后重新登录，单人进入普通蜘蛛洞穴，死亡后先不操作，观察有无倒计时以及结束后的界面。日志核对 0028 被处理、0020 投递和是否随后出现 002A。
2. 下一轮死亡时按一次复活，记录 0029 请求及目标；本阶段尚无复活应答，不预期复活成功或扣币。
3. 单人结果确认后再测组队：一人死亡而另一人存活，然后全灭，分别记录界面和发包。不得以单人结果代替组队实测。

## 2026-09-20 ACK 对照版本

单人实测已有死亡倒计时，但首轮倒计时结束未见自动回城请求。当前版本在接受死亡后，向本人依次发送 CMD 0028 成功 ACK（body `01`）和 NOTI 0020；队员仍只收通知。此前“不发送 ACK”的实现描述已被本次对照版本替代。

专用 handler 为 ret 不等于通用处理无作用：VA 0163BF5E 调 0274D880 减少对应 type 计数，0163BFA3 调 0274DDD0 更新成功/失败计数，再于 0163C078 分发专用 handler。尚未证明这些计数与死亡 UI +54 的因果关系；增加 ACK 是否恢复超时回城，待实机，不引入服务端计时器。


## 2026-09-21 普通副本全灭自动回城

领域服务维护 run 级全灭截止时间；后台每 250ms 观察活动实例，首次观察到全灭后保留 10 秒。重复扫描不重置截止时间，实例退出时删除。到期重新确认全灭、未开放通关且未结算，再原子结束全部活动成员。存在存活成员时清除截止时间；未来接入复活时还需即时取消，不声称已验证复活竞态。

投影沿用实例锁→有序账号锁，验证入场会话代际，提前加载城镇状态。结束后取消翻牌呈现、移除副本投递登记并复用城镇投影；保留队伍，不发未经请求的 002A/007B ACK。单个连接投递失败记录错误，不阻止其他成员；已结束实例的失败投递不自动重试，重连沿用已有恢复流程。

验证：协议测试 997 项、相关领域与架构测试 76 项通过。覆盖最后一人死亡、未到期、到期、重复执行、活人离开后剩余全灭、新实例不受旧截止时间影响。特殊玩法规则、复活扣币和虚弱不在本阶段。

实机：单人普通蜘蛛洞穴死亡后不操作，等待约 10–11 秒回城，确认倒计时消失、能移动、能重新进图。同一轮开启统计上报 Debug 日志。随后再验证倒计时内手动退出并重新进图，以及双人一死/全灭。


### 2026-09-21 单人实机通过

用户确认：普通蜘蛛洞穴死亡后倒计时结束自动回城，倒计时消失后的城镇移动及重新进入副本均正常。本次确认的是单人普通副本回城方案可用，不代表组队、复活或特殊玩法已验证。
