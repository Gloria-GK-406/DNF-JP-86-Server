# 任务进度事件入口

任务进度只有一份持久状态：角色进行中任务的 trigger。业务服务报告已成立的事实，不选择任务或直接修改 trigger；任务服务读取该角色的进行中任务及 PVF 定义，决定哪些通道改变。任务达标（trigger 为零）与交任务、发奖励仍是两个步骤。

## 已接入的事实

| 事实 | 来源与信任边界 | 任务服务处理 | 客户端投影 |
| --- | --- | --- | --- |
| `ClientQuestTriggerReport` | `SET_QUEST_TRIGGER`，客户端声明，需按任务类型和副本上下文校验 | 仅允许客户端计数的目标推进 | 原请求的 `0x0021` CMD 回复；这次变化不再触发 NOTI |
| `QuestEnemyDefeated` | 地下城确认并占用的死亡事实；同一次击杀在事务内交给各受影响角色 | 匹配进行中 `hunt enemy` 的地下城、难度、目标和通道 | 有进度变化时，向该角色发送一次 `0x023F` 活动任务快照 |
| `QuestEnemyDefeated`（含怪物阶级及可选作用域事实） | 同一已确认死亡事实 | 读取统一击杀目标；四字段副本目标及五字段区域目标使用同一模型，区域／推荐等级目标要求明确的上下文 | 与同次击杀的其他任务变化合并为一次 `0x023F` |
| `QuestDungeonCleared` | Boss 房最终 Boss 已由当前 Cell 确认死亡 | 匹配已解析的 subtype6 `condition under clear` 副本和难度；缺少队伍证据，不处理subtype5；不由后到的 `BOSS_DIE_CHECK` 触发 | 与同次击杀的其他任务变化合并为一次 `0x023F` |
| `DungeonMapCleared` | 普通房间首次由未清空变为清空，或死亡／迷妄塔清空当前层；随死亡结算事务持久化入队 | 可靠订阅者按事件内地图 ID 推进 `clear map`；subtype5通关目标使用Boss房和冻结参与者；镜像任务按原运行 ID 更新 | 更新 trigger 并提交后，发布任务变化事件，通知订阅者读取当前任务查询结果发送 `0x023F` |
| `InventoryContentsChanged` | 持久化容器的成员、数量或物品模板改变；与物品写入共用事务入队，携带容器及变化物品 ID | 可靠订阅者只重算与这些物品相关的已接材料任务，从持久化最终持有量推导进度 | trigger 有变化才持久化并发布 `QuestProgressChanged`，沿既有通知订阅者发送 `0x023F` |
| `QuestHoldingsChanged` | 拾取、击杀直发任务物品、接受任务的起始物品、交任务奖励、NPC 购买或丢弃已改变服务端持有量 | 从当前背包和金币重算 `seeking`，不按事件数量累加 | 有进度变化时，向该角色发送一次 `0x023F` 活动任务快照 |
| `QuestCleared` | 交任务的日志写入、奖励与经验在同一事务内成功 | 从已完成任务集合重算仍未完成的 `clear quest` 依赖；奖励引发的持有量变化一并重算 | 完成 CMD 后，若其他任务进度改变，再发一次 `0x023F` |

一次击杀可同时产生死亡事实和任务物品持有量变化；它们在同一事务中报告，最终只投影一份任务快照。NPC 购买成功后也在交易事务内按最终背包重算，拒绝购买不报告。拾取、购买的物品或金币若未改变任务进度，不发送任务快照。任务进度是角色私有投影，不向区域或全队广播；组队击杀逐个计算受影响角色。

丢弃主背包物品成功后也在同一事务内重算 `seeking`；若丢掉最后一件所需物品，剩余量可以从零回升，客户端在丢弃成功回复之后收到修正快照。交付 `seeking` 任务前还会按当前背包再核对一次，防止旧 trigger 为零但物品已不在时错误发奖。放弃任务的 `0x0020` CMD 从进行中任务列表删除任务，成功回复后同步新的进行中任务快照与 NPC 可接任务列表；这不等于交任务，也不发奖励。

接受 `clear quest` 时也会读取已完成集合算实际初值。接受 CMD 仍携带 PVF 声明初值；若两者不同，紧接着发送一次 `0x023F` 校正快照。因此“先完成依赖、后接任务”与“先接任务、后完成依赖”都不会留下永久错误的 trigger。

`0x023F` 是进行中任务的整份快照。因此后来因别的事实发送的快照可能包含曾由 `0x0021` 回复过的值；“不重复”指不为同一次 `SET_QUEST_TRIGGER` 变化再次主动通知，并不要求两种载荷永远不含相同任务。

## 地图清理的异步路径（2026-10-11）

`领域服务确认清房 → EnqueueAsync(DungeonMapCleared) → 可靠任务订阅者 → 持久化 trigger + 入队任务变化事件 → 通知订阅者 → NOTI 0x023F`。

普通地下城在死亡结算提交前，通过运行领域服务的 `WillClearMap` 预判本次保留的死亡是否会首次清空地图；事务准备时再次验证。预判与实际提交共用 Boss 死亡后的清怪规则，保留正在独立结算的敌人和场景对象波次。塔在工作副本的房间状态首次变为 `Cleared` 时入队。业务事务失败时事件一并回滚，不从协议 handler 在提交后补发。

事件冻结运行 ID、副本 ID、难度、Cell、地图 ID、房间版本、清房时间和参与者。消费时不读取玩家的当前位置来决定清的是哪张图。普通任务更新持久化日志，退出副本后仍可消费；镜像任务只查询原运行的临时状态，被移除的状态不重建，也不会作用于下一场。镜像探索房间数同样消费该事件。旧的同步 `QuestRoomCleared` 已移除。

`IQuestMapClearRuleService.TargetMapOf` 统一解释当前支持的单值／双值 `clear map` 声明，以第一项作为目标地图 ID，其他长度不推测。第二项同行 APC 的额外存活／救援语义仍需独立取证；本次保持镜像任务原先的地图匹配语义。觉醒任务 975 的 PVF 单值为 `30030`，与地下城 `11000` 死亡之塔第 30 层地图一致；初值为 1，不是需要清 30 次。实现没有该任务、地图或层数的专用分支。

`IQuestMapClearRuleService.Matches` 同时处理已解析的 subtype5 `condition under clear`：三个整数为副本、难度（-1表示不限定）和最少人数，人数限1–4；消费 `IsBossRoom` 及按CharacterId去重的冻结参与者。原生20728/20731的 `3538/-1/2` 与“两人以上通关”文本相符。目标解析后归服务端负责，客户端 `SET_QUEST_TRIGGER` 保持当前值；裸 `QuestDungeonCleared` 不含队伍证据，不能推进该目标。其他未核定的通关子类型不推测。巨龙资源恢复及限时目标边界见 [巨龙说明](tasks/giant-dragon/README.md)。

新接取任务将接取时间写入独立的 `character_quest_acceptance_times` 表，与接取／放弃／完成共用事务；不改变旧活动任务表及协议字段。旧任务没有该记录时按历史任务处理。消费会跳过清房之后才接取或重新接取的任务；已完成的 trigger 不重复写入或重复通知。

清房消费采用现有 Reliable outbox：任务更新、投递完成标记和后续变化事件在同一事务提交。失败回滚并按 EventBus 策略重试，重启可恢复待消费事实；超过现有重试上限的记录保留为失败状态供排障。在线提示为 LiveOnly，离线或过期提示不补播，重新登录读取已持久化结果。这里的异步处理不承诺固定延迟。

验证证据为 `CurrentImplementation`：指定地图、错误地图、塔清层后离场、普通组队死亡事务回滚、重复投递、消费失败重试、重启恢复、迟接／重接任务隔离、镜像跨运行隔离、实际 PVF 任务 975 与第 30 层对应关系，以及编码后的 `0x023F` 通知。还需 A21 实机通关第 30 层检查提示及任务交付，不能据此标为 `ClientVerified`。

## 容器持有量的异步路径（2026-10-12）

`持久化物品 Take / Put / 数量或模板 Update → EnqueueAsync(InventoryContentsChanged) → quest.inventory 可靠订阅者 → 任务领域服务重算相关已接任务 → 持久化变化 + EnqueueAsync(QuestProgressChanged) → 通知订阅者 → NOTI 0x023F`。

邮件领取、仓库转入主背包、出售或消耗材料等，只需发生正常的持久化容器变化，任务系统便可收到同一事实；邮件、仓库和售卖业务不增加任务调用。任务仅消费角色 Main 和账号 SharedMaterial 的变化，其他容器变化不表示任务所需物品已在身上。共享材料变化检查该账号的全部角色，不影响其他账号。

事件新增 `ChangedItemIds`，保留原事件名和 v1；没有该字段的旧载荷按未知变化 ID 处理，回退到检查已接材料任务。新事实在同一事务内按 `(容器, 物品 ID)` 去重；每批新增 ID 在入队时冻结，允许一个容器产生多批不同 ID 的事件，避免入队时立即序列化遗漏后续物品。物品变换同时记录旧、新模板 ID。事务回滚不会留下事件。

消费先找出 `SeekingItems` 与变化物品 ID 相交的已接任务，再读取持久化主背包、账号共享材料和当前金币，复用 `IQuestStateRuleService` 求结果；不按事件中的增加数量累加，也不依赖在线容器注册。延迟消费、角色下线和服务重启后仍能更新进度。已交付或放弃的任务不重建；已达标但未交付的任务在材料不足时可以回退，部分进度变化也会通知。换槽、重复投递和其他无实际进度变化的操作不再写 trigger 或生成新的任务变化通知。

任务进度写入、可靠投递完成及后续事件共用消费事务；失败回滚并按 EventBus 的重试策略处理。在线通知仍为 LiveOnly，离线不补播旧提示，登录读取当前结果。原有 `QuestHoldingsChanged` 同步校准路径暂时保留；它已持久化相同结果时，异步订阅者不会重复通知。纯金币变动尚未新增通用事件；混合材料／金币任务在相关物品变化时会读取最终金币，但不能据此声称所有金币变动均可即时刷新。

验证为 `CurrentImplementation`：邮件领取和编码后的 `0x023F`、部分进度／达标／材料移走回退、无关任务过滤、多物品事务去重、换槽无变化、共享材料跨角色隔离、回滚、下线／重启消费、失败重试、已交付任务不重建、旧载荷兼容，以及宠物模板变换的旧／新 ID。尚未部署本次修改，也未进行本次 A21 实机验收。

## 尚未覆盖

- `hunt monster` 的推荐等级副本选择器（`-3`）和世界地图五字段目标已统一解析，但生产死亡事件尚未提供 `WorldMapId`／`IsRecommendedDungeon`，因此仍不能推进这两类目标；这些事实不能仅由副本 ID 和怪物阶级猜出。完整四字段普通目标继续由服务端死亡事实计数。未确定含义的 `-4、-5、-11` 等目标显式保留为不支持，并拒绝新接受，详见 [击杀任务声明统一解析](QuestKillObjectiveParser-20261010.md)。
- 纯金币变动尚未新增通用持有量事件，仍依赖既有校准路径；持久化物品容器变化已由上述通用事件覆盖。角色进入时的快照校准保留原路径。
- 放弃任务已清除任务日志并刷新客户端任务列表；上游还会回收仅属于该任务的任务道具，此处尚未实现道具自动回收。不要把放弃任务实现误读为完整的物品回收规则。
- `hunt enemy` 的被动对象仍通过客户端 `SET_QUEST_TRIGGER` 上报，并受当前任务关联剧情副本的上下文约束；怪物／AI 死亡走服务端事实。其他混合类型的通道规则留待逐类核实。
- `0x023F` 的字段形状有静态证据，以上新推送路径经过服务端测试，但 A21 对所有任务类型的实机显示效果尚未验证。不要把测试或上游行为写成 `ClientVerified`。

地图清理只走上述可靠事件路径；持久化物品容器变化新增上述可靠事件路径，其他现有事实仍使用 `IQuestProgressDomainService.ReportAsync`，本次没有迁移整个任务系统。以后新增事实由事实所属领域发布，在任务订阅者／任务服务内匹配 PVF；不要在业务命令中新增任务 ID 分支或直接写 trigger。任务服务不直接依赖网络发送器，异步变化继续经 EventBus 和通知订阅者投影。
