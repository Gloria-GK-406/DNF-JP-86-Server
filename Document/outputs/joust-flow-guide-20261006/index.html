STATE ≠ STAGE ≠ SCENE

三种状态，三种职责

state 是管理器状态；stage 是赛果包的分支输入；scene 是本地画面状态。相同的 BB stage，在不同 scene 会有不同结果。

04B8 state 消费

状态的业务名称是领域映射。原生没有已确认的 silent 高位标志。state5 依赖已有 counter，不是通用起播。

04BB stage × 当前 scene

Stage0 消费前 6 槽，Stage1/2/3 消费全部 7 槽；有效填槽数量是另一项服务端策略。

场景条件试验

修改收到赛果前的 scene，观察同一 stage 的去向。此试验独立于上方时间线。

打开、查询与投注

  1. 入口先看093D。通用活动表有此项才能走结果UI入口；它不会代替马战state初始化。
  2. 打开先发04E6，再立即读已有state。已有manager的state0会拒绝，无法靠稍后查询ACK解除这次同步检查。
  3. 成功ACK确保对象，显示是另一条路径。投注窗显示初始化会查询04E8；ensure不会自动显示或发送历史查询。
  4. 投注请求不等于扣除。04E7确认回调发所选骑士、物理槽、数量；DOMAIN接受与扣除、共享库存投影、ACK刷新、BA个人投入各负其责。
  5. 查询不结算。历史ACK更新客户端记录和滚动范围。服务端查询只读与客户端回包无公告是两项独立约束。

公告为什么重复

B8 state1–4 的直接公告没有旧状态/轮次去重。scene12的冠军公告也没有去重：重复BB3、在非起播scene收到BB2，以及第三组本地动画结束都可能进入它。窗口已显示主要影响浮动提示，不能据此抑制聊天。

0190兼容插件只跳过B8直接公告；它没有抑制BB或本地scene12，也没有精确恢复已播放时间的字段。每组先state4的模拟候选可起播，但会重复触发state4公告，不能当作最终生产方案。
