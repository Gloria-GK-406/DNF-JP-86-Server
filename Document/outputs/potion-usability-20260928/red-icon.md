# A21 7377 秘药：客户端使用门与图标颜色的证据边界

日期：2026-09-28。范围：只读检查 A21 客户端内存转储、既有字面量索引和本次运行快照；未修改客户端或服务端，也未 attach。下列地址均为镜像基址 `0x00400000` 下的 **VA**；括号内给出相应 RVA。静态转储：`DNFClient-A21-debug/dumps/dnf-dump-20260922-194214-883-23144/DNF-memory-rva.bin`。运行快照：本目录的 `live-items-readonly.json`、`live-unusable-ids.json`、`live-template-7377.json`。

## 发现但当前未启用的 7377 专门拒绝路径

客户端函数 `VA 0x016DC620`（RVA `0x012DC620`）存在 7377 的专门分支：

```asm
016DC623  mov eax, [ebp+8]        ; 传入物品模板 ID
016DC626  cmp eax, 0x1CD1         ; 0x1CD1 = 7377
016DC62B  je  016DC651
...                             ; 其他 ID：查模板并检查模板+0x367 == 1
016DC651  mov al, 1
016DC653  pop ebp
016DC654  ret
```

`VA 0x017F8770`（RVA `0x013F8770`）对物品做一串可用性检查。在 `VA 0x017F89F7` 查询场景/模式键 `0x66` 后，若键启用，则 `VA 0x017F8A1B`（RVA `0x013F8A1B`）调用上述函数；`test al,al` / `jne 0x017F88FD` 使 7377 走 `xor al,al; ret 4` 的拒绝出口。**当前只读运行快照中，键 `0x66` 所在容器为空，`contains(0x66)=false`，所以此分支在当前会话被跳过，不能用它解释本次红色/无 CMD。** 此处是客户端代码中的条件式 ID 特判，与 `[usable expired item]` 或 `[impossible contents]` 的字面解释无关。`VA 0x016DC620` 的另两处直接调用位于 `0x0141A6BE`、`0x0243EA70`。

调用上游可静态追至 `VA 0x01803AE0`（RVA `0x01403AE0`）的 `0x01803CBF call 0x017F8770`，再至 `VA 0x01563B30`（RVA `0x01163B30`）的 `0x01563D33 call 0x01803AE0`。既有 `ClientHack/tools/literals-a21.csv:13979-13980` 把最后一层标为 `IRDSQRCharacter::isUsableItem`。因此这条分支确实位于客户端物品可用性调用链，而非仅凭函数名猜测。运行观察中，普通 Lv80 角色的 7377 在城镇和地下城均无法使用、服务端无 `USE_STACKABLE`；删除 `[usable expired item]` 后重启仍相同。**当前原因仍未由本分支闭合。**

## 运行对象核对

运行快照中，背包 slot 71 的对象 `itemVA=0x54865400`，`item+0x20` 的模板 ID 为 7377；其 vtable `0x032D8DD4` 与 slot 69/70 的正常堆叠物相同。`vt+0x28=VA 0x011BA6D0` 返回 `item+8`，所以相关模板信息从 `0x54865408` 读取。slot 69/70/71 的 `item+0x60` 均为 1，`item+0x27D`、`item+0x7C` 均为 0；不能把这些共同值当成 7377 的独有红色原因。

只读模板快照把 slot 71 解析到 `0x54F4C100`，键为 `event/burning/item_burning.stk`；`template+0x367` 的字节值确实为 1。客户端多处把 ID 7377 与其他物品的 `template+0x367 == 1` 导向同一路径，但这不足以给该字段命名或证明它参与图标着色。当前快照的 `item+0x45C=0`、`item+0x2C4=0xFF`；slots 69/70 的这两项也分别是 0 和 0xFF。

曾检查 `vt+0x78=VA 0x00EEB5B0`：它遍历全局集合 `0x03A2A0A8`，该集合来自 `etc/chn_undeletable_item.etc`（`literals-a21.csv:9255`），当前只含 4237、4238、4240、4277、4275。它是不可删除物品限制，不是此处的使用或着色依据。

## 图标着色尚未闭合

已确认一个物品绘图入口：`VA 0x0134C6F0`（RVA `0x00F4C6F0`，字面量 `CNRDBaseInterface::drawItemQuickSlot`）在 `0x0134C8D0` 经 `vt+0x10` 调入通用绘图函数 `VA 0x00EEEEE0`（RVA `0x00AEEEE0`）。该函数继续画图标、标记与覆盖层，并使用操作检查 `VA 0x02312480`；当前未找到它直接调用 `0x016DC620`、`0x017F8770` 或 `0x01803AE0`。这只是**快捷栏**绘图入口，不能据此断言主背包红色一定由上述 ID 特判着色。对已解码的本地脚本/资料检索 `isUsableItem`，仅命中客户端字面量索引；A21 PVF 中无 `.nut` 文件，现有 44 个 `.lua` 路径为 AI 脚本。脚本间接调用仍未排除。红色可能来自独立绘图条件、图标资源或模板状态；现有证据无法区分。

该快捷栏函数从 `VA 0x00EEEF5F` 经 `vt+0x104=VA 0x00EEAE10` 画基础图标，并在 `VA 0x00EEF8BE` 调用 `VA 0x00EE9760` 画时间标记。后者在 `VA 0x00EE98BA` 通过 `VA 0x02503280` 读取物品的 `+0x45C`，又在 `VA 0x00EE98CB` 经 `vt+0xD0=VA 0x016DD450` 检查模板的 `+0x1B4/+0x1BC` 条件；`VA 0x00EE98E4` 调用 `VA 0x016DD0E0` 计算剩余时间，条件满足时才画资源 `0x031F50B8`。这是过期/限时图形线索，但无法把当前红色归因于该支：7377 的 `item+0x45C=0`，并且还未取得该虚函数在 live 对象上的返回值。基础图标和快捷栏覆盖层可见的颜色构造都是 `alpha << 24 | 0xFFFFFF`；本路径内未找到 `0xFFFF0000` 或 `0x00FF0000` 红色立即数。图标仍可能由资源本身或上层背包控件染色。

若需只读运行时裁决，最小观察是记录 7377 主背包格最终绘图时传入的对象指针、调用的绘图入口与颜色/覆盖层参数，并与同屏正常堆叠物比较；同时逐项核对 `0x017F8770` 在当前会话的实际拒绝出口。无需改 PVF、改内存或发送使用命令。此前删除 `[usable expired item]` 的 A/B 已为阴性，无需再用这个标签解释红色。
