# pickup-trace 动态取证 Runbook（v3）

配套：`pickup-trace.cdb.txt`（纯命令脚本）、`pickup-retention-investigation.md`（报告）。
目标：用**一次成功拾取 + 一次失败拾取**的采样，在候选假设 H-A/H-B/H-C/C-C/C-D 之间做出区分（不承诺唯一定位；判读边界见 §7）。

---

## 1. 适用客户端与启动方式

- **仅适用**：`E:\Project\DNF\DNFClient-A21-debug\DNF.unpacked-b1-debug.exe`（b1 调试 exe，跳过宿主反调试；cdb attach 是既有流程，先例 `cdb-real-00ab.txt`）。
- **禁止 attach**：`DNFClient-A21-protocol2` / play 目录的原版壳客户端（壳+反调试会检测/崩溃，且地址不适用）。

## 2. 前置检查（每一步不过就停止）

1. **镜像校验**：对 b1 exe 计算 SHA-256，必须等于
   `DC322D8FB2A8A33FCE31065CEEAC5801ED854F34409190FE257AACF2663306E9`。
   （重启后需先跑"重建 debug exe"流程再校验——KnownDLL ASLR 会使旧 b1 exe 失效。）
2. **cdb 存在性**：本机当前**没有安装 cdb**（已查证，仅 8.1 kit 的 dbghelp.dll）。需要在装有 Windows 调试工具（x86 cdb）的机器上执行。
3. **命令语法验证（本机未验证，必须先做）**：在隔离进程上逐条验证脚本用到的语法——
   开一个无关进程（如 `cdb notepad.exe`），依次执行：
   - `.logopen E:\...\pickup-trace-syntaxtest.log`（确认绝对路径可写、日志实际落在哪里）
   - `r $t0=0`、`r $t0=@$t0+1`、`.printf "seq=%x val=%04x\\n", @$t0, 0x2b`（转义与 %x）
   - `.echotime`（若报"无法识别"，删除脚本中全部 `.echotime` 行，改用序号+墙钟手工记录对齐）
   - `bp notepad!WinMainMain?` 不可用时改用：`bp kernel32!GetTickCountW ".printf \"HIT\\n\"; g"`（验证"带引号命令串+g 自动继续"）
   - `.if (dwo(0x7ffe0000) != 0) { .echo IF-OK } .else { .echo IF-BAD }`（.if/.else）
   - `wo(0x7ffe0000)`、`by(...)`、`poi(...)`、`dwo(...)`（内存算子）
   - `qd`（确认 detach 语义：notepad 继续运行、断点消失）
   任何一条失败：**不要 attach 游戏**，把失败命令与报错记录下来反馈，修订脚本后再来。
4. **帧关联源（三选一，采样前确认哪个可用）**：
   - 调试客户端 ClientHack.ini 的 `[FrameCapture]`（若启用，出站 002B/入站 0027 实文+时间戳）；
   - 服务端 `stdout.log`（002B/0027 发送行，北京时间）；
   - 用户手工记录每次按键时刻。
5. **磁盘**：确认 `E:\Project\DNF\DNF-JP-86-Server\Document\outputs\pickup-retained-20260922\` 可写；旧 `pickup-trace.log` 先改名归档。

## 3. 采样流程（用户最少操作）

1. 城镇待命时由操作者执行：
   `cdb -cf pickup-trace.cdb.txt -pn DNF.unpacked-b1-debug.exe`
   调试器输出必须出现 `GATE-OK-ALL-5` 与 `BREAKPOINTS-SET-RESUMING`、`bl` 列出 11 个断点、无任何错误行；任何 `GATE-FAIL-*` 会自动 `qd` 退出——按 §2.1 重新校验镜像。
2. 用户进入目标地下城（进图即被记录）。
3. 杀怪 → 出现掉落 A → **记下拾取时刻与地面是否消失**（成功样本）。
4. 换房 → 在另一房间制造/拾取与 A **同编号**的掉落 B（若自然出现）→ 记录结果。
5. 重访 A 所在房间 → 对残留幽灵再次按拾取键（NothingThere 样本）→ 记录"无任何反馈/有弹窗"。
6. 全程如遇明显卡顿：见 §6 降级。结束后操作者执行 `qd`（detach，游戏继续、断点随调试器消失，零残留）。
7. 用户另纸记录模板：`时刻 | 动作(捡A/捡B/重试幽灵/换房) | 地面是否消失 | 是否有提示`。**"失败"由用户确认，不由脚本推断。**

## 6. 风险与降级

- **性能**：T8 在全游戏所有键注册处触发（条件过滤在断点命令内，仍付出陷入开销）。若帧率不可接受：`qD` 退出 → 注释掉 T8 两行（保留 T8b，击杀路径专用、开销小）→ 重启采样。
- **时序影响**：断点陷入（微秒~毫秒级）理论上可能改变竞态窗口的复现概率。若多次采样均无法复现失败，需在报告记录"采样下不复现"本身，不得反推假设不成立。
- **崩溃**：若游戏在断点期间崩溃：保留 pickup-trace.log 与崩溃时机记录，`qd` 清理，停止采样上报。
- **反调试**：b1 exe 跳过宿主反调试；但 **不得** 附加调试器到壳客户端；也不得同时运行其他调试工具。

## 7. 判读边界（可确认 / 只能缩小 / 无法判断）

**可直接确认（单轮采样内）：**
- C-D 派发异常：帧日志有 0027 入站、T1 无输出（前提：§2.3 验证通过、断点确在 `bl` 列表、同一时间窗）。
- G1 场景空：T2 输出 scene=0。
- 请求确实派发且构建器确实进入：T6a 与 T6b 同 seq 邻近出现，且帧日志同刻出现出站 002B（三者齐=请求真正发出；T6a 有而 002B 无=构建器内部放弃）。
- 剥离/失活发生过：T7/T9 输出及对象指针。

**只能缩小范围（需结合注册史与序号）：**
- G2 查找失败（T3=0）：区分"从未注册"（T8/T8b 无该编号注册行）与"已注册但查不到"（有注册行）——注意采样起点晚于注册时 T8 永远缺席（本方案已把 attach 提前进图前，正常不应缺席）。
- G3 引用为空（T3≠0 且 T4 itemRef=0）：结合 T7/T9 历史判断是否命中了被剥离对象（指针相同或同号同场景）。
- 同号不同对象：T6a 的 targetObj 与 T3 的 hitObj 不同——**仅是线索**，见 §8 身份关系表，不等于跨房间碰撞。

**本轮无法判断（明确边界）：**
- 指针相等跨时间复用问题：同一地址在不同时间可能是不同生命周期的对象。判读必须以 (seq, 场景指针, 编号, 注册/剥离史) 四元组关联，不得只看地址。
- "旧房间对象是否本应被清理"的规范问题：脚本只能记录实际发生了什么，不能判定设计意图。
- 修复有效性：不在本轮范围。

## 8. 对象身份关系表

| 指针/字段 | 来源 | 可否直接比较 | 说明 |
|---|---|---|---|
| T6a targetObj | 拾取控制器持有的被点对象 | 与 T3 hitObj **不可直接判定**相等/不等即下结论 | 两者若相等→同一对象（强证据）；若不等→需先核对：①两者虚表（[obj]）是否相同类；②编号字段（+0x9C 字符串首 4 字节）是否同号；③T8/T8b 注册史里这两个指针各注册在哪个场景（ecx）。三条都齐才能区分"同号不同对象/不同生命周期/包装指针" |
| T3 hitObj | 查找命中对象（包装层） | 与 T7/T9 的 obj 可直接比（同为注册池对象指针） | 剥离史判定用 |
| T4 itemRef | [hitObj+0x1134] 内部物品对象 | **不得**与 hitObj/targetObj 比较 | 内部物品是另一对象（入包用它，移除用包装层） |
| T8/T8b scene (ecx) | 键注册时的场景 | 可用于"创建代次"分代 | 不同房间注册的 scene 指针不同则可区分生命周期；相同则需配合 seq |
| numStr9c（+0x9C 首 4 字节） | 编号字符串原始字节 | 与十进制编号人工对照（"1"→0x31） | 不是整数，是字符串字节 |
| 地址复用 | — | 禁止跨时间只按地址等同 | 见 §7 末条 |

## 9. 备选方案（仅设计，不部署）：最小诊断插件

若 cdb 路线不可用（无 cdb 机器/语法验证失败/断点开销改变复现），备选为 ClientHack 诊断插件（编号建议 `0115_PickupObjTrace`，**本轮不实现不部署**）：
- 原理：在 ClientHack 初始化后对同样 11 个 VA 打 INT3（`0xCC`），注册向量异常处理器（VEH），在处理器内按 §5 表读取同样字段，以与 `clienthack-a21-pickup-trace.log` 相同的 JSONL 格式写 `clienthack-pickup-objtrace.log`，恢复原字节/单步后继续。
- 优点：无外部调试器（b1 模式下无反调试对抗）、开销更低、与既有抓包日志同进程同时钟。
- 风险与撤回：写 INT3 属于修改客户端代码字节（仅采样期）；撤回=关闭客户端并从 plugins 目录移除；需要一次隔离环境全流程演练后才可上实机。
- 前置：client-debug-lab 分支构建产物；主 agent 审核后另行安排。

- 本轮不修改任何生产 DLL、不部署任何插件、不动数据库、不重发奖励。
