# 拾取残留调查接手核验（2026-09-22）

## 结论边界

尚未定位本次拾取失败根因。旧 v3 采样文件不能直接用于实机：请求路径存在 RVA/VA 混用，需先修正并隔离验证调试器命令。

## 本轮独立确认

1. 协议机器区的构包点 0x012FC95B / 0x020681F2 是 RVA。加 ImageBase 0x00400000 后，VA 0x016FC95B / 0x024681F2 均为对 0x0274D1E0 的调用，前面确有 push 0x2B。因此外部报告 v3 的 R16 撤回不成立。原机器区本轮未改。
2. 第一条构包函数入口 VA 0x016FC920，参数 [ebp+8] 装入 ESI，随后调用物品引用 getter 0x0174CEA0。在 0x016FC99E 调该对象 vt[0x4C]，返回 EAX 于 0x016FC9A0 压栈，之后调用 WriteU16。此处可以直接取得实际序列化的掉落编号及源对象，而不是从未经证明的路径猜请求。
3. 候选地面物虚表 0x032DC624 的 vt[0x4C] = 0x01765290。该 getter 对 this+0x9C 使用 0x027BC0F0 族保护数值解码。因此读取 dwo(obj+0x9C) 不能当成实际掉落编号。在请求 WriteU16 前读已解码 EAX 不需要调用目标函数或解 VMP。
4. 第二条构包函数 0x024681E0 从 ESI+0x1A8 读 u16 编号，不能把这里的 ESI 无条件当成第一条路径的地面实体。
5. 旧 T5 打印的 drop 参数错误地使用 recipient 的局部变量 -0x250；应为 -0x258。旧 T1 位于头字段读取后，需要另设 handler 真入口，避免把字段读取期间异常误判为未分发。

## 隔离调试器验证结果

全盘定向查找找到了 E:/VM/OVFTool/cdb.exe（微软 CDB 6.11 外壳；实际载入系统 10.0.26100.1 调试引擎），无需安装。另有工具箱 WinDbg。外部报告“本机没有 cdb”应修正为此前未在常用目录找到。

已通过该 CDB 在自建的 cmd.exe 子进程上验证：单行 .if、bp 内嵌 .printf 引号、序号、线程 ID、.time、断点命中及 qd。32 位子进程启动存在额外 WOW64 初始断点，首次实验停在此处，第二次明确处理 0x4000001f 后命中预期入口并退出调试器。实验只作用于自己启动的隔离进程，不涉及游戏。

重要修正：嵌套 bp 字符串中的换行必须保留双反斜杠形式；单反斜杠会丢失换行。已恢复草案中的转义。原稿 .echotime 改为实测可用的 .time。

上述只是基础语法验证，不代表整份脚本或对游戏安全性已验收。下一步仍需验证完整字节门控、失败自动脱离、所有断点及线程关联。未 attach 当前两个游戏客户端，也未重启服务器。
