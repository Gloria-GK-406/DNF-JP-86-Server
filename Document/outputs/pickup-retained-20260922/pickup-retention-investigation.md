## 3. 注册—查找—剥离—注销—换房 证据链（本轮新静态成果）

### 3.1 生成与注册（三条创建路径，注册时机不同）

| 路径 | 创建 | 键注册 (类别,编号) | cell 注册 |

| NOTI 0x0026 击杀掉落（48B 记录） | 逐记录处理器 0x017EB8C0 → 0x0174EE90 | **0x017EBBE7 调 0x191E450** | 未见直接调用（见 G-A） |
| NOTI 0x0028 掉落出现（本服务端不发送） | handler 0x0117FE50 → 0x0174EE90 | **0x01180274 调 0x191E450**：`0x191E450(场景, 0, 0x121, 编号, 对象, 0,0,0, 1)` | 未单独调用（同上） |

**通用键注册 0x0191E450**（约千余调用方，ClientStatic）：
- 入口查重 0x0190F510(场景, 对象) 是**指针**成员检查（遍历场景 +0xC..+0x10 向量比对指针）——**同编号不同指针不会被拒绝**（同号共存在此层不设防）；
- 设置对象身份：vt[0x30](对象) 返回身份记录，写入类别（arg2）与编号（arg3，字符串）；
- 加入场景主列表（0x01914 310 族）；加入场景**按类别子列表**（`场景+0x1C + catIdx*0x14`，带 0x293B470 守卫锁）；vt[0x68](对象, 场景) 建立回链。

**cell 注册 0x017467F0**（ClientStatic）：按对象坐标算 cell（步长 0x520FE26），经映射表 [0x3A8F620]（cellIndex→区域槽位）选容器：槽位 ≥0 时从哈希 0x3A8F608 按 cellIndex 取集合，取其 cells[槽位]；槽位 <0 时落主数组 [0x3A8F5D0/5D4]。随后向容器做至多四次列表插入（0x1B23D40/0x1913440/0x19134E0/0x1913580）。

### 3.2 查找池的真实结构（0x017284B0）

- 搜索顺序：**主池 [0x3A8F5F4]（向量）优先，随后按槽位 0..[0x3A8F614] 枚举哈希 0x3A8F608 的全部集合**，每个集合经 0x01722CB0 遍历（容器计数 0x01910570 / 取子对象 0x01910510，比对 vt[0x48]==0x121 && vt[0x4C]==编号），**首个命中即返回**；
- 传入的场景参数被 0x01722CB0 忽略（v1 已证，复核成立）；
- **哈希 0x3A8F608 的来源（本轮新证）**：0x017370B0（地图类虚方法，thunk 0x22C5170，被多个 .code 虚表引用）是**空间索引重建器**：按地图尺寸重建全局 cell 数组，并遍历地图对象 +0x2C0 的 0x14 步长区域记录，逐条分配 0x3C 字节集合对象、清零其各向量、经 0x140D190 以**坐标对为键**插入 0x3A8F608。即：查找池=当前地图的全部空间集合，**按地图（重）建**；
- 无法从静态判定 0x017370B0 的触发时机（虚调用：地图加载？每次进房？）与重建时旧对象是否幸存——这是"跨房间共存"假设的核心未闭合点（G-B）。

### 3.3 剥离与注销（修正 R1 后的完整链）

NOTI 0027 效果段（接收者==我，0x011860CA）→ **0x0174E660(对象)**：
1. `[obj+0x1181]!=0` 仅控制日志/物品名消息分支；**无论该标志如何都会执行** 0x0174DF90(obj, 0)；
2. **0x0174DF90(obj, 0)**：`[obj+0x1134]=0`（**物品引用确认清空**）→ 调 vt[0x17C]；
3. **vt[0x17C] = 0x017778C0(obj, 0, 0)**（真实地址，可反汇编）：
   - 门：`[obj+0xC0]!=0` → 只释放传入引用（本次传 0，等于直接返回）；
   - `[obj+0xC0]==0` → 0x01768E10(obj)（基类脱离，同样以 +0xC0 为门；内部为多步 vt 调用的通用失活，不触碰任何 cell/集合全局）→ 读 `[obj+0xB8]`（所属者），**非空时 0x0191DE70(所属者, obj)**：在所属者 +0xBC 的守卫列表中定位并**移除 obj**（迭代器比较+锁 0x293B470）；
4. **关键否定性结论（ClientStatic）**：整条剥离链（0x0174E660/0x0174DF90/0x017778C0/0x01768E10/0x0191DE70）经字节级全局引用扫描，**均不直接引用任何 cell/集合全局（0x3A8F5E4..0x3A8F624）**。即：
   - 物品引用清空：**已证**；
   - 场景主列表移除：**已证**（+0xBC 列表）；
   - 按类别子列表移除：未见（间接调用未穷尽）；
   - **查找池（cell/集合）注销：未证**——要么经 vt 调用间接发生，要么延迟到 tick，要么不发生（失效对象残留池中，vtable/类别/编号身份仍在，查找仍可命中并读到 +0x1134==0）。**这正是 G3 候选的机制基础，需运行时裁决。**

### 3.4 换房生命周期

- 静态未走完 0x01157B30（StartMap）的清理段；空间索引重建器 0x017370B0 的触发时机未定（虚调用）→ "旧房对象在换房时被清除还是幸存于集合"**未证**（G-B）；

- 已结算的掉落 1 不再被重声明（F4），其幽灵无任何已知帧会清理——与"换房返回后仍在"一致。

### 3.5 请求对象与 NOTI 命中对象的身份关联

- 请求侧：拾取控制器 0x012FC940 → 目标对象 vt[0x470]=0x018B6BA0（大量前置门）→ vt[0x480]=0x018B7030 构包发送。目标即**被点击的地面物对象本身**（地面物类，+0x98 类别=0x121、+0x9C 编号字符串、+0x1134 内部物品对象——初稿未区分的两层：**地面物包装对象**与**其 +0x1134 指向的内部物品对象**是两个对象，0027 的移除作用于包装对象、入包取的是内部物品）；
- NOTI 侧：按 (0x121, 编号) 在查找池中**重新检索**，命中对象身份=包装对象；
- **两个通路没有共享的对象指针传递**：请求不查池，NOTI 不引用请求目标。同一编号在池中存在多个候选（若共存成立）时，NOTI 命中者可能是**另一个同号对象**——此差异正是 §6 脚本用指针对比直接裁决的目标。

## 4. 编号复用是否造成查找歧义：已证 / 未证分栏

**已证实（ClientStatic + 服务端代码）：**
1. 服务端编号按房间分配、跨房间复用（`DungeonCellAggregate.nextGroundItemNumber`，声明与击杀掉落共用该计数器；`GroundDropId(Cell, Number)` 注释自认两房间会同号）；
2. 查找池跨集合枚举（主池+全部哈希集合），首个 (0x121,编号) 匹配即返回，无场景过滤；
3. 键注册的查重只看指针，同号不同对象不被拒绝；
4. 请求通路不依赖查找池——"看得见点得动"与"NOTI 查得到"无结构性绑定。

**未证实（假设，需动态裁决）：**
- H-A 跨房间同号对象**实际共存**并参与匹配：取决于 0x017370B0 重建时机与旧对象是否从集合清除（G-B、3.3 第 4 点均未闭合）；
- H-B 失效对象（已剥离、+0x1134==0）**残留于查找池**并可先于有效对象被命中（G3 的机制前提）；
- H-C 同房间内"生成中/注册中"窗口（击杀后 0.3–1 秒快速拾取时，键注册 0x191E450 是否已执行）——0x26 路径的 cell 注册缺失（G-A）使该假设比 v1 更具体：击杀掉落可能**只完成键注册、未完成 cell 注册**，若查找实际依赖 cell 集合，则存在"已创建未入池"窗口。

**结论**：按用户指令，"碰撞已成立"不写；上述三项假设均给出可达路径与未闭合点，由 §6 采样裁决。

### 5.2 公共尾语义（修正 R4/R8）

所有失败 reason（含 15/13）执行：**0x016FB9D0([0x3A5C9BC], 2)**（全局待处理状态队列取消 id=2，**非声音**；无已证音频调用）+ 遍历当前场景列表对**全部** 0x121 类对象调 **0x0174CEF0(obj, 0)** 清在途标志。

### 5.3 失败应答能解决 / 不能解决

- **能**：解除全局待处理状态 2 与全部对象在途标志（可再次请求的必要条件）；给玩家准确反馈（51/04 分支）。
- **不能**：移除地面幽灵视觉（失败路径无任何 0x0174E660 调用）；修复背包/地面不一致本身。
- 禁止事项（维持）：不得伪 ACK 成功；不得重发成功 NOTI 0027（普通物品/金币有再次入包或增量重复应用风险——0027 物品分支执行入包、金币分支依赖 000E 余额帧，重放均非幂等）；不得因未发送 0x0028 就断言现行 0x1D/0x26 生成协议缺少注册步骤——0x26/0x1D/0x28 三路**共用** 0x0174EE90 创建与 0x0191E450 键注册，差异仅在 cell 注册（G-A），是否"缺步骤"待 H-C 裁决。
