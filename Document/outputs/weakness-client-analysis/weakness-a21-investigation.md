## 1. 结论摘要（实施视角，v2 修订）

**"虚弱状态投影"可以现在实现**：施加/更新/恢复的活体通道（NOTI 0x0021 任意值 →
stamina setter + 属性重算）、恢复请求/错误码（CMD 0x0009 + 18/22/4）、展示值

**"正式虚弱业务规则"还不能**：施加的等级门槛、严重度档位、自然恢复速率是
服务端业务/原版规则，客户端静态给不出（§2.4.3、§5.2）；免虚弱资格来源未闭合（§4.3）。

1. UI 文案全部住在 `dstr.dat`（SC01 + 差分 XOR），已全解（§2.1）。用户截图的警告
   弹窗 = 字符串 38254。

3. `0x27BC0F0` 族是**运行期受保护数值（anti-tamper）编解码库**，不是 PVF 读取

### 2.4 等级门槛（v2 重写：+0x14 字段已定名）

**v1 曾把弹窗条件 #2 的 `0x27BC0F0` 称为"PVF 两级表读取"并留作"字段语义未定"。v2 撤回该命名并闭合此字段。**

#### 2.4.1 0x27BC0F0 同族 = 受保护数值（anti-tamper）解码库，与 PVF 无关 — Confirmed（静态）

五个兄弟函数（0x27BC0F0/0x27BC160/0x27BC1D0/0x27BC240/0x27BC390）只差校验公式。共同结构：

```text
eax = [ecx]                        ; 字段内存放的 handle（表索引）
T   = [0x03B89618]                 ; 运行期生成的代换表对象
sub = T->[0x24 + (handle>>16)*4]   ; 一级表
ent = sub[(handle&0xFFFF) 同址 + 0x2114]  ; 二级表项 u32
e16 = ent & 0xFFFF
out = (e16 * 0x00010001) ^ key     ; key = 字段旁的第二个 dword（[field+4]）
校验：ent>>16 == f(out.hi, out.lo, e16)，f 为五变体各自的加减乘组合
校验失败 → 置空指针参数走错误路径
```

编码方向（写入方）在 0x27BB8xx-0x27BBBxx：选 handle、算 e16 与校验、**把表项写回
`[T 一级 + idx*4 + 0x2114]`**、key 存 `[field+4]`。即每个受保护字段 = 8 字节
{handle, key} + 表内一项校验。通用编码入口 0x27BBA60（全镜像 18,489 调用），
字节/字变体 0x27BB9B0/0x27BB2B0 等。使用点的对齐分派
（`and eax,0xF` + 跳表）按**字段地址的低 4 位**选编码/解码变体——字段布局固定，
因此每个字段永远走同一变体。密钥流表 0x36018B8。**该表运行期生成与校验，不是 PVF 数据。**

```text
    min/max 两组 4 个 float → [ebp-0x30..]/[ebp-0x20..]（四个基础属性）
门 1：0x163E2D0(0x1102C30(9))  非 0 → 跳过 stamina 应用
门 2：0x163E2D0(0x1102C30(0xD)) 非 0 → 跳过 stamina 应用
    （两个子系统开关，语义未定名；任一激活则按 100% 计算）
通过则：解码 this+0x56C8 → [ebp-0x88]          ; 0x0186E770-0x0186E7CE

缩放（0x0186F12E 起，五处）：
  ①-④  target(+0xD18/+0xD28/+0xD38/+0xD48) = source(+0x55B8/+0x55C0/+0x55C8/+0x55D0)
        × pct，再 ÷1000（魔数 0x10624DD3, sar 6）
        —— 源值在"线上 ×10"刻度（见 NOTI 0x0002 subtype1 记录），等效 ×pct/100
  ⑤    vt[0x3E4](1) 的值 × pct ÷100（魔数 0x51EB851F, sar 5）→ vt[0x6D8](…)
        （vt+0x3E4=0x017B0480 经 vt[0x5D4](3) 统计块取值；vt+0x6D8=0x017B8D30 为
          VMP 包装 setter；具体属性身份未定名）
其后继续走 UI/对象刷新。
```

要点：
- **四个 0x10 步长的属性字段**（+0xD18..+0xD48，源 +0x55B8..+0x55D0）按 pct 线性缩放，
  外加一个 ÷100 刻度的标量（⑤）。**未证明**这四个就是 力量/智力/体力/精神 —— 只证明
  "四个等距属性槽 + 一个标量被 stamina 百分比缩放"。
- **进入 setter ≠ 证明 setter 全部业务效果**；但重算链本身是显式指令，不是推断。
- v1 的"客户端没有公式、服务端直接下调下发值即可"**撤回**：客户端持有
  `值 × pct` 的本地重算，服务端若再下调下发值会**双重惩罚**（见 §5.1 v2 边界）。

#### 3.3.3 NOTI 0x0021 handler 全文（v2 精读）— Confirmed（静态）

### 3.4-c 登录/入城虚弱字段的接收位置（v2 新增，问题 C）

**结论：本轮未闭合；且已排除一条关键路径。**

1. **NOTI 0x0002 handler = `0x013E91E0`**（census；本轮经 0x2F47FB0 转发块反查修正过一次
   误认——该转发块注册的 `0x013E9830` 实为 **NOTI 0x02ED** 的 handler，
   `push 0x2ED` 在 0x2F47FBC。曾沿 0x02ED 的记录解析器 0x013E8AF0 走出一段
   (u8, u32, u8→B+0x300) 的尾部，**那些字段属于 0x02ED，与 0x0002 无关**，已作废）。
2. 0x0002 的解析结构：读 u8 subtype；subtype==0 走 0x013E9248（一段日志 + u16）后
   **并入** 0x013E92AB 公共解析；随后 `0x013E92FE/0x013E9307` 两读 u16、
   `0x013E933C u8 + 0x013E9345 u32`（dstr 名）——与 86JP subtype0 的
   (version u16, charId u16, name dstr) **头三组吻合**；**此后读序发散**
   （客户端连读 u16/u32 并注入多个子解析器 0x13E16F0/0x13E2930/0x13E4070/…，
   而 86JP 写的是六个 u8 连排）。因此 86JP 的 "remaining/tail" 布局只是字节自洽，
   **不能逐字段映射到 A21**；"整包被接受"只证明总长兼容，不证明任何尾部字节语义。
3. **关键排除（Confirmed，镜像全扫）**：登录/入城解析**不调用** `vt[0xA0C]`
   （stamina setter；装载点全集见 §3.3.1）。因此即便 subtype0 某字节携带虚弱，
   它也不会经该 setter 进入角色的活体 stamina 字段——只能落在某个展示性记录
   （如组队名单/查看他人）或被丢弃（0x02ED 解析器中确有"读后即丢"的先例）。
4. FatiguePenalty（86JP 名）：除名字与 Stamina 相邻外**无任何 A21 侧证据**；
   本轮在 0x02ED 尾部看到的"读后丢弃 u32"属错误协议，已作废。**不得据此持久化字段设计。**
5. 入城字段与 NOTI 0x0021 的**刻度比较：无法进行**——0x0021 是 0-100 直通 setter；
   入城字段的刻度因接收点未定位而未知。
6. 可用/不可用投影路径（对服务端实现）：
   - **可用作正式依据**：NOTI 0x0021（施加/更新/恢复，§3.3.3）、CMD 0x0009+错误码
     （§3.2）、NOTI 0x0007 偏移 9（展示值）、subtype1 偏移 95（当前 HP% 呈现）。
   - **不可用作正式依据**：86JP subtype0 尾部 byte16/17..20 的"登录虚弱"布局
     （A21 接收侧未证实，且被 3 排除进活体字段的可能）。

### 3.5 施加与退出的关系（v2 修订）

- 普通地下城**全灭倒计时到期回城 = 服务端计时器主动推送**（第一/二轮已验收：
  0028 handler 创建 PartyWipe 计时器，到期由服务端结算回城投影）——**客户端不发送
  也不需要发送 0x002A**。0x002A 是**手动放弃/结算画面离开**等路径的请求帧
  （0x002A 记录 2026-08-26 实机：结算画面确认后发送）。两者必须分开：全灭自动回城
  与手动放弃共用"服务端结算退出"这一结果，不共用"客户端发 0x002A"这一动作。
- **本轮调查覆盖范围内**未发现"请求施加虚弱"的上行（0x0009 是恢复请求；0x002A 是
  退出请求；全镜像 0x2A/0x0009 构包点已复核）。此表述按覆盖范围陈述，不作为
  "全客户端不存在"的证明（未做穷尽的全上行语义分类）。
- 施加虚弱 = 服务端在结算退出时的单方面动作；客户端感知通道：NOTI 0x0021（活体，
  §3.3.3）与入城投影的呈现类字段（§3.4）。
- **顺序要求**：入城投影与 NOTI 0x0021 的先后静态无证据；E1 实验步骤 4 专门区分
  "0x0021 会话内覆盖"与"入城投影权威"（§6）。
- 顺带记录（支线，未展开）：**CMD 0x004EB**（上游枚举名 HALLOWEEN_2016_CHN，A21 实际语义
  未定）body 定长 22B，构包点 `0x004D0409` 一带受"状态==6 且全局 vt+0xE4≠5 且未发过"门控；
  其 ACK handler 正是 `0x01106220`（`0x0110C60A` 注册，CMD 表）——ACK 结果标志低字节为 0 时
  **构包发送 0x002A**。与虚弱主线的关系未证明，仅登记。

## 6. 受控实验设计 E1：区分"NOTI 0x0021 只改 UI"与"同时改客户端属性/计算"

| 5 清场收尾 | body=100 一次 | 确认完全复原；若步骤 4 已复原可跳过 | — |

**结果解释表**：

| 观察组合 | 结论 |
|---|---|
| 步骤 1 面板四属性≈基线×32%（±1 舍入） | "同时改变客户端属性计算"证实；四槽=面板属性（可对号入座命名） |
| 步骤 1 仅图标/百分比变，面板不变 | "只改 UI"——与静态结论冲突，需复查（例如被门 1/门 2 的模式开关跳过，§3.3.2） |
| HP/MP 最大值变化 | 缩放含 HP/MP 上限（⑤号站点身份可定名）；只有当前值变化 | HP% 通道（subtype1 呈现）独立 |
| 步骤 3 不复原 | 重算单向或需其它触发——服务端恢复必须附带完整入城刷新 |
| 步骤 4 回到基线 | 入城投影是权威；服务端施加必须在**每次入城**时重发当前 stamina（0x0021 不能只发一次） |
| 步骤 4 保持 32 | 客户端自己保住了状态（则服务端可少发）；与"登录不设 setter"（§3.4-c-3）合并解释 |

**本实验不能得出的**：原版服务端的施加规则/等级门槛/自然恢复速率（自服实验只验证
协议消费与客户端表现，不证明原版规则）；免虚弱资格来源（另案）。
