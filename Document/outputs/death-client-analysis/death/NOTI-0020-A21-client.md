# A21 客户端死亡与复活倒计时取证

日期：2026-09-20。只读分析对象为 `DNFClient-A21-debug/DNF.unpacked-b1-debug.exe`，SHA-256 `DC322D8FB2A8A33FCE31065CEEAC5801ED854F34409190FE257AACF2663306E9`。其 PE ImageBase 为 `0x00400000`，下列地址均为 VA；`NOTI 0x0020` 的旧 RVA `0x00D4F420` 对应 VA `0x0114F420`。未附加或控制游戏进程。

## 可执行结论

1. **Confirmed，静态客户端代码：** `NOTI 0x0020` 的固定读取前缀是 `u16 actorId, u8 state, u8 unknown`，共 4 字节。读取点分别为 `0x0114F44E`（经 `0x027C52A0`）、`0x0114F469`、`0x0114F477`（后两次经 `0x027C5230`）。第四字节在该 handler 后续指令中没有再被引用，不能赋予计时语义；由于下游间接调用，不能以此断言总载荷上界。actorId 与最多 8 个槽位中的角色 ID 比较（`0x0114F4D4`–`0x0114F50B`）。
2. **Confirmed：** `state=1` 或 `2` 走复活分支（`0x0114F6DD`–`0x0114F6ED` 跳 `0x0114F862`）；其他值走死亡分支。读取后，状态值还会传给匹配角色的 `0x01834860`，写入角色对象 `+0x3814`（`0x0114F525`–`0x0114F52F`）。因此 `state=0` 是死亡路径，但“非 1/2 值全部具有合法死亡语义”仍需样本验证。
3. **Confirmed：** 死亡数字倒计时是客户端本地计时。死亡界面对象的 `+0x4C` 等于 `2` 时，绘制回调 `0x0138B360` 在 `0x0138B3E7` 调 `0x0138A320`。该函数从对象 `+0x30` 计时器取已过毫秒（`0x0138A36C`），计算 `floor((9999 - elapsedMs)/1000)` 并限制下界为 0（`0x0138A371`–`0x0138A394`；乘数 `0x10624DD3`、右移 6 是除以 1000 的整数实现），使用 `Interface2/Common/digit/coin_countdown.img`（字符串地址 `0x0328E450`，引用 `0x0138A39E`）绘制。`0x0138AE10` 改变界面状态时于 `0x0138AE42` 重置该计时器。未见从 `0x0020` 第四字节读取时间值。
4. **Confirmed，普通模式的客户端状态门：** `0x011500EA` 的模式判断经 `0x00A9AA30 → 0x0163D610` 读取 `CNGame+0xF48`，仅在状态 `0x1B`（27）为真。状态名表 `0x04E20D50` 的第 27 项由 `0x02FEEC1D`–`0x02FEEC27` 初始化为字面量 `0x03661264`，lab 字面量表解出 `CHANNEL_TERRITORY_COMBAT`；因此这是领地战模式门。普通模式下，`0x01150212` 调 `0x019E7380(1)` 统计未死亡角色。角色 vtable `0x032E5D64` 在 `0x0182BA9B`、`0x0182CAB9` 写入；其 `+0xB10 = 0x01833C70` 写 `this+0x57FA`，`+0xB14 = 0x01833C80` 读该字节。镜像中含这对相邻槽位的 25 张派生 vtable 均指向同样的两个函数，虽未从进程堆取到这次角色的实际 vptr，槽位目标在这一继承族内相同。`NOTI 0x0020` 在 `0x011500D0` 把 `state==0` 转成布尔值，于 `0x011500D9`–`0x011500E8` 经 `+0xB10` 写入，故死亡为 1，复活为 0。`0x019E7380(1)` 遍历 8 槽，过滤 `+0xB14` 为真的角色（`0x019E7390`–`0x019E73B5`），并有备用本地角色计数分支，返回的是未死亡角色数。结果大于 0 时走 `0x01150230`–`0x01150306`，界面状态为 `0` 或 `1`，没有 10 秒数字；结果为 0 时走 `0x0115030B`–`0x0115041B`，在其他 UI/玩法检查通过后，`0x0115038A push 2 → 0x01150416 call 0x0138AE10` 进入倒计时状态。即普通单人死亡与组队全灭均可能进入状态 2；组队尚有存活成员则走状态 0/1。领地战走另一条界面分支，本报告不将普通倒计时规则套用给它。
5. **Confirmed，协议交互边界：** 客户端普通倒计时由 `NOTI 0x0020` 下游将死亡界面置于状态 `2` 驱动。`CMD 0x0028` 注册的响应入口 `0x02231720` 是单字节 `ret`，也是其他协议共用的空 handler，没有专有 ACK 动作可启动倒计时；注册本身不能推出死亡上报必须有 ACK（通用分发副作用另论）。本次服务端未处理 `CMD 0x0028` 死亡上报，因而没有发出 `NOTI 0x0020` 生死状态通知，应先接通死亡上报到状态通知。`CMD 0x0029` 才是复活请求。
6. **Confirmed，附带交叉核对：** `0x0138A320` 在 `elapsedMs > 9999` 且对象 `+0x54` 标志非零时，经 `0x0138A4F2` 的 `push 0; push 0x2A` 和 `0x0274D1E0`/`0x0274E6D0` 走 `CMD 0x002A` 发送。该 UI 对象构造 `0x0138A960`、关闭 `0x0138AE71` 与普通状态设置尾部 `0x0138B32A` 均清 `+0x54`；本次离线搜索未定位到可信的置非零写者，所以不能断言每次到期必发送 `0x002A`。`CMD 0x007B` 的构包入口 `0x010CBBE6` 明确使用 `push 0x7B`，与上述倒计时到期路径不同。

## VMP 覆盖与剩余边界

本次没有在 `.vmp1` 节停步。死亡 handler 的 `0x0114F818`、`0x0115049C` 调 `0x0526AB41`；直接反汇编得 `mov eax,[ecx+0xC4]; sub eax,[ecx+0xC0]; sar eax,2; ret`，确认为四字节元素向量的元素数，因此两处循环上界不是未知虚拟机行为。`0x0114F6F5` 还调入 `.vmp1` 的变形函数 `0x052E5931`；用 lab 的 `symeval.py` 对离线 `DNF-memory-rva.bin` 跟踪至 `ret`，但返回地址/副作用表达式仍不可靠，故不赋予它死亡业务含义。主要倒计时状态门、计时公式和绘制回调均在可读的 native 指令中独立成立。

未解析的关键边界：领地战的另一条界面路径，以及倒计时对象 `+0x54` 何时置为非零。上述结论均是静态客户端证据，尚无本次死亡会话的逐帧/界面差分验证，不能升级为 `ClientVerified`。下一次最小实机验证是在服务端接通死亡上报后，以同一套抓包与界面观察分别覆盖普通单人死亡、组队尚有存活成员、组队全灭；每种情况核对 `0x0028 → 0x0020`、UI 状态对应的倒计时可见性，并在超过 10 秒后记录有无 `CMD 0x002A`。领地战只在需要支持该模式时另测，不应以普通模式结果代替。
