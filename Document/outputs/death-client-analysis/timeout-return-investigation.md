（SHA-256 `DC322D8FB2A8A33FCE31065CEEAC5801ED854F34409190FE257AACF2663306E9`，ImageBase `0x00400000`，
下列地址均为 VA），交叉核对镜像 `dumps/dnf-dump-20260912-222635-726-46724/DNF-memory-rva.bin`。
未启动/停止服务，未操作游戏进程，未修改任何代码。工具：`Document/_pickup_workbench.py`
（capstone 线性/入口对齐反汇编 + E8/E9 调用者全扫 + 字节模式扫描）。

## 一句话结论

**`+0x54` 的置位者找到了：`0x01705500`（`mov byte ptr [ecx+0x54],1; ret`），唯一直接调用点
`0x01150208`，位于 NOTI 0x0020 死亡下游的领地战（territory combat）分支。普通地下城的全灭分支
把倒计时 UI 置为状态 2 但从不调它——普通模式下倒计时到期后客户端本地什么都不做是设计行为，
回城由服务端在全灭后约 10 秒主动推送回城序列完成（§5、§6）。**
当前服务端没有实现这件事，所以观察到的"倒计时结束、无 0x002A、只剩心跳"与客户端静态结构完全一致。

**2026-09-21 修正**：初稿曾把"全灭会发送 0x007B"与"0x007B 是普通全灭计时器的请求端"连在一起，
该联系不成立，已在 §5/§8 修正——普通模式的 PartyWipe 计时器由 0028 处理直接创建，
**不依赖收到 0x007B**；0x007B 在普通模式被参照服忽略（无 CombatDeathRespawn 票据即返回），
它只是客户端在三种"本局结束"场景都会发的统计上报（§8）。

## 2. `+0x54` 完整读写清单（全镜像普查）

普查方法：对 `.text` 全量扫描 `mov byte [reg+0x54], imm8/reg8`（disp8 与 disp32 编码）、
`inc/dec/or/xor/and/add` 的全部字节写形式，再用"从候选地址回看是否落在真实指令边界"甄别；
另对 getter `0x02300BC0` 的全部 54 个调用点做后向 40 条指令窗口检查；最后对 setter
`0x01705500` 做全 exec 区段（含 `.vmp0/.vmp1/.­wI` 等）的 E8/E9 直接引用与 dword 指针引用扫描。

| 地址 | 操作 | 所在函数 | 条件与业务含义 |
|---|---|---|---|
| **`0x01705500`** | **写 1**（`mov byte ptr [ecx+0x54],1`，两指令函数） | 自身即"arm 自动回城" setter | **唯一非零写者**。唯一直接调用点 `0x01150208`：NOTI 0x0020 死亡下游的**领地战分支**，紧跟 `0x0138AE10(2)`（置倒计时状态）之后，`ecx` 为本对象。扫描覆盖范围内无其他引用（见下行） |
| `0x0138A960` | 写 0 | 构造 `0x0138A8D0` 尾 | 初始化为"不许自动发送" |
| `0x0138AE71` | 写 0 | `0x0138AE10`（状态设置）arg==0 尾 | 关闭倒计时时 disarm |
| `0x0138B32A` | 写 0 | `0x0138AE10` arg!=0 长路径尾 | **任何非零状态设置都 disarm**（含 arg==2） |
| `0x0138A524` | 写 0 | `0x0138A320` 倒计时到期发送之后 | 发送一次后 disarm（防重发） |
| `0x0138A4C4` | 读（cmp 0） | `0x0138A320` 到期门 | 见 §3 |

"唯一"的覆盖范围（2026-09-21 收窄表述）：`.text` 全量 E8/E9 直接引用扫描、全部 exec 区段
（含 `.vmp0/.vmp1/.­wI` 等）与数据区段的 dword 字面引用扫描、0x02300BC0 getter 全部 54 个
调用点的后向窗口检查。**经寄存器传址的间接调用与 VM 加密立即数不在覆盖内**——该边界与 §2 末段
的 VMP 残余说明相同，不改变主结论（普通模式分支在 native 路径上就没有 arm）。

未被此清单覆盖的残余可能性只有一种：`.vmp1` 内某个 VM 函数以加密立即数构造 `0x01705500`
或等价写。这一点静态无法排除（VM 立即数含运行期 VIP，见 lab `a21-vmp1-instruction-set.md`）；
但即便存在，它也不改变本报告的主结论——普通模式分支**在 native 路径上**就没有 arm，
且实机观察（倒计时出现、到期无动作）与"未 arm"完全一致。lab 的 `vmp1-walk-a21.jsonl`
不含 native 调用目标记录，无法用作反证，如实记为边界。

## 3. 倒计时与 CMD 0x002A 的完整触发链

### 3.1 帧回调（每帧）

`0x0138B360`（vtable[0]，创建时注册进回调列表 `0x02320DF9`→`0x087E3D0`）：

1. `[ebp+8] != [this+0x24]`（owner 不匹配）→ 返回；
2. `0x1389E90()` 假 → 返回；
3. **`+0x4C != 0` 且游戏存在且 `0x163E1E0(game)==1`（村庄）→ `0x0138AE10(0)`**——服务端把玩家
   送回城镇后，倒计时 UI 在下一帧自动关闭（`0138B3BD`，arg 0）；
4. **`+0x4C == 2` → `0x0138A320`**（倒计时更新/绘制）。

### 3.2 倒计时更新 `0x0138A320`

- `0x0138A36C`：`0x27C3660(&this+0x30)` 取已过毫秒；`sec = clamp0(floor((9999-elapsed)/1000))`
  （乘 `0x10624DD3` 右移 6 的除 1000 实现），用 `coin_countdown.img`（字串 `0x0328E450`，前报告已解）绘制；
- `0x0138A49C`：秒数变化时（`[this+0x50] != sec`）经 `0x1648A20` 播放滴答音并记 `+0x50`；
- **到期自动发送门（`0x0138A4C4`–`0x0138A524`）**：
  1. `cmp byte [esi+0x54],0; je 结束`——**未 arm 直接跳过，本地无任何动作**；
  2. 再读计时器，`9999-elapsed >= 0`（未到期）→ 跳过；
  3. `0xA9AA30()`（领地判断）为真时额外做 `0xAA6B90→0x0AAA2F0`；
  4. `push 0; push 0x2A; call 0x0274CA50`（构包，body 空）→ `0x0274D1E0`（发送）；
  5. `0x01102C30→0x0119B940→0x0119B2B0` 取某 UI 对象 → 非空则 `0x017238F0`（关闭它）；
  6. `0x0274E6D0`（flush）；`mov byte [esi+0x54],0`（disarm）。

即：**`+0x54` = "倒计时到期后自动发 CMD 0x002A（GIVEUP_GAME，空 body）"的许可位**。
CMD 0x002A 的响应 handler 为 `0x01105CC0`（注册点 `0x0110C31F`，另有第二表 `0x01188823`→`0x01160360`）：
result==0 全跳过；成功则弹本地化提示（串表 `0x3240BA8/0x3240C38/0x3240C88`）、执行同一条
`0x0119B940→0x0119B2B0→0x017238F0` UI 关闭链，再按游戏状态（9/0xD/…）调兄弟窗口接口。

### 3.3 状态设置 `0x0138AE10`（`ret 4`）

- arg==4：**不改 `+0x4C`、不重置计时器**，仅重算语音行并 disarm（"刷新"语义）；
- 否则 `+0x4C = arg`，`0x27C3410/0x027C3B60` 重置计时器；
- arg==0：设 `[edi+0x50]=-1`，`0x02304790(0x40,-1,0)` 播音，`0x0138AE71` disarm；
- arg!=0：一长串模式/成员检查（`0x163E1E0` 游戏状态、`0x164B880`、`0xA9AEE0→0x2706970→0x19E7970`、
  成员 flags `+0x308/+0x334/+0x360/+0x368/+0x438/+0x440/+0x44C/+0x314`、复活队列 `0x1729F00/0x1729F80`、
  观战数 `[+0x5C4]`、`0x63BBA0`、串表计时 `0x3B3E19C` 等）折算出语音行号 esi∈{0,1,2,4,6,7,8,9,A,B,C,D,E}，
  `0x02304C70` 播报；尾部（arg!=4 时）`[edi+0x50]=-1`，`0x0138B32A` **disarm**。

### 3.4 NOTI 0x0020 死亡下游（handler `0x0114F420` 内，`0x011500A0` 起）

1. `0x011500D0`：state==0 → `[vtable+0xB10](char, 1)` 写角色死亡位（`this+0x57FA`）；
2. `0x011500EA`：`0x0A75300()`（= `0xA9AA30` 封装：`CNGame+0xF48==0x1B` 领地战）：
   - **领地真** → 串表 `0x3B3E190` 查值，`[ebp-0x2D4]`（NOTI actorId）等于该值且本人 IsDead
     （`[0x3B3DFB8]` vt+0xB14）且两道兄弟窗口门（`0x02300BF0→0x2846D50`、`0x02300C00→0x1A182F0` 均为 0）
     → `0x011501F6` `0x0138AE10(2)` → `0x01150208` **`0x1705500(UI)` arm**；
   - **普通模式** → `0x01150212` `0x019E7380(1)` 数存活：
     - 存活>0：遍历 8 槽做可见性处理；本人已死且门通过 → `0x01150301` `0x0138AE10(1)`（无数字），
       否则 `0x0138AE10(0)`；
     - **存活==0（全灭）**：`0x0115030B` 四道门 → `0x01150373` **`0x10CBBD0()`（发 CMD 0x007B）** →
       `0x11038E0()` 配置开关：假 → `0x01150416` `0x0138AE10(2)`（倒计时，**不 arm**）；
       真 → 走消息框 `0xE4B/0xE4C` + `0x02300930(1)→0x1331350` / `0x02300930(0)→0x1343D30` 的另一套 UI（无倒计时）。

`0x11038E0` 读全局 `0x3A5C980` 的配置位（`+0x39C+4` 映射查询），决定全灭时用倒计时还是消息框，
具体游戏含义未命名（ Hypothesis：某活动/引导开关）。普通实测出现了倒计时，说明本环境该开关为"假"。

### 3.5 CMD 0x002A 的三个发送端与 CMD 0x007B 的唯一发送端

全镜像构包点普查（`call 0x0274CA50` 前取 type 实参）：

| type | 构包点数 | 关键点 |
|---|---|---|
| 0x002A | 30 | `0x0138A4F6`（倒计时到期，**仅领地 arm 后可达**）；`0x023D7BC8`（死亡对话框按钮 1）；`0x13A7A51` 等（用户主动放弃族：先 `0x10CBBD0()` 发 0x7B 再发 0x2A，见 `0x013A79FB`–`0x013A7A58` 样例） |
| 0x007B | **1** | `0x010CBBE8`，在 `0x10CBBD0` 内。body = 6×u32：`[0x3A390CC]`、`[0x3A390D0]`、前两者之商（除 0 取 0）、`[0x3A390D4]`、`[0x3A390D8]`、`[0x3A390DC]`。入口门 `0xE13B70` = `mov al,1; ret` 恒真 |
| 0x0029 | 3 | 已知（复活请求），不赘述 |

`0x10CBBD0` 的调用者：`0x42D8FC、0x4CD796、0x635569、0xAAC0A9、0xAAF3FC、0x11499B7、
0x1150373（全灭分支）、0x13A7xxx 族、0x23DE410`——除两个例外，其余全部紧跟一次 0x2A 发送；
两个例外是 **0x1150373（全灭分支）**与 **0x11499B7（NOTI 0x001F `ENABLE_CLEAR_DUNGEON`
handler `0x01149950` 内，通关结算路径）**——它们只发 0x7B、不发 0x2A，把"接下来去哪"留给服务端。
0x7B 的语义定性见 §8。

死亡对话框（vtable `0x035C35FC`，窗口资源 0x283，构造 `0x023D7E80`，回调 `0x023D7BB0`）：
按钮 0 → 查 `[0x3B3DFB8]` 链取目标 actorId → 发 CMD 0x0029（u16 目标）；按钮 1 → 发 CMD 0x002A（空）
+ 同一条 UI 关闭链 + `0x023B8010` 关窗。这是**手动**回城路径，与倒计时无关。

## 5. 参照服的两套计时机制（2026-09-21 重写）

以下来自参照服 `ServerS4A21` 源码（`DungeonCombatHandler.cs` / `DungeonInstance.cs` /
`DungeonInstanceRegistry.cs` / `GameProtocolHandler.cs`），**是参照行为，不是客户端取证**。
客户端侧只 Confirmed 到"到期无本地动作 + 等待 + 游戏状态回村庄时 `0x0138B360` 自动清 UI"。

`HandleDieCharacter`（0028）先按 `ResolveCharacterDeathFlow(suppressRespawn, isTower, isTournament)`
分流，再广播 NOTI 0x0020。两条计时路径由此分岔：

| | **PartyWipe 计时器** | **CombatDeathRespawn 计时器** |
|---|---|---|
| 粒度 | 实例级（`DungeonInstance`），名字 `dungeon-party-wipe:<instanceId>` | run 级票据（`DungeonRunTimerKeys.CombatDeathRespawn`），名字 `dungeon-death:<session>:<run>:<gen>` |
| 创建者 | `SchedulePartyWipeIfNeededAsync`（`HandleDieCharacter` 的 **default/PartyWipe 分支**，:301）；另外参与者断线移除时 `DungeonInstanceRegistry.RemoveParticipantLife` 也能经 `_partyWipeStarted` 回调启动（断线不阻断全灭结算） | `ScheduleDeathRespawn`（**仅 Tournament 分支**，:298）；重连时 `RecoverDeathRespawnTimer`（`DungeonHandler.cs:311`）恢复票据 |
| 启动条件 | `MarkParticipantDead` 判定该实例**全部活跃 run 均死亡**（`WipeStarted`）；单人即首死即启动 | 角色死亡即设 `IsWaitingDeathRespawn=true`、`DeathRespawnAvailableAt=now+10s` |
| 时长 | `PartyWipeDelay = 10s`（`DungeonInstance.cs:899`） | `DeathRespawnDelay = 10s`（`DungeonCombatHandler.cs:33`） |
| 客户端 0x007B 的作用 | **无。**`ResolvePartyWipeDeadlineAsync` 全程不查询任何 0x7B 状态；到期直接 `TryCommitPartyWipe` → 逐参与者回城。普通模式下客户端发来的 0x7B 走 `HandleDeathRespawn`，因无票据在 `TryGetCurrentTicket` 处被拒（日志 "no active timer"）后**忽略** | 可作提前解算请求：未到期记 "delayed Nms" 返回；到期则立即走 `ResolveDeathRespawnDeadlineAsync(force:false, source:client)`。服务器自己的计时器到期则 `force:true` |
| 到期出口 | `ResolvePartyWipeDeadlineAsync` → 每个在线参与者 `TownReturn.ReturnAsync(..., DeathRespawn, successAckPacketType: 0x007B)` | `ResolveDeathRespawnDeadlineAsync` → 同一个 `TownReturn.ReturnAsync(..., 0x007B)` |

**两套机制共享回城出口** `TownReturn.ReturnAsync → ProjectEndedRunAsync`，但相互独立创建、
互不触发。因此：

> **普通副本的自动回城不依赖收到 0x007B。**（Confirmed，参照服调用链：0028 →
> SchedulePartyWipeIfNeededAsync → SchedulePartyWipeTimer → 时钟回调 → ReturnAsync；
> 链上没有 0x7B 节点。）

`ProjectEndedRunAsync` 的发送序列（参照）：
`NOTI 0x0003`（用户状态→城镇，`session.Player.UserState = 0x00` 先行）→ 城镇在场投影
（或 `NOTI 0x0017` + `NOTI 0x0018`）→ `CMD 0x007B` 成功 ACK（body `01`）→
`NOTI 0x00CA`（body `00`）→ `NOTI 0x0002` subtype0 广播 → 婚礼回放刷新。
发送前后反复以 `CanProjectEndedTownState` 校验会话仍是该 run、已无副本选择——
**服务端生命周期同步（EndRun、取消票据、清 CurrentDungeonSelection）是序列的一部分**，
不是可选装饰。

本服现状对照：`0x7B` 已解码为 `CharacterStatisticReport` 但无应答（Debug 日志还被级别过滤）；
手动放弃路径（`GiveUpGameHandler`）已发 `0x2A ACK + 0003 + 0017 + 0018`（stage1 日志可证，
且回城后用户在城镇继续聊天操作，说明客户端确实完成切场景）；缺的是**死亡侧的全灭计时器与
主动推送**。这不是"用服务端计时器绕过问题"——客户端静态结构表明服务端推送就是普通模式的设计机制。

## 6. 回城序列逐消息的客户端作用（2026-09-21 新增）

NOTI 注册表锚定：以目录已核对过的 handler（NOTI 0x0020→`0x0114F420`、NOTI 0x005F→`0x0114DCE0`、
NOTI 0x00E4→`0x011612D0`）定位到 NOTI 批次注册族（`0x0115Fxxx` 与 `0x0119A780` 起的 149 项批次），
取出回城序列各 type 的 handler 并整函数走读：

| 消息 | handler | 读取与主要作用 | 对四项收尾的贡献 |
|---|---|---|---|
| NOTI 0x0003 | `0x01191B30` | body = `u8 count + count×(u16 characterId, u8 state)`；逐项 `0x19E2EF0` 找角色、写入角色配置 `+0x1C`、父窗口两处刷新、非 {0,4,5,6} 状态时更新队伍列表；末尾若 run 上下文与窗口条件成立再触发一个窗口动作（`0x9C06E0`） | **不切场景**。只设用户状态字段（城镇/空闲 = 0）及派生 UI |
| NOTI 0x0017 | `0x011922A0` | 序言即执行 `0x0119B940→0x0119B2B0→0x017238F0` 关窗链；body = `u16 id + u8×2 + u16×2 + u8×2`；与新区域比较，不同则 `0x191E450(场景管理器, 0, 0x12, id, …)` **投递场景切换事件（0x12）**并更新全局区域状态；两道前置门：`0x1A09CF0`（过场/演出活动时整帧跳过）、游戏状态==5（加载中，仅 0018 有此门） | **场景切换的驱动者**；同时提前关掉全屏窗口 |
| NOTI 0x0018 | `0x01193590` | 区域内用户列表（在场实体的生成/更新）；有 游戏状态==5 与 0x1A09CF0 两道门 | 在场同步，**非场景切换**；单人回城时主要是内容性 |
| NOTI 0x00CA | `0x01194CD0` | 村庄物件列表（u8 + 0x50B 字段 + …），生成村庄静态物 | 村庄内容渲染，非状态 |
| NOTI 0x0002 | `0x013E91E0` | u8 subtype 分发（==4 特例、==0 主路径），全量用户信息更新 | 在场/角色信息同步（参照服注释：好友侧看场景状态变化） |
| CMD 0x007B 响应 | **无注册**（全部 943 个 `0x0163C4A0` 注册点按 imm8/imm32/宽松窗口三种方式复查，0x7B 零命中；目录普查同结论） | 仅通用分发层：`0x0274D880` 未决计数减一 + `0x0274DDD0` 成功计数 | **无任何回城作用**（见 §7） |

对四个具体问题的回答：

1. **游戏状态切换为村庄**：不在任何单个 handler 里显式赋值，而是 NOTI 0017 → `0x191E450`
   投递场景事件 0x12 后由场景管理器状态机流转（加载中/村庄）。倒计时 UI 的关闭依赖的
   "游戏状态==1"（`0x0138B360`→`0x163E1E0`）由此满足。状态流转的具体赋值指令未逐条还原——
   边界如实记录，不影响"0017 驱动"这一因果（切场景调用只有 0017 路径上有）。
2. **地图加载/场景切换**：NOTI 0017 独占（`0x011924C1`）。0003 只设字段、0018/00CA/0002 都是
   切换后的内容同步。**"仅改变用户状态不足以切场景"——Confirmed（0003 handler 全函数无
   场景调用）**。
3. **本地死亡角色状态恢复**：死亡标志（角色 vt+0xB10 → `+0x57FA`）在五个回城 handler 里
   **均无写入**（逐个扫描 `+0xB10` 引用为零）。已知的清零途径只有 NOTI 0x0020 复活分支
   （state 1/2）。回城后表现恢复（站姿、可动）最可能来自场景切换时地图 actor 重建；
   roster 标志是否残留未证实。影响面评估：`0x019E7380`（数存活）遍历的是**当前副本**的
   槽位，重进副本时 roster 重建，残留不跨 run——列为实测观察点（回城后 UI 是否完全正常）。
4. **死亡倒计时 UI 关闭**：两条独立路径——NOTI 0017 序言的关窗链（立即），与场景状态到
   村庄后 `0x0138B360` 的 `0x0138AE10(0)`（下一帧）。后者已证，前者随 0017 必然发生。

**发起者必须收到的回城消息 vs 广播**：0003（本人状态）与 0017（本人区域移动）是发起者
收到的核心两条；0018 是区域内在场列表（本人也会收，但服务于"看到别人"）；00CA/0002-subtype0
是村庄内容与好友侧投影。参照服的发送清单 ≠ 客户端必需清单——按静态分析，**最小集是
0003 + 0017**（0018 影响进城后能否正确显示其他玩家，单人场景可后补）。此"最小集"仍是
静态推断，需 §11 的 V2 实测确认。

**主动回城（服务端推送）与手动 002A 回城的前置差异**：差异全部在**发送侧**（对话框状态
`[this+0x18C]`、ESC 菜单的门、领地 +0x54）；**接收侧同一套 NOTI 序列，无不同前置**。
手动路径额外先收到 CMD 0x2A 响应 → `0x01105CC0` 弹提示并关窗（表现层），随后 NOTI 序列照常。
即：服务端推送路径少一条 0x2A ACK 也能完成切场景——ACK 不是切场景的必要条件。

## 7. 通用分发计数与 ACK 的关系（排除项收口）

- `0x0274D880`（收帧侧 `0x0163BF5E` 调用）：连接对象 `+0x2BD094` 映射按 type **递减未决请求数**；
- `0x0274DDD0`（`0x0163BFA3`）：`+0x2BD0A8` 映射记成功/失败；
- 发送侧 `0x0274ED82`–`0x0274EDA5`：`inc [map]` + `inc [conn+0x2BCC38]`（总发送数）；
- 读侧消费者全镜像仅三处：`0x0199010`/`0x0199102B`（**type 0x13** 的失败/未决查询，重连逻辑）与
  `0x0110DC60`（小型报表）。

结论：这组计数是连接级 per-type 统计，唯一业务消费者是 0x13 的重试判断，**与死亡 UI、
`+0x54`、0x2A 发送门无任何数据流连接**。"补 ACK 是否 arm 自动回城"的答案是：不 arm
（ACK 只影响计数与专用 handler `0x02231720`=ret）。两次实机（无 ACK / 有 ACK）行为一致，
与该结论互相印证。此前两版推断（"注册 handler 就必须回" vs "handler 是 ret 所以回不回都行"）
就此收口：回不回 ACK 只通过这组计数产生可忽略的副作用，不影响回城。

## 8. CMD 0x007B 的语义界定（2026-09-21 新增）

**发送端三场景**（全部静态核实，调用链：场景入口 → `0x10CBBD0` → 门 `0xE13B70`（恒真）
→ `0x274CA50(0x7B)`/`0x274D1E0`/六个 `0x274D340` → `0x274E6D0`）：

| 场景 | 调用点 | 随后是否发 0x2A | 后续 |
|---|---|---|---|
| 全灭（普通/领地的 NOTI 0020 下游全灭分支） | `0x01150373` | 否 | 显示倒计时（state 2），等待服务端 |
| 通关结算（NOTI 0x001F `ENABLE_CLEAR_DUNGEON` handler） | `0x011499B7` | 否 | 打开结算画面，等结算序列 |
| 用户主动放弃（ESC 菜单族/对话框确认族） | `0x42D8FC、0x4CD796、0x635569、0xAAC0A9、0xAAF3FC、0x13A7xxx×8、0x23DE410` | **是**（紧邻 +9 字节处） | 等 0x2A ACK + 回城序列 |

body 为 6×u32（`[0x3A390CC]`、`[0x3A390D0]`、两者之商、`[0x3A390D4]`、`[0x3A390D8]`、
`[0x3A390DC]`，全程累计型全局；实帧样本 `32 00 00 00 01 00 00 00 32 00 00 00 31 …` 即 50/1/50/49/0/0，
与"命中/总数"类比率形态一致）。

**定性（区分三个证据等级）**：

- **构包调用已执行**：三场景全部 Confirmed（静态指令级）；
- **发送函数已调用**：同上 Confirmed——门恒真，无其他出口；
- **真实网络帧已观察**：**仅通关场景有 1 例实帧**（2026-08-26 采样，记于
  `protocol/game/client-to-server/0x007B.md`：结算画面打开时一次，参照会话收 1 回 0）。
  全灭与主动放弃场景的 0x7B **尚无实帧记录**（本服日志因 §10 所述级别过滤不可见；
  主动放弃场景在本服同样无观察）。

**结论**：0x7B 是"本局结束统计上报"——在客户端本地判定本局结束的每个时机（全灭/通关/放弃）
都会发送一次；它**不是**专门的离开请求（三场景中两个根本不伴随任何离开指令）。
"特定场景兼作离开信号"只能描述**参照服的服务端解释**（锦标赛路由），不是客户端语义。
客户端没有为它注册任何响应 handler（§6 表），服务端回不回 ACK 只影响通用计数。
原版官方服务器如何使用它，本报告不试图回答——静态证据到此为止，如实定为边界。

对服务端方案的含义：**可以继续按 UnansweredReport 处理（不回）**；若为了对齐参照行为在
回城序列尾部补发 CMD 0x7B 成功 ACK，其客户端效果为零（仅计数结算），不是回城的必要条件。

## 9. 已排除的歧路（记录以免重走）

1. `parent+0x8FA0/0x8FA4/0x8FA8` 的 disp32 命中（12 处）——是父窗口**兄弟指针字段**的访问
   （`mov ecx,[esi+0x8fa8]` 等），不是对象内 `+0x4C/+0x50/+0x54`（对象经指针挂载，无内联）；
2. 全镜像 `mov byte [reg+0x54],1` 的 66 处 imm8 候选 + 24 处 reg8 候选 + 22 处 inc/or/xor/add 形式
   ——逐一验证指令边界后全部属于其他类（BuffSystem/EventSystem/Dungeon/Coupon/CardGame 等）自己的 +0x54；
3. `0x0114E53E` 这个第三个 `0x0138AE10(2)` 调用点——属于 **NOTI 0x005F `WARROOM_DIE_STATE`**
   handler `0x0114DCE0`（注册点 `0x0115F692`，3×u8+2×u16，`0x114E471 jle→push 2`），
   是另一模式的死亡传播，同样不 arm；
4. CMD 0x0028 响应注册 `0x0110C2FF` → `0x02231720` —— 该地址同时是本 UI 类 vtable[1] 的空槽，
   即共享空 thunk，坐实"无专有 ACK 动作"。

## 10. 证据边界（如实声明）

- **服务端日志不是客户端全量明文抓包**：入站帧只在未注册（warn）或 handler 记日志时可见；
  `UnansweredReport` 家族（含 0x7B）是 Debug 级被 Information 默认级别滤掉。因此"客户端是否发了 0x7B"
  当前**无法从现有日志证实或证伪**——静态上它必然发（门恒真、分支已到，倒计时出现即为到达的证据）。
- VMP 残余：`+0x54` 的 VM 内写者静态不可穷尽排除（加密立即数）；不影响主结论（见 §2）。
- 本报告所有客户端结论为静态（含与 dump 交叉核对），尚未 ClientVerified。
- 参照服行为仅作协议流参照（AGENTS.md 对 `Docs/` 参照类资料的边界要求同样适用于直接读
  `ServerS4A21` 源码——其语义命名以本仓取证为准）。

## 11. 可实施结论与最小验证矩阵（未执行，待批）

### 已证实的客户端回城触发链（静态，本报告）

全灭 → 客户端发 0x7B（统计）→ 倒计时 state 2（不 arm）→ 到期无本地动作 →
**等待服务端推送**；收到 `NOTI 0017`（区域移动）→ 关窗链 + `0x191E450` 场景事件 0x12 →
加载/切村庄 → 游戏状态到村庄 → `0x0138B360` 下一帧 `0x0138AE10(0)` 关闭倒计时。
`NOTI 0003` 先行设置用户状态字段。**CMD 0x2A ACK 与 CMD 0x7B ACK 都不是该链的节点。**

### 普通全灭计时器最合理的起点

服务端在**处理 CMD 0x0028 并广播 NOTI 0x0020 时**（而非收到 0x7B 时）判定全灭并起算
10 秒。证据来源：参照服调用链（§5，Confirmed-参照）+ 客户端 9999ms 倒计时的对齐关系
（设计一致性，High）。0x7B 在该机制中无角色（§8）。

### 最小候选消息序列与逐条必要性证据

| 消息 | 必要性 | 证据 |
|---|---|---|
| NOTI 0x0003（count=1, 本人的 id, state=0） | 预期必要（状态字段是后续 UI/逻辑输入） | 静态：handler 只设字段；必要性未单独实证 |
| NOTI 0x0017（本人 id + 村庄区域字段） | **必要**（唯一的场景切换驱动） | 静态 Confirmed：`0x011924C1` 是序列中唯一的 `0x191E450` 调用点 |
| NOTI 0x0018 | 非必要（在场列表；单人场景为内容性） | 静态：无状态切换动作 |
| NOTI 0x00CA / NOTI 0x0002 subtype0 | 非必要（村庄内容/好友投影） | 静态：无状态切换动作 |
| CMD 0x7B 成功 ACK | 非必要（无响应 handler） | §6/§8 |
| CMD 0x2A ACK | 非必要（仅手动路径的表现层提示） | §6；推送路径本来就没有请求 |

服务端必须同步的生命周期（不能只推画面）：结束 run/实例、清理副本选择与在场注册、
取消一切未决票据——参照服以 `EndRunAsync` + `CanProjectEndedTownState` 双向校验实现（§5）。
**这些是参照服行为**；本服等价物（`LeaveDungeonSlice` 等）已存在于手动放弃路径。

### 仍是参照服行为或推断的结论清单

- 10 秒时长与"最后死亡起算"：参照服参数 + 客户端倒计时对齐（推断，未实机比对到期时刻）；
- 序列顺序（0003 先于 0017 等）：参照服顺序；静态未见 0017 依赖 0003 的硬约束（推断）；
- 0018/00CA/0002 的"进城后再补也行"：静态推断，未实测缺帧表现；
- 0x7B 的三场景中两个（全灭/放弃）无实帧记录。

### 最小实验矩阵（按区分度排序）

| # | 实验 | 区分什么 | 预期（若模型成立） |
|---|---|---|---|
| V1 | 服务端把 `UnansweredReportHandler` 日志类别开 Debug，单人普通本死亡、不操作 | 全灭分支是否真的发出 0x7B（实帧级） | 死亡同秒出现 `GameCharacterStatistic body(24B)` |
| V2a | **测试版服务端**在全灭 +10s 推送 `0003 + 0017`（仅两条），同步走完 run 结束生命周期 | 最小集是否足以切场景/关倒计时 | 客户端回村庄、倒计时消失；若缺 0018 导致他人不显示，属预期内差异 |
| V2b | 对照组：同上但只推 `0003` | 0003 单独是否足够（直接验证"仅状态不足"） | **不切场景**、倒计时残留——与静态结论互证 |
| V3 | （V2 通过后的正式实现）完整序列 + 0x7B ACK + 00CA + 0002 | 对照参照顺序的行为等价性 | 与 V2a 无客户端可见差异（ACK 无效的运行时复核） |

次数下限：**V1 + V2a + V2b 共三次受控实验**即可把剩余候选（0x7B 实帧、最小集、0003 不足）
全部区分；V3 属实现验收不属取证。领地路径（arm→自动 0x2A）本环境不可达，不测。

**升级规则**：V2a"收到推送后成功回城"只证明**方案可用**，不证明"原版服务器机制如此"——
后者在本报告的证据体系里永远停在"参照服 + 客户端静态结构"这一级，除非获得官方服务器观测。
表述时不得混用。
