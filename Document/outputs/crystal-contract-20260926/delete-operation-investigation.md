# DELETE_ITEM operation=2 调查

2026-09-26。只读客户端调查；未修改、重启或回滚当前服务器。

镜像 SHA256：`d7618a102251f1db724f2514c74a4cc855df26e6a4bc308f8ee9f2397db0a99a`，ImageBase=0x400000。本页地址全部为 VA。脚本与逐指令输出见同目录 `inspect-delete-operation.py`、`delete-operation-static.txt`。

## 结论

**operation=2 至少明确用于技能所需材料消费，不是“任意材料均可删除”的标志，也不是无色专属枚举。** 客户端原生材料消费辅助函数固定传2，列表由技能材料检查生成。该原生辅助函数未发现其他直接E8调用者，但不能据直接调用扫描排除虚表、指针或VMP中的间接路径。

## 指令链

1. `0x018983F0` 诊断字符串解码为 `IRDCharacter::useSkill`，另有 `Error - Character Use Skill In Town Module`。其材料检查调用点 `0x01898A26` 调用 `0x01870B80`，检查成功及其他条件满足后，`0x01898A49` 调用 `0x01836720`。此函数含VMP段；这里只采用明确的原生调用片段，不声称全函数控制流已反虚拟化。
2. `0x01870B80` 自带字符串为 **IRDCharacter::checkSkillNeedItem**。`0x01870C8B` 生成材料列表，随后按8字节条目遍历物品ID与数量，查物品对应槽及现有数量，`0x01870ECB` 将槽号和需求数量加入输出列表。并非固定只请求3037。
3. 无色3037 (`0xBDD`) 在 `0x01870D81` 另有分支；`0x01870D89..92` 设置安全跳过索引1。解码字符串为 `setCurPassPadSkipIndex(SAFE_MODE_SKIP_MOOCU_SKILL)`。因此 safeMode=1 是无色技能上下文证据，不宜当作所有技能材料的必填值。
4. `0x01836720` 检查列表非空、选择物品管理器，`0x01836747 push 2; push eax; call 0x016FDFC0`。另一直接调用者 `0x01612CD0` 同样先调上述技能材料检查，再于 `0x01612DE6` 调此函数；该调用者的完整业务名称尚未定名。
5. `0x016FDFC0` 是 `CNRDItemManager::requestDeleteItems`。第二个参数 `[ebp+0xC]` 为操作原因，入口对2有专用前置分支。`0x016FE229..234` 将此参数作为每条entry的u16写入0012。它按列表写条目，故客户端具备多材料请求形状，当前服务端19B单条解码尚未覆盖它。
6. `0x016FE3E6..40E` 读取安全上下文写末尾u8并清零；与操作原因是两个独立字段。

以上原生指令与解码名称为 ClientStatic。服务端本次实帧日志（`artifacts/material-consumption-20260926/server.stdout.log`）记录 Main/358、3037、数量1或2、entries=1、operation=2、reserved=0、safeMode=1，随后因OperationType拒绝；这是该具体无色技能路径的运行证据。

## 旧文档修正

旧探针将 `0x012FDFC0` 当作地址直接描述，它实际是本镜像的 **RVA**，对应VA `0x016FDFC0`；同组0x012FE...也应加ImageBase。其 `0x012FE12D` 实际是BeginCommand调用，不是写operation=1，不能作为普通丢弃原因值的静态证据。普通丢弃=1仍有独立实帧证据。

直接调用枚举另外发现3、4、5传参，业务尚未逐项命名，不能放行。此次也不能把晶之契约消耗直接归入operation=2；它需要独立的调用链或实帧证据。

## 建议边界（未实施）

- 一个0012协议入口按操作原因分派：1走普通丢弃CMD；2走独立技能材料消费CMD。物品归属（账号材料袋/角色背包）是后续路由，不应代替业务原因分派。
- 技能材料消费不归入ItemDiscardDomainService；复用底层容器和账号材料扣除能力，在同一事务中校验身份、槽与物品匹配、正数数量和余额，提交后ACK及绝对数量投影。
- 多entry需先闭合解码、批量原子扣除和回包，再开放；未知原因值继续拒绝。
- 0012没有技能ID，不能独立核对技能等级、冷却、实际耗材公式。关联GameUseSkill上报进行更强校验属于后续设计，本次不伪造该能力。
- 当前已部署69cc7e9a只是“账号无色+operation2”的临时修复，尚未完成上述业务边界拆分。本轮不改生产代码。
