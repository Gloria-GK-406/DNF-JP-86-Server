# A21 特效材料消费与晶之契约 patch

2026-09-26。用户确认operation=1为丢弃、2为技能材料消费、3为特效材料消费；晶之契约作为特效接入原生消费请求。本次没有服务端消费timer。

## 客户端证据与改动

静态镜像：`DNF.unpacked-b1-debug.exe`，SHA256 `d7618a102251f1db724f2514c74a4cc855df26e6a4bc308f8ee9f2397db0a99a`，ImageBase `0x400000`。下表均为VA，插件内部使用RVA。

- `0x00E92E80`：判定premiumType97有效且当前效果装备ID与契约选中的效果装备ID一致，成立返回true。
- `0x00E971C9`与`0x00E9827B`：在材料存在且数量足够之后调用该判定；成立则跳过材料列表追加。这证明**通用特效扣料链主动豁免晶之契约**，不证明全镜像不存在另一条专用上报。
- 第一条链在`0x00E9786E`传入operation=3，于`0x00E97880`调用`0x016FDFC0`（CNRDItemManager::requestDeleteItems），由既有构包器产生CMD0012。
- PVF六种晶体对应效果装备均含`[consume item] 晶体ID 1`；金色为3262。规则含30000ms周期，用户已观察到入图立即获得暴击效果；具体发包频率仍需实帧验收。

独立插件`0170_CrystalEffectConsumption.dll`启动先核对两处完整指令签名，再经宿主patch API写入。签名不符拒绝安装；宿主负责写失败回滚，已安装的相同字节允许重复初始化。不修改磁盘exe，不替换Az，不关闭余额检查，不新增消息，不伪造技能operation=2。

第二处属于另一条效果处理路径；它取消同一豁免，但未据此宣称其自身发送TCP。单人/组队是否重复上报留作实机验收。

## 服务端流程

CMD0012 handler按原因分流：1丢弃、2 ConsumeSkillMaterialsCommand、3 ConsumeEffectMaterialsCommand，其他原因继续拒绝。技能和特效共用材料消费领域服务/规则及结果，类型从SkillMaterial归一为Material。

校验选中会话、角色归属、位置与物品ID、正数数量、余额及普通背包可堆叠属性，分别通过账号材料和普通背包容器扣除。事务及账号/在线用户排他门保证一致性。成功提交后不可重试事件依次发送0012 ACK和000E绝对数量或清槽；失败仅ACK，不投影未提交结果。

### 边界

- 仍只接受19B单条请求。通用构包器的多条材料形状继续拒绝，不截断处理。
- operation=3不是晶之契约专属，故不对整个分支强加premium97资格门。协议不携带效果ID，目前不能验证来源效果、PVF应耗量或精确周期；与技能消费一样接受经材料/归属校验的消费上报。
- 客户端可先执行效果；失败ACK不等于撤销buff，不宣称完整效果权威校验。
- 原未部署timer草稿保存于忽略目录`artifacts/crystal-effect-patch-20260926/timer-draft`，不进入源码或发布包。

## 检查与部署方式

新operation3余额/提交后投影用例在旧实现失败2例，接入后通过。Application相关43例、Protocol相关18例通过；覆盖普通/账号材料、持久化异常回滚、非法报文及既有技能消费/架构边界。插件x86 Release构建与C测试通过；覆盖双地址预校验、签名错误不写、重复初始化及保留call/test；真实静态镜像签名复核一致。

源码在main。同一个ABI2插件用于debug、protocol、protocol2，仅添加此DLL，debug保留原有调试插件。退出客户端移走DLL后重启即回滚，无需重建exe。部署不证明实机正确，当前证据为ClientStatic/ServerImplemented。

## 最小验收

记录金色晶体数量，选择金色契约后单人进图，确认效果出现时是否扣1；原地等待约65秒，记录数量变化并核对日志operation=3、3262、数量1及时间间隔。换房检查异常连扣，再用耗无色技能确认operation=2正常。最后用少量晶体验证耗尽行为，组队确认不重复扣除。实际行为不符时保留帧与日志，不通过新增服务端timer掩盖。
