# 成长契约领主神器掉落调查

日期：2026-09-28。状态：调查完成，待用户确认实施；未修改生产代码、未部署。

## 结论与实施边界

保留本服在生成怪物时预先计算 pending loot 的方式。70 在死亡时计算，二者使用资格状态的采样时刻不同；用户已接受该差异。契约过期或组队变化不追溯修改已经生成的掉落。

领主神器的基础掉落已经由独立掉落表覆盖，缺少的是成长契约的概率加成。建议只对普通怪物来源、领主身份、纯 `boss drop` 神器池施加加成。读取 A21 成长契约的四档参数，按参与者中有效契约持有人数选档，不改池内权重、抽取次数或掉落上限。

该标签限制是本服针对当前 A21 数据及已约定业务范围的适配，不是 70 原始算法中的装备标签判断。

因此，70 直接条目不走此加成分支，APC 领主也不等于普通领主。70 没有在该分支检查装备稀有度或 `boss drop` 标签。70 使用的 type 79 不可直接搬为 A21 类型号。

特殊地下城门的全部业务名称尚未闭合；例如 dungeon+0x89C 不应未经证据命名为远古或深渊。本轮足以实现普通地下城范围，其他模式应保留显式适用范围。

## 建议实现

1. 启动加载时，为独立掉落规则准备“纯领主神器池”元数据，沿用现有缓存；运行期不再反复读 PVF。
2. 契约领域服务封装有效资格和四档加成查询，对外返回加成值；无资格返回 0。
3. 生成掉落时使用上下文的参与者凭证查询资格，仅对普通地下城、普通领主与目标池调整外层阈值；已有静态缓存保持不可变。
4. 沿用现有 pending loot、死亡结算和掉落通知。不新增客户端协议，不修改任务掉落或伤害效果。
5. 对未来出现的混合池单独告警并保守不加成，避免整个池内无关物品被提升；当前数据没有此情况。

验证重点：0–4 个持有人、过期契约、普通怪物/APC/普通领主、材料/故事簿不加成、原权重与次数不变、缓存不被请求修改。低概率实机只能验证流程；概率正确性应由可控随机数测试及模拟统计验证。
