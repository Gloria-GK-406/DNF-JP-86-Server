## 0. 一句话结论与闭环问题回答

**slot3 是客户端自主施加、后置上报、快照防环的服务**：客户端在"选图→普通地下城"模块切换时，
经 13 道门（订阅 end≠0、事件参数 (旧=2,新=3)、场景/守卫、非绝望之塔、无在途、资格三态==3）后，
**先本地给角色挂 7 个 buff 对象**，再发一帧 76 字节 C2S 0x036F（`u16 1 + 74B 块`，块头 u16=3 其余全零，
与实测帧逐字节吻合），并置在途标志 [mgr+0x14]=1；服务端回的全量快照被 ACK handler 整块拷入管理器，
其 slot3 分支被在途标志挡住——**不重施 buff、不重上报，无循环**。在途标志由 NOTI 0x001B
（进入选图）清除，因此**一次地下城恰好上报一次**，下一次进图重新武装。

**闭环问题**："服务端校验并记一次用量，再回 used+1 的完整 036F 快照，是否足以闭环？"
**答：对合法客户端足以闭环**，附四个必要条件（ClientStatic 推导，§5）：
1. 回包总是 **result=1 的全量快照**（74B 权威状态）。客户端对 result=0 的失败应答只打日志
   （`error = %d`），不改任何状态、不清在途标志——失败应答没有任何恢复语义，不要用。
2. **选角/进选图时必须推送新鲜快照**：slot3 资格检查**不过滤过期**（end≠0 即通过，无 now() 比较），
   且 used 只能被快照刷新（无本地增量）——跨日重置/到期收回若不发快照，客户端会继续按陈旧状态触发。
3. 服务端**权威配额兜底**：客户端"每跑图一报"只是在途标志+事件门的约定，不是安全边界；
   伪造/重放帧必须由服务端扣次校验拒绝（拒绝时仍回权威成功快照，见条件 1）。
4. **不需要任何施加 buff 的 NOTI**——效果 100% 客户端本地完成；服务端发施 buff 帧反而会双加。
   当前服务端"不扣次、只回快照"的现状=客户端照常触发，但 used 永不增长，显示与权威状态漂移。

## 3. 分问证据

### 3.1 Q1 加 BUFF 前检查什么？（UI 提示 / 效果 / 上报三者分离）

- **对应是否确为 slot3**：三重钉死——入口栈参 (2,3) 的 3 走 0x143FB30 的 slot 参数；
  构包块头 u16=3（0x014405B5 对照 slot4 是 4）；首门读 [mgr+0x38]=slot3 end（块偏移 6+9×3）。
- **订阅期限 end 来自哪里**：快照整块拷贝 0x143FDC0 写入 mgr+0x17 起的 74B（每槽 end u32）。
  slot3 end = [mgr+0x38]。
- **used 来自哪里**：同快照，slot3 used 字节 = [mgr+0x3C]（块偏移 10+9×3；0x143FB69 `movzx byte`）。
  **无本地乐观增量**（发送函数与 ACK handler 均不写块内字节；v2 §5.4 结论在本链再证实）。
- **limit 来自哪里**：**本地配置字节 [mgr+0x63]**（§3.5），与快照无关。
- **未购买**（end==0）：首门 0x01440663 即退出；**已过期但 end≠0**：**不退出**——0x143FB30 全程
  无 now() 比较（唯一涉及 now 的是显示聚合 0x143F9A0 与剩余时间 getter 0x143F8B0，均不在本链），
  过期槽在 limit>used 时仍返回 3 并触发（v2 §6 的"缺口"在 slot3 实链上**闭合为已证不过滤**）；
  **次数用尽**（limit<=used）：0x143FB30 返回 2，0x0144074B 退出。
- **三个出口全部静默**（0x1440B96 = 纯 epilogue）：无弹窗、无文案、无消息帧、无已证音效调用。
- **效果时机**：**上报前本地执行**（效果段 0x01440751..0x01440B2B，构包在 0x01440B52 起）；
  不等待、不依赖服务端响应。**UI 提示**：本链不存在（唯一 UI 相关是 ACK 后按 [mgr+1] 刷新契约图标，
  非本服务提示）。

### 3.3 Q3 回快照会否循环 / 重复扣次？

逐步走读（§2 时序后半）：客户端上报（在途=1）→ 服务端回 used+1 全量快照 →
ACK handler 整块拷入（used/ende 全部刷新）→ slot3 分支三条件中 **[mgr+0x14]==0 不满足 → 跳过**。
即：**不重施 buff、不重上报、本地在途标志保留（直到下一次 NOTI 0x1B）**。无循环。
客户端不计数（无本地增量），重复扣次只能来自服务端对自己重复帧的处理——合法客户端一个跑图一帧。
**服务端识别一次合理消费**：一帧=一次消费（客户端约定），配额校验+扣次在同一事务；
不需要跨帧幂等键，但必须容忍**异常序**：伪造/重放/同跑图第二帧由配额与（可选）同跑图去重兜底。
**唯一的服务端主动快照陷阱**：在客户端"处于地下城且在途==0"的窗口（理论上仅断线重连进图等边缘态）
主动推 036F 会触发捕获路径 → 客户端再施 buff 并再上报（多扣一次）。常规选角/城镇推送无此风险（mode≠3）。

### 3.5 Q5 最后一次与耗尽后

- **used=limit-1 触发、返回 used=limit**：本地门 (limit > used) 仍过 → buff 已施（保留——ACK
  路径无任何撤销/移除调用，buff 对象 +0xF4=1 持续）→ 上报 → 快照回 used=limit，整块拷入，
  在途保留到出图。
- **下一次入图**：NOTI 0x1B 清在途 → (2→3) 触发 → 0x143FB30：end≠0 但 limit(10) > used(10) 不成立
  → 返回 2 → **静默退出。无上报、无提示、无错误帧**（0x1440B96 纯 epilogue）。
- **上报被本地拦截后是否有提示**：没有（三个失败出口全部静默）。
- **无资格/已耗尽仍收到请求（服务端视角）**：客户端对 result=0 的 036F ACK **只做日志**
  （0x110E156..0x110E1B3：读 u8 错误码 → `error = %d` 日志 → 返回；不改块、不清在途、无 UI），
  已证分支中**不存在**任何"未订阅/耗尽"专用错误码消费。**应回权威成功快照**（result=1 + 现势 74B）：
  end=0 或 used=limit 的快照会让客户端在下一次入口自行静默拦截。不借用其他协议错误码（与既往纪律一致）。

## 4. wire 逐字节对账（ClientStatic ↔ 实测）

构包序列（0x01440B41..0x01440B8D）：`memset(74B,0)` → `block[0..1]=3` → `BeginCommand(0x36F,0)` →
`写 u16 1`（0x274D310）→ `写 74B 块`（0x274CED0）→ `Send`（0x274E6D0）。body = 2+74 = **76 字节**：
`01 00 | 03 00 | 00×72` ——与用户实测帧 `u16 category=1 + u16 slot=3 + 72B 零` **逐字节一致**；
且"72B 零"不是凑巧的填充，而是**与 S2C 同布局的 74B 块**（除槽号头外全零）。
服务端 77B 回包（u8 result + u16 variant + 74B）与 ACK 读取序列（结果字节→u16→74B）一致（v2 已证，本链再核）。

## 5. 服务端最小实施建议（不实施）

1. **扣次时机**：收到 76B slot3 上报帧本身即消费事件（效果已在客户端先行发生）。
   事务内：校验 slot3 订阅有效（end>now）→ `used < 10`（PVF 值，业务日界按现有
   `IDailyResetRuleService`）→ 按现有 `PremiumServiceUsageDomainService.TryUseAsync` 模式
   新增 `TryUseBuffServiceAsync`（CAS `TryWriteAsync` 已并发安全）。
2. **回包**：无论是否扣次成功，**一律回 result=1 + 全量 74B 权威快照**：
   - 扣次成功：used 反映 +1；
   - 未订阅：slot3 end=0（客户端下次入口自拦）；
   - 已耗尽：used=limit（同上）；
   - 伪造形状已由 decoder 严格校验挡住（现状 76B+slot∈{3,4}+全零校验与本轮 wire 结论吻合，保留）。
   禁用 result=0（客户端无消费语义、且会把在途标志悬挂到下一次选图）。
3. **幂等范围**：合法客户端一个跑图一帧（事件门+在途门），无需跨帧幂等键；服务端配额是唯一权威边界。
   可选加固：同一角色同一跑图（同 ExpectedRunId）内重复 slot3 帧只扣一次——非必需，量级极低。
4. **回包顺序**：单帧即可（ACK 即快照）。**不要追加任何施 buff NOTI**（双加风险）；
   不要在客户端处于地下城的边缘窗口主动推 036F（§3.3 捕获路径会多扣一次；选角/城镇推送无风险）。
5. **快照新鲜度义务**（本链已证的客户端缺陷面）：选角后与每日重置/到期收回时必须重发快照——
   资格检查不过滤过期 + used 只能靠快照刷新，两处都依赖服务端主动同步（与 v2 §7 一致，本轮升级为
   slot3 链上的已证约束）。
6. slot4 不在本轮范围，其结论不外推（调查边界）。
