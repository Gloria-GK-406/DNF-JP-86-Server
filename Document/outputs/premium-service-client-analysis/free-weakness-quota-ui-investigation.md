## 0. 一句话结论

**"未购买"和"次数用尽"在免费解除虚弱流程中走的是同一个提示（70715 购买确认框，窗口 0x29B）；

也没有任何"正确的服务端响应"能让虚弱流程弹出次数用尽文案。**

### 槽位资格 0x0143FB30（本轮逐指令复核，ClientStatic）

```text
slot > 7                    → 4
end  = u32 [mgr+0x1D+slot*9]  （mgr=[0x3A42CCC]=0x3A42CD0）
end == 0                    → 0        ← "未购买/未开通"
limit = 0x143FA40(mgr,slot)            ← 跳转表 0x143FA94，乱序映射本地配置字节：
        slot0→byte[mgr+0x61]  slot1→+0x62  slot2→硬编码0  slot3→+0x63
        slot4→+0x65           slot5→+0x64  slot6→有符号[mgr+0x69]  slot7→硬编码1
used = byte [mgr+0x21+slot*9]
limit > used → 3            ← "可用"
否则        → 2             ← "次数用尽"
```

**因此：状态 0（未购买）与状态 2（次数用尽）在 0x023FCC4D 处进入完全相同的分支，
客户端在虚弱恢复流程里对二者不做区分** —— 都要过 0x163D0C0，都弹 70715/0x29B
（或在特殊场冒下同样静默）。

## 3. 错误码 0x73、字符串 115、窗口 0x29E 到底是什么（Q3）

1. **字符串 115 不存在**。dstr 四个语言资源（66 中文 / 68 / 69 日文 / 6a 韩文，同一 ID 空间）
   的 ID 分布为 0,1,2,135,…，**100–134 段整体缺失**（dstr，逐资源 grep 验证）。
2. `0x28C14C0` 是全局 dstr 查表（由 695/696/697/1201/6559/70715/70727 等已知内容锚定；
   底层 0x2CA8D80→单例 0x4E28C84，locale-messages 形态）。**查不到时走 0x028C15D5**：
   用字面量 `getStr(%d) == none`（0x3620D50 解密）格式化后**返回占位字符串**（0x0977E70 =
   vsprintf 包装）。即 `getStr(115)` 的实际返回文本是 **`getStr(115) == none`**。
3. 因此 CMD 0009 收到错误 0x73 的真实画面是**双重窗口**：
   - 窗口 0x29E 显示占位文本 `getStr(115) == none`；
   - 公共尾 0x26181C0 的 0x73 分支再开窗口 0x209 显示 7521（**交易限制**文案）。
   这是一个明显坏掉/残留的分支：0x73 在**公共表**里是交易类错误码，与"次数用尽"无关。
4. **70727「已达到今日使用上限。」与虚弱流程零关联**。本轮把四个 push 0x11447 引用点
   全部指令边界验证并定性：

| 引用点 | 所属 | 触发条件 | 展示方式 |
|---|---|---|---|
| 0x01123331 | **CMD 0x17 ACK handler**（0x01122C40，注册 0x01144C74：`push 0; push 0x1122C40; push 0x17`，注册函数 0x163C4A0）。修理服务族（同 handler 错误 0xA → 751「修理费不足」、0x15/0x16 → 46379/46380 物品族） | `cmp al,0x73`（0x0112332C） | 70727 + 窗口 0x209 |
| 0x0113AC34 | **CMD 0xA0 ACK handler**（0x0113A830，注册 0x01145255：cmd 0xA0）。道具/物品使用族（错误 4→2057、0xE0→1201、0x13→3002 等） | 二级跳转表（0x113ACDC 字节表 + 0x113ACB8 目标表，索引=错误码−4）路由：**错误 0xE1 (225)** → 0x0113AC29 | 70727 系统消息（0xA9AF50/0x1A60620） |
| 0x01140677 | **开罐/袖珍罐 ACK handler**（函数 0x0113F780，错误链 0x01140572 起；handler 尾部读 `0x143FB30(mgr,7)`——slot7 高效开罐；非 push-imm 注册，CMD 号未钉） | `cmp al,0xE1`→70147「您今天太累了…袖珍罐…」；`cmp al,0x73`（0x01140672） | 70727 + 窗口 0x209 |

## 4. 第 11 次点击为什么弹购买提示（Q2 裁决）

四种假设逐一裁决：

1. **"客户端这条按钮路径本来就如此" —— 成立（主因，ClientStatic + 实机闭环）**。
   第 11 次点击时：slot5 end≠0（订阅有效）、used=10、本地上限=10（见 §5）→
   `0x143FB30` 返回 **2**；网吧查询 ≠2；→ 0x163D0C0（城镇）=假 → **70715/0x29B**。

   （第 10 次），第 11 次无任何 CMD 0009 入站，与用户观察一致。
2. **"快照字段/资格载体/同步时机不正确" —— 排除**。
   - DB（只读）：`character_daily_counters` `premium_free_weakness_used`=10（character 4）；
     `account_premiums` type585（slot5）end=1792614972=2026-10-22 04:36，当前有效。
   - 服务端编码（ServerCode，`StateSynchronizationPayloadCodec.Entry.cs`）：
     end u32 @6+9s、used 单字节 @10+9s；帧 92B = 15 头 + 1+2+74。客户端接收侧
     （0x0110E05A：READ_BYTES 74 → 0x143FDC0 `rep movsd`×18+`movsw` 整拷到 mgr+0x17）
     与之字节级吻合：slot5 end=block[51..54]→mgr+0x4A、used=block[55]→mgr+0x4E（1 字节读）。
   - 时机：日志显示第 10 次成功后紧跟 `S->C 036F frame=92`（行 420），选角链路亦发

3. **"应由服务端错误响应触发另一个窗口" —— 不成立（对虚弱流程）**。
   请求被客户端本地拦截，服务端没有可响应的对象；且即便能收到 0x73 拒绝，
   CMD 0009 的 0x73 分支展示的是 §3 的乱象（占位文本 + 交易文案），不是次数文案。
4. **"其他遗漏状态" —— 未发现**。0x143FB30 的结果只被 0/2/3/4 消费；除网吧查询与
   0x163D0C0 外无第三个输入；`[mgr+4]`、`mgr+0x15`、`mgr+1` 等标志位均不参与本分支。

## 5. 本地每日上限与 036F 快照（Q4）

- **接收布局**：如 §4-2 所述，77B（u8 结果 + u16 变体 + 74B 块）结构在客户端
  0x0110DFE9 变体分派（1→0x0110E05A；4→0x0110E00A 网吧块；其他忽略）下字节级对齐。**正确**。
- **"未购买/用尽"的状态表达**：接收侧没有独立标志——未购买=end(0)，用尽=end≠0 且
  limit≤used；两者仅能靠 0x143FB30 的返回值区分，而按钮分支把 0 和 2 同等对待（§1）。
- **本地每日上限来源**：slot5 上限 = byte[mgr+0x64]（乱序映射见 §1）。镜像中该字节初始为 0
  （.data 全零，静态初始化 0x2F4A37C 只做置指针+清块区；嵌套对象 ctor 0x1441080 不写 +0..+0x19；
  036F 快照 74B 落在 mgr+0x17..+0x60，不覆盖 +0x61）。**写入者未定位**：
  全 .text/.code 的 mod01/mod10 字节写与 dword 写均做过边界校验扫描，无命中；
  `mov [x+0x64], 0x0A` 形式的立即数存储亦不存在。结合 VMP 文档（3,939 个游戏函数有
  mutation 边进入 .vmp1），判定装载点大概率在变异/虚拟化代码或通用解析循环里
  （ClientStatic 未闭合 → Hypothesis）。
  **运行时证据**：免费路径连续成功 10 次、第 11 次被拦，反推 limit5=10；
  与 PVF `etc/chn_characpremium.etc [free_stamina] 364 10` 一致（PVF 级）。
- **同步时机**：无造假必要也无造假空间——快照按"选角后 + 每次使用后"推送即可，
  客户端 used 完全跟随最后一次快照（无本地乐观计数，维持既有结论）。
- 附带观察（RuntimeLog）：客户端在地图加载完成时会主动发 **C2S 036F**（76B，
  `01 00 03 00 …`，seq=53/69），服务端记为 Unhandled。客户端 S2C 侧只消费变体 1/4，
  该请求疑似变体 3 的拉取请求；当前"服务端主动推"的策略已覆盖其用途，不构成缺陷，
  但若未来对齐原版节奏可作参考（Hypothesis，未验证客户端是否等待该响应）。

## 6. 能否仅靠服务端协议让第 11 次显示"次数用尽"？（Q5）

**不能。已验证的限制范围（均为 ClientStatic）：**

1. **发包前拦截**：第 11 次点击在 0x023FCC69/0x023FCC6E 两个放行条件处失败，
   永远到不了 0x023FCD76 的构包发送。服务端没有任何帧可以"响应"一个未发出的请求。
2. **无文案连线**：CMD 0009 handler（0x011209D0）与公共处理器（0x026181C0）全量走读，
   均无 70727 引用；0x73 响应只会触发 §3 的双窗口乱象。
3. **快照杠杆全部无效**：发 end=0（伪造未购买）→ 同样 70715；不发快照（陈旧 used=9）
   → 0x143FB30 返回 3 → 按钮放行 → 第 11 次免费恢复真的会发生（这属于服务端作弊，
   不是"正确协议"，本调查明确不采用）。
4. **理论边角（不推荐，仅记录）**：伪造一帧未经请求的 CMD 0x17/开罐类 ACK（body=`00 73`）
   或可令客户端弹 70727——但这属于跨协议伪造响应：site A 尾部还会写 `[mgr+4]` 状态、
   handler 可能按序配对丢弃未知 ACK（分发层配对语义未验证），且与"正确服务端协议"的前提
   相悖。**明确不建议**。范围内未发现任何 NOTI/推送型消息携带次数文案的路径
  （70727 的全部四个引用点已枚举定性；不排除极远处存在未发现的窗口路径，但那超出
   "虚弱恢复流程"的可验证范围，不做绝对化断言）。

**可行的替代认知**：70715 弹窗内含"确定前往商城购买吗？"，其"确定"动作走商城
（行为未走读）；在原版语义下，**次数用尽后引导续购与"未购买引导首购"共用同一文案
本就是该客户端的既定 UX**——若产品上必须区分，只能改客户端（超出本任务范围）或
在服务端用其他通道（如聊天公告 0xA9AF50 类）主动推送自定义提示（同样超出"正确协议"范围）。

### 服务端是否需要修正

都无法凭空造出 70715 之外的本地提示；当前实现（成功后 0021+0009ACK+036F 快照重发、
DB 计数、订阅投影）已与客户端消费面完全对齐，属**正确实现**。

可选的低风险改进（非必须，均不改变上述结论，实施与否由你们决定）：
1. **错误码语义对齐**：服务端目前免费资格/次数不足用错误码 4 拒绝——客户端对 CMD 0009
   的 4 完全静默（§2）。由于正常玩家在第 10 次后根本发不出请求，此路径只在
   "快照与 DB 短暂不一致"或未来新增调用方时才会出现；若希望任何极端路径下都有反馈，
   可改用 0x12（696"不处于虚弱状态中"）或 0x63（1201 城镇限制）等已连线文案中语义最接近者
   ——但"次数用尽"语义在 CMD 0009 上无对应文案，无完美选项。依据：§2 错误表（ClientStatic）。
2. **C2S 036F 处理**：当前 Unhandled。可在日志降噪或按变体 3 回一发变体 1 快照做对齐实验
  （不改变现有推送策略前不影响任何已验证行为）。依据：§5 附带观察（RuntimeLog + Hypothesis）。

## 8. 反证与撤回记录

| 原假设/直觉 | 撤回原因 |
|---|---|
| "错误码 0x73 会显示次数用尽文案（70727）" | 仅在 CMD 0x17/开罐 handler 成立；CMD 0009 的 0x73 → getStr(115) 缺失 + 0x29E 占位 + 0x209 交易文案（§3） |
