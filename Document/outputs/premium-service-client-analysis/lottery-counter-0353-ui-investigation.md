## 0. 结论（先答三问）

1. **这两个值控制哪个操作**：只控制一件事——**窗口 0x2B2（袖珍罐双倍奖励设置窗）里两个"购买/续购"按钮（+0x208/+0x210）点击后的分支**：`pair[0] < pair[1]` → **直接跳商城**（关窗+固定三元组导航）；`pair[0] >= pair[1]` → 先弹 **0x2B3 确认窗（dstr 70985 固定文案）**，点"是"后走**完全相同**的商城导航。除此之外全镜像无任何消费者（穷尽扫描，§3）。开罐、执行、普通开罐、双倍确认、全部开启、高效开罐都不经过该比较。
2. **为什么产生当前弹窗差异**：**服务端从不发 0353 时两字段恒为 (0,0)，`0>=0` 恒走弹窗分支**——观察到的"8 次耗尽后弹 70985"其实是"任何时刻点购买按钮都弹"；实验发 (0,30) 后 `0<30` 走直接商城分支——观察到的"不再弹窗直接商城"。两组实测都被同一比较门精确解释。文案里的"8"与"30"是**固定文字**（无占位符）：8 对应 slot1 契约额度（036F 体系，另一套字段），30 对应 pair[1]（0353 体系）。
3. **还缺什么证据才能定正式业务规则**：静态已把**机制**钉死，但 **pair[1]=30 的业务语义（"每日双倍总上限"还是"每日开罐总上限"还是纯提示门槛）与 pair[0] 的口径（客户端对任何模式的成功开罐都 +1，与服务端想要的口径可能不一致）**无法由静态裁决——需要 §7 的两个最小实验 + 一项业务决策（30 上限约束在服务端 mode=1 校验里怎么实施）。服务端若每次开罐后重发 0353 真值，客户端计数口径问题即被覆盖，不构成阻塞。

## 3. 两字段（角色对象 +0x3A34/+0x3A38，虚表 0x032E5D64）读写生命周期

检索方法与边界：全镜像（.text 0x401000..0x3A00000）skipdata 线性扫描
①直接偏移 `+0x3A34]/+0x3A38]`（mov/lea/cmp/inc/add/push）；②虚表槽 `+0xC58]/+0xC5C]` 的全部载入点并逐一验证接收者是否角色（排除容器类 (end−begin)/4 模式 7 处）。**结论：除下表外无其他访问者**（字节级扫描穷尽=高置信；不排除经 getter 返回指针再传递的二级别名，但二级读法本身必经已枚举的 0x018340E0 调用点）。

| # | 地址 | 所属函数 | 触发条件 | 读/写 | 证据 |
|---|---|---|---|---|---|
| 1 | 0x01836480/89/8F | setter（vt+0xC58，`ret 8`） | 被 NOTI 0353 handler 调用 | 写 +0x3A34=arg1、+0x3A38=arg2 | 客户端静态 |
| 2 | 0x0118B340（→#1） | NOTI 0353 handler（注册 0x0119AF7C/81，NOTI 表） | 收到 2B body 且角色≠0（角色空则整帧忽略） | 写两字段=body 两字节各 movsx | 客户端静态 + 现有实帧 |
| 3 | 0x018340E0 | getter（vt+0xC5C，`lea eax,[ecx+0x3A34]; ret`） | — | 返回 &pair | 客户端静态 |
| 4 | 0x01140545..59（→#3） | CMD 0x001B 成功 ACK 尾 | **成功 ACK（result≠0）且角色≠0**；**无 mode 判断、无罐名单判断、无窗口存活条件**（fastbreak 分支两侧与双倍跳过路径均汇入）；失败分支（0x1140572+）无递增 | pair[0] += 1（`inc dword [eax]`） | 客户端静态 |
| 5 | 0x0148AA4D..62（→#3） | 0x2B2 购买按钮分支 | 点击 +0x208/+0x210 | 读 pair[0]、pair[1] 比较（`cmp; jl` 有符号） | 客户端静态 |
| 6 | 0x018A3978/7E | 角色对象初始化 A（含 0xB076B0(0x171) 工厂等大初始化） | 角色对象构造 | 双双清零 | 客户端静态 |
| 7 | 0x018A53BE/C4 | 角色对象初始化/复位 B（+0x3A40 链表头重置邻域） | 角色对象构造/重置 | 双双清零 | 客户端静态 |

推论：
- **登录/换角色**：角色对象重建时归零（两处构造路径都清；对象生命周期推断为选角时重建——High，未动态验证）。
- **进/出商城、购买、续购返回、失败 ACK、关窗**：均不触碰两字段（无写者）。
- **第二个字段**：唯一消费者就是 #5 的比较；**无清零、无限流、无动画、无引导、无活动入口用途**；无 UI 显示（"剩余次数"用的是 slot1 口径，§4）。
- **ACK 递增覆盖面**：任何成功开罐（普通/双倍/连开中的每一次）都 +1；两次特殊罐（2679712/2682016，提升几率族）走同一 handler 同样计入。无类型过滤。
- **无其他协议写同一状态**（036F 整块拷贝只写 mgr+0x17 块，不触角色字段；0042 不写）。

## 4. "剩余次数"显示与 pair 的分离（防混淆的关键实证）

0x2B2 的"剩余次数 : %d次"（70983，0x0148B0F1..0x0148B12D）：

```text
0x143F880(mgr,1)==0 → 显示 0（edi 预置 0）
否则：used = 0x143F970(mgr,1)   ← end≠0 才返回 used 字节[mgr+0x2A]，否则 −1
      limit = 0x143FB90(mgr,1)  ← end≠0 才转发 0x143FA40(1)=本地上限[mgr+0x62]（PVF 8），否则 −1
显示 = limit − used
```

即**显示走 slot1 契约口径（036F used + PVF 本地上限），与 pair 完全无关**；pair 没有任何显示。
0x143F970/0x143FB90 是 UI 专用带 −1 语义的包装（本轮新钉），limit 最终仍来自上轮已证的
0x143FA40 跳表——slot1 尾块 20..23 依旧无已证消费者，维持"不命名"。

## 5. 商城购买往返链（两入口对比）

| 项 | 直接商城分支（pair0<pair1，0x0148AA87） | 0x2B3 确认分支（pair0>=pair1 → 是，0x0147DB80） |
|---|---|---|
| 前置 | vt[0x78] 关闭 0x2B2 | （0x2B3 窗已打开，显示 70985 + 是/否） |
| 导航 | `shop=[mgr+0x8FAC]`（0x2300D10）；**0xB44A00(shop,1) → 0xB41960(shop,1,1) → 0xB3E610(shop,4)** | **完全相同的三元组** |
| 收尾 | — | 0x23010C0 关闭 0x2B2（若开着） |
| 目标页 | 商城魔王契约页（用户实测锚定；静态=固定页码参数 1/1/1/4，无商品/槽位/模式参数） | 同左 |

- **客户端不区分"买期限"与"买次数包"**：两入口、两分支共用同一固定导航，不传 slot/商品参数；任何区分只能来自商城页本身（服务端/商城数据侧）。
- **购买成功后客户端更新**：NOTI 0x0042（提示性，不写 8 槽）+ 036F 快照（slot1 end/used）→ 用户回到开罐流程重新开 0x2B2 时"剩余次数"刷新；**0x2B2 不会被自动重开**（确认分支已关窗）；双倍标志 mgr+0x15 不被购买流程清除（上轮已证 ACK 成败均不清）。
- **未识别的续购上行/下行**：无。0x2B2/0x2B3 的全部动作=本地比较+导航+关窗；没有"请求续购额度"的 C2S。
- 当前服务端的期限续购行为是服务端侧实现，不作为客户端机制证据（按任务边界）。

## 6. 候选语义模型与证伪矩阵

| 模型 | 内容 | 支持证据 | 冲突证据 | 可证伪实验 |
|---|---|---|---|---|
| **A（主）服务端同步的"今日开罐数 vs 每日阈值"** | pair[0]=客户端累计的成功开罐 ACK 数（任何模式），pair[1]=服务端下发的每日阈值（30=文案的"总限制"）；阈值内点购买→直接商城；到顶→70985 提示再商城 | ①ACK 递增无 mode 判断（§3-#4）；②(0,0)→恒弹窗、(0,30)→直接商城，两组实测精确吻合；③70985 固定文含"每天30次的总限制"；④NOTI 下发两值+客户端本地递增=典型"服务端同步+本地漂移"设计 | 文案说"该服务项…8次"暗示服务(双倍)口径，而 pair[0] 是全口径——文案与计数口径不一致（可用"文案为固定模板"解释，但为解释项） | E1/E2（§7）：改 pair 值直接翻转分支；(29,30)+普通开一罐→弹窗（证明任何模式递增参与比较） |

| D 窗口复用/错误归因 | 弹窗是"过期/复用 UI 的意外触发" | 我们服务端从未发 0353→(0,0) 退化态触发 | 静态显示 0x2B3 是 0x2B2 的正规配套窗（相邻 ID、确认路径完整导航），非误触 | 已被 0/30 实验否定"不可控"；分支随 pair 值精确受控 |

统一解释（回答任务 §4 四现象）：8=slot1 契约额度（036F 口径，弹 70727/剩余次数显示用），
30=pair[1]（0353 口径，文案字样）；"普通开罐也递增"是 pair[0] 的设计口径（全部成功开罐）；
"0/30 跳过提示"=`0<30` 走直接商城；"达阈值反而弹可再次购买"=`>=` 分支的 70985 正是"到顶告知"
（文案措辞为固定模板）。**矛盾消解的关键=把"8 次耗尽"与弹窗解耦：未发 0353 时弹窗与 8 次无关，
任何点击都会弹**（该解耦由 (0,0) 恒弹窗的静态结论直接支持，不是假设）。

## 7. 最小实测方案（成对、单变量；由主 agent 安排）

前置：0353 实验开关可配 Current/Threshold；同一 UI 入口=0x2B2 的购买按钮（建议用户固定点同一个）。

| # | 操作 | 采集 | 裁决 |
|---|---|---|---|
| E1 | 登录发 (0,0) → 点购买按钮；重登发 (0,1) → 再点 | 是否弹 70985 | (0,0) 弹、(0,1) 不弹 → 比较方向与 0 阈值行为坐实（=1 即够，不必 30） |

## 8. 对现有实现的建议（不实施）

**足以实现的（静态已闭环）**：
1. **0353 转正式或保留实验**：登录（角色发布后）发送 `(服务端真值, 阈值)`；**并在每次开罐成功后重发**——服务端真值覆盖客户端漂移计数（客户端任何模式都 +1，若业务口径是"仅双倍"或"服务端权威"，重发即纠偏；这是对 §6 口径分歧的鲁棒解法，无需先裁决口径）。
2. 阈值取 30（若采纳文案业务）；值域记住两字节各 movsx（−128..127），服务端输出 0..127。
3. 0/30 实验现状**无副作用**（§3 穷尽：唯一消费者=比较+递增，无显示无其他状态），可安全保留为默认登录推送，直到正式规则定案。
