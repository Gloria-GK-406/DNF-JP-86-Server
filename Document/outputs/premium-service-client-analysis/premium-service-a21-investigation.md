### 3.2 S2C CMD 0x036F `PREMIUM_SERVICE`（8 槽快照）— ClientStatic + ServerCode

**分发前缀（v1 存疑项，本轮闭合）**：CMD 响应通用分发把 **body[0]（u8 结果标志）消费为
handler 参数 [ebp+0xC]**（错误码进 [ebp+0x10]），handler 的 reader 从 body[1] 起。证据：
- 0x002A ACK：实帧 body=`01`（1 字节，2026-08-26 归档），handler 0x01105CC0 首指令
  `cmp byte [ebp+0xC],0`——结果只能来自分发层（RuntimeVerified 实帧 + ClientStatic）。
- 0x0009 成功 ACK：本服 body=`{1}`（RecoverStaminaSlice.cs:41），用户实机恢复成功
  （RuntimeVerified 用户 + ServerCode）。
- 0x0029 ACK handler 0x011062E0 同构（ClientStatic，round-3 记录）。
→ **服务端 `u8 1 + u16 1 + 74B` 的 77 字节编码结构正确**（u8=结果，u16=变体 1，74B=块）。

**74B 块全偏移表**（块被整拷到 [0x3A42CCC]+0x17；变体 4 整拷到 [0x3A42DB4]+4）：

| 块偏移 | 类型 | 含义 | 客户端读取指令 | 等级 |
|---|---|---|---|---|
| 0..5 | 6B | 未知头（客户端未见读取；服务端写 0） | — | ClientStatic(未见读者) |
| 每槽 s∈0..7，基址 B=6+9s： | | | | |
| B+0..B+3 | **u32** | **到期：绝对 unix 秒**；0=未开通 | 0x0143F8C3 `mov esi,[eax+ecx+0x1D]`（dword）；0x0143FB42 同 | ClientStatic |
| B+4 | **u8** | **当日已用次数**（与 0x143FA40 上限比较） | 0x0143FB69 `movzx ecx, byte [edx+0x21]`（**字节**） | ClientStatic |
| B+5..B+8 | 4B | 未知（客户端未见读取；slot7 的 B+5.. 越出缓冲不存在） | — | ClientStatic(未见读者) |
| 算术注记 | | 6+8×9=78>74：**末槽（s=7）记录被截断**——其 end(69..72) 与 used(73) 存在，尾 4 字节不存在 | | ClientStatic |

- **used 宽度裁决**：客户端唯一读取指令是 `movzx byte`（B+4 单字节）。不存在"字段更宽、
  只读低字节"的已知反例——但 B+5..B+8 的 4 字节**无任何读者**，不能排除服务端另有约定；
  服务端 `WriteInt32(data, 10+s*9, …)` 与客户端字节读**语义可兼容**（小端低字节相同），但
  **slot=7 时越界写 73..76**（74B 数组）——ServerCode 缺陷候选（从未以 slot7 发送过则未触发）。
- **时间基准**：槽 end 参与的是 `end - 0x164F710()`（当前 unix 秒）的实时减法
  （0x0143F8D4 起）→ **绝对 unix 秒，ClientStatic 强**（与 NOTI 0042 的不可判形成对照）。
- **变体 1 vs 4 持有者**：变体 1 → [0x3A42CCC]（魔王契约管理器，DevilContract.cpp，
  资格三件套 0x143F8B0/0x143FB30/0x143F9A0 的对象）；变体 4 → [0x3A42DB4]（**网吧等级特权**
  持有者；查询 0x1443BF0(idx≤5) 走 0x1443A00 的 0x3B/0x3C/0x3D 档位判定，其 own 块的
  used 字节同样在 +10+9s 布局（0x0143C1F），阈值在对象 +0x50/+0x51 本地字节）。两者同布局
  家族、互不拷贝；同一 74B 线格式服务两个体系。
- **单项更新通知**：未发现。C2S 侧 0x036F 构包点 ×3（VA 0x018405CC 等，body 未走读）；
  S2C 侧除两变体整块外无逐槽写路径（§1-5 覆盖性声明）。

## 5. 金币/契约恢复：入口、条件与次数（D 冲突闭合）

### 5.1 恢复窗的完整开窗链（ClientStatic + RuntimeVerified）

```text
窗口消息 handler 0x023FCB50（ReportConfirmWindow）：
  前置：有角色（[0x3B3DFB8]≠0）且 mode==1（城镇）        ← 0x023FCB6C-0x023FCB7F
  若角色 stamina（vt[0xA10]）== 100 → 直接返回（不虚弱不开窗）  ← 0x023FCB8C-0x023FCB9F
  ……（0x023FCBAC 起）两个按钮子对象 [esi+0x184]/[esi+0x18C] 的
      UI 消息路由检查 0x27DCC30（[obj+0x31] 有效 && 全局序号 [0x3998E00]==[obj+0xD4]）
      ——纯消息有效性判断，与契约/资格无关（v1 误读已纠正）
免费路径初始化（0x023FCC4D-0x023FCC71）：
  edi = 0x1443BF0([0x3A42DB4], 4)   ← 网吧特权查询（idx4，返回 1/2）
  eax = 0x143FB30([0x3A42CCC], 5)   ← 契约槽 5（0/2/3/4）
  edi==2 或 eax==3 → 免费路径可用（进入开窗初始化）
  否则若 0x163D0C0(mgr)==0 → 文案 70715（去商城购买魔王之契约）——仅此分支出现付费墙文案
  [esi+0x214]=0（body 模式复位）
```

- **开窗本身不需要契约**：城镇+虚弱即可（与用户实机"无契约也能打开金币恢复 UI"一致，
  v1 结论撤回）。70715 只在"点免费/契约路径但无资格"的分支。
- `0x27DCC30`/`0x27DCC50`：窗口子控件的消息序号检查（两个全局 0x3998E00/0x3998E04 对应
  两控件），不是资格判断。
- 第二持有者查询（网吧）与槽 5（契约）是**并列的两条免费资格来源**，任一满足即开免费路径。

### 5.2 按钮 → CMD 0x0009（mode 语义与响应）

| 项 | 结论 | 等级 |
|---|---|---|
| body u16 | **0=金币恢复（开窗默认 [esi+0x214]=0）；1=契约恢复按钮**（handler 0x023FC9D0-0x023FCA30 写 [esi+0x214]=1） | ClientStatic |
| 成功 ACK | 分发层消费 body[0]=1；handler 0x011209D0 走成功路径（stamina setter+重算+文案 695）；本服 body=`{1}` 已实机 | RuntimeVerified(用户)+ClientStatic |
| 失败 ACK | 结果=0 时按 [ebp+0x10] 错误码分派：0x12(18)→文案 696"不处于虚弱"、0x16(22)→697"金币不足"、0x13(19)→6559、0x63(99)→1201、0x7E(126)→70005+窗口 0xFB、默认分支未逐条读完 | ClientStatic（分支），18/22 与文案绑定；**错误码 4 客户端分支未确认**（86JP 惯用=ReferenceServer） |
| 金币不足 | 客户端本地拦截（不发包）——用户实机"金币不足时客户端提示并阻止"；服务端 22 拒绝路径**无实帧** | RuntimeVerified(用户，客户端侧) |

### 5.3 三条件分离（Q3-5）

| 条件 | 判定 | 位置 |
|---|---|---|
| 是否处于虚弱 | stamina（vt[0xA10]）≠100 | 开窗门 0x023FCB9C |

### 5.4 次数更新机制（Q3-6）

- **客户端无乐观增量**：免费按钮 handler（0x023FC9D0）与 0x0009 成功 ACK handler
  （0x011209D0）均不写 [0x3A42CCC]/used 字节（后者不在 148 引用集中）。
- 管理器 used 的唯一已知写入=0x036F 整块拷贝 → **次数更新依赖服务端重发快照**（或未发现的
  单项通知）。何时重发（每次使用后/每日 6 点/登录）无帧证据——R3 裁决。
- 无重复计数风险于客户端侧（它根本不计数）。

## 6. 生命周期与到期（Q3-三连同题分拆）

| 问题 | 结论 | 等级 |
|---|---|---|
| 显示时过滤过期？ | **是**：0x143F9A0 循环 `jg` 只采纳正剩余（end>now 才计入汇总/显示） | ClientStatic |
| 使用时过滤过期？ | **是**：0x143FB30 end==0 → 0；end≠0 但已过期时——**未单独过滤**（只比较 end 与 used/上限；过期未到期值 end<now 时 0x143F8B0 返回负剩余，0x143FB30 的比较不涉 now——**过期槽可能仍返回 2/3**？未闭合：0x143FA40 比较的是上限与 used，不比较 now。**缺口**：过期但 end≠0 的槽在资格检查中的行为需实机或更深走读） | ClientStatic(部分)+缺口 |
| 本地 timer/清理 | 未发现（v1 维持）；0x143F7A0（置空全局）**无调用者**——管理器进程期常驻 | ClientStatic |
| NOTI 0377 | u32 对列表→窗口 0x197 子系统；不写 8 槽（§3.4） | ClientStatic |
| NOTI 0042 end=0 | 到期消息+UI 刷新；**不清 8 槽** | ClientStatic |
| 重登录/换角色 | 管理器不清零（无 teardown 调用者、无逐字段写 0 路径）→ **陈旧状态保持到下一次 0x036F 快照**（同机换账号也会带上前一号的槽状态——服务端必须在选角后重发快照，否则串号） | ClientStatic(高置信) |
| 各载体恢复什么 | 0x036F=8 槽期限+次数（唯一）；0042=通知（type 级）；0377=窗口列表消息；登录列表=未闭合 | 见 §3 |

**"必须服务端全量重发"的降级说明**：静态可证的只是"客户端自身无清除/无单项写、状态由
整块拷贝替换"。原版服务器用何种节奏（每次使用后即发/每日/仅登录）**无帧证据**——R 矩阵裁决。

## 7. 登录、到期、恢复成功后的必要同步序列（当前证据下的服务端约束）

1. **选角/入城后**：必须发 CMD 0x036F 变体 1 全量快照（8 槽 end+used）——否则客户端契约
   UI/效果门无状态，且**换号会沿用上一账号陈旧状态**。（ClientStatic 推导）
2. **授予/续期**：NOTI 0x0042 v2（u16 2 + u8 type + i64 非零）做提示性通知；状态权威更新
   仍需重发 0x036F（0042 不写槽）。（ClientStatic）
3. **到期**：可选 0042（T=0）做提示；清单化到期可用 0377（窗口列表）；清除资格必须重发
   0x036F（end=0）。（ClientStatic）
4. **免费恢复成功**：①CMD 0x0009 ACK `{1}`；②NOTI 0x0021{100}（虚弱恢复，已实机）；
   ③**重发 0x036F**（used+1 的权威更新——客户端不自行计数）。（1-2 RuntimeVerified，3 为
   ClientStatic 推导的服务端义务）
5. **金币恢复成功**：①③同上 + 金币余额刷新（已实机）。（RuntimeVerified 用户 + 推导）

## 10. 最终结论（任务 §五 四问）

1. **现在能可靠实现**（证据闭合）：
   - 订阅域服务的两层模型落地（premiumType 单元 + 魔王契约 8 槽单元，每槽独立期限）；
   - CMD 0x036F 快照投递（77B 结构、绝对秒、每槽独立）；
   - NOTI 0x0042 授予/到期提示（现 i64 格式可保留）；
   - 免费解除虚弱的**完整服务端闭环**：选角后快照（slot5）→ 免费恢复按钮可用 →
     CMD 0x0009 body 1 → ACK{1}+NOTI 0x0021{100} → **重发快照（used+1）**。
     需要的用户确认仅剩：每日 10 次上限值（PVF `[free_stamina] 364 10`，PVF 级）采纳与否。
2. **还会改变领域模型/协议的问题**：
   - 过期槽在资格检查中的行为（R2）——影响"过期即失效"的实现位置（服务端过滤 or 客户端自滤）；
   - 登录订阅列表载体的客户端消费方（§3.3 缺口）——影响登录投影是否需要重设计；
   - 霸王 17..22 六码语义（时长 SKU vs 子能力）——影响该契约的单元拆分。
3. **只影响后续具体服务**：槽 1/2/3 效果点定位；NOTI 0377 的 A/B 语义；网吧特权体系（独立
   调查）；黑钻资格来源；每日上限配置的客户端装载来源（+0x61..）。
4. **免费解除虚弱闭环仍缺的证据**：R1（快照实帧+UI 生效）、R3（used 更新节奏）两项实机；
   其余链路（开窗门、按钮 mode、成功序列）已有 ClientStatic+用户实机双重覆盖。
   "有订阅图标"不作为验收——验收=免费按钮可用性 + body=1 实帧 + 次数递减。
