# 婚姻 PVF 调查结论

## 必须更正

`20737/20738` 并未缺失。它们存在于当前 `n_quest/quest.lst`，当前 `PvfQuestDefinitionSource` 也正从该路径读取。服务端 PVF 与四份客户端 PVF 中的任务、婚姻主表和关键地图规范化 dump 相同，这些内容不是服务端独有。

## 一期可采用的静态规则

- 最低结婚等级 `30`，任务职业为 `[all]`。
- `20737`：与心上人 2 人队通关普通地下城 5 次，奖励真爱考验箱。
- `20738`：前置 `20737`，收集心意娃娃 ×1，奖励心意通 ×5。
- 婚礼金币档：普通 `500,000`、高级 `2,000,000`、豪华静态金币 `0` 且另需 `2683401 ×1`。
- 婚礼时长候选原始值 `300/600/900`；按秒解释为 High 推断，档次 tuple 末列 `10/20/30` 的语义仍未知。
- 爱心点上限 `999`；离婚静态费用双方各 `500,000`，再婚/频率相关表值均为 `1` 日。
- 爱之摩伽陀 `3541` 静态要求 Lv30、2 人、邀请函 `10002609 ×3`，物品文案要求夫妻 2 人组队。

`20737/20738` 都不引用 `3541` 或其他具体副本；`3541` 也不要求这两个任务。前两者是婚前普通图/收集试炼，`3541` 是婚后夫妻玩法，静态 PVF 没有循环依赖。

PVF 未声明性别限制，因此性别规则仍是 Unknown，不能写成已允许或已禁止同性婚姻。

## 当前服务端缺口

- Wedding grade 被通用可接列表有意排除，说明它应走专用入口。
- `20737` subtype `22` 不被当前 DungeonClearRequirement 解析；`-1 -1 5` 还会因 stride 4 不足而把初始 trigger 算成 `1`，现有任务进度不能兑现“5 次普通图”。
- 通用 `0x001F` 请求进入 `AcceptQuestHandler -> AcceptQuestCommandHandler -> QuestLog.AcceptAsync`，只对 Crack/Circle 有特殊门控；Wedding 没有等级/前置校验。协议直送可绕过资格，原生 UI 是否会这样发送仍待 A21 确认。
- 当前 MirrorArad WestCoast 没有大司祭 `20013`。带该 NPC 的旧 `town/hendonmyre.twn` 未被当前 `town/town.lst` 选入；教堂 map 也不是普通 town area。只可表述为当前 town graph 未连通，不能据此断言求婚 UI 必须经 NPC。
- `20743` `爱情的升华` 是现存普通引导任务，但完成 NPC 仍是 `20013`，且它不是 `20737/20738` 的硬前置。

一期应建立专用婚姻资格服务，并补 subtype 22 或采用有审计的等价状态机；不可预先把任务标记完成。副本准入必须查询真实、持久化的双方配偶关系。

完整证据与代码引用见 [pvf.md](pvf.md)。
