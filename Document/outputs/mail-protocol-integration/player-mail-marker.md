# A21“玩家邮件”标志与未定字段

2026-09-24。ClientStatic：只读既有RVA镜像，未修改运行服务、客户端或数据库。镜像与既有receive-wire.md一致（AAAE2421…），VA=RVA+0x400000。

## 控制链已闭合

- dstr中文70699=“玩家邮件”，70524=“该邮件属玩家邮件，邮件内容仅代表玩家的个人观点。”。
- UI构造入口0x01A51580，0x01A5163E取70699，控件保存到view+0x3C。
- 0x01A51E50设置当前邮件；0x01A51EAC调用0x01A472B0读取邮件wrapper+4所指payload的首字节。首字节=0时向上述控件虚函数+8传1；非零传0。70524提示入口0x01A4F600同样先调用getter，非零直接跳过提示。
- 标志在payload构造入口0x01A489A0写入：0x01A48C9A..D06先检查发件人名称是否为UTF-16“公会管理员”（5汉字+终止零，共12B）；匹配则置0。其余名称下，senderId==0或2000000000（0x77359400）置1，否则置0。
- 发件人参数映射：0061摘要0x01198F87读取第二个u32到-0x56C；0x0119954B/562传给0x01A4AC70的+0x14；该函数转发到0x01A48FB0的+0x10，再原样传给0x01A489A0的+0x10。构造函数0x01A489FD将其存payload+0x20，0x01A48CF5作上述分类。

因此一般情况下：真实玩家senderId显示“玩家邮件”；senderId=0隐藏该标志及警告。不存在已证的独立wire IsPlayerMail字段。公会管理员是客户端特殊例外，不应推成普通玩家或系统业务分类。

当前服务：MailType不直接编码成一个独立字节，仅影响服务端MailboxSenderId/Name选择。玩家源投影真实characterId；系统源senderId=0。该设计在普通来源上已符合静态分类条件，无需新增客户端flag。尚未进行官方/玩家两封邮件的受控UI差分，不能称该标志已ClientVerified。

## 实机修正：系统名称不应自定义
用户截图证实客户端对系统邮件自带“DNF管理员”显示，自定义senderName会追加到后面。已移除MailSource的SystemName能力，改为FromSystem()；MailBuilder.FromSystem仅保留收件人参数。新系统邮件持久化空名称，协议对系统senderId或内部MailType覆盖为空名称，使旧样本也无需批量改库。相关53项测试覆盖，未重启在线服务。
