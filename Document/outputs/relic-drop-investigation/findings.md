## 已核实

- 两次 Boss 均为 dungeon84、61013 UM-0终结者、64级、普通难度、2人。旧部署日志第4968行拾取10149525；新部署日志第2420行拾取同ID，随后为3337和3267等物品。

```text
0 61013 10149525 100000 100000 100000 100000 100000 1 2 3 4 4 0 0 -1 0
```

按当前服务端政策解释：五档难度均100000/1000000=10%；1/2/3/4人分别1/2/3/4次独立尝试，数量上限4，角色等级上下限0/0表示不限制；本行不存在另加等级差衰减。每怪执行一次独立来源，不是循环队员重复执行Ground。

两人至少一件概率1-0.9²=19%，期望每Boss0.2件；两局都至少一件理论概率3.61%。这不是必掉配置。数字含义依赖本服现行字段/分母政策，不当作官服爆率证明。

## 算法验证

`artifacts/relic-drop-probe` 直接引用生产 DropRandom 和 IndependentDropRules，对100000个不同输入种子执行本行2次抽取：0件81102局，1件17928局，2件970局。至少一件18.898%，不支持概率被误算为100%的假设。未重放两局原始随机票据；现有服务日志未记录这些票据。进图代码每次 Random.Shared.Next() 生成run seed，没有按角色/副本固定seed；不能据此声称已比对两局实际seed。

结论：来源已定位到PVF独立掉落行；当前实现使2人约19%的Boss战掉该书。两局命中不足以证明抽取程序故障。若目标爆率应显著更低，应进一步核对独立掉落分母、次数语义及是否存在外层条件，而不是直接删除物品或判作世界掉落误入。原版设计正确性仍未定案。

## 70 服务端分母复核

二进制 `Research/1995chen-dnf/other/等级补丁/70/df_game_r` SHA256=CF45F4E8514C3BF560DD322C146F8441249F6C28246EC8566DCF9EBC4E1B2EB7。

Confirmed（70 ELF静态）：`generateIndependentItem` 0x0834989A，在0x08349AF2写参数0xF4240（1000000），0x08349AF9调用get_rand_int，0x08349AFE比较概率值与返回值，0x08349B00为setg，命中增加成功次数。循环按参与人数索引次数列，结束后0x08349B42以min限制最大数量。支持当前“百万基数、人数对应尝试次数、成功数封顶”的核心解释。

`get_rand_int` 0x086B1B87已走读：含rand取模和备用生成分支。备用分支保留等于上界的极小边界可能，不将实现简单断言为严格均匀[0,N)；这不支持将分母扩大十倍或百倍。

额外控制：0x08349992先调用independentItemRateControl(0x0834972F)。该函数按物品ID匹配控制记录，计算两个上下文字节(+0x3F和+0x34)的差，达到配置阈值后乘 `(10000-配置系数*差)/10000`，小于零时将分子改为1。上下文字段完整写入链本轮未追，不把其身份直接定案为等级。常量0x08C349EC按float解码10000。控制记录由IndependentDropParameterScript::ImportIndependentDrop的`[dungeon drop rate balance]`标签载入（0x0897CA0A字符串引用；三整数写入）。

当前A21运行PVF全1108个.etc脚本扫描该标签，命中0；independent_drop.etc本身也无该段。因此虽本服尚未实现这个控制机制，但目前没有证据它应该降低这件书的10%基础率。生成函数还有若干模式/加成分支，本轮仅记录存在，不宣称所有外层上下文已还原。70时期算法不能证明A21这件具体道具的官方最终爆率。
