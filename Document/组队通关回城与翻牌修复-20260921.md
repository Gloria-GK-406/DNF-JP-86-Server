# 组队通关回城与翻牌修复

## 观察与定位

用户确认死亡/复活验收通过，但通关后信息区显示 5、4、3、2、1 秒后返回城镇，未实际回城；手动回城成功。截图由用户提供。双人翻牌时，队友一端显示 0 金币、无装备，而实际领取有装备。

日志 revival-20260921/stdout.log:3462–3484 确认两名角色分别获得金币 39 与背包更新，最终 0047 快照广播双方；此前 0023 结算编码只在槽 0 写收件人自己的奖励，其余位置为零。共同翻牌按队伍位置读内容，因此显示与发奖不一致。

## 客户端静态证据

分析只读 A21 b1 镜像 DC322D8FB2A8A33FCE31065CEEAC5801ED854F34409190FE257AACF2663306E9，以下地址均 VA。

- 0x025FAA24–0x025FAA33：剩余时间 = panel+0x780 - elapsed(panel+0xC4) + 60000。另一特殊分支加 180000（0x025FAA16），不用于本次普通副本修复。
- 0x025FAA63 判断剩余不足 6000ms，除 1000 得秒数；0x025FAAC0 起按 1..5 及已提示位输出消息，0x025FAB8F 取得文本，0x025FABC8/0x025FABCF 投递信息区。
- 倒计时中的 0048(01 02) 构包在 0x025FAB03–0x025FAB43，受 0x013DB490(0xF) 模式门限制；门不满足直接跳到提示文本分支。并非每个普通客户端到期都会发送回城。
- 0x025F82E0 是 UI 状态切换；状态 5 分支 0x025F83DD 在 0x025F84AD 写入 +0x780 时间。服务端以翻牌版式投递作为 60 秒起点，精确可见时序仍需实机核对，不宣称原版服务器实现一致。

## 修改

- 结算时幂等固定同实例参与者的个人牌面，所有客户端的 0023 免费奖励行按同一队伍槽位携带全部成员金币和装备。经验与背包仍只给本人，未改变发奖事务。
- 双人及以上入场的已通关实例，在翻牌版式投递后记录一次 60 秒截止时间；轮询到期后核对 runId 和会话代际，结束实例并逐成员投递已有城镇状态。手动离开/换图清理旧截止时间。
- 单人和特殊模式未据此新增推断规则；这次覆盖已观察的普通组队流程。

## 待实机验收

双人通关并翻牌：两端共同结果的金币/装备应一致；不点击返回，信息区倒计时结束后双方自动回城，再次进图正常。手动提前回城重新进图后不受旧计时影响。
