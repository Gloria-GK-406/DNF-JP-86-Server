# 每日补给

当前实现：`DailyRefillConfigurationDomainService` 合并规则，`DailyRefillDomainService` 执行发放，角色进入游戏时通过这两个领域服务完成每日补给。

Web配置读取链路为HTTP → GM补给领域服务 → 补给配置领域服务 → `IDailyRefillConfigurationRuleService` → PVF内容源。配置规则服务负责读取PVF声明／有效规则、物品名称和自定义补给物品解析；配置领域服务负责持久化、版本校验及规则合并，不直接读取内容源。规则服务不读取玩家状态或配置数据库。

## GM 配置

左侧「每日补给」显示规则列表。每行标明 PVF / 自定义来源、补给方式、数量、截止时间和生效状态。列表可按全部 / 生效 / PVF / 自定义 / 未生效筛选；新增及编辑在右侧抽屉完成，物品从当前 PVF 目录选择，截止时间按北京时间填写；自定义支持永久普通背包堆叠物品。

选择物品经通用目录服务查询，由补给配置规则独立判断准入，并在分页前过滤；不经过初始化或邮件规则。调用链见 [ItemCatalog.md](ItemCatalog.md)。

PVF 规则直接读取 `etc/chn_server_limititemusageinfo.etc` 的 `[refill item]`，不复制到配置表，也不修改 PVF 文件。过期和数量为零的声明仍可在列表查看。GM 可禁用 / 恢复 PVF 规则，也可以创建同物品自定义规则覆盖。删除自定义规则后，已启用且有效的 PVF 规则恢复生效；自定义过期后不会自动恢复 PVF，需删除覆盖规则。

配置只保留一份生效内容，持久化于 `daily_refill_settings`。版本检查避免相互覆盖，修改和操作审计在同一事务提交。保存发生版本冲突或结果不明时，页面要求重新读取生效规则后再操作。配置变更不会删除角色当天处理记录。替换 PVF 后，已不受支持的自定义物品标为「物品不支持」并跳过，不妨碍其他补给和入场；仍不会自动恢复同物品 PVF。

## 发放

- 普通补给每个角色每日首次成功入场尝试一次，按游戏日（`IDailyResetRuleService.PeriodDay`，当前 UTC+8 06:00）切换；没有后台定时补发。牛头怪乐园等活动门票另有在线补发，见下文。
- **存量补齐**（目标数量 X）：背包内已有同物品达到或超过 X 时不发，不扣超出部分；不足时尝试补缺口。
- **增量发放**（发放数量 X）：额外尝试发放 X 个。单堆上限限制每堆容量，不限制此次总发放量。
- 先填已有堆，再在对应背包分类的已开放格子中建新堆；规则按物品 ID 升序处理。
- 放不下的剩余数量通过统一物品派发转入邮件；补给与领取记录在同一事务提交，邮箱中的待领取数量计入目标存量。
- 当天清理空间、重登、添加新规则或改数量均不会触发第二次补给。持续在线跨日也不自动补给，需要重新入场。

处理记录继续使用 `character_daily_counters`，不另建领取表。`daily_refill_attempt` 保存整个角色最后一次处理日期；保留兼容的 `pvf_daily_refill_item_<id>` 记录，PVF / 自定义共用物品标识，覆盖和删除不能重领。记录按日期先后比较：记录日期不早于当前游戏日即视为已领。原零点规则下的记录在切换当天可能比游戏日靠前，因此不会重复发放。

背包空间不足转邮件属于正常结果，不回滚已成功补给的物品。实际持久化异常仍使入场事务失败，避免发放与处理日期不一致。

PVF 列表对应当前进程已加载的档案，替换 PVF 后需按现有内容加载流程重启服务；Web 刷新不负责热加载档案。

## 牛头怪乐园门票（2026-10-15）

690001556 每个游戏日新增 1 张，日界与普通补给相同。每物品 `pvf_daily_refill_item_690001556` 独立去重，不受普通 `daily_refill_attempt` 批次遮挡。离线多日只领取当前周期的一份。

登录的 `ApplyDailyRefillAsync` 仍记录普通首次入场批次，即使规则为空或仅包含牛头票。6 点在线调度及选角发布后的补检调用 `ApplyIndependentRefillAsync`，只允许独立周期规则，不抢占普通登录批次。选角跨过 6 点时，发布后以当前时间重检同一领取记录，补上未发布阶段被调度器跳过的票。

在线任务仅枚举当前 selected 会话，并在账号命令门内重验 published/active 代次；离线角色交给登录处理。发放成功经 EventBus 更新背包；没有发放不产生额外背包通知。其他普通补给“当天新增规则不重发”的语义保持。
