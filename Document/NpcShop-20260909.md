# NPC 购买实现边界

日期：2026-09-09；起始提交：`8a82d584`。

购买沿既有模式：`BuyItemHandler → BuyItemCommand → INpcShopDomainService →
NpcShopPurchaseCompleted → Event handler`。限购查询采用相同命令与 Event 总线。
命令 handler 只注入领域服务与时钟，Event handler 只组合响应，不改业务状态。

`NpcShopRuleService` 通过内容源读取 NPC 与商店绑定、职业页、价格、材料和限购。
它先模拟整笔扣材料和入包，能容纳全部商品才交给领域服务写入。
金币、材料、商品和 `npc_shop_purchase_counts` 在同一 SQLite 事务中提交；
账户排他命令串行化账号限购购买。新增表由现有 schema 入口创建，不迁移旧物品记录。

限购按 PVF 的账号/角色范围计数；只有独立的 `[reset daily purchase item]` 声明
才按现有日界规则重置，单凭 `[daily purchase limit]` 名称不能推断每日重置。
没有金币 price 的材料兑换不以 `[value]` 出售价替代购买成本。

当前支持普通装备单件与堆叠商品，允许金币、材料或混合支付。普通装备 rawCount=0
按一件；负数、堆叠商品 0、数量越界、未知商品/商店、未支持的付费类型拒绝。
装备使用既有到达规则和 PVF 耐久/封印；物品期限和收集任务进度未在此次扩展。

礼盒的 `[booster info]` 是开启奖励作用域，内部 `[cera]` 不属于购买条件。
购买解析器只读取该作用域之外的价格、材料和限制；实际顶层 `[cera]` 仍按未支持的
付费类型拒绝，未闭合奖励作用域也拒绝。复活币礼盒 490003531 的购买成本为
`[need material] 490003528 2`，账号限购 10，无每日重置标志。

没有空格不必然拒绝购买：已有同类堆叠仍有容量时可购买；如果只能容纳一部分，
整笔拒绝。数据库测试覆盖全满、部分能容纳、可完整叠加三种情况，并检查金币、
材料、商品、限购及仅发送错误 4 的行为。

测试入口：

- `NpcShopRuleTests`：支付预演、空间、数量、商店绑定、重置声明。
- `NpcShopPurchaseTests`：真实 CommandBus/SQLite/Event，提交前不通知，写入故障全回滚，
  并发限购、跨角色限购、多材料堆与多商品槽、通知失败不重购。
- `BuyItemCodecTests`：真实请求向量、严格长度、A21 ACK 101 字节记录与两张计数列表。
- `GameLoginIntegrationTests`：真实 TCP 下未选角色购买与限购查询的 CMD 拒绝。
- `PvfNpcShopDefinitionSourceTests`：实际 PVF 中赛丽亚/塔娜及三种采样商品。

已实机确认秘药、职业转换书及金币装备购买正常，退出后的数据库结果与四笔交易一致，
见[实机记录](../protocol/patterns/data/traces/a21-shop-live-20260909.md)。
礼盒修复也已实机通过，两次购买入包 2 件、扣除 4 个预约硬币，限购表记为 2；
开盒功能不属于购买验收。背包空间及限购拒绝边界目前由服务端测试覆盖；没有归档完整 S2C 帧。
协议字段证据和应答顺序分别见 [BUY_ITEM](../protocol/game/client-to-server/0x0015.md)
与[商店流程](../protocol/patterns/flow-npc-shop.md)。
