## 比赛与状态

PVF 继续提供骑士名称、攻击类型、胜负动画、货币、奖励和等级门槛。规则服务负责读取内容，领域服务传入历史统计及随机种子，纯规则计算预测和赛果。

攻击类型编号采用 `0 → 1 → 27 → 28 → 0` 循环克制，相邻优势系数 1.25、反向 0.8，隔位和同类型为 1。未知类型按互不克制处理，不虚构其中文名称。

每期为参赛骑士抽取并保存三种状态：condition 0 强势（1.15）、1 常态（1.0）、2 弱势（0.85）。这三个编号是服务端策略。ClientStatic 确认 04B9 的 condition 字段选择图片 index=condition+3；三张图片的完整业务含义仍待实机核对。

单场 `P(A胜)=状态强度A×克制系数AB / (状态强度A×克制系数AB + 状态强度B)`。交换双方后概率互补。按固定淘汰树逐层枚举可能对手，计算八位选手夺冠概率，总和为 1。七场比赛使用同一套单场概率抽签，赛果一次保存；预测不读取已经抽出的赛果，不提前把冠军概率变成 100%。

## 历史与定价

历史强度 `(胜场+10)/(败场+10)`；无记录强度为 1。以历史强度的两两胜率走同一淘汰树，得到历史夺冠基准 H。它与客户端显示的真实累计胜率不同：显示仍为 `胜场/(胜场+败场)`，未做平滑。

本期夺冠概率为 P。定价概率 `q=H+k×(P−0.125)`，k 初始 0.4。如果某位选手超出 [0,1]，统一降低 k，使所有选手合法；不逐个重归一化。因此 P 为 12.5% 的选手，其历史基准不变。比赛抽签使用 P 对应的单场模型，定价 q 只决定赔率。

初始赔率采用用户确认的分段曲线：

```text
a = ln(6/14) / ln(0.6) ≈ 1.658683161
q ≤ 0.125：D₀ = 2 + 14 × (1 − q/0.125)^a
q > 0.125：D₀ = 1.1 + 0.9 × (1 − q)/0.875
```

0%、5%、12.5%、100% 分别对应 16.0、8.0、2.0、1.1。无历史、无状态差异、互不克制时，所有人均为 2.0；真实每期随机状态和历史不同，起始赔率会不同。

动态赔率 `D=1.1+(D₀−1.1)×1000/(1000+B)`，B 为该骑士本期全体玩家累计投注；别人给其他骑士投注不抬高本骑士赔率。赔率按一位小数四舍五入并限制在 1.1..16，客户端、存档、结算共用该精度。初始 2.0 时，累计投注 1000 后为 1.6，9000 后为 1.2，持续增加时趋近 1.1。

## 持久化与兼容

轮次 JSON 保存算法版本、种子、状态、H/P/q 和完整赛果。封盘由生命周期事务保存八位骑士的最终赔率；查询只能读取，不能写入封盘。重启、改赛程或历史统计增长不改变已有快照。即使时钟回拨到投注期，已经封盘的场次也不能再下注。

中奖骑士的同角色投注先汇总，再按 `floor(投注量 × 封盘赔率)` 计算奖励；不向上取整。最低 1.1 倍时，1 枚返回 1 枚，10 枚返回 11 枚。已保存的封盘赔率不因规则更新重算。

Result 才按封盘赔率统一发奖、记录赛果和更新胜败统计；冠军增加 3 胜。邮件提醒由邮件系统负责，查询和投注不增加公告。跨期时，新场次历史基准包含同一事务内已结束的上一期结果。

升级前的轮次没有概率快照，保留版本 0 的原投注池赔率和原赛果，避免改变已接受投注的奖励。所有新创建轮次使用版本 1；旧期不重抽、不重新发奖。此次部署同时包含此前已完成的 time 场次 ID 与跨日递增结果期号迁移。
