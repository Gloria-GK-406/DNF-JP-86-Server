# 指定怪物独立掉落

状态：服务端实现与自动化验证完成；A21 全表预热通过。尚未部署或实机验收。

## 规则

- 在 Cell 生成 actor 时调用一次 Ground 生成，结果冻结在 PendingLoot，死亡后进入现有地面编号与拾取流程。
- sourceType：Monster=0、APC=1；相同数字 ID 分属不同命名空间。APC 只查询对应独立表，不走普通、Extra、世界或 monster reward 来源；经验和清房规则不变。
- 五个概率列按难度 0..4 选择；分母 1,000,000，超过分母饱和为必掉。
- 前四个数量列按整队 1..4 人选择试验次数，第五列限制成功次数。每条规则按整队计算一次，不再按人数乘一轮。
- 等级字段作为玩家等级闭区间，0 为不限制。本轮共享 Ground 使用生成角色（当前 Cell 工厂为队长）的等级；领域内部读取，不把动态等级或背包快照加入对外 context。混合等级队伍的逐成员资格/个人归属是后续独立边界，不能声称已实现。
- mode=0 直出物品；mode=1 每次成功按内嵌列表相对权重抽一项。重复条目保留，零权重不命中，累计权重在启动时构建。
- 原始第16字段保留但不筛选，跟踪 #128。外部池模式不支持并明确拒绝。
- 随机流按 seed/map/cell/actor/行序号派生，与其他来源隔离。同一生成事实可复现。

以上是本服明确采用的规则，不标记为原版台服或 A21 服务端算法已证。

## 缓存与数据检查

Host 在运行前预热全部独立规则、物品元数据、按来源/ID 的索引和列表累计权重。绘制不重读 PVF。匹配到来源后才查询角色等级，同次调用只读一次，角色等级不存进静态缓存。

A21 原始表：3046 行，374 行 APC，4953 个列表条目，1961 个不同物品 ID。
全表交叉核对 equipment.lst / stackable.lst 发现唯一缺失引用：

```text
zero-based ordinal=2801
sourceType=0 sourceId=65696 itemId=10150672
probability=[500000,500000,500000,500000,500000]
attempts=[1,1,1,1] cap=1 playerLevel=[0,99] rawFilter=-1 mode=0
```

不是解析器少读字段：独立 dump 与索引扫描同样找不到该 ID。用户选择不禁用，只记录警告：

- 保留全部行、原概率和原列表权重；缺失定义作为显式 null 元数据缓存，启动预热记录 Warning（行号、来源类型、来源 ID、物品 ID）。
- 该行仍参与抽取。实际抽中缺失定义时记录 Warning，只是不生成这一次未知物品，不重新抽取、不替换物品、不调整其余权重。
- 这不是将未知物品伪装成普通材料；不会向客户端下发缺少定义的物品。补齐 PVF 后重启即可恢复正常产出，无需启用规则开关。
- 缓存缺键与已知缺失定义区分：缺键仍抛异常，格式错误、未知模式、空权重池等仍明确失败。
