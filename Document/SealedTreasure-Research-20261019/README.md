# 封印的藏宝地（DGN 3557）调查汇总

调查日期：2026-10-19。对应 [GitHub #154](https://github.com/Gloria-GK-406/DNF-JP-86-Server/issues/154)。

本轮授权：“你先派子代理完成全部信息收集吧”。三条调查线分别覆盖历史玩法、当前 PVF 内容和生产差距、A21 协议与 70 服务端参考。本文是调查成果汇总，尚未进入实现阶段。

## 结论

本图具备继续开发所需的静态资源和通用副本基础，但不能直接照搬南部溪谷的开放逻辑就宣称完成。除入口、门票和单人限制外，还需要处理跨房间元素封印，以及中央宝箱的奖励出现时机。

当前最明确的准入缺口是：免费票 `10003235` 的补给声明有效至 2030 年，现有代码有补给能力，但通用地下城入口只读取普通票 `10003196`，免费票不能满足入场条件。70 通用服务端明确采用“活动票优先、普通票回退、只扣一种”；这是合理的初始设计参考，尚未证明 A21 本图原服也使用完全相同的策略。

历史国服的“每天免费 1 次、额外买 2 次、06:00 刷新、不消耗疲劳”有同期资料支持，当前生产代码却是普通补给零点换日、没有本图独立每日次数上限，而且通用路径会消耗疲劳。它们是需要明确选择并验证的规则差异，不能把两套行为混写成已还原原服。

## 实现前需要处理的差距

1. **准入与消费**：解析备选活动票，保证检查、选票、扣票与创建运行之间的一致性。仅改变具有备选票声明的地下城，避免破坏普通多材料入场的 AND 语义。70 的优先级可作为候选，不照搬其拒绝码。
2. **入口和限制**：当前没有 3557 专用活动路由。开放显示优先验证 `NOTI 0x033F {0,1,3557,0}`，并差分 state 2 / 0；schedule `2331` 只是配置身份，不作为同等的线上 contentId 候选。单人和禁止练习应在实际准入执行。
3. **次数、补给和疲劳**：现有免费票补给按北京时间自然日、选角阶段处理，不是本图在线 06:00 补发。stack limit 1 / 2 不能证明每日次数上限。当前 PVF 无 `[no fatigue]`，通用路径会扣疲劳；采用历史规则需要显式实现和验收。
4. **跨房元素状态和道路**：现有服务端没有 PARTY SYMBOL / 四元素状态，通用移动不解释四块封印石。需确认客户端 ACT 能自行完成哪些行为，再决定服务端状态与房间投影如何配合，防止重新进房恢复石头或绕过封印。当前没有已证据支持的新 opcode。
5. **中央箱与奖励**：当前源码在创建房间时冻结并投影声明物件掉落，未证明客户端会按物件关联延迟到打碎后显示。需检查提前拾取、重复报告、回房、背包满和事务幂等。147 项开箱池存在不代表所有奖励已实测可创建。
6. **退出与任务边界**：正常通关、放弃、死亡、断线、重试的退票/扣次规则没有可靠原服证据。三个孤儿任务维持现状，只有原生可达证据出现后才评估恢复。

## 下一步最有价值的验证

- 两票都无、各持一种、两种都有：入口显示、扣票优先级、成功/拒绝帧与数量。
- 单元素击杀后离房再回：对应石头、道路和状态是否保持；保存双向帧，判断是否存在独立同步。
- 中央箱打碎前后：掉落显示与实际可拾取时机、只开一条路线能否到达中央、重复请求是否重复奖励。
- 合法路线至 Boss：疲劳变化、结算和宝箱开启；再验证放弃、断线和新一局的状态清理。
- 跨日和额外购票：区分补给次数、库存上限、购买上限和真正的挑战次数限制。

这些未知项不应伪装成资料收集遗漏后用常识补齐；需要原生客户端或新的协议证据。当前资料足以提出可评审的实现方案，尚不足以宣布该活动图可正常游玩。
