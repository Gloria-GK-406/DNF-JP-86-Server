# 跨栏位存取合并：实现与 70 端证据（#314）

## 实现

`CargoTransferDomainService` 处理背包 ↔ 个人金库 / 账号金库、共享材料 → 金库这几类跨存储移动时，不再直接用客户端提名的格子：

1. 可堆叠且上限大于 1：在目标栏位已开放的格子里，从低格号往高找 `CanStackWith` 成立、还有余量的同种堆，依次填满。
2. 填不下的余量：提名格为空就放提名格，提名格被占就放第一个空格。余量超过单堆上限，或没有空格，整次移动拒绝，两边都不变。
3. 提名格被别的物品占着时不再交换。
4. 上限为 1 的物品不合并，落提名空格或第一个空格（沿用 2026-10-03 的行为）。
5. 目标是共享材料（每种材料固定一格）、或涉及镜像的移动，仍走原来的直接路径。
6. 回执里的目的格是第一个实际落点；随后照常推两边容器的 NOTI 0x000D 完整快照。

同栏位内拖动和整理不变。整理补了一条成功日志（角色、栏位、排序条件、移动件数）。

## 70 端证据（静态逆向，High，未实机）

ELF：`Research/1995chen-dnf/other/等级补丁/70/df_game_r`，地址为 ELF 虚拟地址。

- 入口：`DisPatcher_MoveItem::process` @0x081c5904 → `CUser::exchange_interspace` @0x0865f7b0（按源、目标空间两级 switch）。
- 背包 → 个人金库（@0x0865f8c1）：可堆叠物品先 `CCargo::check_item_exist` @0x0850bc14 从 0 号格往后找第一个同 ID 格，找到就把目标改成该格（@0x0865fb62），不管客户端提名哪格。没有同种堆时，提名格为空就用它；被占则 `CCargo::get_empty_slot` @0x0850c406 改投第一个空格（@0x0865fb46）。没有交换分支。
- 个人金库 → 背包（@0x0866034e）：完全不读提名格，`CInventory::insertItemIntoInventory` @0x08502d86 自动选格，先找同种堆（`stackInvenItemIntoCorrespondingSpace` @0x08502a7e），再找空格。
- 背包 → 账号金库（@0x0865ff3b）：`CAccountCargo::GetSpecificItemSlot` @0x0828a61a 找同种堆，空格逻辑同个人金库，只允许整堆存入。

## 与 70 不同的两处（按 #314 已定方案）

- 合并后超出堆叠上限：70 整体拒绝（`_tryAddStackItem` @0x0850b4b0 返回 -10 → 错误 4），不做部分合并；本实现填满已有堆，余量开新格。
- 上限为 1 的物品：70 在金库已有同 ID 时也会被强制指向那一格并拒绝；本实现落空格。
- 70 只按物品 ID 找同种堆；本实现按 `CanStackWith`（除数量外 item_core 相同）判断，更严格。

本次线上出问题的物品都没写 `[stack limit]`，不受前两处差异影响。
