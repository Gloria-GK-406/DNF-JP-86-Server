# PartyKey 与副本成员重构：A21 实机验收

状态：服务端自动化回归已通过；以下客户端行为**尚未实机验证**。本工作区没有部署到主干 Host，不能将此文档视为 ClientVerified 结论。

## 测试前提

- 在获得部署授权后，用本任务构建部署同一份服务端；两名测试角色 A、B 使用不同客户端和连接，保留服务端日志及必要的客户端帧记录。
- 每个场景重新组队、重新进入副本，避免上一场景的队伍或运行状态干扰。记录角色 ID、队伍客户端 ID（若抓包可见）、副本 RunId、房间/Cell、动作时间和双方画面。
- 遇到卡死、掉线或不同步，先保存现场、日志与双方截图；不要用“重登后恢复”代替原场景的结果。

## 场景与通过条件

| 场景 | 操作 | 双端应观察到的结果 |
|---|---|---|
| 城镇队长离队 | A 建队、邀请 B；确认队伍设置后，A 主动离队。 | A 清除旧队伍；B 成为队长且仍是单人真实队伍，队伍设置保留。B 的客户端旧队伍对象先退役，再显示新客户端队伍 ID 的队伍，并出现原版“是否保留队伍”提示。 |
| 副本中队长离队 | A/B 共同入场并进入至少一个 Cell；A 单独退图/离队；B 继续移动、过图及清怪。 | B 不被强制退图，服务端保持原 RunId 与已创建 Cell；B 继任队长。A 不能再操作该 RunId，也不收到其后续通知。新加入队伍但未入场的 C 也不能操作或收到该 RunId 通知。 |
| 离队后的新 Cell | 在上一场景中由 B 首次进入未生成房间，再回访该房间。 | 首次生成只按当前 B 及当前队伍人数处理成员相关内容；回访不重新生成；已有共享掉落/房间内容不因 A 离队消失或整体重算。A 尚未落地/发放的个人专属结果不转给 B。 |
| 通知与连接 | B 留在副本继续行动；若条件允许，让 A 重连，检查旧连接与新连接的收件情况。 | 只向仍具该 RunId 资格的当前连接投递；离队者、旧连接和图外新成员均不收到副本事件。 |
| 单人虚拟队伍 | 未组队角色独自选图、入场、过图、拾取及退出。 | 不需要创建真实队伍；流程与既有单人体验一致，不出现真实队伍提示或孤儿副本。 |
| 多人常规流程 | A/B 重新组队，正常选图、入场、过图、清怪、拾取、退出。 | 两人可见且同步，未因身份分离退化；队伍广播不误发给旧连接。 |

## 反馈格式

请按“场景、操作顺序、发生时间、A/B/C 角色、预期与实际、双方截图/录像、服务端日志区间、能否稳定复现”记录。若能拿到抓包，再附旧/新客户端队伍 ID 和通知顺序；不要为了抓包延迟保存崩溃现场。

实机验收前，本任务只能声明服务端构建、测试与静态投影顺序通过；客户端是否显示“保留队伍”提示、P2P 是否保持连接及双端视觉效果必须以这轮测试为准。
