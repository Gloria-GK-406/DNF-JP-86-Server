# 共享材料统一容器：集中实机验收

状态：代码及自动验证交付后待部署、待用户实测。本清单不授权自动部署；当前运行服务和数据库未在此任务中修改。模型与迁移限制见 [账号共享材料容器](AccountMaterialBag.md)。

## 部署前

停服备份完整数据库及当前程序；在副本先完成启动迁移，核对 11 种材料迁移前后逐账号数量，以及账号金库、个人金库与装备 UID 未变化。若报告历史材料实体冲突，按来源核实，不猜测相加或删除。首次启动成功后再启动一次，材料数应不再变化。

## 一次集中操作

1. 同账号准备两个角色，以一个角色记录六种晶体与五种品级灵魂数量。逐种向个人金库存入一部分，再存一部分合并，取回全部；对账号金库重复。尤其验证无色晶体 Main/358 不断线、图标和数量及时刷新。
2. 账号金库留一部分材料，换同账号另一角色：共享栏数量一致，账号金库内容一致；取回后两处总量不变。个人金库保留角色归属。另一个账号不得见到前一账号材料。
3. 对空槽/已有同种槽分别拖动和点击存入，尝试满仓、未开放槽、错误材料槽及超过持有量的请求（客户端允许时）；应正常拒绝且数量不变，不断线。
4. 完成一组技能材料消费、强化或分解、地面拾取/任务奖励、材料邮件领取与可用开包。核对实际花费/产量、背包、共享栏与费用；金库里的材料不应被技能等消费自动扣走。
5. 把一种材料消耗到最后 1 个再耗尽：立即清零，不出现“获得 0 个”或头顶材料图标；再次获得时恢复正确。其余未耗尽材料不被清空。
6. 有非零材料时触发现有重新同步路径；退回选角、换角色、退出重登，再重启测试服。所有数量应与操作后相同，不能重复增发或恢复迁移前余额。

记录版本、角色、操作前后数量、异常日志时间；出现问题时保留对应客户端抓包。无需为每种材料重复所有玩法，存取矩阵覆盖 11 种即可，消费/奖励选有代表性的晶体与灵魂。
