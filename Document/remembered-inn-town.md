# 当前城镇与登录旅店分离

## 问题与行为

从虚祖（11）进入时空之门（12）后，原实现把当前城镇写为 12，登录又用这个城镇寻找赛丽亚出生点。时空之门没有可用的旅店入口，因而回退到初始城镇（1）。

现在分别保存：

- `town_id / area_id / pos_x / pos_y / direction`：角色当前实际位置，跨区与退出时照常更新。
- `last_inn_town_id`：最近到达的、具有有效赛丽亚出生点的普通城镇，普通频道登录使用它。

是否能记录为旅店由 `EntryPlacementRuleService.CanRememberInnAsync` 根据 PVF Gate、协议坐标范围和特殊频道规则判断。进入没有旅店的区域仅更新当前位置；同一事务内先到有旅店的城镇、再进入无旅店区域，仍保留前者。位置与旅店同事务提交或回滚。

普通频道登录优先使用记录的旅店；旅店无效仍回退到配置的初始城镇。CH100 沿用圣者之鸣的临时落点，不持久化该频道的位置或覆盖普通旅店记录。在线位置查询、进图和出图继续使用实际位置。

## 旧数据与验收边界

统一 Schema 为既有数据库补 `last_inn_town_id INTEGER NOT NULL DEFAULT 0`，不覆盖任何现有位置，不把任意未知区域硬编码成虚祖。值为 0 的旧角色首次登录用现存城镇尝试解析旅店，成功落地后保存有效旅店。

如果旧数据已经被回退覆盖，或只剩时空之门位置，数据库没有更早的旅店历史，无法可靠恢复之前的虚祖；角色再次到达虚祖后会正确记录。查询过程本身不补写历史。

回归检查覆盖实际 PVF 下的 11/12 旅店区别、跨角色隔离、CH100 临时落点、登录使用旅店而非当前城镇、连续跨区与退出保存、事务回滚、旧 Schema 补列和重复打开。客户端期望流程为“到虚祖 → 时空之门 → 正常退出 → 普通频道重登 → 虚祖赛丽亚旅店”；自动检查不代替该实机验收。

本次只修复本地源码，不部署、不修改运行数据库，不修改客户端或 PVF。
