# GM 官方邮件

在 [GM 后台](gm-web-admin.md) 的“官方邮件”页面操作；管理员需要独立 SendMail 权限，可以没有 QueryPlayers/ViewAudit。页面只查询必要收件角色身份，不提供账号资产。操作记录总页面仍需 ViewAudit；个人邮件发送历史在邮件页查看。

先填标题、正文、每人金币，通过“添加物品附件”检索并配置物品，再查找并明确选择角色。跨页保留选择，按 ID 计次，同账号两个角色也会各收到一封。单批最多 100 个角色；预览显示真正发送的文本、收件人、每人及全批数量，确认后整批提交。预览之后返回编辑会取消该确认，必须重新预览。

附件弹窗支持名称包含搜索、精确 ID、装备/材料/消耗品/任务物品/其他分类；装备可按部位、最低/最高等级和稀有度筛选。名称使用当前 PVF 原文；目录分页只返回邮件支持的永久物品，不做额外翻译。图标来自部署的 [图标包](gm-item-icons.md)（缺失时显示名称首字），tooltip 为静态 PVF 资料（见 [GM 后台](gm-web-admin.md)「服务信息与物品展示」）。选中后配置每人数量，加入后可编辑或移除；相同 ID 和配置合并数量，不同配置的同 ID 装备分别保留。

普通装备可保留模板封装状态或解除封装，并选择“无强化/增幅”“强化”“增幅”。强化与增幅共用升级等级，不能同时设置；增幅可选力量、智力、体力或精神，基础异次元属性值由 PVF 规则生成。允许等级按现有装备成长规则确定，最高不超过 31；不支持的选项禁用并说明原因。GM 直接生成指定最终状态，可保留模板封装，不走玩家随机升级、不消耗材料或金币。附魔、魔法封印词条与任意 core 字段不在此入口开放。

装备配置另有三项（JSON 字段 `forge`、`socket`、`quality`，取默认值时不写入，旧草稿/模板/操作的序列化与校验值保持逐字节不变）：

- **锻造** `forge`：只限武器，0..锻造表上限（`etc/upgrade_separate.etc [separate upgrade max]`，当前 8），写入物品的锻造等级，可与强化或增幅同时设置。非武器或超上限拒绝。
- **开孔** `socket`：按装备部位的徽章孔布局（`etc/chn_equipmentsockettypelist.etc`）开出空孔，与玩家打孔后的状态相同；武器、称号等没有布局的装备拒绝。
- **品级** `quality`：0 最下级、1 下级、2 中级、3 上级、4 最上级，省略即 4（显式 4 与省略视为同一配置）。

GM 邮件生成的每件装备都写入所选品级对应的 A21 固定属性种子（0→999999993、1→999999996、2→999999999、3→999999995、4→999999998），客户端按该档上限（20/40/60/80/100%）显示；不再逐件随机种子，同一固定种子重复出现属正常（PVF 最上级品级箱同样使用 999999998）。依据见 `protocol/game/server-to-client/CMD-0x0051.md`「装备种子（ClientStatic）」。物品详情 `GET /api/gm/v1/mail/items/{id}` 的 `equipment` 同时返回 `maxForgeLevel`（非武器或锻造表不可用为 0）、`socketCount`（0..2）与 `socketClass`（两孔同类返回单字母如 `C`，混合如 `A/B`，无孔为 null）；预览与新收据的物品行附带 `forgeLevel`、`socketCount`、`quality`，旧收据读出时按 0/0/4。

草稿每管理员一份，保存后可刷新/重新登录恢复；“重新加载草稿”显式覆盖当前编辑。个人模板最多 20 份，保存内容与附件，不带收件人；加载模板保留当前选择。保存/覆盖/删除带版本检查，遇到冲突应重新加载，再确认内容，不自动覆盖。

支持永久普通装备、永久堆叠物和金币。每人最多 10 个展开物品附件及一份金币：装备每件占一个附件、各有不同 UID，堆叠物一行按数量领取；0 金币不生成附件。时装、宠物、宠物装备/消耗品、期限道具、复活币/虚拟资源、权益服务和未知/不支持实例声明会被拒绝。账号共享材料通过原邮箱领取进入账号材料袋。后端独立验证数量、模板和装备组合，不接受客户端指定现有玩家 UID 或原始装备数据。

实际展示为正文，或“标题 + 换行 + 正文”，最多 511 个 UTF-8 字节。中文通常占 3 字节；以预览为准，超限拒绝，不截断。系统官方来源、提交起 30 天有效，玩家在原邮箱领取；满背包或金币上限导致领取失败时附件仍保留，腾出空间/金币容量后再领。

一次确认产生一个 UUID，随完整内容提交。相同管理员用同编号/内容重试返回原邮件编号，不重复发放；改内容复用编号返回冲突。结果暂未确认时，页面保存冻结请求，刷新仍可查询原编号或按原内容安全重试，禁止新建编号再发；“记录未找到”并不证明先前请求已回滚。持久化结果列出每位收件角色、邮件 ID、装备 UID 及实际期限。在线提醒未确认不改变已发送状态，不代表客户端已读或已领取。

草稿、模板、预览、冻结请求和收据保留装备配置。新收据还保存发放时的物品名称、封装、等级和异次元属性值，不随之后的目录变化重算。旧草稿和收据可继续读取，未指定装备配置的请求保留原序列化校验值；使用显式默认配置与旧请求等价。会话或权限失效不会清除待确认请求。

## 待真实客户端验收

后台 HTTP/SQLite/页面判据与客户端表现分别验收；以下客户端项目在用户执行前不标 ClientVerified。测试环境及测试玩家资产需要显式操作授权后才可准备，不使用现服做自动化验证。

| 项目 | 操作 | 预期 |
|---|---|---|
| MAIL-01 | 保存草稿，刷新/退出再登录，加载内容模板 | 草稿及明确角色可恢复；模板只替换内容，保留当前收件人 |
| MAIL-02 | 给一个离线角色发送纯文字官方邮件，登录打开邮箱 | 系统官方来源；中文标题/正文与预览一致，30 天期限 |
| MAIL-03 | 给两个明确角色批量发送材料、金币 | 各一封，各有相同附件数量；其它角色不收到 |
| MAIL-04 | 给一个角色发 2 件普通装备并领取，重新登录 | 两个不同 UID；初始耐久/封装正常，领取及重新登录后仍存在 |
| MAIL-05 | 发账号共享材料并领取 | 进入既有账号材料袋，数量正确，不额外进入普通物品栏 |
| MAIL-06 | 背包满/金币到上限时尝试领取，腾出容量后再领 | 初次失败不消失，后续仅领取一次 |
| MAIL-07 | 给在线角色发送，再用原编号重试 | 邮件仅一份；在线提醒正常或明确未确认，重新打开邮箱可看到持久化邮件 |
| MAIL-08 | 预览超长中文、期限/时装/宠物附件及无效目标 | 明确拒绝，全批无部分邮件 |
| MAIL-09 | 后台记录查看、刷新及网络失败恢复 | 结果/邮件 ID 可追溯；未确认请求只查原编号或原内容重试 |
| MAIL-10 | 按名称、精确 ID 和分类查找附件，切换装备部位/等级/稀有度并翻页 | 显示符合条件的永久可发放物品，筛选后回到第一页；空结果可识别 |
| MAIL-11 | 同一装备添加 +7 与 +10 两种配置，保存草稿和模板后重新加载 | 两行配置和数量分别保留，预览及收据与配置一致；每件装备独立 UID |
| MAIL-12 | 给测试角色发送解除封装、增幅 +10 的合格装备，领取后重新登录 | 指定封装、等级和所选异次元属性保持一致；界面实际效果由 A21 验收 |
| MAIL-13 | 添加重复材料；增加装备数量使展开附件超过 10 | 材料合并数量；超限不能发送，后端同样拒绝 |
| MAIL-14 | 发送锻造 +5、品级“中级”的武器与开孔、品级“最下级”的手镯，领取后查看 | 武器显示锻造 +5，手镯有两个空徽章孔可镶嵌；两件品级分别显示为中级/最下级的上限值 |

## 隔离页面夹具

自动化使用 `GmMailBrowserFixtureTests.ExplicitMailBrowserFixture`。显式设置 `DNF_GM_MAIL_BROWSER_FIXTURE=1`，并把 `DNF_GM_MAIL_BROWSER_FIXTURE_DIRECTORY` 指向任务工作区 `artifacts/gm-mail-browser/spec004/` 内新的子目录；已有 test.db 会拒绝启动，不会清库。仅监听 127.0.0.1:18083，游戏/登录器网络关闭，创建隔离 operator 与 45 个合成账号，角色 1/2/3 可接收邮件。预置“测试补偿”模板但不发邮件；物品示例 27312（普通装备）、3（堆叠物）、3037（账号材料）来自当前只读 PVF。

设置 `DNF_GM_MAIL_BROWSER_FIXTURE_VERIFY_ONLY=1` 可做启动/预览/模板和页面自检后正常停止；常驻模式在夹具目录创建 stop.txt 停止，最长 15 分钟。不能与共享输出的 .NET build/test 同时运行。页面始终测试隔离资产，不把合成生命周期当作真实游戏客户端收件证据。
