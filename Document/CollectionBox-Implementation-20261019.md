# 常驻收集箱：实现与实机验收

日期：2026-10-19。基准提交：`bf283b868cef249ca731e5555b64d8d80202a556`。任务 #164，工作分支 `task/collection-box`。

## 已实现行为

系列与格子来自 PVF `localization/collectbox/collectboxinfo.etc`；当前 SAO 15 件、生肖之灵 12 件、三国志 11 件共用同一实现，三国最后的 `-1` 洞不接收物品。支持系列 ID 1–255，每系列最多256格、255个有效物品；重复 ID、坐标、同箱重复物品及超限定义拒绝。

角色同时选择一套。历史系列到期时间不再限制箱子，03EB 始终 `remaining=0/permanent=1`。默认选择最低有效系列；显式选择或成功物品转移会保存选择。登录、当前角色状态重建和已提交请求重放均填充全部系列，最后重复选中系列并设 `selectAndRefresh=1`。客户端原生应用该箱加成，服务端不向基础四维或攻击数值重复加成。

放入从当前默认、持久 Main 背包对应业务格中精确取一件，不依据请求的物品 ID 创建新物品。拆堆保留完整物品快照，取出走 `InventoryOnly` 的现有原物投递路径，合入兼容堆或空格；满包拒绝，不转邮件。SealFlag、TradeRestriction、附魔和其他实例字段随原物保存。首版拒绝限时、已过期、排序锁和装备锁物品；常驻规则不清除物品自身期限。只允许操作当前选中系列，伪造其他箱号不能触发切换或全局搜物。

## 持久化和升级边界

`InventoryContainerType.CollectionBox=241` 是角色独占的服务端容器。`item_slots` 中的稳定位置为 `boxId*256+slotIndex`，slotIndex 为行优先的格子序号；完整快照继续由 `items` 保管。`character_collectbox_state(character_id,selected_box_index)` 仅保存选择，不保存派生加成或历史期限。两者在同一个 SQLite 参与者、同一命令事务中结算。新系列不需要新增业务类或系列专属表；客户端也必须拥有匹配的新资源，服务端配置不能凭空创造客户端系列。

普通角色库存查询仅加载 0/1/2/3/7，不把241编码为客户端背包。账号所有者不能创建 CollectionBox 容器。

旧 `character_collectbox_slots` 只有 itemId，无法恢复原始实例；保留原行，记录诊断并拒绝覆盖对应格，不制造默认新物。系列删除或格子改义后，原物仍留在241，冲突物品不投影加成，查询诊断和服务端警告日志说明位置。此类原物需要另行审核的迁移或返还操作；本轮没有自动迁移。不得复用既有系列／格子 ID 去悄悄改变物品含义。

DDL 是新增表，但旧 v0.2.6 库存加载器不认识241，因此**不能把旧二进制直接配新存档回滚**。未来部署前应保留二进制和数据库的成套备份；恢复旧库会丢失备份之后的进度，需停写后另行决定。此次没有修改真实玩家数据库，也没有部署。

## 协议与证据

| 协议 | 当前实现 |
|---|---|
| C2S03E5 | 1B箱号；成功完整体 `01 boxId` |
| C2S03E6 | 8B：箱号、零保留字节、Main绝对槽u16、itemId u32；成功 `01` |
| C2S03E7 | 5B：箱号、itemId u32；服务器选择背包落点；成功 `01` |
| C2S03E8 | 严格8B；永久模式拒绝，券与背包不改变 |
| NOTI03EB | 8+4n完整箱快照；先所有箱select=0，再选中箱select=1；永久标志为1 |
| NOTI0381 | 独立两帧 `01 01 FF FF FF FF 00 00`、`02 01 FF FF FF FF 00 00` |

拒绝完整体为 `00 error`。当前协议映射：选择失败5F；放入时源槽缺物／源物品ID不符12、锁／限时17、非本箱物品及其他无效操作15、未知箱5F；取出缺物01、满包04、其他15；延期5F。映射限定在各原生处理器可处理分支内，但具体提示语和领域原因对应仍需实机核验，不能当作原服抓包结论。

提交后投递顺序为库存绝对变化 → 箱快照 → ACK，三者属于绑定原物理连接的同一个批次；拒绝ACK也绑定原物理连接，不通过可复用连接ID重新寻址。这是当前服务端选择，参照上游行为，没有新增A21实帧证明其严格时序。领域层仅返回业务拒绝原因，上表原生错误码完全由协议切片映射。

若提交后投递失败，结算账本不会再次转移物品；放入／取出的有效窗口重试发送当前库存与全部箱状态，不重放旧ACK。选择请求重试只恢复当前箱与选择，不附带普通库存帧。断线后的新连接通过选角从持久事实恢复。

静态布局依据和镜像身份见 [设计](CollectionBox-Design-20261019.md)、[研究](CollectionBox-20261019.md) 及 `protocol/game` 对应记录。当前等级为 **CurrentImplementation + ClientStatic**，尚无本轮 WireCaptured 或 ClientVerified。

## 自动验证覆盖

真实 SQLite 测试覆盖三系列拆堆／合堆和完整快照、满包无邮件、转移后选择表故障回滚、锁和期限拒绝。合成系列测试覆盖扩展、持久选择、跨角色隔离、旧记录及定义冲突；不依赖PVF。编解码和完整 dispatcher 测试覆盖严格字段、固定0381、选角、重放、丢失投递后的资产守恒及投递顺序。最终验证和独立审核位置：`tasks/collection-box/verification/completion-evidence.md`、`tasks/collection-box/reviews/change-review.md`。

## 用户实机验收步骤

1. 后续另行部署后，用测试角色打开收集箱，确认 SAO、生肖之灵、三国志均可选择，且历史期限不阻止操作。记录空箱03EB及选择03E5实帧。
2. 每套分别准备一件、同类多件堆和带绑定／封装状态的物品。放入后背包只少一件、对应格出现物品；再次放同格被拒绝。三国空格保持不可用。
3. 切换系列观察角色面板，只应用当前箱加成；重登及重新选角后仍恢复原选择和已放物品，避免三套累加。
4. 取出时验证合堆和空格落点、物品自身字段及绑定状态不改变；背包全部可用格填满且无兼容堆时，取出拒绝，箱内物品保留。
5. 锁定和限时物品不能存入。尝试延期操作，确认拒绝提示、券数和原箱状态不变。
6. 保存全过程双向抓包，核对03E5–03E8、03EB字段及原生提示；当前自动检查不能替代这一步。

实际PVF未改动。常驻文案建议只移除各系列说明中的历史到期／延期提示，保留格子、物品、加成和PVP限制定义；资源变更应单独备份、校验并验收。
