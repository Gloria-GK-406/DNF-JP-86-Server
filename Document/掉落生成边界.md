# 掉落生成边界

2026-09-23，#124 第一阶段：统一怪物掉落生成入口，保留现有产出规则。后续各来源的算法与 PVF 解释仍需分别调查、实现和验收。

## 对外调用

```csharp
await drops.GenerateGroundAsync(monsterId, context, cancellationToken);
await drops.GeneratePersonalAsync(monsterId, characterId, context, cancellationToken);
```

怪物创建方通过 `IMonsterDropDomainService` 的两个入口分别生成地面与个人产出。`MonsterDropContext` 包含副本实例 ID、地下城 ID、随机种子、房间坐标和地图 ID、难度、怪物实例序号、实际等级和类型，以及发起角色与入场参与者的账号/角色 ID。

参与者是入场时固定的身份集合，使用不可变数组；不传背包、任务快照、在线连接、房间实例或领域服务对象。人数从身份集合得出，不接受另一份可能不一致的人数。发起角色必须属于集合，重复角色身份拒绝。

`RunId` 可供后续来源按需查询副本事实；当前随机序列仍由原来的 seed、map、cell、actor sequence 组成，避免本次结构迁移改变抽取结果。上下文不携带完整 `DungeonLayout`。

## 内外职责

| 层次 | 职责 |
|---|---|
| 房间创建 | 每个怪物调用一次 Ground，再为每名参与者各调用一次 Personal；合并结果固定到 actor 的 PendingLoot |
| 掉落领域服务 | Ground 编排各来源（当前启用普通和世界，其余具名占位）；Personal 校验目标属于入场参与者，再查询该角色的个人来源 |
| 普通掉落规则服务 | 读取静态掉率表、金币表、物品池，按场景值和种子计算 |
| 任务掉落领域服务 | 一次只按目标角色 ID 读取当前任务、背包，不遍历其他参与者 |
| 死亡与发放流程 | 消费固定列表，继续执行任务物数量限制、地面编号、投影和实际入账 |

生成只读，不扣额度、不推进任务、不入账、不发消息。返回 `RolledDrop` 列表保留金币/道具、数量、品质、耐久、归属、投递类型、任务 ID 与授予上限。生成结果尚未分配地面编号；整局唯一编号仍由副本运行流程处理。

同样种子和事实可复现。只重复传递相同 ID **不保证**两次结果完全相同：其间任务或背包可以改变。需要重复使用结果时复用 actor 上的列表，不在死亡、重访或重发消息时重新抽取。生成不预留任务物额度，死亡时已有的发放上限检查继续保留。

归属与投递方式是两个维度：`Ground + OwnerCharacterId` 仍可表达个人专属的地面物品；当前任务产出使用 `DirectQuestItem + OwnerCharacterId`。个人入口不会因为携带角色 ID 就重新抽取一份普通掉落。

## 后续重构边界

怪物声明、世界掉落、PVF `independent_drop`、任务掉落及特殊模式来源在对应生成入口内部组合。新增来源不要求调用方读取其业务事实；通过身份向所属领域查询。规则服务保持静态内容和传入事实的计算职责。

PVF 的 `independent_drop` 是一种产出来源，不等同于个人可见/个人拾取。产出来源与分配方式后续分别建模。

本阶段没有合并场景物件、通关翻牌、罐子等不同触发时机的入口，也没有新增独立掉落/世界掉落公式、任务助手倍率、统计模拟器或缓存策略。现有任务来源内部的算法分解可以继续推进，外部无需再传任务或背包信息。

## 验证

- 普通金币、装备、道具、等级范围、Boss 倍率及固定种子结果的既有测试继续通过。
- 房间创建传递正确怪物 ID、身份与场景值；非怪物不进入掉落生成。
- Ground 不查询任务来源；Personal 不调用普通规则，因此普通表缺失不会阻断个人产出。
- 双人队伍每怪仅生成一份地面掉落、每人一份个人产出；非参与者的个人请求在查询前拒绝。
- 同一身份上下文复用时，任务移除或背包达到目标数量会被重新查询到。
- 空参与者、重复角色或发起角色不属于参与者时，在查询来源前拒绝。
- 掉落、房间、副本运行、死亡及命令架构相关定向测试：122 项通过。未部署，未新增实机验收结论。
