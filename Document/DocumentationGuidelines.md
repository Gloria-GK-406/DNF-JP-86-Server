# 文档与注释规范

文档服务于开发、诊断与验收决策。只保留当前有用的规则、设计理由、已知限制、排障方法与证据。

## 事实归属

| 内容 | 唯一维护位置 |
|---|---|
| 项目简介、简要目录与按任务阅读索引 | 根 `AGENTS.md` |
| 当前架构、开发约束、领域规则、运行与排障指南 | `Document/` 中对应的专项文件 |
| 协议结论、布局与原始证据 | `protocol/`，遵循 [知识库规则](../protocol/README.md) |
| 仅在读某段代码时有用的原因或不变量 | 就地注释 |
| 设计／取证原始材料与验收数据 | 所属专项资料；标明来源、适用版本、证据等级和未验证边界 |

优先更新已有同主题文档。其他位置用链接指向它，不复制第二份规则。
专项文件标题说明主题，开头说明适用任务；根索引写明何时读取，避免要求所有任务全量加载。
`Docs/` 中标注 ServerS4A21 的材料只描述参照服务端，不能证明本仓行为。

## 保留什么

- 当前实现与必须遵守的边界，以及仍决定设计选择的理由。
- 可复用的坑：触发条件、如何识别、如何处理、哪些推断不成立。
- 可复核的依据：源文件、协议记录、样本身份、测量口径；区分实现、自动化与实机证据。
- 当前兼容规则：什么数据或调用方仍依赖它、允许什么、不允许什么。

## 删除什么

- 从 A 改到 B 的经过、提交串、评审轮次、谁发现或修复了什么、一次性部署交代。
- 过期结论及其层层补记。直接更新正文，不把旧答案留在前面再在后面纠正。
- 无消费价值的统计、没有来源的数字、未形成当前约束的未来打算。
- 以任务过程稿代替现行说明；根入口和现行指南不依赖 `.rks-agent/` 才能理解约束。

删除演化叙述不等于删除仍支撑结论的协议样本、版本身份或验收边界。
协议记录若需说明不采用某项证据，应留下技术原因和依据，避免重犯；无需复述修改经过。

## 注释与测量

注释只解释代码表达不了或核查代价很高的原因、来源、不变量和缺口；不逐句翻译代码。
逆向得到的兼容行为用 XML doc remarks 指明来源。避免把过程说明搬进注释。
写数字必须说明口径；不能确定就明确未知。需要小计时同时给出各项、项数和加法，或省略小计。
修改结论时同步协议记录与 catalog 状态，并检查引用是否仍指向正确主题。
