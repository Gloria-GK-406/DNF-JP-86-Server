# 婚房交互与婚戒提示修复

日期：2026-10-18。用户授权一起修复并部署。本轮保留当前婚姻、钱包、家具、树和戒指进度，不回档。用户已反馈种树、浇水、婚戒升级和铺设婚房可正常完成；本轮 UI 改动仍需再次实机验收。

## 服务端

`03D1` 是带成功公告副作用的升级事件，不再用于选角、跨房、外观重建或请求重放。本人成功 `CMD03F4` 负责一次提示；在线配偶只收一次 `NOTI03D1`。

恢复统一沿用 `03D0` 静默婚姻状态；新增只读 `MarriageInfoSnapshot` 仅含配偶 ID、阶段、结婚时间、接收者个人心意点及婚戒等级。HousingReadView 直接读账本，避免调用完整婚姻写服务或加载配偶外观。

独立审核发现旧 `03D0` 编码误将等级放在 raw[5]，之前由补发 `03D1` 掩盖。固定 A21 的 8959B0→895290 明确把 raw[14] 写 mgr+0x70，再写人物+0x386；raw[5] 写另一个未知字段。现修为 body[14]，body[5] 保持 0。初版新增测试也错断言 body[5]；审核指出后纠正 oracle，先复跑得到 Expected1/Actual0 的失败，再修编码并通过。没有把错误断言算作证明。

## 客户端

补丁归 `0200_GameplayCompatibility.dll`，文件 `housing_interaction_fix.c`。不改客户端 EXE、PVF、网络数据或服务端资格校验。

- native `01F01820(ui,01BD)` 查询活动窗口栈；只有 `03FD` 成功且 flag0 才打开该保管箱。因此待回包、拒绝和关闭时婚房家具 hover 返回 false。
- 保留 `0087FC90` 的矩形和布局命中算法。在其调用 `0273CF60` 的返回地址 `0087FD7E` 上，用原生 `0273D360` 排除含槽0/1的地板/壁纸。其它调用点、渲染、物品摆放和拖拽查询保持原生。
- native 戒指 setter `00892960` 在更新等级后，仅当人物状态谓词允许才构造提示。原生 `015DB4E0` 接受字段值0/6，其余跳过；不推断该字段的具体游戏枚举。将仅位于戒指成功路径的 `008929F9` 条件跳转置 NOP，保留现有角色存在检查、原生文本/窗口及后续属性刷新，使实际升级事件即时提示。错误 ACK 不进入该 setter，状态恢复也不再调用它。
- 所有函数/调用点/补丁字节在首个写入前校验；通过宿主登记 hook/patch，失败归统一插件检查点回滚。

1. 未开保管箱时，移到已铺普通家具上应是普通鼠标；点云清打开成功后，可收回家具变可点击，墙壁/地板仍普通。
2. 关闭保管箱再悬停，恢复普通鼠标；双端同时开时，另一方开失败不得出现可收回光标。NPC、爱情树照常可交互。
3. 使用当前等级对应的下一阶升级券：本人立即提示一次，在线配偶也一次；失败不提示成功。当前已升1级，应使用下一阶券10002612；正常购买按当前PVF价格，勿再用最低阶券作为成功测试。
4. 确认弹窗后反复进出婚房、换宠物、进本回城、重登：不再弹升级成功，婚戒等级/属性与心意点保持。
