# 世界掉落规则

日期：2026-09-23；实施基线：`e4bce08a`。使用 A21 Script.pvf 的 `etc/worlddrop.etc`；表结构和物品引用由本地档案确认。概率基数与一次抽取政策采用本服规则，不标为原版定案。

## 规则

- 按怪物实际等级精确索引，不按角色等级，不向相邻等级回退；没有该等级组返回无掉落。
- 每只怪物在房间创建时抽一次世界来源，独立于普通、任务来源；命中返回一件物品，否则无产出。不套用品质抽样、creation rate 或普通掉落倍率。
- `WorldDrops:ProbabilityBasis` 默认 100000；本次部署显式配置同值。保留物品原始顺序，以正权重计算累计上界，随机票据在 `[0, basis)`，选第一个大于票据的上界；超过末界代表无掉落。零权重禁用。
- 这与本地旧上游“总和/basis 过门后按权重选一件”在总和不超过基数时分布等价，随机序列不等价。固定基数、一次一件仍需原版证据，当前为已选用的本服政策。
- 世界随机种子由既有怪物种子加世界来源标记生成，不消耗普通/任务随机流。返回值带实际物品品质、种类及耐久，沿用 Ground、PendingLoot、死亡编号与拾取链。

## 缓存与错误

启动监听前由 `IWorldDropRuleService.Initialize` 读取整张表、校验有效引用、编译累计区间并一次性发布不可变等级索引。运行期只查缓存和二分抽取，不再读取 PVF。重复初始化复用缓存；初始化失败不发布半张表；初始化前调用生成明确抛错。

每组结构是 `level reserved (itemId weight)* -1`。当前只支持 reserved=0。重复/非法等级、未知头字段、截断、负权重、正权重指向不存在物品、异常物品元数据、权重和超过基数均明确报错。`0 0` 和其他零权重行作为禁用记录跳过，不要求被禁用引用可解析。重复物品条目保留为分别的区间，不擅自去重。

## A21 核对样例

| 物品 | 非零等级 | 权重 |
|---|---|---:|
| 碎布片 3030 | 3～200 | 850 |
| 破旧的皮革 3028 | 3～200 | 830 |
| 钻石硬币 7454 | 1～200 | 300 |
| 英雄的宿命 3303 | 63～72 | 5000 |
| 无尽的永恒 3332 | 73～110 | 500 |

以当前基数计算，碎布片单次世界抽取概率为 0.85%。85 级整组权重和 8947，对应世界来源总命中率 8.947%。这不是全体掉落的总概率，亦不是原版概率验证结果。活动类物品是否应增加日期/资格过滤尚无证据，本次忠实使用有效表条目，未虚构活动日历。

## 验证与部署

- 应用定向回归 126 项通过：普通产出不受追加世界来源影响，普通等级表缺失仍可生成世界物品；逐票据验证边界与空区间、缓存只读一次、等级隔离、确定性、非法参数拒绝。
- 内容测试 9 项通过且未跳过；真实 A21 的 200 组和全部有效引用通过验证。
- Release 发布成功。部署目录 `artifacts/world-drop-20260923/runtime`；沿用前一运行环境的配置、资源与同一个数据库绝对路径；SQLite backup API 生成备份并通过 integrity_check。
- 启动实测：200 个等级组初始化 300ms；TCP 7001/10010/10011/18080 和 UDP 12311/12312 已监听，标准错误为空。未新增客户端实机验收结论。

测试时正常进图清理数个房间，观察碎布片、皮革等世界表物品是否可掉落并拾取；再换房、返回检查残留。抽样未出现某种物品不能单独视为失败，不为了实测改高生产概率。

## 临时空结果可视化与实机验收

`WorldDrops:DebugClearCubeOnMiss` 默认 false。启用后：已匹配等级表但随机落入空区间时，返回 1 个无色小晶块（3037，品质1）；正常命中保留原物品，不追加晶块，也不额外抽随机数。等级表不存在仍不产出，避免掩盖选表问题。

2026-09-23 用户实机确认：正常版出现克尔顿的印章、下级砥石等材料；开启兜底验证版后，大多数怪物产出无色小晶块，用户明确验收世界掉落通过。该结果验证了世界来源接入与空结果替换链路，不证明原版概率基数，也不是对长期掉率的统计验证。验收后关闭验证开关，恢复未命中不产出的正常规则。
