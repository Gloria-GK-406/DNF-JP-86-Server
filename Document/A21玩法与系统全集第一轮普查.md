# A21 玩法与系统全集第一轮普查

## 1. 目的与边界

本文是《功能全集与里程碑开发管理规范》的第一份输入，用于回答：

> 日服 Season4 Act21、等级上限 86 的目标版本，理论上有哪些玩家玩法与游戏系统需要纳入项目视野？

本文先建立 **Milestone 与 Feature Cycle 候选全集**。在用户确认第一轮结构后，将已确认范围投影为 GitHub Milestone 和 Feature Cycle 父 Issue；尚未裁决的功能保留调查标记，不提前展开子 Issue。

版本边界采用：

- 客户端 `DNF.exe` PE 时间戳：2016-12-05；
- 日服 Season4 Act21「自覚」上线日：2016-12-07；
- 收录在此日期之前已经存在于日服、并仍适用于 A21 的系统；
- 不因为客户端枚举、PVF 或上游代码存在，就自动认定功能在日服 A21 已启用；
- Season5 及其后的正式新增内容默认排除。

## 2. 证据分层

| 标记 | 含义 | 能证明什么 |
|---|---|---|
| `JP-Live` | 日服官网更新、同期日服资料或实机行为确认 | A21 当时确实可用或已上线 |
| `ClientStatic` | A21 客户端 opcode、handler、窗口或静态代码存在 | 客户端具备处理能力，不证明日服启用 |
| `PVFPresent` | A21 `Script.pvf` 存在规则、地图或资源 | 数据随包存在，不证明入口开放 |
| `UpstreamImplemented` | `ServerS4A21` 存在服务端实现或骨架 | 可作为实现参考，不是客户端权威证据 |
| `CurrentImplemented` | 当前服务端已有对应实现 | 说明开发覆盖，不提升版本或协议置信度 |
| `ActivationUnknown` | 静态能力存在，但未确认日服 A21 是否开放 | 只能进入调查候选，不能直接承诺实现 |
| `ExcludedPostA21` | 官方确认在 2016-12-07 之后上线 | 从 A21 基线任务集排除 |
| `RegionResidue` | 明显属于中国、韩国或其他区域的共用资源 | 默认不纳入日服 A21，除非找到反证 |

本轮本地证据规模：

- A21 客户端解密字面量 36,678 条；
- A21 协议枚举含 1,272 个 CMD、1,219 个 NOTI；
- A21 PVF 文件表含 712,010 个文件；
- PVF 主要内容根包括装备、怪物、被动对象、地图、消耗品、角色、任务、宠物、UI、技能、NPC、地下城和活动；
- `ServerS4A21` 已出现账号、角色、好友、队伍、邮件、PvP、Raid、塔、副职业、装备改造、小游戏等领域模块。

这些数字只说明候选面很大，不代表存在同等数量的玩家功能。

## 3. 第一波功能全集候选

状态说明：

- `纳入`：已有足够证据认为属于日服 A21 基线；
- `调查后纳入`：很可能属于 A21，但仍需补一条版本或实机证据；
- `候选`：客户端/PVF 有完整表面，日服 A21 是否启用未知；
- `排除`：已知晚于 A21 或明显属于其他区域。

## 8. 当前裁决

第一轮已经建立覆盖 27 个 Milestone 的功能全集，并在用户确认后完成 GitHub 第一波投影。当前只展开到 Feature Cycle，未批量创建更细的功能子 Issue。

后续使用方式是：

1. 持续将未决循环裁决为 `In Scope / Later / Out of Scope / Unknown`；
2. 每次只激活一个主要 Feature Cycle；
3. 启动循环时才创建可独立验收的子 Issue；
4. 调查或开发中发现的旁支问题进入 Bug、Debt 或 Investigation，不扩大当前循环。
