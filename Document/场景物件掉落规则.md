# 场景物件掉落规则

日期：2026-09-23。地面奖励已实现并通过自动化验证，未部署、未实机验收。物件的个人任务奖励尚未接入破坏上报。

## 70 端证据

样本：`Research/1995chen-dnf/other/等级补丁/70/df_game_r`，ELF32 x86，SHA-256 `CF45F4E8514C3BF560DD322C146F8441249F6C28246EC8566DCF9EBC4E1B2EB7`。以下地址为 ELF VA，依据符号边界反汇编，不是客户端地址。

| 入口 | 静态结论 |
|---|---|
| `CMap::set_map` 0x0834E18A，item 分支 0x0834E6E6 | item 动作类型为 2；传入 group、指定次数、随机次数、物件索引给 `insert_item` 0x0834EB94。同一物件遍历全部动作，并非固定一条 |
| `CBattle_Field::add_item_curr_map` 0x08302BC6 | 入房时生成；组内 level=-1 取地下城标准等级，普通情形使用副本难度、人数参数 1。先随机奖励、再指定奖励，之后逐件写入地图物品表，保留物件索引 |
| `CObjectDrop::generateRandomItem` 0x0853818A | 根据参数 +0x37 的次数逐次调用通用随机物品生成，使用 object 生成器自己的表 |
| `CObjectDrop::generateSpecificItem` 0x08538234 | 根据 +0x39 的次数重复抽取；每次以 10000 为随机上界，累计条目权重，ticket 小于累计值时生成一件并结束本次抽取；尾部允许落空 |
| `CGenerateRandomNumber::generateNumber` 0x085334A4 | 两条 RNG 路径；MT 的 `randInt(n)` 0x080CBABE 包含上界，旧全局随机路径行为并不完全相同 |
| `DisPatcher_DieMob` 0x081EBB0E；`CParty::DestroyPassiveObject` 0x085B6540 | 有独立物件破坏分支，不能视为普通怪物死亡。这里未闭合 A21 报文判别字段及物件实例映射，不据此新接个人任务发放 |

上述对象级次数、累计权重、进房预生成属于 70 端静态已证；A21 是否完全同实现仍需实机。普通类别、品质、金币算法复用本服已有规则，只换为 object 表，不声称完整移植了 70 端全部经济控制。

## A21 数据及本服规则

A21 PVF SHA-256：`19F5FA85FF73CCE94E299E0902269DE2F0164934128F15B8A7B99249C881BE1A`。

- `.dgn [special passive object item]`：每组为 `group level entryCount`，后接 `item weight` 对。实际扫描 1022 组，空组保留，level=-1 表示沿用地下城等级。
- `.map [special passive object]`：每个物件头为 `code x y z actionCount`；普通动作接 `kind + 5 integers`。`[item]` 五整数为 group、指定次数、随机次数及两个保留值。-1/0 次均不抽，不再强制至少一件。
- 5473 段真实物件声明已通过生产解析器测试。零动作物件仍占索引；同物件的多个动作独立计算。可跳过变长 `[hellparty]...[/hellparty]` 动作和两张旧 Amon 地图的末尾独立深渊块；不执行深渊奖励。
- 指定抽取使用 **0..9999** 的 10000 格累计区间，不按总权重归一化。总权重不足有落空区间，超过时后面的区间被截断。每次命中创建一件独立物品，不能将次数误写为第一件的堆叠数。
- 上述端点是明确移植政策：不复制旧 MT 包含 10000 的额外落空点。A21 两个教学地下城的肩甲权重都是 10000，必须能稳定完成教学流程。
- 随机抽取使用 `itemdropinfo_object.etc`、组等级覆盖/地下城基准等级、当前难度、rank=0、人数=1。金币金额同样读取 object 配置，不借用 monster 配置；不附带世界、独立或 Extra 来源。
- 静态声明首次访问后缓存；随机结果不放进静态缓存。每次 Cell 生成使用副本 seed、地图、坐标、物件索引及动作序号确定抽样流，结果进入现有 Cell 和全副本编号分配。换房重访沿用 Cell，不重抽。
- 格式错误、未知动作及不存在的奖励组显式报错，避免静默改成第一项。现有物品元数据缺失的处理未扩展，本轮不重构整套内容校验。

## 协议边界与待办

继续使用现有 NOTI 0x001D 的物件索引及逐件地面奖励记录，拾取继续走原有链，没有新增报文或把 70 opcode 直接移植到 A21。当前 A21 数据按每次随机最多五类奖励保守计算，单房上界 140 件，低于进房报文的 255 件限制。

地面物件奖励无需等服务端收到破坏事件才抽取。个人任务物件奖励是另一条生命周期：还需要证明 A21 破坏报文的对象类别/编号，建立当前 Cell 的物件实例与重复上报保护后，才能连接 `PassiveObject` 任务奖励；不以地面拾取冒充破坏事件。

70 入房函数末尾另有生成器 type 4 的追加调用，本轮未闭合其语义；扫描 A21 未发现 `[object drop item]` 标签，但不能据此声称所有版本的附加来源不存在。特殊模式及其额外奖励仍不在本轮实现范围。

## 验证

World 603 项、物件 PVF 13 项、进图/拾取/死亡协议回归 156 项通过，共 772 项，无跳过；全解决方案构建零警告、零错误。

覆盖累计区间和落空尾部、权重零、教学权重 10000 必出、多次抽样逐件发放、同上下文重放和不同 seed 变化、随机与指定来源共存、等级覆盖、object 金币/装备配置，以及全量 A21 物件声明边界。测试为实现后的回归证据，不宣称 TDD RED 或 ClientVerified。

## 个人任务 PendingLoot（2026-09-23，基准 d273794a）

创建 Cell 时读取 `[passive object]` 的四字段记录，以及 `[special passive object]` 的全部对象（包括没有 item action 的对象）。每条声明的身份为「段类型 + 段内序号」，并保留模板代码和坐标；同型号的两台机器不会合并。这个身份是服务端声明身份，**不是已证实的 A21 线上编号**。

任务掉落入口统一为 `IQuestEnemyDropDomainService`，用明确的 `QuestEnemyType` 区分 Monster/APC/PassiveObject。服务内部按参与者凭证查询任务和库存，复用已有的候选选择、概率和数量限制。结果按物件实例保存在 Cell.Objects 的 PendingLoot 中；房间快照读取保存的结果，不重抽，不混入怪物经验、清房判定或地面物品列表。

**当前边界：已实现预生成和绑定；物件破坏后的 claim、当前任务/库存复核、发放和清空尚未接入。** 不能以本次生成测试通过宣称个人任务物件端到端可用。A21 破坏帧识别及其编号到声明实例的映射仍未闭合，证据见 [C2S 0027](../protocol/game/client-to-server/0x0027.md#物件身份边界2026-09-23)。尤其禁止用模板代码匹配后消耗第一个尚未领取的物件：一次重复上报会错误消耗下一台同型号机器。
