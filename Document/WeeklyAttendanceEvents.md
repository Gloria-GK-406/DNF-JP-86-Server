# 活动管理与累计周签到

日期：2026-10-05。开发基线：`af0715492d9b9850756afdd908f8a93614795ea6`。本文描述当前服务端实现与后台操作；真实 A21 日历、签到窗口及邮件领取仍须按[人工验收清单](tasks/event-weekly-attendance/Human-Test-List.md)确认。

## 管理员操作

使用拥有全部 GM 权限的管理员登录 `/gm/events`，进入“活动管理”。目前注册活动为 **2208 累计周签到**。列表只展示名称、类型、当前期次、状态和有效期等公共信息。点击“设置活动”打开该活动的专属窗口；周签到窗口展示 PVF 来源、通关目标和完整的每周／累计奖励，全部只读。规则不可用时保留原因，不能启用。

1. 点击“通用配置”，填写活动标题、短名、说明、开始/结束公告和有效期。公告可留空。时间统一为北京时间 UTC+8，结束必须晚于开始。保存保留当前期次及玩家进度，启停使用列表中的独立按钮。
2. 初始活动默认停用、未配置期限。配置期限后点击“启用”，确认后按有效期生效；提前启用显示“未开始”，到期显示“已结束”。有效区间包含开始、不包含结束。
3. “停用”立即关闭继续累计和签到领奖，已领取记录及邮件保留；重新启用同一期不会刷新领取资格。
4. 在“更多”菜单点击“新建期次”，核对新期配置后再次确认。旧期记录与已发邮件保留，新期玩家从头开始，创建后默认停用，需要另行启用。已有进度的当前期次不能直接修改有效期；继续运营时应明确选择新期次。

编辑过字段后取消，需要确认放弃。保存过程中不能重复提交。版本冲突、服务器故障或网络中断造成结果未确认时，页面锁定写入；点击“重新读取生效活动”，读取成功后才可继续编辑。不要根据一次超时判断配置没有保存。会话或权限失效时按后台统一提示重新登录或检查权限。

通用管理接口 `/api/gm/v1/events` 只返回公共信息。周签到专属窗口通过只读接口 `/api/gm/v1/events/weekly-attendance/settings` 获取规则，沿用全权限管理员访问边界；前端按活动类型注册独立组件，通用表单不承载签到目标或奖励字段。

专属接口的奖励记录包含签到序号、物品 ID、物品名称及数量。名称由签到领域服务通过规则服务读取 PVF 物品目录，页面只拼装“名称（ID）”，不再单独查物品。名称缺失时保留 ID 并标明未找到；名称不进入本期奖励规则快照，不影响发奖和已有进度。

## 玩家行为与规则来源

玩法按账号记录，同一期每个业务周最多签到一次。有效推荐地下城成功结算后推进当周通关目标；达标可在原生周签到窗口签到，当周奖励及适用累计奖励通过当前角色邮箱发放。失败结算、重复结算和重复签到不会重复计数或发奖。

周界使用服务器 UTC+8 业务日的日切换配置，并回溯到周一。普通推荐副本资格按结算前角色等级上下 5 级与副本等级范围重叠判断；本阶段没有次元副本特殊例外。

目标与奖励读取 `event/chn_event/chn_totalattendance.evt`，后台仅展示，不提供奖励或签到目标编辑。当前 A21 归档的普通每周目标为 4 次，含 12 组周奖励与累计 4/8/11 次奖励；目标、实际物品 ID 和数量以当次后台/PVF读取结果为准。活动内容缺失、奖励不可投递或本期规则声明发生变化时，后台显示不可用原因，不使用虚构默认奖励；应核对服务器所用归档，必要时明确新建期次。

本阶段支持普通每周签到和累计奖励。PVF 中存在的 bonus/额外签到字段未闭合玩法与请求语义，没有补签或 bonus 功能入口。
