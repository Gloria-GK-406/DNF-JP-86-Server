# 循环地下城单人闭环（2026-10-09）

用户授权：按已讨论方案直接实现、验证并部署。工作分支 `task/achievement-state-events`，基线 `45031a04`；采用 Direct，在当前工作区完成。不修改客户端或 PVF。

## 协议与职责

1. 客户端按当前区域的 PVF 候选池选择地图与循环任务，发送 `0308`：`u32 dungeonId + u32 questId`。
2. `PrepareCycleDungeonEntryCommand` 调用循环入场领域服务，校验真实 PVF 配对、区域开放任务、角色等级/职业/任务前置与当前选择上下文。只绑定连接代际所属的地图和任务；不接任务、不创建副本、不扣疲劳。
3. `0308` 成功响应为 `01 + u32(1) + u32 questId`；失败为 `00`。客户端自身继续发送 `001F` 接取任务。非零门控值的用途有 ClientStatic 证据，取值 1 采用上游候选，完整链路仍待实机验收。
4. `001F` 仅允许接取已准备的循环任务。相同绑定下的重复接取幂等返回；不重置既有进度、不重复发接受物品。
5. 客户端接取成功后自身发送 `0010`。CMD handler 按循环意图分流，领域服务重新校验资格和已接任务，以请求难度为期望，在当前地图支持且已解锁的难度中选距离最近者，距离相同时优先较低者；精确选择该任务的 active quest maze，复用既有副本实例、房间、入场费用和疲劳流程。地图或任务绑定不符时拒绝，不退回普通地图。实际难度写入本局，并由既有入场 NOTI 同步客户端。
6. 击杀与拾取复用现有任务掉落及进度服务。`0022` 完成任务时，以当前持有材料校验完成条件；循环收集材料消耗、区域礼盒、经验和任务完成在同一事务中提交。材料变更投影为 `NOTI 000E`，奖励仍走原有任务完成回包。满包或重复完成不额外发奖励。
7. Circle 任务可重复。保留完成历史，但历史记录不阻止下一轮接取。循环任务不混入普通 NPC 推荐列表；共用“满足内容前置条件”的只读规则判断。

绑定具有连接代际校验和比较替换；失败入场仍沿用既有恢复选择上下文机制。已有其他未放弃循环任务时不会在准备握手中擅自取消或切换该任务。
