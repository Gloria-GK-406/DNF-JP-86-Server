# 便携分解机协议闭合与服务端实现

## 实机请求证据

2026-09-20 A21 客户端在同一角色背包中产生以下 `0x001A` 请求：

| 动作 | 工具槽 | 工具 item id | providerId |
|---|---:|---:|---:|
| 普通档单件 | 89 | 2600469 | 0 |
| 坚固档单件 | 90 | 2600470 | 0 |
| 优质档单件 | 91 | 2600548 | 0 |
| 普通档批量，目标 1 | 89 | 2600469 | 0 |
| 普通档批量，目标 2 | 89 | 2600469 | 0 |
| 普通档批量，目标 3 | 89 | 2600469 | 0 |

这组样本确认便携模式以工具槽定位分解机，providerId 恒为 0；批量 UI 仍逐件发送单件协议。

## 服务端行为

- Handler 在协议边界将 NPC 分解与便携分解分流为两个 CMD。
- 便携 CMD 从服务端工具槽读取真实物品，不接受客户端声明工具类型。
- PVF `[portable disjoint]` 档位与 `disjointer.exj [portable disjoint info]` 联合给出
  30、50、70、90 级装备上限。
- 每条便携请求消耗一个工具；工具扣除、目标装备删除与产物写入使用同一事务。
- 玩家分解师 `0x00EB` 与勇者装备分解机 `0x0455` 不在本次范围。

## 自动验证

- 便携单件成功后工具数量减一、目标装备消失并写入产物。
- 连续两条请求各消耗一个工具，符合批量逐件协议。
- 超过工具等级上限时工具和装备均保持不变。
- 强制产物写入失败时，工具、装备和产物全部回滚且不发送成功响应。
- A21 PVF 四档工具解析为 30/50/70/90。

## 待实机验收

客户端成功 UI、工具数量显示、目标装备删除及批量逐件结果仍需使用本次 Release 部署确认。
