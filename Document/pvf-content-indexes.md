# PVF 只读索引与补给静态声明

PVF 列表由 `Dfo.Pvf.PvfArchive.ReadList` 按归档实例和文件索引拥有。相同归档中的路径大小写别名、并发读取共享同一份有序声明；不同归档不共享缓存。返回的行、ID 查询和加目录前缀的路径查询均为只读视图，不缓存角色、账号或请求状态。

`PvfListDuplicates` 明确区分重复 ID 拒绝、取首项和取末项。原有内容源分别保留自己的策略；没有重复 ID 的列表可以共享这几种策略的同一视图。会排除歧义项、过滤特殊声明或解释领域事实的内容源仍拥有其派生结果，只复用原始列表和字符串。装备内容源的正整数、路径安全、引号与重复声明校验保持原样。

基础设施中的物品内容源复用相同列表的相对路径和完整路径视图。排序与仓库元数据的组合查询通过 `PvfItemPathView` 访问共享索引，不再另建合并字典；装备与消耗品 ID 冲突仍拒绝。物品目录等带分类信息的索引保留其领域条目，但复用完整路径字符串。

`PvfEntryLifecycleContentSource` 在首次读取时解析补给静态声明，按需解析并缓存物品元数据与不可变 `DailyRefillRule`。每次读取仍用本次时间筛选数量和到期时间；读取全部声明不会把过期时间固化成当前有效性。未被本次读取选中的声明不会提前触发物品元数据错误。配置开关、自定义规则、领取周期、背包事实与实际发放继续由原有规则和领域服务处理，不缓存发放决定。

这些缓存仅影响内容读取。选角普通补给、牛头怪乐园、南部溪谷和领主塔门票的工作单元及其提交、回滚、事件和出站登记顺序保持独立，未合并事务，也未修改协议完成边界。

验证包括合成 PVF 的并发共享、归档隔离、重复 ID 策略、只读性、补给跨到期时间读取与重复调用分配量，以及真实 PVF 内容测试。性能比较应使用相同初始数据库、客户端、PVF、负载节奏和测量窗口；GC 堆快照及分配 trace 单独采集，不把采样扰动后的请求耗时当作常规 benchmark 成绩。
