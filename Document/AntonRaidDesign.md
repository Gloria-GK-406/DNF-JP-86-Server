# 安图恩团本领域设计草案

2026-11-19。本文记录 JP86 安图恩攻坚实例、小队租借及其与现有副本的边界。范围是 A21 安图恩攻坚团本。下面的接口与规则是设计意图，协议时序与客户端行为以实机证据为准。

## 攻坚实例

- **Raid Store** 创建、查找和移除攻坚实例，维护团号、角色归属和频道目录。每次建团有独立实例身份。定时命令、入场回执和归还操作都能据此核对是否仍属于原实例。
- **安图恩实例服务** 推进一支团从招募、编队、准备、两阶段攻坚、结算到解散的生命流程。团长、团员、攻坚编成、阶段、地图开闭、跨地图机制、截止时间、出战与阶段奖励资格都由该实例裁决。定时源按 [现有局内截止时间机制](DungeonRunKinds.md#一局之内的到点推进) 提交命令，实例维护截止时间并核对阶段和代次。
- **普通地下城运行服务** 管理每支出战小队所在的 `DungeonRun` 及其房间、战斗和单局参与。一次团本可以并行有多支小队出战。攻坚实例根据经核对的进图、通关、退出等结果更新全团进度。库存、邮件和任务仍通过现有领域提交门票、奖励与任务进度。

## 五支小队与独占租借

创建攻坚实例时，由组队模块创建并登记五支小队，向该实例授予独占租借。每支小队最多四人，持有独立且稳定的 `PartyKey`。五个编组位置始终存在。空队保留 key，允许没有队长，不占用副本；团员也可以留在未编队区。清空当前成员与归还小队是两个独立动作。

| 职责 | 所有者 |
| --- | --- |
| 创建与登记、分配 `PartyKey`、提供统一查询、处理归还并注销 | `PartyService` |
| 决定成员放在哪支小队、委任小队队长、确定可调队的阶段、决定何时归还 | 持有租借的安图恩实例 |
| 四人槽位、成员唯一性、队长须属于所在小队等通用规则 | 从现有组队逻辑提取的共享小队模型 |
| A21 队伍号、名单和清理通知 | 协议投影层 |

`FindByKey` 能查到租借中的小队，`KeyOf` 能查到角色当前有效的小队。实际名单只有一份，由 Raid 持有的小队实例提供。改编时，受影响的小队、队长、角色归属索引在同一次玩法变更里更新。开团冻结名单、单次出战名单和阶段奖励资格可以各自保存，因为它们记录的是不同时间点的业务事实。

沿用普通组队的对外行为。凡是可能变动租借小队的入口，都先识别所有者，例如普通退队请求和掉线清理。小队是否清空、队长由谁接任、角色是否仍留在攻坚队，由 Raid 处理。客户端 `PartyId` 是协议投影，团内编组与副本关联使用 `PartyKey`。

## 团长改编与出战

Raid 提供按目标编成调整小队的操作。团长可以分配、移动或交换成员，委任小队队长，也可以把团员撤回未编队区。先检查团长权限、实例和阶段、成员归属、容量、槽位和队长归属，再一次应用变更。例如两支满队互换成员，按交换完成后的名单校验容量，两边一起生效。调整失败时保持原编成。

`DungeonRun` 按 `PartyKey` 读取当前小队成员与队长，并用实际进图名单限制本局参与者。改编必须与选图、入场和离场协调。首版拟允许团长调整待命队伍，涉及正在选图或出战的小队时拒绝整次调整。这是暂定规则，最终允许调整的时机、需要的客户端确认和通知顺序以 A21 实机为准。

## 收尾与归还

1. Raid 进入收尾，停止新编队和新入场，使过期的阶段、计时和编队操作失效。
2. 结束相关选图和地下城运行，按结束原因完成结算，释放参与者占用。留存清理客户端队伍显示所需的原队伍标识及收件人。
3. 从五支小队清退所有成员并清理团员归属。小队清空期间仍保有原 `PartyKey`。
4. Raid 凭本实例的租借凭据归还五支空队。`PartyService` 检查持有人和租借身份，确认已完成离场后注销队伍及索引。重复归还得到安全结果，过期请求无法注销其他实例的队伍。团实例收尾完成后从 Raid Store 移除。

单个团员离队只释放其相应成员关系与本局参与。整团归还发生在攻坚实例完成收尾时，覆盖最终阶段结算完成、总攻坚超时和提前解散等路径。

## 依据与待确认项

- **JP86 当前实现。** `PartyService` 的正式小队需要队长，最后一名成员离队时注销小队。`DungeonRunStore` 通过 `PartyKey` 查成员，已有按 `RunId` 结束整局并释放占用的入口。租借设计需要扩展空队、所有者、登记归还与离场路由。[组队服务](../Server/src/Dfo.Server.Application/Parties/PartyService.cs#L393) · [副本成员](../Server/src/Dfo.Server.Application/World/DungeonRunStore.Model.cs#L77) · [整局离场](../Server/src/Dfo.Server.Application/World/DungeonRunStore.Departure.cs#L32) · [会话清理](../Server/src/Dfo.Server.Application/Sessions/SelectCharacterLifecycleServices.cs#L175)
- **ServerS4A21 参照实现 `1870c85`。** 招募时 `Network/Handlers/RaidHandler.cs` 的 `HandleRaidManagerWork` 更新攻坚编组。攻坚中和阶段间歇，`Network/Handlers/PartyHandler.cs` 的 `ReassignLiveRaidPartyAsync` 联动实际小队，并检查受影响成员的选图及出战状态。上游用于对照行为与协议，五支小队的独占租借是 JP86 的设计。
- **A21 待实机确认。** 招募时拖动成员是否立即形成实际小队，开团准备是否依赖组队应答，阶段间歇、退队和断线重进时怎样恢复编组，及结束时小队与团显示的清理顺序。另需确认团长委任小队队长是否有独立客户端动作。[团长操作协议](../protocol/game/client-to-server/0x029E.md) · [开团协议](../protocol/game/client-to-server/0x029B.md) · [重进协议](../protocol/game/client-to-server/0x029D.md)
