# 组队翻牌：个人确认与共同展示

## 证据边界

- A21 单人静态与抓包：免费牌的 `CMD 0x0047` 样本为 `00 00`；客户端点击可先在本地翻开，服务端的同 type 下行携带列与座位归属。见 `protocol/game/client-to-server/0x0047.md`。
- 2026-09-18 双开玩家观察：各人先在自己的牌面选择，之后按队伍顺序显示共同结果。本次现场未加载完整帧抓包插件，不能把两人上行均为 `00 00` 或最终下行时序标为实包确认。
- 上游服务端的 `0x0046` 版式按队伍槽位写有效成员；本仓此前将单人样本 `01 00 FF FF...` 写死用于组队。

## 当前实现模型

1. 结算分别固定每位角色的个人奖励；`0x0046` 仅标当前副本参与者的队伍槽位，不携带奖励。
2. 免费牌上行 `0x0047` 是该角色的个人确认，协议入口把所报 index 归一为 `0`。同队两人都报 `0` 不相互占用；每人每种牌仍只能领取一次，奖励与金币提交保持原事务边界。
3. 当前有效参与者都已完成免费确认后，按队伍槽位生成互不冲突的显示列，并向全队发送一次完整的下行 `CMD 0x0047` 快照。此前只向领取者发送其背包与金币变化，不广播半成品牌面。自动翻牌也确认本人的 `0`，不争夺另一个显示列。
4. 付费牌属于可选行为，不作为免费牌共同展示的等待条件；其精确组队展示节奏尚未取得双人实包。

## 实机验收与未闭合项

- 双人都手动翻免费牌：先翻者不应使后者卡住；两人完成后，两端只收到一轮共同结果，按队伍槽位显示。
- 一人手动、一人等待自动翻牌：自动选择应补齐共同结果；同角色重复请求不能重复发奖。
- 记录每人 `0x0045/0x0046/0x0047` 的原始收发帧、顺序和 UI 视频，再确认客户端展示阶段与奖励内容如何对应。尤其不能仅凭此服务端实现给组队协议标 `ClientVerified`。
- 中途有人离场，恰好使已确认者成为全部剩余参与者时，领域等待条件应释放，但主动下行投影还未接入离场路径；该边界暂不宣称完成。
