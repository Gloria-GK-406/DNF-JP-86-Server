# 怪物死亡结算事务

2026-10-11，`task/despair-tower`。用户授权：按已讨论的单次死亡结算方案重构并部署。

## 结构变化

原路径在 CMD 0x0027 处理器中先加载完整角色视图，再对每个队员分别执行奖励命令，最后手工确认死亡。事务外的角色视图装配会逐项读物品；组队失败时可能出现部分队员已提交。

新路径：`MonsterDeathHandler → ProcessMonsterDeathCommand → MonsterDeathDomainService → MonsterKillRewardsDomainService`。

- 顶层命令经现有命令管线打开一个事务，锁住全部参与账号及其精确会话的生命周期；必要的 SP、经验、身份及任务查询复用该事务。不再为死亡请求装配完整角色、背包和登录视图。
- 全部有效参与者的经验、任务及直达任务物品奖励一起提交。奖励服务调用领域实例，不嵌套调用 CommandBus，不自行开启事务。
- 死亡和队员奖励令牌作为事务参与者准备、提交、回滚。数据库失败释放令牌；数据库提交后才确认死亡、生成地面掉落。提交结果不确定时封锁本次结算的全部精确会话，禁止盲目重发奖励。
- 协议处理器只投影已提交结果。升级时直接查询可接任务所需事实，不加载完整角色视图。
- 保留既有边界：镜像房间清理任务报告、宠物房间经验及地下城通关投影在死亡提交后执行；幻影塔、破坏对象沿用各自业务命令。并非把整个网络处理器和网络发送包进数据库事务。

- Application 全量：3659 通过；Protocol 全量：1443 通过；Persistence 全量：468 通过；解决方案 Release 构建零警告、零错误。
- 死亡协议集中回归 67 项，经验／注册及真实数据库集中回归 21 项。最后一次集中检查包含全量检查后补强的断言。
- 真实 SQLite + 实际 CommandBus：第二队员业务失败、SQLite 写入失败均撤销两名队员的经验和金币，释放死亡令牌；重试只提交一次；重复死亡不上奖。两名队员实际使用同一个 SQLite 事务对象，重试使用新事务。
- 协议回归保留经验、SP、升级可接任务、掉落归属、任务物品、清房／通关、发送失败与会话封锁检查。

证据：主仓库 `artifacts/death-transaction-tests/*.trx`。运行部署信息另见部署目录的 `deployment.json`，包括源提交、程序集版本与哈希、旧版本位置、数据库备份、PVF 和监听端口。
