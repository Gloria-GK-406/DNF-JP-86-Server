# Specification: A21 商城实体商品购买

## Why and Outcome

商城确认购买现在发出CMD 0x0040后无应答。完成后，一次购买要么扣去正确费用并交付全部实体物品，要么明确失败且余额、物品都不变；客户端收到与提交结果一致的购买窗口、余额和物品更新。遗忘河之水是当前可复现入口，但实现按商品声明工作，不只特判商品110000。

## Scope

覆盖普通实物道具/材料、装备、时装、宠物及仅含实体奖励的礼包，含对应实例事实、数量、期限、选项和容器边界。受支持的请求形状必须严格解析，未知形状或尚不能可靠兑现的声明拒绝并保留诊断。

契约、技能树/仓库扩容、改名等即时权益和混有这类权益的礼包不购买；赠送、充值及其他商城协议不在本次范围。购买遗忘河之水只交付物品，不执行技能退点，也不假设客户端购买后会自动使用。

## Requirements

| ID | Requirement |
|---|---|
| RQ-001 | 商品号通过当前PVF映射到实际内容、数量和费用；110000必须解析为道具3、1个、3600点券。未知或矛盾定义不能当成免费商品。 |
| RQ-002 | 请求区分商品条目、支付/券标志与商品选项；长度、数值、计数和选择范围全部验证，不能截断后按部分内容购买。 |
| RQ-003 | 仅当前选角会话和其所属账号可购买；购买使用当前库存、金币与三类点券事实，费用按明确的内容和支付规则计算，不允许负余额或溢出。 |
| RQ-004 | 全部商品及礼包组件先判断可交付性；普通堆叠遵守上限和分栏，独立装备/时装/宠物获得有效身份及必要实例事实，期限和选择项保留。 |
| RQ-005 | 同次请求的全部扣款和发货具有原子结果。任意商品不满足条件、容量不足或存储失败时不留下部分扣费/部分物品。串行或并发购买都以最新事实结算。 |
| RQ-006 | 权益商品、混合权益礼包及不能安全解释的声明在扣费前拒绝。新增洗点道具保持在库存中，技能状态不改变。 |
| RQ-007 | 事务提交后才发送成功购买结果及必要的金币、点券、各容器更新；同步数据来自本次已提交结果，发送失败不能反向撤销已提交交易。失效会话不能收到属于新会话的结果。 |
| RQ-008 | 失败应答按A21实际客户端读取长度和分支编码，解除等待的协议效果与具体可见提示区分；内部日志给出商品、发货与余额或精确拒绝原因。 |
| RQ-009 | 旧NPC买卖、物品移动/堆叠、入场与技能学习仍正常；交付构建与协议/内容证据，明确哪些结果尚未实机观察。 |

## Acceptance Criteria

| ID | Covers | Criterion |
|---|---|---|
| AC-001 | RQ-001 | 读取真实A21档案得到110000→3×1、3600点券，并对每种实体类别和权益类别给出可复查的内容样本；缺失档案、未售商品、异常字段不返回可购买报价。 |
| AC-002 | RQ-002 | 已归档19字节请求解成商品110000；单件/多条及选择类受支持形状可往返解释。截断、尾随、零/超限数量、非法选择和未知支付组合均不能形成部分有效购买。 |
| AC-003 | RQ-003, RQ-005 | 给定账号100000普通点券与足够空间，买一次遗忘河之水提交后为96400且增加1个道具3；独立连接重读一致，其他账号/角色和另外两种余额不被无关修改。并发请求正确累计扣费与数量。 |
| AC-004 | RQ-004 | 覆盖普通堆叠新建/合并/拆成多槽、普通装备、时装属性及期限、宠物实例和仅实体礼包；重新加载后仍能编码/显示，原有物品身份和附加事实不丢失。 |
| AC-005 | RQ-003, RQ-005 | 余额不足、无空间、同包后项失败、故障注入在扣款或首件发货之后、受影响行不符时，事务回滚且独立连接证明全部余额/物品原样。 |
| AC-006 | RQ-006 | 契约、扩容等权益商品和含权益组件的礼包不扣款不发部分物品；成功购买道具3后已学技能及余额账本不变。 |
| AC-007 | RQ-007, RQ-008 | codec与TCP/handler证据证明成功/失败布局和更新顺序；提交回调前不发送成功，已提交后的发送异常不撤销，拒绝之后连接可继续处理请求。错误码提示含义有直接证据或明确标为兼容选择。 |
| AC-008 | RQ-009 | Release构建无警告/错误；完整适用回归通过并逐项核对TRX。协议资料保留来源/置信度，构建可供用户继续实测，尚未实测部分不标为ClientVerified。 |

## Success Evidence

PVF探查与请求样本放在既有protocol资料目录；最终验证记录保留各类别和拒绝场景的结果、构建与完整测试证据。真实SQLite测试证明支付和实例写入的共同事务边界，协议测试与独立客户端指令核查共同证明应答形状；实际购买窗口、背包呈现和客户端自动续发行为由后续实机补证。
