# TaskContract: A21 商城实体商品购买

## Context

### Source Request

用户：买的应该是遗忘河之水。不过不清楚这个购买后会不会自动使用。要不先完成商品购买这一块的内容？

范围澄清：契约这种应该不要先完成。要不先完成实例的购买？也就是有实际东西的。

### Current Situation

普通技能学习已实现；用户尝试减级保存时先被零点券门拦截。按授权补测试点券后，客户端发来商城购买 CMD 0x0040，body为19字节，当前服务端没有处理器。PVF etc/cerashop.etc 已确认商品110000对应1个道具3，价格3600点券；stackable/cash/river_lethe.stk 将道具3命名为遗忘河之水。点券已有账号存储，物品有实例、容器与事务边界，但商城定价、支付与发货尚未接线。

## Goal

玩家可通过A21商城购买能实际获得的物品：服务端依静态商品声明验证、计价、扣款、创建或叠加正确物品，并在提交后返回客户端可消费的购买结果与余额/背包更新。当前遗忘河之水购买是首个实测入口，购买后是否继续发出使用或退点请求保持可观察。

## Scope

### In

- CMD 0x0040 的请求解码、成功/失败响应和当前角色会话接入，保留真实样本及直接协议证据。
- PVF商品目录到实际物品的映射、数量与价格；实体道具、装备、时装、宠物以及仅含实体奖励的礼包发货。各类按档案与现有实例模型确定性处理，未知定义或不支持的分支明确拒绝并列明边界。
- 当前账号余额支付与角色物品落库、背包/对应容器容量校验及提交后的同步；同包多条购买不能留下部分扣款或部分发货。
- 真实数据库与协议回归、失败不改变状态的验证，以及可供继续实机测试的构建和步骤。

### Out

- 契约、仓库/技能树扩容、改名等购买后直接修改账号或角色权益的服务；混有此类权益且不能整体兑现的礼包不得部分售出。
- 技能退点、重置、自动使用遗忘河之水的业务实现。不得为了推进本次测试而伪造使用结果或主动消耗洗点道具。
- 赠送、充值、商城之外的新交易协议；客户端补丁或修改PVF价格。

## Constraints

- 遵守仓库的协议/领域/规则/内容源/持久化分层；价格和物品规则只从权威静态内容推导，不信任客户端提供的商品含义，也不照搬参照服未证实的常量。
- 扣款与全部实体发货保持一个业务结果；余额不足、无空间、无效商品、失败写入或失效会话不能造成丢钱或发货不完整。
- 不改动正在运行的Host、真实账户余额和角色物品，直到本次构建准备好且用户授权切换。所有功能验证使用隔离数据。

## Success Conditions

| ID | Observable condition | Required evidence |
|---|---|---|
| SC-1 | 实际商品号110000能从当前PVF得到道具3、数量1、点券价3600，实体与权益商品边界可解释 | PVF提取证据及各实体类别、未知/权益定义的内容和规则测试 |
| SC-2 | 实测19字节请求可被解释；受支持购买形状、失败及畸形输入有确定性结果 | 真实向量、客户端读取路径、codec与端到端协议验证；未观察部分明确区分 |
| SC-3 | 成功购买准确扣费并产生正确实例/堆叠、容器与属性，客户端同步使用已提交结果 | 各实体发货与支付测试、真实SQLite独立重读、同包购买及写入故障回滚证据 |
| SC-4 | 余额不足、容量不足、非实体服务和无法可靠解析的输入不能扣款或部分发货；不擅自使用洗点道具 | 拒绝路径状态前后对照、契约/混合礼包边界、洗点道具保留验证 |
