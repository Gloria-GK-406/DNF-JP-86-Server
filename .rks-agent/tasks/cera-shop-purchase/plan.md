# Implementation Plan: A21 商城实体商品购买

## Approach

先建立当前PVF的商品与实体发货声明，再由共享商城规则将请求和当前事实变成完整支付/发货计划。领域服务统一验证当前会话、读取余额及各容器、应用全部写入；Protocol仅解包、派发命令与按结果送帧。普通道具沿用已有堆叠/分栏规则；时装和宠物的新实例事实通过容器写入，而不是在协议handler中临时造物。

## Decisions Before Work

- BD-001：新增 `ICeraShopDefinitionSource` 只读PVF、`ICeraShopRuleService` 负责目录/支付/实体/选项规则、`ICeraShopDomainService` 执行购买。Data承载请求选择、拒绝原因及提交回执；内容源与规则服务不保存角色状态。
- BD-002：请求以游标解析四个头字段和每条商品的三个字节、商品号、两个变长列表及该条自己的券ID/槽位。第二头字段为1的DString变体属赠送范围外；未知形状转为可拒绝请求，不从部分成功解析结果收费。当前无选项19字节只是该格式特例，CMD 0040不加技能包MD5尾。
- BD-003：商品110000从目录查出3×1/3600。avatar目录负价格是读取 `avatar type select` 价格档位的标记，不能夹成0；package的数量列0不是空奖励。显式购买等级/限购标签与物品使用等级、职业分类分开，未兑现的限购不能忽略后售出。权益识别使用目录/专用内容与有出处的路径，不把所有 `[etc]` 当实体或全部禁掉。
- BD-004：规则先展平可直接发货的实体礼包并验证所有组件；普通可使用礼包/随机箱保持箱子实例。输出按容器分组的最后槽位状态及新实例附加事实，重复商品、叠加和容量共同规划。未知选择、混合权益、循环/无法解释的礼包整包拒绝。
- BD-005：在现有 `IItemContainer` 增加携带新实例事实的写入入口，默认实现只接受无附加事实的普通写入，持久容器实现完整入口。`StoredItem` 携带时装和宠物创建事实，`SqliteItemDomainStore.FillAsync` 在新世界行内同时写入；已有世界实例迁移保持原附加列。创建宠物时用实际世界身份投影现有宠物列表。
- BD-006：账号新增条件更新三类点券的行方法，只改货币列，保留其他账号字段。购买命令沿用OnlineUser与AccountExclusive、Transactional执行策略；领域服务先计算完整计划，再在同一SQLite事务内扣款/发货。写入开始后的失败必须异常退出以回滚，不能返回普通拒绝后提交部分结果。
- BD-007：回执含每条商品号、已提交余额、最终受影响容器快照及新宠物列表。提交后先发每条商品的CMD成功（24字节基础，category=-1，辅助字段0），再发必要余额与实例更新；多条UI可见效果保留实测边界，不滥用extra列表表示背包。失败码1/4/11统一按A21实际23字节完整尾编码；1=请求购买信息错误、4=空间不足、11=点券不足，字段来源写入协议资料。

## Choices During Implementation

支付优先级、购买券/时装券、礼包选择和非零使用期限按可追溯内容与客户端证据落地；不能可靠解释的组合返回明确拒绝并在交付说明中逐项列出。宠物初始状态中不由PVF给出的字段采用标明来源的兼容策略，不伪称客户端已验证。T-001若识别出新的实体存储要求，在BD-005内有界补齐，不借机实现契约/使用道具。

实现任务可串行交接写入边界，独立只读协议/内容核查并行；最后对完整结果做独立审查。每个局部变更先用能暴露失败的用例驱动，最终以真实生产组合验证事务与实例一致性。
