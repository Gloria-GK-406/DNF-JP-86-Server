# Specification: 普通技能学习

## Why and Outcome

把已捕获的 A21 CMD 0x001D 普通加点接到当前角色技能规则与持久化事实，支持一次增加多级和批量加点。成功后客户端收到最终等级和余额，失败不留下部分学习。

## Scope

仅普通 PvE 技能页正向加点。退点、初始化、树切换/解锁、自由决斗与特殊职业模式不在此边界。运行服务端切换和实际界面验证遵守 TaskContract 的授权边界。

## Requirements

| ID | Requirement |
|---|---|
| RQ-001 | 解码 page/count 与 N 个 u16 ID/u8 refund/u8 increment，验证普通尾字节为零。正文长度 1..400 时验证客户端折叠 MD5；超过 400 无校验尾。拒绝错误长度、校验、空包、退点和不支持模式。 |
| RQ-002 | 在在线用户与账号排他事务内校验当前会话、角色归属与普通页权限；使用当前职业、等级、技能和奖励预算，不信任客户端余额。 |
| RQ-003 | 共享规则处理职业可学性、固定技能、等级上限、前置、SP/TP 和新技能槽位；同包前置按最终目标事实验证，重复技能拒绝；已有 slot/extra 保留。 |
| RQ-004 | 完整准备并校验最终账本后才写库；中途写入异常必须抛出让事务回滚；余额从技能事实计算，不存冗余余额。 |
| RQ-005 | CMD 成功按实帧和客户端读取顺序输出 success/page/SP/TP/count/slot/id/level/optional-extra；失败输出有来源或明确保守选择的代码；handler 只协调身份、命令和发送。 |
| RQ-006 | 协议记录保存样本、来源 hash、RVA 和置信度；通过必要回归，提供可实测构建，不能把静态读取或参照服样本标为本仓 ClientVerified。 |

## Acceptance Criteria

| ID | Covers | Criterion |
|---|---|---|
| AC-001 | RQ-001 | 已捕获 id=1 增量2、三项批量和增量8准确解码；校验损坏、长度边界、退点/非零模式不能学习。 |
| AC-002 | RQ-002, RQ-003 | 当前职业/等级/页/会话变化影响接受结果；一包前置顺序不改变最终结果；新学和升多级按共享累计成本结算，预算不足不写。 |
| AC-003 | RQ-003, RQ-004 | 实际 SQLite 提交后独立重读等级及余额一致；失败或写入异常回滚整包，另一页、附加配置和无关角色数据不变。 |
| AC-004 | RQ-005 | 历史成功帧逐字节匹配；解包接线、提交后响应和拒绝响应经 handler/网络测试验证。 |
| AC-005 | RQ-006 | 样本可追溯，构建与相关测试通过；用户收到明确实机步骤与尚未观察的行为。 |

## Success Evidence

AC-001/004 使用原始请求和历史应答向量、客户端读取反汇编及线级测试；AC-002/003 使用领域规则与实际 SQLite 事务测试；AC-005 使用构建、回归记录及协议记录。最终验证逐项映射 TaskContract SC-1..SC-5。
