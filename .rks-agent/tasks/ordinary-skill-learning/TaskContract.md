# TaskContract: 普通技能学习

## Context

### Source Request

用户在讨论普通学习逻辑及回包证据后明确授权：“可以，按你说的顺序来开发吧”。此前建议顺序为普通学习首版，然后验证成功后的技能等级与余额、失败响应、请求尾部。

### Current Situation

main da623c2d 已有职业共享技能规则、当前技能事实和 SP/TP 账本。A21 CMD 0x001D 尚未接线。当前守护者角色 000 为 85 级；客户端操作从 1 级加到 3 级发出增量 2。已有单项、多项、多级请求及参照服普通成功回包，失败码及附加字段证据不完整。

## Goal

让普通技能加点能够根据当前角色与共享规则完成一致的批量学习，并输出有来源的成功或失败响应；提供可供客户端实测的结果，清楚区分代码验证与实际客户端观察。

## Scope

### In

- 普通技能页的主动加点：单项、多项、一次多级，SP/TP 按现有共享规则结算。
- 新技能槽位与既有技能等级修改，保留无关技能及附加配置。
- CMD 0x001D 请求解析、鉴权、事务命令及成功/失败回复。
- 保存现有样本、核查请求尾部和响应读取证据；补足测试与协议记录。
- 制备可实机验证的构建；观察不到的客户端结果如实报告并列明下一步操作。

### Out

- 退点、洗点、初始化、技能树解锁或切换、自由决斗独立学习、特殊职业专有学习模式和自定义指令编辑。
- 新增或修改达人契约规则、转职觉醒流程；不以普通加点绕过这些边界。
- 自动修改用户角色的已学技能/职业/奖励预算来制造测试结果。

## Constraints

- 遵守 AGENTS.md 的协议切片、领域编排与共享规则边界；handler 不包含业务规则。
- 已确认增量语义必须保持。未证实的尾部和错误码解释不伪装成客户端事实。
- 一包失败不留下部分技能或点数变化。点数从当前事实推导，不新增持久化余额。
- 保留现有角色无关字段和技能配置，不因未知或不支持请求误执行其他模式。

## Success Conditions

| ID | Observable condition | Required evidence |
|---|---|---|
| SC-1 | 当前捕获的单项、多项、多级请求可以解码，等级按增量解释；畸形和不支持分支不会产生写入 | 真实向量和边界测试；协议记录引用原始样本 |
| SC-2 | 学习检查当前职业、等级上限、前置、点数与页可用性；费用及预算共用现有规则 | 领域用例覆盖成功、拒绝、多项依赖与费用变化 |
| SC-3 | 既有技能更新和新技能插入完整保存，失败整包回滚，无关配置保留；重读反映新等级与余额 | 实际 SQLite 事务及独立重读验证 |
| SC-4 | 成功和失败响应由当前学习结果产生；普通成功形状与历史实帧匹配，其他解释有证据或明确置信边界 | codec、handler、真实网络检查与客户端读取/参照证据 |
| SC-5 | 现有流程不回归；交付可实测版本，明确已观察与待实测结果 | 必要构建/回归通过；验证记录和实测步骤 |
