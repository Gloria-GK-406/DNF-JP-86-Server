# TaskContract: 移除会话内长期保存的登录结果快照

## Context

### Source Request

用户指出修复耐久后进入副本又显示旧耐久，质疑登录快照为何长期保存在会话；在要求全面检查受影响路径后明确授权：“对，写任务契约执行吧”。

### Current Situation

选角结果 `SelectCharacterResult` 被 `SelectedSessionRuntimeDirectory` 长期保存。刷新逻辑没有覆盖物品等所有可变字段，进入地下城时会从这份旧结果构造扩展角色状态，覆盖客户端刚收到的真实耐久。目录还承担已发布和连接代际保护；它的消费者跨背包、任务、队伍、地下城和城镇，不能仅删除单个字段读取。

## Goal

会话不再长期保存整份登录结果；选角结果只用于当次登录投影。后续业务从相应领域的权威状态取得可变角色数据，同时保持连接代际隔离及既有游戏协议行为。

## Scope

### In

- 盘点并迁移 `SelectedSessionRuntimeDirectory` 中整份选角结果的生产读取和更新路径。
- 消除耐久、装备及其他可变数据因旧登录结果回灌客户端的问题。
- 保留选角已发布、旧连接不可操作新连接等生命周期保护。
- 检查与该长期快照相关的物品租约及手动同步逻辑，移除不再需要的重复真源。
- 增补覆盖关键跨领域路径与连接代际的回归验证，更新受影响的架构文档。

### Out

- 不改变装备耐久消耗和修理的数值规则。
- 不修改客户端二进制、协议字段布局或数据库内容。
- 不在本任务中合并主干、部署或重启正在运行的服务。

## Constraints

- 登录阶段一次性结果 DTO 可以保留，但不得作为会话内长期可变状态的来源。
- 保持 SQLite 中持久化的装备等数据为权威来源，不能用新缓存取代旧缓存。
- 替代读取须保持连接代际精确匹配，避免旧连接向新连接投影或持久化。

## Success Conditions

| ID | Observable condition | Required evidence |
|---|---|---|
| SC-1 | 会话运行时目录不再持有整份 `SelectCharacterResult` 或等价可变角色聚合 | 实现检查及针对目录的测试 |
| SC-2 | 修理后进图、回城、组队及查看角色时使用当前装备/耐久，不从登录快照恢复旧值 | 关键投影的自动回归测试和数据流检查 |
| SC-3 | 任务、等级、技能、宠物及其他被迁移的可变数据仍能正确更新并投影 | 相关测试通过及完整消费者审计 |
| SC-4 | 旧连接退场和延迟通知不影响同角色的新连接 | 连接代际回归测试 |
| SC-5 | 完整解决方案构建与相关自动测试通过，文档描述与新模型一致 | 构建、测试及文档差异记录 |

## Authorization

| Capability | Evidence | Authorized scope |
|---|---|---|
| task | 用户在上述完整清理讨论后回复“对，写任务契约执行吧” | 编写契约、隔离工作区内实施、验证及一个本地结果提交；不含合并、部署、重启或清理工作区 |
