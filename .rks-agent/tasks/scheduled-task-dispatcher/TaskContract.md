# TaskContract: 通用注册式定时任务调度器

## Context

### Source Request

“这个要写任务契约后跑了，别实现时候改偏了，还没审核抓住。你来做吧，然后我们再看看这个清理工作怎么加。最好是能直接复用同一个清理逻辑在登录和定时任务中用。还有就是这个定时清理任务只对在线角色使用。不在线的就走登录时清理。否则6点压力有点大了。没问题吧？”

### Current Situation

基准1a0d8f9e；task/next-round-20261013。已讨论注册式调度：注册体定义时间规则与回调，调度器只负责唤起、并发和异常。现有过期清理在每次选角前执行；本次先交付调度机制，清理接入下一步讨论。

## Goal

建立可注册、可测试、可停止的通用后台任务调度器。业务执行由注册回调承载，调度器不侵入物品、角色、数据库事务或客户端通知。

## Scope

### In

- 稳定任务身份、每日指定时刻/固定间隔时间规则与异步回调注册。
- 共用等待循环、任务不重叠、有限重试、失败隔离、执行scope与停止取消。
- 明确错过执行与启动补执行语义，测试及独立结果审查，本地提交。
- 记录后续清理接入约束：定时仅在线角色，离线走登录；共用同一过期清理领域逻辑。

### Out

- 本次不注册真实删除任务，不改变物品生命周期/历史数据，不执行过期物品删除。
- 不迁移现有次数等后台服务，不增加全库六点扫描，不部署或重启现有服务。
- 不实现分布式调度、cron全集、跨进程恰好一次保证或任务管理UI。

## Constraints

- 注册回调决定具体业务；调度器不能包含角色枚举、物品删除或NOTI逻辑。
- 每次实际尝试使用独立DI scope；调度器不替回调开启领域事务。
- 同任务不能因超时/重试而产生并行执行，停止要传播CancellationToken。
- 沿用当前工作分支；保留原有Tool/WireSmoke/__pycache__/。

## Success Conditions

| ID | Observable condition | Required evidence |
|---|---|---|
| SC-1 | 注册回调按每日/间隔规则被触发，业务与调度分离 | 可控时钟的实际回调测试及调用面审查 |
| SC-2 | 长任务不重叠、不阻塞其他可执行任务，整体并发受限 | 阻塞回调/多任务回归 |
| SC-3 | 启动补执行及错过多周期只补一次或跳过，有明确边界 | 跨日、时间跃迁、慢回调测试 |
| SC-4 | 失败有限重试/隔离；独立scope释放；停止不再派发 | 异常、取消、scope生命周期回归 |
| SC-5 | 空注册不触发实际业务，本次没有清理/全库扫描/运行部署副作用 | 正式接线、差分和独立审查 |

## Authorization

| Capability | Evidence | Authorized scope |
|---|---|---|
| task | Source Request中“写任务契约后跑了…你来做吧，然后我们再看看这个清理工作怎么加” | 调度器契约、设计、实现、验证、独立审查和本地接受提交；清理实际接入另行讨论 |

## Assumptions

- 回调需幂等；启动补执行不保证跨服务重启不重复，精确持久调度记录不属于本次范围。
- 同进程静态注册即满足当前需求，运行时新增/移除和修改计划留待真实需求。
