# Specification: 通关结算发经验

## Why and Outcome

打完一整个副本，走到结算屏，经验一分不涨，屏上每个数字都是零。经验现在只从击杀和交任务两条路进来，通关本身什么也不给。

结果要变成这样：清完一个副本后，结算屏上出现这一局的通关经验和评分奖励，角色的总量随之上涨；跨过等级线时和打怪跨线一样升级、一样刷新可接任务表。屏上写的数字就是实际到账的数字——**没有一分钱是付了却报不出来的**。

## Task Perspective

- Core outcome: 通关会给经验，且给了多少屏上说得清。
- Necessary support: 三张档案表的读取；跨等级线的后续处理与击杀路径共用；发放走同一件。
- Peripheral assurance: 表缺失、点位越界、比率越界时不发或按边界发，而不是让结算失败或凭空发一个数。

## Scope and Non-Goals

### In Scope

- 通关基数的计算与其四个因子的来源。
- 评分奖励的定档与比率。
- 通过既有发放件支付，以及跨等级线的后续处理。
- 结算时两个帧对这两项的如实申报。
- 表缺失、越界、点位超范围的行为。

### Non-Goals

- **结算侧的频道奖励与账号权益加成。** 客户端在 A21 的结算帧里用哪个固定槽申报它们没有测过，上游旧版的答案属于另一份槽数不同的帧。付了报不出来会让屏上的合计短一截，所以本 Spec 不付。测法记在下面。
- 装扮、宠物、冒险团、黑钻的通关奖励——没有来源。
- 逐怪经验条目、卡片、金币、掉落。
- 时间奖励点位（`[dungeon clear time reduction bonus]` 在档案里，但客户端报来的评分点位已经是它算过的结果，服务端再加一次是重复计算）。
- 组队。

## Constraints

- 发放路径唯一。
- 结算帧仍是 274 字节，字段偏移不动；只有原本恒零的字段现在带上真实值。
- 档案声明的数从档案读。上游代码里 `[clear rank exp bonusrate]` 的兜底常量与本档案实际值差一个数量级，不得作为来源。
- 付出去的每一分都必须在某个帧里报得出来；报不出来的本轮不付。

## Definitions

| Term | Meaning |
|---|---|
| 通关基数 | 这一局副本本身值多少经验，在任何加成之前 |
| 基准等级 | 副本自己声明的 `[basis level]`，也是房间不声明怪物等级时替补的那个值 |
| 评分点位 | 客户端在 `SET_PLAY_RESULT` 里报来的那一个字节，它自己算出的本局评分 |
| 评分档 | 评分点位落在档案的评分等级表的第几段，决定用哪一条评分奖励比率 |

## External Behavior and Data Rules

- 经验奖励表在档案里以 `值 -1 值 -1 …` 交替存放，`-1` 不是等级值。交任务已经在读同一张表，本 Spec 复用其读法而不另立一份。
- 评分等级表由高到低排列（`99 90 80 60 50 30 20 10`）。评分奖励比率只有五条，对应最高的五个档；低于第五档的评分不拿评分奖励。
- 世界级通关率（`[clear exp bonusrate]`）在本档案里是 1，因此任何实测都无法把它与"不乘"区分开。它与已经在用的 `[monster exp bonusrate]` 同形，按同样的方式参与。

## Observable Requirements

| ID | Requirement |
|---|---|
| RQ-001 | 清完一个副本后角色的总经验增加，增量等于通关基数加评分奖励 |
| RQ-002 | 通关基数取档案的经验奖励表在副本基准等级处的值，乘世界级通关率、该难度的难度率与该副本的经验权重，向下取整 |
| RQ-003 | 评分奖励为通关基数乘该评分档的比率，向下取整；比率取自档案 |
| RQ-004 | 客户端报来的评分点位低于最低的五个档时，评分奖励为零 |
| RQ-005 | 支付经由与击杀、交任务同一个发放件；结算不含第二份加经验与落库的实现 |
| RQ-006 | 结算跨过等级线时，角色升级，可接任务表按新等级重算并随结算一起下发 |
| RQ-007 | 结算的经验帧报出的是支付之后的等级与总量 |
| RQ-008 | 结算帧的通关基数与评分奖励两个字段带实际支付的数字，其余字段仍为零，帧长仍为 274 |
| RQ-009 | 经验奖励表取不到值（基准等级越界、表缺失）时通关不发经验，结算其余部分照常完成 |
| RQ-010 | 评分等级表或评分奖励比率表缺失时不发评分奖励，通关基数照发 |
| RQ-011 | 支付的每一项都对应结算帧或经验帧里的一处申报，没有付了不报的项 |

## Acceptance Scenarios

| ID | Covers | Given | When | Then |
|---|---|---|---|---|
| AC-001 | RQ-001, RQ-002 | 一个基准等级、难度、权重已知的副本 | 报告通关结果 | 总经验增加，增量的基数部分等于表值乘三个率再取整 |
| AC-002 | RQ-003 | 客户端报来一个落在某评分档的点位 | 报告通关结果 | 增量比基数多出基数乘该档比率再取整 |
| AC-003 | RQ-004 | 客户端报来一个低于最低五档的点位 | 报告通关结果 | 只有基数，没有评分奖励 |
| AC-004 | RQ-005 | 一次结算 | 报告通关结果 | 与击杀走同一发放件，落库一次 |
| AC-005 | RQ-006 | 结算的经验跨过等级线 | 报告通关结果 | 等级上升，可接任务表按新等级重算并随结算下发 |
| AC-006 | RQ-007 | 一次会涨经验的结算 | 报告通关结果 | 经验帧带的是支付后的等级与总量，不是入场时的 |
| AC-007 | RQ-008 | 一次已知金额的结算 | 结算帧被编码 | 前两个字段是这两个金额，其余字段为零，帧长 274 |
| AC-008 | RQ-009 | 副本的基准等级在表的范围之外 | 报告通关结果 | 不发经验；结算屏的其余部分照常 |
| AC-009 | RQ-010 | 评分表缺失 | 报告通关结果 | 只发基数 |
| AC-010 | RQ-011 | 任意一次结算 | 比对支付项与申报项 | 两者逐项相等 |

## Assumptions

- 结算帧头四个字段的**位置**是结构性的，其**含义**取自上游命名，未经实测。通关基数远大于评分奖励，一次实机截图即可看出二者有没有被写反；若写反，按截图纠正。
- 通关基数与交任务共用经验奖励表。这是上游的做法，若实机数字对不上则以实机为准。
- 结算侧频道奖励的下一次测法：在结算帧的二十三个固定槽里各填一个互不相同的值，跑一次通关，结算屏会把它认得的那几个连名带值列出来——与 2026-08-28 测经验通告十四个槽用的是同一招。
