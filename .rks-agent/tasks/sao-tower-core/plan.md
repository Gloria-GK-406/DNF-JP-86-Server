# 实施计划

采用direct：主代理维护同一实现计划，PVF补丁与名称调查界限明确，可委派一名worker；结果审查独立执行。

1. T-001 建立SAO内容契约/规则、共享Store模型和SQLite表。以共享状态/竞争/100循环/事务回滚测试先验证；不复用character_despair_tower表。
2. T-002 领域服务通过公共Admission进入映射DGN；Layout冻结Sao计划。怪物死亡确认Boss房间清理的事务按runId参与者竞争首通，统一派发额外奖励，每成员持久标记，失败整笔回滚。跨轮旧run无推进权。
3. T-003 入场路由、再次挑战、MonsterDeath事务接线与NOTI03E9编码/刷新接线。保留普通翻牌，额外奖励独立于选牌。检查登录/选图重连、会话身份和组队事务。
4. T-004 委派worker审计SAO相关固定期限，扩展现有PVF工具生成可重复/可检查补丁，核对全部开发客户端清单、名称占位符。先生成并验证，主代理合并审查后才同步真实文件；不改OneKey发行包或上游对照基准。
5. T-005 更新Document一期实现/验收和协议人工区。独立review完整diff及PVF差异，修复阻塞项；跑针对性及必要全量回归，备份后同步开发客户端和服务端PVF，不启动服务。最终记录SHA与数据库仅增表边界。

## Verification

- 真SQLite：竞争首通、run幂等、100→1、重启读取、事务回滚。
- Application：请求目标重映射/收费失败/未通关拒绝/多成员额外奖励/发放失败回滚。
- Protocol：03E9八字节、入场路由、登录/选图/结算接线；必需架构检查和相关现有副本回归。
- 内容：每来源独立生成，验证每个档案条目无关内容不变，期限清单与备份哈希；不能用测试冒充客户端验收。
