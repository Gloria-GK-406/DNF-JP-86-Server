# TaskContract: SAO 共享爬塔一期

## Context

用户要求：「先弄出来SAO塔的领域服务，然后慢慢将缺失的地方补全？pvf那里把过期物品的标示删除掉或者延后吧。然后同步给全部我们开发的client。然后看看dnf_xxxx的命名是不是缺失了对应的命名。你先把过塔循环，谁先过谁得到额外奖励这套弄完？」

入口现已恢复，但3600仍按普通地下城进入、结算，未推进共享层数。原生SAO支持全服共享100层循环及每层首队奖励。专用翻牌消息时序仍待实机确定。

## Goal

建立SAO领域服务，完成可持久化的共享爬塔循环与首队额外奖励；修复本次SAO相关历史过期声明并同步开发客户端；调查地图名称占位符。

## Scope

### In

- 共享层数决定实际入场目标；100层通关后开启下一轮第1层。
- 同轮同层只有首支有效通关队伍推进并获得额外奖励；重复报告与旧副本不能重复推进/发奖。
- 复用现有门票消费、地图实体、事务和物品派发，满包额外奖励转邮件。
- 登录、选图和通关后的层数协议投影。
- SAO活动物品固定历史期限审计、删除；各开发客户端与服务器PVF按自身原档生成和验证补丁。
- 定位dnf_xxxx名称来源，有确定证据才修复，无证据明确报告限制。

### Out

- 专用翻牌完整还原、每日门票补给、额外每日入场次数限制、SAO商店及所有联动活动。
- PR、合并、发布、重启服务及修改玩家现有物品期限。

## Constraints

- 沿用当前工作分支，不新建工作区；保留无关Tool/WireSmoke/__pycache__。
- Application不得引用Infrastructure/Persistence/Protocol；内容规则通过规则服务提供。
- 客户端基准资源不整体互相覆盖；补丁须保留每份档案无关内容和可回退备份。

## Success Conditions

| ID | Observable condition | Required evidence |
|---|---|---|
| SC-1 | 新入场读取共享进度，失败不扣票，不推进；再次挑战重新选层 | 服务测试与入场接线检查 |
| SC-2 | 每层首队唯一、奖励每成员一次，100→下一轮1；重试/竞争/旧轮不重复推进 | 真实SQLite事务回归、领域测试 |
| SC-3 | 额外奖励与持久化同事务，满包使用既有邮件派发 | 派发接缝与回滚/重放测试 |
| SC-4 | 客户端可接收当前共享层数快照，未知协议语义标注 | 编码/投影测试及待实机验收列表 |
| SC-5 | 开发客户端和服务器的SAO历史期限声明修复，无关条目保持一致 | 每档案差异清单、哈希和备份清单 |
| SC-6 | 地图名占位符得到有证据的定位或明确未解边界 | 调查结果、修复时的内容验证 |

## Assumptions

- 先保留普通结算路径；额外首通奖励与共享推进不依赖翻牌选择，完整SAO翻牌后续实现。
- 客户端清单以本地目录和用途核验；OneKey发行包、上游对照基准不自动算作开发客户端。
- 代码/静态资源测试不代替玩家实机验收；本期不启动原先已停止的服务。
