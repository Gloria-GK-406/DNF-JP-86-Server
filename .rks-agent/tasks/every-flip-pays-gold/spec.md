# Specification: 翻牌一定给金币，且金额随副本与难度浮动

## Why and Outcome

通关翻开一张免费牌，现在有相当一部分局是**一点反馈都没有**：牌里没摇到装备，金币也不给。
金币这一格既只在有装备时才付，金额又是本服务器自定的常量 1，没有出处也没有浮动。

使用者定的语义是**底薪**：免费牌一定给金币，金额有波动。档案给得出这个数 —— 每个等级一个金币
基数与一个波动百分比，每个难度一个金币倍率。本 Spec 让翻牌一定付出一笔由档案决定的金币，
玩家翻开任何一张牌都看得到自己拿到了什么。

## Task Perspective

- Core outcome: 玩家翻开一张免费牌，账户一定进一笔金币，金额随副本与难度变化而不是固定值。
- Necessary support: 金额在结算时与牌面一并定下并保持不变；组成它的三个因子各自有档案出处。
- Peripheral assurance: 判据钉规则层产出的数值与解码后的帧；其余规则层取值逐值不变的回归保护。

## Scope and Non-Goals

### In Scope

- 免费牌金币的金额从哪里来：三处档案读数及其相乘方式。
- 金额恒大于零，与牌里有没有装备无关。
- 金额在一局内稳定：重复询问、断线重来给同一个数。
- 结算通知把这个金额放在它该在的那一条上；翻牌一律把它入账。

### Non-Goals

- 不采用击杀数、评级加成、队伍人数除法，以及参照服务端那个无出处的比例系数。
- 不新增按局的击杀计数。
- 不改出货概率、品级带、副本定价、掉落池选取等既有取值。
- 不改协议编码的结构：金币那一条的位置由上一个 Spec 定下，这里只改它的值。
- 不做付费（黄金）牌与黑砖牌的金币。

## Constraints

- 进入金额的每一个因子都必须指得出档案里的哪一节；指不出来的因子不进公式。
- 判据的断言对象是规则层产出的数值与按客户端读法解码后的帧，不是编码动作。
- 规则服务不读世界状态：金额只由喂进去的事实与显式种子决定。

## Definitions

| Term | Meaning |
|---|---|
| 底薪 | 免费牌一定付出的那笔金币，与牌里有没有装备无关 |
| 基数 | 档案按等级声明的一份金币值 |
| 难度倍率 | 档案按副本难度声明的金币乘数 |
| 波动百分比 | 档案按等级声明的上下浮动幅度 |

## External Behavior and Data Rules

- 金额取自三处档案读数：按副本**基准等级**取基数与波动百分比，按本局**难度**取倍率。
- 浮动是双向的：金额落在基数与倍率之积的上下各一个波动百分比之内，两侧都可能取到。
- 金额与牌面在同一次结算里决定，用同一个显式种子，因此同一局问几次都是同一个数。
- 结算通知里，这个金额出现在那张牌的第一条条目上；翻牌的应答不携带它。

## Observable Requirements

| ID | Requirement |
|---|---|
| RQ-001 | 免费牌的金币恒大于零，与该牌里有没有装备无关；付费牌不拿这笔金币 |
| RQ-002 | 金额以副本基准等级的档案基数为底 |
| RQ-003 | 金额按本局难度的档案倍率缩放 |
| RQ-004 | 金额按该等级的档案波动百分比上下浮动，且不越出该范围；该百分比按等级分段，不是一个常数 |
| RQ-005 | 浮动双向可达：足够多的种子下，低于和高于中值的取值都出现 |
| RQ-006 | 同一局的金额不随询问次数、时间或断线重来改变 |
| RQ-007 | 结算通知里那张牌的第一条条目携带这个金额 |
| RQ-008 | 玩家翻开免费牌时这笔金币一律入账，牌里没有装备时也入账 |
| RQ-009 | 除金币之外，规则层产生的每一个值与既有基线相同 |
| RQ-010 | 每一个进入金额的因子都能指出它来自档案的哪一节 |

## Assumptions

- **三个因子如何相乘是本服务器定的。** 档案给出三个数，但没有一处说明它们的组合方式。
  参照服务端把它们相乘后还叠了四个没有出处的因子（加权击杀数、评级加成、队伍人数除法、
  一个 `175/1000` 的比例），其中那个比例在它自己的代码里出现两次而零注释、档案里也查不到。
  本 Spec 只取有出处的三个，其余不取；这一点在规则所在之处具名，供更好的证据推翻。
- 档案按等级声明的那一列百分比读作「上下各这么多」，依据是参照服务端把该列取名 `variancePercent`
  并正是这样用的。三列结构本身来自档案，可核对。
- 副本基准等级沿用既有读法，不在本 Spec 重新论证。
