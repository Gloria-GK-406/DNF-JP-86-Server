# Specification: 每日在线到期清理

## Why and Outcome
在线跨六点无需重登即可删除已过期物品；离线角色继续依赖已验收的登录清理。

## Scope
仅注册现有调度器并补在线编排/投影，不再建线程或timer；不修改期限生成、历史数据和数据库结构。

## Requirements
| ID | Requirement |
|---|---|
| RQ-001 | 采用现有每日重置配置（当前UTC+8六点），按在线快照调度；执行时排除已下线、换角、旧generation及尚未发布的会话 |
| RQ-002 | 登录与调度调用同一CleanupAsync；只删除其原有范围内已到期实例，永久哨兵和未来期限保持不变 |
| RQ-003 | 每角色账号隔离事务删除与事件同提交；客户端在提交后读取当前状态刷新受影响容器，穿戴更新沿用统一外观计算；旧会话不得收到更新 |
| RQ-004 | 单角色故障记录并继续其余角色，未完成批次交调度器有限重试；重复执行无额外删除，无变化不通知 |

## Acceptance Criteria
| ID | Covers | Criterion |
|---|---|---|
| AC-001 | RQ-001 | 受控时钟跨六点运行实际注册；离线/排队中退出或换角的会话不进入删除 |
| AC-002 | RQ-002 | SQLite登录与在线使用同一核心；含装扮/普通物品、永久和未来期限的清理与回滚测试通过 |
| AC-003 | RQ-003 | 事件只在有删除时生成，回滚不投影；当前容器及穿戴由当前视图生成，旧generation和无变化不发帧 |
| AC-004 | RQ-004 | 一人失败仍处理下一人，重试保留失败证据；幂等回归和部署身份/就绪检查通过 |

## Success Evidence
自动测试证明服务器逻辑，不替代真实客户端跨六点的刷新验收；真实下一次六点可由用户保持在线测试。部署保留数据库备份与原运行产物，不人为调整用户物品期限。
