# TaskContract: 在线角色每日到期清理

## Context
Source Request：“测试ok，登录后这些限时物品都清理了。现在把每天6点的在线角色清理接到定时任务里吧，和登录共用同一个清理逻辑，离线角色不用处理。”
基准 d5632d90，task/next-round-20261013；通用调度器已有，登录清理已经用户实机验收。

## Goal
每日北京时间六点自动清理在线角色的到期物品，使用登录同一清理逻辑，并向在线客户端同步结果。

## Scope
- 注册现有通用调度器；只枚举在线角色，执行前重新确认当前会话。
- 登录和定时清理共用到期判断、容器范围和删除逻辑。
- 删除、物品变动事件事务一致；提交后同步受影响容器及穿戴表现。
- 失败隔离、有限重试、重复执行幂等；提供自动回归和部署证据。
- 不处理离线角色，不改历史物品期限，不扩展账号仓库/邮件/称号簿清理，不迁移其他timer。

## Constraints
沿用当前工作分支，不动无关 Tool/WireSmoke/__pycache__/；数据库备份后部署，无结构迁移。

## Success Conditions
| ID | Observable condition | Required evidence |
|---|---|---|
| SC-1 | 六点由现有调度器触发，只处理仍在线的角色 | 时间边界、注册与离线/切角回归 |
| SC-2 | 与登录共用删除逻辑，永久/未来期限不动，回滚不留删除 | 真实SQLite清理回归与调用检查 |
| SC-3 | 提交后在线容器和穿戴表现更新，旧连接不被更新 | 投影、会话及事件回归 |
| SC-4 | 故障不阻断其他角色，任务可重复执行 | 失败隔离、重试/幂等及部署就绪证据 |

## Authorization
| Capability | Evidence | Authorized scope |
|---|---|---|
| task | Source Request | 契约、实现、测试、独立审查、当前分支本地提交；沿用当前测试服务部署流程 |
