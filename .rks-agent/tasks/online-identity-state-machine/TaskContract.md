# TaskContract: 在线身份收成一台状态机，在线角色状态拆成按会话归属的运行时

## Context

### Source Request

处理 issue #186「账号当前选中角色/会话存了 4 份、分在 3 把锁后」。讨论中用户提出把“他是谁”（账号、会话、会话的角色）与“他怎么样”（角色的在线状态）切成两部分：前者聚合成会话身份，后者作为一个不加锁、与角色领域服务相似但不并入它的服务。Agent 补充：身份做成一台状态机（含“已选中/在世界/已隔离”），运行时状态只属于一个会话代数，“是否存位置”由频道推导而删除。用户回复：“第三条记录一个issue，然后我们完成这部分的重构。写任务契约，sdd规模你自己确定。大体方向我认同你的看法，细节你来把持吧。做完后再告诉我”。另说明本会话中 AGENTS.md 只作参考意见。

### Current Situation

基准 `7fc8acdc`，路径相对 `Server/src/`。“这个账号/角色/连接现在是哪个会话”存了多份：

- `SelectedSessionDomainService.sessions`（选角准备即写入，一把锁）；
- `SelectedSessionRuntimeDirectory.entries`（发布时写入，带“是否存位置”，一把锁）；
- `OnlineStateRegistry.activeByAccount` 与 `OnlineUser.CurrentCharacterId`（发布时写入，第三把锁）；
- `SelectedSessionSafety.blocked`（结算结果不明而隔离的会话，另一把锁）。

写入与拆除顺序各不相同。连接被撤销（协议拒绝、登录被顶替）时在线用户立即删除，选中会话却留到断线回调靠 `FindByConnection` 补清（`OnlineUserConnectionObserver.cs:75-87`）：这一“已撤销、待清理”的阶段是必要的（撤销要立刻停止操作，其他聚合的清理要稍后在生命周期门下完成），但目前只能从几份存储彼此不一致间接看出。调用方因此手写多处“三连查”。

角色在线状态分散在四个服务：位置、血蓝百分比按角色 ID 存并各带会话副本做代数比对、各一把锁；物品冷却是无锁 `ConcurrentDictionary`，键为（角色, 冷却键），不带会话；灵药加成不存会话副本，在自己的锁内查选中会话判定。清除时机不对称：灵药在发布时清，冷却在拆除后且角色未被重新选中时清。“是否存位置”等于 `!channel.IsTransient`，频道可由会话的 `ListenerPort` 解析。

## Goal

“他是谁”只有一个真源：连接、账号、选中会话、会话的角色，以及会话处于已选中、在世界、已隔离、连接已撤销待清理中的哪一阶段，由一个组件在一个一致性边界内回答，调用方不再拼接多处结果。“他怎么样”只有一个归属：位置、血蓝百分比、物品冷却、灵药加成由一个在线角色运行时服务持有，每条状态只属于一个会话代数，旧会话不能读到、改到或复活同角色新会话的状态；该服务不加业务锁，并发更新不丢失。游戏协议行为保持不变。

## Scope

### In

- 把选中会话目录、活跃角色登记、在线用户上的当前角色、会话隔离集合收为同一个在线身份组件；删除 `SelectedSessionRuntimeDirectory` 及其接口。
- 在线身份按账号、角色、连接、`WireUserId` 查会话，并给出既有调用点需要的阶段判定；读取被删存储的调用点迁到对应判定，保持每个调用点原有的接受范围。
- “连接已撤销、待清理”成为在线身份中显式可查询的阶段，由同一条记录表达；选角准备、发布、拆除、断线、协议拒绝、顶替、隔离各路径改用在线身份的状态转移。
- “是否存位置”不再存储，拆除时由会话频道推导。
- 新建在线角色运行时服务，承接位置、血蓝百分比、物品冷却、灵药加成；迁移原四个服务的全部调用方并删除原服务与其接口。发布时一次建立、拆除时一次移除。
- 补充或改写自动测试覆盖阶段转移、代数隔离、撤销待清理阶段与运行时并发更新；更新描述这些结构的仓库文档。

### Out

- 不统一其余手写的“会话仍是当前”内联判定（#185）；`OnlineUserSnapshot` 上对外可见的当前角色与状态继续提供，其读者不在本次迁移。
- 不改执行门、会话租约与加锁原语（#182、#204）。
- 不改 `SelectedSessionSafety` 按连接对象记录的连接级栅栏：它约束的是连接本身，须在在线用户记录删除后仍然有效，不属于会话身份。
- 不处理城镇区域里的第二份位置与专家商店无写入方（#208）。
- 不改城镇区域、队伍、副本、两塔、PvP 大厅、婚房、宠物运行时、物品容器等跨角色或带事务的聚合，除非它们直接读取被删除的存储。
- 不改协议字段、数据库结构、客户端；不合并、推送、开 PR 或部署。

## Constraints

- 代数精确：被替换或已拆除的会话不能读到、改到、复活或投影到同角色的新会话。位置、血蓝已是既有行为，须保持；冷却、灵药按此补齐（实质风险：同账号命令可并发、拆除与迟到操作可交错）。
- 在线角色运行时不使用 `lock`、`Monitor`、信号量等互斥锁；并发集合自身的原子操作不算业务锁。同一会话的并发更新不得丢失（用户要求“不用锁”；命令管线对同一账号取共享租约，并发真实存在）。
- 在线角色运行时是独立服务，不并入现有角色领域服务（用户要求）。
- 一次迁完、删净，不保留旧存储、转发层或 `[Obsolete]`（`Docs/Agent/RefactorPreferences.md` §2 记录的用户原话“一次性全迁移吧，没必要留一半”）。保留下来的接口须由新组件直接实现。
- 游戏协议回包与持久化结果保持不变。

## Assumptions

- “已选中但未发布”期间的读者目前只依赖“仍是当前”语义（命令管线 `DemandCurrent` 只查选中会话目录）；若发现调用点依赖更细的区别，在 Spec 中按调用点逐一保持。
- 会话期间其频道配置不变，拆除时按 `ListenerPort` 解析得到的“是否存位置”与发布时一致。
- 现有自动测试足以作为“协议行为不变”的主要证据；对未覆盖的关键路径补表征测试。
