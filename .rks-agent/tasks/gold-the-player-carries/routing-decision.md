# Routing Decision

- TaskContract: `.rks-agent/tasks/gold-the-player-carries/TaskContract.md`
- Contract revision: `1`

## SDD Readiness

- Intent and outcome stability: 结果可观察且已被玩家亲自定义——「背包上那个数字是对的，重登还在」。根因已查实到字节层面（随身金币是主背包虚拟槽 0；本仓所有收入进了账号金库），不再有诊断上的未知。用户已亲自定下命名方案与随身金币要挂在角色对象上，这两项原本是最可能返工的决定。
- Requirement stability: 可枚举且可独立核对。命名侧：`purse` 79 处 10 文件、`Gold` 的三种非货币用法、三份走样的文档，每一条都能单独查证。实现侧：写路径、建角色起始行、携带上限、三个入账点改流向、变更帧推送，每一条都有明确的观察方式。
- Execution direction: 已知。存储格式、槽位分段、两个协议帧的帧内偏移都已与参照服务端逐字节比对一致，写路径（容器写随命令事务提交）现成可用。参照服务端的失败模式也已查明并写进契约约束（业务层不收敛导致上限失效），据此选择了单一入口的形状。
- Remaining uncertainty: 仅剩非语义的局部选择——起始金币取什么值、超上限时截断还是拒绝、变更帧在哪些路径上推送。这些不改变任务语义，留给各自的 Spec 定。

## Marginal Control Value

- User precision signal: 明确偏精度。用户拒绝了「先按上游改了再说」的做法，坚持先系统性解释清楚协议与结构才动手；发现根因后主动要求走 SDD 而非直接改；并接受了「拆两步、第一步行为零变化」这个更慢但更安全的路径。
- Direct failure mode: 「改到一半却看起来完成了」。这不是假想——本仓已经因同类错误吃过一次亏：`Docs/新功能接入规范.md` 把「角色金币既没有落库路径」答成「已有」，此后所有相关工作都建立在这个假前提上，直到玩家实机发现金币归零才暴露。命名这一步的具体形态是：79 处 `purse` 里有 62 处在测试类名与用例名中，漏改测试名会让下一个人以为随身金币已有回归覆盖；漏改那句「已有」则陷阱原封不动。而全量判据只能证明行为没变，**证明不了改全了**。
- Useful control: 可独立核对的 Spec 要求（每一类漂移与每一段闭环各一条，均可用检索或实机观察单独查证）加独立评审。评审在本仓已多次抓到自查漏掉的东西。
- Time-for-quality rationale: 值。第一段是行为保持的重构，1993 条判据是现成的强 oracle，Spec 补的正是它证明不了的那一半——覆盖完整性。第二段触及玩家能直接看到的数字，错了会以「钱不见了」的形式暴露给玩家，检测成本高、信任损失大。相对于两段各自可能的返工，写 Spec 的时间是小头。

## Structural Selection

- Selected workflow: `multi-spec-workflow`
- Boundary evidence: 两个**独立可验收**的结果，各有各的 oracle 与回滚边界。第一段的验收是「名字与文档不再指错，且行为逐值不变」，由全量判据加检索核销；第二段的验收是「玩家看到的钱是对的，重登不丢」，由实机观察。关键判据是：**第一段交付后即使第二段永不进行，仓库仍处在一个严格更好的状态**——假前提被拔除、两笔钱可区分。反过来第二段依赖第一段确立的名字，顺序不可颠倒但耦合是单向的。两段的失败也互不牵连：命名归位失败不该阻止随身金币实现，随身金币实现失败也不该回滚已经正确的命名。
- Why Direct is insufficient: Direct 无法廉价提供覆盖完整性的证据。这里的失败不是「做错了」而是「做漏了」，而漏掉的部分在运行时完全不报错——判据全绿、编译通过、行为不变，只有下一个读代码的人会被误导。要挡住它只能靠一份可独立核对的枚举，而那正是 Spec。
- Reroute conditions: 若第一段实施中发现命名归位无法在行为不变的前提下完成（例如某处改名会改变序列化或反射行为），则该段的验收边界失效，退回重新定边界；若第二段发现随身金币无法挂在既有 `ICharacter` 上（例如 `CharacterItemLeaseState` 对 virtual resources 的排除构成硬阻碍且无法在本 Spec 内解决），则该段的中心方案失效，须重新路由而非在 Spec 内硬推；若两段在实施中被证明必须同时改动同一批文件才能各自绿，则边界判断有误，应合回单一 Spec。
