# TaskContract: Reactive dungeon cell runtime

## Context

### Source Request

用户在确认“首次切换到 Cell 时完整创建，随后只操作该 Cell”的领域方向后，明确授权：
“对，先用sdd完成这部分的重构逻辑吧。范围还是有点大的”。

### Current Situation

当前地下城运行态把 `DeadActors`、`MonsterDrops`、`TakenGroundDrops` 等 Cell 内事实分散
保存在整个 Dungeon Run 中；进入房间时又从 PVF 声明与这些补丁集合临时拼装房间内容，怪物
死亡时还会重新访问掉落与房间规则。这造成 Cell 没有单一真源、重访依赖重建、掉落创建和
拾取投影可能乱序，而且 Run 服务承担了过多房间内部职责。

## Goal

建立由 Dungeon Instance 管理、按 Cell 首次访问完整创建并在后续访问中复用的运行时 Cell
实体，使已创建 Cell 自己拥有怪物和地面物等运行时事实；现有怪物死亡、掉落生成、拾取和
房间快照均以该 Cell 状态为权威来源。

## Scope

### In

- 为每个 Dungeon Run 建立按迷宫坐标唯一标识的运行时 Cell 生命周期。
- 首次进入目标 Cell 时，通过现有 PVF/content 与规则边界准备完整 Cell，准备成功后才原子
  发布并切换；准备失败不得留下半初始化 Cell 或提前改变当前房间。
- 重访 Cell 时复用已有实例及其状态，不重新生成怪物、初始地面物或已消耗内容。
- Cell 拥有现有运行所需的怪物/Actor 状态、地面物状态、房间清理状态和单调版本；移除 Run
  上用于拼装这些事实的平行真源。
- 将现有房间声明物与怪物产生物统一为 Cell 的地面物模型；该模型对来源保持中立，并为建筑
  或玩家丢弃等后续来源提供同一加入入口，但不虚构当前没有协议证据的行为。
- 怪物创建时固化后续掉落所需的确定性计划或结果；怪物死亡后不再查询 PVF/content。若最终
  结果必须依赖死亡时事实，Cell 只能使用创建时固化的计划和死亡命令携带的事实完成结算。
- 让首次进入、重访、怪物死亡和拾取投影从同一 Cell 快照/变更序列产生，保留现有 A21 协议
  线格式及背包持久化事务边界。
- 更新相关自动化测试和领域文档，证明生命周期、复用、原子创建及地面物一致性。

### Out

- Boss 结算、翻牌、等待回城和奖励规则的功能重做。
- 新增未经协议证据支持的建筑破坏、玩家主动丢弃或任意时点全量重同步线协议。
- 将 SQLite 更换为 MySQL，或移除当前带事务命令的串行化策略。
- 修改 ClientHack、客户端二进制、客户端资源或 `debug-lab`/`client-debug-lab` 工作区。
- 合并到 `main`、部署服务器、启动客户端或进行实机验收。

## Constraints

- 保持 Application 不引用 Infrastructure 的既有分层规则；PVF/content 只通过抽象接口参与
  Cell 创建。
- Cell 创建期间不得在 Dungeon Run 的可见状态中发布半成品；并发请求同一 Run/Cell 时只能
  形成一个被采用的实例。
- 地面物对客户端使用的标识在 Cell 生命周期内稳定，拾取成功后不得因重访或重新投影复活。
- 背包写入与 Cell 地面物移除必须保留可补偿的预占/提交语义，不能以先删除地面物的方式换取
  表面一致性。
- 不把 Session、连接端点或协议发送器引入地下城领域状态。

## Success Conditions

| ID | Observable condition | Required evidence |
|---|---|---|
| SC-1 | 首次进入新 Cell 时，只有完整构造成功后才切换当前 Cell；构造失败保持原 Cell 且无半成品可查询 | 聚焦领域测试覆盖成功、失败和同 Cell 并发创建，并检查最终快照 |
| SC-2 | 重访既有 Cell 返回同一运行时事实，已死亡 Actor 和已拾取地面物不复活，且重访路径不再次读取 Cell 创建内容 | 行为测试与可观察的伪 content/rule 调用计数证明只创建一次 |
| SC-3 | 房间初始物与怪物掉落都进入同一个 Cell 地面物集合，拾取成功从该集合提交移除，失败可释放预占 | 覆盖创建、死亡转移、拾取成功、持久化失败补偿和重复拾取的领域/应用测试 |
| SC-4 | 怪物死亡后的运行时处理不再查询 PVF/content 或把掉落追加到 Run 级 `MonsterDrops` | 静态代码检查、完整变更审查以及相应行为测试 |
| SC-5 | 房间快照和运行时变更携带单调版本，现有进入、死亡、拾取投影都以 Cell 状态为权威且保持客户端协议兼容 | 投影/编解码回归测试及版本顺序测试通过 |
| SC-6 | 既有地下城进入、组队进入、换房、击杀、拾取及背包事务回归没有被破坏 | 相关测试项目及完整解决方案构建通过，零警告零错误 |
| SC-7 | 领域文档明确 Dungeon Instance、Cell Factory、Cell Instance、规则服务和命令事务协调之间的职责 | 文档审查与代码结构交叉核对通过 |

## Authorization

| Capability | Evidence | Authorized scope |

## Requires Confirmation

- 合并结果到 `main`。
- 清理任务 worktree/分支。
- 部署或重启服务器，以及启动/操作客户端进行实机测试。

## Assumptions

- “生成应该掉落的物品”允许实现为 Cell 创建时固化确定性掉落计划；死亡位置、击杀者等只有
  死亡时才存在的事实可在 Cell 内用该计划结算，但不得再次访问外部 PVF/content。
- 本任务迁移当前已经存在的初始地面物、怪物死亡和拾取行为；对建筑、玩家丢弃只建立统一的
  Cell 领域入口，不在缺少现有协议链时扩大为新功能。
