# Specification: 容器抽象与角色绑定（行为零变化）

## Why and Outcome

道具的读写目前由协议处理器直接向持久化存储发起，存储层无法替换。这条路只有两个调用点，
但它是后续所有背包与副本工作的共同基础：副本临时背包、多容器切换都需要在同一位置换掉存储。

参考实现在同一位置没有设这层接缝，代价是当它需要一个只存在于本次运行中的背包时，
只能把移动与使用的整套规则另抄一份。

本次变更后，道具的存取经由一个可替换的容器完成，角色对「当前使用哪个容器」有显式绑定，
而对外可观察行为一字不变。

## Task Perspective

- Core outcome: 后续需要一个不同的道具存储时，只需提供一个新的容器，既有的移动与使用规则
  原样复用，不必复制。
- Necessary support: 本次变更不得改变任何对外可观察行为——否则这次替换本身就成了一次
  未经验证的行为变更，且会使后续成果失去可对照的基线。
- Peripheral assurance: 既有测试基线保持全绿，以及一次实机走查；二者证明行为未变，
  但它们不是本次交付的成果。

## Scope and Non-Goals

### In Scope

- 道具按槽读取、写入、删除，以及枚举已占用的槽，均经由容器完成
- 容器自述其身份、类型、客户端可见的形状与是否允许被移除
- 角色维度的容器注册、按类型列出、按类型取得当前容器、切换当前容器、移除容器
- 持久与非持久两种容器的并存，以及按既有容器形状创建非持久容器
- 道具移动与道具使用两条协议改由容器完成其道具存取
- 背包投影所需的容器状态可由当前容器供给

### Non-Goals

- 任何对外可观察行为的变更，包括帧字节内容与发送时序
- 道具可用性判定、使用效果模型、冷却
- 多容器切换的持久化结构变更与触发协议
- 每日补给与选角入场路径的存取方式，包括入场时一次性产生的五份初始背包快照
- 修复已知的「非消耗类道具被扣减」缺陷

## Constraints

- 对外可观察行为必须与变更前逐字节、逐时序一致
- 容器的使用方在读写道具时不得依赖该容器是持久的还是非持久的
- 既有测试的语义不得修改；仅允许因类型或依赖变化而做的机械调整

## Definitions

| Term | Meaning |
|---|---|
| 容器 | 一组按槽位编址的道具，自述其类型与容量，可被替换为另一份实现 |
| 容器形状 | 客户端据以绘制该容器的两项事实：容器类型与容量参数 |
| 当前容器 | 角色在某一容器类型下正在使用的那一个容器 |
| 不可移除容器 | 被标记为不允许移除的容器，用作当前容器被移除时的回落目标 |

## External Behavior and Data Rules

- 背包全量投影替换客户端上该容器类型的全部内容；增量投影只改变其指名的槽位
- 对每种已注册了容器的类型，角色在任一时刻恰有一个当前容器；尚未注册容器的类型没有当前容器

## Observable Requirements

| ID | Requirement |
|---|---|
| RQ-001 | 道具的按槽读取、写入、删除与占用槽枚举经由容器完成，协议处理器不直接依赖持久化存储的实现 |
| RQ-002 | 容器自述其身份、类型、客户端可见的形状与是否允许被移除 |
| RQ-003 | 同一容器类型下可同时存在多个容器，且角色对每种类型恰有一个当前容器 |
| RQ-004 | 某类型下第一个被注册的容器成为该类型的当前容器 |
| RQ-005 | 可按类型列出角色的全部可用容器，并将当前容器切换为其中任意一个 |
| RQ-006 | 移除当前容器后，角色对该类型的当前容器变为该类型下第一个不可移除的容器 |
| RQ-007 | 当前容器被移除且该类型下不存在可回落的容器时，该情形以异常暴露，不产生「无当前容器」的状态 |
| RQ-008 | 持久容器与非持久容器并存，且二者的使用方在读写道具时不区分它们 |
| RQ-009 | 可按既有容器的形状创建一个非持久容器 |
| RQ-010 | 背包全量投影与增量投影所需的容器状态可由当前容器供给；对同一存储内容，其编码所得帧字节与入场加载路径所得一致 |
| RQ-011 | 道具移动与道具使用两条协议的对外可观察行为与变更前一致 |

| AC-002 | RQ-002 | 一个已注册的容器 | 询问它的身份、类型、形状与是否可移除 | 四项均由容器自身答出，无需查询别处 |
| AC-003 | RQ-003, RQ-004 | 一个角色，某类型下尚无容器 | 依次注册两个该类型的容器 | 按类型列出返回两个；当前容器是第一个注册的那个 |
| AC-004 | RQ-005 | 一个角色，某类型下已注册两个容器 | 把当前容器切换为第二个 | 按类型取当前返回第二个；列出的集合不变 |
| AC-005 | RQ-006 | 一个角色，某类型下先注册了一个不可移除容器，再注册并切换到一个可移除容器 | 移除当前的可移除容器 | 当前容器变为那个不可移除容器；列出的集合不再含被移除者 |
| AC-006 | RQ-007 | 一个角色，某类型下只有一个可移除容器且它是当前容器 | 移除它 | 抛出异常；角色对该类型的绑定未被破坏 |
| AC-007 | RQ-008, RQ-009 | 一个已注册的持久容器 | 按其形状创建一个非持久容器，并对二者施加同一组按槽读写删操作 | 两者的读写结果一致；非持久容器的内容不进入持久存储 |
| AC-008 | RQ-010 | 一份持有若干道具的存储，其中含另一列表的道具 | 分别由当前容器与入场加载路径生成同一容器类型的容器状态并编码 | 两者所得字节一致；容器只取自己那一列表的道具 |
| AC-009 | RQ-011 | 教学副本中的角色，背包内有一件可堆叠道具 | 将该道具拖到快捷栏槽位，随后使用它 | 表现与变更前一致：道具改换槽位，使用后数量按变更前的规则变化 |

## Assumptions

- 现有的道具移动与道具使用两条协议只回 CMD 应答，不推送任何背包投影；此时新增一次推送
  本身就是行为变更，为本 Spec 所禁止。因此 RQ-010 交付的是「容器可作为投影内容的来源」
  这一能力，并以其与入场加载路径逐字节一致为证，而不是新增一条推送路径。
  真正把入场快照改由容器供给，留待多容器切换一并落地
- 选角入场的初始快照由一次整体加载产生，涵盖五种容器类型且与道具值、锁、租赁等一并读出；
  把它迁到容器之上会拖入整条入场路径，与本 Spec 的非目标冲突，因此本次两条路径共存，
  互不改变对方的字节输出
- 既有的背包投影所消费的容器状态结构足以表达容器的内容，无需改动线上格式；
  若实施中证伪，则「行为零变化」不再是可达的验收面，须停在安全点上报控制器
- 每日补给与选角入场路径继续沿用现有存取方式；它们与容器共享同一底层存储，
  二者对同一角色的并发写入不在本 Spec 处理
