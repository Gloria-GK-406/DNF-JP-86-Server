# Specification: 通关结算的翻牌奖励

## Why and Outcome

玩家打完一个副本，结算画面之后应该有四张背面朝上的牌，翻开一张，看到四张各自是什么，
把翻到的东西收进背包。今天这一步不存在：服务器在结算之后只回一个「知道了」，
卷轴关掉，一局就这么结束，玩家两手空空。

结束之后必须成立的是：通关的玩家能翻一张牌，四张牌的内容当场揭晓，翻到的装备出现在
背包里、金币计入账号；同一局里这四张牌是什么，一经定下就不再改变；牌面上每一件东西
的由来都能指回归档所声明的规则，而不是一个凭印象填进去的数。

## Task Perspective

- Core outcome: 玩家通关之后能翻牌并拿到东西，且拿到什么由归档的规则决定。
  消费者是玩家，他需要的是「打完副本有奖励可拿」这个能力，不是任何一份表的读取器。
- Necessary support: 牌面内容在本局内稳定不变（否则同一次结算里重复询问会给出不同答案，
  奖励就成了可以反复摇的）；牌位不可重复翻开（否则一张牌能领无数次）；
  付费翻牌先收费后发奖，且付不起时不发（否则金币可以凭空变成装备）。
- Peripheral assurance: 每一处归档读数与其出处的对照记录；各稀有度档次的可达性证明；
  分层落点的依赖枚举；既有判据不被打破。

## Scope and Non-Goals

### In Scope

- 结算之后的完整翻牌交互：请求卷轴状态、请求牌面版式、翻开某一张、以及随之而来的
  到货告知。
- 免费牌与付费（黄金）牌两种。付费牌按归档的等级成本表收费，付不起则拒绝且不发奖。
- 牌面内容的产生：牌位是否有东西、有的话是什么档次、什么品级带、从装备池里抽哪一件，
  全部由归档所声明的概率、加成、阶梯与池子决定。
- 每张翻到的牌附带固定 1 金币，计入账号。
- 副本自行声明的牌面产出覆盖全局表；未声明的副本落到全局表。
- 结算帧里已经预留但一直写零的那段牌面信息，按本 Spec 产生的内容填写。
- 新增的归档读取与规则落在仓库既有的分层约定里。

### Non-Goals

- 安图恩团本的材料与武器奖励。它与普通副本确实不同，但其翻牌是否同一套机制尚未确认；
  本 Spec 不覆盖，也不为它预留抽象。
- 需要黑钻的那种免费牌。
- 怪物击杀掉落。
- 材料类奖励。归档的物品类别概率只声明装备与时装两支，没有材料。
- 时装。物品类别概率里时装占一支，本 Spec 只取装备那一支。
- 归档中三段用途未查明的声明（一段稀有度控制、一段付费牌生成率、一段编年史套装奖励率）
  一律不使用。不使用是本 Spec 的决定，不是遗漏。
- 队伍。本服务器没有队伍模型，人数恒为一人。
- 探索度。本服务器不记录它，归档中按地图数给出的那一档加成也不是探索度。

## Constraints

- 规则数值与结构的依据必须来自归档。参照服务端在同一族归档文件上已被证实有三处编造，
  其中一处使两个最高稀有度永远无法掷出而代码表面毫无异样，因此它不构成依据。
- 归档没有声明的值必须单独具名并写明它是本服务器的假设及其理由，不得混在有出处的
  读数里；读不出来的字段记为未查明，不得填一个看起来合理的数。
- 归档读取只经规则服务进入服务器；规则服务不查世界状态，只接收传入的事实与显式种子。
- 能触达持久写的用例按仓库既有的事务约定办。
- 既有的全部判据不得被打破。

## Definitions

| Term | Meaning |
|---|---|
| 牌位 | 结算牌面上的一个位置。本 Spec 涉及四个可翻的牌位 |
| 牌面内容 | 一个牌位背后是什么：一件装备与一份金币，或者什么都没有 |
| 揭晓 | 把某个牌位的内容告知客户端，使其显示出来 |
| 翻开 | 玩家选定一个牌位，该牌位的东西就此归他，并触发全部牌位的揭晓 |
| 出现概率 | 一个牌位是否有东西的几率，由归档的基础率与若干加成合成 |
| 稀有度阶梯 | 归档声明的累积门槛序列，末位是摇点的基数，决定抽出的东西是哪一档 |
| 品级带 | 按副本基准等级给出的品级上下探范围，限定可抽的池子 |
| 档位 | 客户端自己算出并上报的本局评级 |

## External Behavior and Data Rules

- 结算之后的交互由四个外部交换构成：卷轴状态请求、牌面版式请求、翻牌请求，
  以及背包变化告知。前三个各有其应答，第四个是服务器主动推送。
- 卷轴状态请求的应答之后必须跟随一帧牌面版式。今天服务器不发版式，客户端因此关掉卷轴
  并且不提供任何牌；发出版式是「有牌可翻」的前提。
- 版式帧声明有哪几个位置，**不携带任何物品**。牌是背面朝上的，客户端此时不应当、
  也无法得知牌里是什么。
- 翻牌请求携带牌型与牌位序号。牌型区分免费与付费；序号超出可翻范围的请求被丢弃。
- 翻牌应答是若干条记录，每条记录声明它描述的是哪个牌位，以及该牌位上有几件东西、
  分别是什么与多少。一个牌位没有东西时，该条记录声明它带零件东西。
- 客户端对已经揭晓过的牌位会忽略后续内容，因此同一牌位的内容一经揭晓便不可更改。
- 背包变化告知携带发生变化的容器与其中的条目，用于让客户端看到新到的东西。
  本服务器今天只有全量快照一种告知，没有增量告知。
- 结算帧本身留有一段描述牌面的区域，今天全部写零。它至少表达免费牌位的物品与金币、
  其余牌位、以及一次付费翻牌的价钱。

## Observable Requirements

| ID | Requirement |
|---|---|
| RQ-001 | 通关结算之后，玩家请求卷轴状态时，服务器除应答外还发出牌面版式，使客户端摆出可翻的牌而不是关掉卷轴 |
| RQ-002 | 一局的四个牌位各自的内容在该局结算时确定，并在该局存续期间保持不变：重复询问、时间推移或连接中断重来，同一牌位给出同一件东西 |
| RQ-003 | 玩家翻开任意一个牌位时，四个牌位各自的内容在同一次应答中全部揭晓，包括没有东西的牌位 |
| RQ-004 | 一个牌位被翻开之后不能再被翻开；一局之内只有玩家选定的那一次翻开会把东西交给他 |
| RQ-005 | 玩家翻到的装备出现在其背包中，且客户端被告知背包发生了变化 |
| RQ-006 | 玩家每翻到一张有东西的牌，账号金币增加固定的一份 |
| RQ-007 | 付费翻牌按归档的成本表收取金币，价钱由副本自身的基准等级决定而非角色等级；账号金币不足以支付时该次翻牌被拒绝，既不扣费也不发奖 |
| RQ-008 | 一个牌位是否有东西，由归档的三项声明与一次摇点共同决定：副本房间数对应的基础值、难度对应的加成值、队伍人数对应的倍率，以及所用档位声明的阈值。房间数超出归档声明范围时取归档声明的最大一档，因而任何可达副本都不会仅因房间数而整面无物。三者如何合成、摇点如何参与、房间数上限取在何处，归档均未声明，由本服务器决定并具名标明 |
| RQ-009 | 抽出的东西属于哪一稀有度档次，由归档声明的累积门槛与其基数决定；归档声明为可达的每一档都必须真的可达，最高两档不得因摇点范围被静默排除 |
| RQ-010 | 抽出的具体物品来自归档所声明的品级带与装备池，按池中声明的权重选取；品级带按副本自身的基准等级取，不按角色等级；本 Spec 只取装备一类 |
| RQ-011 | 副本自行声明了牌面产出的，按该副本的声明产生内容；未声明的副本落到全局表。**前半句在 A21 上为空真**：声明该项的四个副本均无 `[map specification]`，正常进本路径不可达，故本 Spec 未实现它；后半句成立且有判据 |
| RQ-012 | 结算帧中描述牌面的那一段，其免费牌位的物品与金币、其余牌位、以及付费翻牌的价钱，与本次实际产生的牌面内容及归档声明的价钱一致，不再是零 |
| RQ-013 | 每一处规则数值都能指回归档中声明它的位置；归档未声明而由本服务器决定的值单独具名，并在其所在之处写明它是假设及其理由 |
| RQ-014 | 新增的归档读取点只被规则服务读取；新增的规则服务不持有任何世界状态的读写方 |
| RQ-015 | 既有的全部判据在交付时仍然通过 |
| RQ-016 | 翻空的牌是否给出归档声明的保底物品，由每种牌各自的开关决定；开关关闭时翻空的牌不给出任何东西 |

## Assumptions

- **归档的类别概率一段，其两个位置各代表什么未查明。** 该段落只在翻牌所用的那份档案里
  出现，同族其余各表都没有，因此无从横向对照定序。本 Spec 按「物品满值、金币为零」
  读它，依据是同一份档案缺少把金币命中折算成金额的段落，且与玩家实际体感一致。
  这是推断，不是归档明写。
- **每张翻到的牌固定附带 1 金币，是本服务器的决定，不是归档读数。** 归档说翻牌不出金币，
  也没有算金额的段落。用户在知情后选择仍然发金币并把金额定为固定值，待日后另定规则。
  它必须作为具名假设存在于一处，改动规则时只改那一处。
- **出现概率的合成方式由本服务器决定，归档只给数不给式子。** 归档声明了房间数基础值、
  难度加成、队伍倍率与各档位阈值，但没有任何一处说它们如何相加相乘。参照服务端有一套
  自己的式子，本 Spec 不采用它——它同样是私服实现，且其兜底读法在 5 与 6 个房间之间
  有断崖（走满 5 房 0.60，走满 6 房 1.00）。合成方式作为具名假设集中在一处。
- **分母 10000 有归档旁证。** 类别概率两项相加为 10000、物品类别概率四项相加为 10000、
  基础档位本身即 10000，三处独立指向同一基数。稀有度阶梯则是百万分制，其基数从阶梯
  最后一个数读出而非写死。
- **`[drop prob]` 的六个档位按场合选而非按牌型选。** 档位名为 default / event / event2 /
  pcroom default / pcroom bonus / pcroom event，其中 pcroom 即网吧；客户端结算界面另有
  活动标记与网吧奖励两处资源与之呼应。这六个名字在整份档案中只出现于此一处，无从横向
  对照，故其具体启用条件未查明。本服务器只取 default。
- **付费翻牌请求的形状已由抓包实证**（TASK-13 补证，2026-09-02）。此前记为未实证，
  依据是「客户端的点击构包点把牌型写死为免费，付费走另一个构包点且形状不同」。
  直读上游逐帧日志后该说法不成立：`RECV 0x0047` 共 14 帧**全部两字节**，
  其中 **4 帧为 `[01 00]`**，即牌型 1、牌位 0 的真实客户端付费请求。
  **本 Spec 的读法（两字节：牌型、牌位序号）由此得到一级证据支持。**
  记在这里而不是删掉，是因为「记为未实证」与「没去查」写出来一模一样——
  本 Spec 已在 `[gold card create rate]` 上栽过同一次。
- **翻牌应答中指示内容归属哪个牌位的那个位置，其含义来自寻址结构与取值上界的推断，
  未经实机确认。** 「四张全部揭晓」这一玩法整个压在这个读法上；一次实机即可确认或推翻。
- **归档为黄金牌与网吧牌各给了一张翻空兜底表，两件物品在本服务器都不可用。** 黄金牌那件
  是 2013 年 7 月的活动道具，归档自述于 2013-09-03 统一删除；网吧牌那件是黑钻售货机代币，
  属本服务器未实现的体系。机制保留并由每种牌各自的开关控制，开关默认全关，因而今天翻空
  即是空，不以已删除的活动残留物或未实现体系的代币充数。
- **免费牌没有兜底表。** 归档只为黄金牌与网吧牌各声明一张，免费牌一张也没有。这一不对称
  是归档原样，本 Spec 不为免费牌补一张。
- **网吧牌是归档承认的第三种牌，本 Spec 不实现它。** 归档为它单列了兜底表，客户端也另有
  网吧奖励资源；但翻牌协议的牌型字段只接受免费与付费两个取值，第三种牌不经这条协议翻开。
  它如何送达未查明。
