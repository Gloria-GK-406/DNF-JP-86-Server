# Specification: 决斗场一期——自由房个人战 / 团队战与结算

## Why and Outcome

玩家在 A21 客户端的决斗频道里能像正式服一样开房 PK：进大厅、开房或进房、组好队伍后开局，打完由服务端判胜负并结算，回到房间可以继续打；排位频道（环境 24）的胜负、经验、段位、连胜被记住。服务端的房间状态、对局结算与离场处理必须可靠：写库失败不留半截状态、断线不重复或错误结算、停服不误判负。

设计依据：`Document/tasks/pvp-duel/design-r1.md`（下称 r1；协议布局见 r1 §5 与 `Document/tasks/pvp-duel/research.md` §2，规则见 r1 §7–§8）。范围与排除项以 TaskContract「Scope」为准。

## Definitions

- **房间**：决斗频道（同一监听端口）内的 8 座位房间，有房主、模式、地图、可选密码、阶段。
- **大厅**：同一决斗监听端口上已完成选角、不在任何房间里的在线角色。
- **参战名单**：开局时冻结的非空座位角色集合（一期没有观战者）。
- **对局**：一次从开局到回等待（或取消）的过程，有跨服务器重启唯一的身份。
- **终局**：对局结果（胜方 / 平局 / 取消）已确定且不可再改的时刻。
- **记录频道**：权益表中 `RecordsResult` 为真的决斗频道环境；一期只有 24。
- **游戏日**：仓库现有每日重置规则给出的日期。

## Requirements

### A. 频道与大厅

| ID | Requirement |
|---|---|
| RQ-001 | CMD `0x00C3` 在决斗频道有成功应答（上游布局），非决斗频道按上游失败应答。 |
| RQ-002 | 选角进入决斗频道时，大厅名册与房间快照 NOTI `0x0029` 由房间 owner 提供（包括 `SelectCharacterLifecycleServices` 与 `SessionAdjacentEntryDomainService` 两处读取），反映当前所有已公布房间。`PvpLobbyDomainService` 不再保存房间。 |
| RQ-003 | 大厅增量：建房、成员变化（进房 / 退房 / 被踢 / 换队 / 关开座位）、改模式、改地图、开战、回等待、销毁时，同监听端口大厅里的角色收到相应 `0x0029` / `0x002A` / `0x002B` 与 USER_STATE；任意时刻大厅视图与重新入大厅取得的快照一致。 |

### B. 房间

| ID | Requirement |
|---|---|
| RQ-010 | 建房（CMD `0x0032`）：名称、可选密码（≤8 字节）、地图下标、模式（special=1 的练习房一期拒绝）。成功后房主进入房间、离开城镇区域，房主与大厅收到 r1 §4 a 的帧序。失败回 CMD `00 err`。 |
| RQ-011 | 进房（CMD `0x0033`）：按房间号与可选密码；密码错误、房满、房间不在等待阶段、已在其他房间、在队伍中时拒绝并给错误码；成功分配第一个空座位、离开城镇区域，新人与房内成员收到 r1 §4 a 的帧序（含双方 P2P 端点 NOTI `0x000B`）。 |
| RQ-012 | 座位（CMD `0x0034`）：本人换队；房主踢人；本人退房；房主关闭/开放空座位。只剩一名玩家时至少保留一个可加入空位。房主退房时由下一位成员继任，无人则房间销毁。退房与被踢者回到原城镇落点。 |
| RQ-013 | 模式（CMD `0x0036`）：只接受 1 个人、2 团队，其余被拒；切换时座位按模式重新分队并广播。改地图（CMD `0x003B`）：下标来自 A21 PVF `etc/pvpmapbasicdata.etc` 的 `[pvp map order]`，0 为随机，越界拒绝；无应答，经 `0x002A` 广播。 |
| RQ-014 | 准备（CMD `0x0035`）：非房主切换准备只广播 `0x002C`；房主准备时，若非房主成员全部准备、成员数 ≥2、团队模式两队人数相等则开局，否则按上游错误码拒绝。 |
| RQ-015 | 同一角色任一时刻最多在一个房间；房间与队伍互斥：在队不能建房/进房，在房不能接受组队邀请（组队邀请被拒）。 |

### C. 决斗邀请

| ID | Requirement |
|---|---|
| RQ-020 | 等待阶段房间里的成员可经 REQUEST_PEER（type 2）邀请同监听端口大厅里的角色；被邀请者先收到邀请者 USERINFO 再收到 NOTI `0x0007` type 2。邀请人不在等待房间、目标不在大厅、目标在队或在房、黑名单（任一方拉黑另一方）时拒绝。 |
| RQ-021 | 被邀请者经 RESPONSE_PEER（type 2）接受时，重新校验房间仍在等待、未满、邀请未过期（30s）、双方身份仍为发邀请时的精确会话；通过则按 RQ-011 入房（不发 CMD `0x0033` 成功体），否则回 `0x000B` 拒绝体。type 2 的拒绝不发包、不改状态。 |
| RQ-022 | REQUEST_PEER 与 RESPONSE_PEER 各自仍只由一个协议 CMD 处理，在 CMD 内按 type 分派到组队或决斗能力。 |

### D. 对局阶段

阶段转换表（截止时间均为服务端到点推进）：

| 阶段 | 进入 | 客户端上报 | 截止 | 截止到点 |
|---|---|---|---|---|
| Loading | 开局，发 `0x002D` | `0x012A` | 60s | 整局取消 |
| PeerLinking | 全员 `0x012A` | `0x012B` | 30s | 整局取消 |
| Fighting | 全员 `0x012B`（倒计时由客户端负责） | `0x0037`、`0x0038`、`0x006E` | 战斗兜底 = PVF 时限 + 30s；心跳 30s | 兜底判平；心跳超时按离场 |
| AwaitRank | 终局（非取消） | `0x003A` | 10s | 进入结算 |
| AwaitResult | 结算写库完成 | `0x0039` | 10s | 回 Waiting |
| Waiting | 建房 / 回等待 / 取消 | — | — | — |

| ID | Requirement |
|---|---|
| RQ-030 | 对局按上表推进；不在对应阶段的上报被忽略并记日志，不改变状态。 |
| RQ-031 | 死亡（CMD `0x0037`）：发送者须是参战名单中仍存活的本人；击杀者在本局、存活、为敌方时计击杀，否则只记死亡。广播 `0x002E`。个人模式剩一名存活者、团队模式只剩一队有存活者时终局；全部阵亡判平。终局后广播 `0x0031`。 |
| RQ-032 | 超时（CMD `0x0038`）：只在 Fighting、发送者为参战名单内未逃离者、已过时间不早于 PVF 时限减 5s 时接受第一份合格上报；一期一律判平，不加减经验。长度不是 32 字节的拒收并记日志。 |
| RQ-033 | 终局即冻结胜负（或平局）、每人的逃离标记与结算名单；之后任何离场、上报或超时都不改变它们。 |
| RQ-034 | 结算：全员 `0x003A` 或 AwaitRank 截止后结算一次；每个参战者收到 `0x002F` 再收到 `0x0030`。全员 `0x0039` 或 AwaitResult 截止后房间回 Waiting：清准备与存活状态，房内与大厅收到 `0x002A`（state 1）。 |
| RQ-035 | 结果界面期间离开房间的成员，其座位移除投影按接收者延后：在该接收者发出 `0x0039`、下一局开局、该接收者离房或会话被替换时释放；确认超时不释放；房间销毁时丢弃。迟到的 `0x0039`（当前会话所在房间不在 AwaitResult）被忽略，不作用于下一局。 |

### E. 离场、停服

| ID | Requirement |
|---|---|
| RQ-040 | 断线、回选角（含选角替换）与心跳超时都按"离场"处理：Fighting 中离场记为阵亡、无击杀者、逃离，并可能导致终局；Loading / PeerLinking 中离场整局取消；AwaitRank / AwaitResult 中离场不改结果，只从确认等待中移除；Waiting 中离场按 RQ-012 退房。 |
| RQ-041 | 离场产生的投影只在包含离场的事务提交后交付；外层事务回滚时不发出任何离场投影。会因离场而被结算或通知的其他成员纳入该清理的受影响会话集合。 |
| RQ-042 | 正常停服时，在连接被拆除前：已终局未结算的对局先完成结算；其余未终局对局标为取消，此后的断线清理不判负。进程崩溃时未提交的对局全部丢失，不结算。 |

### F. 战绩与规则

| ID | Requirement |
|---|---|
| RQ-050 | 只有记录频道（环境 24）且模式 1、2、结果为胜/负/平的对局写入战绩；环境 8/13 与取消的对局不改战绩。频道环境到权益的映射由规则服务唯一提供；频道脚本中出现未登记的决斗频道环境时启动失败。 |
| RQ-051 | 经验变化（以 A21 PVF `etc/pvp_ref.etc` 为准）见下方决策表；段位按累计经验与阈值表确定，可一次跨多段；满级段经验不再增长但输仍扣；经验下限 0。 |
| RQ-052 | 每日计数：同一角色在同一游戏日（按开局时）第 1–50 胜计经验，第 51 胜起经验 0；第 1–10 负计扣减，第 11 负起经验 0；胜负场与连胜照记。逃离计为负场。 |
| RQ-053 | 连胜：胜 +1、负或平清零；记录历史最高连胜。 |
| RQ-054 | 同一对局只结算一次：重复结算返回已存结果、不重写、不重发结算事件，且跨服务器重启成立。结算事件只在首次结算时发布。 |
| RQ-055 | 选角进入任意频道时客户端收到自己的 `0x0030` 战绩包（经验条不为 0/0）；USERINFO 中的段位字节与战绩来自同一来源。 |

| 情形 | 经验变化 |
|---|---|
| 胜，当日第 ≤50 胜，段位 0 | 升到 1 段下限 |
| 胜，当日第 ≤50 胜，段位 1..满级−1 | +W |
| 胜，满级段 | 0 |
| 胜，当日第 ≥51 胜 | 0 |
| 负（含逃离），当日第 ≤10 负 | +L（不低于 0），满级段同样扣 |
| 负，当日第 ≥11 负 | 0 |
| 平 | 0 |

### H. 架构不变量
