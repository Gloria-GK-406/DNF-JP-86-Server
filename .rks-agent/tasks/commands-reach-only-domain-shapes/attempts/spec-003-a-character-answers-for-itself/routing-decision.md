# Routing Decision

- TaskContract: `./TaskContract.md`
- Contract revision: `1`

## SDD Readiness

- Intent and outcome stability: 目标是一句可判定的话——角色自己的数由角色实例现读现算，升级
  之后报出的剩余 SP 是新等级的值。范围已对着代码收窄：只动与角色自身相关的三个数，会话里
  坐标、世界内容、背包投影等其余部分不动。
- Requirement stability: 要求可枚举。剩余 SP 的三个输入各自的取数点已定位（角色行的等级与
  职业成长类型、技能表的已学技能、入场表的加成、规则服务的 `SkillPointsAsync`）；四个发经验
  帧的位置已定位；入场镜像的读取点可枚举。
- Execution direction: 已知。算法本身已存在于入场准备里，是一个纯函数式的投影；要决定的是
  它换个位置之后由谁持有那些输入。
- Remaining uncertainty: 只剩非语义的局部选择——计算落在角色实例自身还是一个它委托的领域
  服务、实例读等级是走角色表还是走已有的经验领域服务。两者都不改变本成果的含义。

## Marginal Control Value

- User precision signal: 偏精度；要求跑完再汇报，执行期间无人工检查点。
- Direct failure mode: 三个。其一，**这一批带可观察行为变化，因此「判据全绿」不再等于「没改
  坏」**——前两批可以拿 2007 这个数字当护栏，这一批不能，改动的期望值必须逐条能对应到那一处
  被授权的行为变化，否则就是夹带。其二，剩余 SP 是从三处输入现算的，任何一处取错都会得到一个
  看起来合理的数字：档案的 SP 表按等级累加、加成来自数据库、花费要遍历已学技能乘成本表——
  取错的后果是玩家的技能点凭空多出或少掉一截，而没有任何判据天然会红。其三，这个仓库已经
  因为「拿入场快照来加」吃过一次亏（一个任务交两次写了同一个总额两次），同一个陷阱换个字段
  就会重演。
- Useful control: 一份 Plan 把「先定输入归属再动取数点」的顺序固定下来；加上一条专门的成功
  条件（C-3）要求那条判据在实现被改坏时会失败，而不只是在实现正确时通过。
- Time-for-quality rationale: 值得。这是三批里唯一改变可观察行为的一批，也是所有者实机报告
  的那个缺陷的正题；它错了不是结构不好看，是玩家的技能点是错的。

## Structural Selection

- Selected workflow: `single-spec-workflow`
- Boundary evidence: 一个验收口径——角色自己的数由实例现算，且只有剩余 SP 那一处可观察变化。
  三个数共享同一个取数来源的归位动作，拆开做会留下「一半从实例问、一半从镜像读」的中间态，
  那比现状更难说清。
- Why Direct is insufficient: Direct 给不出「改动的期望值逐条对应到被授权的行为变化」这个
  核对，而这一批恰恰失去了「数字不变」这道护栏。
- Reroute conditions: 若发现剩余 SP 的某个输入无法在不重排入场准备的前提下取到，说明这三个
  数的归位牵动了会话聚合的其余部分，本成果的边界被证伪，应退回根控制器重划而不是在成果内
  扩张到整个聚合。

## Controller Selection

- Controller: `sdd-standard`
- Profile source: `code-refactor`
- Why this is sufficient: 有一处真实的耦合值得 Plan 先行裁决——**剩余 SP 的计算换位置之后由谁
  持有它的三个输入**。角色实例若自己注入三张表，它就从「问什么答什么」变成了一个装配器；若
  委托给一个领域服务，则要决定那个服务与入场准备里现有的同一段投影如何共存，否则同一个算法
  会有两份实现，而两份实现迟早分叉——这正是本轮要消灭的那类毛病。这个决定影响后面每一个取数
  点怎么改，先定再动省下的是返工，而返工发生在最终评审看不见的地方。ordinary review 加新鲜
  验证足以保护其余部分。
- Why lighter is insufficient: Lite 没有 `plan.md`，上面那个归属决定只能在实现中临场定；定错
  的代价是同一个 SP 算法出现两份。
- Why heavier is unnecessary: Governed 的独立挑战与审计强度证据挂不到高后果失败路径上。这是
  单机开发中的服务端内部重构：不碰安全、凭据、授权、隐私、财务、法务，无不可逆的外部变更，
  无持久数据丢失路径（剩余 SP 根本不落库，它是算出来的），全部工作在一条本地分支上可整体
  回滚。它的失败模式是「算错一个数」，而那由 C-3 那条会红的判据加完整变更评审来防。
