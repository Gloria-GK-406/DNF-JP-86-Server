# TaskContract: 分离普通地下城与任务关联剧情地下城

## Context

### Source Request

用户先确认“普通地下城逻辑和剧情地下城完成不一样”，要求判断应局部切分还是整体切分；在接受“共享运行机制、切分入口与完成策略”的结论后，授权：“可以，你来处理吧。就按这个方式来切和重构。”用户同时要求避免角色持有相同任务时，把一次普通地下城选择错误路由到剧情地下城。

### Current Situation

当前 `SELECT_DUNGEON` 的已知请求字段没有普通/剧情标志，布局规则虽然接收活动与已完成任务事实，却忽略它们并随机选择所有 maze。运行态只保存布局与难度，不保存本次运行是普通路线还是任务关联路线；击杀、通关、结算和退出因而统一按普通地下城处理。实机已观察到任务 1776 的剧情 maze 偶然被选中后，击杀目标未推进，结算仍声明非任务 maze；手动退出只结束服务端运行态而未回城，造成客户端仍在副本而服务端已无运行的状态分裂。

## Goal

建立显式且可追溯的地下城进入意图和运行目的，使普通地下城与任务关联剧情地下城共享房间、移动、怪物、掉落及运行存储机制，同时各自执行正确的 maze 选择、准入、目标推进、完成与结算规则；持有任务本身不得把普通进入意图升级为剧情进入。任务完成必须按 PVF 的固定、职业条件和可选奖励语义只结算本角色应得内容，不能把奖励数据压成裸整数后整表发放。

## Scope

### In

- 解析并建模 dungeon/maze 的任务连接元数据及选择条件。
- 从可证实的客户端请求或前置选择状态中解析本次进入意图；任务状态只作为剧情路线资格，不作为进入意图。
- 让入口计划与运行态冻结普通或任务关联的运行目的，以及任务关联所需的任务标识和状态。
- 分离普通与任务关联路线的入口、完成和结算规则，同时复用共同的副本运行机制与协议处理外壳。
- 将可信、去重后的怪物死亡事实接入匹配的任务目标推进，覆盖任务 1776 的指定怪物目标而不污染无关普通副本。
- 修复所有适用运行模式共用的手动退出与回城状态收口。
- 结构化投影任务完成的固定奖励、职业/成长类型条件、可选奖励及金币标记；任务完成时使用角色当前镜像和客户端选择生成唯一奖励计划，并与任务状态、背包、金币和经验原子结算。
- 补充对应的内容解析、领域规则、协议处理和回归测试，并更新受本次已证实行为影响的 Markdown 文档。

### Out

- 实现循环地下城、特殊塔类、深渊或其他特殊副本家族。
- 用队伍目录的 `PartyCategory` 直接定义单人或实际副本运行类型。
- 复制完整的普通/剧情 Handler、运行存储、房间移动、怪物或掉落子系统。
- 猜测尚未取得证据的请求尾部字段、剧情奖励卡规则或客户端展示语义。
- 删除或补偿本次实机已经错误发放到角色背包中的历史装备。
- 合并、推送、发布或清理工作区。

## Constraints

- 同一 `DungeonId` 可同时包含普通和任务关联 maze，运行目的必须来自本次显式选择及实际命中的连接，不能按 dungeon id 静态分类。
- 活动或已完成任务仅决定任务关联 maze 是否可用；没有显式剧情进入意图时必须选择无任务连接的普通 maze，或明确拒绝，不能静默升级到剧情路线。
- 副本运行目的必须属于副本领域，不能由连接 session 或队伍目录类别替代。
- 普通怪物/AI 目标必须先通过当前运行、当前房间和 actor 身份校验及去重，才可形成服务端任务推进事实；PVF 声明为被动对象的剧情目标只能接受绑定同一 QuestLinked 运行、任务、地下城、难度和 trigger 通道的客户端报告。
- 无充分证据确定剧情进入意图或剧情结算差异时，必须保留未知并停止相应行为扩张，不得用任务存在性或旧服务端默认值填补。
- `[reward int data]` 的固定/职业条件奖励与 `[reward selection int data]` 的玩家选择奖励必须保持分离；完成流程不得依赖连接 session 的角色职业快照，也不得忽略客户端已经解析出的选择字段。

## Success Conditions

| ID | Observable condition | Required evidence |
|---|---|---|
| SC-1 | 角色持有与目标地下城关联的活动任务时，显式普通进入仍稳定选择无任务连接的普通 maze，不产生任务关联运行。 | 覆盖同一 dungeon、同一任务状态下普通与剧情两种进入意图的入口规则测试，以及可追溯的进入意图证据。 |
| SC-2 | 显式剧情进入只在对应活动/已完成任务及难度条件匹配时选择连接 maze，并把连接任务与运行目的冻结到该次运行。 | dungeon 144/任务 1776 内容解析测试、选择测试和运行态断言。 |
| SC-3 | 普通与任务关联运行通过不同的完成/结算决策，任务 maze 的下行结算不再被硬编码为普通 maze；普通路线的现有结算行为不回归。 | 两类完成与结算的协议/领域测试；对未知剧情奖励表现保持证据边界。 |
| SC-4 | 服务端计数的普通怪物目标只由可信死亡推进；任务 1776 的被动对象目标只在对应 QuestLinked 运行中接受其声明通道并由 1 到 0，错误任务、副本、难度、通道或普通运行不推进。 | 任务目标类型解析、canonical kill 与绑定运行的客户端 trigger 集成测试，包含正例和拒绝/幂等反例。 |
| SC-5 | 手动退出不会留下“客户端在副本、服务端无运行”的分裂状态，并复用公共回城投影。 | GiveUp 处理测试验证结束运行和完整回城帧；普通与任务关联运行均覆盖。 |
| SC-6 | 生产实现没有建立两套重复的协议 Handler 或房间/怪物/掉落运行机制，且应用层仍不引用基础设施层。 | 完整变更审查、分层测试及解决方案构建通过。 |
| SC-7 | A21 实机中，普通进入与任务 1776 剧情进入可被区分；剧情击杀完成任务，手动退出或完成退出后仍可正常回城和再次进入。 | 当前客户端的双路径帧/服务端日志与用户实机确认；若客户端未提供可证实的区分信号，则如实报告阻塞而不降级为启发式路由。 |
| SC-8 | 任务完成只发放角色按当前 job/growType 匹配的固定奖励，并对真正的可选奖励严格执行选择存在性和范围校验；任务 1776 的 job=0/growType=0 角色只获得 `101010437 x1`，不会再次整表发放。 | 真实 PVF 1776 投影与完成测试、合成可选奖励矩阵、金币投影和失败原子回滚测试；既有错误装备不作为验证对象。 |

## Assumptions

- A21 客户端在 `0x000F`、`0x0010` 尚未解释的字段、队伍 Story 目标或相邻状态中提供可证实的进入意图；调查可以选择具体承载方式，但不得用任务存在性替代该证据。
