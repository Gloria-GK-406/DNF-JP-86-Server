# Specification: 普通与任务关联地下城运行模式分离

## Why and Outcome

同一个 dungeon 可以包含普通 maze、活动任务 maze 和任务完成后的 maze。服务器必须先理解玩家本次进入的意图，再用任务状态判断该意图是否有资格命中某个 maze；不能把“持有任务”误当成“选择剧情”。一次运行开始后，其运行目的必须被冻结并驱动目标推进、完成和结算，而房间移动、actor 身份、死亡去重、掉落及公共退出继续复用同一运行机制。

## Definitions

- **进入意图**：由可验证的客户端请求、进入前选择状态或队伍模式上下文表达的本次选择。至少区分普通与任务关联；任务列表不是进入意图。
- **任务连接**：PVF 在 dungeon 或 maze 上声明的 `[quest connection]`，包含连接类型、任务 ID 及可选难度条件。
- **运行目的**：本次实际选择结果。普通目的不带任务；任务关联目的必须带连接任务、连接状态和选中 maze。
- **资格**：活动任务、已完成任务、难度等决定某条任务连接能否使用。资格不能自行产生剧情进入意图。
- **可信击杀事实**：当前运行、当前房间中已解析 actor 的第一次有效死亡；重复报告和无法识别的 actor 不产生该事实。

## Scope

包括 dungeon/maze 任务连接内容投影、进入意图证据、maze 选择与运行目的、任务目标推进、普通/任务关联完成和结算分流、公共 GiveUp 回城，以及自动化和 A21 实机回归。循环、深渊、塔类等特殊家族不在本规格内；队伍 `PartyCategory` 只能提供经过验证的进入上下文，不能替代副本运行目的。

## Requirements

| ID | Requirement |
|---|---|
| RQ-001 | 服务器必须从已证实的请求或前置选择状态取得进入意图；若证据不足，不得根据持有任务推断剧情意图。 |
| RQ-002 | 内容模型必须保留 dungeon/maze 的任务连接，并能区分无连接、活动任务连接和已完成任务连接及其难度条件。 |
| RQ-003 | maze 选择必须先按进入意图分区，再按资格过滤：普通意图只可选择无任务连接的 maze；任务关联意图只可选择匹配的连接 maze。 |
| RQ-004 | 任务关联意图没有合格连接时必须拒绝或返回不可进入结果，不能回落到普通 maze；普通意图也不能升级到任务 maze。 |
| RQ-005 | 入口结果必须同时携带布局与运行目的，运行开始后保存该目的；后续不得重新读取变化后的任务状态来改变本次运行性质。 |
| RQ-006 | 普通与任务关联运行复用同一运行存储、房间、移动、actor、死亡去重和掉落实现，差异通过入口、完成与结算规则表达。 |
| RQ-007 | enemy type 1/2 的怪物或 AI 目标必须由可信 actor 死亡按 dungeon、difficulty、enemy code、enemy type 和数量推进；无关或重复事实不得推进。 |
| RQ-008 | enemy type 3 的被动对象目标由客户端 trigger 通道报告；仅当当前运行冻结为同一活动任务的 QuestLinked、目标 dungeon/difficulty 与通道均匹配时才可推进。任务 1776 的 `0x10` decrement 必须由 trigger 1 到 0，普通运行或任意不匹配报告必须拒绝。 |
| RQ-009 | 普通完成规则保持现有普通结算语义；任务关联完成规则必须识别关联任务/maze 条件，并在 `PLAY_RESULT` 中投影任务 maze 身份。没有证据的卡牌或剧情展示差异不得猜测。 |
| RQ-010 | GiveUp 必须通过所有适用运行模式共用的退出服务结束运行并发送完整回城投影，不得形成客户端仍在副本而服务端已删除运行的状态。 |
| RQ-011 | 协议 Handler 只负责解码、调用业务命令/领域服务和发送结果，不复制普通与剧情两套业务流程；Application 不得引用 Infrastructure。 |
| RQ-012 | 日志必须能识别进入意图、选中 maze、运行目的和任务连接，足以区分“普通选择”“剧情选择”“资格拒绝”和“无证据信号”。 |
| RQ-013 | 任务内容投影必须区分固定奖励、带 job/growType 条件的固定奖励、玩家可选奖励和金币标记，不得用丢失标记的裸整数列表承载 item 奖励。 |
| RQ-014 | 任务完成必须读取角色当前持久化身份并按 job/growType 过滤固定奖励；不得依赖 session 快照，且无条件固定奖励与所有匹配条件奖励按声明顺序保留。 |
| RQ-015 | `FINISH_QUEST` 已解析的 rewardSelection 与 completionCount 必须进入业务命令。没有可选奖励时只接受 `0xFFFF`；存在可选奖励时必须从按角色过滤后的候选中选择恰好一项，缺失或越界均拒绝。 |
| RQ-016 | 金币公式标记必须作为金币奖励语义处理并通过角色金币领域入口发放，不能丢弃、当作普通道具或占用错误协议字段。 |
| RQ-017 | 奖励计划校验、任务完成、道具、金币和经验必须作为一次原子完成；任何后置发放失败不得留下已完成任务或部分奖励。 |

## Acceptance Criteria

| ID | Covers | Criterion |
|---|---|---|
| AC-001 | RQ-001, RQ-003 | Given 角色活动任务包含 1776，when 进入意图为普通且目标 dungeon 为 144，then 只从无连接 maze 中选择，并创建普通运行。 |
| AC-002 | RQ-001, RQ-002, RQ-003, RQ-005 | Given 可验证的任务关联意图、活动任务 1776 和满足难度的连接，when 选择 dungeon 144，then 选择连接 1776 的 maze 并冻结任务关联运行目的。 |
| AC-003 | RQ-003, RQ-004 | Given 普通意图但 dungeon 只有连接 maze，或任务关联意图却没有合格连接，when 解析入口，then 明确拒绝且不创建运行。 |
| AC-004 | RQ-002, RQ-003 | Given 多个活动/已完成连接，when 选择 maze，then 活动连接、已完成连接和普通候选按各自语义过滤；随机种子只在同一合格候选集合内选择。 |
| AC-005 | RQ-005, RQ-006 | Given 运行开始后任务日志变化，when 移动、击杀或结算，then 运行目的和选中 maze 不变化，公共房间与 actor 机制仍工作。 |
| AC-006 | RQ-007, RQ-008 | Given 服务端计数 monster target，when 第一次可信死亡匹配，then 对应通道只推进一次；Given 任务 1776 trigger=1 且当前为其 144/maze1 QuestLinked 运行，when 客户端报告 `selector=0x10 decrement`，then trigger=0；相同报告在普通运行、错误任务/dungeon/difficulty/channel 下拒绝。 |
| AC-007 | RQ-009 | Given 普通运行，when 通关，then `PLAY_RESULT.questMaze=0` 且既有普通结算测试保持通过；Given 任务关联运行，then 任务完成判据由对应规则处理且 `questMaze=1`。 |
| AC-008 | RQ-009 | Given 尚无 A21 证据证明任务 maze 是否跳过卡牌或使用不同退出序列，when 构造结算，then只改变已确认字段与规则，其他投影保持明确共享而非伪造差异。 |
| AC-009 | RQ-010 | Given 普通或任务关联运行，when 收到 GiveUp，then 运行结束且同一响应批次包含成功确认和公共城镇状态投影；后续可重新打开选择并进入。 |
| AC-010 | RQ-011, RQ-012 | 完整变更不新增重复普通/剧情 Handler 或第二套运行存储，分层约束通过，日志和代码审查可追踪本次进入的意图与目的。 |
| AC-011 | RQ-001, RQ-012 | A21 双路径验证必须证明普通和剧情选择的输入区别；若当前客户端没有可证实区别，规格以“阻塞且不启用启发式剧情路由”结束，而不是将任务状态当意图。 |
| AC-012 | RQ-013, RQ-014 | Given 真实 PVF 任务 1776 和 job=0/growType=0 角色，when 无选择完成任务，then 奖励计划及实际发放均只有 `101010437 x1`，其他职业装备不进入背包。 |
| AC-013 | RQ-013, RQ-015 | Given 含固定与可选奖励的任务，when 提交有效选择，then 发放全部匹配固定奖励及恰好一个匹配候选；缺失、越界、禁止的选择均拒绝且无写入。 |
| AC-014 | RQ-014, RQ-015 | Given 相同 itemId 面向多个职业规则，when 当前角色只匹配其中一条，then 只生成一个 grant；客户端索引以过滤后的可选候选列表为准。 |
| AC-015 | RQ-016 | Given item 奖励中的金币公式标记或固定金币，when 完成任务，then 通过角色金币入口结算实际增加量，并以 ItemId=0 的奖励条目通知客户端。 |
| AC-016 | RQ-017 | Given 背包不足、未知道具、角色消失或经验/金币写入失败，when 完成任务，then任务日志、背包、金币和经验均保持完成前状态，客户端收到拒绝。 |

## Success Evidence

- **EV-001（AC-001..AC-005）**：内容解析、入口决策和运行冻结的单元/集成测试，固定使用 dungeon 144 与任务 1776 样例并包含普通反例。
- **EV-002（AC-006）**：任务目标类型解析、MonsterDeath 到 QuestLog 的服务端计数测试，以及绑定 QuestLinked 运行的被动对象 trigger 测试，覆盖匹配、去重及关键拒绝条件。
- **EV-003（AC-007..AC-009）**：普通/任务关联结算编码测试和两种运行的 GiveUp 回城帧测试。
- **EV-004（AC-010）**：解决方案构建、相关测试项目、分层测试和完整结果审查。
- **EV-005（AC-011）**：当前 A21 客户端普通/剧情两条路径的请求字节、前置状态与服务端判定日志，以及任务完成和退出后的用户实机确认。
- **EV-006（AC-012..AC-016）**：真实 PVF 1776 内容/完成集成测试、合成固定/职业/选择奖励决策表、金币协议投影测试、失败注入与事务回滚测试。
