# 实施计划：普通与任务关联地下城运行模式分离

## 规划选择

采用直接详细计划。变更跨越内容投影、入口上下文、运行态、任务推进和退出投影，但共同服从一个不可拆分的验收边界：同一次进入必须从可验证意图一路追踪到冻结的运行目的，并保证普通流程不被任务状态污染。拆成独立 Task Unit 会制造中间不可运行的接口状态，不能提升独立交付价值。

## 方法与共享决策

- `0x0010 SELECT_DUNGEON` 仍是普通与定向进入共用的最终指令；`0x000F ENTER_SELECT_DUNGEON` 建立按角色保存、写新覆盖、消费即删的一次性选择上下文。
- 已确认的 `0x000F=0` 建模为交互式普通选择；`0x000F=dungeonId` 建模为定向选择。任务状态只在定向选择中验证任务连接资格，不能把普通选择升级为任务关联运行。
- PVF 的 `[quest connection]` 投影为明确内容值，保留活动连接、完成连接、任务 ID 和最低难度。maze 自身连接优先；dungeon 级连接作为该 dungeon 下 maze 的默认连接。
- 布局规则返回“布局 + 运行目的”的入口决策。运行目的使用类型化值表达普通或任务关联，并在 `DungeonRunState` 创建时冻结；不使用 `PartyCategory`，也不把网络 session 带入领域服务。
- 房间移动、actor、死亡去重、掉落和运行存储保持共享。任务目标推进只接收已通过运行/房间/actor/首次死亡验证的击杀事实。
- 完成与结算使用按运行目的分派的规则；本次仅改变有 A21 协议证据的任务 maze 身份和任务条件，卡牌、奖励展示及未知尾字段继续显式共享。
- GiveUp 结束运行后走既有公共城镇投影，保持普通与任务关联运行一致。

## 工作与依赖

### T-001 — 投影任务连接和击杀目标内容（RQ-002、RQ-007）

1. 扩展 dungeon/maze 内容模型，加入任务连接值对象和连接状态；更新 `PvfDungeonDefinitionSource` 解析 dungeon 与 maze 范围内的 `[quest connection]`。
2. 扩展任务定义的服务端击杀目标投影，按五元组保留 dungeon、difficulty、enemy code、enemy type、count，不改变客户端权限分类。
3. 先添加解析回归测试：固定验证 dungeon 144 的任务 1776 连接，以及任务 1776 的 `144/-1/13099/3/1` 目标；同时覆盖无连接和格式不完整内容。

依赖：无。该包先完成，供后续入口和任务规则使用。

### T-002 — 建立一次性入口意图（RQ-001、RQ-004、RQ-011、RQ-012）

1. 在 Abstractions/Application 增加角色范围的地下城选择上下文存储，不依赖 transport session；定义普通浏览、定向目标和无有效上下文结果。
2. `EnterSelectDungeonHandler` 记录 `0x000F` 表达的上下文；`SelectDungeonHandler` 原子消费，并校验定向目标与 `0x0010` dungeon 一致。
3. 缺失、已消费、错配或无法解释的上下文明确拒绝进入，不根据活动任务兜底；日志记录 intent、requested dungeon 和拒绝原因。
4. 测试覆盖普通 `0`、定向相同 ID、错配 ID、重复消费和覆盖旧选择。

依赖：无；与 T-001 可在代码顺序上独立，但 T-003 同时依赖二者。

### T-003 — 按意图选择布局并冻结运行目的（RQ-003..RQ-006、RQ-012）

1. 将布局规则输出改为入口决策，包含选中布局与类型化运行目的。
2. 普通意图只建立无连接候选；定向意图在活动/完成任务集合与难度条件中匹配连接。存在连接但没有合格项时拒绝；完全无连接的定向教学入口仍建立普通运行。
3. seed 只在当前合格候选集合中参与稳定选择，不跨普通、活动连接和完成连接集合。
4. 修改 visit/run 创建链，将运行目的存入 `DungeonRunState`；后续任务日志变化不得改写它。
5. 以 dungeon 144/quest 1776 建立入口回归矩阵，并保留普通布局、移动、actor 和掉落既有测试。

依赖：T-001、T-002。

### T-004 — 从可信击杀事实推进服务端任务（RQ-006..RQ-008）

1. 在任务领域接口中增加窄化的 monster-killed 事实入口；任务规则只扫描活动任务和已投影的 hunt-enemy 目标。
2. 将 `MonsterDeathHandler` 已完成的当前运行、当前房间、actor 解析和首次死亡验证结果传入任务推进；不接受客户端 trigger 作为权威写入。
3. 按 dungeon、difficulty（`-1` 为任意）、enemy code、enemy type 匹配并对 trigger 做边界安全递减，持久化后发送现有任务同步投影。
4. 测试 quest 1776 从 1 到 0，以及相同 actor 重放、错误 actor/dungeon/difficulty/type、非活动任务均不推进。普通运行中匹配的服务器任务也可推进，避免把目标事实错误限制为“剧情模式专属”。

依赖：T-001、T-003。

### T-005 — 分离完成/结算规则并投影任务 maze（RQ-005、RQ-006、RQ-009）

1. 将完成判定和结算元数据从通用 handler 的硬编码提取为按运行目的分派的规则服务；普通规则保持现状。
2. 任务关联规则校验冻结的任务连接与本局布局/任务目标条件，并将 `PLAY_RESULT.questMaze` 投影为 `1`；普通运行保持 `0`。
3. 未获证据支持的卡牌、展示、奖励或退出序列继续使用共享投影，并在代码和任务结果中记录该边界。
4. 编码和 handler 测试同时覆盖两种目的，确认普通现有结算没有回归。

依赖：T-003；任务条件测试依赖 T-004。

### T-006 — 统一 GiveUp 回城（RQ-010、RQ-011）

1. 让 GiveUp 在结束运行后调用既有 `TownReturnProjection` 所需的应用服务和角色状态来源，返回确认帧及完整城镇状态投影。
2. 不在普通/剧情 handler 中复制退出流程；运行不存在或重复 GiveUp 保持明确、可测试结果。
3. 测试普通与任务关联运行均在同一响应序列中结束运行并投影城镇状态，随后可重新建立选择上下文与运行。

依赖：T-003。

### T-007 — 集成、日志与静态回归（RQ-011、RQ-012）

1. 更新依赖注入与测试替身，修复所有受签名变化影响的调用；确认 Application 不引用 Infrastructure。
2. 统一入口和运行日志字段：character、intent、requested dungeon、maze、purpose、quest connection、拒绝原因。
3. 运行受影响项目测试、架构测试和解决方案 Release 构建；检查普通地下城、任务日志、掉落和城镇返回既有回归。

依赖：T-001..T-006。

### T-008 — A21 双路径实机验证（RQ-001、RQ-008..RQ-012）

1. 使用隔离工作树 Release Host 和相同 PVF，记录普通选图与任务定向进入的 `0x000F/0x0010` 字节及服务端判定日志。
2. 普通路径在持有 1776 时必须建立普通运行；任务路径必须建立关联 1776 的运行，击杀目标后 trigger 变为 0 且 `questMaze=1`。
3. 分别验证正常通关和 GiveUp 后能够回城、重新选图和过图。
4. 若任务 1776 客户端没有已确认的定向输入区别，保留安全拒绝并记录阻塞证据；不得启用“持有任务即剧情”的启发式。

依赖：T-007；需要用户执行客户端操作。

### T-009 — 结构化任务奖励并原子结算（RQ-013..RQ-017）

1. 将任务 item 奖励从裸整数 operands 改为明确的固定规则、job/growType 条件、可选规则和金币标记；基础设施解析器保留 `[job]` 与 `[reward selection int data]` 的边界，对畸形声明 fail closed。
2. 增加纯奖励规则服务，以任务定义、角色当前持久化身份、rewardSelection 和 completionCount 生成不可变奖励计划；固定项按角色过滤，可选项先过滤后索引。
3. 将 `FinishQuestRequest` 已解析字段完整传给 transactional CMD；在任何任务日志或库存写入前完成计划校验，并让任务、物品、金币、经验的失败通过事务回滚统一收口为拒绝。
4. 金币通过角色领域入口结算，成功响应以 ItemId=0 的奖励条目投影实际增加量；不占用 completionCount/reserved 字段。
5. 以真实 PVF 1776 建立 RED/GREEN 回归，证明 job=0/growType=0 只发 `101010437 x1`；补固定+可选、缺失/越界/禁止选择、重复 itemId 职业规则、金币和失败回滚矩阵。

依赖：T-007；实机发现的奖励错误属于完成链路同一验收边界。明确不删除本次已经错误生成的物品。

## 验证

- 内容测试证明 dungeon 144/quest 1776 的连接和目标没有在 PVF 投影中丢失。
- 入口决策测试使用同一角色、同一活动任务和同一 dungeon，对普通与定向上下文给出不同且稳定的结果，并覆盖所有拒绝方向。
- 运行测试证明目的冻结、公共机制复用和普通行为不变。
- 任务推进测试从 canonical kill 事实验证一次性、条件完整和持久化结果。
- 协议投影测试验证 `PLAY_RESULT.questMaze` 的 `0/1`，GiveUp 集成测试验证完整回城帧。
- 最终执行受影响测试、全解决方案测试或等价全量门、Release 构建和架构约束，再由独立审查者按 Spec/Plan/Diagnosis 审查完整 diff。
- 实机证据作为 AC-011 的最终门；若需要用户操作，只有在服务端和观察点准备完成后才暂停请求输入。
