# Specification: 固定队伍共享剧情地下城首发入场

## Why and Outcome

玩家在城镇已组成队伍后，应由队长一次选择剧情地下城并把当时在线的固定成员共同带入同一局。服务端必须把“副本世界事实”与“每个角色自己的收益和连接”分开：布局、房间、怪物死亡、清图和地面掉落属于共享局；任务进度、经验、结算、翻牌和投递连接属于参与者。这样两端看到的是同一个副本，而不会因重复上报得到重复收益或互相覆盖角色状态。

## Scope and Definitions

- **共享局**：一次入场冻结的副本标识、布局、难度、起始时间、当前房间版本、已访问房间、死亡怪物、地面掉落和清图事实。
- **参与者**：冻结成员中的一个角色，持有自己的角色标识、入场槽位、当前连接投递目标、任务/经验/结算/翻牌状态。
- **固定队伍**：入场成功后，当前局成员不再随 PartyService 的创建、退队、转移队长或解散而变化。
- 首版覆盖普通剧情地下城首发入场；中途加入、断线重连及特殊内容入口不在本规格内。

## Requirements

| ID | Requirement |
|---|---|
| RQ-001 | 队伍入场必须先以 PartySnapshot 冻结队长、成员顺序和成员身份，并在任何角色状态改变前验证发起者是队长、所有冻结成员均在线且当前连接可附着。验证失败时任何成员都不得进入新局。 |
| RQ-002 | 队长的剧情地下城选择继续由队长当前有效主线任务决定；没有相同任务的队员可以随队进入，但只对自己的匹配活动任务产生 Trigger。显式选择普通地下城时仍走普通模式，不得因任一成员持有剧情任务而改路由。 |
| RQ-003 | 一次成功的队伍入场只创建一个共享局标识，所有冻结成员以独立参与者身份附着到该共享局。Session 仅决定当前通知投递和连接代际，不进入共享局身份或业务键。 |
| RQ-004 | 首发入场投递必须使每个参与者客户端完成进入选择状态、副本信息和起始房间投影；任一投递前置条件失败不得留下只注册了一部分成员的领域状态。协议编排应与共享局领域操作分离，以便实机证据校正发送顺序。 |
| RQ-005 | 首版房间推进由冻结队长发起；一次合法推进原子更新共享局的当前房间与房间版本，并向所有仍持有入场连接的参与者投递同一房间。来自队员或对旧房间版本的推进不得产生第二次状态变化。 |
| RQ-006 | 怪物死亡声明、清图判断、怪物掉落分配和地面拾取以共享局及房间版本为键。相同死亡或拾取由任意成员重复或并发上报时只能有一次成功的共享副本效果。 |
| RQ-007 | 一次被接受的怪物死亡应以同一共享事实为依据，为每个符合条件的参与者分别计算经验和匹配任务 Trigger；一个参与者的失败或没有任务不得制造第二个共享死亡，也不得把另一参与者的角色收益写到自己名下。可重试的持久化失败必须保留不会重复共享掉落的明确边界。 |
| RQ-008 | Boss 清图是共享事实；结果屏幕、通关经验、任务完成资格、奖励卡集合和卡片领取按参与者独立记录并至多一次。一个成员的结算或离场不得提前结束其他成员的参与者状态；最后一个参与者离场后才释放共享局。 |
| RQ-009 | 单人入场使用同一共享局模型的一人特例，保持现有单人普通地下城、单人剧情地下城、死亡幂等、掉落、结算与离场协议行为。 |
| RQ-010 | 不实现或发出 `ENTRY_INTO_PARTY`、`ENTRY_INTO_PARTY_FINISH` 等中途加入协议；发现入场后连接失效时只按首版退出/回城边界收口，不尝试恢复或替换连接。 |

## Acceptance Criteria

| ID | Covers | Criterion |
|---|---|---|
| AC-001 | RQ-001, RQ-003 | Given 两名可附着在线角色组成队伍，When 队长发起剧情地下城，Then 两个角色的查询结果具有同一共享局标识、同一冻结成员顺序和各自参与者身份；Given 非队长发起或一个成员不可附着，Then 返回明确拒绝且两个角色都不在新局中。 |
| AC-002 | RQ-002, RQ-009 | Given 队长持有已验证剧情任务而队员不持有，When 队长进入剧情地下城，Then 使用队长任务绑定布局且队员可进入但不推进该任务；Given 同一角色显式进入普通地下城，Then 使用普通选择策略。 |
| AC-003 | RQ-004 | Given 已通过原子入场验证，When 应用层提交队伍入场，Then 每个成员收到可识别的进入选择、选择成功、副本信息和同一起始房间投影；协议构建失败或成员连接代际改变时，不产生部分提交的共享局。 |
| AC-004 | RQ-005 | Given 两人位于同一共享房间版本，When 队长请求合法相邻房间，Then 共享局只推进一次且两端收到同一新房间；When 队员或旧版本重复请求相同移动，Then 共享状态不再推进。 |
| AC-005 | RQ-006, RQ-007 | Given 两端对同一 actor sequence 报告死亡，When 命令并发或重复执行，Then 共享死亡、掉落分配和清图变化只提交一次，而两个符合条件的参与者各自获得一次经验和各自匹配的 Trigger。 |
| AC-006 | RQ-006 | Given 一个共享地面掉落，When 两名成员先后或并发拾取同一编号，Then 只有一个角色获得物品，后续请求不改变任何背包或共享地面状态。 |
| AC-007 | RQ-008 | Given Boss 房已共享清图，When 两名成员分别上报结果、领取卡片并离场，包括重复上报，Then 每人的通关经验、任务奖励、卡片和领取声明均独立且至多一次；第一人离场后第二人仍能完成，最后一人离场后共享局不可再查询。 |
| AC-008 | RQ-009 | Given 单人普通和单人剧情测试向量，When 运行现有完整相关测试和新增一人共享局回归，Then 进入、移动、死亡、掉落、结算、翻牌、任务与离场结果保持既有断言。 |
| AC-009 | RQ-010 | Given 当前局开始后 PartyService 发生变化或参与者连接断开，When 后续命令到达，Then 当前局的冻结成员不被替换或扩充，且服务端不进入中途加入/重连状态机。 |

## Success Evidence

- EV-001 → AC-001..AC-002：PartyService + DungeonRunDomainService 领域测试和双连接应用测试。
- EV-002 → AC-003..AC-004：入场/换图协议投递测试，断言每个逻辑连接的帧种类、顺序及共享房间版本。
- EV-003 → AC-005..AC-007：重复与并发死亡、拾取、结算、翻牌和逐角色任务/奖励测试。
- EV-004 → AC-008..AC-009：相关生产项目测试、解决方案构建和完整测试套件结果。
- EV-005：运行产物的提交、进程路径、监听端口与启动后健康日志，证明双客户端可连接到本任务实现。
