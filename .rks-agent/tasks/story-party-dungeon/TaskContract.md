# TaskContract: 剧情地下城固定队伍首发入场

## Context

### Source Request

用户在确认现有信息足以开始一个边界明确的副本组队首版后授权执行：
“可以，你来执行到可以实机测试的程度。然后我们进行实机测试”。

### Current Situation

主干已有独立的进程内 PartyService、可按频道/城镇/区域查询的 PartySnapshot，以及已经实机跑通的单人剧情地下城进入、移动、击杀、任务完成和结算链路。当前 DungeonRunDomainService 仍按角色保存独立运行态，经验/掉落/翻牌虽已暴露队伍人数参数，实际调用仍按单人处理。旧服存在共享实例与服务端推动队员进图的实验实现，但未获得 A21 双客户端实机确认。

## Goal

使一个已在城镇组成的在线队伍能够由队长选择其当前主线任务对应的剧情地下城，并让入场时冻结的全体成员进入同一局共享副本、共享房间与怪物事实，同时各角色独立、安全且至多一次地获得其适用的任务进度、经验与结算结果，达到双客户端实机验证条件。

## Scope

### In

- 将普通/剧情地下城既有模式选择保留在入场策略边界，并为剧情地下城增加固定队伍首发入场编排。
- 入场时冻结 PartySnapshot；验证队长身份和全体成员的在线可附着状态，避免形成部分入场的分裂副本。
- 将一局副本的布局、房间、怪物死亡、清图和地面掉落事实提升为队伍共享状态，同时保留逐角色参与者状态。
- 向入场成员投递客户端需要的副本进入与换图序列，并使全员保持在同一共享房间版本。
- 对每个参与者独立处理适用的任务 Trigger、经验、奖励、翻牌与离场收口；同一事实不得因多端上报而重复发放。
- 保持单人普通地下城和单人剧情地下城现有可观察行为不回退。
- 补充足以保护共享状态、成员隔离、重复上报和单人回归的自动化验证，并构建、部署到可进行双客户端实机测试的本地运行状态。

### Out

- 运行中途加入队伍或副本（`ENTRY_INTO_PARTY` / `ENTRY_INTO_PARTY_FINISH`）。
- 副本内断线重连、跨进程恢复或服务重启后的副本恢复。
- 入场后踢人、退队、转移队长等队伍变更对当前局的动态生效。
- 特殊塔、Raid、异界入口、需要逐成员特殊门票的内容，以及所有任务 Trigger 类型的一次性泛化补全。
- 修改或猜测尚未实机闭合的中途加入协议布局。

## Constraints

- Session 只用于连接代际、通知投递和当前连接所有权校验，不得成为副本或队伍领域身份。
- 剧情副本由队长当前有效任务决定；普通副本不得因为角色持有剧情任务而被错误路由。
- 入场后使用冻结的参与者集合，PartyService 的后续变化不得悄然改变当前局成员。
- 在缺少双端实帧的地方只实现首发入场所需的最小兼容序列，并保留明确可撤销的协议编排边界。

## Success Conditions

| ID | Observable condition | Required evidence |
|---|---|---|
| SC-1 | 两名在线角色组队后，只有队长能够发起剧情地下城选择；成功入场产生一个共享局标识和两个独立参与者附着，且不会出现仅一人进入的半提交状态。 | 领域/应用集成测试覆盖队长成功、非队长拒绝、成员不可附着时整体拒绝。 |
| SC-2 | 两个参与者收到完整入场投影并进入相同布局、起始房间；队长推进房间时两端进入同一房间版本。 | 协议构建测试与双会话应用测试断言每端投递序列、共享布局和房间状态。 |
| SC-3 | 同一怪物死亡或清图事实即使由两端重复上报也只应用一次，并对双方观察到一致的房间/掉落状态。 | 并发或重复命令测试证明共享死亡声明幂等、房间一致且无重复掉落。 |
| SC-4 | 每名参与者只推进自己持有且匹配的任务 Trigger，并独立、至多一次地获得经验、任务奖励和结算结果；未持有任务的成员不获得该任务进度。 | 双角色任务/结算测试覆盖双方持有、仅队长持有与重复结算。 |
| SC-5 | 既有单人普通与单人剧情地下城行为保持通过，普通地下城不因当前剧情任务而切换为剧情规则。 | 现有测试套件及新增模式隔离回归测试通过。 |
| SC-6 | 本地服务端构建和相关测试通过，并已切换到包含该实现、可接受双客户端连接的运行产物。 | 构建/测试结果和监听端口、运行提交/工作区证据。 |

## Authorization

| Capability | Evidence | Authorized scope |
|---|---|---|
| task | “可以，你来执行到可以实机测试的程度。然后我们进行实机测试” | 创建并执行本契约范围内的设计、代码、测试、隔离工作区、本地提交、构建与本地测试部署；不包含合并主干、推送远端或清理工作区。 |

## Requires Confirmation

- 将结果合并到 `main`、推送远端或清理任务工作区。

## Assumptions

- 首版允许没有相同剧情任务的在线队员随队进入；副本布局由队长的有效剧情任务决定，而该队员只有在自己的活动任务 Trigger 匹配时才获得任务进度。
- 首版只接纳发起时已在线且能绑定当前连接的固定成员；发现陈旧或不可附着成员时整体拒绝，而不是静默缩减队伍。
- 首轮实机验收使用已验证过的剧情任务垂直切片，其他剧情任务由后续 Trigger 覆盖扩展。
