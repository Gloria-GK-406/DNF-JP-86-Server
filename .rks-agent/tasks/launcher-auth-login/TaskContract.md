# TaskContract: WPF 启动器与票据登录链

## Context

### Source Request

用户确认在 `DNF-JP-86-Server` 同一仓库内新增目录实现登录功能：使用 .NET WPF 独立启动器；启动器配置只保存一个 HTTP 服务地址，由 HTTP 协议取得实际游戏/频道连接地址与端口；提供账号密码登录和账号申请页面；后端完成账号注册、密码认证、短时登录票据与 Game 登录联动；UI 样式由 Agent 决定，当前功能优先。用户明确授权：“够了就直接开始实现功能吧。”

### Current Situation

现有 A21 客户端由批处理把固定账号、固定字符串和频道地址写入启动参数。Game `0x0001 LOGIN` 把两个字符串解释为账号与密码哈希，服务端会按账号名自动创建账号、不会验证已保存密码，并固定走成功响应。仓库没有 HTTP 认证入口或桌面启动器，但现有客户端启动参数已经能携带账号、票据与频道端点，适合由独立启动器接管。

## Goal

在同一仓库中交付一个可运行的 WPF 登录启动器和与现有服务端联动的认证链：用户可注册和登录；启动器仅从 INI 读取 HTTP BaseUrl，通过后端获得一次性短时 Game 登录票据及客户端可访问的频道端点，随后以兼容 A21 的参数启动 DNF；Game 登录通过兑换票据绑定正确账号，密码不再进入 Game 协议。

## Scope

### In

- 在仓库内新增 .NET 10 WPF 启动器项目及其自动化测试。
- 提供功能优先的登录、注册、加载和错误状态 UI，并支持记住账号但不保存密码。
- 提供只包含 HTTP BaseUrl 的启动器 INI 配置和严格配置校验。
- 在现有 Host 中提供启动器状态、账号注册和账号密码登录的 HTTP API。
- 安全保存密码验证信息，正确处理重复注册、错误密码和无效输入。
- 由 HTTP 登录响应下发短时登录票据和客户端可访问的频道端点。
- Game `0x0001 LOGIN` 改为兑换票据后绑定现有 AccountId；无效、过期或已使用票据不得登录。
- 保留成功认证后的现有账号状态、选角和进城链路。
- 更新同仓库的运行说明和示例配置。

### Out

- 组队系统本身及组队协议实现。
- 最终美术资源、品牌级视觉打磨、复杂动画和皮肤编辑器。
- 客户端二进制修改、注入新的客户端内置登录界面或修改只读取证客户端目录。
- 自动更新、补丁分发、多区域选择、邮箱验证、找回密码、第三方登录和管理后台。
- 生产环境域名、TLS 证书签发或公网部署。
- Git 推送、合并其他分支和任务工作区清理。

## Constraints

- 启动器与后端必须位于 `DNF-JP-86-Server` 同一 Git 仓库；启动器 UI 使用 .NET 10 WPF。
- 启动器 INI 只能要求一个 HTTP BaseUrl；频道/Game 实际端点不得要求用户在启动器本地重复配置。
- 密码及其可重放等价物不得写入启动参数、Game 协议、日志或 INI；启动参数只携带短时票据。
- HTTP 返回的必须是客户端可访问的公共端点，而非仅进程可绑定的监听地址。
- 第一版以完整功能和清晰错误反馈优先，不以最终视觉完成度作为验收条件。
- 保持现有 Application 不引用 Infrastructure 的分层约束和现有 A21 启动参数兼容性。

## Assumptions

- 第一版面向当前 Windows x64 主机发布，启动器可启动同目录或配置推导位置的 32 位 A21 `DNF.exe`。
- 本机开发允许 `http://127.0.0.1:8080`；设计保持可切换 HTTPS，但本任务不部署证书。
- 当前持久化账号没有可信的已验证密码语义；实现需提供安全、可说明的兼容或初始化策略，而不能把旧值直接当作已验证现代密码。
