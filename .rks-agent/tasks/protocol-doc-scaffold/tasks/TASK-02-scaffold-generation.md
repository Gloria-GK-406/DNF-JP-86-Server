# TASK-02 文档骨架生成与全量索引

## Task Unit Contract

**交付物**：按方向分层的协议文档树与全量索引；每篇文档含身份、body（布局或显式未知）、
定位信息，且机器区与人工区可无歧义区分。

**Spec 覆盖**：RQ-001、RQ-002、RQ-003、RQ-005、RQ-006、RQ-008、RQ-012、RQ-013、RQ-014。

**边界**：只新建协议文档与索引。**不得写入任何已存在的手写文档**。

**依赖**：TASK-01。

**完成证据**：文档集合与身份集合双向差集为空；既有手写文档零改动。

## Execution Result

生成 1396 篇文档 + 全量索引，跳过 14 篇手写文档。

文档路径方案：`game/client-to-server/<type>.md` 与 `game/server-to-client/NOTI-<type>.md`。
C→S 不加族前缀，因为客户端出站帧构造点把 command 写死为 `0x01`，该方向全是 CMD；
S→C 必须加，否则 NOTI `0x0001` 与 CMD `0x0001` 的响应会抢同一个文件。

机器区以 `<!-- rks:machine:begin -->` / `end` 圈定，重新生成只覆盖该区。
**字段含义走 `meanings/*.tsv` 分片作为生成器输入**，不写进文档——因此重新生成会把它带上，
而不是覆盖掉；并行富化也因此零文件竞争。

## Executor Self-check

- 一处真实缺陷已修复：首次运行传错了根路径（从 `patterns/data` 出发 `..` 是 `patterns`
  而非 `protocol`），1411 篇写到了 `protocol/patterns/game/`。已整树删除并以正确根重跑；
  因路径不同，该次误写**没有触及任何既有文档**（`git status` 当时对 `protocol/game`
  无任何输出，已核对）。
- 一处真实缺陷已修复：生成器把重复组一律排在定长字段之后，与真实 wire 顺序不符。
  已改为按指令地址内联渲染，且**组之后的偏移一律打 `?`**——重复次数是运行时值，
  给一个假定 n=1 的数字比给 `?` 有害。
- 一处真实缺陷已修复（由富化代理发现）：含义键 `(族, type, offset)` 不区分顶层与组内字段，
  组内偏移从 0 重新计数会与同号顶层字段撞键，一条含义被贴到两个不相干字段上。
  已引入 `gN:offset` 作用域，并写了迁移工具把既有分片无歧义地重键（29 行，0 未解决）。
