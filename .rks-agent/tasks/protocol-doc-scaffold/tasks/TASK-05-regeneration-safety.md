# TASK-05 重新生成安全性证明

## Task Unit Contract

**交付物**：可重复执行的证明——重新生成不会破坏人工补充的内容。

**Spec 覆盖**：RQ-011。

**边界**：测试须自行还原现场，不得在树里留下痕迹。

**依赖**：TASK-03、TASK-04。

**完成证据**：植入哨兵内容后重跑全流水线，人工区逐字节不变、手写文档零改动、
分片含义正确并入机器区。

## Execution Result

`check-regeneration-safety.py` 植入三类可区分内容后重跑 `rebuild.py`：

| 植入位置 | 期望 | 结果 |
|---|---|---|
| 生成文档的人工区（机器区之后追加） | 逐字节不变 | 通过 |
| 生成文档机器区之前的内容 | 逐字节不变 | 通过 |
| 完全手写的文档（`0x00AB.md`，无机器区） | 零改动 | 通过 |
| 分片新增的字段含义 | 出现在重生成后的机器区 | 通过 |
| 测试后的树状态 | 完全还原 | 通过 |

失败数 0。

第三项是这套设计成立的关键：**改字段含义要改分片，不要改文档**。分片是生成器的输入，
所以重新生成会带上它；直接改机器区则会在下一次重跑时丢失。这一点已写进
`meanings/README.md` 与 `protocol/README.md`。

## Executor Self-check

- 测试用的探针文档由脚本按"有字段表且非手写"自动挑选，不是写死的，
  因此换客户端版本后仍然有效。
- 测试在 `finally` 中还原，即使中途失败也不留痕；还原后再跑一次 `rebuild.py` 使产物与
  树状态一致。
- 该测试证明的是**机制**而非某一篇文档：机器区边界由标记决定，与文档内容无关。
