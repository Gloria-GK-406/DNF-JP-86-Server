# Specification: 稳定队伍身份驱动共享地下城

## Why and Outcome

组队成员是谁必须只有 PartyService 能回答。地下城保持自己的 `RunId` 和 Cell，引用稳定的队伍领域身份 `PartyKey`；客户端所见队伍 ID 仅是可换代的协议身份。队长退出时，留下的人继任并继续同一个副本，客户端通过旧队伍退役、新队伍建立看见正确的单人队，而非丢失队伍。单人虚拟队伍走同一副本业务路径。

## Scope

包括真实/虚拟队伍身份、当前成员查询、客户端队伍投影换代、地下城成员资格和队长裁决、入场/退出、通知受众、Cell 创建与成员专属结果发放，以及对应回归。与此无关的怪物规则、概率、任务完成条件、P2P 握手和结算玩法不变。连接代际与每角色进度仍可保留，但不得成为队伍成员真源。

## Definitions and Invariants

- `PartyKey`：在同一队伍业务生命周期内稳定、可通过 PartyService 反查当前成员的领域身份。真实队伍与虚拟单人队伍互不混淆；两个不同虚拟队伍也互不混淆。
- 客户端队伍 ID：A21 `PARTY_INFO` 等协议使用的标识。它可以在同一 `PartyKey` 生命周期内变化；不用于领域成员、目录或副本查找。换代后，旧客户端对象必须先退役，新对象才成为当前投影。
- `RunId`：一次地下城的独立身份。地下城绑定一个 `PartyKey`；换队长或客户端队伍 ID 不改变 `RunId`、现有 Cell、房间进度或已生成的共享内容。
- 成员资格由 `PartyService` 根据 `PartyKey` 的当前成员决定。角色的副本准备状态、个人进度、物品归属和会话可达性不是另一份成员名单。连接代际只防旧连接接收新通知。
- 运行中队伍只允许按已定义的退出语义缩减成员或更换队长；图外角色不能因加入该队伍就进入现有副本。运行中副本不得因成员退出而改绑另一支队伍。

## Requirements

| ID | Requirement |
|---|---|
| RQ-001 | PartyService 为真实与虚拟队伍提供稳定且可反查的 `PartyKey`，并作为成员和当前队长的唯一领域真源。 |
| RQ-002 | 客户端队伍 ID 从领域身份中剥离；队长退出后，服务端队伍及其设置连续，协议层按客户端可识别的旧 ID 清除、新 ID 建立顺序投影。 |
| RQ-003 | 一次副本绑定 `PartyKey + RunId`。入场、操作、过图与退出依据当前队伍成员及该副本状态决定，不依赖入场时冻结名单来授予资格。 |
| RQ-004 | 副本通知从当前队伍成员导出，并只发往可接收本次运行的当前连接；离开者、图外者和旧连接不接收。 |
| RQ-005 | 新 Cell 创建时从绑定的 `PartyKey` 获取当前成员及队长，不再把入场时冻结的队长/人数当作当前规则输入；已生成的 Cell 和共享内容不因后续成员变化重算。 |
| RQ-006 | 成员专属的未落实结果在实际落地、授予或消费时确认归属人仍为当前队员；离开者的结果跳过，不转赠，不触发 Cell 整体版本复核或重试。 |
| RQ-007 | 真实多人和虚拟单人遵循同一副本资格模型；离队、退图和连接清理后的队伍/副本状态相容，剩余成员可继续原运行。 |

## Acceptance Criteria

| ID | Covers | Criterion |
|---|---|---|
| AC-001 | RQ-001 | 给定两支真实队伍和两个未组队角色，四者拥有互不混淆的内部身份；通过每个身份能取得对应当前成员。真实队伍客户端 ID 改变后，内部身份与反查结果仍连续。 |
| AC-002 | RQ-002 | 给定 A 为队长、B 为队员，A 主动离队后 B 为唯一成员及队长，队伍设置不丢；离队者清旧 ID，B 端先丢弃旧队伍对象再建立新客户端 ID 的单人队。A21 实机可显示 B 的队长状态及“是否保留队伍”提示。 |
| AC-003 | RQ-003 | 给定 A/B 已在同一个 `RunId`，A 退队/退图后 B 保持原 `RunId`、已生成 Cell 与房间进度，可作为新队长继续操作；A 的后续操作被拒绝且不改变副本。图外新成员不能获得此 `RunId` 的资格。 |
| AC-004 | RQ-004 | 当副本事件在成员退出后发布，B 的当前连接得到通知，A 与旧连接不得到通知；虚拟单人只通知本人当前连接。 |
| AC-005 | RQ-005 | 在 A 退出、B 继任后首次创建新 Cell，成员相关生成规则取 B 和当前人数；再次访问该 Cell 不重新生成。队伍变化不回滚或重算已经发布的共享内容。 |
| AC-006 | RQ-006 | 成员专属的待落实结果若归属人已离队则被跳过，其他人不代领；已提交共享结果保留。退出与生成先后变化不要求整次 Cell 取消、重试或按队伍版本验证。 |
| AC-007 | RQ-007 | 真实单人、虚拟单人、多人组队均可选图、入场、过图和退出；退出最后一名成员后没有可继续操作的孤儿运行，连接清理不让旧会话恢复成员资格。 |

## Success Evidence

|---|---|---|
| EV-001 | AC-001, AC-002 | 队伍领域/协议测试及客户端旧清除→新建立的编码与顺序断言；A21 双客户端实机观察。 |
| EV-002 | AC-003, AC-004, AC-007 | 副本入场、队长离开、继续过图、通知收件人与旧连接排除的领域和协议集成测试；双客户端连续运行实机观察。 |
| EV-003 | AC-005, AC-006 | Cell 与成员专属掉落测试，覆盖离队前后首次生成、重复访问及发放前退出。 |
| EV-004 | AC-001–AC-007 | 全解决方案构建与相关测试通过；受影响领域调用点检查不再用客户端队伍 ID 判定成员或定位副本。 |
