# 角色静态规则与动态事实

## Why and Outcome

现有流程和后续技能用例应从同一套不可变规则与角色当前事实得到答案，避免已学组合缓存增长、选角副本过期和职业上限读取错误。

## Scope

实现职业、基础属性、技能规则和现有角色消费者迁移。沿用存储事务及协议格式，不接入新学习、退款、转职、觉醒协议，不实现 Buff 或装备属性计算。保留尚未建模的持久字段；历史属性列不能覆盖当前职业等级的基础属性。

## Requirements

| ID | Requirement |
|---|---|
| RQ-001 | 明确基础职业、转职索引和觉醒阶段；集中编码解码，结构合法性与 PVF 支持性分开判断。 |
| RQ-002 | 提供支持职业组合 1—86 级基础属性只读查询；结果共享并在初始化阶段准备，生产查询不重新解析成长档案。保持既有定点表达。 |
| RQ-003 | 技能规则服务返回只读实例，提供说明、前置要求、职业等级上限、累计 SP/TP、免费基线及静态学习资格；未知规则明确缺失，零上限不可提升为一。 |
| RQ-004 | SP/TP 总量为静态规则；实际投入由当前已学技能页与免费基线算出；奖励为动态事实。不缓存已学组合、不持久化余额。 |
| RQ-005 | 角色实例回答当前身份、成长、基础属性与技能状态；相关消费者读取当前事实。已有事务内可读写入结果，回滚及重新加载一致。 |
| RQ-006 | 创建、选角、经验奖励与技能点读取接入统一规则；既有物品流程和协议保持兼容，文档如实说明残留边界与证据置信度。 |

## Acceptance Criteria

| ID | Covers | Criterion |
|---|---|---|
| AC-001 | RQ-001 | 对职业打包值做合法/非法及往返检查；PVF 未声明的组合拒绝查询。 |
| AC-002 | RQ-002 | 真实 PVF 遍历支持组合与 1—86 级；代表职业等级边界与独立计算一致，记录初始化与重复查询耗时。 |
| AC-003 | RQ-003 | 剑魂 25 级十字斩 3 级可学、血之狂暴不可学；元素点燃使用该职业的 maximum 多值；累计费用、前置缺失、TP、免费基线可验证。 |
| AC-004 | RQ-004 | 不同页、等级和奖励正确影响余额；技能记录变化立即影响查询；未知费用不可静默产生免费投入。 |
| AC-005 | RQ-005 | 临时 SQLite 库验证当前读取、提交、回滚、重载；静态结果不因角色变化复制或污染。 |
| AC-006 | RQ-006 | 全解决方案构建与测试，逐项检查 TRX；完整独立审查通过，真实数据验证不改运行数据库，无新技能协议。 |

## Success Evidence

真实 PVF、合成边界测试、临时数据库行为测试及静态依赖审查共同覆盖 TaskContract SC-1—SC-6。属性成长合成沿用已核对的参考算法，注明代码推导，不将其当作实机确认。没有捏造硬性延迟阈值，报告实测成本与查询不重新解析的结构证据。
