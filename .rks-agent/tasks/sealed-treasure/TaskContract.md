# TaskContract: 封印的藏宝地

## Context

### Source Request

用户：“那就给spicies dungeon也定义为不消耗疲劳。其他的就按当前设计实施，后续再说要不要改。这样的话可以开始实施流程了嘛？”

此前用户授权先收集全部信息；成果是 `Document/SealedTreasure-Research-20261019/README.md` 及其三份报告，研究提交 `2764030f`。本次授权从调查进入实施。

### Current Situation

3557 的资源存在，通用副本路径不能接受免费票，没有本图活动路由或四元素运行状态。历史国服规则、70 服务端参考、A21 静态内容和当前实现的区别见研究报告。用户接受以当前设计先实施并后续调整。

## Goal

交付可供下一轮部署与 A21 人工验收的封印的藏宝地服务端实现：入口与门票正确，元素路线和宝箱形成可运行闭环，标记本类地图不耗疲劳，同时保护既有活动和普通副本。

## Scope

### In

- 将所有声明 `[spicies dungeon]` 的地下城定义为不消耗疲劳。
- 3557 的活动开关与入口投影、70 级门槛、固定难度 2、单人、禁止练习。
- 活动票优先、普通票回退，只消耗一份；失败不扣票，普通多材料规则保持原语义。
- 四元素精灵与对应封印石的局内跨房状态，中央宝箱和既有奖励/开箱链的接线及必要修正。
- 有针对性的合成、真实 PVF 和完整解决方案回归，更新实现与人工验收文档。

### Out

- 本轮不新增独立“每日三次”计数或 06:00 补给规则：保留现有免费票补到 1 的有效配置与周期，次数由可用门票约束。历史运营规则留待后续调整。
- 不恢复 20747..20749 孤儿任务，不发明专属兑换店或额外奖励。
- 不部署、改运行数据库、发玩家物品、修改客户端/PVF、推送或合并分支；本轮完成后等待部署/验收指令。
- 不把未实测的 A21 UI/协议行为宣称为原服事实；原生客户端人工验收由下一轮部署后完成。

## Constraints

- 遵守仓库 AGENTS.md 的 DomainService → RuleService → ContentSource 边界；Application 不引用 Infrastructure/Protocol。
- 门票和奖励处理不得因重复请求、失败或回房而重复扣除/发放；改动保护其他地下城现有行为。
- 不预设 ACT 参数 1/2/4/8 的 native 位编码，不新增无证据 opcode；允许服务端使用私有命名状态。
- 原服未知项使用暂定实现并明确标注。静态资源和自动测试不得升级为 WireCaptured / ClientVerified。
- 保留本工作区所有任务外未跟踪文件及运行服务。
