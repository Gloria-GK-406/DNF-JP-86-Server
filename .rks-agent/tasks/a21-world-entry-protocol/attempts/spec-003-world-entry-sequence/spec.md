# Specification: A21 入场序列

## Why and Outcome

A21 客户端已经能选中角色并收下整批入场通知，但收完之后它发一条统计命令就关闭连接——
与登录阶段那次初始连接通知发错时是同一形状。入场批次里有四处报文体是定长或半定长的，
而本仓发的与该客户端已知接受的会话不同；另有若干通知本仓没发或多发了。

本规格要达成的可观察结果：A21 客户端选中角色后进入并留在游戏世界里。

## Task Perspective

- Core outcome: 客户端进入游戏世界后不再断开。
- Necessary support: 入场批次中定长与半定长报文体的字节为该客户端所接受；缺发与多发两组
  各自有处置。
- Peripheral assurance: 每处改动可追溯到实测字节；被判为数据差异而不改的那些有明确理由；
  协议知识库同步。

## Scope and Non-Goals

### In Scope

- 账号信息通知在入场阶段的三个子类型的报文体。
- 进入世界完成通知的报文体。
- 入场批次里本仓缺发与多发的通知集合。
- 上述各处在协议知识库与其目录状态中的表述。

### Non-Goals

- 进入世界之后的任何协议。
- 报文体大小仅因角色或账号数据不同而不同的协议。
- 服务架构、分层、切片边界与命令总线语义的任何改变。
- 合并同一通知类型的两个编码器。

## Definitions

| Term | Meaning |
|---|---|
| 入场批次 | 服务器在接受选角之后、客户端开始在城镇中活动之前推送的一组通知 |
| 子类型 | 账号信息通知报文体的首字节，决定其后字段的含义 |
| 定长报文体 | 长度不随角色或账号数据变化的报文体 |
| 数据差异 | 两份报文体因所载数据不同而长度不同，而非因字段布局不同 |

## External Behavior and Data Rules

- 进入世界完成通知的报文体为八字节：两个值为一的三十二位整数。
- 账号信息通知的入场子类型有三个，依次为 `0x00`、`0x01`、`0x06`，各出现一次。
- 子类型 `0x06` 的报文体为二十五字节，依次为：子类型、两字节版本一、两字节角色标识、
  一个全为一的三十二位值、一个固定的三十二位常量、两个值为二百五十五的三十二位值、
  一个值为零的三十二位值。
- 子类型 `0x00` 的报文体在子类型与两字节版本之后有三十八个零字节，其后才是角色标识与
  角色名；当角色没有宠物时，宠物三元组为一个全为一的三十二位值、一个固定的名称字符串、
  以及一个值为二百五十五的字节。
- 字符串字段的形式为四字节长度前缀加其后的字节。

## Assumptions

- 已归档的 A21 已知良好会话代表该客户端接受的行为。
- 断开的直接原因尚未定位；上述四处定长与半定长报文体是首选嫌疑，但这是待验的假设。
  若改完它们客户端仍断开，说明原因在别处，须继续诊断而不是把清单当作已尽。
- 该会话的角色有装备与技能，本仓用的是新建的一级角色，因此依赖数据的协议大小本就不同。
- 子类型 `0x00` 与 `0x01` 的尾部在参考实现中是写死的字节段，其自认「尚待实机确认」。
  本规格按实测字节实现，不按其字段划分实现。
