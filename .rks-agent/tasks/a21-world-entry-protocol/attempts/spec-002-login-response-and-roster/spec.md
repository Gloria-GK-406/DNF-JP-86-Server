# Specification: A21 登录应答与花名册条目

## Why and Outcome

A21 客户端已能登录并到达「选择角色」界面，但账号里的角色在那里渲染不出来：花名册的逐角色
条目仍是上一版客户端的形状。登录应答也与该客户端接受的字节差一个字节且版本号不同——
客户端当前接受了它，因此这一处没有可观察的症状，但它与已知良好会话不一致。

本规格要达成的可观察结果：A21 客户端在「选择角色」界面上渲染出账号已有的角色，
而登录应答与花名册的线级字节与该客户端已知接受的会话一致。

## Task Perspective

- Core outcome: 账号已有的角色出现在「选择角色」界面上。
- Necessary support: 登录应答与花名册的字节为该客户端所接受；账号里存在可渲染的角色。
- Peripheral assurance: 每条具名字段可追溯到实测字节；结构长度闭合；协议知识库同步。

## Scope and Non-Goals

### In Scope

- 登录应答的报文体字段序列与取值。
- 花名册通知中逐角色条目、外观条目与尾部的字段序列。
- 使账号存在可渲染角色所需的数据改动。
- 上述两者在协议知识库与其目录状态中的表述。

### Non-Goals

- 入场状态的其余子类型与选人之后的任何报文。
- 角色创建流程本身的协议行为。
- 服务架构、分层、切片边界与命令总线语义的任何改变。

## Definitions

| Term | Meaning |
|---|---|
| 登录应答 | 服务器对客户端登录命令的同类型答复，客户端据此确定环境、端口与对外主机 |
| 花名册 | 服务器推送的账号角色清单，客户端据此渲染「选择角色」界面 |
| 外观条目 | 花名册中每个角色附带的显示部件记录，条目数由其前一个字节给出 |
| 结构闭合 | 各字段宽度之和与实测报文体长度精确相等 |

## External Behavior and Data Rules

- 登录应答的报文体依次为：一字节接受标记、一个两字节版本值、一字节环境标识、一个零字节、
  四字节连接端口、对外主机字符串、两个四字节端口、其后二十四个零字节。
- 版本值为二十。
- 花名册报文体的头部为十八字节，其后是角色计数所声明的若干条目。
- 每个角色条目依次为：两字节槽位、角色名字符串、两个零字节、一字节职业、一字节成长类型、
  一字节等级、两个固定字节、两个四字节零值、一字节外观条目数、该数目的外观条目、
  以及三十六字节尾部。
- 每个外观条目为二十三字节，依次为：一字节槽位、四字节显示部件标识、四字节常量四、
  四字节扩展数据、一字节状态、四字节关联部件标识、四字节强化值、一字节标志。
- 角色条目尾部的最后十五字节为六个零、一个全一字节、八个零。
- 一个角色带一条外观时，花名册报文体共一百零三字节。
- 字符串字段的形式为四字节长度前缀加其后的字节。

## Assumptions

- 已归档的 A21 已知良好会话代表该客户端接受的行为。
- 该会话只含一个角色、一条外观条目，因此外观条目与尾部之间的边界由长度差值与上游结构
  双向印证得出，而非由多样本差分独立确定。实机渲染异常时首先怀疑这一处边界。
- 等级之后那两个字节在唯一的观察样本里是 `0x0B` 与 `0x01`。**它们是常量还是某个数据字段的
  低半部分，一个样本无法判定**：本仓既有模型把这一带读作两个四字节进度值加一个两字节保留，
  按那种读法同一批字节意味着首个进度值为 267。倾向常量的迹象是——这两个字节在同一角色的
  其余入场报文里一次都没有出现，而参考实现也把它们写成字面量。本规格按观察到的字节实现，
  并把该不确定性记进协议记录；判定它最便宜的证据是第二个进度值不同的角色。
- 登录应答目前被客户端接受，因此本规格对它的改动不以修复可观察故障为目的，而以与
  已知良好会话一致为目的。
