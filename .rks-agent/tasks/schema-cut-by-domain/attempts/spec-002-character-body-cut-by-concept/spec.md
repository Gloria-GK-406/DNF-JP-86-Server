# Specification: 角色本体按概念重切

## Why and Outcome

角色今天是三张表，切分线是选人下发那一包协议的段落：身份、由等级与装备算出的数值、以及这个角色身上发生过什么，按「第几段」混在一起。另有六张表各自只为「每角色至多一行」而存在。

要变成真的是：角色本体的每一张表都能用一句话说清它承载哪个概念，没有一张的边界要靠协议包来解释；而客户端收到的每一个字节与今天完全相同。

两者缺一不可。只做前者会得到一个更好看却下发不同内容的服务器；只做后者等于什么都没做。

## Task Perspective

- Core outcome: 库里角色本体这一块的形状，与已封存的裁定给出的目标形状一致——概念一张表，边界说得清。
- Necessary support: 六张每角色一行的表要在建角色时各得一行，且未被写入的列取到与今天相同的值；九张源表的每一条约束要在其列的落点上继续成立。没有这两样，形状对了而行为变了。
- Peripheral assurance: 下发帧的字节比对与表征用例的可证伪性。它们证明行为没变，但它们本身不是成果。

## Scope and Non-Goals

### In Scope

- 角色本体三张表与五张折入表的形状改为裁定的目标形状；`character_expert_job` 保留并吸收其应得的列。
- 九张源表的读写路径、按表接口与其行类型随之改写。
- 每日挑战的组与领取合并到一处；拼写错误的表名更正。
- 领域层的跨表组装随形状更新。
- 表征用例改写到新形状。

### Non-Goals

- 不动物品域与技能域的表。金币上限迁入派生数值之后，物品侧对它的那一处读取在本成果内改为读新位置，只做这一处最小改动；物品域自身的重切不在本 Spec 内。
- 不为既有数据设计回填、修复或迁移路径。
- 不改动裁定中标为暂定或悬置的归宿。
- 不改变对外协议行为。

## Constraints

- 裁定是设计权威。与它不一致的实施须先更新裁定并说明理由，不得就地偏离。
- 源表的每一条约束在其列的落点上存续。
- 未被建角色写入的列，其取值不得改变——其中数个的值直接或经映射到达客户端。
- 开发阶段擦库不迁移：直接以新形状建库。
- 覆盖不可净减少。

## Definitions

| Term | Meaning |
|---|---|
| 裁定 | `Docs/Refactor/TableOwnershipRuling.md`，本 Spec 的设计权威 |
| 目标形状 | 裁定中「Target shape」一节给出的表与列 |
| 每角色一行的表 | 一个角色至多也至少有一行的表 |
| 承载 | 目标形状中存放某一概念的那一张表 |

## Observable Requirements

| ID | Requirement |
|---|---|
| RQ-001 | 库形状在角色本体这一块上与裁定的目标形状逐列一致：表名、列名、列的归属都相同 |
| RQ-002 | 每角色至多一行的状态不再只因为「至多一行」而单独成表；仍然保留的那一张能指出它承载的概念 |
| RQ-003 | 改动前九张源表的每一条键、唯一性、检查与外键，在其列的落点上仍然成立 |
| RQ-004 | 建一个角色之后，六张每角色一行的表各有一行 |
| RQ-005 | 建角色的写入没有指名的列，取到的值与改动前相同 |
| RQ-006 | 选人下发的帧与改动前逐字节相同 |
| RQ-007 | 今天由整记录表征用例守住的每一列，在新形状下仍被守住，且该守卫可证伪 |
| RQ-008 | 每日挑战的组与它是否被领取由同一处承载；一个未被领取的组，读出来仍然是未领取 |
| RQ-009 | 更名后的表与更名前承载同样的内容，读写路径不因更名而改变行为 |
| RQ-010 | 持久化类仍只指名一张表；跨表组装仍在领域层，且每条记录只有一个定义点 |

## Acceptance Scenarios

| ID | Covers | Given | When | Then |
|---|---|---|---|---|
| AC-001 | RQ-001 | 一个以新形状建起来的库 | 把它的角色本体各表的列与裁定的目标形状比对 | 表名、列名与列的归属逐一相同，无多无缺 |
| AC-002 | RQ-002 | 改动前的六张每角色至多一行的表 | 在新形状里查找它们 | 五张不复存在，其列出现在各自的落点上；保留的那一张可指出它承载的概念 |
| AC-003 | RQ-003 | 改动前九张源表的约束清单 | 逐条在新形状里查找对应的约束 | 每一条都能找到，或能指出它在何处以何种形式存续 |
| AC-004 | RQ-004 | 一个空库 | 建一个角色，然后读六张每角色一行的表 | 六张各有一行 |
| AC-005 | RQ-005 | 一个刚建好的角色 | 读那些建角色写入未指名的列 | 取到的值与改动前读同一个角色时相同 |
| AC-006 | RQ-006 | 同一个角色在改动前与改动后 | 走一次选人并录下下发帧 | 两次的字节完全相同 |
| AC-007 | RQ-007 | 改写后的表征用例 | 对每一处承载，构造一次列错位或列缺失 | 用例变红 |
| AC-008 | RQ-008 | 一个已生成但未被领取的每日挑战组 | 载入它 | 读出来是未领取，与改动前一致 |
| AC-009 | RQ-009 | 更名前后的同一批内容 | 读它 | 读出的内容相同 |
| AC-010 | RQ-010 | 改动后的持久化层与领域层 | 清点每个持久化类指名的表，以及每条记录的定义处 | 每个类只指名一张表；每条记录只有一个定义点，且组装在领域层 |

## Assumptions

- 裁定中标为已核实的事实成立。若实施中发现某条不成立，先更新裁定再继续。
- 目标是本机开发库，现有数据可直接丢弃，因此不需要考虑既有行的可转换性。
