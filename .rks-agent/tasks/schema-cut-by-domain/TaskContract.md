# TaskContract: 角色数据库按领域重切

## Context

### Source Request

用户在看过一份现状调查与切分草案后，拒绝分块推进并要求一次全部改完：

> 不，一口气全改了。可以按multi-spec来处理。

该请求承接同一轮对话中已达成的三项一致：表的边界要按概念而非协议字段来定；相近概念要聚到一张表里；把不同概念压成通用键值行是不可接受的。

### Current Situation

字符数据库当前声明 53 张表：角色侧 41、账号侧 7、邮箱 3、`rental_items` 1、投递外发箱 1。这些表的边界不是从角色这个概念推出来的，而是从选人时下发的那一大包协议字段推出来的——包里每出现一段可重复结构，就落成一张表。一次选人载入因此要读其中 33 张。

这带来三类可指认的后果：

- **同一个概念散在多张表里**。物品分属 12 张表，其中还并存着两代形状：上一代的分解列式与本代的定长核心块。上一代的两张（角色物品、账号仓库物品）在生产代码里只剩「问它空不空」这一种用法，没有任何写入。租借同一个概念存在两张列语义相同的表。
- **同一个实体被协议分段横切**。角色本体被切成三张，切线是「协议包的第几段」，因此运营态、派生数值与身份三类东西按段混在一起，而不是按概念分开。
- **每角色至多一行的状态各自成表**。有六张表以「至多一行」的方式被读取，它们本可以是角色行上的列。

上一轮工作（已合并）已经把持久化收敛为一表一类、跨表编排归领域层，并留下三份整记录表征用例作为守卫。那一轮解决的是「谁来编排」，没有动表本身的边界；本任务动的正是表的边界。

## Goal

让每一张表对应一个概念，并且同一个概念在库里只有一处承载——把今天由协议分段造成的重复、分裂与遗留形状一次清除，同时对外协议行为一字不变。

## Scope

### In

- 物品：让任意归属下的一件物品由同一处承载，无论持有它的是角色背包、账号仓库还是称号册；退役只被用来做空判的上一代物品表；让按件的附加信息不再自成一表。凡记的不是一件东西而是一类东西（例如收集箱记的是模板号），不属此列。
- 角色本体：把切分线从「协议包第几段」换成概念线——身份、派生数值、运营态。
- 每角色至多一行的状态：其列若属于已有归宿的概念则迁入该处，该表随之消失；若本身是一个无处可归的概念则保留。不得只因为「至多一行」而存在一张表。
- 技能：同一个概念不因它服务 PVE 还是 PVP、不因它属于哪个职业而重复承载。红线优先于本条——若合并需要引入一个重新解释载荷列的判别列，则不合并。
- 账号：每个概念只有一处承载。
- 对每一处「合并」与每一处「看起来像但不合并」，给出判据如何成立或不成立的裁定，包括邮件附件是否属于物品这一处。
- 同一件事的状态不分散在多处；不同的事不因名字相似而被收敛到一处。
- 让今天由整记录表征用例守住的每一列，在新形状下仍有用例守住。
- 领域层的跨表组装随表形状更新。

### Out

- 不把语义不同的表压成通用键值行。
- 不为既有数据编写回填、修复或迁移路径。
- 不改变对外协议行为，包括下发内容、字段顺序与错误路径。
- 不退回上一轮已确立的形状：持久化类仍只指名一张表，跨表组装仍在领域层且每条记录只有一个定义点。
- 不改动 `Tool/` 与 `.worktrees/legacy-reference/`；不改动客户端可执行文件与 DLL。

## Constraints

- 合并判据（用户确立）：同一个键、同一个生命周期、同一个写入用例，三条同时成立才可合并进一张表；仅「名字相近」不足以合并。
- 红线（用户确立）：不得把不同概念压成 `(kind, key, value…)` 形态的通用行。理由是它把上一轮刚治掉的「库里存着查不出含义的东西」换了个形式重新引入。
- 开发阶段擦库不迁移：直接以新形状建库，不得为既有数据写回填、修复或迁移路径。
- 今天被表征用例覆盖的列，改动后必须仍被覆盖；覆盖可以重写，不可净减少。
- 对外协议行为一字不变。
- 全程不产生任务级提交；仅在评审与新鲜验证通过后做唯一一次已接受结果提交。
- 测试以单进程方式运行（`-m:1`），并需 `PVF_ARCHIVE_PATH` 与 `Pvf__ArchivePath` 指向 `D:/project/DNF/DNFClient-debug/Script.pvf`。
- C# 文件为 CRLF、无 BOM UTF-8；目标框架 net10.0，警告即错误。
- `protocol/` 目录不得含凭据、令牌、聊天隐私或个人可识别信息；C→S `0x0001` LOGIN 样本不得入库。

## Assumptions

- 上一代物品表（角色物品、账号仓库物品）在生产代码中没有写入路径，只被问「空不空」。若实施中发现存在写入，物品域的边界需要重新裁定。
- 两处租借承载的是同一个概念，其列语义可以一一对应。
- 目标是本机开发库，现有数据可直接丢弃，没有需要保留的持久数据。
- 六处「每角色至多一行」的状态确实至多一行；若某一处实际可有多行，它不属于折入角色本体的那一类。
