# TaskContract: 账号级晶体与稀有度灵魂背包重构

## Context

### Source Request

用户要求将晶体与五种稀有度灵魂实现为账号级 Bag：不同角色通过同一套获取方式访问同一账号记录；清理材料栏中错误的晶体和灵魂后，以新实现继续实机测试。宇宙灵魂暂时仍按普通角色材料处理。用户明确授权：“可以，就这样实现一个重构。我把材料里的错误cube和soul丢弃。后面你启动新的后再测试”。

### Current Situation

当前入场读模型已从账号表投影六种晶体到主背包虚拟槽，但缺少可参与领域事务的账号材料聚合；五种稀有度灵魂尚未按账号资源持久化和投影。装备分解把规则产物统一规划进角色材料槽，因而晶体与稀有度灵魂会形成错误的角色材料记录和客户端状态分叉。

## Goal

建立唯一的账号级晶体与稀有度灵魂状态，使同一账号下不同角色读写同一份资源；分解按产物类型在一个业务事务中删除角色装备、消耗便携分解机并增加正确的账号或角色材料；客户端继续通过 A21 固定虚拟槽看到权威数量。

## Scope

### In

- 账号级六种晶体与五种稀有度灵魂的领域实例、Store、持久化与加载。
- 同账号不同角色获得同一逻辑账号材料状态。
- 装备分解产物分类、事务结算与客户端同步。
- A21 主背包虚拟槽 354..364 的账号资源投影。
- 自动化回归测试以及协议/架构文档中的服务端玩法策略说明。

### Out

- 宇宙灵魂账号化；它继续作为角色普通材料。
- 自动迁移或保留用户已主动丢弃的材料栏错误晶体/灵魂。
- 分解产出公式、便携分解机等级规则以及其他背包系统重写。
- 合并、部署、启动服务和工作区清理；这些在实现验收后另行处理。

## Constraints

- 账号材料状态必须只有一个持久化真源；角色普通材料槽不得继续保存晶体或五种稀有度灵魂。
- 角色装备/便携分解机变化与账号材料增加必须共享一次业务事务，失败时整体不生效。
- 宇宙灵魂及其他非账号材料仍遵循现有角色背包规则。
- 协议事实、A21 原始语义和本服玩法策略必须在文档中明确区分。

## Success Conditions

| ID | Observable condition | Required evidence |
|---|---|---|
| SC-1 | 同一账号的两个角色读取到相同的晶体和稀有度灵魂数量，另一账号不共享 | 账号所有权与持久化集成测试通过 |
| SC-2 | 分解产生晶体或五种稀有度灵魂时，不创建角色材料槽记录，而是增加账号资源 | 分解领域与持久化回归测试验证最终状态 |
| SC-3 | 分解产生宇宙灵魂或其他材料时，仍进入角色普通材料背包 | 分类边界测试通过 |
| SC-4 | 装备移除、便携工具消耗、角色材料和账号材料在失败时一起回滚 | 事务失败注入或等价的原子性测试通过 |
| SC-5 | 客户端入场及分解后可收到槽 354..359 的晶体和槽 360..364 的五种灵魂权威数量 | 协议投影与通知编码测试通过 |
| SC-6 | 文档明确记录虚拟槽线协议事实、本服账号级策略及宇宙灵魂例外 | 协议/架构文档审查无混淆表述 |
| SC-7 | 解决方案构建和相关测试通过，未留下新旧两套写入路径 | 完整 diff 审查、构建与测试结果 |

## Requires Confirmation

- 合并到主干、部署/启动服务以及删除任务工作区需要后续明确授权。

## Assumptions

- 当前运行环境是单逻辑游戏服务器，因此账号材料以 AccountId 为所有权键；模型不把进程内对象引用相等当作跨进程契约。
- 用户会在新版本实机测试前自行清除角色材料栏中既有的错误晶体和稀有度灵魂。
