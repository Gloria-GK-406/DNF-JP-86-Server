# Implementation Plan: 账号材料聚合与分解结算归一

## Planning Choice

采用 direct 计划。改动虽跨越 Abstractions、Application、Persistence、Protocol 与测试，但执行方向稳定，所有步骤围绕同一个账号材料聚合，详细计划可以在一处维护；不需要可独立交付或恢复的 Task Unit。

## Approach and Shared Decisions

- 在领域层建立由 `AccountId` 唯一确定的账号材料实例和服务。服务负责按账号复用实例，实例提供读取快照及类型化增加行为；对象引用复用是进程内实现，账号键和持久化记录才是业务身份。
- 建立账号材料 Domain Store，并让 SQLite 实现作为现有 `SqliteDatabaseParticipant` 的独立 facet 加入事务。它与角色物品 Store 使用同一数据库参与者，因此一个分解命令只产生一次可失败提交。
- 保留现有 `accounts.cube_*` 为六种晶体真源，在同一账号记录增加五种稀有度灵魂字段。入场读取和运行时写入统一经账号材料模型，删除仅供晶体读取的旁路语义。
- 以集中映射定义受支持资源的 itemId、类别、客户端槽位与持久化位置。分解规则仍只负责返回 itemId/count；结算层按该映射把账号资源与普通材料分流。
- 分解回执把“本次产物”和“最终账号虚拟资源绝对值”分开表达。协议 ACK 保留产物列表语义，NOTI 0x000E 对主背包虚拟槽发送绝对数量；角色材料槽继续走既有更新路径。

## Work and Dependencies

### T-001：建立账号材料类型与聚合契约（RQ-001、RQ-002、RQ-003）

- 在 Data/Abstractions 定义账号材料快照、受支持资源映射、Bag/Service/Store 会话契约。
- 在 Application 实现账号材料实例和按 AccountId 缓存的服务；读取及变更自动加入当前领域事务，没有环境事务时使用独立事务完成一次操作。
- 用单元测试锁定同账号实例复用、不同账号隔离、类型约束、非正数量与溢出拒绝。

### T-002：实现 SQLite 账号材料真源（依赖 T-001；RQ-001、RQ-003、RQ-006）

- 扩展账号表五种稀有度灵魂字段及既有数据库迁移声明。
- 实现账号材料 Store facet：事务内读取能看到本会话暂存变化，prepare 时以受约束更新写入账号行，失败由数据库参与者统一回滚。
- 让入场账号虚拟资源从账号材料快照生成 354..364 投影，保留零值省略策略和固定映射。
- 增加 schema、持久化、同账号跨角色及另一账号隔离测试。

### T-003：重写分解产物结算（依赖 T-001、T-002；RQ-004、RQ-005）

- 在规划阶段先分类产物：账号资源只校验数量边界，不占角色背包空间；普通材料沿用现有堆叠与空槽规划。
- 在同一 transactional command 中暂存装备删除、便携工具消耗、普通材料写入和账号材料增加。
- 回执保留所有规则产物，同时分别记录角色槽最终状态和发生变化的账号资源最终绝对值。
- 覆盖纯晶体、纯稀有度灵魂、混合产物、宇宙灵魂、角色背包已满但只有账号产物、以及账号写入失败整体回滚。

### T-004：完成协议同步与文档（依赖 T-003；RQ-006、RQ-007、RQ-008）

- 让分解完成投影对角色槽继续发送既有清除/占用更新，对账号资源发送主背包虚拟槽的 NOTI 0x000E 绝对状态。
- 确认同账号其他在线角色的显示不会长期滞后：账号材料变化事件以账号为受众，至少更新当前操作角色；若现有通知目录支持同账号多连接，则覆盖全部当前角色。
- 更新 NOTI 0x000D/0x000E 或相邻架构文档，分别说明线格式、历史证据、本服账号级策略和宇宙灵魂例外。
- 增加协议消息顺序、槽位映射和编码测试。

### T-005：删除旁路并集成验证（依赖 T-001..T-004；RQ-001..RQ-008）

- 搜索并移除直接读取 `FindCubeFragmentsAsync` 或把账号资源规划进普通材料槽的生产路径；只保留必要的底层持久化实现。
- 运行相关项目测试、解决方案构建及完整测试；审查完整 diff，确认没有双真源、未授权迁移或宇宙灵魂账号化。

## Verification

- Application：账号实例身份、资源映射、分解分类、混合结算、容量与宇宙灵魂边界测试。
- Persistence：schema 与账号材料 Store 的读取、暂存可见性、跨角色共享、跨账号隔离和 SQLite 失败回滚测试。
- Protocol：入场 354..364 快照和分解后 0x000E 绝对状态测试，ACK 产物列表保持兼容。
- Integration：现有 NPC/便携分解全链路测试扩展为账号资源，并验证装备、工具、普通材料和账号余额共同回滚。
- 最终运行 `dotnet build Server/86JP.Server.slnx` 与相关/完整测试集；完整 diff 审查必须证明生产代码不存在第二条账号材料写入路径。
