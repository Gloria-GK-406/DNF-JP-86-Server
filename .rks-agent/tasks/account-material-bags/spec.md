# Specification: 账号级晶体与稀有度灵魂单一真源

## Why and Outcome

晶体和五种装备稀有度灵魂是客户端主背包中的固定虚拟资源，而不是可占用普通材料槽的物品。本服需要让同一账号下的所有角色共享一份权威数量，并让分解结算直接更新该账号状态，消除账号虚拟槽与角色材料槽同时保存同类资源造成的状态分叉。

## Scope

本规格覆盖六种晶体、普通/高级/稀有/神器/传说五种灵魂的账号所有权、领域访问、持久化、分解结算、入场投影与分解后同步。宇宙灵魂及其他材料仍属于角色普通背包；既有错误材料行由用户在测试前自行清除，本任务不做历史数据迁移。

## Definitions and Invariants

- `AccountMaterialBag`：由账号标识唯一确定的逻辑聚合，包含类型受限的晶体余额和稀有度灵魂余额。
- “同一实例”指相同账号键始终解析到同一逻辑权威状态；进程内对象引用复用可以作为 Store 实现，但引用相等不是跨进程契约。
- 账号材料数量不得为负，也不得溢出客户端和持久化所支持的数值范围。
- 晶体与五种稀有度灵魂不得作为普通角色材料结算；宇宙灵魂不得进入账号材料聚合。
- A21 固定投影为晶体槽 354..359、稀有度灵魂槽 360..364；槽位与 itemId 映射唯一。

## Requirements

| ID | Requirement |
|---|---|
| RQ-001 | 账号材料服务必须按 AccountId 提供唯一逻辑 `AccountMaterialBag`，同账号角色共享状态，不同账号隔离。 |
| RQ-002 | 账号材料聚合必须仅接受已知六种晶体和五种稀有度灵魂，并拒绝负数、溢出或未知类型变化。 |
| RQ-003 | 晶体和稀有度灵魂必须只持久化于账号材料真源；角色普通材料槽不得承载新的同类产物。 |
| RQ-004 | 分解结算必须将规则产物分类为账号晶体、账号稀有度灵魂或角色普通材料，并把装备删除、便携工具消耗和全部产物变化原子提交。 |
| RQ-005 | 宇宙灵魂以及所有未列入账号资源映射的材料必须继续按现有角色背包容量、堆叠和槽位规则处理。 |
| RQ-006 | 角色入场必须从账号材料真源生成固定虚拟槽快照；零数量的传输形状保持与既有 A21 投影约定一致。 |
| RQ-007 | 分解成功后，发给客户端的状态变化必须包含所有已改变的角色槽以及改变后的账号虚拟资源绝对值，且不得把账号资源伪装成角色材料槽。 |
| RQ-008 | 协议文档必须区分线上槽位事实、原版版本语义与本服账号级玩法策略，并明确宇宙灵魂例外。 |

## Acceptance Criteria

| ID | Covers | Criterion |
|---|---|---|
| AC-001 | RQ-001, RQ-003 | 给定同一账号的两个角色和另一账号的角色，当任一同账号角色增加晶体或稀有度灵魂后重新读取，前两个角色看到相同数量，另一账号数量不变，且角色材料槽没有该资源。 |
| AC-002 | RQ-002 | 对每个受支持 itemId 增加合法数量均得到对应余额；未知 itemId、非正增量、负结果或溢出不会产生部分写入。 |
| AC-003 | RQ-004 | 给定可分解装备及可选便携分解机，当产物同时包含账号资源和普通材料时，成功结果同时删除装备、消耗一次工具、增加账号余额并写入角色材料。 |
| AC-004 | RQ-004 | 在账号余额写入或角色材料写入发生失败时，装备、便携工具、角色材料和账号余额全部保持操作前状态。 |
| AC-005 | RQ-005 | 产物为四种宇宙灵魂之一时，它按普通材料进入角色背包并受容量限制，账号稀有度灵魂余额不变。 |
| AC-006 | RQ-006 | 账号快照按 354..359 与 360..364 的固定映射编码；两个同账号角色的投影一致，不同账号独立。 |
| AC-007 | RQ-007 | 分解完成通知/响应使客户端能够以绝对状态刷新账号虚拟资源和实际改变的角色槽；结果列表仍表达本次分解产物。 |
| AC-008 | RQ-008 | 文档包含本服策略标签，且未把账号持久化所有权写成仅由客户端报文证明的 `ClientVerified` 事实。 |

- EV-003：入场与分解同步的协议测试覆盖虚拟槽映射和绝对值投影，覆盖 AC-006、AC-007。
