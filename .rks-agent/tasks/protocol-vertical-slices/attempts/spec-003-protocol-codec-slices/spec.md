# Specification: Protocol Codec Slices

## Why and Outcome

一个协议的事实目前仍被拆散在两个编译单元里：它的线上标识、解包、编码与组帧散落在承载传输的 `Dfo.Server.Networking` 的一个共同 `Framing` 目录下，与真正的传输物（帧头拆装、TouchSocket 适配、连接注册表、加密原语）混在一起，按文件名首字母排列。读者要回答"这个协议怎么收、怎么发"，必须在一个混杂目录里按名字凑齐分散的文件，而"哪些是协议、哪些是传输"没有任何结构上的表达。

本成果之后，协议内容与传输分属两个编译单元；协议单元内每个协议有一个自己的目录，该协议的入站解包与出站编码在同一处可见；承载传输的单元只剩传输。协议与传输的分界从"读者的经验判断"变成"编译期的项目边界"。

这是一次纯结构迁移。它的价值全部在结构，因此它的主张是"除位置外什么都没变"，而这一主张本身必须可被独立核验。

## Task Perspective

- Core outcome: 协议内容以"一协议一目录"的形态存在于一个与传输分离的独立编译单元中，且该迁移未改变任何行为。
- Necessary support: 编译期依赖方向必须是协议单元依赖传输单元而非相反；跨编译单元访问所需的可见性放宽必须取最小必要范围；协议接线的两张路由表随协议内容迁移且其"无条件生效"的既有性质不变。
- Peripheral assurance: 零逻辑变更的逐文件比对结论、可见性改动的逐项交代、既有断言未改的证明，以及全量测试对齐基线。

## Scope and Non-Goals

### In Scope

- 协议内容与传输内容分属两个独立编译单元。
- 协议单元内按协议组织的目录形态，覆盖全部已实现的入站协议与出站消息。
- 协议接线的入站与出站两张路由表随协议内容迁移，并保持其注册不受监听开关影响。
- 被多个协议共用的编解码件在迁移后仍只有一份。
- 针对被迁移编解码的既有测试随之迁移；针对传输的测试留在原处。
- 迁移直接导致的失效引用修复，包括原先靠父命名空间隐式可见的类型引用与失效的文档交叉引用。

### Non-Goals

- 消息 DTO、消息 handler、命令与命令 handler 的迁移。它们的迁移会使仍留在应用层的消息 handler 反向依赖协议单元，与协议单元对应用层的依赖构成循环。
- 项目级文档中协议开发动作与切片边界规则的更新，以及消息 handler 业务语义边界的审计。
- 任何字节布局、加密参数、组帧规则、投递次序、解包判定与丢弃语义的改变。
- 共享字段读写原语的抽取与越界语义的统一。
- 传输内容的重写或重组。
- 新增或删除任何协议、消息或注册项。

## Constraints

- 本次变更除文件位置、命名空间、using、可见性修饰，以及迁移直接导致的失效引用修复之外，不得包含任何行为改动。任何被迫的例外须逐处列明并说明其不可避免性。
- 承载传输的编译单元不得依赖承载应用逻辑或协议内容的编译单元。
- 线级可观察行为必须不变：未知线上帧键静默丢弃、出站按端点校验、Channel 载荷的加密与压缩参数、Game 出站帧头、选择角色的静态帧流与补充投影的有序投递及其失败补偿次序、登录失败体仍不可编码。
- 可见性放宽仅限跨编译单元访问所必需者，且取最小必要范围。不得以放宽类型、抑制诊断或关闭"警告即错误"的方式换取编译通过。
- 既有 580 项测试须全部继续通过，且断言内容不得改动；迁移可改变测试的位置、命名空间与 using。

## Definitions

| Term | Meaning |
|---|---|
| 协议内容 | 与某条具体消息绑定的编解码事实：线上标识、入站解包、出站编码、以及只服务于该消息的组帧与投影件 |
| 传输 | 与具体消息无关的承载机制：帧头拆装与组装、字节流适配、连接注册与生命周期、端点级载荷保护 |
| 切片 | 协议单元内属于同一个协议的一组文件所在的目录 |
| 路由表 | 把线上帧键绑定到解包器、把出站消息绑定到编码器与其端点的一处集中注册声明 |

## Assumptions

- 被迁移的编解码只依赖抽象层接缝、数据契约与传输原语，不依赖应用逻辑单元的类型。若实施中发现反例，协议单元的引用图前提失效，须停在该处评估而非放宽引用方向。
- 端点级载荷保护属传输而非协议：它与具体消息无关，且已被同端点的多条消息共用。
- 迁移前为编译单元内可见的编解码类型，在迁移后的协议单元内可继续保持同等可见性；只有确实被跨单元消费的部分才需要放宽。
- 基线中存在一次未复现的宿主启动测试瞬时失败。同类瞬时失败不得计为本成果的回归，但须在结果中如实记录其发生。
