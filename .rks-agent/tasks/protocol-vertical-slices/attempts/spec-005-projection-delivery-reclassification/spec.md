# Specification: Projection Delivery Reclassification

## Why and Outcome

服务端有一个类型被当成消息对待，但它不是消息。它不含任何线上字段，它装的是领域投影和**收件人**——其余任何消息都不携带自己的收件人。它表达的是一份扇出投递计划："这批必送这个连接，那几批尽力送那几个连接。"

被误标为消息带来三个可观察的后果：它占用了一个消息目录值，与真正的选择角色响应共用同一个值，使目录不再一值一义；它使投递计划得以被传进"发送一条消息"的接缝，而那条路径上并没有能编码它的东西，只会在运行期失败；它把一个投递策略概念锁在数据契约单元里，而使用它的只有传输实现与声明投递接缝的抽象单元。

本成果之后，投递计划位于声明投递接缝的抽象单元内，不再实现消息接口、不再占用目录值；把投递计划误当消息发送在编译期就不成立。投递本身的次序、失败隔离与所产字节一字不变。

## Task Perspective

- Core outcome: 投递计划不再是消息——它位于投递接缝一侧，且误用它的路径在编译期即被关闭。
- Necessary support: 投递接缝的形态改变不得引入新的编译期依赖方向；受影响的测试替身须自行满足新的接缝形态。
- Peripheral assurance: 投递次序、失败隔离、空值校验与所产字节不变的证明，被调整测试替身的断言强度未下降的证明，以及全量测试对齐基线。

## Scope and Non-Goals

### In Scope

- 投递计划类型及其目标记录归位到声明投递接缝的抽象单元。
- 去掉投递计划类型的消息接口实现与目录值报告。
- 投递接缝方法由带回退实现的成员改为每个实现者必须自行实现的成员。
- 因接缝形态改变而必须自行实现该方法的测试替身的调整。
- 同步以"两个类型共用同一目录值"为依据的既有说明性注释。

### Non-Goals

- 投递次序、失败隔离、空值校验与所产字节的任何改变。
- 领域投影类型及其实现的迁移或改写。
- 出站编码按消息 CLR 类型建键这一既有结论的改变。
- 消息目录其余成员的增删或取值改变。
- 消息 DTO、消息 handler、命令与命令 handler 的切片归位。
- 任何协议语义、字节布局与加密参数的改变。

## Constraints

- 投递路径的可观察语义必须不变：必送批次先于尽力批次、尽力目标失败不影响后继目标、取消异常照原样上抛、与必送连接相同的目标被跳过、以及投递前的空值校验及其异常类型。
- 投递所产字节必须逐字不变。
- 承载抽象的编译单元不得依赖承载协议内容或应用逻辑的单元；承载传输的单元不得依赖后两者。
- 不得以放宽类型、抑制诊断或关闭"警告即错误"的方式换取编译通过。
- 既有 580 项测试须继续通过。仅当某测试替身因接缝形态改变而必须自行实现该方法时方可调整它，且其断言强度不得下降。

## Definitions

| Term | Meaning |
|---|---|
| 投递计划 | 描述一次投影扇出的值：一批必送内容，加上若干各自带收件人的尽力批次 |
| 消息 | 有线上表示、由编码器变成帧、由调用方指定单一收件人的类型 |
| 投递接缝 | 抽象单元中声明"按投递计划发送"的方法 |
| 消息目录 | 出站消息身份的枚举，本成果不改变其成员与取值 |

| ID | Requirement |
|---|---|
| RQ-001 | 投递计划及其目标记录位于声明投递接缝的抽象单元内 |

| RQ-003 | 把投递计划传入"发送一条消息"的接缝在编译期不成立 |

| RQ-006 | 投递路径的次序、失败隔离与空值校验语义不变 |
| RQ-007 | 投递所产字节不变 |
| RQ-008 | 编译期依赖方向未放宽 |
| RQ-009 | 被调整的测试替身其断言强度不低于调整前 |

## Assumptions

- 抽象单元已直接引用连接标识与领域投影这两个类型，故归位不引入新的依赖方向。
- 全部生产实现者已自行实现投递接缝方法，故去掉回退实现是纯收紧而非行为变更。
- 基线中存在一次未复现的宿主启动测试瞬时失败。同类瞬时失败不计为回归，但须如实记录。
