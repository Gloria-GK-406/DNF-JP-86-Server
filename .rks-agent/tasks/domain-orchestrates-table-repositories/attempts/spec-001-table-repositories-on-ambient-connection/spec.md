# Specification: 九个仓储退回单表读写并接入用例边界

## Why and Outcome

今天"仓储"这个名字与它做的事不符。一个类读 33 张表拼出一条入场记录，另一个读 14 张表拼出背包。它们不是存储访问，是某个业务场景的取数过程，住在 SQL 层——领域层拿到的是成品，既无法复用也无法被自动化。

同时它们各自开连接、各自提交。一次用例内的多处改动因此没有共同结算点，多次读之间也没有共同快照：一次入场装载读几十次，别人的提交可以插进任意两次之间。今天没暴露只因并发低。

要成为真的：**仓储只表达单张表的读写，连接与事务由当前用例给定，跨表的取数编排归领域层且只有一处。**

## Task Perspective

- Core outcome: 领域层能够自己编排取数——它向若干只认一张表的仓储要行，自己拼出需要的记录；仓储不再替它做这件事。
- Necessary support: 编排要成立，那些读必须落在同一次用例的同一个连接与同一个事务里，否则拼出来的是撕裂快照，比今天更糟；写同样如此，否则拆分会把今天的 26 次独立提交放大成上百次。
- Peripheral assurance: 单表边界的清点、自开连接归零的清点、组装唯一性的清点，以及帧字节与全量不变的证据。

## Scope and Non-Goals

### In Scope

- 九个仓储按其触及的表拆分，拆出的每个仓储只读写一张表。
- 仓储的连接与事务由当前用例边界给定，不再自行开启。
- 一次用例内的读落在同一个数据库事务内，读之间不被其他连接的提交穿插。
- 入场装载的跨表组装移入领域层，且在领域层只有一处定义。
- 移除因建表集中化而恒为真的表结构元数据探查。
- 既有测试随类型与依赖变化作机械调整。

### Non-Goals

- 不动物品容器路径的存储与会话。
- 不退役内存载体构造。
- 不引入泛型仓储或字段映射机制。
- 不改变以字节形式存储的列的形状。
- 不改数据库的表与列，不为既有数据编写回填、修复或迁移路径。

## Constraints

- 对外可观察行为一字不变。协议帧的字节与时序，以及既有测试的语义，只允许因类型或依赖变化作机械调整。
- 一次用例内的多处改动必须全有或全无，不得因拆分退化为逐条提交。
- 跨表组装在领域层只能有一处定义。散入多个调用方与本 Spec 目标相反。
- 仓储不得声明表结构，也不得查询表结构元数据。
- 开发阶段擦库不迁移：不得为既有数据编写回填、修复或迁移路径。

## Definitions

| Term | Meaning |
|---|---|
| 单表仓储 | 其全部语句只提及一张表的读写单元。表名出现在语句中即算提及，不因语句是读还是写而区别对待。 |
| 用例边界 | 一次业务操作的起止范围，由命令管线开启与结算。落在其内的持久化访问共用同一连接与同一数据库事务。 |
| 跨表组装 | 把多张表的行拼成一条供上层使用的记录的过程。它是编排，不是存储访问。 |

## Observable Requirements

| ID | Requirement |
|---|---|
| RQ-001 | 每个仓储的全部语句只提及一张表。 |
| RQ-002 | 仓储不自行开启数据库连接，也不自行开启或结算数据库事务。 |
| RQ-003 | 一次用例内的多次读看到同一份快照：读与读之间，其他连接已提交的改动不可见。 |
| RQ-004 | 一次用例内对多张表的改动全有或全无。 |
| RQ-005 | 入场装载的跨表组装位于领域层，且在领域层只有一处定义。 |
| RQ-006 | 持久化实现不查询表结构元数据。 |
| RQ-007 | 建表归属不变：拆分不引入任何新的表或列声明。 |
| RQ-008 | 对外可观察行为不变：协议帧的字节与时序与改造前逐字相同。 |

## Assumptions

- 九个仓储触及的每张表都能被单独读写。若某张表的写必须与另一张表在同一语句内完成，该仓储脱离本 Spec 的接受边界。
- 一次用例内的读进入数据库事务后，与另一条连接的写之间可能产生锁竞争。在本项目的并发水平下，该竞争不构成可观察的可用性问题。
