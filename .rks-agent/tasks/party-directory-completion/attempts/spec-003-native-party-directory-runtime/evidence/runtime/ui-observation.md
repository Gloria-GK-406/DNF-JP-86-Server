## 用户完成的原生操作序列

用户报告并在同一轮运行中完成：

1. 两个账号分别建立标题 `A`、`B` 的队伍，在相同区域列表中同时可见。
2. `A` 队伍变更为“强强联合”，另一端可见同一行更新。
3. `A` 队伍解散，另一端先看到该行标记“已取消组队”。
4. 点击原生刷新后，取消组队的行消失，只剩 `B` 队。

运行时身份对齐：

- `DNFClient-A21-protocol/DNF.exe`，PID `37064`，character/user `2`：`A` 队创建者及解散者。
- `DNFClient-A21-protocol2/DNF.exe`，PID `63228`，character/user `1`：`B` 队队长，也是观察端。

## 截图时点客户端回读

## 运行时例外与证据边界

截图明确闭合了原生主目录的 UI 身份，但在两个客户端中对静态 final vptr `0x031FFFD4` 的全可读内存扫描均
只命中代码常量 `0x00F712AD`、`0x00F747CC`，没有命中堆实例。因此本轮不把 `this+0x188` 直接向量回读
伪装为已完成；客户端对象层改由当前 CNUser/CParty 关联、存活 party 集合和用户原生 UI 共同支撑。静态
final-vptr 是否仅在特定焦点/生命周期阶段存在，留作独立客户端逆向问题，不改变本轮已观察的服务端目录行为。

## 独立审查补证 UI 序列

独立审查指出首轮客户端对象快照只落在删除后。用户随后在新的隔离 runtime、同一 pro1/pro2 客户端组合中
完成补证：

1. pro1 再建 A，pro2 确认 A/B 同时可见；
2. pro1 将 A 切换到预设标题，pro2 确认同一行更新；用户对本次显示文本的原话为“强强联合\~”；
3. pro1 解散 A，pro2 原生刷新后确认 A 消失、只剩 B；
4. 用户正常退出两个客户端。

UI 文本只作为用户观察记录；wire 结论保持为 `titleIndex=1`，不把本地化文本或末尾 `~` 解释为网络载荷。
本次三时点对象快照进一步把可见行绑定到同一 `partyId=3` / CParty 地址，并直接记录 `titleIndex 0 -> 1`
及 clear 后对象消失。
