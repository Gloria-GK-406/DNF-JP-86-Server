# TaskContract: 地下城失败虚弱与自然恢复

## Context

### Source Request

“可以，就按这个方式来实现吧。信息已经足够吧？需要走任务契约嘛？”

### Current Situation

NOTI 0021 的 32/100 登录实验已由用户实机确认。自然恢复和失败施加尚未实现。20 级、初始 10、60 秒增加 9 点是用户选定本服规则，不宣称 A21 原服已证实。

## Goal

失败离开地下城后正确施加虚弱，并在城镇和离线期间统一恢复；入本暂停，登录和回城显示当前值。

## Scope

### In

- 等级至少 20 的角色未通关退出（主动退出、全灭、断线/客户端崩溃）施加虚弱；通关后离开不施加。
- 内存虚弱系统、统一调度、进出副本与登录投影；配置和回归验证。
- SetWeakness 无任意数值参数，Recover 完全恢复；幂等暂停/恢复自然恢复。

### Out

- 金币恢复定价及 CMD 0009 付费业务、免虚弱资格、疲劳、任意值管理接口。
- 持久化、重启后补算、客户端修改。

## Constraints

- 初始值默认 10，门槛默认 20，每 60 秒增加 9 个百分点，可配置；最大 100。
- 一个统一周期，不做每角色 timer，不补算漏过周期；首次恢复接受周期相位差。
- 内存记录值及恢复开关，100 删除记录，无记录返回 100；重启重置。
- 进入地下城暂停恢复而保留数值；离线继续恢复，不删除记录。
- 失败退出按实际 run 一次结算，重复清理不重施加。客户端已有属性缩放，不再下调服务端属性形成双重惩罚。

## Success Conditions

| ID | Observable condition | Required evidence |
|---|---|---|
| SC-1 | 19 级免罚，20 级失败退出为 10，成功退出不施加，重复退出不重置恢复值 | 领域和生命周期行为测试 |
| SC-2 | 活跃恢复值 10 经十个周期到 100，暂停不变，重复暂停/恢复安全，满值删除 | 确定性周期测试 |
| SC-3 | 断线后继续恢复，重登读现值，新的服务实例无旧虚弱 | 离线生命周期与新服务测试 |
| SC-4 | 登录、回城、在线 tick 发当前 NOTI 0021，入本不继续恢复；旧登录实验不覆盖真实值 | 协议/集成测试和用户实机步骤；实机由用户执行 |
