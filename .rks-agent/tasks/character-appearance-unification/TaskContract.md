# TaskContract: 角色外貌统一计算与登录投影

## Context

### Source Request

“对，这样就差不多了。写任务契约实施吧，注意的点是将所有要归一到一起的逻辑完成归一。不要再有独立计算外表的地方了。实现后直接部署，我来测试看看效果”

### Current Situation

基准1e146ba1；task/next-round-20261013。主设置blob已持久化，在线保存可刷新显隐；角色页与首次登录仍未遵循关闭职业装扮的配置。装备部件计算与可见性计算分离，角色列表存在两份编码与固定显示字段。

## Goal

建立唯一角色外貌计算路径，统一角色列表、首次登录和在线刷新；人物实例提供自动适配职业阶段的外貌候选，独立规则服务根据候选、装备及显示配置返回最终语义结果。部署后由用户验证客户端效果。

## Scope

### In

- 人物的普通、当前职业、当前觉醒候选外貌及未转职/未觉醒回退。
- 所有玩家角色外貌计算与协议投影调用方扫描和归一，包括角色页、登录、换装、职业进阶、设置变化、同屏同步。
- 回归验证、协议证据边界更新、本地提交、备份与部署。

### Out

- 修改客户端补丁、改动技能、重新设计角色持久化、发布PR或Release。

## Constraints

- 主设置blob仍是显示选项唯一真源，不双写可见性字段。
- 人物候选不依赖用户显示配置；规则只消费显式参数，不能自行读取角色存储或发送通知。
- 复用当前工作分支，不另开分支；保留已有未跟踪缓存。
- 客户端负责原资源绘制，服务端返回其支持的外貌语义，不能虚构资源ID。

## Success Conditions

| ID | Observable condition | Required evidence |
|---|---|---|
| SC-1 | 未转职/未觉醒和已进阶角色均有有效候选，无需调用方重复判断阶段 | 候选与规则回归 |
| SC-2 | 所有外貌路径消费同一结果，协议编码器仅做格式映射 | 调用方扫描矩阵及独立审查 |
| SC-3 | 已关闭设置用于角色页与首次登录初始化，在线变化沿用EventBus刷新 | 完整路径编码/顺序回归及客户端静态依据；实机验收待用户 |
| SC-4 | 装备/透明外观/称号和未知位兼容，无新增设置状态双写 | 相关回归与数据库结构对比 |
| SC-5 | 新运行版本可追溯且服务启动成功 | 数据库备份完整性、版本/进程/监听/健康检查 |

|---|---|---|
| task | 本文Source Request的完整执行与部署授权 | 本次归一重构、契约/Spec/验证/独立审查、本地提交及部署 |

## Assumptions

- A21客户端的职业原生装扮由职业阶段和显隐状态驱动，不保证存在可替换的普通装备模板ID；候选可用语义值描述。
- 自动化与静态分析不能替代用户的实机显示验收。
