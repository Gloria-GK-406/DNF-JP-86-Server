# 角色外貌归一

基准：1e146ba1；日期：2026-10-14。

## 结构与职责

改前：DrawnAppearance计算装备部件，CharacterEntry临时计算VisibilityBits，设置通知另算位，两个Roster编码器写固定显示尾部。职业候选和显示结果无统一模型。

改后：ICharacter提供当前身份对应的普通/职业/觉醒候选，未转职及未觉醒自动回退。独立ICharacterAppearanceRuleService仅根据显式候选、已穿戴装备、显示选项及兼容位返回不可变CharacterAppearance。领域编排负责读取事实，Protocol只将统一结果适配到A21各消息。不得通过修改协议真实职业身份模拟隐藏职业装扮。

## Requirements and Acceptance

| Requirement | Outcome | Acceptance |
|---|---|---|
| RQ-001 | 人物候选自动适配职业阶段，普通候选始终为基础职业；无需消费者判断是否转职/觉醒 | AC-001：未转职、转职、一觉、二觉及特殊职业回退测试 |
| RQ-002 | 纯外貌规则组合装备/透明装扮/称号与三个设置开关，无存储和通知副作用 | AC-002：相同输入相同输出、未知位保留、候选选择与装备覆盖回归 |
| RQ-003 | 角色页和首次登录使用统一外貌，后发消息不覆盖为固定默认 | AC-003：角色页与登录列表编码一致；首次进入初始化顺序/格式和关闭设置回归；客户端静态字段依据 |
| RQ-004 | 换装、职业进阶、称号、同屏、保存设置均复用统一路径 | AC-004：全生产调用扫描，移除独立计算，独立审查矩阵 |
| RQ-005 | blob仍原样存取，不能双写可见性或伪造外貌模板；通知经EventService | AC-005：设置持久化/事件/事务回归及差分审查 |
| RQ-006 | 部署可识别的新版本且保留回退文件 | AC-006：相关测试通过、备份完整性、进程/程序集/监听/HTTP身份核验 |

## Evidence boundary

Native模型创建是否早于0165不能仅靠服务器发送日志证明。核对实际客户端取值后修正消息数据或明确创建后的刷新时机，不用固定延时规避。服务端自动化与ClientStatic只作为部署依据；角色页、首次登录、在线切换的实机效果由用户验收。
