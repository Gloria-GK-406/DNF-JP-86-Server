# Specification: 城镇区域聚合与副本主动退出闭环

## Why and Outcome

服务器需要把“谁当前处在某个城镇小区域、站在哪里”作为独立的领域事实，而不是从连接、监听端口或各个协议命令临时拼出来。完成后，角色选角进入、选图离开、取消返回、进本、回城、跨区、同区移动和断线都改变同一份区域状态；状态提交后产生可投影事件，使区域内所有在线角色获得一致视图。副本中的单人主动放弃同时执行退队，正常完成和取消选图则保留队伍。

## Scope

本规格覆盖城镇区域成员与位置的领域模型、会话到角色的应用层桥接、现有城镇协议投影、队伍目录联动及主动退本离队。它不解决地下城内远端角色模型/P2P 创建链，不修改登录票据，不改变副本奖励、任务、完成判定或数据库技术选型。

## Definitions and Invariants

- **区域键**：`ChannelId + TownId + AreaId`。同一逻辑频道内，不因 Game listener port 或连接不同而分裂区域实体。
- **成员资格**：稳定角色 ID 加一枚不含网络含义的代次/租约。代次仅用于拒绝旧连接的迟到清理，不向领域暴露 session、connection、listener 或端点。
- **共享可见成员**：允许参与城镇公共可见性广播的区域成员。PVF 标记为私有 gate 的成员仍属于区域实体，但其可见投影只包含自身。
- **成员变化事件**：加入、离开或跨区提交后形成的不可变权威快照；快照表示提交后的事实。
- **移动事件**：成员仍在同一区域时的位置变化；不等同于成员变化，不增加成员修订。
- **回城锚点**：角色离开城镇前最后有效的城镇区域和位置。它可以由现有位置设施保存，但不能被当作“当前仍在区域”的证明。
- 所有区域状态变更先原子提交，再在锁外投影通知。网络发送失败不得回滚或破坏已经提交的区域事实。

## Requirements

| ID | Requirement |
|---|---|
| RQ-001 | 区域服务必须按区域键惰性取得唯一实体，并维护成员、资格代次、共享可见性和实时位置；最后成员离开后实体可立即释放或安全延迟释放。 |
| RQ-002 | 区域领域 API 与实体不得引用网络会话或端点概念；应用层负责从当前角色连接创建成员资格，并对旧资格的迟到离开实行 compare-and-remove。 |
| RQ-003 | 加入、离开和跨区必须由区域服务统一提交并产生对应成员变化事件；跨区对旧、新区域是一次一致迁移，重复进入相同区域或重复离开具有幂等语义。 |
| RQ-004 | 同区移动必须由区域服务校验成员资格、更新实体内实时位置并产生轻量移动事件；角色级 handler 不再自行查询区域听众或构造移动广播名单。 |
| RQ-005 | 选角进入城镇、进入选图、取消选图、实际进本、正常完成回城、主动放弃回城、跨区、同区移动和连接清理必须全部调用区域生命周期入口；离开城镇不会遗留幽灵成员。 |
| RQ-006 | 应用层区域事件投影必须使加入者获得当前可见成员的权威人物视图，使既有成员获得加入者和最新成员关系，使离开者从旧区域视图中消失，并使移动对同区可见成员含自身可见。 |
| RQ-007 | 普通区域离开、跨区、选图和进本不得复用断线 `USER_LEAVE`；真实会话终止仍可投影现有断线通知。 |
| RQ-008 | 区域成员变化必须同步 Party directory 的逻辑频道、城镇和区域镜像；同步失败不得把网络/session 字段引入区域实体。 |
| RQ-009 | 活跃副本中的单人 `GiveUpGame` 必须结束其副本参与并调用现有 Party 退队规则及通知；正常完成后的 `EPLP` 和取消选图 `BackToVillage` 不得隐式退队。 |
| RQ-010 | 私有 gate 可见性、现有协议载荷格式、已验证通知排序约束和 Application 不引用 Infrastructure 的分层规则不得回归。 |

## Lifecycle Transition Table

| Trigger | Required region transition | Party effect | Projection meaning |
|---|---|---|---|
| 选角完成 | 无当前资格 → 加入回城锚点区域 | 无 | 新加入者获得当前区域视图；既有成员获得加入者 |
| 同区移动 | 同资格、同区域内更新位置 | 无 | 向可见成员含自身发送轻量位置变化 |
| 跨区 | 旧区域资格 → 新区域同代次资格 | 更新目录镜像 | 旧区权威移除、新区权威加入；不发送断线语义 |
| 进入选图 | 当前区域 → 不在城镇 | 保留 | 当前区域立即移除；保留回城锚点 |
| 取消选图 | 不在城镇 → 加入各自回城锚点 | 保留 | 每名返回者按实际返回顺序重建所在区域视图 |
| 实际进本 | 确保不在城镇（幂等） | 保留 | 不产生重复离开 |
| 正常完成回城 | 不在城镇 → 加入回城锚点 | 保留 | 返回者和既有区域成员双向重同步 |
| 单人主动放弃 | 不在城镇 → 加入回城锚点 | 退队；队长沿用现有解散规则 | 先形成确定业务结果，再分别投影队伍与区域状态 |
| 会话终止 | 精确资格离开 | 沿用现有断线清理 | 只有实际终止可产生断线语义；旧资格不得移除 replacement |

## Acceptance Criteria

| ID | Covers | Criterion |
|---|---|---|
| AC-001 | RQ-001, RQ-002 | 给定两个不同连接上的角色进入相同区域键，查询得到同一实体的两名成员；领域对象图中不存在 listener port、网络端点、connection/session identity 字段。最后一名成员离开后，再次请求该键得到空的新实体或通过修订校验安全复用的空实体。 |
| AC-002 | RQ-002, RQ-003 | 给定角色以资格 A 进入后又以资格 B replacement，资格 A 的迟到离开不会移除 B；B 离开后成员消失。对同一资格重复加入、离开或“迁移到当前区域”不产生重复成员和错误修订。 |
| AC-003 | RQ-003, RQ-005, RQ-006 | 给定区域已有角色 B，角色 A 从副本正常回城加入该区域时，A 的输出包含 B 的当前人物/位置/成员关系，B 的输出包含 A；A 离开选图再取消返回可重复获得同样的最新视图，且服务查询没有幽灵成员。 |
| AC-004 | RQ-004, RQ-006 | 给定 A、B 在同一共享区域，A 同区移动后实体保存新位置，A 与 B 各收到一份 A 的位置变化；成员数量和成员修订不变。不同区域和私有 gate 成员不收到该移动。 |
| AC-005 | RQ-003, RQ-006, RQ-007 | 给定 A 从区域 X 跨到 Y，X 的剩余成员收到不含 A 的权威结果，Y 的成员和 A 收到包含 A 的权威结果；任何一方都不收到代表 A 断开连接的 `USER_LEAVE`。 |
| AC-006 | RQ-005, RQ-007 | 给定 A 进入选图或实际进入地下城，原区域立即不再包含 A；重复的进本离开为无副作用操作。给定 A 的真实会话终止，精确资格清理后原区域成员仍得到既有断线语义。 |
| AC-007 | RQ-008 | 给定队伍成员发生加入城镇、跨区或离开城镇，Party directory 对该角色的频道/城镇/区域镜像与区域服务提交后的事实一致，队伍列表筛选不会继续使用旧区域。 |
| AC-008 | RQ-009 | 给定 A、B 在队伍与同一活跃副本运行中，非队长 A 执行 `GiveUpGame` 后 A 不在运行且不在队伍、B 收到队伍更新；队长执行时沿用解散规则。相同队伍正常 `EPLP` 回城或 `BackToVillage` 取消时成员关系保持。 |
| AC-009 | RQ-010 | 私有 gate 测试证明两个角色不会互相获得人物或移动投影；Release 构建、架构测试、定向生命周期测试和完整服务端测试全部通过。 |

## Success Evidence

- **EV-001 → AC-001, AC-002**：区域领域单元测试与领域类型结构检查。
- **EV-002 → AC-003..AC-007**：应用 handler/投影测试，断言区域状态、接收者、协议消息种类与必要顺序。
- **EV-003 → AC-008**：`GiveUpGame`、`EPLP`、`BackToVillage` 与 Party 服务协作测试。
- **EV-004 → AC-009**：分层测试、Release 构建、定向测试和完整解决方案测试的新鲜日志。
