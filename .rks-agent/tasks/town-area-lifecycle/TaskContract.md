# TaskContract: 城镇区域生命周期与主动退本语义归一

## Context

### Source Request

用户要求将城镇建模为按 `channel + town + area` 惰性生成的区域实体：角色进入、离开及区域内移动都只向区域服务报告事实，由区域实体维护成员镜像与位置，并在变化后主动产生区域通知；空区域可立即或延迟回收。当前阶段先解决“地下城回城后没有收到区域最新人物信息”和“角色单独退出地下城应等价于退队”，同时把区域内移动归一到同一模型。用户明确授权：“可以，那就开始实施吧”。

### Current Situation

现有 `SessionPresenceDomainService` 以会话存在记录承载角色、频道、城镇、区域和网络监听端口，选角及跨区域命令直接维护记录并拼装广播。同区移动也由协议 handler 自行查询听众和发送通知。进入选图、进入地下城、取消、回城及主动退本没有形成闭合的区域生命周期，因此回城只投影自身或部分队员，区域成员镜像失真；主动退本结束副本运行但不稳定地执行退队语义。角色可见性/P2P 和登录票据超时属于已知但独立的问题。

## Goal

建立一个与网络会话解耦、以城镇区域为聚合边界的成员与位置生命周期，使所有城镇进入、离开、跨区和同区移动经由同一领域入口产生可投影事件；并使进行中的地下城内单人主动退出执行现有退队规则。回城角色应立即得到当前区域的权威人物视图，区域内其他角色也应得到正确变更。

## Scope

### In

- 建立按逻辑 `channel + town + area` 惰性取得的城镇区域实体/服务，维护稳定角色镜像、成员资格代次和当前区域内位置。
- 区域服务拥有加入、离开、跨区和同区移动行为；角色级命令只提交领域事实，不自行维护听众集合或决定广播名单。
- 成员变化产生不可变的权威成员快照事件；同区移动产生轻量位置变化事件，不触发完整成员重建。
- 迁移选角进入城镇、同区移动、跨区、进入选图、取消选图、进入地下城、正常回城、主动退本和连接清理等相关生命周期路径。
- 保留私有 gate 区域的既有可见性规则，同时维持 `channel + town + area` 的区域实体身份。
- 地下城进行中角色单独执行主动放弃/退出时，结束其副本参与并调用现有 Party 领域规则离队；队长行为沿用当前 Party 规则。
- 保持队伍目录中的频道/城镇/区域镜像随区域生命周期变化而更新。
- 为区域行为、投影顺序、回城重同步及主动退本离队补自动化回归测试和架构边界测试。

### Out

- 修复地下城内队友角色模型不可见、P2P 头像或远端 avatar 创建链。
- 修改 launcher/game 登录票据的 180 秒消费与长期连接语义；该问题由 GitHub issue #22 跟踪。
- 将 SQLite 替换为 MySQL 或移除现有事务串行队列。
- 更改普通地下城与剧情地下城的奖励、任务触发或完成判定。
- 合并到 `main`、部署服务器、操作客户端或清理任务工作区。

## Constraints

- Application 不得引用 Infrastructure；领域实体和区域服务不得持有 socket、连接对象、UDP/TCP 端点、listener port 或 `SelectedSessionIdentity`。
- 角色与端点仍只能通过应用层的会话/连接桥接；领域内可使用不暴露网络含义的成员资格代次，以防旧连接清理误删 replacement connection 对应的当前角色。
- 区域实体可产生领域事件，但不得直接发送协议帧；应用层投影器负责解析当前可用连接并发送通知。
- 离开区域应立即对仍在区域内的角色生效；若实现空实体延迟回收，延迟仅影响实体释放，不得延迟成员离开或广播。
- 普通跨区域或进入地下城不得发送表示断开连接的 `USER_LEAVE`；真实会话终止仍保留既有断线语义。
- 正常完成地下城后的回城以及取消选图不得隐式退队；只有进行中的单人主动放弃/退出采用退队语义。
- 复用现有协议格式与已验证通知顺序，不把尚未实机确认的静态逆向假设升级为事实。

## Success Conditions

| ID | Observable condition | Required evidence |
|---|---|---|
| SC-1 | 同一逻辑 `channel + town + area` 只有一个按需区域实体；实体维护成员和位置且不含网络会话/端点字段，最后成员离开后可安全回收 | 领域单元测试、结构/依赖测试及代码审查证据 |
| SC-2 | 选角、选图离开、取消选图、实际进本、正常回城和连接清理形成闭合的区域成员生命周期；重复或乱序调用不会制造幽灵成员或误删 replacement 成员 | 生命周期矩阵测试，包含幂等与代次不匹配用例 |
| SC-3 | 角色从地下城回城时，新加入者收到该区域当前权威人物信息，既有成员收到加入者信息及成员变化；离开后再回来不会依赖旧的 `SessionPresence` 残留 | 应用/协议投影测试，断言帧内容与顺序 |
| SC-4 | 同区移动经区域服务更新位置并向同区可见成员（含自身）产生轻量位置通知；跨区由一次领域迁移更新旧、新区域快照，且不发送 `USER_LEAVE` | 同区移动和跨区多成员测试 |
| SC-5 | 私有 gate 区域不向其他角色泄露成员信息，队伍目录镜像仍随成员的城镇区域变化而刷新 | gate 隔离与 Party directory 集成测试 |
| SC-6 | 进行中的地下城内单人主动放弃/退出会结束其运行参与并执行 `PartyService.LeaveParty` 的既有规则；正常完成回城及取消选图保持队伍 | GiveUp/EPLP/BackToVillage handler 回归测试及 Party 通知断言 |
| SC-7 | 解决方案构建通过，相关测试及完整服务端测试通过，且没有引入 Application→Infrastructure 依赖 | Release build、定向测试、完整测试结果 |

## Requires Confirmation

- 合并到 `main`、推送、创建 PR、部署或重启服务、操作客户端、删除分支或清理工作区。

## Assumptions

- 当前已确认的问题原因足以进入计划性交付：核心缺陷是区域成员状态未覆盖全部生命周期路径，且广播决策散落在命令 handler 中；无需先复现地下城内角色不可见问题。
- 现有 Party 领域的队长离队即解散、普通成员离队即移除规则继续作为主动退本的权威语义。
- 返回城镇位置可继续使用现有持久化/运行时位置服务作为回城锚点，但区域实体是角色身处城镇时的实时位置与成员广播权威。
