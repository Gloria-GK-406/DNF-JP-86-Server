# TaskContract: 领主之塔完整玩法与部署

## Context

### Source Request

用户在确认亡者峡谷当前看不到入口、阅读领主之塔方案后授权：“可以，就按这个方案写任务契约，然后开始实现，完成后部署，我再测试验收。”

已接受的方案：`Document/LordTower-Design-20261019.md`；调查依据及证据等级由该文档和所引 `protocol/` 记录负责。

### Current Situation

基线为 `task/next-round-20261019` 的 `6f19c07b4cd2b5c2656198dbfb725d80544bcf13`。当前PVF具备3505领主之塔、八阶段29张地图、门票和兑换资源，服务端尚未接通2329活动、入口状态和专用玩法。普通副本的迷宫定义不能覆盖此塔。入口门控和专用消息有ClientStatic证据，部分规则来自70Reference；均不等同于已实机验证。

## Goal

按已接受方案实现当前客户端资源中的领主之塔完整游戏闭环，完成自动化验证和本机部署，交付可测试版本、明确的实机验收清单与运行身份，供用户验收。

## Scope

### In

- 活动2329默认常驻及独立启停，选角和在线更新3505调度开放状态；关闭时拒绝绕过入场。
- 60级以上、难度0、禁练习、1～4人，所有有效成员原子检查并各扣2749110一张；重复身份、其他副本占用和失败建房不得产生部分扣票。
- 门票作为入场限制，不另设每日三次硬额度；北京时间06:00在线及重登补足三张，保留GM有效配置、禁用和待收邮件计数，兼容旧补票账本避免重复补给。
- 零疲劳可入场，战斗不耗疲劳；离开和全灭不新增虚弱、不清除已有虚弱；禁复活币和人偶，普通合法消耗品可用。
- 独立八阶段运行态，按当前PVF池加权抽图、加载和Ready、清层后合法走门推进、最终层通关或全灭结算；全灭按当前到达阶段计算。主动退出、断线、成员变化和重试有一致生命周期。
- 塔专用逐怪经验和终局经验、独立及塔指定掉落、任务击杀事实；当前PVF奖励格、金币权重、物品生成与经验上限；每成员奖励只生成及发放一次，容量不足走既有邮件通路。
- 当前地图实际NPC1010/商店1118的受限交易和兑换物品开启；复用既有报价、材料、容量与交付规则，验证相关任务事实不被塔模式截断，不擅改现有任务资源规则。
- 专用0333～0336及既有入场、Ready、击杀、走门、奖励按钮、拾取、离开协议接线，旧会话、重复和非法请求不得重复扣费、发奖或越层。
- 资产及补给账本持久化；运行态不跨重登/重启续闯，成功入场票不退，已提交资产保留。
- 适当回归、独立结果评审、协议与使用边界同步；备份后部署本机服务，验证运行身份和健康，提供用户实机验收清单。

### Out

- 历史开放时段复刻、额外每日硬次数、跨重启续闯、客户端或PVF入口补丁，均不属于已接受方案；不改其他已验收活动的规则。
- 商城、免费复活币和复活币消耗品的既有独立issue，以及其他活动地图不在本功能范围。
- 用户实际游戏验收由用户在部署后进行，本任务负责交付完整可验版本和清单，不以自动测试替代用户验收。
- 本次授权不包含合并、推送、PR或发布版本，也不包含删除其他工作区或恢复玩家数据库。

## Constraints

- 遵守仓库AGENTS的领域/协议/存储分层、命令事务及物品生命周期；全队扣票和奖励失败不得部分提交。
- 保留其他工作、既有验收玩法及玩家资产；部署保留可回退运行输入和数据库备份，自动回退不得覆盖测试期间资产。
- 以当前PVF为内容真源。70Reference、ClientStatic、CurrentImplementation与WireCaptured/ClientVerified明确区分，不把策略或测试结论写成原生已验证事实。
- 不臆造每层战斗限时，不通过普通迷宫伪造此塔的阶段和报文语义。
