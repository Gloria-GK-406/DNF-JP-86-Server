# TaskContract: 响应式拾取投影

## Context

### Source Request

用户确认双方人物可见且移动正常，地面物拾取后也会在双方消失，但远端看不到拾取动作；并授权按已提出的响应式地下城方案修改重构。

### Current Situation

拾取 CMD 已正确占用共享地面编号并只向拾取者入包，但协议 Handler 同时负责构造并直发拾取通知给其他成员。地下城实例当前只有入场变更语言，运行期拾取没有独立 revision、语义接收者和投影边界；远端虽然收到足以删除地面物的结果，却没有呈现拾取动作。

## Goal

在不改变正常 P2P 移动和权威拾取结果的前提下，让一次共享拾取由地下城实例提交为单一运行期变更，并对拾取者和其他有效参与者生成正确的逐接收者投影。服务端只投影权威地面物状态，不伪造属于客户端 P2P 的角色拾取动作。

## Scope

### In

- 追踪 A21 拾取通知的观察者控制流，明确地面物状态与 P2P 角色动作的责任边界。
- 为共享地面拾取建立实例拥有、带 revision 和语义接收者的运行期变更。
- 让协议投影层按拾取者与观察者分别编码和发送，不在领域状态中保存连接或 Session。
- 删除本路径 Handler 内部的参与者目录查询和直接多目标扇出第二真源。
- 覆盖普通地面物、怪物掉落、金币、重复拾取、旧连接和参与者离场边界。

### Out

- 不改动角色移动、攻击等 UDP/P2P 实时传输。
- 不实现任务物品来源、任务 Trigger、Boss 清关、结算或翻牌。

## Constraints

- 拾取共享事实只能提交一次；失败的背包或金币结算不得发布成功变更。
- 拾取者获得物品或金币，其他参与者只收到场景表现与地面物移除所需投影。
- replacement connection、已离场参与者和非本 Run 会话不得收到旧变更。

## Success Conditions

| ID | Observable condition | Required evidence |
|---|---|---|
| C1-SC-1 | 远端投影保留 A21 客户端移除共享地面物所需的正确拾取者身份和消息形态；服务端不伪造角色动作 | codec/handler 回归测试及客户端静态证据说明责任边界 |
| C1-SC-2 | 一次有效拾取只提交一个实例变更，并按当前有效参与者生成逐接收者投影 | Application 领域测试与 Protocol 双参与者测试 |
| C1-SC-3 | 地面物在双方消失、奖励只进入拾取者一次，重复拾取不再发布成功变更 | 普通物品、怪物掉落和金币的双参与者测试 |
| C1-SC-4 | 旧连接、离场参与者和其他 Run 不接收该拾取变更 | replacement、离场和 RunId 过滤测试 |
| C1-SC-5 | 受影响项目 Release 构建与定向测试通过 | 构建输出与测试结果 |

## Authorization

| Capability | Evidence | Authorized scope |
|---|---|---|
| task | 根任务授权：“你来进行修改重构吧” | 在根任务隔离工作区内实现、测试、复审并提交本子结果 |

## Assumptions

- 远端缺失的是客户端角色动作而不是共享地面物删除；A21 静态控制流若证明 0x0027 不触发动作，则本子结果以不破坏 P2P、消除服务端第二真源为正确边界。
