# TaskContract: 响应式地下城同步与结算生命周期

## Context

### Source Request

用户确认双客户端已经能够在地下城中互相看见并正常移动，地面物拾取后也会在双方消失；当前缺口是远端看不到拾取动作，以及 Boss 击杀后没有翻牌、结算和等待回城流程。用户授权：“其余的可以按你说的处理。你来进行修改重构吧”。

### Current Situation

地下城入场已经通过实例变更完成参与者投影，但运行期的拾取、任务进度、Boss 清关、结算、翻牌和离场仍由多个协议 Handler 直接发送或分别推进。剧情任务 1779 是物品收集目标，当前内容投影未建模怪物任务物品来源，运行期拾取也不会立即重算 derived seeking Trigger，导致 Boss 房虽然清空，剧情运行仍被判定为未完成并阻断后续结算。

## Goal

让两人剧情地下城从实时拾取表现、任务物品进度、Boss 清关到双方独立结算、翻牌和回城形成一条由地下城实例拥有状态与接收者语义的完整可实机验收链路，同时保持已经正常的 P2P 移动、共享掉落消失和普通地下城行为。

## Scope

### In

- 明确远端拾取动作属于客户端 P2P 表现边界；服务端不伪造动作，保持现有 P2P 移动，并将权威拾取结果归一为地下城实例变更。
- 建模剧情任务声明的怪物任务物品来源，并在对应运行、角色和目标范围内推进物品获取。
- 在权威背包变化后即时重算并持久化 derived seeking 任务进度，向当前有效会话投影更新。
- 将本任务涉及的拾取、任务推进、Boss 清关、参与者结算、翻牌和离场改为地下城实例提交变更并决定语义接收者，再由协议投影层发送。
- 让共享 Boss 清关只提交一次，并向所有当前有效参与者开放结算。
- 保持结算、奖励牌和离场状态按参与者独立；支持结算摘要后出现牌面、自动免费翻牌、手动翻牌和独立回城。
- 增加覆盖双人剧情地下城、单人剧情地下城和显式普通地下城边界的自动化回归，并更新相关项目文档。

### Out

- 不重写已经正常工作的角色移动、攻击等 UDP/P2P 实时流，不引入 UDP 中继。
- 不实现副本中途加入、副本内重连、服务重启恢复或普通地下城的队伍扩展。
- 不补齐本任务未触达的全部任务目标类型、全部特殊副本结算或大会翻牌协议。
- 不在本任务授权下合并分支、清理工作区或部署运行服务。

## Constraints

- 共享事实包括房间、怪物死亡、地面掉落、拾取占用和 Boss 清关；任务进度、经验、奖励牌、翻牌领取和离场状态按参与者独立。
- 领域实例和领域服务不得依赖连接或 Session；连接代次校验与逐接收者 wire 编码保留在协议投影边界。
- 任务进度只能由服务端权威怪物、掉落、背包和任务内容事实推进，不接受客户端自行声明完成 derived seeking 目标。
- 旧连接和过期计时回调不得向 replacement connection 或后续 DungeonRun 投递通知或奖励。
- 普通地下城不得因角色持有剧情任务而路由成剧情地下城，也不得继承剧情任务完成门槛。

## Success Conditions

| ID | Observable condition | Required evidence |
|---|---|---|
| SC-1 | 一端拾取时，地面物仍在双方同时消失，且只有拾取者获得一次物品；服务端不会为客户端 P2P 动作另造通知真源 | A21 接收端静态证据说明 0x0027 的职责；协议级双参与者测试覆盖共享掉落占用、单次入包、重复拾取拒绝和旧会话过滤 |
| SC-2 | 任务 1779 的目标怪能产生其声明的任务物品，获取后角色的 seeking Trigger 按权威背包数量即时下降并在满足数量时归零 | 真实 PVF 内容测试、任务物品获取与背包/Trigger 原子结果测试、运行期任务进度投影测试 |
| SC-3 | Boss 房清空且冻结队长任务条件满足时，共享运行只清关一次，所有当前有效参与者都进入结算；条件未满足时不重复发奖 | 双参与者并发/重复 Boss 报告测试、清关变更接收者测试、旧会话过滤测试 |
| SC-4 | 两名参与者分别获得自己的结算和奖励牌；牌面按结算节奏出现，免费牌可自动或手动翻开，翻牌状态在队伍内正确显示且奖励只发一次 | 参与者独立结算、定时牌面、手动/自动竞态、逐接收者翻牌投影和幂等测试 |
| SC-5 | 任一成员先回城后，另一成员仍能完成翻牌并独立回城；离开者不会收到旧局后续通知 | 参与者离场状态与接收者收缩测试、过期计时与 replacement connection 测试 |
| SC-6 | 单人剧情地下城和显式普通地下城保持既有路由、清关、奖励与回城行为 | 对应协议与应用回归测试通过 |
| SC-7 | 生产代码可在 Release 下无警告构建，受影响测试及完整解决方案测试无新增失败 | Release 构建输出、定向测试结果、完整测试 TRX 汇总 |

## Authorization

| Capability | Evidence | Authorized scope |
|---|---|---|
| task | “现在是人物可移动，东西也会消失。但是拾取时候没有动作。只是没有动作。其余的可以按你说的处理。你来进行修改重构吧” | 在隔离任务工作区内修改、重构、测试、记录文档并形成一个已验证本地结果提交；不含合并、部署或工作区清理 |

## Requires Confirmation

- 将已验证结果合并到 `main`、清理任务工作区或重新部署服务。

## Assumptions

- 用户观察到的“没有动作”限定为远端拾取表现缺失；走动、攻击等 P2P 实时行为和地面物权威消失已经正常。
- 结算节奏以 A21 上游的“先结算摘要，再显示牌面，再自动翻免费牌”为兼容基线；具体 wire 与时间值可由现有 A21 证据和测试校准。
