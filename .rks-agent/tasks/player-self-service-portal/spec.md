# Specification: 玩家自助后台（#329）与受信代理识别（#305）

## Why and Outcome

玩家想自己给自己的账号加点券、给自己的角色发东西，不必每次找管理员；管理员要能随时关掉这扇门。玩家入口与管理员后台共用同一个网页和监听端口，所以这次同时修好后台在反向代理之后取不到真实来源与协议的问题（#305），否则线上一人输错密码就会锁住所有人。

交付后：

- 玩家用游戏账号登录 `/gm/`，只看到并只能操作自己的账号与角色；
- 管理员在后台一处开关、限额、会话管理；
- 后台在配置的受信代理之后按真实来源与原始协议工作；
- 旧库可用迁移工具升级；用当前主干库准备好用户测试。

## Scope

包含：TaskContract revision 2 的 Scope In 1–11。

不包含：TaskContract Scope Out 1–5。另外，玩家可选币种只有「点券」（`Cera`）与「代币券」（`TokenCera`），不含 `HappyTokenCera`（方案与设计图只出现这两种）。

## Definitions

- **玩家会话**：凭游戏账号登录得到的会话，只携带账号身份，没有任何管理员权限。
- **管理员会话**：现有 GM 登录得到的会话，行为不变。
- **玩家后台设置**：一份全服设置，含总开关、点券子开关、邮件子开关与限额（RQ-020）。
- **日**：服务端现有的每日重置周期（`IDailyResetRuleService` 的日切），与每日补给等玩法一致。
- **受信代理**：配置项列出的代理来源地址；未配置时视为没有受信代理。

## Requirements

### 身份、会话与可见范围

| ID | Requirement |
|---|---|
| RQ-001 | 玩家用游戏账号（登录名 + 密码）登录与登出后台。密码校验与启动器登录使用同一套凭据规则；校验不通过、账号不存在时给出同一种失败，不泄露账号是否存在。 |
| RQ-002 | 玩家会话与管理员会话互相独立：玩家会话不能调用任何管理员接口，管理员会话不能调用任何玩家接口；两类会话的凭据在浏览器里不会被对方的接口当作有效身份。 |
| RQ-003 | 玩家可读到的数据只有：自己账号的登录名、点券与代币券余额；自己账号下未删除角色的 ID、名字、职业、等级、是否在线；自己的操作记录。账号身份一律取自会话；玩家请求中出现的账号标识不改变操作对象。 |
| RQ-004 | 对不属于自己（或已删除、不存在）的角色发起的任何操作被拒，且拒绝结果不区分"不存在"与"不是你的"。 |
| RQ-005 | 玩家会话有固定有效期（与管理员会话相同，8 小时，不自动续期）；过期或被删除后请求被拒，前端回到登录页。 |
| RQ-006 | 玩家接口（含公开的玩家登录、状态、防伪令牌接口）执行与管理员接口相同的传输与跨站防护：只在后台监听端口上响应；非公开接口与玩家登录要求 RQ-032 意义下的安全传输；修改类请求要求本站 `Origin`（或无 `Origin`）、拒绝 `Sec-Fetch-Site: cross-site`，并校验防伪令牌。 |
| RQ-007 | 开关状态、会话有效性、角色归属与限额用量的判定，与该请求的写入（建会话、入账、发信、记录）在同一个串行事务中完成：判定之后、提交之前不会有其它请求改变这些事实。因此：管理员关闭总开关或子开关之后才进入执行的请求一律被拒；在关闭期间完成密码校验的登录不会留下会话；同一账号并发请求的成功总量不超过每日上限。 |

### 玩家操作

| ID | Requirement |
|---|---|
| RQ-010 | 玩家给自己账号增加点券或代币券，数量为正整数。成功后余额按数量增加；结果超过钱包现有余额上限时拒绝且余额不变。在线时账号收到余额变化提醒（沿用 GM 发点券的提醒）。 |
| RQ-011 | 玩家给自己账号下的一个角色发邮件：标题、正文、物品（物品 ID + 数量，可多件）、金币，至少有一项附件或正文。物品合法性、附件件数上限、标题正文长度沿用 GM 官方邮件现有规则；不接受装备高级选项（强化、锻造、增幅、随机属性等任何超出"物品 ID + 数量"的附件字段）。在线角色同样收到并得到新邮件提醒（沿用 GM 邮件）。 |
| RQ-012 | 加点券与发邮件都带请求编号：同一账号用同一编号、同一内容重复提交只生效一次并返回原结果；同一编号换内容被拒。 |
| RQ-013 | 玩家能分页查看自己账号的加点券与发邮件记录（时间、类型、内容摘要、结果），只含自己账号的记录。 |

### 管理员控制

| ID | Requirement |
|---|---|
| RQ-020 | 玩家后台设置包含：总开关；点券子开关；邮件子开关；点券单次上限、点券每日上限、代币券单次上限、代币券每日上限、邮件单封金币上限、邮件每日封数上限（非负整数，0 表示不限）。全新库与迁移后的库默认总开关关闭、两个子开关开启、全部限额为 0。只有拥有全部管理员权限的管理员（与每日补给同级）能读写；并发修改按版本拒绝后写者。 |
| RQ-021 | 设置保存后立即生效，不需要重启：总开关关闭时，玩家登录被拒，已登录玩家的下一次请求被拒，并且关闭的同时所有玩家会话失效；重新开启后玩家可重新登录。总开关关闭时，玩家接口一律以"玩家后台已关闭"拒绝（先于会话检查，使前端能区分"已关闭"与"掉登录"）。子开关关闭只拒绝对应操作，玩家仍可登录查看。 |
| RQ-022 | 限额按账号判定：单次超过单次上限，或本"日"内已成功数量加本次超过每日上限时拒绝，余额不变、不发信。"每日"统计只计成功的操作。 |
| RQ-023 | 管理员能列出当前有效的玩家会话（账号、登录时间、到期时间），踢掉某个账号的全部会话或全部玩家会话；被踢的会话下一次请求被拒。 |
| RQ-024 | 玩家登录（成功与失败）、玩家加点券、玩家发邮件（成功与失败）、管理员修改设置、管理员踢会话都写入现有审计。玩家操作在审计中标明为玩家操作并带账号 ID 与登录名；审计页可只筛玩家操作。迁移前已有的审计记录仍显示为管理员操作。失败登录不记录提交的密码；提交的登录名不符合账号命名规则时不原样记录（避免把误填进账号栏的密码写进审计）。 |

### 受信代理（#305）

| ID | Requirement |
|---|---|
| RQ-030 | 新增配置项列出后台的受信代理地址，默认空。为空时，`X-Forwarded-For` 与 `X-Forwarded-Proto` 一律忽略，后台行为与现在相同。 |
| RQ-031 | 配置了受信代理时，只对直连来源属于受信代理的请求，采用转发头里最近一跳的客户端地址与协议（转发层数上限 1）；其余来源伪造的转发头不起作用。后台以此得到的来源地址与协议用于：登录失败限流的来源键（玩家与管理员两个登录各自独立计数）、会话 Cookie 的 `Secure`、修改类请求的同源检查。 |
| RQ-032 | "远程访问必须 HTTPS"的判断：请求的原始协议为 https，或（经 RQ-031 解析后的）来源地址是本机回环时视为安全。配置了受信代理后，经代理转发来的远程明文请求（`X-Forwarded-Proto: http`）被拒；代理自身不带转发头的本机请求仍视为本机。 |
| RQ-033 | 玩家登录与管理员登录的失败限流互不影响：一方被限流（包括来源槽位被占满）不会让另一方被限流。 |
| RQ-034 | 转发头处理只作用于后台监听端口上的请求；启动器网关接口（LauncherAuth）的客户端 IP 解析与限流不变。受信代理地址按规范化后的 IP 比较（IPv4 与其 IPv4 映射 IPv6 形式视为同一地址）；配置值不是合法 IP 时启动失败并给出配置项名。 |

## Acceptance Criteria

### 身份与会话

| ID | Covers | Criterion |
|---|---|---|
| AC-001 | RQ-001, RQ-021 | Given 总开关开启、账号 A 存在且密码 p 有效；When 用 A/p 登录 → 成功并取得玩家会话；When 用 A/错误密码或不存在的账号登录 → 失败，两种失败的状态码与消息相同；When 登出 → 该会话之后的请求被拒。 |
| AC-002 | RQ-021 | Given 总开关关闭；When 任何玩家用正确密码登录 → 被拒且提示玩家后台已关闭。 |
| AC-003 | RQ-002 | 玩家会话调用每一个管理员接口（至少：会话信息、玩家目录、点券、邮件、审计、玩家后台设置）均被拒为未登录；管理员会话调用每一个玩家接口均被拒为未登录。 |
| AC-004 | RQ-003 | Given 账号 A（角色 a1、a2，a2 已删除）与账号 B（角色 b1）；When A 读取自己的账号信息 → 只有 A 的余额与 a1；请求中附带 B 的账号标识也只返回 A 的数据。 |
| AC-005 | RQ-004 | When A 对 b1、对 a2（已删除）、对不存在的角色 ID 发邮件 → 三者返回相同的拒绝（状态码与消息一致），B 和任何角色的邮箱不变。 |
| AC-006 | RQ-005 | Given 玩家会话已过期（测试中推进时钟）；When 请求 → 被拒为未登录。 |
| AC-007 | RQ-006 | 对玩家登录与一个玩家修改类接口分别验证：缺少或错误的防伪令牌 → 被拒；外站 `Origin` → 被拒；`Sec-Fetch-Site: cross-site` → 被拒；非后台监听端口上请求玩家接口 → 404；（配置受信代理时）经代理转发的远程明文请求访问玩家登录 → 被拒为需要 HTTPS。 |
| AC-008 | RQ-007 | 用可控的执行顺序验证：(a) 关闭总开关的命令先于一个已通过入口检查的加点券请求执行 → 该请求被拒、余额不变；(b) 密码校验完成后、登录命令执行前总开关被关闭 → 登录被拒且不产生会话；(c) 每日上限 1500、已用 1000 时并发提交两笔 500 → 恰好一笔成功。 |

### 受信代理

| ID | Covers | Criterion |
|---|---|---|
| AC-030 | RQ-030 | 未配置受信代理：带任意 `X-Forwarded-*` 头的请求，限流键、Cookie、同源检查、HTTPS 判断与现在完全相同（现有 GM 测试原样通过）。 |
| AC-031 | RQ-031, RQ-033 | 配置受信代理 P：从 P 发来、`X-Forwarded-For` 分别为 C1、C2 的登录请求，C1 连续输错达到限流后被限，C2 仍可登录；玩家登录被限不影响管理员登录，反之亦然。从非 P 来源发来、伪造 `X-Forwarded-For` 的请求按其直连地址计数。 |
| AC-032 | RQ-031, RQ-006 | 配置 P 且 P 转发 `X-Forwarded-Proto: https`，**玩家与管理员两侧各验证一次**：玩家登录与管理员登录成功后的会话 Cookie 都带 `Secure`；玩家与管理员各取一个修改类接口，`Origin: https://<本站主机>` 时通过，外站 `Origin` 被拒。非 P 来源伪造 `X-Forwarded-Proto: https` 时，两种登录的 Cookie 都不带 `Secure`。 |
| AC-033 | RQ-032 | 配置 P：P 转发 `X-Forwarded-Proto: http` 且 `X-Forwarded-For` 为远程地址 → 非公开接口被拒为需要 HTTPS；P 本身不带转发头的请求 → 视为本机，不被 HTTPS 规则拒绝。 |
| AC-034 | RQ-033, RQ-034 | 玩家登录限流的来源槽位被占满时，管理员仍能登录；配置受信代理后，启动器网关接口的客户端 IP 与限流结果与未配置时相同；受信代理配置为 `127.0.0.1` 时，来自 `::ffff:127.0.0.1` 的请求同样被当作受信代理；非法配置值使启动失败且错误信息含配置项名。 |

## Accepted Risks

- 公开的玩家登录会消耗密码计算资源，与启动器登录共用同一个计算限流；登录限流在密码计算之前拒绝超限来源，单来源 15 分钟最多 20 次。大量轮换来源地址（如 IPv6）可占满玩家登录的来源槽位，使新来源的玩家暂时无法登录；这不影响管理员登录（RQ-033），管理员可随时关闭玩家后台止损。功能默认关闭（RQ-020）。
- 玩家登录失败写审计会随尝试次数增长，上限由上述限流约束。
