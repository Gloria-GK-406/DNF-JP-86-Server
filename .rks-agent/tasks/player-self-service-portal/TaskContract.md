# TaskContract: 玩家自助后台（#329）

## Context

### Current Situation

- GM 后台（`Server/src/Dfo.Server.GmWeb` + `Web/gm-admin`）只认管理员账号；点券发放与官方邮件的授权、操作记录、审计都绑定管理员身份。
- 游戏账号密码由启动器登录路径校验（`LauncherCredentialReader`），玩家目前没有任何网页入口。
- 线上 GM 后台经 Caddy 反向代理对外，服务端看到的来源都是 127.0.0.1、协议都是 http：登录限流对所有访客共用、会话 Cookie 不带 `Secure`、同源检查由代理侧临时代办（#305）。
- 数据库表结构版本当前为 6，结构变化须按 `Document/DatabaseSchemaMigration.md` 同时提供迁移步骤。

## Goal

玩家能用自己的游戏账号登录现有后台网页，只看到并只能操作自己的账号和该账号下的角色：查看余额与角色、给自己账号加点券或代币券、给自己的角色发邮件、查看自己的操作记录。管理员能在后台随时关闭整个功能或其中的点券/邮件部分，关闭立即对已登录玩家生效，重新开启后可再登录；管理员能设置限额、查看并踢掉玩家会话；玩家操作在管理员审计中可辨认。后台在受信反向代理之后能识别真实客户端与原始协议（#305）。除 #305 规定的变化外，现有 GM 功能行为不变。旧库可迁移到新结构，功能就绪后用当前主干库准备好用户测试并交给用户。

## Scope

### In

1. 玩家凭游戏账号密码登录 / 登出后台，与管理员登录并存于同一网页入口（登录页可在玩家与管理员间切换）。
2. 玩家可见范围仅限自己的账号（点券、代币券余额）与自己账号下未删除的角色。
3. 玩家给自己账号加点券或代币券。
4. 玩家给自己账号下的角色发邮件，附件为物品（数量）与金币，可带标题和正文；在线角色同样可收。
5. 玩家查看自己的点券与邮件操作记录。
6. 管理员设置：总开关、点券子开关、邮件子开关；单次与每日限额（0 = 不限）；查看玩家在线会话、踢单个或全部会话。
7. 管理员审计能分辨玩家自助操作与对应账号。
8. #305：后台在配置的受信反向代理之后按真实客户端 IP 与原始协议工作（限流、Cookie `Secure`、同源检查），未配置时行为与现在相同；玩家登录与管理员登录都受益。
9. 前端：玩家页面（我的账号、发邮件、记录、已关闭状态）与管理员「玩家后台」设置页，布局依据 UI 设计图，适配手机宽度。
10. 表结构变化对应的版本号与迁移步骤。
11. 自动化测试、本地测试服实机验证；按 `Document/FeatureDevelopment.md` §4 用当前主干实际使用的数据库准备用户测试服务，并把编号测试流程交给用户。

### Out

1. 玩家改密码、注册账号、查看他人数据、使用模板 / 草稿。
2. 玩家邮件中的装备高级选项（强化、锻造、增幅、随机属性等）。
3. 物品黑名单。
4. 启动器内嵌入口。
5. 合并、推送、开 PR、发版、部署到线上服务器、修改线上 Caddy 配置。

## Constraints

1. 功能部署后默认关闭，由管理员手动开启（D1）。
2. 遵守服务端仓 `AGENTS.md` 的分层与构建规则：Application 不引用 Infrastructure，`TreatWarningsAsErrors` 下零警告，生产改动配套测试。
3. 玩家邮件的物品合法性沿用 GM 官方邮件现有的物品校验，不另设一套更宽的规则（D4）。
4. 玩家可见范围与操作对象由服务端按登录会话裁定，不信任客户端提交的账号或角色归属（issue #329 验收第 1 条）。
5. 自动测试使用隔离数据库，不在玩家库上做清库或破坏性操作；用户测试使用当前主干实际数据库前先做一致备份（`FeatureDevelopment.md` §3、§4）。
