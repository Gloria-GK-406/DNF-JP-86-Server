# TaskContract: 库存协议槽位与业务槽位边界重构

## Context

### Source Request

用户要求先扫描槽位切换和换算影响面，再生成任务契约并实施；协议侧的 `spaceItem + index` 必须在进入 CMD Handler 前组成不可分割的游戏槽位并转换为业务槽位，业务返回中的槽位必须在 CMD 返回协议前转换为合法游戏槽位。不得让新旧槽位逻辑并存，映射失败属于严重越界，必须显式抛出异常而不是用 `TryXxx` 隐藏。

### Current Situation

当前已实现的移动、使用、丢弃、出售、修理和分解物品 CMD 均以分离的容器类型与槽位编号穿过协议、命令或领域接口。主背包 `Main` 的快捷栏和物品分类区段使用客户端绝对槽位，区段换算及合法性判断散落在协议切片、命令和库存规则中。回复与通知也直接携带旧坐标，存在字段丢失、错配和新旧判断并存的风险。

## Goal

建立严格且可逆的游戏槽位/业务槽位边界：协议坐标始终以原子 `GameSlot` 表示，所有槽位型库存 CMD 在创建命令前转换为原子业务槽位，命令、领域接口及领域结果仅使用业务槽位；需要投影到客户端的结果在协议响应生成前统一转换回合法 `GameSlot`。

## Scope

### In

- 扫描并迁移已实现的移动、使用、丢弃、出售、修理、分解物品 CMD 的槽位输入、命令、领域调用、结果及响应链路。
- 建立原子的游戏槽位和业务槽位值对象，以及唯一的双向槽位映射规则服务。
- 将主背包绝对槽位转换为快捷栏、随身装备、消耗品、材料、任务物品、副职业材料、徽章等业务空间及局部下标；将其他已支持游戏空间转换为对应业务空间。
- 在领域侧统一使用业务槽位完成容器定位、槽位内容合法性和行为资格判断；底层既有持久化数据须继续可加载和保存。
- 删除所迁移链路中分离传递 `space/list/container + slot index`、重复区段偏移和旧式换算的路径。
- 为双向映射、越界失败、快捷栏移动及六条 CMD 的输入输出边界提供回归证据。

### Out

- 分析或改变分解协议 `contextValue` 的语义。
- 新增尚未实现的库存协议或物品玩法。
- 改变客户端已确认的消息布局、字段顺序或普通业务拒绝码语义。
- 合并到 `main`、推送远端、部署或清理工作区。

## Constraints

- `GameSlot` 必须同时持有游戏空间类型和槽位下标；这两个字段不得作为独立参数进入 ICommand 或 CMD Handler。
- `BusinessSlot` 必须同时持有业务空间类型和业务局部下标；命令与领域边界不得依赖客户端绝对槽位。
- 游戏槽位到业务槽位的转换必须在 ICommand 创建前完成；业务槽位到游戏槽位的转换必须在协议 CMD 响应构造前完成。
- 双向转换失败必须抛出带坐标信息的专用异常；映射 API 不得提供 `TryXxx` 或以普通业务拒绝掩盖越界。
- 同一坐标规则只能有一个权威实现；不得保留旧的区段魔术数、平行换算器或逐命令私有偏移。
- 网络最外层必须隔离槽位映射异常，使非法客户端坐标不能终止整个 Host，同时保留明确诊断证据。

## Success Conditions

| ID | Observable condition | Required evidence |
|---|---|---|
| SC-1 | 六条已实现槽位型库存请求在解码后以 `GameSlot` 表示，并在 ICommand 创建前转换为 `BusinessSlot`。 | 生产代码引用扫描与针对每条请求边界的测试。 |
| SC-2 | 六条 CMD、对应 Handler、领域接口和领域结果不再接收或返回分离的游戏空间与槽位下标。 | 编译期类型签名检查、引用扫描及完整构建。 |
| SC-3 | 所有需要回写槽位的 CMD 响应均从 `BusinessSlot` 统一转换为 `GameSlot` 后编码，线上字节布局保持兼容。 | codec 现有样本测试与新增双向投影测试。 |
| SC-4 | 主背包快捷栏及物品分类区段、穿戴栏、时装、宠物和仓库的已支持坐标具有唯一且可逆的映射；保留、未知或越界坐标抛出专用异常。 | 映射边界、往返和异常测试。 |
| SC-5 | 移动物品仍能正确处理 Main 内区段、快捷栏以及跨游戏空间移动，且没有旧式区段换算分支残留。 | 移动协议与领域回归测试、魔术数/旧签名扫描。 |
| SC-6 | 现有库存持久化数据无需破坏性迁移即可继续加载、修改和重新投影为客户端坐标。 | 持久化加载/结算测试及状态同步测试。 |
| SC-7 | 非法游戏槽位形成可诊断的槽位映射异常，但异常被网络请求边界隔离，不影响 Host 继续服务。 | 异常类型测试及消息分发边界测试。 |
| SC-8 | 解决方案构建与相关库存、协议、持久化测试全部通过，完整结果审查确认没有新旧槽位模型并存于约定边界。 | 新鲜构建、定向测试、完整差异审查和最终验证记录。 |

## Authorization

| Capability | Evidence | Authorized scope |
|---|---|---|
| task | “然后修改后可能会影响之前的slot切换和换算逻辑。所以先扫描生成任务契约再实施。不要出现新的逻辑和旧的逻辑都在的情况。特别要守住spaceitem+index在到CMD handler前被转换，返回值如果需要，BusinessSlot需要在CMD返回前转为合法的GameSlot。将作用边界切干净” | 创建并执行本契约范围内的槽位边界重构、测试、审查和一个本地验收提交。 |

## Requires Confirmation

- 将验收提交合并到 `main`、推送、部署或删除任务工作区。

## Assumptions

- 数据库中的既有 `list_type/slot_index` 可以继续作为持久化适配器格式；其存在不构成领域层旧模型，只要协议坐标不泄露到 CMD 和领域接口。
- 账号货币等仅用于状态投影的虚拟槽不作为普通物品 CMD 的合法目标；遇到这类请求坐标应显式失败。
