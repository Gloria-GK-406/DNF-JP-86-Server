# Specification: 恢复 A21 协议资料库与当前证据的一致性

## Why and Outcome

协议资料库需要重新成为理解 86JP A21 线协议的可信入口。完成后，读者能从 catalog 找到当前服务端接入的每个 Game C→S decoder 和每个实际可发送的 S→C wire identity，进入对应协议页后能够分辨：

- A21 客户端直接证明了什么；
- 抓包或真实客户端运行证明了什么；
- 当前服务端仅仅实现了什么；
- 哪些字段、响应关系或客户端效果仍然未知。

本成果不以“把服务端现状写进文档”为目标，而以“让文档忠实表达证据边界”为目标。代码、旧服、静态逆向与实机行为冲突时，按资料库现有证据规则裁决，并保留尚未闭合的问题。

## Scope

### Included

- Game C→S decoder 和 encoder-backed S→C CMD/NOTI 的可重复清点与 catalog 对账。
- 缺失协议页、陈旧状态、断链、协议页内部矛盾和流程页陈旧结论的修复。
- 对 `CMD 0x0084`、`0x0003`、`0x002D`、`0x0048`、`0x0117` 以及审计发现的同类条目的证据化更新。
- 完全探明时对机器生成输入、生成器或机器区的修正，以及再生成安全验证。
- 一项可重复的资料库同步检查和一份供后续维护者阅读的审计说明。
- 一条 Codex 记忆更新备注，记录长期证据原则。

### Excluded

- 修改 Server、ClientHack 或客户端二进制的运行行为。
- 为缺少 A21 证据的协议补造布局、语义、响应或实机验证结论。
- 将“有 decoder/encoder/测试”自动写成“线协议正确”或 `ClientVerified`。
- 重新逆向全部 1410 条静态协议，或在本任务中解决审计发现的服务端实现缺陷。
- merge、push、PR、发布和清理工作树。

## Definitions and Evidence Rules

| Term | Meaning in this result |
|---|---|
| 接入覆盖 | 当前服务端存在注册 decoder，或存在被运行路径引用的 encoder-backed wire identity；只说明当前代码表面，不证明协议正确。 |
| 协议页 | `protocol/game/client-to-server/0xNNNN.md` 或 `protocol/game/server-to-client/{CMD,NOTI}-0xNNNN.md`。 |
| catalog 登记 | 对应四元身份可从 `protocol/catalog.md` 找到，或位于有理由、有证据且明确命名的排除清单。 |
| 实现服务端功能 | 当前端到端服务路径已实现且有足够实现验证；不等于 A21 客户端实机验证。 |
| 双向验证结束 | A21 客户端逆向、线级数据和真实客户端可观察行为共同闭合；不得由单元测试或旧服行为单独授予。 |
| 机器区修正 | 优先修正生成输入或生成逻辑；只有完全探明且可解释时才直接改变机器区所表达的事实。 |

证据优先级、置信度与冲突处理服从 `protocol/evidence.md`。当前服务端源代码是“实现现状”证据；A21 客户端构包/解包指令和同版本真实运行行为才可证明线级事实与客户端效果。

## Requirements

| ID | Requirement |
|---|---|
| RQ-001 | 建立可重复的代码侧 wire inventory，并把所有当前接入的 C→S decoder 与 S→C encoder-backed identity 纳入 catalog 或有证据的明确排除清单。 |
| RQ-002 | 每个纳入范围的 C→S identity 必须有协议页；S→C identity 必须链接到已有协议页，且链接和方向/族不能冲突。 |
| RQ-003 | 为 `CMD 0x0084` 建立 A21 协议记录，明确静态普查为何漏掉它、当前已知请求/响应和证据边界。 |
| RQ-004 | 消除 `0x0003`、`0x002D`、`0x0048`、`0x0117` 及审计发现的同类陈旧矛盾；同一页面不得同时声称“未实现”和“已实现”，也不得把消费无响应误写成布局或语义已确认。 |
| RQ-005 | catalog 的阶段、名称、角色、链接和备注必须与单协议页及流程页一致；阶段只表达相应证据真正支持的成熟度。 |
| RQ-006 | 机器生成内容的变更必须在再生成后稳定，并能追溯到生成输入/逻辑或明确记录的证据化人工例外。 |
| RQ-007 | 资料库必须提供自动同步检查，至少检测注册 C→S decoder 未登记、encoder-backed S→C identity 未登记、已登记接入身份缺少协议页和无效链接。 |
| RQ-008 | 产出一份审计说明，记录覆盖口径、自动检查边界、仍需逆向或实机验证的实现风险，避免把静态代码 inventory 误当成协议正确性证明。 |
| RQ-009 | 所有仓库改动限定在协议资料、项目文档、资料检查脚本和任务控制工件；不改变服务端或客户端运行行为。 |
| RQ-010 | 把本任务的长期证据原则写入唯一一条 Codex 记忆更新备注。 |
