# TaskContract: 任务转职奖励与技能状态同步

## Context
### Source Request
“技能服务要根据职业和转职裁剪技能树，以及计算赠送技能……给用户重新发送技能表后再发送CMD ACK。”
“写个任务契约开始实施吧”
### Current Situation
任务7840完成后仍未转职：任务奖励规则未执行PVF grow type奖励。现有角色、技能规则、属性及外观投影可复用，技能读取尚未整理持久化技能。
## Goal
完成转职任务后，角色职业、适用技能、赠送技能、点数、属性及可见身份一致，无需重新登录才能生效。
## Scope
### In
- PVF转职奖励结算，角色转职更新及统一技能整理。
- 复用已有职业/觉醒、技能、赠送、属性和外观规则。
- 技能表先于完成任务ACK，补足转职ACK及角色刷新。
- 自动回归验证、协议证据分级和可操作的实机验收说明。
### Out
- 魔王契约、新增契约能力、职业转换商城、完整觉醒任务链。
- 自动修改正在运行的服务或玩家数据库；角色234既有失败数据的补偿单独安排。
## Constraints
- 保留适用已学技能及有效快捷栏；新增赠送技能不重复付费，达人契约合法越级技能不误删。
- 任务完成、转职和技能变更原子结算；失败不得留下已完成但未转职状态。
- 遵循现有CMD→领域服务→规则服务分层，不复制另一套技能规则。
- 上游推导与A21实机验证区分；用户负责实际客户端验收。
## Success Conditions
| ID | Observable condition | Required evidence |
|---|---|---|
| SC-1 | 完成合法转职任务更新目标转职；普通任务无变化 | 任务结算回归及持久化检查 |
| SC-2 | 两页技能裁剪、补赠送、保留合法等级/槽位及正确点数 | 技能整理行为测试，含幂等与达人边界 |
| SC-3 | 结算失败原子回滚，重复完成不重复奖励 | 事务/拒绝回归 |
| SC-4 | 技能表在ACK之前，随后投影使用新职业属性与身份 | 通知顺序与编码测试；交付实机步骤，效果待用户验收 |
