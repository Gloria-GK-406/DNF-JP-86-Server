# TaskContract: 翻牌奖励按线上真实结构重做

## Context

### Source Request

「判 failed，重开。然后代码回退，重写这里的逻辑。」

前置对话确立了要重做的原因：十四轮实机与客户端反汇编推翻了前一个 Spec
（`.rks-agent/tasks/flipping-a-clear-reward-card/`）已批准的验收边界。用户在此之前逐条主持了
实验设计（`c=2 改 3`、装备与金币对调、三组各放一件、四列各放一件、主动推应答、`a` 写 0/1/2/3、
应答全填充），并在证据出现后要求先同步协议文档、再判定前一个 Spec 的结局。

### Current Situation

前一个 Spec 的结局已封为 `failed`，代码已回退到接受基线 `a5d164af`。该基线里的**规则层是好的**
（概率合成、副本 `[basis level]` 定价、房间数上限修正、空物品开关），**协议编码层是错的**。

线上真实结构已经写定在三份协议文档里，本任务的输入就是它们：

- `protocol/game/server-to-client/NOTI-0x0023.md` —— 卡尾三组 = 三行（普通 / 黄金 / 黑砖），
  每组八个 slot = 八列；每个 slot 是 `u8 c` 加 `c` 条 `(i32 itemId, i32 amount)`，
  **条目 0 是这张牌的金币且其 itemId 被忽略，条目 1 是装备，条目 2 起客户端照读但不上屏**；
  帧长 `210 + 8N + 8E`。
- `protocol/game/client-to-server/0x0047.md` —— 请求两字节且**第二字节恒为 `00`**；应答是
  信封加八条记录的**整块状态快照**，**记录序号 = 第几列**，`a`/`b` 是**座位号不是布尔**
  （实测：写 `0/1/2/3` 只有 `0` 生效），免费翻牌 `c = 0` 不带内容；**本帧可由服务端主动推**
  （实测：面板刚出、玩家未点时推三条 `a=0x00`，三列立刻翻开）；开牌另有本地一条路
  （实测：应答八条全填充，牌照样翻开）。
- `protocol/game/server-to-client/NOTI-0x0043.md` —— `CARD_SELECT_COMPLETE_STATE` 在本客户端
  是 104 个 type 共用的占位实现，翻牌同步不走它。

由此，前一个 Spec 的核心模型「四个牌位各藏一样东西、玩家挑一张、一次应答全部揭晓」不成立：
**服务端决定亮哪一份，客户端决定亮在哪一列；玩家挑哪张改变不了他得到什么。**

## Goal

让通关结算的翻牌在真实客户端上按线上结构正确工作：结算帧把这一局的牌面内容放进正确的组与
slot，翻牌应答按状态快照的形状回答，玩家翻开的那张牌上真的显示出装备与金币。

## Scope

### In

- 重写结算帧 `NOTI 0x0023` 的卡尾编码：三组 = 三行，slot = 列，条目 0 金币 / 条目 1 装备。
- 重写翻牌应答 `CMD 0x0047` 的编码：八条记录的状态快照，`a`/`b` 为座位号，免费翻牌不带内容。
- 让判据钉住**客户端读得到什么**，而不是**编码器写了什么字节**。
- 把黄金行与黑砖行在帧上的位置留出来并写成空，附带说明它们何时才该有内容。
- 更新受影响的 `Docs/` 与 `AGENTS.md` 记载（若有）。

### Out

- 不改规则层：概率合成、`[basis level]` 定价、房间数上限、空物品开关、掉落池选取一律保持
  基线 `a5d164af` 的行为与取值。
- 不实现付费（黄金）翻牌与黑砖翻牌的**送达路径**；本任务只把它们在帧上的位置写对（空）。
- 不实现组队广播。组队形状是推论、未实测，本任务只保证单人正确且不把组队的路堵死。
- 不追 `[[0x03B3DFB8]]` 虚表槽（需要开着面板时抓的 dump）。
- 不动仓库根目录那三个 0 字节垃圾文件。

## Constraints

- 规则层行为逐值不变，以基线 `a5d164af` 为准。
- 分层不变式不得破坏：规则输入只经规则服务进入服务器；规则服务不读世界状态；
  Protocol 层只经领域服务触达规则（`AGENTS.md` 已授权的 handler 能力除外）。
- 切片规则：`Protocol/<Endpoint>/<Protocol>/` 一个目录，切片内不跨协议引用。
- 协议文档三份是本任务的**输入而非产物**；发现与它们冲突的事实要回改文档并具名。
- 判据必须能在**不跑客户端**的情况下失败：断言的对象是「按客户端的读法把帧解回来之后得到什么」。

## Assumptions

- 那个身份值在单人时为 `0`（实测），组队时是否等于自己的队伍座位号**未验**。本任务按
  单人写 `0x00`，并把这一格集中在一处，使日后改成真实座位号只动一个地方。
- 每张牌固定 1 金币（`GameProtocol.ClearRewardCardGold`）仍是本服务器自定的占位值，
  归档说翻牌不出金币。本任务把它写进条目 0，不改它的取值。
