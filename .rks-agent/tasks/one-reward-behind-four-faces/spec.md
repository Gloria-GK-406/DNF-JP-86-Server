# Specification: 翻牌奖励按线上真实结构重做

## Why and Outcome

通关结算的翻牌功能已经交付过一次，规则层是对的，协议编码层是错的：牌面在真实客户端上
一律显示 NONE。错的原因是对两个帧的结构读错了，而当时的判据断言的是「服务端写了哪些字节」，
所以一千九百多条判据全绿也照不出来。

线上真实结构现已由实机与客户端反汇编定死并写入协议记载。本 Spec 要让结算通知与翻牌应答
按这个结构产出，**结果是玩家翻开的那张牌上真的显示出这一局的装备与金币**。

## Task Perspective

- Core outcome: 玩家在结算面板上翻开一张牌，牌面显示出这一局的装备与这张牌的金币。
- Necessary support: 结算通知把牌面内容放在**普通牌行**上并把黄金牌行、黑砖牌行声明为空；
  翻牌应答按**整块面板状态**的形状回答，而不是按「这次翻出了什么」的形状。
- Peripheral assurance: 判据按客户端的读法把帧解回来再断言；规则层逐值不变的回归保护。

## Scope and Non-Goals

### In Scope

- 结算通知里牌面内容的位置与形状：落在哪一行、哪一列，以及一列内部金币与装备的次序。
- 翻牌应答的形状：八条记录的面板状态，每条记录声明该列的普通牌与黄金牌各被谁翻开。
- 判据的断言对象：解码后的可观察量。
- 黄金牌行与黑砖牌行在帧上的位置被留出并声明为空。

### Non-Goals

- 不改规则层的任何取值：出现概率、品级带、副本定价、房间数上限、空物品开关、掉落池选取。
- 不实现付费（黄金）牌与黑砖牌的奖励送达。
- 不实现组队广播，也不实现「显示队友翻牌结果」。
- 不确定那个身份值在组队时的语义。

## Constraints

- 规则层行为以既有基线为准，逐值不变。
- 判据必须能在**不运行客户端**的前提下失败：其断言对象是「按客户端的读法把帧解回来之后
  得到什么」，不是「编码器写了哪些字节」。这是本 Spec 相对上一次交付唯一新增的硬约束。
- 协议记载是本 Spec 的输入而非产物。若实现过程中发现与记载冲突的事实，先回改记载并具名，
  再继续。

## Definitions

| Term | Meaning |
|---|---|
| 行 | 结算面板上一整排牌。共三行：普通牌行、黄金牌行、黑砖牌行 |
| 列 | 一行里的第几张牌。面板画四列 |
| 条目 | 一列里声明的一份东西。同一列可以声明多条 |
| 身份值 | 应答里用来表明「这一列是谁翻的」的小整数。单人时为 0，保留值表示无人翻开 |
| 面板状态 | 每一列的普通牌与黄金牌各自被谁翻开的完整快照 |

## External Behavior and Data Rules

- 结算通知按三行 × 八列声明牌面；每一列先声明它有几条条目，再依次给出各条条目，
  每条条目是一个物品标识与一个数量。
- 一列的**第一条条目是这张牌的金币**，其物品标识不被读取；**第二条条目是这张牌的装备**；
  第三条起客户端会读走但不显示。
- 翻牌请求携带牌型与一个牌位序号，但**牌位序号恒为零**：客户端不上报玩家点了哪一张。
- 翻牌应答携带八条记录，第 k 条对应第 k 列；记录声明该列的普通牌与黄金牌各被哪个身份值
  翻开，并可携带若干条目。免费翻牌的记录不携带条目。
- 记录中「无人翻开」由保留值表示；条目数为零是合法声明，条目数为保留值会声明出远超帧长的
  内容。

## Observable Requirements

| ID | Requirement |
|---|---|
| RQ-001 | 一局结算后，这一局的牌面内容出现在结算通知的**普通牌行**上，落在该行的某一列 |
| RQ-002 | 该列的第一条条目是这张牌的金币，第二条条目是这张牌的装备；没有装备时只声明金币一条 |
| RQ-003 | 结算通知的黄金牌行与黑砖牌行的每一列都被声明为空 |
| RQ-004 | 结算通知的长度与它自己声明的条目数一致，任何条目数下都不多不少 |
| RQ-005 | 翻牌应答声明**全部八列**的状态，包括无人翻开的列 |
| RQ-006 | 免费翻牌的应答不携带任何条目 |
| RQ-007 | 应答里「这一列被谁翻了」由身份值表示；单人时被翻开的那一列写 0，其余写保留值 |
| RQ-008 | 应答里声明为空的记录，其条目数为零；任何一条记录声明的条目数都不会超出帧本身的长度 |
| RQ-009 | 玩家在结算面板上翻开一张牌，牌面显示出这一局的装备与这张牌的金币 |
| RQ-010 | 规则层产生的每一个值与既有基线逐值相同 |

## Assumptions

- 身份值在单人时为 0 已由实机测得；它在组队时是否等于自己的队伍座位号未验。本 Spec 只
  要求单人正确，并要求这一格集中在一处，以便日后一处改动即可。
- 每张牌固定一份金币是本服务器自定的占位值，归档并未声明翻牌产出金币。本 Spec 不改这个取值，
  只改它在帧上的位置。
- 牌面内容全部来自结算通知这一条，已由「把应答改成不携带任何内容后牌面仍正确显示」实测。
  若日后出现只能由应答提供的内容，本 Spec 的核心分工需重定。
