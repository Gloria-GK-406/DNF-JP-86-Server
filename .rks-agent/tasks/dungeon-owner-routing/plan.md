# Implementation Plan: 副本归属命令先定位、再单次路由，陈旧帧在入口统一丢弃

## Planning Choice

选 `task-units`。表征测试必须先于结构改动提交；定位能力和测试夹具补登记必须先于命令迁移；13 个命令分属 7 个处理器类，按命令组迁移可以单独验证、单独提交。后续阶段的细节依赖前面的产出：表征测试暴露的覆盖缺口，决定迁移时要额外守住哪些格；夹具补登记的方式，决定各命令测试怎么改。各阶段共享同一个验收边界，不构成 Multi Spec。

## Approach and Shared Decisions

总路线：先钉住新鲜帧行为，再建立陈旧定义与定位能力，然后按命令组迁移到“入口判陈旧 → 定位 → 单通道”，最后加结构守护与文档。每次迁移后，表征测试断言不改且通过；陈旧帧丢弃由新增的矩阵测试证明，并在 Task Result 中标出哪些格属于授权的行为变化。

以下决定现在就定下，后续阶段都依赖：

- **BD-001 陈旧定义**：在 `Server/src/Dfo.Server.Protocol/Game/` 新增 `GameRequestFreshness.IsStale(GameMessageMetadata)`，判定式与现行一致。所有调用方改用它，删除 `TowerProtocol.cs`。测试驱动里复制的旧写法同步替换。（RQ-001）
- **BD-002 定位能力**：在协议层新增一个静态定位类型（暂名 `DungeonLocator`，放在 `Server/src/Dfo.Server.Protocol/Game/Dungeons/`），不进入依赖注入，由处理器把已注入的服务传入。这样不触发处理器依赖后缀的架构规则；处理器新增注入的 `IDungeonParticipationDomainService` 符合 `*DomainService` 后缀。
  - `Locate(session, participation, bossTowers, illusionTowers)`：返回一个封闭的位置结果，取值为 Boss 塔（会话 + `BossTowerSnapshot`）、幻影塔（会话 + `IllusionTowerSnapshot`）、普通或不在副本（会话）。规则完全按 Spec“位置”定义：先查登记；登记为某塔时，再向该塔服务按会话取快照，并核对 RunId；不认可就归入普通或不在副本。
  - 无会话不经 `Locate`，由处理器在入口按现行行为处理。
  - `LocateParty(candidates, ...)`：对候选逐个 `Locate`，按“Boss 优先、幻影次之”给出整队位置，并附带去重后的副本列表。候选收集仍由组队代码负责，它需要队伍服务。
  - 普通通道照旧按角色取普通副本，定位能力不返回普通副本快照。（RQ-003）
- **BD-003 通道形状**：每个命令有一个路由方法，依次完成入口判陈旧、取会话、定位、`switch` 到通道。
  - 每个通道是单独的方法，参数是定位结果中对应的强类型分支（Boss 通道收 Boss 会话与快照，幻影通道同理）。通道内删除自己的陈旧判定与归属查询，精确会话校验等处理校验保留。
  - 塔通道放在以塔命名的分部文件或既有塔相关文件中，与路由方法分开。
  - 0x000F 的 Boss 通道返回“是否已释放”，路由方法据此决定是否继续普通选图，不重新定位。（RQ-004、RQ-005）
- **BD-004 夹具补登记**：
  - 构造塔服务、普通副本服务的测试夹具改为注入真实的 `DungeonParticipationDomainService`。服务在入场时自行登记，与生产一致。
  - 只替身了 `Find` 的塔替身（如 `TowerDomainStub`、`TowerPresenceProxy`）需配套一个按替身状态作答的登记替身，或改用真实服务。具体在对应 Task 中按实际夹具决定。
  - 断言不因此改变。（Spec Constraints）
- **BD-005 结构守护**：在 `Server/tests/Dfo.Server.Protocol.Tests/` 新增源码扫描测试。
  - 陈旧判定调用只允许出现在 13 个命令的路由方法、0x009F 与 0x0010 的入口。
  - `bossTowers.Find(` / `illusionTowers.Find(` / `bossTower.Find(` 只允许出现在定位类型，以及一份逐项注明理由的非分发白名单中：投影内部查成员、入场精确性校验、计时器回城、精确会话校验等处理校验。
  - 附带反例用例：一段违规源码文本被判定为违规。（RQ-007）
- **BD-006 文档归属**：在 `Document/ProtocolCommands.md` 新增一节，描述入口判陈旧、定位、单次路由、0x000F 例外与陈旧帧丢弃规则。其他文档只链接，不复写。（RQ-008）
