# Specification: 副本归属命令先定位、再单次路由，陈旧帧在入口统一丢弃

## Why and Outcome

13 个客户端命令要按请求者所在的副本，分给 Boss 塔、幻影塔或普通流程处理。现在的写法是依次尝试各分支，每个分支自己查归属、自己判陈旧，顺序不一，普通流程靠塔分支顺带去重。本规格把它们改成同一结构：
1. 入口判一次陈旧并丢弃；
2. 定位一次；
3. 交给唯一通道。

完成后，陈旧帧在任何位置都被丢弃（用户授权的行为变化）；其他可观察行为不变；新结构有守护，回退会被测试拒绝。

## Definitions

- **陈旧帧**：传输层赋予了入站序号（`InboundOrdinal > 0`）、但序号没有在连接计数上前进一位（`SequenceIsFresh == false`）的帧。不带入站序号的帧（如测试用的 `GameMessageMetadata.Empty`）永远不陈旧。
- **请求者会话**：按连接查到的已发布会话。没有时称“无会话”。
- **位置**：定位能力对一个请求者会话给出的结论，只有三种：
  - **Boss 塔**：副本占用登记为 Boss 塔，且 Boss 塔服务按这个会话找到的副本与登记的 RunId 一致；
  - **幻影塔**：同理，副本占用登记为幻影塔，且幻影塔服务认可这个会话；
  - **普通或不在副本**：其余所有情况，包括：
    - 登记为普通副本；
    - 没有登记（城镇）；
    - 登记为塔但塔服务不认可这个会话（会话代次窗口）；
    - 登记为普通、但按角色已找不到普通副本（离队后尚未结束本局）。

  定位结论附带塔副本快照；普通或不在副本时，普通副本仍由普通流程按角色查找，与现行一致。
- **整队位置**：组队类命令的定位口径。候选为调用者、目标（若有）和所有在线且身份匹配的队员。
  - 任一候选位于 Boss 塔时为 Boss 塔，附带候选所在的全部不同 Boss 塔副本；
  - 否则任一候选位于幻影塔时为幻影塔，同样附带副本；
  - 否则为普通或不在副本。
- **通道**：只处理一种位置的代码单元：Boss 塔通道、幻影塔通道、普通通道。普通通道处理“普通或不在副本”。

## Scope

覆盖 13 个命令：0x002B 拾取、0x0028 角色死亡、0x0027 怪物死亡、0x0025 加载完成、0x002D 过图、0x0048 Eplp、0x0084 回城、0x000F 进入选图、0x0029 复活币、0x002A 放弃、0x000D 退队、0x000E 踢人、0x0079 转让队长。0x009F 与 0x0010 只改用新的陈旧定义。其余排除项见 TaskContract 的 Scope Out。

## Requirements

| ID | Requirement |
|---|---|
| RQ-001 | 陈旧判定只有一个定义，名称和归属与“塔”无关；`TowerProtocol` 不再承载它。0x009F、0x0010 及 13 个命令都使用它。 |
| RQ-002 | 13 个命令都在入口判一次陈旧，先于会话查询、定位和任何领域写入。陈旧帧在普通副本、Boss 塔、幻影塔、城镇与无会话时一律丢弃：不产生领域写入、不登记回包。日志不作要求。 |
| RQ-003 | 有一个统一定位能力，按上面的“位置”定义回答请求者的位置，并提供“整队位置”。它以副本占用登记为依据，是 13 个命令判断归属的唯一入口。 |
| RQ-004 | 每个命令的新鲜帧在定位之后只进入一个通道，对应关系见下文“位置 → 通道对照”。唯一例外是 0x000F：Boss 塔通道释放副本成功后，同一命令直接进入普通通道的城镇选图，不重新定位、不再判陈旧。 |
| RQ-005 | 通道不判陈旧，也不为路由自行查询两塔或普通副本的归属。通道内部为处理本身做的校验（如精确会话校验、读取队员会话、普通流程按角色取普通副本）不受此限。 |
| RQ-006 | 新鲜帧在各位置的处理结果与基准一致：由哪个通道处理、回包、收件人、领域写入都不变。具体包括会话代次窗口、离队后尚未结束本局、组队类整队归属，以及各通道的私有差异（例如 0x000E 幻影塔失败发拒绝帧而 Boss 塔不发，0x0029 在 Boss 塔回拒绝帧）。 |
| RQ-007 | 新结构由能拒绝反例的守护保护：通道或命令入口以外的地方重新出现陈旧判定、为路由查询塔归属时，测试失败。 |
| RQ-008 | 分发结构与陈旧帧规则在一个所属文档中描述，其他位置只引用；代码中描述旧顺序差异“刻意保留”的注释删除或改写。 |

### 位置 → 通道对照（新鲜帧）

“普通”指普通通道。该表即现行行为，RQ-006 要求保持。

| 命令 | 无会话 | Boss 塔 | 幻影塔 | 普通或不在副本 |
|---|---|---|---|---|
| 0x002B 拾取 | 普通（记录后返回） | Boss | 幻影 | 普通 |
| 0x0028 角色死亡 | 直接结束 | Boss | 幻影 | 普通 |
| 0x0027 怪物死亡，非物件 | 记录后返回 | Boss | 幻影 | 普通 |
| 0x0027 物件破坏 | 记录后返回 | 忽略（不回包） | 普通 | 普通 |
| 0x0025 加载完成 | 普通（记录后返回） | Boss | 幻影 | 普通（含城镇加载） |
| 0x002D 过图 | 记录后返回 | Boss | 幻影 | 普通 |
| 0x0048 Eplp | 普通（记录后返回） | Boss | 幻影 | 普通 |
| 0x0084 回城 | 普通（记录后返回） | Boss | 幻影 | 普通 |
| 0x000F 进入选图 | 普通 | Boss，释放成功后接普通选图；未释放则结束 | 普通 | 普通 |
| 0x0029 复活币 | 普通 | Boss（回拒绝帧） | 普通 | 普通 |
| 0x002A 放弃 | 按现行入口 | 按整队位置 | 按整队位置 | 按整队位置 |
| 0x000D / 0x000E / 0x0079 | 按现行入口 | 按整队位置 | 按整队位置 | 按整队位置 |

组队类命令中，“按整队位置”指整队位置为 Boss 塔时进 Boss 通道，为幻影塔时进幻影通道，否则进普通通道。

### 陈旧帧行为变化清单（RQ-002 授权的变化）

以下组合现行会处理陈旧帧，改后丢弃：
- 0x000F：普通副本、幻影塔、城镇；
- 0x0029：普通副本、Boss 塔（不再回拒绝帧）、幻影塔、城镇；
- 0x0027 物件破坏：普通副本照常处理，改为丢弃；幻影塔与城镇回空通知，改为不回包；
- 无会话：0x002D、0x0048、0x0084、0x000F、0x0027、0x0028、0x0029 现行不判陈旧，改为一律丢弃（这些情况下现行也无领域写入，差别主要在回包与日志）。

其余组合现行已丢弃陈旧帧，保持丢弃。

## Success Evidence

- 表征测试提交早于任何结构改动提交（`git log` 顺序可查）。
- 陈旧帧矩阵测试、定位能力测试、结构守护测试，以及它们的变异检查记录，写在对应 Task 的 Result 中。
- 完整测试输出存放在 `verification/`。

## Constraints and Notes

- 日志文本与级别不在保护范围内。
- 测试替身与驱动需要补上副本占用登记，或改为使用真实登记服务，才能让定位能力看到塔与普通副本。这属于测试适配，不改变断言。
- 实施中若发现新的登记与现行查询不一致窗口，按“对应服务不认可即为普通或不在副本”处理，在 Task Result 中列出，并在最终结果中报告。
