# Plan: Item rules in the bag

七个有序任务。次序是这份计划的主要内容：**先给没有守卫的行为立守卫，再迁移**，
否则迁移把它改掉不会有东西变红。

## Ordered tasks

### T-001 — 先给教程奖励的今日行为立用例（不改生产代码）

`GrantTutorialRewardCommandHandler` 今天没有直接用例。为它当前的行为立五条：

1. 续在已有堆上：落点、物品编号、这次放进多少，三个数都断言。
2. 占用一个空格：同上三个数。
3. 格子带满：该件**被排除在回执之外**，且其余各件照常处理（用两件构造，一件满一件不满）。
4. 档案里查不到摆放声明：该件被跳过，其余照常。
5. 一步声明两件同一物品：后一件看得见前一件已写下的东西（第二件应续在第一件刚开的堆上）。

**不改任何生产代码。** 这五条必须在当前实现上全绿——它们是迁移的判据，不是迁移的目标。

依赖：无。

### T-002 — 背包获得放入与补充，并在内部完成到货落地

在 `Dfo.Server.Abstractions/Inventory/` 立结果类型（落下了 / 放不下 / 不认识这件物品），
在 `IItemContainer` 上立两个动词。

实现放在 `StoreBackedItemContainer`：它组合的是自己的读与写，不是存储的能力。
容器获得三个只读依赖（摆放声明源、到货规则）；`SelectCharacterEntryInventoryDomainService`
的构造点随之传入。

「把到货判决变成写入」的那一段写成容器内部的一处私有步骤——**两个动词共用它**，
这就是 RQ-4 收敛的对象。两个动词的差别只在它们各自调用哪条到货规则、以及格子带与物品类别从哪来。

**不改任何调用方。** 本步结束时旧路径原样跑着，全量应仍绿。

依赖：无（与 T-001 可互换次序，但 T-001 先做更安全）。

### T-003 — 教程奖励改为调用背包

`GrantTutorialRewardCommandHandler` 去掉摆放声明源与到货规则两个依赖，改为对背包调用放入。
「放不下」与「不认识这件物品」两种结果都在**调用方**翻译成「排除在回执之外」——
背包不知道有回执这回事。

判据：T-001 的五条用例期望值**一个字都不改**，全绿。

依赖：T-001、T-002。

### T-004 — 每日补充改为调用背包

`DailyRefillService.GrantAsync` 改为对背包调用补充。逐条保留：

- 「放不下」仍抛 `InvalidDataException`，消息仍指出是哪个格子带满了。
- 规则的物品类别为 0 时仍抛。**这一条今天在写入之前判**，迁移后不得漏。
- 提交记录仍是容器类型、落点、物品编号、这次放进多少、共有多少。

补一条 RQ-7 的用例：补充落在已有堆上之后，该行的代理键可以改变，而对外投影不变。
同时在用例注释里指出代理键在协议侧只出现于异常字符串，以及那个因槽位唯一而不可触发的排序备选键。

判据：`SqliteEntryInventoryMutationRepositoryTests` 九条期望值**一个字都不改**，全绿。

依赖：T-002。

### T-005 — 背包获得移动，判定迁入

在 `Dfo.Server.Abstractions/Inventory/` 立移动结果类型：搬成了（数量、物品编号）/ 没变化 /
被拒绝（五种原因之一）。**这五种原因只含判定**，不含协议自己的三种
（没有会话、不服务该列表、没有绑定容器）——那三种仍由处理器给出。

`MoveItemSpaceCommandHandler.PlanAsync` 的全部判定迁入背包的移动动词；
背包内部仍调用 `ItemContainerOperations` 执行，后者继续不判定。

处理器保留：主列表判断、两端同格的判断可迁可留（迁入更自洽，留下也不违反契约——
本计划迁入）、以及把领域拒绝原因翻成 `ItemMoveStatus` 再翻成客户端码。
`ItemMoveStatus` 的十个值一个不减，`ErrorCodeFor` 不动。

判据：`MoveItemSpaceHandlerTests` 十三条与 `ItemRefusalCodeTests` 九条期望值不改，全绿。

依赖：T-002。

### T-006 — 收旧路、订正注释、修订设计文档

- 删掉因迁移而失去最后一个调用方的旧路径。**删之前逐条核对**：
  `ICharacterItemTable` 上的写入方法若仍有其他调用方则不删。
- 订正两处注释（`IItemContainer` 的接口注释、`ItemContainers.cs` 中说「是协议的问题」的那一句），
  在两处都说清 `ItemContainerOperations` 仍不判定，且它正是「拼装不需要存储知情」的证据。
- 在 `Docs/Refactor/DomainInstanceDesign.md` 中记下本成果确证或修正的条目：
  R-2 的「跨实例归仓库」在本成果中未被触及（移动仍在单个背包内）；
  「What does not move」一节关于 `ItemContainerOperations` 的段落已由本成果落实，
  其中点名的 `ItemContainers.cs:51` 注释已订正，并补上此前遗漏的第二处
  （`IItemContainer` 的接口注释）。

依赖：T-003、T-004、T-005。

### T-007 — 可证伪演示与全量

对 AC-1、AC-2、AC-3、AC-6、AC-7 所立的保证各做一次真改真跑：故意改坏 → 确认变红且**只红被点名的那条** →
复原 → 确认逐字节回到原样。至少五次。

随后跑构建与全量，记录数字。

依赖：T-001..T-006。
