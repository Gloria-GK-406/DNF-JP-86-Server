# Plan: The character instance

六个有序任务。次序仍是这份计划的主要内容：**先给只活在注释里的规则立守卫，再搬**。

## Ordered tasks

### T-001 — 先核实两条注释级规则有没有守卫（已完成，结论与预期相反）

计划起初假定它们没有守卫、要先补。实测推翻了这个假定：

- 把冷却检查提到等级检查之前 → 红 `A_permanent_reason_is_reported_ahead_of_one_that_will_expire`。
- 把「在场记录缺失」的默认翻成地下城 → 红两条地点用例。

两次都逐字节复原。**因此不补冗余用例**，这两次真改真跑记为 AC-8 的两次演示。
本任务的产出是这段证据本身，以及对 Spec 中那处判断的更正。

依赖：无。

### T-002 — 造人物实例与交出它的仓库接缝

实例按角色定位，持身份与依赖，不缓存状态，由仓库按需交出——不建注册表、不设生命周期，
理由见 Spec 的 RQ-1 与契约 revision 2 的修订说明。

**不改任何调用方。** 本步结束时全量应仍绿。

依赖：无。

### T-003 — 判决那一半提纯，实例供身份

把等级、职业族、所在地、冷却的比较提取成一个纯规则服务：吃档案声明与四个事实，吐判决。
签名里不出现身份。**判定的先后次序原样搬过去**，并在那里把「为什么冷却最后问」的理由一并带上。

实例负责取那四个事实并调用它。

依赖：T-001、T-002。

### T-004 — 用消耗品的用例改向实例提问，收旧路

`UseStackableCommandHandler` 去掉可用性服务依赖，改为向人物实例提问。
删掉因此失去最后一个调用方的东西——删前逐条核对。

判据：六条既有可用性用例与 T-001 的两条期望值**一个字都不改**，全绿。

依赖：T-003。

### T-005 — 裁定未决项并写回文档

在 `Docs/Refactor/DomainInstanceDesign.md` 中，把「人物实例是否就是运行时会话态」这一未决项
替换为裁定：写明结论、理由、以及它依赖的前提（哪一份是权威、若权威改变会怎样）。
一并记下本成果确证或修正的其他条目。

依赖：T-002、T-003。

### T-006 — 可证伪演示与全量

对 AC-1、AC-3、AC-4、AC-5 所立的保证各做一次真改真跑，至少四次；
其中必须包含**把冷却提到等级之前**这一处——它是本成果最可能被无声改掉的东西。
T-001 的两次已计入。

随后跑构建与全量，记录数字。

依赖：T-001..T-005。
