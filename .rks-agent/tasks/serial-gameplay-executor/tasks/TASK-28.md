#### 1.3 S5 的各项与收尾窗口

**收尾窗口**：从工具开始关闭连接的时刻到 Host 进程结束。
- 起点的取法：矩阵驱动给工具的标准输出逐行加 UTC 毫秒时间戳（§2.3）。
  - `run`：起点是「logins done, flooding」那一行的时刻加 `--flood` 秒数（灌包窗口结束，工具随即关闭全部连接）；
  - `ramp`：起点是最后一行「ramp N: …」的时刻（最后一档统计结束，工具随即关闭连接）。
- `host.log` 的时间戳是本地墙上时钟（+08:00），与工具输出同一台机器的时钟，换算成 UTC 后比较。起点写进 `logs/task-28-runs.txt`。
- 起点有约 1 s 的不确定性（工具输出行与实际关闭之间的间隔）。落在起点前 1 s 内的告警行，在判定输出中单列，逐条说明。

**S5 命中的情形**：
1. 任一次运行出现构成 B 基线没有的错误（断线、超时），即 `summary.json` 的 `errors` 非 0；
2. 任何失败命令或失败作业（`Command … failed in handler`、`Gameplay … failed`），不能归因为协议预期的拒绝。**不设时间豁免**（§1.2 第 2 条）；
3. `host.log` 中出现以下任一信号（应为 0）：
   - `GameplaySelfWait`（含 RQ-003 的网络等待检查：`GameplayNetworkWaitAssertion` 以 `GameplaySelfWaitException("Waiting for the network (…)")` 抛出）；
   - `must happen inside a gameplay job`、`Nested command dispatch`、`did not drain within`、`GameplayLeakedFlowException`、`GameplayDepthExceededException`、`database is locked`；
   - 发件箱：`A work unit was still open when its gameplay job ended`、`The sender refused a gameplay job's outbox`、`could not be encoded; that target is skipped`、`Outbound composition for recipient`（以上见 `Server/src/Dfo.Server.Application/Execution/Outbox/GameplayOutbox.cs:78`、`:185`、`:421`，`OutboxAdapters.cs:124`）；
   - 停机阶段以外的 `GameplayExecutorStoppedException`（工具直接结束 Host，没有优雅停机阶段，任何出现都报告）；
   - `direct send deadline exceeded`：产生它的代码已在 TASK-23 删除，保留在表里只为与 M-1 同表，应为 0；
4. `Outbound connection … closed: OverLimit`（`OutboundSender.cs:250`），**任何时刻**出现即命中。依据：合成负载不超过 21 个在线角色，选角全序列实测最大 41,891 B，城镇换区最大 936 B（`t006-closure.md` §6 AC-013 行），离 1,048,576 B 的队列上限有一个数量级以上；出现即说明上界判断有误或有放大；
5. 收尾窗口**之外**出现下列告警，且不能按下一段归为「工具主动断开」：
   - `Outbound connection … closed: TimedOut` 或 `closed: Failed`；
