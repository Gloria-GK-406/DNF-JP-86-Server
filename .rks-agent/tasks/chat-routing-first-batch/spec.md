# Specification: 聊天单入口路由与第一批频道

## Why and Outcome

A21 玩家现在在聊天框发出的任何话都被服务端丢弃。交付后，玩家用区域、队伍、私聊、频道喇叭、服务器喇叭发言，消息会到达正确的在线收件人并在其客户端显示为对应频道；其余聊天方式得到明确拒绝，客户端不会卡住。服务端以一个入口接住所有发言，按「范围」分流，范围成员由各自现有 owner 回答。这个结构是后续公会聊天、系统公告、禁言与黑名单的落脚点。

## Definitions

- **在世界内的角色**：其选中会话已进入世界（`InWorld`）且连接仍有效。只有它们能成为收件人或发言者。
- **频道**：一个 Game 监听端口对应一个频道。本服务器的全部频道即本进程的全部 Game 监听。
- **第一批 mode**：区域 3、45、46；队伍 2、9；私聊 1、7；频道喇叭 13；服务器喇叭 11、12、57；1:1 窗口内发言 43。
- **进行中的会话**：已建立、尚未因关窗或选中会话结束而结束的 1:1 会话。会话绑定双方建立时的选中会话；成员的选中会话不再是当前在世界内的那一个时，该成员不再是收件人。
- **拒绝**：给发言者回同 type 的失败应答，不投递，不改变任何状态，连接保持可用。
- **静默**：不投递、不向发言者报错，按正常成功处理发言者这一侧。

## Scope

包含 TaskContract（revision 6）Scope In 的全部内容。系统／GM 公告、`Channel(id)` 范围、禁言／黑名单／限频／违禁词判定、公会系统、多人群聊（`0x01A4`、NOTI `0x016B`／`0x016C`／`0x016D`／`0x0170`）、换频道后保留会话、留守方复用旧窗口、mode 33／37 的本地 1:1、GM 喇叭、攻坚队／占领战、其他喇叭、物品链接投递均不在本 Spec 内。

## Requirements

### 入口与结构

| ID | Requirement |
|---|---|
| RQ-001 | 来自在世界内角色的每一帧 CMD `0x0011` 由同一个协议命令处理。wire `mode` 只在协议层出现，进入领域层前已映射为聊天频道或被判为拒绝。 |
| RQ-002 | 聊天范围是封闭基类加子类：相对范围 `PartyOf`、`AreaOf`、`ChannelOf`、`GuildOf` 各带一个锚点角色；绝对范围 `Server`、`Character`、`Conversation` 带各自目标（`Conversation` 带会话 id）。由一个领域服务的单参数 `MembersOf(scope)` 按子类分流并返回角色列表；遇到未处理的子类时报错，而不是返回空。 |
| RQ-003 | 范围成员只取自现有 owner：全服与频道取自在线会话，区域取自城镇区域服务，队伍取自组队服务，1:1 会话取自会话 owner。范围服务不保存任何群组成员名单；1:1 会话成员只由会话 owner 在内存中保存一份，不持久化。 |
| RQ-004 | 投递前有一个且只有一个发送前检查步骤，现阶段对所有发言放行；以后禁言、黑名单、限频都接在这一步。 |

### 投递

| ID | Requirement |
|---|---|
| RQ-010 | 区域聊天投递给与发言者处于同一城镇区域的全部在世界内角色，用 NOTI `0x000C`。发言者不在任何城镇区域时静默。 |
| RQ-011 | 队伍聊天投递给发言者所在队伍的全部在世界内成员（含副本中），用 NOTI `0x000C`。发言者无队伍时静默。 |
| RQ-012 | 私聊按 CMD 中的对方名字找到角色；对方在世界内时投递给对方，用 NOTI `0x0041`（状态字节 0，带发言者名字）。对方不在线或不存在时静默。 |
| RQ-013 | 频道喇叭要求 CMD 所指背包槽位上是物品 37；成功时扣 1 个，投递给与发言者同一频道的全部在世界内角色，用 NOTI `0x0076`。 |
| RQ-014 | 服务器喇叭要求槽位物品与 mode 对应（11→36、12→898、57→10151255）；成功时扣 1 个，投递给本服务器全部频道（含决斗与特殊频道）的全部在世界内角色，用 NOTI `0x0076`。 |
| RQ-015 | 公会聊天（mode 6）范围恒为空，静默。 |
| RQ-016 | 发言者在自己客户端看到自己的这句话恰好一次。A21 客户端发言后不在本地显示（ClientStatic，Confirmed），所以区域、队伍、两种喇叭的收件人包含发言者本人；私聊只投递给对方，不给发送者回帧（与 70 一致），发送方那一行的显示以实机为准。 |
| RQ-017 | NOTI 中的字段取值使收件人客户端走该频道的正常显示分支：发送者标识是发言者的 `WireUserId`，名字是发言者角色名；`0x000C` 的 serverGroup 写 0；`0x0076` 的频道字节写发言者所在频道的频道编号（即该频道 `0x0001` 下发的频道编号），服务器字节写本服务器的编号。 |
| RQ-018 | 成功与静默时不回 `0x0011` 应答（mode 43 在任何情况下都不回，见 RQ-042）；拒绝时回 `0x0011`（`0x01A9` 回 `0x01A9`）失败应答 `u8 0, u8 reason`。发言者客户端不卡住输入。 |

### 拒绝

| ID | Requirement |
|---|---|
| RQ-020 | `0x0011` 中第一批以外的 mode 一律拒绝：服务器专用 0、4、0x0A、0x10–0x1E；不支持 48、33、14、15、34、50、56、52–55、36、37、38；以及任何未映射值。43 不在拒绝集合内。 |
| RQ-021 | 物品链接 CMD `0x01A9` 回同 type `0x01A9` 的失败应答，不解析正文，不投递。 |
| RQ-022 | 喇叭槽位为空、槽位物品与 mode 不符时拒绝，物品数量不变。 |
| RQ-023 | 正文为空，或超过所用 NOTI 在客户端的显示上限（`0x000C` 正文须少于 256 字节，`0x0076` 正文不超过 511 字节）时拒绝，不截断。 |
| RQ-024 | 解码不了的 `0x0011` 帧（长度不足、长度字段越界）不投递、不改变状态，并且不导致连接异常以外的副作用。 |

### 1:1 对话窗口

| ID | Requirement |
|---|---|
| RQ-040 | CMD `0x01A3`（`dstr 目标名`）来自在世界内的角色：按名字找到的目标在世界内、不是发起者本人、两人之间没有进行中的会话、发送前检查放行时，建立会话，分配一个当前进行中会话都没在用、且不为 0 与 `0xFFFFFFFF` 的 u32 id，并给双方各发一条 NOTI `0x016A`：`u8 0, u32 id, u8 2, dstr 对方名, dstr 自己名`。其余情况不给任何人发帧，不改变状态。 |
| RQ-041 | `0x0011` mode 43：aux 为会话 id。发言者是该进行中会话的成员时，只给对方（其绑定的选中会话仍在世界内）发 NOTI `0x016F`：`u32 id, dstr 发言者名, dstr 正文`；发言者本人不收任何帧。会话不存在、发言者不是成员、对方不在、正文为空或不少于 1024 字节时静默：不投递，也不回 `0x0011`。 |
| RQ-042 | mode 43 的任何结果都不回 `0x0011` 应答（客户端已在窗口内本地显示该句，失败应答只会弹通用错误框）。 |
| RQ-043 | CMD `0x01A5`（`u32 id`）：发送者是该进行中会话的成员时结束会话；对方仍在世界内时给对方发 NOTI `0x016E`：`u32 id, dstr 离开者名`。不是成员或会话不存在时不做任何事。 |
| RQ-044 | 选中会话结束（下线、换频道、回选人）时，结束绑定在这个选中会话上的全部会话，并给每个仍在世界内的对方发 NOTI `0x016E`。之后两人再次发起会建立新会话。 |
| RQ-045 | CMD `0x01A6` 被接收并忽略：不回帧、不改变状态，不再作为未处理帧告警。 |
| RQ-046 | `0x016A`／`0x016E`／`0x016F` 中的名字取自服务端保存的角色名，须少于 128 字节；`0x016F` 正文少于 1024 字节。不满足时该帧不发（`0x01A3` 按不回处理，mode 43 按静默处理）。 |

## Assumptions

- A21 布局来自客户端静态分析，没有 ClientVerified；字段取值依据以实现时补查的客户端证据为准，并在实机中确认。
- 喇叭：客户端收到发送者名字等于自己的 `0x0076` 时会在本地扣喇叭；服务端扣除后的物品显示与重登后数量一致，以实机为准。
- 普通发言若实机发出 mode 8 或 5（客户端开关或特殊地下城），按未映射拒绝，并回到用户决定是否纳入。
- `0x0076` 的服务器字节与客户端比较的值来源未读出；对不上时客户端走跨频道分支，仍按喇叭颜色显示（Confirmed），不影响投递。
- 1:1 会话的客户端行为来自 ClientStatic（`research/conversation-re-20261112.md`）：每条成功的 `0x016A` 都新建窗口、不按 id 去重；名单首位为对方；发言本地回显；`0x016F` 中发送者是自己时客户端丢弃。均待实机确认。
