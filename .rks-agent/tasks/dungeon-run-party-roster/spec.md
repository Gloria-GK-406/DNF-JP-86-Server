# Specification: 普通地下城副本只挂在队伍上，人员只问队伍

代码基准 `1cff7218`，路径相对 `Server/src/`，行号指该基准。

## Why and Outcome

“谁在这个副本里”现在有两份独立维护的事实：队伍成员，以及副本自己的 `ActiveParticipants`；另有按角色到副本的索引 `runsByCharacter`。两份靠各离开路径的调用顺序保持一致，任何新路径只改一边，就会让成员视图缺人或缺队长，进而让 `ViewFor` 抛异常或让所有人都不是队长、过图被拒。

结果：副本只与一支队伍（真实队伍，或单人的虚拟队伍）关联。成员、槽位、队长只由队伍回答；角色找副本先得到所属队伍，再得到该队伍的副本。副本只保留入场时确定的不可变事实和每名成员在本局的运行状态。游戏可观察行为不变。

## 术语

- **副本**：`DungeonRunDomainService` 持有的普通地下城运行实例（`DungeonRunAggregate`）。大会、镜像、深渊、SAO、地狱、祭坛底层副本等布局都由同一聚合创建，同属本规格范围；两塔（`BossTower*`、`IllusionTower*`）各有独立运行时，不在范围内。
- **副本的队伍**：入场时由入场队长解析出的 `PartyKey`，副本生命周期内不变。
- **入场名单**：入场时参与者的角色与账号，不可变。它不是成员名单，只用于两件事：提供账号，以及排除图外角色。
- **图外角色**：不在入场名单里的角色。
- **副本成员**：副本的队伍的当前成员中，属于入场名单的角色。这是副本成员唯一的定义。
- **个人离开**：一名角色离开副本，队伍中其余成员继续本局。
- **整局结束**：副本对所有成员同时结束，副本被移除，队伍不变。

## Scope

包含：

- 副本的成员、槽位、队长视图与“角色 → 队伍 → 副本”的查找。
- 队伍服务新增“角色所属队伍键”查询。
- 所有个人离开与整局结束路径：放弃副本、断线拆除、退队、被踢、整队退出（Eplp）、选图回城、清场回城、全灭结束、入场中止、同一队伍开新局前结束旧局。
- 运行中副本的队伍不能增员的显式守护。
- 接口注释与仓库文档更正；测试构造方式迁移与新增测试。

不包含：两塔运行时、`DungeonParticipationDomainService` 占用登记本身的结构（#187）；本服务队伍依赖以外的可选依赖（#183）；协议字段、数据库、客户端；推送、PR、合并。

## Requirements

| ID | Requirement |
|---|---|
| RQ-001 | 副本成员视图（成员、槽位、队长）只由“副本的队伍的当前成员 ∩ 入场名单”得出，槽位与队长取队伍当前值。副本不持有任何可变的成员集合；入场名单与入场队长是副本仅存的人员相关事实。 |
| RQ-002 | 副本服务必须依赖队伍服务，不存在“没有队伍服务时退回入场名单”的路径。 |
| RQ-003 | 队伍服务提供由角色得到所属队伍键的查询：角色在真实队伍中时返回该队伍键，否则返回该角色的虚拟队伍键。 |
| RQ-004 | 由角色找副本：先用 RQ-003 得到队伍键，再取该队伍键绑定的副本；副本服务不维护按角色到副本的索引。一支队伍同时最多绑定一个副本。 |
| RQ-005 | 个人离开：离开者先不再是副本的队伍成员（真实队伍中退队或被踢），随后副本清理其本局状态（见 RQ-008）。离开者若是副本的队伍里唯一的副本成员（含单人虚拟队伍），则改为整局结束。剩余成员保持原 `RunId`、原 Cell 与房间进度继续，队长变化体现在成员视图中。 |
| RQ-006 | 整局结束：整队退出、选图回城、清场回城、全灭结束、入场中止、同一队伍开新局前的旧局，都对副本的全部成员一次结束副本并移除副本，不改变队伍。选图回城只在请求者是副本的队伍队长时整局结束；非队长请求不结束副本（基准中该分支只在请求者已无副本时可达，见“可达性说明”）。 |
| RQ-007 | 运行中副本的队伍不能增员：邀请或接受加入一支已绑定副本的队伍时被拒绝。守护不得让队伍服务依赖副本服务（保持“副本 → 队伍”单向依赖）。即使队伍被构造为含图外角色，该角色也不属于副本成员，得不到任何副本操作、通知或发放资格。 |
| RQ-008 | 每名离开者（无论个人离开还是整局结束）的本局副作用与基准逐人拆离一致。所有路径都要：释放占用登记、恢复虚弱回复、关闭宠物战斗标志、移除准备与死亡标记、清理该角色的结算与翻牌领取记录。离场生命周期与失败虚弱只在基准会产生它们的路径上产生：个人离开（`EndAsync`）记录生命周期，未清场且布局适用时设失败虚弱；全灭结束记录生命周期，布局适用时设失败虚弱；清场回城只记录生命周期；入场中止与同一队伍开新局两者都不产生。协议层照旧记录离场（`ParticipantDeparted`）。副本被移除时，副本级记录（清场回城与全灭期限、死亡、参战效果、结算领取、机制唤醒）照旧清理。结算与翻牌领取记录的清理无法从公开接口观察，由代码审查确认。 |
| RQ-009 | 在合法操作可达的任何状态下，存续副本的成员视图恰有一名队长，不因离开路径的执行先后抛出未处理异常。 |
| RQ-010 | 游戏可观察行为不变：协议帧内容与顺序、通知收件人、结算、掉落与翻牌归属、过图与入场结果与基准相同。 |
| RQ-011 | 接口注释与仓库文档描述的副本成员模型与 RQ-001～RQ-007 一致，不再称成员“冻结”。 |

## 可达性说明

- 选图回城（`Protocol/Game/DungeonSelection/DungeonSelectionCommandPhases.cs:26-115`）以 `entryIntents.ClearExact(session)` 为前提。入场意图在进入选图界面时记录（`:214`），入场时消费（`DungeonEntry/DungeonEntryCommandPhases.cs:164` 等），整队退出结束副本后才恢复（`GamePartyTransitionCommandHandler.cs:233`），且 Eplp 在副本内发现成员持有意图时拒绝（`:191`）。因此请求者持有意图时通常没有副本，`:80-90` 的逐人结束是防御性代码。RQ-006 把它改为“仅队长整局结束”，不改变可达行为。
- 运行中的队伍当前无法增员：邀请与接受都要求双方在城镇区域（`Protocol/Game/Party/PartyCommandSlice.cs:288-312`，`PartyProtocolCommands.cs:160-166,227-233`），入场会离开城镇区域。RQ-007 只把这一点变为显式守护，不改变可达行为。
- 现有个人离开路径全部伴随离开队伍：放弃副本（`GamePartyTransitionCommandHandler.cs:331-341`）、断线拆除（`Application/Sessions/SelectCharacterLifecycleServices.cs:123-139,172-183`）、退队与被踢（`GamePartyTransitionCommandHandler.Stages.cs:161-178`）。未发现“个人离开副本但保留队伍”的可达路径；若实施中发现，按 TaskContract 回报用户。

## Acceptance Criteria

| ID | Covers | Criterion |

| AC-001 | RQ-001 | Given 两人队 A（队长）、B 在同一副本，When 队伍把队长转给 B，Then 副本成员视图中 B 是队长、A 不是，且副本未调用任何同步方法。 |
| AC-002 | RQ-001、RQ-002 | 代码检查：`DungeonRunAggregate` 无可变成员集合、无按角色到副本的索引；`DungeonRunDomainService` 所有构造路径都要求队伍服务。 |
| AC-003 | RQ-003 | 队伍服务对真实队伍成员返回其队伍键；对不在真实队伍中的角色返回其虚拟队伍键；成员退队后返回其虚拟队伍键。 |
| AC-004 | RQ-004 | Given 真实队伍副本与单人虚拟队伍副本，When 按成员角色查找，Then 各自得到所属队伍的副本；Given 成员已退队，Then 按其角色找不到原副本。同一队伍开新局后，按任一成员找到的是新副本。 |
| AC-005 | RQ-005、RQ-008 | 对放弃副本、断线拆除、退队、被踢四条路径分别：Given 两人队副本，When B 走该路径离开，Then B 不在成员视图中、按 B 找不到副本、RQ-008 列出的 B 的本局副作用全部发生；A 保持原 `RunId`、原 Cell 与进度，A 为队长。B 为队长时同样成立，A 成为队长。 |
| AC-006 | RQ-005 | Given 单人虚拟队伍副本，When 该角色放弃副本或断线，Then 副本整局结束并被移除，RQ-008 的副作用全部发生。 |
| AC-007 | RQ-006、RQ-008 | 对整队退出、选图回城（队长）、清场回城、全灭结束、入场中止、同一队伍开新局六条路径分别：When 路径执行，Then 原副本被移除，每名原成员发生 RQ-008 为该路径规定的副作用（含生命周期与失败虚弱的有无），队伍成员与队长不变。 |
| AC-008 | RQ-006 | Given 副本存续，When 非队长发起选图回城，Then 副本不结束。 |
| AC-009 | RQ-007 | Given 队伍已绑定副本，When 有角色请求加入或被邀请，Then 请求被拒、队伍不变。Given 测试把图外角色直接放入副本的队伍，Then 该角色不在成员视图中，其按角色查找、过图、拾取、结算请求均不改变副本。代码检查确认队伍服务未引用副本服务。 |
| AC-010 | RQ-009 | 对 AC-005～AC-007 的每条路径，在路径执行过程中与执行后读取成员视图均不抛异常；存续副本恰有一名队长。 |
| AC-011 | RQ-010 | 基准中断言协议帧、收件人、结算与归属的既有测试，迁移后断言不变且通过；只允许改测试的构造方式与夹具（例如提供队伍、让离开者在测试队伍中退队）。基准缺少表征的离开或结束路径，在结构改动前先补表征测试并在基准上通过。 |
| AC-012 | RQ-010 | 经同一聚合的其他布局（大会、镜像、深渊、SAO、地狱、祭坛底层副本）的既有测试全部通过。 |
| AC-013 | RQ-011 | `Abstractions/World/IDungeonRunDomainService.cs` 等接口注释与相关 `Document/` 文档不再出现“frozen participants”等与 RQ-001 冲突的描述，并说明副本成员由队伍回答。 |
