# Specification: 物品有自己的身份，槽只说它在哪

## Why and Outcome

今天一条物品记录同时承载「这是什么东西」与「它在哪」，而改变位置的做法是把那条记录销毁重建。
于是一件物品没有跨越写入而不变的身份，也没有办法表达「这件东西存在，但此刻不在任何槽里」。

同一个字段还承担着三种互不相干的含义——堆叠的数量、契约兽指向自身实例状态的键、时装指向
自身细节的键——靠一个种类值分辨，而那个种类值本身与内容档案对同一件物品的解释并不一致。

做完之后：**有身份的物品与它的位置是两件分开的事实**。移动一件装备不再改变它是哪一件；
它的强化、洗出的属性、附魔随它走。没有身份的东西（消耗品、材料）继续只在槽里记
「是什么、几个」，不会被凭空赋予一个会误导后人的身份。客户端看到的字节不变，
例外只有两条被明确授权的缺陷修复。

## Task Perspective

- Core outcome: 一件有身份的物品在任何位置变动之后仍是同一件，且它的可变状态随它走而不随槽走。
- Necessary support: 槽对两类东西是同一种形状；「一件物品该不该有身份」的分类规则显式、每次写入都会走、且不以单一不可靠的值为唯一依据；投影仍能产出今天线上的字节。
- Peripheral assurance: 无人引用的有身份物品可被查询；被授权的行为变化逐条可指认；既有的注入面机检继续通过。

## Scope and Non-Goals

### In Scope

- 有身份的物品的存在与它所在的位置分开表达。
- 有身份的物品按其类别分别承载各自的可变状态。
- 槽对「有身份的物品」与「无身份的东西」用同一种形状表达。
- 「一件物品该不该有身份、属于哪一类」的分类规则显式化。
- 位置的改变不再以销毁并重建承载该物品的记录的方式发生。
- 入场与增量的物品投影仍产出今天线上的字节。
- 无人引用的有身份物品可被查询出来。
- 两条被授权的缺陷修复：契约兽取下后能装回去；契约兽的种类判定与档案一致。
- 仓库约定记下这套建模、被授权的行为变化、以及本轮没有做的部分。

### Non-Goals

- 定时清理无人引用的物品。本轮只要求它们可被查询。
- 既有数据库的自动升级。所有者已裁定现有测试库作废重建，新形状只对新建的库生效。
- 启用「存在但不在任何槽里」的具体用法：地上掉落、交易托管、拍卖挂单、邮件附件。
- 契约兽领域本身：它的实例动词、喂食、经验、等级、饱食度记账。
- 裁定契约兽占用的是哪一个装备槽位。本轮沿用今天使用的那一个。
- 裁定契约兽专属容器承载什么内容。
- 裁定契约兽技能是否进入服务端。
- 角色状态记录中那五个含义未查清的契约兽相关列。

## Constraints

- 除下面明确授权的两条变化外，服务器发给客户端的字节逐值不变。
- 不新增协议帧，不改变任何帧的字节布局。
- 既有判据的期望值与断言不得为迁就实现而改写。类型改名带来的符号更新、以及正对应被授权
  行为变化的改写除外。
- 既有的命令处理器与通知处理器注入面机检必须继续通过，其判定谓词与具名豁免清单不得放宽或扩充。
- 不得引入「从槽取出一个凭证、去别处换成可操作的对象、操作完再换回一个新凭证写回槽」的往返。
  动词直接作用在它的主语上；把读到的状态攥在手里再写回去会在事务回滚时领先于数据库，
  而没有任何东西会报告这件事。
- 领域词汇里表示「事务结算的真源」的那个词只有一种读法，不得因本轮而出现第二种。
- 分层由项目引用强制，本轮不得出现反向依赖。
- 编译告警即错误；未被读取的主构造器参数会让编译失败。

## Definitions

| Term | Meaning |
|---|---|
| 有身份的物品 | 同一模板的两件之间可以互相区分、且各自带着只属于自己的可变状态的东西。本轮包括装备、时装、契约兽。 |
| 无身份的东西 | 同一模板的两份完全可互换、除数量外没有自身状态的东西。本轮包括消耗品与材料。 |
| 世界侧 | 承载有身份物品自身及其可变状态的那一侧，与「它在哪」无关。 |
| 槽 | 「某个容器的某个位置上放着什么、几个」这一事实。 |
| 身份 | 一件有身份的物品跨越任何位置变动与任何写入都保持不变的那个值。 |
| 无人引用的物品 | 存在于世界侧、但没有任何槽指向它的有身份物品。 |
| 分类 | 判定一件东西属于「有身份的物品」还是「无身份的东西」，以及前者属于哪一类。 |

## External Behavior and Data Rules

- 客户端在入场序列与增量更新中收到的物品字节，与本轮之前逐值相同，两条被授权的变化除外。
- 契约兽在其清单帧上的对外标识以带范围检查的 32 位有符号整数写出；服务器不得产出一个
  无法以该宽度表示的标识。
- 被授权的行为变化一：玩家把契约兽从装备槽取下之后，能再把它装回该槽。
  本轮之前取下即无法装回。
- 被授权的行为变化二：契约兽物品的种类判定与内容档案对同一件物品的解释一致。
  本轮之前两者不一致。

## Assumptions

- **无人引用的物品在本轮不会实际产生。** 已核实：今天没有任何生产通路销毁一件有身份的物品——
  清空槽位的五处调用全部发生在移动过程中（清空源槽），而消耗到零只作用于无身份的东西。
  因此「本轮不清扫」不会造成可观察问题，RQ-007 只要求可查询即足够。
  **若实现期发现存在能产生无人引用物品的通路，这条假设被推翻，须停下返回控制器。**
- **契约兽的对外标识用 32 位有符号整数足够。** 有身份的物品仅在被创建时取得标识，
  而角色可持有的物品数量由格子数封顶；按所有者的估算，即使全服长期运行，
  创建次数也远不足以耗尽该范围。RQ-008 只要求「不能产出无法表示的标识」，
  用一个窄标识空间还是另设一个对外标识，属于实现选择。
- **时装的若干细节列在上一轮刚被并入物品记录，本轮要再搬一次。** 所有者已认可这个代价：
  上一轮合并的理由是「细节的键是物品已经持有的一个值」，而本轮给了物品一个真正的键，
  那个前提被取代。
- **存储标识今天已经部分泄漏进领域层，并且是承重的。** 入场库存的对账扫描以
  「保留这些标识、删除其余」的方式工作，其保留清单取自投影所携带的存储标识。
  这不是本轮引入的，但它意味着**已经有代码在依赖一个每次写入都会改变的半身份**，
  RQ-002 的成立会同时消除这处隐患。
- 既有数据库不会被自动升级。所有者已裁定作废重建，故本轮不需要新的迁移机制，
  也不需要为旧形状保留兼容读路径。
