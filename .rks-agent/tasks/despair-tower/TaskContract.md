# TaskContract: 绝望之塔可玩闭环

## Context
用户要求：“然后实现一下绝望之塔的逻辑？我测试看看”。基线 b2c3134e 已统一地下城入场凭证与收费，现有绝望塔仅有静态研究，没有专用进度与结算。

## Goal
实现可供真实客户端测试的单人绝望塔：按角色进度进入、战斗、通关奖励、每日限制与持久化，并部署可回滚版本。

## Scope
包括楼层规则读取、入场资格与费用、长期进度、通关结算和专用客户端投影、回归检查与测试部署。排除其他特殊副本、客户端补丁和未经确认的周目兑换扩展。

## Constraints
遵守仓库领域分层；入场资格与目标选择分离，收费复用凭证流程；不重复扣疲劳。保留运行数据库和旧部署。

## Success Conditions
| ID | Observable condition | Required evidence |
|---|---|---|
| SC-1 | 角色按自己的下一层入场，不能伪造跳层；失败不推进 | 规则、领域和接线回归 |
| SC-2 | 每日资格与邀请函费用可解释，拒绝或组图失败不收费 | 事务回归与明确规则说明 |
| SC-3 | 通关一次性推进且重登保留，奖励与进度一致 | 持久化与重复结算回归 |
| SC-4 | 部署可启动且保留回滚输入，提供实测步骤 | 运行身份、健康检查与未验收边界 |

## Authorization
| Capability | Evidence | Authorized scope |
|---|---|---|
| task | “然后实现一下绝望之塔的逻辑？我测试看看” | 实现、检查、本地结果提交、测试部署 |

## Assumptions
当前PVF的邀请函允许每日最多挑战三层。未闭合的原生细节采用显式且可回滚的服务器规则，不将其标作 ClientVerified；100层后停止推进，周目兑换留待后续。
