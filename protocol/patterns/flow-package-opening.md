# A21 礼包开启流程

状态：**服务端实现与自动化验证完成；赛丽亚魔盒批量/单开成功路径已获 A21 实机确认**。初次交付记录只观察到第一层魔盒请求；交付后用户确认真实客户端批量与单开正常，服务端日志摘要记录了成功结算及幸运值迁移。原始逐帧抓包和完整日志未归档，普通礼包、装扮礼包以及未观察的魔盒 UI/奖励分支仍不得标记 ClientVerified。

## 三个业务边界

| 领域服务 | 负责的规则 | 协议入口 |
|---|---|---|
| `IMagicBoxOpeningDomainService` | 魔盒/钥匙匹配、批量随机抽取、赛丽亚幸运值与额外奖励 | [0450 批量](../game/client-to-server/0x0450.md)、[00D0 单个](../game/client-to-server/0x00D0.md) |
| `IPackageOpeningDomainService` | 固定、随机、自选的普通道具/装备/宠物奖励 | [00A0](../game/client-to-server/0x00A0.md)；0207 的无装扮选项形态 |
| `IAvatarPackageOpeningDomainService` | 全套或所选装扮、属性合法性、期限、完整装扮实例事实 | [0207](../game/client-to-server/0x0207.md)；00A0 的装扮选择形态 |

按真实内容区分领域，协议共用同一个 UI 入口不改变领域边界。普通宠物胶囊可以是 `[usable cera package]`，但若所含奖励全部已知且均非装扮，归普通礼包。魔盒不会经普通礼包服务绕过钥匙或幸运规则。

共享 `IOpeningInventoryDomainService` 仅承接身份校验与库存结算机制；PVF 解析、纯规则服务、三个领域入口保持分离。Application 只依赖抽象契约；Infrastructure 内复用已有静态道具元数据读取，开礼包不执行商城价格/购买限制或扣点券。

## 一次提交及有序反馈

1. 事务型命令取得账户与在线用户独占访问。确认选中会话仍为当前代、角色活动且属于该账户、容器已绑定，来源未过期且满足使用等级/职业/场景/冷却规则。
2. 从 PVF 定义生成奖励。客户端只能选择声明过的 ID/属性，不能自报奖励数量；魔盒另比对请求与当前槽位的来源、材料 ID。
3. 先规划来源/材料扣除和全部奖励落点。已有堆叠必须在完整 core 属性上兼容；装备、装扮与宠物进入各自容器，装扮写入 30 字节 jewel socket 等实例事实，宠物写完整实例记录。满包、缺少奖励定义、失效奖励与不支持声明全部拒绝。
4. 消耗、物品实例、premium 到期时间、赛丽亚幸运值在同一数据库事务内提交。后续失败抛异常回滚全部写入；会话 entitlement 投影和使用冷却仅在提交后更新。
5. 提交后向仍匹配的角色/连接代发送成功 CMD，再对已耗尽并被新物品占用的格子发送清格，随后发送最终背包绝对值及剩余清空槽位，最后发期限增量或宠物列表。**客户端原生魔盒 ACK 会自行扣减来源和材料；先更新背包再 ACK 会产生二次扣减。** 普通 00A0 当前的零附加字段路径不会删除来源对象，不能沿用魔盒扣减假设。A21 的 000E 对已有 class=1 堆叠物不同 ID 不直接替换，所以复用格必须先清后填。魔盒依据：handler RVA `00D170C0` 与 [指令文件](data/probes/a21-package-opening-20260909.md)；普通礼包及同格复用依据见 [2026-10-15 调查](data/probes/a21-opening-slot-reuse-20261015.md)。新增修复为 CurrentImplementation，客户端接收分支为 ClientStatic，尚待修复后的实机验收。

失败仅回对应 CMD 拒绝包，不发成功奖励。通知重试上限为 0，避免重放有客户端副作用的成功 ACK；旧会话的延迟通知会被过滤。库存事务可以防止两个并发请求消费同一份不足的来源，但没有声称按网络 seq 做端到端 exactly-once：两个有效的新请求在仍有来源时都可能成功。

## 真实 PVF 与赛丽亚规则

档案：`DNFClient-A21-protocol/Script.pvf`，SHA-256 `19F5FA85FF73CCE94E299E0902269DE2F0164934128F15B8A7B99249C881BE1A`。以下配置事实在自动化中读取真实档案验证；幸运奖励倍数属于参考实现业务策略（High）。交付后的真实客户端已走通赛丽亚魔盒成功路径，但没有归档能逐字段复放的成功帧，因此不能由该反馈反推 ACK 内全部字段语义。

- 第一层 `10007368` 配材料 `10007367`。60 次开启得到 `2600014 ×120` 和赛丽亚魔盒 `2682272 ×60`。先前买到的外包装 `10007476` 不属于这次材料消耗，更新服务端时保留。
- `2682272` 的材料声明保留了 `201 ×0`，含义是不用钥匙，不能将其视为缺钥匙错误。每个 `[int data]` 奖励组独立按权重抽取；本实现不因抽到不支持奖励而重新抽取。
- 幸运值独立存入账户 `seria_luck_value`，范围 0..8，默认 0；不借用 `lucky_star`。进入一次开启时值为 8，则该次触发幸运奖励，随后值变为 1；其他值递增 1。参考 `InventorySpecialConsumableService.cs` 发放规则为基础奖励加两份额外奖励，即触发的那次合计 3 倍。原生批量回包分别承载基础与幸运展示列表，实际入库按总奖励结算。
- 复活币模板 42 映射到 main 虚拟槽 1 的模板 1；premium 奖励不创建伪物品，按照 `etc/premiumlist_new.etc` 的 type/term 延长 `max(原到期,现在)+天数×数量`，使用 [NOTI 0042 subtype=2](../game/server-to-client/NOTI-0x0042.md) 发送剩余秒数；宠物奖励同步完整 NOTI 0069 列表。

## 当前内容边界

2026-11-14 起按 #328 重做礼包读取规则。规则和证据见 [任务文档](../../Document/tasks/package-opening-328/README.md)，要点如下：

- **固定内容**：`[package data]`、`[package data include usable period]`，后出现的覆盖先出现的，与客户端一致。
- **随机组 `[booster info]`**：
  - 类别开闭标签必须匹配；
  - 时装行的两个扩展数：第一个是该时装 `[avatar type select]` 的行号，决定期限，越界时用时装自己的期限；第二个是时装属性（70Reference）；
  - `[charactor]` 职业池只为开启者的职业抽取，没有对应职业的奖励时拒绝且不消费；职业名后的两个数只记录，不执行。
- **自选 `[booster select category]`**：按类别坐标组织，见 [00A0](../game/client-to-server/0x00A0.md)。
- **单值字段重复**：`[attach type]`、`[stack limit]`、`[usable period]`、`[equipment type]`、`[stackable type]` 在顶层重复时，以后一次为准（ClientStatic）。
- **物品分类**：只有装备类型 `[creature]` 是宠物；stackable 的 `[creature]`、`[feed]` 是宠物消耗品。
- **服务类道具作奖励**：金库和物品栏扩展券当普通物品发放，进入背包后经 0x0198、0x01AF 使用；其余服务类道具继续拒绝。
- **商城礼包**：带 `[package data selection]` 的 `[cera package]` 不从背包开启，只在发放时展开。

仍会拒绝且不消费来源的情况：
- 档案缺失或已过期的奖励，由 #340 修改 PVF 解决；
- 增幅、品级、强制时装属性；
- 未实现的服务类道具；
- 多外部材料；
- 未知使用次数限制。
