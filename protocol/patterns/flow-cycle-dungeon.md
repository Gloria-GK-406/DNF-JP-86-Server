# 循环地下城：准备、入场、奖励与再次挑战

2026-10-10 收口。A21 SHA-256 `1F8244D3F7309BBE2FDE4299E1863A894F6B28D5707BF01732980585B20B00DD`。
单人正常路径已被用户作为阶段接受；字节含义仍分别依赖静态分析、既有原始帧与实现，不把接受结论扩展为所有字段均实测。

## 正常流程

| 顺序 | 方向/协议 | 责任与状态变化 |
|---|---|---|
| 1 | C2S CMD000F | 打开选图上下文；普通交互通常目标为 0，重试可能携带旧地图 |
| 2 | 客户端本地 | 按当前区域 PVF 循环候选池选出地图/任务对 |
| 3 | C2S CMD0308 | 8B：`u32 dungeonId + u32 questId`；服务端校验合法配对、资格和连接代际，绑定 Cycle 意图 |
| 4 | S2C CMD0308 | 成功 9B：`01 + u32(1) + u32 questId`；失败 1B：`00`。只确认准备，不接任务、不建副本、不扣消耗 |
| 5 | C2S CMD001F | 客户端按成功响应继续接取任务；服务端核对本次 Cycle 配对，相同任务重复接取幂等 |
| 6 | C2S CMD0010 | 接取成功后客户端发正式入场；按 Cycle 意图选 active quest maze，执行准入并冻结实际难度 |
| 7 | S2C 入场投影 | 复用正常入场与 NOTI001C/001D，投影本局地图、实际难度及已创建 Cell；加载/战斗复用通用运行时 |
| 8 | 战斗及任务 | Cell 权威身份处理死亡、掉落和任务推进；CMD0022 走正常任务完成事务，循环材料与区域奖励同事务 |
| 9 | S2C NOTI0025/0023 | 即时击杀奖励和结算展示分开；0023 逐对象条目取个人已发奖账本，不再次加经验；翻牌尾部按变长列表推进 |

循环地图随机选择发生在客户端；服务端验证请求配对及资格，不另外随机出一个不同地图。
CMD0010 请求难度是期望值；服务端只从本地图支持且已解锁的难度中选最近值，同距选低，NOTI001C 同步实际值。
区域 `[difficulty level]` 未证实为固定入场难度，不能用它强行覆盖请求。

## 再次挑战

已观察序列：`CMD000F(旧地图82) → CMD0308(新地图85/任务15217) → CMD0020(取消旧任务15242)`，
随后沿正常接取/入场流程继续。前半段来源为解码后的运行日志，不伪称新增完整原始帧。

明确的 0308 请求可将同一已通过资格校验的循环区域内的 Directed 旧选择比较替换成 Cycle；
准备阶段允许旧任务尚未取消，正式接取时再检查冲突。无效配对、无关定向目标和过期连接仍拒绝。
该路径不证明 EPLP CMD0048 的所有 option；“下一个地下城”续关仍见 [#119](https://github.com/Gloria-GK-406/DNF-JP-86-Server/issues/119)。

## 关键编码与证据

- 请求样本：`54 00 00 00 63 3B 00 00`，地图84/任务15203；2026-10-09 服务端未处理帧日志，WireCaptured / High。
- 请求构包 RVA `0x0231C84D`；响应处理 RVA `0x00D05C70`，任务受理 Circle 分支 RVA `0x00D38230`：ClientStatic / High。
- NOTI0023 的 `(u32 roomActorSequence, u32 baseExperience)`：静态结果行 +0x10 与字典消费链已核对，详见[结算记录](../game/server-to-client/NOTI-0x0023.md)。
- 普通/精英/Boss 类别和 named 独立：named 内置区间加 DGN 扩展名单；经验 ×3 与类别倍率叠乘。参照算法不是 A21 官方倍率实测。
- 用户确认当前经验播报符合预期，并接受单人主线一圈；未新增字段差分、全区域、组队或异常路径验收。
