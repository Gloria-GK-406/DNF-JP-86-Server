# A21 NPC 商店

2026-09-09；当前阶段：实现服务端功能，秘药/职业转换书/金币装备/复活币礼盒购买已实机通过，
满包与限购等边界待实机验证，见[实机记录](data/traces/a21-shop-live-20260909.md)。

实机 C2S 先观察到 [SHOP_PURCHASE_COUNT](../game/client-to-server/0x02CC.md)，
随后点击购买产生 [BUY_ITEM](../game/client-to-server/0x0015.md)。
金币和预约硬币支付共用 BUY_ITEM，请求中不携带价格。

本仓成功响应顺序（2026-10-17，堆叠商品获得播报补正）：

1. 每个材料槽的 NOTI `0x000E` 绝对更新（耗尽则清槽）。
2. 对堆叠商品先发 NOTI `0x000E` 更新全部目标槽，触发原生真实新增量播报。
3. CMD `0x0015` 成功 ACK；尾表N=0。已前置投影的堆叠首记录Data=0，避免确认时再次加量。
4. 若扣了金币，NOTI `0x000E` 更新携带金币。
5. 非堆叠商品在ACK后发 NOTI `0x000E` 更新全部目标槽。
6. 限购商品附带 CMD `0x02CC`，将该商品累计购买数绝对写入商店UI；数值来自同一购买事务。

通知在购买事务提交后通过既有 Event 总线发出；失败只回 CMD 错误。
非堆叠路径仍包含原有增加语义ACK，业务购买没有增加新的自动重试；投递失败不重新执行购买。
返回选人/换角色后，旧精确会话的通知不会发送给新会话。

**2026-09-18 更新：** 2026-09-09“尚不能重算收集任务”的实现边界现已失效。购买事务内会按成交后
背包/金币重新计算持有类任务；计数确有变化时，购买 ACK 和物品/钱包通知之后再发
[`NOTI 0x023F`](../game/server-to-client/NOTI-0x023F.md) 活动任务快照。
“购买药剂 → 任务进度变化”的服务端测试已覆盖，但该增量通知与 UI 的 A21 成对实帧
仍待归档。时装、宠物、商城付费类型和未知商店条件仍不属于普通 NPC 商品范围。

实机验收需观察：硬币商品扣币并入包；金币装备扣金并入包；有限购的商品重复购买拒绝；
返回选人再进入后余额、商品及限购保持一致。跨多槽购买、失败文案及不同职业商店页面
仍需分别覆盖，不能由一次成功购买推定全覆盖。
