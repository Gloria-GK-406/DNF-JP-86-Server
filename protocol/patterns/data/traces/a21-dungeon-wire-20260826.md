# A21 副本段：线级重放与参照的逐帧对照（2026-08-26）

## 怎么取的

`scratchpad/dungeonprobe.py` 用线级客户端走完「连接 → LOGIN → SELECT_CHARACTER」，
然后**按真客户端的顺序重放它进城后发的每一帧**，记录服务端的回答。
重放的帧序取自实机记录 [a21-live-entry-20260825](a21-live-entry-20260825.md)。

**这证不了客户端接受什么**——只有客户端能证。它证的是服务端答了什么，
而这一半不需要 GUI。在锁屏反复打断取证的那两天，这条路子是唯一还能走的。

## 断线原因（先前未知）

第一次重放时，服务端在收到 6 字节 `0x008F` 的**瞬间关闭连接**，日志里一个字都没有。

- `TaggedIdReportPayloadCodec` 要求 body **恰好 5 字节**——那是旧客户端的长度；
- A21 发 6 字节（`u8 模式 + u32 flagIndex + u8 rewardFlag`），解码器抛 `InvalidDataException`；
- `GameNetworkPlugin.OnTcpReceived` 的 `try/catch` **只包住派发、不包解码**，异常直接逃出，
  连接被拆，什么都不记。

所以真客户端弹的「网络连接中断」**是服务端挂断了它**。
而且旧的读法把 `00 1E 00 00 00 01` 读成 id=7680、flag=0，正确是 flagIndex=**30**、reward=1——
即使长度放宽，教程奖励也会按错误的编号去查。

## 改完之后：与参照逐帧同形

| 客户端发 | 参照答 | 本仓答 |
|---|---|---|
| `0x000F` | `0x0002`、**CMD `0x000F`**、`0x0003`、`0x001A` | 同序同型 |
| `0x0010` | **CMD `0x000F`**、`0x001B`、`0x019F`、`0x001C`、`0x001D` | 同序同型 |
| `0x008F` | CMD `0x008F` = `01 00` | 逐字节相同 |
| `0x0252` | CMD `0x0252` = 六个零 | 逐字节相同 |
| `0x0025` | NOTI `0x001E` = 五个零 | 逐字节相同 |
| `0x00BF` | NOTI `0x00AA` = `01 00` + 回显请求两字节 | 逐字节相同 |
| `0x04DD` | CMD `0x04DD` = `01` | 逐字节相同 |

三条通知的 body 与参照的差别只剩数据：`0x001B` **37 字节逐字节相同**；
`0x001C` 只差副本号（客户端报 10000，参照那局是 10005）与 boss 格；
`0x001D` 只差随机种子与房间地图号。

**会话在重放结束时仍然存活。**
