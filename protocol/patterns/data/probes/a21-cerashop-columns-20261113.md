## 客户端字符串是延迟解密的

镜像里搜不到 `CeraShop`、`[package]` 这类明文。原因是字符串常量加密存放，第一次使用时才解密，结果放在堆上的缓存里，不写回原处。所以内存镜像里同样没有明文。

| VA | 作用 |
|---|---|
| `027BACA0` | 单字节字符串入口：首字节为 `A1` 视为已解密，否则调 `027BAB90(p, 1)` |
| `027BACC0` | 宽字符串入口：首字为 `0x2CA1` 视为已解密，否则调 `027BAB90(p, 2)` |
| `027BAB90` | 查缓存；未命中时算长度、分配缓冲，调 `027BA5A0` 解密 |
| `027BA5A0` | 解密核心 |

密文块格式和算法（已离线复现，解出 `etc/` + `chn_schedule.etc`，与 `011C4B54` 处已知的加载点一致）：

- `b = 块[1] & 0xFE`，`w = u16(块[2..4])`。
- 长度 = `((b << 7) | b) ^ w`，按字符计；再乘字符宽度（1 或 2）得到字节数。
- 密文从 `块+4` 开始。初始密钥 `key = 0x9A714CA0 | b`。
- 每 4 字节：`明文 = 密文 ^ key`，然后 `key = key * 0x1003F + 明文`（32 位截断）。
- 剩余不足 4 字节的部分：`明文 = 密文 ^ (key & 0xFF)`，然后 `key = key * 0x107 + 明文`。

用法：扫描所有 `push imm32` 后紧跟 `call 027BACA0/027BACC0` 的位置，对立即数指向的块解密，本次共解出 78,001 条字符串，带调用点地址，可以直接按字符串反查代码。

## 加载与解析

- `00B47623`：`CNRDCashShop`（`RDAR/CashShop/Localization/CNRDCashShop_CHN.cpp`）以 `Etc/CeraShop.etc` 调用 `02B1F0A0`。同一处还加载 `Etc/MileageShop_chn.etc`、`Etc/chn_CeraShopHideList.etc`。
- `02B1F0A0`：把文件读成文本 token，用一张静态的「标签 → 编号」表分派。分节编号节选：`[coin]` 0x540、`[package]` 0x58D、`[community package]` 0x594、`[avatar]` 0x59C、`[item]` 0x5C9、`[community item]` 0x5D1、`[premium]` 0x5D9、`[creature]` 0x5FE、`[regular package]` 0x61C。0x51A–0x614 段经 `02B2357C`（字节索引）/ `02B23528`（跳转表）分派。
- 每个分节的处理代码把一行读进同一种商品记录，记录首字节写分节类别（`[item]` 3、`[creature]` 4、`[package]` 8、`[premium]` 10），再插入各自的列表（`029E8860`）。

## `+0x24` 是格子上的活动角标

`00B483D1` 加载 `interface/cashshop/cs_eventtag_cn.img`，存到界面对象 `+0x20EE0`。读这个成员的绘制代码在 `00B33960` 起：

```
00B33966 cmp  byte ptr [edx+0x24], 0        ; 0：不画
00B339A4 movsx eax, byte ptr [edx+0x24]
00B339AB dec eax ; je 00B33B68              ; 1：第 0 帧（某开关打开时改播 +0x20F18 的动画）
00B339B2 dec eax ; je 00B33A95              ; 2：第 2 帧，再叠一层闪烁的第 3 帧
00B339B9 sub eax, 2 ; jne 跳过               ; 4：第 9 帧，再叠一层闪烁的第 10 帧
```

其它值不画。帧号是 `027D7F30` 的第二个参数（`push 0/2/3/9/0xA`）。

所以 1、2、4 只决定格子上画哪个角标。**置信度 High（静态走图）**：

- 已覆盖：分节解析代码里没有其它地方读这一字节。
- 未覆盖：记录被复制进界面对象后可能另有读者，静态走图没有全部追到。
- 每个值对应什么文字（NEW、HOT 等）没有核对，要看图片帧。
