## 售价不能直接照抄参考服

PVF 装备 27312（锋利的印度古剑）明确声明 `[price] 18000`、`[value] 12960`、
`[durability] 45`；`equipment/pricetable.tbl` 首段为 `200 150 30`。
这能确认字段原值，**不能单独证明出售公式**。

参考实现 `E:/Project/86JP/Server/DfoServer/Game/Inventory/ItemMetadataResolver.cs:211`
对装备使用 `max(1, value * EquipmentRate / 1000)`；堆叠品使用 value/5，并有 price 回退。
它是另一份重建，只作线索。本仓不能把购买价直接作为出售所得。

当前客户端出售确认窗 `1FEECC3..1FEECFF` 使用物品虚表 `+94` 的返回值乘数量。
已定位一组装备对象虚表（VA `03235F24/03236404/03236B54`），该槽指向 RVA `01285FA0`：
它携带对象状态和两个安全整数进入 `02538230`，第五个实参固定为 1。
`02538230` 存在比率选择、可选两个整数的比值、浮点截断和末尾 90/100 折算。
完整价格函数另存为[指令摘录](a21-sell-price-20260909.disasm.txt)。

## 运行参数与用户报价（2026-09-09 11:00 左右）

用户把古剑停在出售确认框，最终更正报价为 **2332**（先前口述 2322 是笔误）。
只用 `OpenProcess(PROCESS_QUERY_INFORMATION | PROCESS_VM_READ)`、`VirtualQueryEx`、
`ReadProcessMemory` 读取 PID 34320；没有附加断点、写内存、注入或操作窗口。
售价表 VA `04E0FDE0` 三个安全整数解码为 `200,150,30`；
VA `03045E20` 的 float32 为 `0.0010000000474974513`。

筛选装备虚表 `+94 == 01685FA0` 且对象 `+78 == 12960`，得到以下两对象：

| 字段 | 对象 400E0000 | 对象 400E2000 |
|---|---:|---:|
| 虚表 VA | 032D842C | 032D842C |
| `+78` 基础 value | 12960 | 12960 |
| `+40C` 比率分支字节 | 0 | 0 |
| 安全整数 `+618` | 45 | 45 |
| 安全整数 `+FF8` | 45 | 45 |
| 安全整数 `+1070`（是否改用特殊基础值） | 0 | 0 |
| 安全整数 `+F64`（特殊基础值） | 0 | 0 |

安全整数按 RVA `023BC0F0..023BC390` 的只读算法解码：索引查全局
`03B89618` 的 page/key 表，用低 16 位 key 复制到高位后 XOR 对象存值。
上述数值 **Confirmed**；两整数对应最大/当前耐久 **High**，与 PVF 45 和数据库 45 相符。
对象未在此次采样中独立解码物品 ID，归属古剑由 value、耐久、数量和当前确认框交叉支持，
该归属为 **High**。分支字节非零以及特殊基础值对应的业务状态仍待独立验证。

普通装备采用客户端运算顺序：

```text
raw = float32(value) * float32(rate) * 0.001f
if maxDurability != 0: raw = raw * min(currentDurability, maxDurability) / maxDurability
unitGold = trunc(raw) * 90 / 100  // 最后为整数除法
totalGold = unitGold * count
```

古剑为 `trunc(12960 × 200 × 0.001 × 45 / 45) × 90 / 100 = 2332`，
与用户确认框报价一致。最大耐久为 0 的分支按原指令先算 `rate * 0.001f * value`。
普通堆叠物品基类 getter RVA `00AE6C70` 传入 0,0,0,0，使用第一比率且无 90% 折算；
这条路径有静态证据，尚无成功实机成交样本。
