## A21

**2026-08-24。** 上面的机器区由 **A12** 客户端（SHA-256 `F78F0AEA…`）的静态普查生成。
本节记录 **A21** 客户端（SHA-256 `1F8244D3…`）上不同的部分。判据除另有注明外，都是一份
A21 参照会话，归档于
[a21-world-entry-20260823.log](../../patterns/data/traces/a21-world-entry-20260823.log)
（section L 是入场序列的逐帧顺序）。

A21 在 `0x0016 USER_POSITION` 之后发这一帧（section L 第 60 帧）。

参照 body 508 字节，结构由步长解出：

```text
[0]      标志/子类型（参照为 0）
[1..2]   u16 条目数（参照为 5）
之后     每条 101 字节，条目内偏移 69 处是 0xFF
```

`3 + 5×101 = 508`，闭合。参照的五条 id 是 `0xB1`..`0xB5`，与该角色 `items` 表里
`list_type=0` 的五行一一对应；每条的 `[2:]` 与库里的 `item_core` **前 81 字节相同**，
其后还有 18 字节未解释。

服务端目前**发空表**（`00 00 00`，条目数 0），因为条目内容尚未建模。

### 2026-08-25：入场批次逐帧对账

判据是本仓入场批次与 A21 参照会话的逐帧对账，归档于
[a21-entry-batch-diff-20260825](../../patterns/data/traces/a21-entry-batch-diff-20260825.md)。

**入场窗口里参照只发一帧，而且不是空信封。** 那一帧就是当日补给的实际结果（5 条，
id `0xB1`..`0xB5`），位置紧接 `0x0016 USER_POSITION` 之后、`0x0165` 之前。

本仓此前在批次里发一帧空表（`00 00 00`），补给的真结果在四帧之后另发一帧——于是参照有一帧
的地方本仓有两帧，且两帧都不在参照的位置上。现在补给命令与它的增量都提到闸点之后的尾帧
**之前**执行，空信封撤掉。

上文「服务端目前发空表」那句到此为止：它描述的是那次改动之前的状态。

### 补记：同一天第二次进场没有这一帧

当日补给每角色每天只发一次。撤掉空信封之后，`CommittedUpdates` 为空时这一帧一帧都不发——
所以「与参照多重集一致」只在当天首次进入该角色时成立。

参照那一局是不是首次进场无从判断，因此**无法区分「A21 总是发一帧 `0x000E`」与「因为补给
发生了才发」**。两种读法在现有证据下等价；如果后者为真，现在的行为是对的，如果前者为真，
非补给日就少一帧。取得一份「同一角色当天第二次进场」的参照即可判定。

### 2026-09-01：第二个调用方——通关翻牌

在此之前本帧只有一个调用方，就是上面那条入场补给。现在有第二个：**通关结算的翻牌**
（`CMD 0x0047 SELECT_CARD`）。玩家翻开一个牌位，牌位上的装备进背包，本帧说明背包哪一格
变成了什么。

**参照服务端确实在翻牌之后发本帧，而且紧接应答。** 判据是参照服务端自己的报文日志
`ServerS4A21/_reference-backup-20260826/packet_log.txt`（本仓之外），822–825 行连续两帧：

```text
SEND cmd=0x01 type=0x0047 len=48  body=(33B)  [01 00 FF 00 00 FF FF 00 00 FF FF …]
SEND cmd=0x00 type=0x000E len=119 body=(104B) [00 01 00 00 00 00 00 00 00 91 00 …]
```

先应答后通知，中间没有别的帧。同一份日志 236 行是入场那一帧（508 字节，5 条，
`0xB1`..`0xB5`），与本页 A21 一节记的完全一致，所以这份日志与那一节是同一类证据。

**这一帧的 body 闭合于 `3 + 1×101 = 104`。** 列表类型 `0x00`（主背包），条目数 1，
条目按已记的布局读出：槽位 `0`、物品 id `0`、数量 `145`。

**但这条参照样本装的不是一件装备。** 同一份日志 148 行是参照自己的主背包全量快照
（`NOTI 0x000D`，14 条），它的头三条就是 `槽 0 / id 0`、`槽 1 / id 1`、`槽 2 / id 2`，
数量都是 0——这三个是虚拟槽，id 等于槽号。所以参照那一次翻牌用本帧告知的，是虚拟槽 0
的数量变成了 145，而不是某一格里多了一件东西。**因此「参照如何用本帧描述一件装备的到货」
并无样本**——本仓翻牌到货写的是普通条目，依据是本帧条目区的布局本身（已闭合），不是对
这条参照样本的模仿。

同样**无从判断的**还有：参照是不是每次翻牌都发这一帧，还是只在有东西可说时才发。只有一份
样本，而那一次恰好有变化。

**顺序在本仓的实现。** 应答与本帧在同一次发送里发出，应答在前；这既是上面那段参照的顺序，
也与地面拾取（`CMD 0x002B` 的应答后跟 `NOTI 0x0027`）一致。

**实现映射变了一处。** 该帧此前是 `Game/StateSynchronization/` 切片内的类型；
