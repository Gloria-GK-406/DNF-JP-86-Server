| 项 | 内容 |

| Endpoint / Direction | Game，Server → Client，CMD 族 |
| Evidence | ClientStatic：A21 DNF.exe SHA-256 `1F8244D3F7309BBE2FDE4299E1863A894F6B28D5707BF01732980585B20B00DD`，响应 handler RVA `0x00D3D950`；UpstreamReference：`ServerS4A21/Server/DfoServer/Network/Builders/Inventory/ItemUpgradeAckBuilder.cs`；CurrentImplementation：本服 `ReinforceItemResponseEncoder` |

客户端通用 CMD 信封先读取 `u8 ok`，若为 0 再读 `u8 reason`；错误最短必须为 `00 reason`，不能只发 `00`。本 handler 在 PE VA `0x0113E56C–0x0113E59F` 有 reason 跳表；静态可达 reason 包括 `04,07,0A,0D,13,15,16,17,5F,D6` 等。本服只选其中有参考端候选语义的值：目标/会话 `04`、耐久 `07`、金币 `0A`、内容/结果不支持 `0D`、限制 `13`、容量 `15`、材料 `16`、模式 `17`、锁定 `D6`。具体 UI 文案尚未由实机确认。

成功包（括号内字段语义为 UpstreamReference，宽度及顺序由 ClientStatic `0x0113DA21–0x0113DABB` 的 1/2/4 字节读取原语证实）：

```text
u8  1                    // CMD 成功信封
u8  method               // 普通强化 0，增幅 1
u16 materialSlot
u32 materialRemaining
u16 optionalTicketSlot
u8  reserved = 0
u8  oldLevel
u8  resultCode           // 0 成功，1 保留，2 降级，3 破坏
u8  newLevel
u8  targetList           // body[14]：0 主背包，3 穿戴装备
u16 targetSlot
u16 optionalTicketSlot
if resultCode == 3:
    u8 rewardCount
    repeat rewardCount: u16 slot, u32 itemId, u32 count
```

`resultCode == 3` 的附加读取可定位于 PE VA `0x0113E24F–0x0113E304`；即使没有产物也需写 `rewardCount=0`。当前实现先由账户命令事务结算，再发 ACK、受影响物品槽、账户虚拟材料及金币的更新；没有把 70 的 `0x53` 或 `0x56` 报文直接搬到 A21。成功字段的 UI 意义、可选券是否应回显请求槽位以及公告条件仍需真实帧和用户 GUI 结果确认。
