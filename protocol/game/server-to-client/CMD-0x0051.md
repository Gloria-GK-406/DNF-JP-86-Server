## 成功 body（9字节，含 CMD 信封）

| 偏移 | 类型 | 含义 |
|---|---|---|
| 0 | u8 | 成功=1 |
| 1 | u16 | 材料在 Main 的槽位 |
| 3 | u32 | 材料剩余数量；0删除槽位 |
| 7 | u16 | 操作类型；1封蜡，2品级重抽 |

客户端 handler RVA `0x00D255B0`：读取 u16/u32/u16，按第一个字段查材料；数量0调用 `0x012F1300` 删除，非0调用材料对象 vfunc+0x40 更新数量。最后字段1/2分别走文本ID `0x6A3`/`0x6A4`。CMD信封在分发前剥离，失败分支读取错误码并关闭相应操作窗口。

回包不携带装备 ID、目标槽或新种子。提交后按 CMD0051 → NOTI000E 目标装备完整 core 投影；不重复发送材料000E。上游曾使用“目标ID+列表类型+目标槽”的10字节成功回包，与此 A21 handler 不符。

2026-10-13 CurrentImplementation：普通黄金蜜蜡采用同一9字节成功体，最后u16操作类型为1，材料剩余量按本次PVF费用扣除；NOTI000E更新原实例的封装状态与次数，不重建装备。次数位于Attribute高三位，低五位强化不变。失败仍只有`00 + reason`，不发送成功提示／装备刷新；次数满0D、已封装12、材料不足11、其他限制13，具体文案待实机。原调级成功仍为操作2。见[实现和验收](../../../Document/EquipmentReseal-20261013.md)。

## 装备种子（ClientStatic）

ItemCore.Value 对装备是属性种子，与服务器 ItemUid 不同。以下地址均取自本页头部的内存证据，按指令读出。

- `0x01ED2DD0` 是 glibc `rand_r`：`state = state × 0x41C64E6D + 0x3039` 连推三次，取 `(s1>>16)&0x7FF`、`(s2>>16)&0x3FF`、`(s3>>16)&0x3FF` 拼成 31 位结果并写回 state。Confirmed。
- `0x0126E650` 对种子副本调一次 `rand_r`，结果 `%100` 按 20/40/60/80 分成档 0–4。不能用 seed%100，也不能按种子数值大小判断品级。Confirmed。
- `0x026430B0` 识别固定属性种子 `999999993、999999996、999999999、999999995、999999998`；这五个值经 `0x0126E650` 依次落在档 0–4。PVF 明确最高品级箱使用 999999998。普通生成/重抽使用正 31 位随机数并排除这五个值；不得将 999999998 视为普通随机种子的有效上界。

品级百分比 p 在 `0x00AA6E60` 计算（唯一调用点 `0x0128BA63`，即 `0x0128B9F0` 转调），两条分支在 `0x00AA7650` 写入同一局部变量：

| 种子 | p | 等级 |
|---|---|---|
| 固定种子 | `(档位 + 1) × 20`，档 0–4 依次为 20/40/60/80/100，即各档上限；不消费随机数 | Confirmed |
| 普通种子 | `s × 档位 + (rand_r % 2000) / 100`，档内随机宽度 20 | 公式 Confirmed；`s` 未闭合 |

常量 20、100.0、1.0 取自函数内受保护容器（初始化源 `0x30440E8`=100.0、`0x304396C`=1.0，整数 20）。档位由调用方以 `0x0126E650(seed)` 求得后传入。`s` 由调用方取自 `0x0126E6A0`（物品 vfunc `+0x144` 的解引用，取不到时返回 0x19）；0x19 在 `0x0128B9F0` 与 `0x00AA6E60` 入口是跳过品级计算的标记，0x0D 走另一分支。`s` 的实际取值没有证据，按 20 理解只是 Hypothesis。p 随后夹在上下限之间，再在 `0x00AA7A3F` 一带按 `round(p / 100 × 基数)` 换算（`0x0124CE20` 转整数）；基数来源未闭合，因此 tooltip 逐项显示值仍不能由服务端算出。
