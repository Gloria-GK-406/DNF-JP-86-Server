## 偏移 14 是地图 id，不是迷宫序号——用错会崩

上游那个字段在类型里叫 `MazeSumInfo.Index`，名字读起来像"迷宫序号"，**它不是**。两条旁证：

- 血色祭坛分支往同一个位置传的是 `(ushort)sentMapId`（`DungeonMapHandler.cs:568`）
- 深渊那段日志把它和另一个 map id 并列打印：`hellMap={maze.Index} normalMap={hellRoomInfo.NormalMapId}`

迷宫序号另有其位——它是 [`0x001C`](NOTI-0x001C.md) 里的 `modeFlag`，而且是 `u8`。

**实机判别（2026-08-18）**：这里误写迷宫序号 `0` 时，客户端进度条正常走满，
随后**切换时黑屏、等待数秒、进程崩溃**——即"加载一个不存在的地图"的表现。
改成房间地图 id（教程起点房间 `61000`）后角色正常站入。

*教训*：上游的字段名是转录来的线索，不是定义。一个叫 `Index` 的字段可以是 id。

## A21

**2026-08-26。** 上面的机器区由 **A12** 客户端（SHA-256 `F78F0AEA…`）的静态普查生成。
本节记录 **A21** 客户端（SHA-256 `1F8244D3…`）上不同的部分。判据是 A21 参照会话的字节
（[原始字节](../../patterns/data/traces/a21-reference-entry-bytes-20260825.md)）与本仓的线级重放
（[副本段对照](../../patterns/data/traces/a21-dungeon-wire-20260826.md)），以及产出那份参照的
服务端自己的构包器。

**23 字节，不是 21。**

两处不同：

1. **房间地图号是 `i32`，不是 `u16`。** 值没变，宽度错了——这是两个字节里的两个。
2. **偏移 7 那个字节默认是 2，不是 0。** 本仓把它当深渊模式标志写 0；A21 的构包器把它
   默认成 2（普通副本标记），参照会话的两帧 `START_MAP` 也都是 2。

顺带纠正一个曾经的猜测：`[0]` 就是当前格的 X。参照第二帧 `01 01 00 …` 是 X=1、Y=1，
不是「是否换图」。

### 2026-08-26：怪物表在这一帧里，空表等于房间里没东西可打

**23 字节是「房间里没有 actor」的长度，不是这一帧的长度。** 之前把它当成定长，是因为参照
会话（魔枪士，副本 10005）的前两间房**本来就没有怪** —— `Tutorial_Demonic/tutorial(0,1)_start.map`
整张图没有 `[monster]` 段。空表和它逐字节相同，所以这个缺口在 66 帧对账里完全不可见。

**布局：**

```text
u8   当前格 X
u8   当前格 Y
u8   分层房间标志
i32  随机种子
u8   普通副本标记（A21 默认 2）
u8   其后一个未命名字节
i32  房间状态值（默认 1）
u8   房间状态标志（首次进入 1）
i32  房间地图号
u8   actor 条数 n
n ×  {
       u16  模板序号
       i32  包内索引
       u16  运行序号
       i32  code
       u8   等级
       u8   类型      0..3 怪物，5..8 AI 角色
       u8   标志 0
       u8   标志 1
       i32  额外状态
       u8   A21 追加
     }                                            ← 每条 21 字节
u8   预生成掉落条数
u8   深渊迷雾标志
u8   可骑乘对象分组数
u8   队伍成员索引（单人 0xFF）
```

**actor 从房间的地图文件来，不是副本文件。** `.dgn` 只说哪一格用哪张图，图里才写站着什么：

- `[monster]` 一段是**连续多条**记录，每条 `code 等级 类型 x y z ? ?` 八个整数 + 两个引号词。
  新手副本后面几间房一段里就有四条、五条，按"一段一条"读会把除最空的房间外全部读少。
- `[ai character]` 每条 `code x y z` + 两个引号词 + 两个整数。**等级不在地图里**，在这个角色
  自己的 `.aic` 的 `[minimum info]` 里：一个引号名，然后第 5 个整数就是等级。

**运行序号**是客户端事后指认 actor 的名字——它在 `CMD 0x0027 DIE_MONSTER` 里回的就是这个数。
A21 每个房间从 1..60000 随机取起点（沿用旧服 `get_rand_int(60000)`），目的是避免快速退本重进时
和客户端手里残留的 identity 撞号。本仓改为从本局种子和房间地图号推导，效果相同且不用存计数器。

**实测对账（2026-08-26）：** 同一客户端、同一副本 10000、同一间房 61000，本仓与上游的
`START_MAP` 都是 65 字节，**差异只有随机种子和序号基数**，两者都是每局自取的值：

|---|---|---|
| actor 条数 | 2 | 2 |
| actor 0 | seq 75，code 61670，等级 1，类型 0 | seq 6093，code 61670，等级 1，类型 0 |
| actor 1 | seq 76，code 461，等级 80，类型 5 | seq 6094，code 461，等级 80，类型 5 |

code 61670 是地图声明的怪物，461 是 `aicharacter/swordman/aganzo_tu/aganzo_tu.aic`（阿甘左），

### 2026-08-26（二）：预生成掉落块，房间可破坏物的内容

`actor` 表之后那个 `u8` 不是恒零的填充，是**房间里可破坏物所含物品的条数**，每条 19 字节：

```text
u8   对象序号（房间内声明顺序，从 0）
u16  地面物件号（从 1 起）
u32  itemTemplateId
u32  实例值
u16  耐久
u8   强化类型
u16  强化值
u16  扩展
u8   扩展
```

**注意与 `NOTI 0x0026 DIE_MONSTER` 的掉落记录不是同一形状**：那边每条 48 字节，多一个掉落组 id
和两段留白。同一件事，两帧写法不同。

**内容由两处声明合成，缺一不可：**

- 房间的 `.map` 的 `[special passive object]`，每条 `code x y z ? [item] 组号 数量 -1 -1 -1`
  （5 个整数 + 一个引号词 + 5 个整数）。只有引号词是 `[item]` 的才产出东西。
- 副本的 `.dgn` 的 `[special passive object item]`，是一串组：`组号 ? 条数`，其后 `条数` 对
  `(itemId, 权重)`。**组可以声明 0 条**——新手副本第三组就写作 `2 -1 0`——所以这一串必须按
  计数读，不能按固定步长切。

耐久取自物品自己的 `[durability]`，与角色创建时穿上的那几件同源。

**判据。** 参照会话（魔枪士，副本 10005）第三间房 61032 发 63 字节：1 个 actor + **1 条掉落**，
`objIndex=0 ground=1 item=14400 耐久=25`。14400 是残破的牛皮护肩，其耐久正是 25，而该角色
此后确实把它穿在了 15 号槽上。本仓在鬼剑士副本 10000 的第二间房 61001 发 126 字节、同样 1 条、
同样 `item=14400 耐久=25`——两个副本经各自的表取到同一件物品。

**这一条是卡关的直接原因（2026-08-26 实机）：** 该房间清空后客户端连发两次
`CMD 0x00BF 00 02`（剧情暂停开始）而**再不发 `01 02`（结束）**，此后只剩心跳。教学在
"打破箱子拿道具"这一步等一件永远不会出现的物品。反证：魔枪士副本前两间房**不声明**可破坏物，
上游那两帧就是 23 字节零掉落，客户端照样走过去了。

### 2026-08-26（三）：地面物件号是客户端后来指认这件东西的名字

上一节把「地面物件号」记作「从 1 起」，那时它只是照抄参照帧的一个数。同日实机之后它有了意义：
玩家拾取时发的 [`CMD 0x002B GET_ITEM`](../client-to-server/0x002B.md) **只读两字节，就是这个号**。

于是它有两条约束：

- **同一间房内互不相同**——否则拾取请求指认不出是哪一件；
- **同一间房被重新描述时不变**——玩家走出去再走回来，客户端手里那个号还得对得上。

本仓因此把它定为**房间内按声明顺序数，从 1 起**，而不是像上游那样从一个整局递增计数器取。
上游 `PassiveObjectDropProjectionService` 把掉落登记进 `run.Drops` 字典、按 `SceneSlot` 分配，
本仓则每次重新从档案读房间、只在运行状态里记「哪一号已被拿走」。两种做法都满足上面两条；本仓
这一种不需要为一间房存一份掉落表。

**剔除在编号之后。** 已被拿走的那一条从表里去掉，但不重排剩下的号——先按房间的完整声明编号，
再滤掉拿走的。否则玩家拿了第二件之后，第三件就会改叫「2」。
