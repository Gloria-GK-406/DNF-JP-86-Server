### subcmd 0 / 1：好友列表

```text
u32 subcmd          ; 0 或 1
u32 count           ; 有符号，<0 时放弃（01A2FEF8）
count × {
  u8   server       ; ≥0xFA 时放弃本条及其后全部（01A2C655）
  u16  ch           ; → 条目 +0x24
  dstr name         ; 1–255 字节（01A2C698 ReadDStrW max 0x100）
  u8   level        ; → +0x26
  u32  job          ; → +0x28
  u8   grow         ; → +0x2C（经 019DAFB0）
  u8   bl           ; → +0x2E = (bl≠0)，即「在黑名单中」标志
  u32  tail         ; → +0x38，未见读取（High，见下）
}
```

条目读取 `01A2C600`，Confirmed。逐条插入 `01A2FCD0` 的规则（Confirmed）：

- 该 `(server,name)` 已是好友 → 插入失败，**其后条目全部不读**（`01A2FD24`→`01A2FF8B`）。所以同一份表里
  名字不能重复；玩家若对某好友做了客户端本地的临时遮断，该节点会在 subcmd 0 中保留下来，下一份全量表读到它时
  同样中断（服务端无法感知，属客户端限制）。
- 已存在但不是好友（例如只在黑名单里）→ 只置好友标志，线上的 ch/level/job/bl **不写入**（`01A2FE08`）。
- 不存在 → 整条插入。

**全量会清掉黑名单**（RQ-004）：`01A31F62 cmp byte [node+0x5F],0 / je 跳过` 只把临时遮断节点复制到临时 map，
随后清空原 map 并交换（`01A32047` 起）。`CMD 0x0078` 应答写的是同一张 map（`0111F91B → 01A2F4B0`），
所以全量之后黑名单页为空，直到再收到 `0x0078` 应答；被拉黑的好友只剩线上 `bl` 字节决定的标志，加入日期丢失。

**末尾 4 字节**（RQ-003）：只存到条目 `+0x38`（`01A2C74D`）并随条目复制（`01A2B91A`、`01A2B9EB`）；在好友/黑名单类
（`01A2A000–01A34000`）与好友窗口绘制区（`02480000–0248A000`）没有任何读取。ClientStatic / High。写 0 即可。

## 实现：本仓 CurrentImplementation（2026-11-12，#60，待实机）

消息、编码器与构建在 Game 层 `Server/src/Dfo.Server.Protocol/Game/FriendFrames.cs`，在 UnitedFriend 切片注册一次：

- `FriendListMessage`（subcmd 0）：`[0:u32][count:u32]` 加每条 `[1][ch:u16][name dstr 1–255B][level:u8][job:u32][grow:u8][bl:u8=0][tail:u32=0]`。
  没有好友也发 count=0（8 字节）。64 条时最大 body `8 + 64 × 273` = 17480；条数受关系上限 64 约束。
- `FriendRemovedMessage`（subcmd 2）：`[2:u32][count:u32]` 加每条 `[1][name dstr 1–255B]`。
- 构建 `FriendListBuilder.BuildAsync`：条目顺序取关系服务的顺序；名字、等级、职业、转职取目标的当前值；ch 为好友所在频道号
  （`ISelectedSessionDomainService.TryGetInWorld` 的监听端口经 `IChannelEntryDomainService.ResolveAsync` 换成 `ChannelId`），
  同频道在线也填频道号、不补发 USERINFO（Spec AM-2），离线为 0。server 恒为 1（与 USERINFO subtype 0 尾块 +55 一致）。
  名字为空或超过 255 字节、与前面条目重名（客户端会从重复项起丢弃整表其余部分）、等级或转职超出一字节的条目跳过并上报，
  由调用方记 Warning。`bl` 写 0：随后的 CMD `0x0078` 会把黑名单标志补上。
- `FriendListRefresh`：全量与紧随其后的 [CMD `0x0078`](../client-to-server/0x0078.md) 黑名单列表成对构建、按序发给同一接收者
  （RQ-004 证实全量会清掉黑名单）；CMD 用 `RegisterAsync`，通知处理器取 `Messages`。
- 发送方：CMD [`0x0122`](../client-to-server/0x0122.md)／[`0x0123`](../client-to-server/0x0123.md) 成功后；选角进入批次在原空基线的
  位置（CERA 之后、USER_POSITION 之前）发真实全量，紧跟 CMD `0x0078`，进入序列中只有这一份全量
  （见 [进入世界](../../patterns/world-entry.md)）。好友上下线、升级、被删除时给观察者的推送属后续单元。
- 已知限制：未配置频道目录的监听端口解析为 `ChannelId` 0，好友在这样的频道上在线会显示为离线。
