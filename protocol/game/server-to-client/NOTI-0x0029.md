## 2026-11-15 座位 uid 的"无人"值为 0xFFFF（Spec SA-2，CurrentImplementation）

观察：实机房间人数固定显示 8/8；当时服务端空座与关闭座位写 uid 0。

服务端现在空（`0xFF`）与关闭（`0xFE`）座位一律写 uid `0xFFFF`，占用座位写其会话 uid。规则只在
`SupplementalSynchronizationCodec.PvpSeatUserId` 一处，本帧与 [NOTI-0x002B](NOTI-0x002B.md) 共用。修复后待实机复核人数显示。

### 客户端证据：座位 uid 0xFFFF 表示无人（ClientStatic/High）

来源：b1 debug exe 的反汇编（由支持客户端 `1F8244D3…` 重建，ImageBase `0x400000`），下列地址均为客户端镜像 VA。

| VA | 位置 | 看到的事实 |
|---|---|---|
| `0x01173790` | 本条的读取函数（机器区 handler 入口 RVA `0x00D73790` + ImageBase） | 每个座位读 `u8 state` + `u16 uid`，随后调用房间对象虚表 `+0x5C`，参数 `(seat, uid, state)` |
| `0x01A6B970` | 房间信息结构初始化 | 对每个座位写 state=`0xFF`、uid=`0xFFFF` |
| `0x01A0573C` | 空座计数 | 循环比较 uid 数组 `[+0x2C + 4i]` 与 `0xFFFF` 并计数 |
| `0x01A070A0` | 座位设置函数 | 新 uid == `0xFFFF` 时走移除分支 |

推论（由上表得出，未逐帧跟踪）：uid 0 不等于 `0xFFFF`，因此此前写 0 的空座与关闭座位都被当作占用者，人数显示 8/8。
