# CMD 0x0019 COMPOUND_ITEM 制作结果

A21 handler RVA00D36A30。静态直接读取序列为ClientStatic/High；当前编码为CurrentImplementation。上游CompoundItemAckBuilder仅是UpstreamReference。本实现没有成功制作的A21 S2C实帧或ClientVerified。

失败：`u8=0,u8错误码`。成功：`u8=1,u8消耗行数,消耗行[],u8产物行数,产物行[]`。状态字节由CMD分派读取，成功handler从消耗行数开始。

消耗行7B：`u8列表,u16槽,u32扣减量`。堆叠/账户虚拟材料列表0，金色小晶块槽359。客户端D36A90..D36BAB用该值移除/减数量，语义High；后续NOTI提供绝对最终值。

产物行当前45B：`u8种类,u16槽,u32模板,u32数量或实体值,u8属性,u16耐久,u8封印,u16增幅值,u8增幅类型,u32标记,u8Genuine,u8Emancipate,u8Trade,u16Tail0,5×u8尾字段,12B不透明零值,u8EquipmentLock`。

D36DB7/D36DD1初始化4/8B不透明对象，经受保护函数234FBE0读取，D36DEE再读最后u8；上游用12B零尾。当前把这12B放在每个产物行内。内部语义与真实编码宽度仍需实机/S2C校准，不称作字符串或金币，也不以编码自测证明协议。

成功提交后CMD与全部变化/清空背包槽、账户材料最终值一并派送。重复请求不重复发改变本地计数的CMD，重新读取当前库存/余额发绝对刷新，避免旧回执覆盖后续操作。

服务端：`Game/CompoundItem/CompoundItemSlice.cs`负责协议，`RecipeCraftDomainService`负责检查和结算；`IRecipeCraftRuleService.GetResultAsync(drawingId)`只返回需求/产物。
