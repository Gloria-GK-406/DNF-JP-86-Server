## 本仓写什么(2026-09-02 修订)

**本页此前写的是「本仓这一局什么都不发,帧里也就这么写」,并把原因记为「经验公式、
评级奖励表和翻牌生成器这三样都还没有」。这句已经不成立,分两次失效,三样现在都有了。**

**一、经验(`+0` 与 `+4`)。** 通关经验落地之后,这两格写的是这一局**实际入账的**那一份,
不是估价:`+0` 是授予记录里的基础值,`+4` 是实得减去基础值。估价本身出自
`DungeonClearExperienceRules`——基础按副本 `[basis level]` 查任务奖励表,再乘世界通关率、
难度率与副本自身的经验权重;评级加成按客户端上报的评分在 `RankSystemInfo.etc` 的评级表里定档,
乘该档费率。没被经验表上限夹住时,`+4` 就等于那个评级加成。
发不出去时(会话没有技能点镜像,或授予未发生)两格写 0。

**二、牌尾。** 通关翻牌落地之后,牌尾按本局结算时定下的**免费**牌面写实值:

| 本仓偏移 | 字段 | 写什么 |
|---:|---|---|
| 160 | 免费翻牌位数 | 牌位 0 有东西写 2,否则写 1 |
| 161 | 免费牌物品 | 牌位 0 的物品 id;没有东西写 0 |
| 165 | 免费牌金币 | 牌位 0 有东西时写 `GameProtocol.ClearRewardCardGold`,否则 0 |
| 169…223 | 七个牌位 | 标记**七个都写 1**;(物品, 数量) 前三个取牌位 1、2、3,后四个本仓没有对应牌位,两个字段都写 0 |
| 232 | 付费翻牌花费 | 见下 |

牌面内容**不是这个编码器去问来的**,而是结算时定下、随帧传进来:一个自己去问档案的编码器
会成为「这一局的牌面在哪定的」的第二个答案。牌位 0 的那份金币是**预告**——账号真正加钱发生在
玩家翻开那一张时,见 [`0x0047.md`](../client-to-server/0x0047.md)。也就是说结算帧在玩家翻牌**之前**
就把免费牌位 0 的内容说出去了;版式帧不带物品,这一格带,两者并存是有意的。

**付费花费那一格是四字节的价钱,里面没有「没有价钱」这个取值**,所以两种没价钱的情形各写一个
约定值:一局根本没定下牌写 `0`(这是牌尾存在之前本帧就在写的值);定下了牌但档案不给这一级报价、
或该副本 `[gold card use] 0` 关掉了付费牌,写 `int.MaxValue`——档案成本表里没有任何一个价等于它,
所以它不会被误当成读出来的数。**客户端见到它会怎么显示未查明。**

**其余各段仍然写零,零仍然是诚实值。** 装扮、宠物、冒险团、黑钻、成长契约这些加成各自需要一个
本仓还没有的来源,凭空写数字仍会在结算画面上留下服务端自己交代不了的钱和经验。与击杀确认帧
同样的立场。
