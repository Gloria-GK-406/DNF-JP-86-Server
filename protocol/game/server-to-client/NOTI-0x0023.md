## 地址口径：本页所有地址都是 RVA，不是 VA

`protocol/` 下记的客户端地址一律是 **RVA**。本帧的 handler `0x00D5CF80` 在 VA 空间里是
`0x0115CF80`；内存 dump 按 RVA 索引，所以「本页地址 = dump 文件偏移」。换算 **VA = RVA + 0x400000**，
`ClientHack/tools/*.csv` 里的 `func_va` 是 VA，两套不能混。

复核方式：`0x00D5CF80` 处是 `55 8B EC`（`push ebp; mov ebp,esp`）的函数首字节；同一数值按 VA 读
（`0x0115CF80`）得到 `45 E8 C7 45 FC FF`，落在指令中间。

### 一个 slot 长什么样

```text
u8  c                      条目数
c × { i32 itemId, i32 amount }
```

每一条 → `AddCard(itemId, amount, slot, kind)`，存进 `panel + 0x1E8 + 100*slot + 20*kind`，
元素 68 字节的 **vector**（`begin=+4, end=+8`），所以一个格子装得下多条。
`c == 0` 时组 0 与组 1 改调 `0x21EF2F0` 把 `[panel+0x6D8+4*slot]` 置 -1（组 2 不调）。

### 组、slot、条目各是什么

| 维度 | 是什么 | 证据 |
|---|---|---|
| **组 k = kind k = 第 k 行** | 组 0 普通牌行 / 组 1 黄金牌行 / 组 2 黑砖牌行 | 实机：三组各放一件不同装备（十字架 / 拖鞋 / 护肩），三行按序显示出对应的那一件 |
| **slot k = 第 k 列** | 一行里的第 k 张牌 | `[panel+0x1E0] = 4` 由 `0x21EF2D0` 写死；请求校验 `牌位 > 3` 丢弃；上游状态数组是 `byte[4]` |
| **条目 0** | 这张牌的**金币**，`itemId` 那一格**被忽略** | 实机：第 0 条写 `(20001, 121)` → 界面显示 **+121 金币** |
| **条目 1** | 这张牌的**装备**，按 `(itemId, 数量)` 画 | 实机：第 1 条写 `(14401, 1)` → 牌上显示「磨损的牛皮护肩」 |
| **条目 2 起** | 客户端照读不误，**不上屏** | 实机：`c=3` 写两件装备，只显示第 1 条那件 |

`itemId = 0` 是「金币」这件物品——把 `(0, 1)` 写在条目 1 的位置，装备区会画成「金币 x1」。

kind 一共有 **5** 个（复位函数 `0x21F7D90` 外层 8 次、内层 5 次、步长 `0x14`）。帧只能填 kind 0/1/2；
kind 3/4 由翻牌应答填，见 [`0x0047.md`](../client-to-server/0x0047.md)。

**「面板画几列」帧里没有这一格。** `0xD5D9EF` 调 `0x21EF2D0`，而 `0x21EF2D0` 的全部内容就是
`mov dword [ecx+0x1E0], 4; ret`。

## 参照服务端怎么写

`DungeonNotificationBuilder.BuildClearDungeonReward` 的卡尾：

```csharp
w.WriteByte(0);                                  // M
byte freeCnt = (byte)(freeCardItemId > 0 ? 2 : 1);
w.WriteByte(freeCnt);                            // 组 0 slot 0 的条目数
w.WriteInt32(0);                                 //   条目 0 的 itemId（被忽略）
w.WriteInt32(freeCardGold);                      //   条目 0 的金币
if (freeCardItemId > 0) {
    w.WriteInt32(freeCardItemId);                //   条目 1
    w.WriteInt32(freeCardItemCount);
}
for (var i = 0; i < 7; i++) {                    // slot 1..7
    w.WriteByte(1); w.WriteInt32(0); w.WriteInt32(0);
}
w.WriteInt32(paidCardCost);
for (int i = 0; i < 8; i++) w.WriteByte(0);      // 组 1 全空
for (int i = 0; i < 8; i++) w.WriteByte(0);      // 组 2 全空
```

**它只做免费行**，黄金行与黑砖行全空——不是另一种写法，是那两行本来就没东西。

## 实机证据（2026-09-02）

十四轮实机，每轮都有服务端逐字节日志与屏幕观察，结论逐条是这么钉下来的：

| 发了什么 | 看到什么 | 钉住哪一条 |
|---|---|---|
| 组 0 slot 0 = `c=2`，`(0,1)` + `(14401,1)` | 牌上出现「磨损的牛皮护肩」+1 金币 | 牌面内容来自**组 0**；条目 0 是金币、条目 1 是装备 |
| 同上但 `c=3`，多一件 `(18403,1)` | 只显示第 1 条那件 | 条目 2 起不上屏 |
| `c=2` 但顺序对调：`(20001,121)` 在前、`(0,1)` 在后 | 显示 **+121 金币**，装备区画成「金币 x1」 | 金币由**位置**决定，不看 itemId |
| 三组各一件不同装备 | 三行分别显示，顺序 = 普通 / 黄金 / 黑砖 | **组 = 行** |
| 组 0 的 slot 0‑3 各一件不同装备 | 不论点哪一张，都出 slot 0 那件 | 亮哪个 slot 由应答决定，不由玩家点哪张决定 |

其余与面板行为有关的实机观察记在 [`0x0047.md`](../client-to-server/0x0047.md)。

- **黄金牌显示「金币余额不足」时**，是客户端拿本帧的付费花费与它自己的金币显示比较：
  `0x21F0627` 取玩家持有金币（虚表槽 `+0x48`），`cmp eax, [esi+0x660]`。
- **物品确实进背包**（走 `NOTI 0x000E`）。
- **黄金牌与黑砖牌不显示金币。**只有普通行画条目 0 的那个数。

5. **`panel+0x6D8[]`（`c == 0` 时被置 -1 的那张表）的消费者。**
