# NOTI `0x0344` `BUY_RESTRICT_ITEM_LIST`

<!-- rks:origin:a21 -->
> **本篇是 A21 原生记录**：判据全部来自 A21 客户端与其参照会话，没有任何 A12 结论，因此不带 A12 退场块。

> **本篇没有机器区。** `patterns/data/generate-docs.py` 的普查跑在 **A12** 客户端上，
> 而 `0x0344` 是 A21 才有的号——A12 的全量索引里没有它，所以生成器不会产出本文件。
> 全文均为人工记录；A21 客户端尚未做静态普查。

## 身份

| 项 | 值 | 来源 |
|---|---|---|
| Endpoint | Game | 帧协议基线 |
| Direction | Server → Client | 参照会话方向 |
| Command 族 | `0x00`（NOTI） | 同上 |
| Type | `0x0344` | A21 `PacketTypesA21` 按名字查得 |
| 名称 | `BUY_RESTRICT_ITEM_LIST` | A21 NotiPacketType |

**A12 把同一个协议放在 `0x02DA`。** 名字与号是两件事：本仓的类型名沿用旧名，号按 A21 走。

## Body

参照会话在入场序列里于本号发一帧，body **4 字节**
（[trace](../../patterns/data/traces/a21-world-entry-20260823.log) section L 第 53 帧，
位置在闸点 `0x007C` 之前一帧）。

本仓在同一位置产出的 body 也是 4 字节，与参照长度一致。**字段边界与含义均无证据**——
只知道长度和它在序列中的位置。

## 证据

双向印证，两条独立证据一致：

1. A21 的 `PacketTypesA21` 表按名字 `BUY_RESTRICT_ITEM_LIST` 查得 `0x0344`；
2. 参照会话确实在 `0x0344` 上发这一帧，而在 A12 的号 `0x02DA` 上**什么都不发**。

证据级别 `High`：缺一条客户端解包路径的指令级证据。
