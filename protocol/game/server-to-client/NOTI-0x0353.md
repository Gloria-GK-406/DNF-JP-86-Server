## ClientVerified：提示逻辑异常与临时处置（2026-09-23）

本协议存在提示语义问题：两字段控制购买确认提示，不能当作双倍每日额度协议。用户实测与静态分支一致，但固定文案声称的8次/30次规则与客户端全口径开罐计数不一致。

- 登录下发0/30后，购买按钮直接进入商城，不弹70985确认框。
- 登录下发29/30，普通模式成功开一罐后，再点购买出现70985确认框（用户实机确认）。普通开罐也递增第一字段。
- 窗口0x2B2的两个购买按钮比较current >= threshold；成立先打开0x2B3，确认后进商城，否则直接进入相同商城页。该比较不执行开罐准入或购买结算。
- 剩余双倍次数仍取036F slot1；0353不能证明续购后清零及每天30次的正式规则。70985中的8和30是固定文字，不能证明第二字段的官方取值。
- 未发包时初始0/0；成功开罐后第一字段会增长，并非始终0/0。

用户决定：当前部署登录时发送固定body `00 00`，保留原有购买确认提示。不开启开罐后重发，不修改每日8次计数或续购规则。此为兼容处置，不是修复客户端文案，也不表示零额度；客户端仍会本地递增第一字段。

后续“续购清零、每天累计最多30次”须由服务端独立制定与校验，不能依赖该UI分支。问题跟踪：[GitHub #122](https://github.com/Gloria-GK-406/DNF-JP-86-Server/issues/122)。
