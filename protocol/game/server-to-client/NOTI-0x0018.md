## 它是区域内角色的名册

客户端自己的读法就是名册：先 `u8 town`、`u8 area`、`u16 count`，然后按 count 回跳的循环，
每轮读 8 字节。见下方 Body 一节的 RVA。

## 换区时不能省，但"为什么不能省"还没定

2026-08-17 实现 [`0x0024 SET_USER_AREA`](../client-to-server/0x0024.md) 时只推了
`0x0017`，理由是"名册要第二个角色才有意义"。实机结果：客户端把同一帧 `0x0024`
**重发八次**，角色停在原地（服务端日志八次 `Set user area 1:0 -> 1:1`，每次一条 `0x0017`）。
补上本条之后，四次跨区各一帧、零重试。

**所以"跳过它"被否证了，但"自己必须在名册里"没有被证明。** 那一次补上的是
`count = 1` 且唯一一条就是自己，两件事同时变了：

| 读法 | 与现有证据相容？ | 怎么分辨 |
|---|---|---|
| 本帧**到达**即换区的完成信号，内容是名册 | 是 | 发 `count = 0` 仍能换区 |
| 名册里**必须有自己**，本帧是落点确认 | 是 | 发 `count = 0` 会卡住 |

`count = 0` 从未试过。客户端的循环是 `jl`（index < count），所以 `count = 0` 时
**一条 per-entry 字节都不读**，不会越界——这个实验在协议层是安全的。

**另有一条反例说明它不是"占用区域的必要条件"**：进城那一批里根本没有 `0x0018`
（见[进入世界](../../patterns/world-entry.md)的阶段一序列），角色照样落在城里。
handler 开头也确实按客户端状态分支（`0x0093A4D7  cmp eax, 5` / `je` 直接退出，
`0x0093A536  cmp eax, 3` / `jne` 走另一条），所以本帧的效果是**依状态而定**的，
不能从"换区需要它"推出"任何时候都需要它"。

参照实现的名册是 `{ 自己 } + 其他人`——它把自己算进去了。这一句足以否掉
"单人下可以不发"，但不足以说明自己**必须**在里面。

|---:|---:|---|---|

| +7 | 1 | `u8` | 区域状态 |

单人因此是 12 字节。

**边界由客户端的读取指令确证**，不再只是参照实现的转录。由客户端
`F78F0AEA…` 的 `0x0093A4A0`–`0x0093ADB0` 反汇编：

```text
0x0093A50E  call 0x1D00420   ; ReadU8  -> [ebp-0x35]   town
0x0093A519  call 0x1D00420   ; ReadU8  -> [ebp-0x36]   area
0x0093A522  call 0x1D00490   ; ReadU16 -> [ebp-0x5C]   count
...
0x0093AA43  call 0x1D00490   ; ReadU16 ┐
0x0093AA4C  call 0x1D00490   ; ReadU16 │ 每条 8 字节
0x0093AA55  call 0x1D00490   ; ReadU16 │
0x0093AA60  call 0x1D00420   ; ReadU8  │
0x0093AA6F  call 0x1D00420   ; ReadU8  ┘
0x0093ADA3  jl   0x0093AA30                            按 count 回跳
```

`count` 因此确实是真实前缀，循环体是 8 字节。

**每条里那 8 字节各自是什么，仍然只有参照实现作依据**——读取指令给的是宽度和顺序，
不是含义。`u16` 是 wire user id、两个 `i16` 是坐标这一层，靠的是我们发出去的值
被客户端接受且角色出现在预期位置，属于间接证据。
