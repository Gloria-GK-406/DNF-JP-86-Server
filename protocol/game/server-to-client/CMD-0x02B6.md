# CMD `0x02B6` 镜像阿拉德入场拒绝

## 证据

ClientStatic / High：A21 原始内存 dump `DNFClient-A21-debug/dumps-keep/dnf-dump-20260822-184128-028-16280/DNF-memory-rva.bin`，客户端 handler RVA `0x00D0A1A0`、错误分派 `0x00D09FD0`。支持客户端 SHA-256：`1F8244D3F7309BBE2FDE4299E1863A894F6B28D5707BF01732980585B20B00DD`。RVA 直接作为 memory-rva 文件偏移，不能减 ImageBase。

## 当前发送

拒绝 body：`u8 success=0 + u8 error + u8 context`，selector=01/type=02B6。context 当前使用阻塞队员槽，没有阻塞队员时为0；当前选用的通用/不可入场分支不读取它。

| error | 客户端语义 / 本次策略 |
|---|---|
| 01 | 默认通用入场失败；配置、疲劳、材料、日限等拒绝使用此分支 |
| 12 | 自动重新选取并重试；本次不使用，避免无效请求自动循环 |
| 13 | 不可入场提示（stringID B664）；已在副本、前置条件不足使用此分支 |
| 16 | 另读队员索引、显示队员格式消息（697F）；不是普通0010的疲劳码，本次不使用 |

这是兼容性的错误分支映射，不宣称每种业务错误均有精确原生专用文案。不能直接复用0010错误码表。

成功时当前服务端不发送此 CMD，直接以 [0278](NOTI-0x0278.md) 和共用地图加载继续。客户端成功 ACK 的非-1 DGN 路径会再发送000F/0010，不适用于服务端已创建的镜像实例。

CurrentImplementation：编码和拒绝后重试已测试；实际客户端提示、等待状态解除与入场仍待部署后验证。
