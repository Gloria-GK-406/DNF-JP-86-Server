# NOTI `0x0465` `EPIC_BOOK_INFO`

> **本篇没有机器区。** `patterns/data/generate-docs.py` 的普查跑在 **A12** 客户端上，
> 而 A12 的全量索引里没有覆盖到本号，所以生成器不会产出本文件。
> 全文均为人工记录；A21 客户端尚未做静态普查。

## 身份

| 项 | 值 | 来源 |
|---|---|---|
| Endpoint | Game | 帧协议基线 |
| Direction | Server → Client | 参照会话方向 |
| Command 族 | `0x00`（NOTI） | 同上 |
| Type | `0x0465` | A21 `PacketTypesA21` |
| 名称 | `EPIC_BOOK_INFO` | A21 NotiPacketType |

A21 与 A12 两张表在本号上同名同值——它不在两处插入点之上，编号没有位移。

## Body

参照会话在入场序列里发一帧，body **5 字节，全为 `0x00`**
（[trace](../../patterns/data/traces/a21-world-entry-20260823.log) section L 第 22 帧，
紧接在物品表之后、`0x021E` 之前）。

服务端按同一常量下发。**字段边界与含义均无证据**：五个零字节可以是五个 u8、也可以是
`u8 + u32`，参照的最小形态区分不了。

## 证据

只有一份 A21 参照会话的转抄：长度 5、内容全零、在序列中的位置。

证据级别 `Hypothesis`——按 [README](../../README.md) 的规矩，只有转录支撑的结论到此为止。
本仓按 offset 与原始宽度建模（一个 5 字节常量），**没有**给字段起领域名。
