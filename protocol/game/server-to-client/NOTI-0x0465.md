# NOTI `0x0465` `EPIC_BOOK_INFO`

<!-- rks:origin:a21 -->
> A21 原生记录。空包有参照会话转抄；非空布局来自上游 ServerS4A21 实现，尚未获得本客户端非空实帧或消费者静态确认。

## 身份与布局

Game / Server → Client / cmd `0x00` / type `0x0465`，上游名称 `EPIC_BOOK_INFO`。

| offset | 宽度 | 含义 | 证据 |
|---|---|---|---|
| 0 | u8 | mode：0 全量、1 变更项 | UpstreamReference / High |
| 1 | u32 LE | 条目数 | UpstreamReference / High |
| 5 + 8i | u32 LE | 碎片物品 ID，不是装备 ID 或目录索引 | UpstreamReference / High |
| 9 + 8i | u32 LE | 累计数量，不是新增数量 | UpstreamReference / High |

body 长度 `5 + 8 * count`。本仓数量限制为 `0..int.MaxValue`，存储只留正数条目；无碎片的全量包仍是五个零。

## 来源与置信度

- A21 [入场参照转抄](../../patterns/data/traces/a21-world-entry-20260823.log) section L 第 22 帧：五个零，位于物品表之后、0x021E 之前。仅空包的字段边界无法独立判定，证据等级仍为 Hypothesis。
- 上游 `ServerS4A21`，检查基线 `c20dba5`：`Server/DfoServer/Network/Builders/Init/GenericBuilders.cs` 的 `A21UsableCount0465BodyBuilder` 明确写 mode、u32 count、pieceId/count 对。`InventoryHandler.EpicBook.cs`、`DungeonCombatHandler.cs` 和登录路径分别使用增量或全量形式。这是上游实现证据，不等同于 ClientVerified。
- PVF `etc/epicpieceinfo.etc` 的 `[piece list]` 声明装备 ID/碎片 ID 配对；配方数量是合成需求，不作为本仓持有上限。
- 当前实现：拾取 CMD 0x002B 在背包之前分流，持久化账号数量；成功后按 CMD ACK → NOTI 0x0027（目的槽 0）→ 本通知（mode 1）发送。满额仍 ACK/移除掉落，省略未变化的余额通知。其他队员只收到地面移除通知。
