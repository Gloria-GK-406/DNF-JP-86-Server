# CMD 0x0040 BUY_CERASHOP_ITEM

Game，Server → Client，cmd=1/type=0x0040。阶段：实现服务端功能，待实机。

以下布局为 **Confirmed（A21客户端读取指令）**；字段业务名中category/commodity来自查商品路径，其余aux保持未知。取证RVA和固定二进制身份见 [读取路径](../../patterns/data/traces/a21-cera-shop-wire-20260909.md)。

成功body为 `24 + 8*N` 字节：

| Offset | 类型 | 内容 |
|---:|---|---|
| 0 | u8 | success=1 |
| 1 | u8 | flag，本实现0 |
| 2 | i32 | category，本实现-1（跨全部27类搜索） |
| 6 | i32 | commodityId，实际商品号 |
| 10 | i32 | auxA，本实现0 |
| 14 | i32 | auxB，本实现0 |
| 18 | i32 | displayItemOverride，本实现0（按商品表显示）；非零分支不是数量 |
| 22 | u16 | N，本实现0 |
| 24 | N×(u32,u32) | 客户端展示状态附加项，本实现不发送 |

失败码1/4/11的body为 **23字节**：`u8 success=0 + u8 error + u8 flag=0 + i32 category=-1 + i32 commodity=-1 + i32 auxA=0 + i32 auxB=0 + i32 auxC=0`。不同于参照服22字节构造，不能省掉flag。1=请求购买信息错误，4=物品栏空间不足，11=点券不足。其他失败码有额外分支，本实现不外推通用布局。

成功后同步余额NOTI0035、必要金币NOTI000E、各容器物品NOTI000E和新增宠物时的NOTI0069；顺序及当前范围见 [购买流程证据](../../patterns/data/traces/a21-cera-shop-wire-20260909.md)。仅在事务提交后发送。单元向量证明编码长度/字段；真实客户端UI、多商品提示及后续请求仍待验证。
