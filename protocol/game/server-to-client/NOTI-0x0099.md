## A21 服务端实现

**状态：ClientVerified（A21 名册后初始 HP 与在队定向查询；真实 S2C body 待归档）。**
[`PartyRealtimeEncoder`](../../../Server/src/Dfo.Server.Protocol/Game/Party/PartyNotificationSlice.cs) 按
`1 + n×5` 编码，成员按队内槽位顺序来自不可变 snapshot：

| 记录内 Offset | Size | Enc | 值/含义 |
|---:|---:|---|---|
| 0 | 2 | `u16 LE` | wire user id |
| 2 | 1 | `u8` | HP 百分比；来自该精确 selected-session 已组装的当前角色投影，钳制到 `0..100`；会话缺失时为 `0` |
| 3 | 1 | `u8` | help-abuse 标志，当前固定 `0` |
| 4 | 1 | `u8` | 队内槽位，当前有效范围 `0..3` |

它是所有非空队伍 refresh 的第一阶段；Round 5 实机显示，首次摘要早于客户端 slot 建立而不会
填充初始头像 HP，因此建队/新增成员顺序现为
`0x0099 → 0x0008（仅邀请者）→ 0x000B → 0x0009 → 0x0099`。最后一帧复用同一不可变 snapshot
并投递给全体成员，只为让完整名册后的 slot 消费当前 HP，不等待客户端主动查询。成员离开后的幸存者刷新仍为
`0x0099 → 0x000B → 0x0009`。单独端点更新不触发此通知。C2S `0x00A6` 会查询当前 snapshot，
并只向请求连接定向补发一条 `0x0099`。通知仅投递给 snapshot 中仍是当前精确会话的成员。

队长客户端的空 body `0x00A6` 也得到当前单人摘要。见
