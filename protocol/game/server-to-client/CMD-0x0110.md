# CMD `0x0110` — 装备宝珠附魔结果

## 证据等级

- **ClientStatic**：A21 unpacked-b1 的响应 handler RVA `0x00D1B110`（PE VA `0x0111B110`）；成功分支 VA `0x0111B12E–0x0111B14B` 依次读取 `u8 targetList, i16 targetSlot`，再对列表 `3`（穿戴装备）、`7`（宠物）及其他类型分别刷新对应 UI。通用 CMD 成功/错误首字节由分发层处理。
- **ClientStatic**：错误分支 VA `0x0111B1C8–0x0111B244` 对 reason `0x11`、`0x13`、`0x17` 有特殊路径；前置通用错误处理函数仍可能截获，不能据此宣称对应提示文案。
- **UpstreamReference**：`EnchantByBeadAckBuilder.BuildSuccess` 写 `01,u8 targetList,i16 targetSlot`；错误写 `00,u8 reason`。上游 handler 在 ACK 前刷新宝珠/目标槽。
- **UpstreamReference + ClientStatic**：上游 `Game/ExpertJob/EnchantByBeadResult.cs` 将材料无效、目标无效、内容不支持分别编码为 `0x11/0x13/0x17`；A21 客户端错误分支对这三个字节均有特殊路径。当前实现按该参考映射发错误，但没有实帧和用户提示验证，不能据此断言具体文案或同版本错误语义。
- **70Reference**：`Dispatcher_EnchantByBead::send` `0x081d25b0` 使用不同的 `0x0113` 成功/错误回包，不可用于 A21 `0x0110` 的线缆布局。

当前无 `0x0110` 实帧。字段宽度和先后是客户端静态读取证据；字段业务名与通知顺序是客户端静态和上游结合的推断，等待用户测试。服务端成功结算提交后才投递两个权威槽状态与 ACK；此项通知无后台重试，同会话近期同序列重送时再次按当前槽状态刷新而不再次扣珠。连接计数的新鲜度在网络入口基于全部入站 Game 帧判断，异常或超窗旧包拒绝。宠物目标的 `7` 分支不得当成装备目标处理。
