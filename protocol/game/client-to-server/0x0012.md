两份新样本分别是：

```text

000101000900B06A0000010000000000000000  # 主背包槽9，装备27312 ×1
```

`reservedZero` 是构包器直接写入的常量零，**Confirmed**。最后一字节来自安全模式状态的
`curSafeModeSkipIndex`，发送后立即复位为 `SAFE_MODE_SKIP_NONE`；技能检查可把它设为
`SAFE_MODE_SKIP_MOOCU_SKILL`，因此它表达的是**安全检查例外上下文**而不是删除规则，**High**。
服务端 typed message 保留并命名这两个字段，但当前普通丢弃领域决策不读取它们。

另一个 `0x00B70700` 构包路径发送 18 字节、`operationType = 0`，没有末尾安全上下文字节。
它的业务语义尚未闭合，本实现不会把它误读成普通丢弃，也不把收集箱等调用方并入本切片。

### 回包与实现

客户端 `0x00D303E0` handler 的读取闭合了两种回包：

```text
成功：01 | u8 container | u8 entryCount (=1) | i16 slotIndex | i32 appliedCount | i16 0
失败：00 | u8 errorCode (=0x17) | u8 container
```

服务端已实现 19 字节普通单条请求：Package Handler 只派发事务 CMD；CMD 调用丢弃领域服务，
领域服务通过规则服务校验主背包、`operationType=1`、槽位、物品一致性、数量与装备锁，随后以服务端
在线库存为真值扣减或清槽；提交后通过 Event 组合一次成功 ACK。失败不改库存并返回 `0x17`。
codec、真实 SQLite 持久化、装备全删、堆叠物部分删除以及拒绝路径均有自动化测试。
