## 2026-11-14 决斗场一期实现（TASK-06，CurrentImplementation，待实机）

`u8 seat, u8 state`，恰好 2 字节（静态 Confirmed）。state 的含义按上游 `HandleSetSeatStateWithinTransition`（Hypothesis）：

| state | 作用 |
|---|---|
| 0 / 1 / 2 | 本人换到个人 / 第一队 / 第二队（只能改自己的座位）；线上值经 codec 映射到领域队伍，不直接读领域枚举 |
| `0xFE` | 自己的座位 = 退房；他人占用的座位 = 房主踢人；空座位 = 房主关闭 |
| `0xFF` | 房主打开已关闭的座位 |
| 3 / 4 | 观战，一期拒绝（`00 08`），不进领域 |

座位越界、其他 state 或长度不对应答 `00 08`。机器区显示客户端没有为本 type 注册 CMD 回包 handler；拒绝仍照上游回
`00 reason`（信封先被统一读掉），客户端是否显示待实机。

投影：换队、关/开座位 → 同端口大厅就绪者收 NOTI `0x002B`（该座位）。退房/被踢 → 除离开者外的大厅就绪者依次收
USER_STATE（离开者，0）、NOTI `0x002B`（空出的座位）、房主换人时 NOTI `0x002A`；最后一人离开时 `0x002B` 之后是 `0x002A` 销毁体。
离开者本人先走回城投影：USER_AREA → AREA_USERS（同屏有人时其角色帧在名册前），不发自己的 USER_STATE（复用城镇回归投影的
无自身状态选项；上游 `PublishTownReturnAsync`），之后才收到同样的 `0x002B`/`0x002A`。顺序依据上游 `PvpRoomHandler` 主动退房、
`CompleteKickedMemberExitAsync`、`CompleteOwnerExitAsync`、`PublishReturnedPvpStateAsync`（state 0 只发给排除本人的大厅；Hypothesis）。
房间销毁时若多人同时被送回，被送回者彼此收不到对方的 state 0（上游逐个回城时会收到），待实机。
