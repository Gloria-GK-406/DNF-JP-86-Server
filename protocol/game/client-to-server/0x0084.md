# `0x0084` `BACK_2_VILLAGE`

<!-- rks:origin:a21 -->

## 身份

| 项 | 值 | 来源 |
|---|---|---|
| Endpoint | Game | 帧协议基线 |
| Direction | Client → Server，请求与响应同属 CMD | A21 实帧与参照路由 |
| Command 族 | `0x01`（CMD） | A21 实帧；客户端只发送 CMD |
| Type | `0x0084` | A21 实帧 |
| 名称 | `BACK_2_VILLAGE` | 上游 `CmdPacketType` / 路由名；不是本资料库自造名 |
| Role | Mutation / 关闭选图界面并恢复城镇投影 | 参照响应序列与当前实现 |
| 阶段 | 实现服务端功能；尚未以当前服务端完成真实客户端复验 | 当前 decoder/handler/encoder 与回归测试 |

这条身份是静态普查的已知盲区：`protocol-identity.tsv` 没有 C→S `CMD 0x0084`，只有无关的
S→C `NOTI 0x0084 END_ASSAULT`。A21 客户端却连续发送了三帧本请求，说明构包器位于普查扫不到的
混淆代码区；缺少静态条目不能推翻同版本真实线级观察。

## Wire layout

Game 帧头见 [game-frame](../../patterns/game-frame.md)。请求 body 为空：

```text
RequestBodyLength = 0

SuccessResponseBodyLength = 1
u8 accepted = 0x01
```

| 方向 | Offset | Size | Encoding | Meaning | Confidence | Evidence |
|---|---:|---:|---|---|---|---|
| C→S | — | 0 | empty | 关闭选图界面的请求 | Confirmed（线级） | `E-001` 三帧均为 0B |
| S→C CMD | 0 | 1 | `u8` | 成功信封 `0x01` | High（参照 + 当前编码器）；尚缺当前服务端实机复验 | `E-001`、`E-003` |

本页的“空请求”由真实 A21 帧闭合，但尚未取得构包指令，所以不能给出 builder RVA；响应字节目前由
参照路由和当前实现共同支持，不能越级写成 `ClientVerified`。

## Verification

- Request vector：A21 三帧 `CMD 0x0084 (0B)`。
- Response vector：参照 `S→C CMD 0x0084 01`；当前 encoder 测试覆盖相同字节。
- Response order：当前测试覆盖 ACK 后的 `USER_STATE` / `USER_AREA` / `AREA_USERS` 投影路径。
- Real-client result：只记录到“旧服务端未回答时按钮无反应”；当前实现后的成功按钮行为尚未归档。

## Unknowns and next evidence

| 未解问题 | 影响 | 最便宜的证据 |
|---|---|---|
| A21 构包器 RVA | 缺少请求侧指令级定位 | 对 `Cipher::Encrypt` 的 `0x0084` 帧记录调用栈并与 `MakeHeader` 交叉定位 |
| 当前服务端四帧是否被真实客户端完整接受 | 决定能否升为“双向验证结束” | 真客户端打开选图界面后点回城，归档收发帧并记录 UI/位置结果 |
| 失败/无会话时客户端期望 | 决定是否需要拒绝信封 | 构造失效状态或读取响应 handler 的失败分支 |

## 逆向工作日志

最初因为全量静态索引没有 C→S `0x0084`，观察只写在流程 trace 与不谐清单中，没有独立协议页。
这条缺口证明“静态普查全覆盖”只覆盖其可见集合：真实帧可以为混淆区构包器建立手写例外，不能让
生成器的沉默覆盖真实客户端行为。
