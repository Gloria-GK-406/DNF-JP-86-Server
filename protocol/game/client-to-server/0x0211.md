## A21：Boss 房入场条件的召唤请求（#357）

**用途。** 地下城 `[boss room entrance condition]` 的目标都狩猎完后，服务端发 NOTI 0x0138；
队长的客户端收到后，按**当前地图**的 `[conditional summon monster]` 行发这条请求，召唤
`[clear action] [summon monster]` 指定的怪（2010 陷落的村庄是 69264 血蝎迪奥女王）。

### 请求：19 字节（ClientStatic，构包 `0x00E46954..0x00E469F3`，High）

| Offset | Size | 字段 |
|---:|---:|---|
| 0 | 2 | kind：0 怪物，1 APC |
| 2 | 4 | 怪物代码 |
| 6 | 4 | 请求号：客户端全局计数 `[0x039B1070]` 自增，≥1 |
| 10 | 4 | 地图号 |
| 14 | 2 | 房间格 x |
| 16 | 2 | 房间格 y |
| 18 | 1 | 相同请求合并后的条数 |

与机器区按上游命名的字段一一对应（conditionalType → kind、stateId → 请求号、
conditionalParam0/1 → 房间格）。发送前要过 `0x00E44690/0x00E44800` 两道门，
不通过就延后（Hypothesis：去重）。

### 回包：同 type 0x0211 CMD（ClientStatic，handler `0x01109050`，High）

```text
成功：u8 1, u32 请求号回显, u8 n, n × (u16 怪物序号, u32 怪物代码, u8 等级档, u16 等级)
拒绝：u8 0, u8 reason, u32 请求号
```

- **A21 没有额外尾部**。上游 15 字节的回包正好是 n=1 的情况。
- 客户端按请求号配对（`0x00E461E0`），要求代码与请求一致（`0x00E43130`），然后在自己那份地图的
  召唤坐标处、以回包里的序号生成怪物（`0x00E432B0`）。等级档 0 普通、1 精英、2 超级精英、3 Boss。
- 之后它以这个序号上报 0x0027，所以序号不能与本房已有怪物重复。

### 本仓实现

见 `Game/EntranceSummon` 切片与 `DungeonEntranceDomainService`。领域服务先校验：请求者是队长、目标已全部狩猎、
代码与地图都符合本局、本局尚未召唤过，然后取本房未用的序号，经 `StageDynamicCell` 把怪加进当前房。
拒绝时用 reason 1 回请求号。召唤体的击杀会计入迷宫的 `[hunt boss]` 通关条件。
