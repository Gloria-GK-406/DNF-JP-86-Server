## 2026-11-14 决斗场一期实现（TASK-07，CurrentImplementation，待实机）

只接受 5 字节（Spec RQ-075）：`u16 死者 user id, u16 击杀者 user id, u8 flag`（上游 `DiePvpCharacterRequest` 的 5 字节形；
上游另收的 2 字节兼容形本仓拒收）。其他长度记日志、不进领域。死者 user id 必须是发送者本人，否则记日志拒收。击杀者按本局冻结名单里
持有该 user id 的战斗者换成角色；0 或名单外的 user id 视为无击杀者，是否计击杀（本局、存活、敌方）由领域判定。flag 只记日志
（上游注释：角色属性比较，不是击杀许可）。

静态走图读出 ≥ 7 字节（机器区，经虚表间接调用，不完整），与上游 5 字节、70 服务端 `u16 killer` 三方不一致，待抓包定案。

成功（`Died`）时房内成员收 NOTI `0x002E(死者座位, 击杀者座位/0xFF)`；该死亡终局时随后收 NOTI `0x0031`。被领域忽略的上报
（非本人、已死、阶段不符）不发帧。无 CMD 应答。

实机前不标 ClientVerified；无 `.hex` 样本，布局来自上游转录与静态走图，字节由编码/解码测试固定。
