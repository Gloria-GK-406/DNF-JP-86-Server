## A21

**2026-08-26 实机。** 结算画面看完之后客户端发这一帧,body 为空。参照会话同样发一次,回 1 字节
`01`。归档见 [a21-room-rules-and-leaving-20260826](../../patterns/data/traces/a21-room-rules-and-leaving-20260826.md)。

```text
C->S CMD 0x002A   (0B)
S->C CMD 0x002A   01
```

**这是本仓里唯一让一局副本结束的东西。** 在 2026-08-26 之前 `IDungeonRunDomainService.End`
**从来没有被任何地方调用过** —— 玩家已经回到城里,服务端却还认为他站在副本中。这也是同一次会话
能从 Boss 房走回上一间房的另一半原因。

**回城本身不靠这一帧。** 那次实机里它没被应答,客户端照样回到了城镇:它自己发
`SET_USER_AREA`、`SET_USER_POSITION`,拿到了 `NOTI 0x0017`/`0x0018`/`0x0016`。参照服务端会在这
一帧之后主动推 `NOTI 0x0003 USER_STATE`、`0x0017`、`0x0018`;本仓不推,记在
`Docs/ProtocolScaffoldDissonances.md`。

## 2026-09-14：服务端回城投影修复（待 A21 复验）

本仓现在把 `GIVEUP_GAME` 作为完整退出处理：先结束当前运行，再发送 CMD `0x002A 01`，随后
复用 EPLP/取消选图的公共城镇投影（`USER_STATE`、`USER_AREA`、`AREA_USERS`）。这修复了已观察到的
状态分裂：旧实现先删除运行，只回确认；客户端仍留在副本并继续发 `MOVE_MAP`，服务端则因
`no run in progress` 拒绝过图。

实现与自动化回归已完成；客户端能否在手动退出后稳定回城并再次进入，仍需 A21 实机确认后才能
