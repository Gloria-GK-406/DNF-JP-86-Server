# `0x0006` `DELETE_CHARACTER`

> 名称取自旧服 `CmdPacketType` 枚举。共享证据与名字字段编码见
> [角色生命周期协议族](../../patterns/character-lifecycle.md)。

## Identity and behavior

| Property | Value |
|---|---|
| Endpoint | Game |
| Direction | Client → Server（响应同 type 反向） |
| Command | `0x01` |
| Type | `0x0006` |
| Role | Mutation / 有响应 |
| Trigger | 角色列表屏删除角色并输入名字确认 |
| Expected response | CMD `0x01` / `0x0006`，**成功时其后再补一帧 NOTI `0x00` / `0x0002` 角色列表** |
| 阶段 | 实现服务端功能 |

**尚无实机样本。**

## Wire layout

Game header 见 [Game TCP 帧组织](../../patterns/game-frame.md)。

**请求**：

```text
BodyLength = 1 + 4 + nameLength
```

| Offset | Size | Encoding | Meaning | Confidence | Evidence |
|---:|---:|---|---|---|---|
| 0 | 1 | `u8` | 槽位序号 | Hypothesis | `E-001` |
| 1 | 4 | LE `i32` | 名字字节数 | Hypothesis | `E-001` |
| 5 | `nameLength` | 原始字节 | 确认名，须与该槽位占用者相同 | Hypothesis | `E-001` |

确认名不是冗余：它是唯一能阻止**客户端持有过期名单**时误删当前占用该槽角色的东西。
比较用原始字节，不用解码后的文本。

**响应——本条与同族约定相反：**

| 情况 | body |
|---|---|
| **成功** | `00` + LE `u16` 被删角色 id（共 3 字节） |
| 确认名不符 | `15`（裸码） |
| 请求不合法 / 槽位为空 | `02`（裸码） |

同族其他四条里 `00` 开头代表拒绝，这里却代表成功。这不是转录失误：客户端必须读出后面那个
id，`00` 在此是「后面有 id」的判别位。**但没有实机证据能证实这一点**，详见
[族文档的回复约定](../../patterns/character-lifecycle.md#回复约定以及它自相矛盾的地方)。

成功后补发角色列表，理由与 [0x0005](0x0005.md) 相同。

## Client reversing evidence

| Evidence | Kind | Location | Supports |
|---|---|---|---|
| `E-001` | static | 旧服 `CharacterSelectHandler.Handle_ENUM_CMDPACKET_DELETE_CHARACTER`（`d51e74b`） | 请求布局、响应形状、全部原因码 |

客户端普查表里 **`0x0006` 没有静态注册的接收 handler**。普查表只含静态注册、缺 439 条运行时
注册，所以这既不能证明客户端不处理响应，也不能证明它处理。本条是本族里客户端侧佐证最弱的一条。

## Server and historical evidence

旧服为**软删除**（`delete_flag = 1`），不删行；并在删除前检查 `MercenaryRestrictions.CanDelete`，
角色正在佣兵远征时回 `{0x28}`。本实现保留软删除，**不实现远征限制**——没有佣兵子系统，
这条检查没有可判定的输入。相应地 `0x28` 不会被发出。

软删除同时释放名字：`NameExistsAsync` 只看 `delete_flag = 0` 的行。

## Implementation mapping

| Layer | Type/path | Responsibility |
|---|---|---|
| Data | `CharacterDeletionStatus` / `CharacterDeletionResult` | 领域契约 |
| Networking | `GameMessageDecoderRegistry` 键 `0x01/0x0006` | 分发 |
| Protocol | `Game/DeleteCharacter/` | 解码、command、handler、编码器 |
| Application | `CharacterService.DeleteCharacterAsync` | 槽位定位与确认名比对 |
| Infrastructure | `SqliteCharacterRepository.SoftDeleteAsync` | 置 `delete_flag`，重复删除返回 false |

命令为 `Direct` + 账号 `Exclusive`。

## Verification

- Parser/codec vectors：`CharacterLifecyclePayloadCodecTests` 覆盖槽位+名字解析、
  成功体含 id、两种裸码。
- 领域规则：`CharacterLifecycleServiceTests` 覆盖确认名不符不删、空槽位、正常删除。
- 持久化：`SqliteCharacterLifecycleTests` 覆盖软删除后从名单消失、名字被释放、重复删除返回 false。
- Real-client result：**未做**。
