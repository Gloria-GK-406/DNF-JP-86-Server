# `0x00E0` `WRITE_GUILD_MEMBER_MEMO`

| 项 | 值 |
| --- | --- |
| Endpoint | Game |
| Direction | Client → Server，使用同 type 的 CMD 回执 |
| Command | `0x01` |
| Type | `0x00E0` |

## 布局

| 偏移 | 字段 | 含义 |
| ---: | --- | --- |
| 0 | `u32le` | 备注的编码字节数 |
| 4 | 文本字节 | 当前角色自己的公会备注，长度为 0 时清空 |

**ClientStatic · Confirmed。** A21 在 VA `0x0248D060` 写入 opcode，经 `0x0248D0A8` 写入一个 DSTR。旧普查将相邻 `0x02EC` 分支写入的职级字节误计入本请求。本页使用手写布局。

**ClientStatic · Confirmed。** 回执处理器在 VA `0x0111B6F0` 对成功跳过提示，对失败分别处理 `0x22`、`0x6C`。取证镜像 SHA-256 为 `6BD2746DA3858E6F29B3E2D386AF4938056269BAD6C9FFF9455E133E7D953507`，对应 A21 原版 SHA-256 `1F8244D3F7309BBE2FDE4299E1863A894F6B28D5707BF01732980585B20B00DD`。

**UpstreamReference / CurrentImplementation。** 参照 ServerS4A21 的 `GuildManagementHandler`、`GuildRepository.EditText` 与 `GuildManagementRules`。仅当前公会成员可以保存自己的备注，规则上限 30 个 UTF-16 代码单元、60 个 JP86 UTF-8 字节。服务端成功回 `01`，非成员回 `00 22`，无效正文回 `00 6C`。成功提交后向在线同会成员刷新[全量名单](0x008C.md)，[普通名单](0x0043.md)也读取同一备注字段。

**WireTest · Confirmed。** 隔离线路 `1795765676560441200` 使用由旧库副本迁移而来的验收库，验证普通成员写入中文备注、不同频道的同会角色收到全量名单、无公会角色和两种无效正文被拒绝、重登读回、清空后双端刷新及持久化。

**ClientVerified / ClientStatic。** 用户确认成员页第二页可以编辑和查看备注，并反馈中文长度计数异常。A21 编辑窗口在 VA `0x0248CDC7` 取当前文本长度并传给计数标签。共用编辑框函数 `0x027F51F0` 经过 `0x027BADD0` 转码后逐字节计数。JP86 客户端兼容补丁把该转换使用的代码页从 GBK 936 改为 UTF-8 65001，常用汉字在计数标签中占 3。编辑窗口的提交校验另在 VA `0x0248CF60–0x0248CF72` 按 UTF-16 代码单元与 20 比较。界面计数、输入上限、提交规则和线格式字节数需要分别核对，当前未修改。
