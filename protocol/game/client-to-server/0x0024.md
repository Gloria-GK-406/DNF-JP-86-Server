## 偏移 9 是**离开的那个区域**

四次跨区，偏移 9 依次为 `00`/`01`/`02`/`01`，与每次**出发**的区域号逐次相符。
这不是目标区域（那在偏移 1），是来源区域。

偏移 7–8 四次都是 `01 00`。这**可能**是来源镇（值 1，与整段会话唯一到过的镇一致），
也可能就是常量——四个样本全在镇 1 之内，两种读法给出相同字节，**分辨不了**。
要分开需要一次跨镇样本，见下方待补全。

偏移 6 是朝向（`05`，与同期 `0x0023` 报的朝向一致），偏移 10–14 四次全零。

## 这是唯一能改变"上次所在城镇"的指令

登录时服务端下发的镇号来自 `characters.town_id`
（见 [`0x0004` 偏移 218](0x0004.md#偏移-218-是入场镇-id不是槽位写-0-必崩)），
而本条是唯一写它的输入。整条链见[进入世界的「城镇的持久化」](../../patterns/world-entry.md#城镇的持久化)。

## 前六字节：目标镇、区域与坐标

机器区的布局由客户端构包器闭合在 **15 字节**，其中前六字节的含义由上游确证
（`TownHandler.SetUserAreaCoreAsync` 读 `body[0]`、`body[1]`、`ToInt16(body,2)`、`ToInt16(body,4)`），
其后九字节上游一个都不读，也没有别的证据。

**坐标是有符号的。** 归档里的到达点存在负值（`SilverCrown` 的 `[gate] 474 234` 为正，
但 `.twn` 的区域坐标并不保证非负），按无符号读会把角色放到地图外。

## 响应形状：`0x0017` + `0x0018`，两条都必须

客户端为本 type 注册了 CMD 接收 handler（`RVA 0x008E37E0`），但成功路径**不回 CMD**，
推两条 NOTI：

| NOTI | 内容 |
|---|---|
| [`0x0017`](../server-to-client/NOTI-0x0017.md) USER_AREA | 角色的新位置 |
| [`0x0018`](../server-to-client/NOTI-0x0018.md) AREA_USERS | 该区域的名册，**含自己** |

**`0x0018` 不是多人功能。** 2026-08-17 第一次实现时只推了 `0x0017`，客户端把同一帧
`0x0024` **重发了八次**（服务端日志八次 `Set user area 1:0 -> 1:1`，每次一条 `0x0017`），
角色停在原地。补上 `0x0018` 之后四次跨区各一帧、零重试。

参照实现的名册是 `{ 自己 } + 其他人`，所以单人是一条记录的列表，不是特例——
把它当"要第二个角色才有意义"而跳过，是这次走错的那一步。

但**"名册里必须有自己"没有被证明**：那次补上的是 `count = 1` 且唯一一条是自己，
"发了本帧"和"自己在名册里"同时成立。分辨办法与客户端侧的读取证据见
[NOTI-0x0018](../server-to-client/NOTI-0x0018.md#换区时不能省但为什么不能省还没定)。
