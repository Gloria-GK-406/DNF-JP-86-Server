## A21

**2026-08-26 实机。** 客户端在 Boss 房发了这一帧(0 字节),服务端不认得,日志记
`Unhandled Game frame ... type=0x01E4`,此后教学卡在原地。归档见
[a21-tutorial-ending-20260826](../../patterns/data/traces/a21-tutorial-ending-20260826.md)。

**body 是空的。** 判断需要的一切 —— 谁在问、几级、在不在副本 —— 服务端本来就知道。

**这是教学里唯一真正发经验的地方。** 之前每一次击杀的 `NOTI 0x0025` 报的都是角色当前的等级与
总经验,不加也不减;等级是在这里一次给到的。上游 `DungeonTutorialHandler.HandleTutorialLevelUp`:
`TutorialTargetLevel = 2`,经验取 `character/ExpTable.tbl` 第 `目标等级-1` 项 —— 是**赋值**不是
累加,所以打得多打得少的人走到这一步都停在同一处。

回包:

```text
S->C NOTI 0x0025 EXP                 83B  新的等级与总经验
S->C NOTI 0x0015 ACCEPTABLE_QUEST_LIST 25B  ← 本仓未发,见下
S->C NOTI 0x0002 USERINFO           579B  ← 本仓未发,见下
S->C CMD  0x01E4                      1B  [01]
```

不满足条件时上游回 `[0x13]`,并且不区分「已经过了 1 级」和「不在副本里」。

**本仓少发中间两帧。** 它们都是把已发布的整份入场状态重投影一次,而会话快照眼下没有局部更新的
路径。已发的那两帧带着新等级,客户端因此知道自己升了;缺的两帧记在
`Docs/ProtocolScaffoldDissonances.md`,不留给以后重新发现。
