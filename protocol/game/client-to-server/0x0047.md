## 请求：两个构包点，形状不一样

上区的字段表来自上游的读法（`body[0]` 牌型、`body[1]` 牌位序号），两个构包点则是这样：

| 构包点 | 写了什么 | 用在哪 |
|---|---|---|
| `0x00704460` | `WriteU8(0)` 把牌型写死为免费，再 `WriteU8(arg)` 写牌位序号 | 点击牌面那条路，**永远发免费牌** |
| `0x00D10DFF` | 只写一个字节，形状不同 | 付费（黄金）牌那条路 |

普查因此把本 type 标为 `divergent`。**免费那一条有上游读法互证，付费那一条没有**——那一个字节是什么
未查明。

## 应答：8 条记录，每条声明它描述哪个牌位

```text
01                       成功标志
每条记录：
  a  u8                  记录不为空时才继续；a == 0xFF 该条不处理
  b  u8                  **内容归属的牌位序号**；> 7 就跳过这一条的对
  c  u8                  其后 (u32 id, u32 count) 对的条数；<= 0 不读
  (id, count) × c        每对调 setSlot(id, count, b, 3)
  尾 u8                  又一个按记录序号存的标志
共 8 条
```

八条都不带对时是 **33 字节**（`01` + 8×4），这正是上游 `BuildCardInfoAck` 写出的长度：它写
`01`，然后第 0 条 `free?00:FF, paid?00:FF, 00, 00`，第 1–3 条 `FF FF 00 00`，第 4–7 条
`FF FF FF FF`。

### `b` 是牌位序号——**推断，未实机确认**

依据是应答处理器（RVA `0x00D05250`）里那个门函数的寻址：

```text
0x021EF720(b, 3):  addr = this + 0x1E8 + 100*b + 60
                   return ([addr+8] - [addr+4]) / 68
```

即「牌位 `b` 的第 3 类内容列表里已经有几条」；列表非空时客户端跳过这一对，所以**牌位一经亮出
就不会被覆盖**。加上 `> 7` 这个上界恰好等于记录条数，两条合起来指向「序号」而不是布尔。

**这不是实测。** 一次实机即可确认或推翻：给牌位 2 填一对，看是不是第 3 张亮起来。
静态分析出处见 `.rks-agent/tasks/finishing-and-leaving-a-run/card-reward-evidence.md`。

上游把 `paidSelected ? 0x00 : 0xFF` 写进的正是这个 `b`，于是它永远只指向牌位 0 或者哪也不指——
**「只有第 0 张有货」是上游的简化，不是协议的限制**。

### 本仓与上游的差别

上游只填第 0 条；本仓给四个牌位各填一条，`b` 填该牌位自己的序号，没有东西的牌位写 `c = 0`
（**声明它带零件东西**，而不是从应答里省掉）。四个牌位全空时长度仍是 33 字节；每多一件东西多 8
字节。牌型（`a`）按本仓的读法写免费 0 / 付费 1；上游在免费面写的也是 `0x00`。

`id == -1` 且标志成立时客户端按金币处理（`setSlot(amount, 1, slot, 4)`）。**本仓此处不发金币**——
编码器只写 `slot.Item` 的 `(id, count)` 对，`id == -1` 的记录一条也不写。

**但牌面金币本身已经实现，只是不走这一帧。** 翻到有货的牌位时，`SelectCardCommandHandler`
把 `GameProtocol.ClearRewardCardGold` 加进**账号**（该常量是本服务器自定的占位值 1，
不是档案读数——档案里翻牌不出金币）。这一次交换的两帧都不报它：本帧只有物品对，
随行的 `NOTI 0x000E` 说的是那件装备进了背包哪一格。免费牌位 0 的那一份在更早的结算帧
`NOTI 0x0023` 的免费牌金币位上**预告**过（见
[`NOTI-0x0023.md`](../server-to-client/NOTI-0x0023.md)），
**其余三个牌位的那一份则没有任何帧公布**。

### 请求被丢弃的两种情形

牌型不是 0 或 1、牌位序号大于 3 的，解包时就丢掉（返回 null，帧被丢弃，连接不受影响）——与上游
的 `cardType > 1 return` / `cardIndex > 3 return` 同界。体长不足 2 字节的同样丢掉，
`0x00D10DFF` 那条 1 字节的付费请求因此不被接受：它的形状未查明，不猜。
