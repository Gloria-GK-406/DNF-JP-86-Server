# `0x00B3` `CHANGE_GUILD_NAME`

| 项 | 值 |
| --- | --- |
| Endpoint | Game |
| Direction | Client → Server，使用同 type 的 CMD 回执 |
| Command | `0x01` |
| Type | `0x00B3` |

## 请求与回执

| 偏移 | 字段 | 含义 |
| ---: | --- | --- |
| 0 | `u16le` | 主背包中改名卡所在的线槽号 |
| 2 | `u8` | 容器 0，即主背包 |

**ClientStatic · Confirmed。** A21 在 VA `0x02492F2A` 发 [验名 `0x009C`](0x009C.md)，并暂存验名文本。确认时对照该文本，改名构包 VA `0x02492D7A` 调用物品线槽查询 `0x016EF580`，写入槽号和 0 后跳到封包函数。相邻 `0x02F8` 分支的 `u32` 属于另一个请求。客户端成功回执处理器 VA `0x0111BCB0` 读取公共成功标志。

**PvfContent / HistoricalReference。** 配套 PVF 的 `stackable/chn_490001375.stk` 为「公会改名卡」，说明为可修改公会名称，物品类型 `[etc]`。日服后续公告也记录了用公会改名券更名的规则。A21 配套客户端的卡片触发入口待实机采样。[日服改名券公告](https://arad.nexon.co.jp/news/notice_view.aspx?no=9171)

**CurrentImplementation。** 验名绑定当前选角会话、公会、原名称和新名称。提交时重新检查会长权限、名称冲突及指定槽的卡片。仅在改名事务成功时扣一张卡，保留公会 ID、成员和权益。成功回 `01` 并更新背包槽。在线成员收到公会资料刷新，其他同会角色收到 [改名通知](../server-to-client/NOTI-0x00DA.md)。搜索和推荐以新名称读取。

**WireTest · Confirmed。** 隔离线路 `1795770720212970000` 验证无验名、普通成员、重名、错槽、旧推断的多余字节和重放均不扣卡，成功只扣一张、没有金币扣费，跨频道成员看到刷新、旧名查找失败、新名搜索及推荐可用，重登读回同一公会的新名称。A21 端到端操作待实机验收。
