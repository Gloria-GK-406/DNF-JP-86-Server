## A21 服务端结算边界

**2026-09-14，代码/PVF 推导，尚未提升为 ClientVerified。** 请求中的
`rewardSelection` 与 `completionCount` 进入事务命令，不再只记录日志：

- 没有 `[reward selection int data]` 时只接受 `rewardSelection=0xFFFF`；存在可选奖励时，
  索引作用于按角色当前持久化 job/growType 过滤后的候选，并且只发其中一项。
- `[reward int data]` 是固定奖励表；其 `[job] job growType count` 条件必须保留，不能把
  后续整数重新配成 item/count。真实 PVF 任务 1776 对 job=0/growType=0 的结果是
  `101010437 x1`，不是表内所有职业装备。
- itemId=0 的声明是金币语义；金币通过角色领域入口结算，成功响应再以 ItemId=0 投影
  实际增加量，不能当普通物品，也不能占用 completionCount 或末尾哨兵字段。
- 奖励计划在写任务日志前完成校验；任务、物品、金币和经验处于同一事务。可预期的后置
  发放失败以专用拒绝异常越过命令边界触发回滚，再由 Handler 映射为拒绝响应。

**2026-09-18 补充：** 对持有物品目标，当前服务端在事务内再次根据背包计算剩余需求，
然后才允许任务日志完成和发奖。若旧 trigger 为零但物品已经丢掉，回复拒绝并补发
[`NOTI 0x023F`](../server-to-client/NOTI-0x023F.md) 校正任务进度。
这是本仓规则与回归测试；“丢弃 → 交付被拒 → 任务 UI 回退”的 A21 成对帧及画面

## A21 双构包路径复核（2026-09-18）

机器区的两个构包点虽然均为 10 字节，**末字段值却不一致**：
`RVA 0x00C7ED10` 路径写 `0x0022, arg1, arg2, arg3, 0xFFFF`；
`RVA 0x00B4D307` 路径写 `0x0022, [ebx], 0xFFFF, 1, u16(edi)`，而该路径
先检验 `edi > 0` 才发包。故 offset 8 不是所有 A21 路径都恒写 `0xFFFF`。
指令与边界见[`A21 静态复核`](../../patterns/data/probes/a21-quest-repair-durability-readers-20260918.md)。

当前服务端 decoder 和上游都把 offset 8 强制当 `0xFFFF` 哨兵，因此会拒绝
后一条路径产生的非 `0xFFFF` 值；尚不知它对应何种任务/交付方式，也没有实帧证明本次场景触发。
本页只记录这个协议差异，不据此放宽校验或猜测奖励计算。

## 2026-10-11 普通奖励 ACK 的条件前缀更正

证据：**ClientStatic / Confirmed（字段读取顺序）**；当前上游 `ServerS4A21/Server/DfoServer/Network/Builders/Quest/QuestAckBuilder.cs::BuildFinish` 交叉支持。
客户端为本页所列固定 SHA-256，取证 dump 为 `DNFClient-A21-protocol/dumps/dnf-dump-20260906-224825-165-31384/DNF-memory-rva.bin`。

客户端 `RVA 0x00D40AFD..0x00D40B15` 依次读取 objectiveKind、经验、u32；
`0x00D40B23..0x00D40B4D` 仅在 objectiveKind 为 `0` 或 `0x19` 时读取 consumedCount，随后循环读取每条 7B 消耗记录。
`0x00D40C77..0x00D40C95` 独立读取 chain；chain=0 时 `0x00D40D6A..0x00D40D7A` 再读奖励数量。
普通奖励的正确形式为：

```text
success(1), questId:u16, objectiveKind:u8, exp:u32, completionValue:u32,
[consumedCount:u8, consumedCount * {updateType:u8, slot:u16, count:u32}],
chain:u8(0), rewardCount:u8, rewardCount * 19B
```

方括号只对 objectiveKind=0/0x19 存在。本服继续用后续权威物品 NOTI 同步消耗，故前缀数量为 0，避免重复扣除。
非材料任务固定头 14B；材料任务固定头 15B。历史任务 1016（meet npc=4）的 71B 捕获保持原样，其中 offset12 的 0 实际为 chain，不能将它解释成所有任务共有的 consumedCount。

故障样本：1123 完成材料任务 974（觉醒－剑圣 1/4）后，旧编码只有 14B 头，奖励数量 3 位于 offset13，被材料分支当成 chain=3。
`RVA 0x00D4181A..0x00D41844` 在 chain=3 时创建窗口类型 `0x1A7`，与用户观察到的深渊资格公告吻合。
任务持久化已经完成；用户随后在 GSD 接到 2/4，确认没有回退。该公告与未自动续接的因果关系尚待修复后实机确认。

回归覆盖材料任务 0/1/2/3 项奖励及 objectiveKind=0x19、历史 meet-npc 捕获和拒绝响应。自动检查不等同于修复后的 ClientVerified；本节不改变特殊转职/觉醒 chain 的既有实现。
