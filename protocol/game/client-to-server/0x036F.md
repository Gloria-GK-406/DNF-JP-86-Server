## 2026-09-22 BUFF / HP-MP 使用上报与应答

已实现接收本轮确认的两种 76B 形状：`u16 category=1 + u16 slot(3或4) + 72B零`。slot3 为 BUFF，slot4 为 HP/MP 自动恢复；不是把上行 74B 当成客户端提交的权益快照。其他类别、槽位、长度或非零尾部暂不支持。

- ClientStatic：A21 VA `01440360` 检查无虚弱、场景条件、slot4 资格及 mgr+2 本地标志；HP 严格低于最大值一半后，`01440513` 置标志，先应用恢复效果，再于 `014405CC..014405F1` 构造并发送 category1/slot4。`01440B68` 则为 category1/slot3 的效果上报。旧报告中的 `018405CC` 地址不适用于此链，应为 `014405CC`。
- RuntimeLog：artifacts/pickup/deployment/stdout.log 的 seq417 为 `01000400` 加72零；seq406 为 `01000300` 加72零。用户观察首次低血自动回满、第二次低血没有恢复；当时服务端尚未处理该上行，回血不等待此应答。
- ClientStatic：CMD 接收 handler VA `0110DF80` 的 category1 成功分支读取74B并复制到 mgr+17..+60，不覆盖 mgr+2；随后刷新界面，并按条件触发 BUFF/自动修理检查。它不直接再次执行自动回血。mgr+2 的清零见 NOTI0018、NOTI001E 的特定模式分支、NOTI0105；不将这些条件概括为任意换房必重置。

服务端以当前连接选中角色读取权威权益与已有用量，回复同号 CMD 的完整77B：`01 + u16(1) + snapshot[74]`。无选中角色或失效会话不发送；不回复单独01，不额外发回血消息，不新增槽3/4每日计数。槽4未写用量，编码默认为0；每轮恢复由客户端本地标志限制。此实现不宣称完成反作弊或所有特殊场景的次数规则。
