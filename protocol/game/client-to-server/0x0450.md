### S→C：CMD 0x0450

成功 body（LE）：`u8 success=1, u8 listType, u8 bonusFlag, u16 consumedCount, i16 sourceSlot, i16 materialSlot, u16 primaryCount, primary[40], u16 reserved=0, u16 bonusCount, bonus[40]`。

每条 40 字节：`i16 slot, i32 itemId, i32 displayCount, u16 durability, u8 ability, i32 expiration, zero[23]`。条目尾部尚未赋予全部业务语义，当前按参考编码器写零；**不要与背包的 101 字节条目格式混用**。数量为本次获得/展示数量，不是堆叠后的背包总数。body 总长 `15 + 40*(primaryCount+bonusCount)`。

列表结构与两个列表调用点 Confirmed：客户端 handler RVA `00D170C0`，共享条目 reader `00D152C0`，两次调用位于 `00D173AE`、`00D177B5`。字段用途及尾部默认值 High：参考 `MagicBoxOpenAckBuilder.cs`。客户端原生 UI 根据 listType 和 bonusFlag 分支；第一层魔盒也能进入原生路径，本实现统一发完整 CMD 0x0450。参考服务器“仅赛丽亚使用原生 0450，其他魔盒用 00A0”的选择属于参考实现策略，不能当作客户端强制要求。

失败 body：`00 reason`；本实现无空间 `7E`、材料不足 `16`、其他拒绝 `02`。失败分支 RVA `00D17F65`，`7E` 比较位于 `00D17FE6`；错误码业务映射 High（参考实现）。失败不携带成功列表。
