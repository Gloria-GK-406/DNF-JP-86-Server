## A21(二):进不去的时候要说话

**2026-08-26。** 成功路径此前就对:回 `CMD 0x000F` 的 1 字节接纳,再
`NOTI 0x001B` / `0x019F` / `0x001C` / `0x001D` 四帧。线级实测正式副本 144
(`StormOfMetastasis/Abnoba/Redcrystal_Forest`)照样走通 —— 布局规则解出 maze=3、start=(0,0)、
room=55612、boss=(5,0),`START_MAP` 126 字节带 actor 与掉落。**教学和正式副本走的是同一条路。**

**缺的是拒绝。** 副本解不出布局时本仓此前**一帧都不发**,到玩家那里就是一个按了没反应的按钮 ——
探针打副本 5000(风振训练室,档案里没有迷宫)复现的正是这种沉默。

上游 `DungeonAdmissionRejectBuilder` 的拒绝体是 3 字节,发在**同一 type** 上:

```text
00 | 错误码 | 上下文
```

| 错误码 | 上游理由 |
|---|---|
| `0x01` | DungeonUnavailable / Unknown(等级门用的就是它) |
| `0x08` | NotPartyLeader |
| `0x11` | MissingRequiredItem |
| `0x13` | InvalidSelectionState |
| `0x15` | DungeonNotFound |
| `0x16` | InsufficientFatigue |
| `0xAD` | MemberEntryLimitReached / MissingPermission(上下文写队员槽位) |
| `0xF6` | DailyEntryLimitReached |

**客户端为这些码画什么句子还没读过**,不像移动与使用那两类有字符串表佐证,所以本仓按"服务端判定
了什么"命名而不是按"玩家看到什么"。

本仓眼下只发得出 `0x15 DungeonNotFound` —— 那是唯一一条它真的能判定的。等级门要档案的
`[minimum required level]` 加上上游的"剧情副本豁免",少了豁免就会拒绝客户端本来就提供的副本,
所以没有实现,记在 `Docs/ProtocolScaffoldDissonances.md`。

线级实测:副本 5000 与 65535 都回 `CMD 0x0010` 3 字节,连接存活;副本 144 照常五帧进入。
归档见 [a21-dungeon-admission-20260826](../../patterns/data/traces/a21-dungeon-admission-20260826.md)。
