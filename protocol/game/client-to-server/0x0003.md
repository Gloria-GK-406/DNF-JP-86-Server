## A21：已实现，与上游同形；一次"没做"的误判

**2026-08-27 实机。** 玩家跑完教学、回到城里，按退出游戏 —— **卡住**，初判是"这个协议还没做"。
**实际上做了，而且和上游逐字节一致。**

上游的处理就一行（`GameProtocolHandler.RegisterMiscHandlers`）：

```csharp
d[0x0003] = (s, h, b) =>
    s.SendPacketAsync(GamePacketEnvelopeBuilder.Build(0x01, 0x0003, CommonPacketBodyBuilder.BuildSuccessAck()));
```

**回一个字节的成功，别的什么都不做** —— 不落库、不断连接、不推投影。上游抓包对得上：

```text
RECV cmd=0x01 type=0x0003 len=15 body=(1B) [00]
SEND cmd=0x01 type=0x0003 len=16 body=(1B) [01]
RECV cmd=0x01 type=0x02B3 STATICS_RUNTIME_TING     ← 之后客户端自己收尾
```

本仓 `Game/Exit` 走同一条，答 `[01]`。

实现映射：`GameExitMessageDecoder` → `GameExitHandler` →
`GameExitResponseEncoder`。`GameExitIntegrationTests` 从真实 TCP 入口验证 typed pipeline、`01`
响应和响应后连接仍可继续收帧；该测试证明当前实现，不替代客户端 UI/进程退出结果。

**卡住的真正原因在两帧之前**：回城时客户端发的 [`CMD 0x00C2 CLIENT_SPEC_PROFILE`](0x00C2.md)
在 A21 上是 362 字节，本仓按 A12 的 24 字节包头算成 361，解码器抛异常，**连接当场被拆**。
玩家此后按的退出，是在对一个已经关掉的 socket 说话。归档见
[a21-exit-and-return-20260827](../../patterns/data/traces/a21-exit-and-return-20260827.md)。

*教训*：客户端卡在某个动作上，不等于那个动作的协议没做。先确认连接还在。

## 历史登录会话处理（2026-09-27，已被 2026-10-07 修正替代）

当前EXIT仍回成功ACK且不主动关闭连接，允许客户端完成后续flush；同时撤销该连接绑定的登录凭证。
迟到的旧连接EXIT不会影响已交接给新连接的凭证。TCP自然断线走5分钟宽限，不等同于EXIT。
