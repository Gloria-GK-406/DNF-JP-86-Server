## Wire layout

Game header 见 [Game TCP 帧组织](../../patterns/game-frame.md)。构包器 `RVA 0x01CD3300` 一带
（`MakeHeader` 调用点 `RVA 0x01CD33B7`，由构包点普查定位），全部字段读自单例
`[VA 0x03091FB8]` 指向的统计对象。

body 是一串**以 u16 tag 引导的段**，tag 决定该段的载荷形状：

```text
tag 0..6 （7 段，各 6 字节）
    u16 tag              ; 循环变量，恒为 0,1,2,…,6
    u32 value            ; 均值：total / count，向零截断

tag 7                    ; 4 + 9 * count7
    u16 tag              ; 字面量 7
    u16 count7           ; ← [stats+0x898]
    count7 × Record      ; 9 字节

tag 8                    ; 4 + 9 * count8
    u16 tag              ; 字面量 8
    u16 count8           ; ← [stats+0x89C]
    count8 × Record      ; 9 字节

（tag 8 的循环之后立即 Finalize，没有第 9 段）
```

```text
BodyLength = 42 + 4 + 9*count7 + 4 + 9*count8
           = 50 + 9*(count7 + count8)
```

五次会话 `count7 = count8 = 0`，body 恒为 **50 字节**，与算术精确闭合、零剩余字节。

### `Record`（tag 7 与 tag 8 共用，9 字节）

| Offset | Size | Encoding | 源偏移 | Confidence |
|---:|---:|---|---|---|
| 0 | 2 | LE `u16` | `rec+0x0` | Confirmed |
| 2 | 1 | `u8` | `rec+0x2` | Confirmed |
| 3 | 2 | LE `u16` | `rec+0x4` | Confirmed |
| 5 | 2 | LE `u16` | `rec+0x6` | Confirmed |
| 7 | 2 | LE `u16` | `rec+0x8` | Confirmed |

内存里的记录**步进是 10 字节**（`add esi, 0xA`），wire 上只有 9 字节——`rec+0x3`
那一字节是对齐填充，不上报。字段语义全部未定：五次会话 `count` 均为 0，从未采到实际记录。

### tag 0..6 的值是均值（Confirmed，`E-002`）

每段的 `u32` 不是直接读出来的，而是当场算的：

```asm
mov  eax, [ebx]          ; 分母（样本数）
je   zero                ; 为 0 → 写 0
mov  eax, [ebx-0x24]     ; 分子（累计量）
je   zero                ; 为 0 → 写 0
fild  dword [ebp-8]      ; 有符号整数载入
jns  +                   ; 负数先加 2^32 修正
fadd dword [0x27E2B00]
fidiv dword [ebp-4]      ; / 分母
fnstcw / or 0xC00 / fldcw ; 控制字置「向零截断」
fistp qword [ebp-0xC]    ; 取整
zero:
WriteU16(index) / WriteU32(value)
```

- 分子与分母在同一数组里相距 `0x24`，每段 `ebx += 4`——即两条平行的 7 元数组
  （累计量与样本数）。
- 取整是**向零截断**（控制字 `0xC00`），不是四舍五入。服务端若要复算必须用同样的截断。
- 任一为 0 即写 0，所以**全零 body 不代表出错**，代表该会话没有采到样本。

这解释了五次样本为何全零：会话都没真正进入游戏，7 个指标一个样本都没有。

## Implementation mapping

| Layer | Type/path | Responsibility |
|---|---|---|
| Networking | `Framing/SessionMetricsPayloadCodec.cs` | 分段解析、tag 校验、`50 + 9*(count7+count8)` 长度校验 |
| Networking | `Framing/GameProtocol.cs`（`SessionMetricsType`） | 线路 type 常量 |
| Data | `Networking/NetworkMessages.cs`（`SessionMetricsReportRequest` / `SessionMetricMean` / `SessionMetricRecord`） | 强类型消息 |
| Application | `Game/SessionMetricsHandler.cs` | 仅记录日志，不回响应、不改领域状态、不过命令总线 |

实现要点（均已落实）：

- 长度按 `50 + 9*(count7+count8)` 校验，不写死 50；尾部有多余字节即拒收。
- 七个均值段的 tag 必须等于自身下标（客户端写的就是循环变量），不等即拒收；
  两个计数段的 tag 必须分别是 7 和 8。
- `Record` 字段按 offset/宽度命名（`Word0`/`Byte2`/`Word3`/`Word5`/`Word7`），不猜语义。
- 均值为 0 在日志里显示为 `-`（未采样），七个全 0 时只输出一次 `7tags nothing-sampled`——
  因为 0 的含义是"没有样本"而非"测得 0"。
- 服务端不试图从均值反推分子分母：客户端算的是向零截断的整除，信息已经丢失。

## Verification

- Parser/codec vectors：实测 50 字节全零 body → 7 个 tag 0..6、均值全 0、两段均空
- Boundary cases：长度 < 50 拒收；尾部多 1 字节拒收；`count` 超出剩余字节拒收
- 条件分支/重复项：`count7=2, count8=3` → 长度 95，两段分别 2/3 条记录；
  单条记录五个字段用互不相同的值验证过偏移与字节序
- tag 校验：均值段 tag 改成 9 → 拒收；计数段 tag 改成 6/9 → 拒收
- Response count/order：无响应
- Real-client result：2026-08-15 第五次实机会话通过——`SessionMetricsHandler` 输出
  `Session metrics Game:01-00-00-00 account=1 onlineUser=…: means=7tags nothing-sampled section7=empty section8=empty`。
  全部严格校验（七个均值段 tag = 自身下标、两个计数段 tag = 7/8、无尾部多余字节）
  在实机数据上均通过
- **未经实机验证的分支**：`count > 0` 的计数段只有单元测试覆盖，从未在 wire 上出现过；
  要覆盖它必须有角色并真正进入游戏

## 逆向工作日志

### 1. 「8 × 6 字节索引表」这个早期猜测是错的

协议清单里原来记的是"形如 8 × 6 字节的索引表（`00…00`、`01…00` … `07…00`）+ 2 字节尾"。
按 6 字节切确实能切出 0..7 八组，看起来很整齐——但那是**巧合**：真实结构是
7 组 6 字节（tag 0..6），然后 tag 7 那段的 `u16 tag + u16 count=0` 恰好又凑成 4 字节，
再加 tag 8 的 4 字节。把它读成"第 8 组 + 2 字节尾"就把两个段错切成了一个组加一个尾。

只有 body 全零时这两种切法都"说得通"，这正是**全零样本最危险**的地方：它对任何切分都不反驳。
结构只能来自构包器。

### 2. 长度闭合这次立了功

第一遍只读到第二个循环，算出 `42 + 2 + 2 + 9k = 46 + 9k`，怎么也凑不出 50
（`4/9` 不是整数）。正是这个凑不齐逼着继续往下读，才发现循环之后还有 tag 8 段，
补上后 `42+4+4 = 50` 精确闭合。

对比 [`0x0117`](0x0117.md)：那条协议闭合失败是**正确结果**（多态载荷）。两者的区别在于
`0x0117` 的构包器里有经 vtable 的间接 `call`，本协议没有——判别方法已写进
[game-frame](../../patterns/game-frame.md)。

### 3. 未走的路

- 没有追 `[stats+0x24]` 数组的写入点来给 tag 0..6 命名。那需要扫全局单例
  `VA 0x03091FB8` 的所有 xref，而更便宜的证据是"进游戏一次让这些槽变非零"，
  等有角色之后顺手就能拿到。
- 没有为全零 body 单独存样本文件，理由见 Samples。
