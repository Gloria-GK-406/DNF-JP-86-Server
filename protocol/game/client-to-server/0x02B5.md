# `0x02B5` `CHECK_DOUBLE_CHARACTER_NAME`

> 名称取自旧服 `CmdPacketType` 枚举。共享证据、原因码表与名字字段编码见
> [角色生命周期协议族](../../patterns/character-lifecycle.md)。

## Identity and behavior

| Property | Value |
|---|---|
| Endpoint | Game |
| Direction | Client → Server（响应同 type 反向） |
| Command | `0x01` |
| Type | `0x02B5` |
| Role | Query / 有响应 |
| Trigger | 建角色对话框里输入名字后的可用性检查 |
| Expected response | CMD `0x01` / `0x02B5` |
| 阶段 | 实现服务端功能 |

**尚无实机样本**：客户端从未发出过本帧，因为建角色界面此前打不开。

## Wire layout

Game header 见 [Game TCP 帧组织](../../patterns/game-frame.md)。

**请求** body 只有名字字段：

```text
BodyLength = 4 + nameLength
```

| Offset | Size | Encoding | Meaning | Confidence | Evidence |
|---:|---:|---|---|---|---|
| 0 | 4 | LE `i32` | 名字字节数，旧服限 1..30 | Hypothesis | `E-001` |
| 4 | `nameLength` | 原始字节 | 名字，UTF-8 | Hypothesis | `E-001` |

长度是**字节数不是字符数**，且本条的 30 字节上限比 [0x0005](0x0005.md) 的 18 字节宽——
同一个名字可以在这里通过、在建角色时被拒。这是旧服的既有行为。

服务端不信任声明长度，先与实际 body 比较再切片；比较用减法避免整数溢出。

**响应**：

| 情况 | body |
|---|---|
| 可用 | `01` |
| 已被占用 | `00 18` |
| 长度非法 | `00 14` |
| 文字不可用 / 非法 UTF-8 | `00 9F` |

## Client reversing evidence

| Evidence | Kind | Location | Supports |
|---|---|---|---|
| `E-001` | static | 旧服 `CharacterSelectHandler.Handle_ENUM_CMDPACKET_CHECK_DOUBLE_CHARACTER_NAME`（`d51e74b`） | 请求布局与全部原因码 |
| `E-002` | static | client handler `0x008C5E30`，注册于 `0x008D04EF` | 客户端等响应 |

**`E-002` 只证明 handler 存在，不证明响应格式。** 可达性扫描走了 222 个函数、15 个调用进入
打包区，未命中任何读取原语；同批正对照（LOGIN）正常命中，所以是子树太黑而非扫描器故障。
本条响应格式**只有旧服行为支撑**，故整体标 Hypothesis。

## Server and historical evidence

旧服按 `body.Length < 5` → `{0x02}`、长度越界 → `{0x14}`、名字非法 → `BuildCmdError(0x9F)`、
重名 → `BuildCmdError(24)`、可用 → `{0x01}` 分支。本实现保持相同码值，
仅把「body 过短」并入 `00 14`（长度非法）——旧服的 `{0x02}` 是裸码且与 `0x0006` 的含义冲突，
而两种情况对玩家都是「这个名字不行」。此处**有意与旧服不同**，记录在案。

## Implementation mapping

| Layer | Type/path | Responsibility |
|---|---|---|
| Data | `CharacterNameStatus` | 领域结果 |
| Networking | `GameMessageDecoderRegistry` 键 `0x01/0x02B5` | 分发 |
| Protocol | `Game/CharacterName/` | 解码、command、handler、编码器 |
| Application | `CharacterService.CheckNameAsync` + `CharacterNameRules` | 形状规则与重名查询 |
| Infrastructure | `SqliteCharacterRepository.NameExistsAsync` | 按 blob 比较，非文本 |

命令为 `Direct` + 账号 `Shared`：只读，不改任何状态。

## Verification

- Parser/codec vectors：`CharacterLifecyclePayloadCodecTests` 覆盖全部五种状态的编码。
- Boundary cases：超长声明长度、负数长度、短 body 均被拒（含整数溢出用例）。
- 领域规则：`CharacterLifecycleServiceTests` 覆盖字节长度、非法 UTF-8、重名。
- Real-client result：**未做**。
