当前 body 只有两个严格 wire 形状：

```text
direct:       12 bytes
inline-title: 2 leading bytes + i32-le titleLength + title[titleLength] + 10 trailing bytes
        BodyLength = 16 + titleLength
```

inline-title 的 `titleLength` 在 offset 2，标题从 offset 6 开始。标题不属于规范设置块；规范块由
前导 2 字节和标题后的 10 字节拼成。direct 本身就是规范设置块。2026-09-12 当前 A21 实帧进一步
证明 direct 不等于“仅 create”：已有两人队伍从原生设置 UI 编辑时同样使用 12 字节 direct。

### 当前 A21 direct 创建与编辑样本（2026-09-12）

最终实机中，用户从无队状态选择预设标题创建 Normal：

```text
00 03 04 00 00 00 00 05 00 02 00 00
```

服务端交换前两字段后回送 `titleIndex=3, special=0, capacity=4, category=2, target=0`，客户端继续存活并
正确显示预设队名。样本见 [`0x000C-20260912-02.hex`](samples/0x000C-20260912-02.hex)，完整时序见
[`a21-normal-party-live-20260912.md`](../../patterns/data/traces/a21-normal-party-live-20260912.md)。这证明
Normal canonical target/default 为 `0`；旧服务端的 `0xFFFF` 是 placeholder 错误。

用户在已有两人 Normal 队伍中把容量改为 2，并选择/修改队伍标题后，客户端发出：

```text
01 01 02 00 00 00 00 05 00 02 00 00
```

服务端日志记录 `accepted=True`，4 ms 后向两名当前成员分别发出一份 `NOTI 0x0009 type=1`；客户端
继续存活并立即显示新的队伍标志。定向中转没有观察到 `0x000C` CMD response。样本见
[`0x000C-20260912-01.hex`](samples/0x000C-20260912-01.hex)，完整时序与字段级 UI 差分见
[`a21-party-settings-live-20260912.md`](../../patterns/data/traces/a21-party-settings-live-20260912.md)。

两次 direct body 都不含 UTF-8 标题内容，因此不能声称自定义标题文本已到达服务端。inline-title、
非队长拒绝与拒绝 response 仍待当前实帧。
