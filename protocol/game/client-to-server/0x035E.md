## 王者战编队

**ClientStatic / High**。构包点写一个 Dstr 和三个 u8。参照服的 `PvpTotalMatchTeamRequest` 将三字节解释为账号角色列表的位置，成功回包为 `01 + 三个位置`。已存在的队名保留，成员可以编辑。参照服在成功回包前发送 [NOTI 0x031B](../server-to-client/NOTI-0x031B.md)。

**CurrentImplementation**。同事务校验当前会话、所在场景、三角色和名称唯一性，保存账号队伍。响应采用参照服的 `00 01` 重名、`00 02` 不合法编队、`00 9F` 不合法名称。A21 实机尚待取证。

**ClientVerified（界面） / WireCaptured（房间），2026-11-24**。在 CH68 模式 8 房间内，「更换队员」打开「队伍构成」。A21 实机截图显示独立的「输入队伍名」、一个代表角色栏、两个队员栏以及「选定队伍」按钮。公告提示，如果当前登录角色不是设置后的代表角色，改用代表角色登录时会进入频道待机房间。打开面板和本次单击剑魂后，CH68 抓包未见 `0x035E`、`0x035F` 或 `0x0360`，两测试账号也没有已保存的编队。候选转职限制和实际提交载荷待后续样本。房间模式样本见 [CMD 0x0036](0x0036.md)。

### 2026-11-24 保存成功与代表角色重入

**WireCaptured / Confirmed**。13:48:07，CH68 房主 aaa（名单位置 0）保存[队伍「123」，位置 `01 02 00`](samples/0x035E-2026-11-24-01.hex)。服务端先发 `0x031B`，再回 CMD `01 01 02 00`。隔离库确认首位 KingBSecond、第二位 KingBThird、第三位 aaa。原会话离开房间，随后同一 TCP 连接收到间隔约 51 ms 的两批 `0x0030 → 0x031B → 0x0029`。用户看到客户端进入决斗大厅后卡住。此版抓包仅保留部分类型，未记录换角的 `0x0007`、`0x0004` 入站帧。

**ClientStatic / Confirmed**。A21 b1 full 的 CMD 响应处理 `0x0110D890` 在 `0x0110D8BB` 循环读取三个位置。如果首位与当前角色不同，`0x0110D934` 保存待自动选择的角色位置，`0x0110D944` 发送空体 CMD `0x0007`。A21 在收到 USERINFO subtype 2 的名单时调用 `0x026ED550`，当自动选角索引有效时，`0x026ED748` 或 `0x026ED7C3` 会尝试发送 `0x0004`。该索引在游戏模块切换后才由 `0x0164428C` 清除。若服务端在同一次重入的初始化中再次刷新名单，可能在清除索引之前触发第二次选角。见[返回选角](../../patterns/flow-return-selection.md)。

**CurrentImplementation / TCP 自动化**。成功保存不同代表时记录该连接预期的选角位置。决斗频道中，原选中会话已释放、下一次选角的位置匹配时，代表角色沿用返回选角阶段已发送的名单，这次进场省略第二份 subtype 2，仍发送入场完成、队伍与大厅通知。随后普通选角会照常刷新名单。针对两轮初始化的 A21 实机复验尚待完成。
