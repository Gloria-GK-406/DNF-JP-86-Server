# `0x01BA` `MERCENARY_INFO`

> 名称取自旧服 `CmdPacketType` 枚举。**注意同号异义**：`NotiPacketType` 里的 `0x01BA` 是
> `GROWTH_WEAPON_EVENT_INFO`，与本条无关。共享证据见
> [角色生命周期协议族](../../patterns/character-lifecycle.md)。

## Identity and behavior

| Property | Value |
|---|---|
| Endpoint | Game |
| Direction | Client → Server（响应同 type 反向） |
| Command | `0x01` |
| Type | `0x01BA` |
| Role | Query / 有响应 |
| Trigger | 角色列表屏自发发出，实测 seq 6 |
| Expected response | CMD `0x01` / `0x01BA` |
| 阶段 | 实现服务端功能 |

佣兵远征信息，**与建角色无关**。它出现在这批工作里，只是因为它和建角色卡在同一屏，
且同样得不到应答。与 [0x0286](0x0286.md) 一样，本帧长期只以 seq 空缺的形式存在。

## Wire layout

Game header 见 [Game TCP 帧组织](../../patterns/game-frame.md)。

**请求** body 长度 **0**。旧服显式要求长度为 0，非 0 即回错误。

**响应** 长度随记录数变化：

```text
BodyLength = 7 + Σ(记录)   // 每条记录 = 12 + 名字字段
```

| Offset | Size | Encoding | Meaning | Confidence | Evidence |
|---:|---:|---|---|---|---|
| 0 | 1 | `u8` | 状态，`1` = 成功 | High | `E-001` |
| 1 | 1 | `u8` | 管理等级 | High | `E-001` |
| 2 | 4 | LE `u32` | 管理点数 | High | `E-001` |
| 6 | 1 | `u8` | 记录数 `N` | High | `E-001` |
| 7 | … | `N ×` 记录 | 见下 | High | `E-001` |

单条记录：`i32 characterId`、名字字段（`i32` 长度 + 字节）、`u8 state`、
`i32 remainingSeconds`、`u8 areaIndex`、`u8 periodIndex`、`u8 avatarBonusTier`。

失败为 `00 01`。

**本服务端恒发空名单** `01 00 00000000 00`（7 字节）：没有佣兵子系统，而「你没有派出佣兵」
是真话，也是一个新账号在正常服务端上会得到的答案。回错误则是在声称请求失败，那不是事实。

## Samples

请求已实测（服务端日志，2026-08-16）：`selector=0x01 type=0x01BA seq=6 body(0B)`。
响应无实机样本；本地回环实测 `body=01000000000000`。

的布局之一。

## Server and historical evidence

旧服 `MercenaryExpeditionHandler.HandleInfo`：要求 `body.Length == 0` 且会话已认证，
否则回 `BuildError(1)`；通过则查 `MercenaryService.GetInfo(accountId)` 并回成功体。
本实现不查询任何服务，直接回空名单。
