## 证据与样本

<!-- 人工区：重新生成不会触碰本节及其之后的一切内容。 -->

`samples/0x0023-2026-08-17-01.hex` —— 7 字节 `DA01EA00056800`，与静态的 `≥ 7` 相符。

**前三个字段已有证据（2026-08-17）。** 同一次会话里服务端自己算出的 spawn 是
`pos=(474,234) direction=5`，而客户端本帧回报 `DA01 EA00 05 6800`：

| 偏移 | 字节 | 值 | 含义 | 依据 |
|---:|---|---:|---|---|
| 0 | `DA01` | 474 | **x** | 与服务端下发的 spawn.X 一致 |
| 2 | `EA00` | 234 | **y** | 与 spawn.Y 一致 |
| 4 | `05` | 5 | **direction** | 与 spawn.Direction 一致 |
| 5 | `6800` | — | 未知 | — |

不需要专门做"变更坐标"的差分——**服务端下发的 spawn 本身就是对照物**，客户端把它原样回报了。
含义已写入 [`meanings/20-world-entry-capture.tsv`](../../patterns/data/meanings/20-world-entry-capture.tsv)。

那次会话的九帧**逐字节全同**——角色一步没走，474/234 就是 `SilverCrown.twn` area 0 的
`[gate] 474 234`。"客户端原样回报"既是它成为证据的原因，也是它当时的边界：
证明了字段位置，没证明取值会变。

**2026-08-17 走了一圈，这条边界解掉了。** 10 级角色在银色村庄移动 14 帧
（[frame-capture-20260817-town-walk.jsonl](../../patterns/data/traces/frame-capture-20260817-town-walk.jsonl)）：

- 坐标从 (474,234) 一路变到 (2660,358)，随移动改变；
- 朝向取到 **5、2、4、6、8** 五个值，所以偏移 4 不是常量；
- **尾部那个 `u16` 也不是常量**：站在到达点时是 `6800`（104），一旦开始移动全部变成
  `6400`（100）。原先"实机恒为 `6800`"的记述据此作废——它只是静止时的取值。

上游只读前两个字段（`BitConverter.ToInt16(body,0)` 与 `(body,2)`），朝向和尾部它都不看。

尾部两字节仍未知。上游对应的下行 builder 写 8 字节而这里是 7，该分歧记在
[Docs/ProtocolScaffoldDissonances.md](../../../Docs/ProtocolScaffoldDissonances.md)。
服务端仍整段收下不拆——按含义切分要等尾部也有证据。

本条与入场批次同时出现：客户端接受入场批次、开始加载城镇时连发一批 fire-and-forget 上报
（`0x0002` / `0x0023` / `0x003F` / `0x01F8` / `0x0252` / `0x02B3`）。

**本条已从那一族里搬出来。** 其余五条不带任何状态、整段收下即可，而这一条带的是坐标，
服务端必须留着——它是会话结束时落库的那份位置的唯一来源。

那五条客户端确实没有注册 CMD 接收 handler，所以"无响应"有普查作证。
**`0x0002` 是例外**：它注册了响应 handler `0x008C62C0`（见 [`0x0002`](0x0002.md)）。
我们对它也不回帧而客户端继续前进——那只说明**被容忍**，不说明不需要。

**2026-08-17 首次观察**，与它们同批出现的还有 `0x000F` / `0x0010`。

## A21：本条**有**响应

**2026-08-24。** 上面"无响应"的记述来自 A12：客户端未注册 CMD 接收 handler，2026-08-17 那次
九帧也确实没有回包。**A21 会答**，而且答的不是 CMD 而是一条 NOTI：

```text
C→S  CMD  0x0023  SET_USER_POSITION   body 7B
S→C  NOTI 0x0016  USER_POSITION       body 9B
```

判据是 A21 参照会话里这两帧**紧邻**（第 70、71 帧），且九字节可以逐字段解释为

```text
u16 线上用户 id | u16 x | u16 y | u8 direction | u16 尾部
```

**尾部是客户端说了算，不是我们的常量。** 参照里客户端上报 `68 00`，回包也是 `68 00`；
而入场批次里服务端自己发的那条 `0x0016` 是 `64 00`。这与上一节"静止 104、移动中 100"的
观察一致——服务端把客户端刚说的值原样送回。

因此本条在 A21 下不再是 fire-and-forget：**客户端发出它，本身就是城镇已经建成的判据**
（在此之前它还在 `InitGraphicSystem` 里，见
[进入世界](../../patterns/world-entry.md#进城之后客户端才会做的第一件事)）。
