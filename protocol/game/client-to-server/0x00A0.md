### 2026-11-14 类别坐标与整类发放（#328）

- `[booster selection num]` 的取值决定请求里带什么 ID：
  - 为 N>0 时，已选个数必须等于 N 才能确定；
  - 为 0 时，不需要点选，请求带该类别全部条目的 ID（按 PVF 声明顺序，`0151C7D4..0151C863`），即整类发放；
  - 类别为空时不能确定。
- 按职业或物品自动选类别（autoget）时，`context1` 为自动得到的类别，`context2` 为 0，窗口直接发包。
- 70 `_processBoosterSelect` 同样按 `(cat1,cat2)` 查类别（70Reference）。

CurrentImplementation：
- 服务端按 `(context1, context2)` 找到类别，找不到则拒绝；
- 选择数 N>0 时，要求 N 个互不重复且属于该类别的 ID；
- 选择数为 0 时，要求请求 ID 与该类别全部条目一致（不计顺序），然后发放整类；
- 块内的强化等级只作用于装备行。值为 255 时，按 `[random probability]` 的权重抽强化等级。增幅和品级尚未实现，含这两项的礼包继续拒绝。
